# Требования к исправлению комментариев

Задание для модели, которая выправляет комментарии проекта по правилу
«Комментарии» свода кода. Документ самодостаточен: здесь предмет, инструменты,
порядок работы, образцы переписывания, границы и критерии приёмки.

## Предмет

Комментарий описывает назначение кода: что делает функция, модуль, ветвь,
файл. Он обязан оставаться верным, когда обстоятельства его появления забыты.
Правило записано в [docs/CODE.md](docs/CODE.md), раздел «Комментарии», и в
[docs/RULE.md](docs/RULE.md), правило «Текст проекта пишется по-русски и без
служебного шума». Машиной его проверяет `scripts/check-comments.py`, классы
`C1`…`C14`; долг заморожен в `scripts/comment-baseline.txt` и расти не вправе.

Область: все отслеживаемые файлы проекта, кроме каталога `docs/`. Это
исходники, тесты, фикстуры `tests/data`, примеры `examples/`, скрипты,
конфигурации (`Cargo.toml`, `rust-toolchain.toml`, `.cargo/`, `.github/`),
плагины `extensions/`, книга `book/`, веб-часть `web/`. В документах `*.md`
комментарием считается только разметка `<!-- -->`.

## Инструменты

```bash
python3 scripts/check-comments.py
```

Проверка в режиме предкоммита: находки сверх реестра долга и протухшие записи
дают отказ.

```bash
python3 scripts/check-comments.py --list takt-lang/src/diagnostics/
```

Все находки под префиксом пути без оглядки на реестр. Так берётся в работу
один файл или каталог. Без префикса печатается весь долг.

```bash
python3 scripts/check-comments.py --update-baseline
```

Переписывает реестр по текущему состоянию дерева. Зовётся после правки:
`git diff scripts/comment-baseline.txt` обязан показывать только уменьшение
чисел и исчезновение строк. Рост числа в любой строке означает, что правка
внесла новое нарушение.

```bash
bash scripts/test-check-comments.sh
```

Самопроверка проверки. Правка самой проверки без новой пробы не принимается.

## Классы находок

| Класс | Что ловит | Что делать |
|---|---|---|
| `C1` | типографские знаки и пиктограммы | заменить на ASCII: `-`, `"`, `->`, `<-`, `...`, `<=`, `>=`, `!=` |
| `C2` | номер работы со словом-маркером | снять номер, оставить смысл |
| `C3` | по чьей просьбе сделано | снять упоминание, оставить само требование |
| `C4` | разделы «Что было», «Зачем», «Цена», «Замер» | снять раздел целиком; правило или формат из него перенести в описание |
| `C5` | жаргон: «гейт», «сторож», «фикс», «дефолт», «бэкенд», «рантайм» | проверка, тест, исправление, умолчание, генератор, время выполнения |
| `C6` | выделение прописными | строчные; выделяет слово, а не регистр |
| `C7` | код решения или теста карточки со словом или в скобках | снять код, оставить смысл |
| `C8` | отсылка к образцу заимствования | снять |
| `C9` | датированный замер, проба, прогон | снять; ссылка на стандарт остаётся |
| `C10` | номер работы голый, через дробь, после косой черты | снять; соседний код называть именем модуля или функции |
| `C11` | код карточки голый, заголовок теста `**T1.**` | снять код; заголовок теста заменить фразой о том, что тест проверяет |
| `C12` | история словами: «прежде», «первая редакция», «найдено замером», «починено», «дожило» | переписать в настоящем времени о том, что код делает |
| `C13` | происхождение модуля: «вынесено из», «по правилу размера», «упирается в лимит» | снять; оставить, за что модуль отвечает |
| `C14` | хвостовой пробел, висячий дефис перед знаком, пустая `//!` последней | убрать остаток |

## Порядок работы

1. **Каталог за каталогом, файл за файлом.** Взять каталог, напечатать его
   долг флагом `--list`, править файлы по одному, после каждого файла
   перечитать комментарий целиком: правка одной строки часто ломает абзац.
2. **Очерёдность каталогов.** Сначала код: `takt-lang/src`, `takt-sim/src`,
   `takt-wasm/src`, `web/`, затем тесты `takt-lang/tests`, `takt-sim/tests`,
   затем `scripts/` и конфигурации, затем `extensions/`. Последними идут
   `examples/`, `book/` и фикстуры `tests/data`: их комментарии уезжают в
   порождённый код и снимки, и за ними следует пересборка.
3. **Внутри файла классы правятся вместе.** Одна строка часто несёт несколько
   классов (номер, типографику, историю); переписывается предложение, а не
   отдельный знак.
4. **После каталога:** `--update-baseline`, просмотр диффа реестра, прогон
   `rustfmt --check --edition 2024` по тронутым `.rs`, коммит.
5. **Перед коммитом, затронувшим `examples/`, `book/` или `tests/data`:**
   полный `./scripts/precheck.sh`. Он пересобирает `examples/generated` на
   месте; снимки книги пересобирает `scripts/check-book-generated.sh --update`.
   Порождённые файлы руками не правятся.

## Как переписывать

Принцип: снять историю, оставить устройство. Спросить у каждого предложения,
отвечает ли оно на вопрос «что делает код» либо «по какому правилу». Всё
остальное принадлежит карточке и журналу и уже там лежит.

Было:

```
// Прямого пути у владельца нет, но корень доступен всегда - адресуем от него.
// Достижимость ветки CC-019 не установлена: единственный найденный способ
// получить None отсекается раньше кодом CC-012. Диагностика оставлена как
// отказ по умолчанию: альтернатива - вернуть неверный путь молча, то есть
// ровно тот класс дефекта, против которого заведена 0028.
```

Стало:

```
// Прямого пути у владельца нет: адрес строится цепочкой от корня, который
// владеет всем по значению. Модель вне дерева - отказ, а не неверный путь.
```

Было:

```
//! Тесты разбора аргументов подкоманды `compile` (перенесены из `bin/taktc.rs`
//! вместе с логикой - правило размера модуля, /0134).
```

Стало:

```
//! Тесты разбора аргументов подкоманды `compile`.
```

Было:

```
// Смешанная знаковость: на 64 битах C сравнивает беззнаково, и равенство
// отрицательного с беззнаковым тоже ломается - первая редакция 0359 покрыла
// лишь `<`/`>`.
```

Стало:

```
// Смешанная знаковость: отрицательное знаковое сравнивается отдельной
// проверкой, иначе C сравнивал бы его беззнаково. Правило одно на все
// операторы сравнения.
```

Было:

```
/// **T7.** Разрядность счётчика выбирает компилятор (T7 отчёта `DIFF.md`).
```

Стало:

```
/// Разрядность счётчика выбирает компилятор, а не автор модели.
```

Было:

```
// Форма выбрана прогоном (замер 2026-09-04): yosys принимает только шаблон.
```

Стало:

```
// Форма - шаблон присваивания: другую yosys не синтезирует.
```

Ссылка на стандарт остаётся как есть: `(IEEE 1800 6.5.7p5)`, `IEC 61131-3`.

## Что сохранять

- **Назначение.** Первое предложение doc-комментария функции, модуля, поля.
  Если после снятия истории от комментария не остаётся ничего, написать одно
  предложение о назначении, а не удалять комментарий.
- **Правило, формат, устройство.** «Порядок сверху вниз по файлу», «формат
  берётся у любого операнда, оба одного типа», «ширина по слову», раздел
  `# Ошибки`. Это не история, даже если рядом стояла история.
- **Обещание фикстуры.** Комментарий в `tests/data/**/*.takt` называет, что
  фикстура показывает; тест проверяет это обещание. Обещание остаётся, номера и
  история снимаются.
- **Комментарий автора примера.** В `examples/` и `book/` комментарий читает
  пользователь языка и видит в порождённом коде. Он описывает модель, а не
  проект.
- **Ссылки rustdoc**: форма ``[`имя`]`` и форма «текст в квадратных скобках,
  адрес в круглых». Путь к карточке в ссылке есть адрес, он законен.
- **Имена классов проверок** в `scripts/` (`T1`, `D2`, `N3`): проверка так
  называет свои условия, это не отсылка к карточке.
- **Имена состояний** в примерах (`S1`, `S2`).
- **Блоки примеров** внутри комментария между тройными обратными кавычками.

## Чего не делать

- **Не менять код.** Правятся только комментарии. Строковые литералы
  диагностик, имена, тесты не трогаются, даже если в них есть номер.
- **Не делать замен без границ слова.** Замена «фикс» без границ портила
  «фикстура», «префикс», «суффикс»; замена «прежде» портит «прежде чем».
  Всякая массовая замена проверяется диффом глазами.
- **Не удалять doc-комментарий целиком** из-за истории внутри него.
- **Не переносить историю** в другой комментарий, в `CHANGES.md` или в
  карточку: она там уже есть по построению.
- **Не править порождённое**: `examples/generated/**`, снимки `book/`, файлы
  `*.svg`. Правится источник, снимок пересобирается.
- **Не расширять исключения проверки** ради удобства. Новая граница правила
  обсуждается с заказчиком и получает пробу в самопроверке.
- **Не оставлять остатков**: висячего дефиса перед знаком, пустой строки `//!`
  перед `use`, хвостового пробела, предложения без точки, голой скобки `()`.
- **Не переводить историю в сослагательное наклонение.** «Иначе бы молча
  изменило выдержку» есть та же цена ошибки; остаётся правило («множитель обязан
  быть целым»).

## Особые области

- **`tests/data`.** Фикстура нередко состоит из одного комментария и модели;
  комментарий обязан по-прежнему называть обещание. Прогнать `cargo test`
  после каталога: тесты форматтера и проверки фикстур читают эти файлы.
- **`examples/*.takt`.** Комментарии переносятся в вывод семи целей.
  После правки `./scripts/precheck.sh` пересобирает `examples/generated`;
  дифф снимков обязан состоять только из комментариев.
- **`book/src`.** Комментарии Typst (`//`) и комментарии в примерах книги.
  После правки примеров: `scripts/check-book-generated.sh --update`, затем
  `make -C book build`.
- **`extensions/intellij-takt`.** Kotlin и XML; сборка вне предкоммита
  (`./gradlew --offline test` локально). Комментарии проверяются наравне.
- **Конфигурации** (`toml`, `yml`, `.cargo/config.toml`, `Makefile`,
  `Dockerfile`). Комментарий объясняет назначение ключа, а не историю его
  появления.
- **`scripts/*.txt`** реестры долга других проверок: заголовок описывает,
  что хранит реестр и как снимается запись.

## Проверка результата

После каждого каталога:

```bash
python3 scripts/check-comments.py --update-baseline
git diff --stat scripts/comment-baseline.txt
python3 scripts/check-comments.py
git diff --name-only -- '*.rs' | xargs rustfmt --check --edition 2024
```

Перед коммитом, затронувшим примеры, книгу или фикстуры:

```bash
./scripts/precheck.sh
```

## Коммиты

- Один коммит на каталог либо на класс в большом каталоге. Сообщение в форме
  прежних коммитов серии: `refactor: комментарии <область> описывают
  назначение`, в теле кратко, что снято и что возвращено.
- Без `Co-Authored-By` (решение заказчика, проверка истории). Работа не
  привязана к фиче, трейлер `Feature:` не ставится.
- Реестр долга коммитится вместе с правкой, которая его уменьшила.

## Критерии приёмки

1. Реестр долга по взятому каталогу пуст; в остальном дереве числа не выросли.
2. Предкоммит зелёный; для примеров и книги снимки пересобраны и в диффе
   только комментарии.
3. Каждый тронутый комментарий читается как описание кода: по нему можно
   понять, что делает функция или модуль, не открывая карточку.
4. В диффе нет изменений кода, строковых литералов и порождённых файлов,
   сделанных руками.
5. Слова не испорчены заменой: `git diff | grep -E 'фикс|префикс|суффикс'`
   показывает только осмысленные строки.
