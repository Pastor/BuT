Живой контекст проекта для сессий Claude Code (claude.ai/code) и других
AI-инструментов. Здесь — **только контекст** (что за проект, архитектура,
ключевые файлы, инварианты, состояние), без правил процесса.

- **Правила работы — эталон:** [`docs/RULE.md`](docs/RULE.md). Процесс = жизненный
  цикл фич; `FEATURES.md` — витрина незакрытых фич, карточки фич — в
  `docs/features/`. Плоских списков задач (`TASKS.md`/`STATUS.md`) нет.
- **Правила написания Rust-кода:** [`docs/CODE.md`](docs/CODE.md).
- **Журнал изменений:** [`CHANGES.md`](CHANGES.md) (формат Keep a Changelog).
- **Описание языка (для пользователя):** [`book/`](book/) — **Typst** → PDF
  (шрифт Fira Code), сборка `make -C book build` (нужен только `typst` ≥ 0.13;
  сборка — шаг `precheck.sh`, фича 0240). Содержит **только язык**
  (синтаксис/семантику/примеры), без деталей реализации, номеров фич и процесса
  (**правило 24**). Каждая языковая фича проходит стадию «Документирование»;
  каждый новый раздел — отдельная фича.
> **Завершение фичи → коммит + пуш (стойкое разрешение проекта).** Закончив
> работу над фичей (стадия закрытия: статус `ГОТОВО`, документы обновлены,
> `./scripts/precheck.sh` зелёный), **закоммить и запушь** изменения без
> дополнительного запроса. Это переопределяет дефолт AI-инструмента «коммить и
> пушить только по явному запросу пользователя». Сообщение коммита — по правилу
> 22 свода (`feat(NNNN): …`), **плюс трейлер `Feature: NNNN`** в конце тела
> (правило 17: номер фичи обязателен в каждом коммите — заголовок для человека,
> трейлер для машины, `git log --grep '^Feature: NNNN'`). Если `precheck.sh` не
> зелёный или фича не закрыта — **не** коммить.

## Проект

**Takt** (Typed, Automata, Known Timing) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из трёх крейтов:

- `takt-lang` — компилятор (бинарник `taktc`) и LSP-сервер (`takt-lsp`).
- `takt-sim` — симулятор моделей и GIF-визуализация.
- `takt-wasm` — привязки для браузера (фича
  [0531](docs/features/0531-web-playground.md)): те же компилятор, слой LSP и
  эталон одним модулем WebAssembly, без своего знания о языке.

**Язык сделан в учебных целях**, и его основная задача — показать принципы
**автоматного подхода к разработке**: поведение задаётся состояниями и переходами,
исполнение детерминировано и разбито на такты, из одной модели порождается код для
разных платформ, а сама модель пригодна для проверки (симуляция, инварианты, LTL).
⚠️ **При этом язык применим и ПРОМЫШЛЕННО, и отсюда вся строгость проекта**:
учебный пример, который врёт, ничему не учит, а прошивка, которая врёт, стоит
дороже — потактовые сверки, гейты чужих инструментов и запрет молчаливых
расхождений между целями держатся именно на этом.

## Команды

```sh
# Сборка
cargo build --bin taktc
cargo build --features lsp --bin takt-lsp

# Канонический форматтер .takt (фича 0024)
cargo run --bin taktc -- fmt examples/          # на месте
cargo run --bin taktc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (параллельно — фича 0190 сняла `--test-threads=1`)
cargo test
cargo test --all-features                       # включая тесты LSP
cargo test <имя>                                # один тест по имени

# Предкоммит-проверка (fmt + clippy + test + гейты целей и документа), ~330 с
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Толчейн и CI** описаны один раз — в разделе «Документ и процесс»: пин
`rust-toolchain.toml` (стабильный `1.97.1`) и прогон всего `precheck.sh` под
`PRECHECK_STRICT=1`. Здесь только то, чего там нет: `Cargo.lock` **отслеживается**
(workspace даёт бинарники, а `lalrpop` берётся из git — без lock состав
зависимостей плавает), `resolver = "3"`, MSRV `rust-version = "1.97"` в обоих
манифестах (нижняя граница не измерялась).

**Внешние зависимости** (для сборки и тестов `taktc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — гейт цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого ST (фича 0041); ставить
  руками не надо: `precheck.sh` зовёт `scripts/ensure-iec2c.sh` (≈15 с) и
  **никогда не валит предкоммит** (нет сети/bison → мягкий пропуск; переменные
  `IEC2C_PREFIX`, `IEC2C_SRC`, `IEC2C_SKIP=1`). Проверка —
  `iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st` (0 = валиден).
  ⚠️ **`-I` обязателен**: `make install` ставит только бинарники, и без
  `lib/ieclib.txt` `iec2c` падает на любом входе (скрипт копирует библиотеку сам).
  Ручные пробы — `takt-lang/tests/data/st/probes/*.st`.
## Архитектура

Конвейер компиляции: `.takt` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (НЕ нарушать)

Чек-лист перед правкой ядра. Каждый пункт подробно разобран ниже, в
«Технических подводных камнях», — здесь только имя инварианта, чтобы шесть самых
дорогих были видны вместе.

⚠️ **Связь двусторонняя и сторожится машиной**
([0289](docs/features/0289-claude-md-invariant-checklist-gate.md)): подробный
пункт несёт метку `` `[критический инвариант N]` ``, и
`scripts/check-claude-md.py` требует, чтобы номера чек-листа и метки совпадали
**в обе стороны**. Прежде запись надо было внести дважды, а забытую половину
никто не ловил — класс 0084/0193/0195, только списки не в коде, а в контексте.

1. **Условия рёбер `ref` не разрешаются** — прохода `resolve_state_references`
   не заводить (раздел «Семантика и диагностика»).
2. **`Condition` и `Expression` не унифицировать** — у них разная семантика `=`
   (там же).
3. **Присваивание `:=`, сравнение `=`, `==` из языка выведено** (там же).
4. **Адрес порта: inline `:=` < оператор `address` < внешняя карта** — вместе с
   квалификацией ключа, диапазоном бита и экспортом (раздел «Цели генерации»).
5. **Вход в стартовое состояние не расходует такт** — контракт для всех
   бэкендов (там же).
6. **Model-level `always` исполняется каждый такт** до диспетчеризации
   состояния (там же).

### Общее

- **Пути** — через `std::path::Path`, не разбивкой строк; при генерации C явно
  обрабатывай анонимную/корневую модель (имя `Root`) и пустые случаи.
- **Новые тесты** — сперва зонд для захвата реального вывода, затем проверки
  против захваченного: не угадывать строки, адреса и позиции.
- **Сторож фикстуры проверяет её ОБЕЩАНИЕ, а не факт разбора**
  ([0288](docs/features/0288-fixture-guards-audit.md)). Ратчет —
  `scripts/check-fixture-guards.py` + реестр `scripts/fixture-guard-baseline.txt`.
  ⚠️ «В дереве нет `Unresolved`» проверять нельзя (условия рёбер `ref` таковы по
  инварианту), и узел искать надо там, где он написан.
- **Параметр функции виден и при ИНДЕКСАЦИИ**
  ([0346](docs/features/0346-array-param-index.md)): ветвь `ArraySubscript`
  спрашивала только переменные модели, и `a[0]` по параметру давало `SE-003`.
  ⚠️ Параметры нужны и разбору **индекса**, и срезу; отказ приходил из семантики,
  то есть одинаково у эталона и всех восьми целей.
- **Разрешение переменных** проверяй в обоих путях — верхнеуровневый и вложенный
  доступ к модели (`tick`/`init`): починка одного часто ломает другой.
- **Поведение цели сверяется ПОТАКТОВО, а не только компилируется**
  (`takt-sim/tests/conformance_*`). ⚠️ Гейт целевого языка доказывает, что вывод
  компилируется, но не что он верен: сверку заводить вместе с бэкендом — у
  [0045](docs/features/0045-sv-backend.md) дефект приняли оба инструмента SV, у
  [0050](docs/features/0050-rust-backend.md) сверки не было вовсе.
- **Тесты идут ПАРАЛЛЕЛЬНО; каталог теста уникален по ПОТОКУ И ПРОЦЕССУ**
  ([0190](docs/features/0190-precheck-selective-gates.md),
  [0429](docs/features/0429-sv-conformance-flake.md)). Имя потока уникально лишь
  внутри процесса — каталог обязан лежать внутри `takt_pid<PID>`; сторож —
  `scripts/check-test-temp-dirs.py`. ⚠️ Покраснел параллельный прогон — чини
  каталог теста, а не возвращай `--test-threads=1`.
- **Интеграционные тесты — ОДНА цель на тему, набор внутри остаётся файлом**
  ([0244](docs/features/0244-test-target-build-cost.md),
  [0271](docs/features/0271-test-target-gate.md)): тем семь, файл темы —
  `tests/<тема>/main.rs` с одними `mod`. Сторож — `check-test-targets.py`
  (`T1`…`T3`); набор без `mod` не собирается вовсе при зелёном `cargo test`.
- **Генерация детерминирована** ([0048](docs/features/0048-deterministic-codegen.md)):
  порядок задаёт **тип контейнера** (`BTreeMap`/`BTreeSet`), а не сортировка на
  выходе. Сторож — жёсткий шаг `precheck.sh` (два прогона × все цели → `diff -r`);
  следствие — дифф `examples/generated/` несёт смысл.
- **Размер модуля** — ≤ ~1000 строк вместе с тестами (`docs/CODE.md`, фичи
  [0091](docs/features/0091-module-size-rule-in-code-md.md),
  [0261](docs/features/0261-module-size-warning-zone.md)). Гейт —
  `scripts/check-module-size.sh` (жёлтая зона 970…1000 не влияет на код возврата),
  долг — `scripts/module-size-baseline.txt` и расти он не вправе.
  ⚠️ Правя большой файл, готовься к отказу «вырос»: новое выносится в модуль.
- **Генератор фич `scripts/new-feature.sh` идемпотентен**
  ([0094](docs/features/0094-new-feature-script-fixes.md)): повторный `--register`
  не дублирует строки; регресс — `scripts/test-new-feature.sh` в предкоммите.

### Семантика и диагностика

- **Значение аргумента параметра ПОНИЖАЕТСЯ, но только вне специализации**
  ([0489](docs/features/0489-parameter-and-const-value.md)): аргумент — позиция
  приёмника (0381), и q-литерал обязан доехать представлением; прежде цели
  печатали 2 вместо 640, а `sv` отвечал `SV-002`. ⚠️ Под `specialize` значение
  понижает общий проход объявлений — двойное масштабирование даёт `SE-058`.
  ⚠️ Соседний класс шире параметров: константа `duration` не переводилась
  целью `c` (`CC-023`), пока у неё не появилась ветвь печати.

- **Параметр модели — поле экземпляра, а под `--parameters=specialize` —
  константа копии** ([0185](docs/features/0185-model-parameters.md), версия языка
  0.8.0): аргумент вычислен и понижен в литерал, за границей семантики выражения
  аргумента нет. ⚠️ Флаг меняет **форму** вывода, не поведение (сторож сверяет
  четыре трассы); проход константности стоит после специализации и до стадии 2;
  параметр там, где нужна величина сборки, — `SE-088`.
- **Ошибка разрешения оператора не зависит от глубины вложенности**
  ([0155](docs/features/0155-semantic-nested-statement-resolution.md)): ошибка
  пробрасывается `?` во **всех** телах. ⚠️ `unwrap_or_else(|_| Unresolved(…))`
  нельзя: цель `c` печатает `Unresolved` пустотой, и терялась не диагностика, а
  **сам оператор**.
- **Прерывание вне цикла — отказ `SE-132`, а не поведение**
  ([0530](docs/features/0530-break-outside-loop.md), версия языка 0.17.0):
  признак ведёт потоковый страж `semantic::loop_context` на построении тел
  циклов. ⚠️ Запись принималась МОЛЧА, и потребители расходились: эталон
  прерывал тело и проверял переходы, а `break;` внутри ветви `case` у цели `c`
  выводил управление из `switch` мимо присваивания состояния — автомат не уходил
  из состояния никогда. ⚠️ Страж снимается по `Drop`: «залипший» счётчик делает
  отказ невозможным, и на это есть контроль.
- **Глубина вложенности ограничена** `MAX_NESTING_DEPTH = 32` → `SE-062`
  ([0129](docs/features/0129-semantic-deep-nesting.md)); без предела инструменты
  падали `SIGABRT` без диагностики. ⚠️ Счётчик меряет глубину **узлов дерева**, а
  не скобок.
- **Второй предел — на разборе: `MAX_PARSE_DEPTH = 96` → `SY-005`**
  ([0156](docs/features/0156-parser-depth-limit.md)), проверка в единой точке
  `takt_lang::parse`, поэтому дерево глубже предела наружу не выходит.
  ⚠️ Предел разбора обязан быть **выше** семантического (инвариант держит
  `const _: () = assert!(…)`), а отвергнутое дерево утилизируется итеративно —
  производный `Drop` роняет процесс на ≈ 18 750 узлах.
- **Guard границ массива — по флагу, и живёт он в СЕМАНТИКЕ**
  ([0433](docs/features/0433-array-bounds-guard.md)): `--bounds-check` оборачивает
  оператор проверкой, признак уходит в порт `bounds_fault`, печатники целей не
  трогаются. ⚠️ Умолчание — выключено (решение заказчика); нижняя граница — только
  у знакового индекса; эталон обязан получить тот же проход.
- **ФОРМА обёртки guard зависит от оператора, а сам guard идёт ПОСЛЕ подстановки**
  ([0466](docs/features/0466-matrix-build-scenarios.md)): `return` получает возврат
  умолчания (носитель `semantic::default_value`), объявление остаётся снаружи с
  умолчанием. ⚠️ Проход обязан обновить **оба** представления функции (владелец и
  ячейка вызова — класс 0184); порядок «форма, затем защита» держит эвристику 0444.
- **Сценарии сборки перебираются СОЧЕТАНИЯМИ флагов**
  ([0466](docs/features/0466-matrix-build-scenarios.md)): шесть проб × семь
  сценариев × восемь целей; пять классов невалидного вывода жили там, где каждый
  флаг по отдельности проходил. ⚠️ Корпус матрицы 0450 флагам безразличен (замер:
  295 случаев × три флага — ноль находок), потому у оси свои пробы.
- **Применимость флага к ЦЕЛИ решает одна таблица**
  (`compile_cli::target_flags`, [0466](docs/features/0466-matrix-build-scenarios.md)):
  `--bus=apb` у `sv` отказывал, а у `rust` и `plantuml` принимался **молча** —
  рапорт об успехе на невыполненной просьбе. ⚠️ Отказ цели (`SV-019`) остаётся
  защитой в глубину: через библиотечный API CLI не участвует.
- **Проверка границ смотрит на ЗНАЧЕНИЕ, а не на форму записи**
  ([0434](docs/features/0434-const-index-bounds.md)): `d[K]` при `const K := 5`
  судится так же, как `d[5]` (значение константы известно — 0192). ⚠️ Переменная
  под правило не подпадает (guard по флагу — 0433); поле у значения, которое
  структурой не является, — `SE-030`.

  родами сообщений (неизвестно против ошибки записи). Дробное, длительность и
  агрегаты остаются эталону.
- **Приведение `as` вычисляется при компиляции, ПОКА оно тождественно**
  ([0286](docs/features/0286-sv-const-initializer-expression.md)): значение целое,
  тип целочисленный, значение помещается (границы — `literal_range::type_range`).
  ⚠️ Правила изменения значения принадлежат **эталону**, копии их в `takt-lang`
  быть не должно — отсюда узость (`300 as u8` невычислимо).
- **Вычисленный инициализатор НОРМИРУЕТСЯ по типу объявления, литерал автора — нет**
  ([0207](docs/features/0207-bitwise-not-unsigned-literal.md), версия языка 0.9.0):
  беззнаковое — обёртка, знаковое — `SE-089`; различает их свёртка (`is_literal`).
  ⚠️ Границы — у одного носителя `validate::literal_range::type_range`.
- **Инициализатор `var`/`const` доезжает до потребителей ЛИТЕРАЛОМ**
  ([0192](docs/features/0192-const-init-fold.md)): свёртку делает
  `semantic/const_eval/`, имя в инициализаторе значит **начальное значение** и
  ссылается только назад. ⚠️ Порядок трёх шагов: разрешить → вывести типы →
  свернуть; значение запоминается всегда; послабление «имя вычислимо» живёт в
  `const_eval::Locals`, а не в `resolve_name`.
- **Операция константного вычисления живёт в ОДНОЙ таблице — `int_ops`**
  ([0208](docs/features/0208-const-evaluators-unification.md),
  [0407](docs/features/0407-const-power-fold.md)): знака, которого в ней нет,
  свёртка не считает, и узел доезжает до целей неразвёрнутым. ⚠️ Семантика операции
  берётся у того, кто её задал (степень — 0328); язык **адресов** знак не
  наследует; сторож — тождественность выводу для готового литерала.
- **Обходы по числу состояний — итеративные, не рекурсивные**
  ([0052](docs/features/0052-verify-iterative-traversal.md)): рекурсия роняла
  инструмент `SIGABRT`; сторож — `deep_model_tests.rs`. ⚠️ `expand` в `buchi.rs`
  рекурсивен осознанно; `outer_dfs` делает работу после потомков — нарушение
  постпорядка даёт неверный вердикт.

### Типы и представление

- **Носитель числового значения — `i128`; граница приёма литерала — ТИПЫ языка**
  ([0157](docs/features/0157-literal-u64-representation.md)): приём —
  `[i64::MIN, u64::MAX]`, вне — `LE-009` (`parser/literal_range.rs`). ⚠️ Носитель
  шире приёма намеренно: промежуточный результат не должен переполняться. Значение
  варианта перечисления — тот же `i128`; адрес порта остался `i64` (`SE-055`).
- **Литерал вне диапазона типа приёмника — `SE-089`**
  ([0157](docs/features/0157-literal-u64-representation.md),
  `semantic/validate/literal_range.rs`): проверяются позиции с объявленным типом,
  накопительно. ⚠️ `bit`/`bool` пропущены намеренно (их судит `validate_bit_values`);
  проверяется **литерал**, не значение выражения.
- **Печать широкого литерала зависит от цели**
  ([0157](docs/features/0157-literal-u64-representation.md)): `c` — суффикс `ULL`
  выше `LLONG_MAX`, `sv` — размерная форма по ширине приёмника (иначе `WIDTHEXPAND`
  уже с 33 бит), прочие — как есть. ⚠️ Особая форма печатается только по нужде —
  иначе поедут снапшоты `examples/generated/`.
- **`[bit;N]` — упакованный вектор** ([0078](docs/features/0078-bit-array-semantics.md)):
  скаляр при N ≤ 64, массив `uint64_t[⌈N/64⌉]` при N > 64; правило — в едином слое
  `semantic::bit_vector`.
- **Разряд за ОБЪЯВЛЕННОЙ шириной — `SE-125`**
  ([0394](docs/features/0394-bit-beyond-declared-width.md)): ширина — контракт,
  раскладка по словам — деталь представления; проверка живёт в существующем обходе
  доступа к члену, в **обеих** ветвях (выражений и условий). ⚠️ «Переменного
  индекса» тут нет: `w.idx` есть поле; выражение без выводимого типа остаётся с
  `SIM-011`.
- **`q(m, n)` В ПАРАМЕТРЕ функции опознаёт СЕМАНТИКА, а не грамматика**
  ([0380](docs/features/0380-fixed-point-parameter.md)): тип параметра грамматика
  хранит выражением, и `q(8, 8)` приходит вызовом; непохожая форма — `SE-034`, а не
  воронка `SE-119`. ⚠️ Вторым слоем вскрылось: Q-хелперы `st` печатались после
  пользовательских `FUNCTION` — вызов шёл раньше объявления.
- **Fixed-point `q(m, n)`: арифметика ПОБИТОВО едина** у симулятора и всех целей
  ([0061](docs/features/0061-fixed-point-type.md),
  [0061-01](docs/fixes/0061-01-q-wrap-storage-width.md)); эталон —
  `takt-sim/src/eval/fixed.rs`, `*` — floor к −∞, `/` — к нулю. ⚠️ У `c` floor —
  хелпером, не `>>` (сдвиг знакового implementation-defined); **перенос идёт к
  `W = m + n`**, а не к ширине хранения — три цели на `q(6, 6)` давали 38.0 против
  −26.0.
- **Насыщение — свойство ТИПА: `q(m, n) sat` прижимает, `q(m, n)` переносит**
  ([0170](docs/features/0170-fixed-point-saturation.md)): признак — поле типа,
  смешение запрещает `SE-059`, слово, отличное от `sat`, — `SE-104`. ⚠️ Прижатие
  идёт **до** сужения (у `sv` промежуток в `2W`), и насыщение эмитится всегда, в
  отличие от переноса.
- **q-ЛИТЕРАЛ понижается в представление ВЕЗДЕ, где известен приёмник**
  ([0381](docs/features/0381-fixed-literal-in-body.md),
  [0382](docs/features/0382-fixed-literal-in-place.md)): присваивание, сравнение,
  аргумент, возврат, локальное объявление, условие ребра. ⚠️ Приёмник — **место**,
  а не имя (поле и элемент тоже), тип даёт `base_type` (0358); проход стоит после
  стадии 6; арифметика в объём не входит (`SE-059`).
- **Прозрачный `float` через глобальную Q-точность**
  ([0096](docs/features/0096-fixed-point-native-float.md)): автор пишет `float`,
  представление выбирают `--float-as-q=m.n` / `--float-embedded` — осознанное
  исключение из «CLI не меняет логику». ⚠️ `VariableNode` живёт в **двух**
  представлениях (owned и `Rc<RefCell>` тела) — проход обязан мутировать оба `ty`;
  литерал понижается только в инициализаторе, проход идемпотентен.
- **Раскрытие условия сторожит КОНТРОЛЬ ЗНАЧЕНИЯ, а не факт компиляции**
  ([0476](docs/features/0476-matrix-named-conditions.md)): в выводе обязано быть
  значение условия и не быть его имени. ⚠️ Мутация «печатать `true`» даёт
  ВАЛИДНЫЙ вывод с другим автоматом — инструмент цели её не видит; ⚠️ у `st`
  охранной формулы в выводе нет (`ST-022`), и там раскрытия не бывает.
- **`formula` цели ПРОПУСКАЮТ, тело `assembly` печатает ЦЕЛЬ ПО ИМЕНИ**
  ([0484](docs/features/0484-target-blocks-semantics.md), версия языка 0.15.0):
  имя — язык вывода, режим сборки — `SE-129`; без имени печатают все и
  исполняет эталон. ⚠️ Отбор живёт в СЕМАНТИКЕ (`target_block::prune`):
  признак использования цели не знает, и чужая вставка в дереве давала у `c`
  печать без объявления, а её отсутствие — ложное `SE-036`. ⚠️ Эталон
  исполняет только безымянную — иначе вердикт зависел бы от цели.
- **Места блоков ВЫРОВНЕНЫ: уровень модели, состояния и любое тело**
  ([0518](docs/features/0518-block-places-alignment.md), решение заказчика):
  своей семантики выравнивание не вводит — вставка разворачивается в блок
  `always` СВОЕГО уровня, формула пропускается. ⚠️ Место задаёт МОМЕНТ
  исполнения (уровень модели — каждый такт, включая терминальное состояние);
  подмена уровня даёт валидный вывод и другое поведение, сторож — сверка.
  ⚠️ Новые узлы АСД валят сборку в слоях использований, стиля, символов LSP.

- **Именованное условие в ТЕЛЕ печатается тем же печатником, что на ребре**
  ([0331](docs/features/0331-named-condition-in-body.md)): `if ready { … }` давал
  пять ответов, у цели `c` — ссылку на неопределённый идентификатор при нулевом
  коде возврата. ⚠️ Своего разбора условия не заводить; у `rust` понадобилась вторая
  правка — `expression_type` не знал `Condition`.
- **Массив КОПИРУЕТСЯ поэлементно и когда справа переменная**
  ([0490](docs/features/0490-array-copy.md)): `a := b;` печаталось целиком, и
  `cc`/`iec2c` вывод отвергали при нулевом коде возврата. ⚠️ Разворот берёт
  ТОЛЬКО переменную: результат вызова индексировать нельзя (0431) — первая
  редакция это сломала. ⚠️ Структура в объём не входит (замер: её присваивают
  целиком и C, и IEC); константа-массив у `c` объявляется `static const`.

- **Присваивание АГРЕГАТА печатается поэлементно у `st` и `sv`**
  ([0330](docs/features/0330-aggregate-assignment.md)): агрегатной формы в IEC нет
  вовсе, а шаблон `'{…}` у `sv` работает лишь в ветви сброса. ⚠️ Класс найден
  **чтением текстов отказов**: два обещали давно закрытые задачи; сверка берёт
  разные значения по элементам и меняет их по тактам.
- **Операнды степени у цели `rust` печатаются С ОГЛЯДКОЙ НА ПРИЁМНИК**
  ([0415](docs/features/0415-rust-power-operands.md)): база-литерал получает суффикс,
  приведение показателя — по нужде; тип доезжает полем `Scope::power_target`.
  ⚠️ Позиций приёмника **пять** ([0418](docs/features/0418-rust-power-receiver-positions.md)),
  тест перечисляет их и падает списком; разворот в умножения отвергнут семантикой.
- **Целую степень переводят ВСЕ восемь целей**
  ([0329](docs/features/0329-power-in-rust-sv.md)): `rust` печатает `wrapping_pow`
  (обычный `pow` паникует при переполнении), `sv` разворачивает в умножения при
  литеральном показателе. ⚠️ Расширение цели ломает чужие сторожа — тест 0308 брал
  `**` как пример непереводимого.
- **Целая степень `**` считается ЦЕЛЫМИ**
  ([0328](docs/features/0328-integer-power.md)): у `c` — хелпер `takt_ipow`, у `st` —
  разворот в умножения (оператор IEC определён над вещественным). ⚠️ Прежде `3 ** 40`
  давало 12157665459056928768 против …801 у эталона; широкий тип в сверке
  обязателен — на `u8` `double` точен.
- **Сдвиг на ширину типа цель `rust` печатает НАСЫЩЕННЫМ**
  ([0326](docs/features/0326-rust-shift-width.md)): `>> (ширина − 1)` для знакового,
  `0` для беззнакового. ⚠️ `wrapping_shr` не годится — маскирует величину (`8 % 8`);
  переменная величина не трогается (граница названа).
- **Знак и ширина перечисления считаются общим слоем** `semantic::enum_facts`
  ([0060](docs/features/0060-enum-width-shared-layer.md)); ⚠️ знак обязан дойти и до
  **значения** ([0423](docs/features/0423-sv-signed-enum.md)): `sv` печатал
  `logic signed`, а вариант — `4'd-5`, чего `verilator` не разбирает; отрицательное
  печатается `-W'sdN`, положительное форму не меняет.
- **У структуры обязано быть хотя бы одно поле — `SE-115`**
  ([0284](docs/features/0284-empty-struct-semantics.md)): язык принимал, а вывод не
  принимали чужие инструменты (`cc -pedantic`, `iec2c`), эталон исполнял.
  ⚠️ Квантификатор грамматики оставлен намеренно — правило языка не должно быть
  свойством LR-разбора (урок 0172).
- **У перечисления обязан быть хотя бы один вариант — `SE-105`, и судит СЕМАНТИКА**
  ([0172](docs/features/0172-empty-enum-semantics.md)): прежде отвергала грамматика,
  то есть правило языка было свойством квантификатора. ⚠️ Отказ стоит на
  **объявлении**: при использовании сообщение вырождалось в `SE-043` с пустым
  списком; порядок сообщений задаёт `diagnostics::normalize` по позиции.
- **Структуры переводят ВСЕ цели, и форма агрегата у каждой своя**
  ([0293](docs/features/0293-struct-in-st-rust.md)): `c` — `struct`, `st` —
  `TYPE … STRUCT`, `sv` — `typedef struct packed` с конкатенацией, `rust` — литерал.
  ⚠️ Именованную форму SV отвергает yosys (verilator принимает); `Eq` не выводится
  (поле `float`); запись в поле делает переменную `let mut`; порядок полей — у
  объявления.
- **Член РЕЗУЛЬТАТА вызова поднимается во временную — в семантике**
  ([0431](docs/features/0431-array-function-return.md),
  [0432](docs/features/0432-call-result-field.md)): подъём живёт в общем модуле с
  разворотом среза (0400), печатники целей о форме не знают. ⚠️ Индексация поднимает
  только составной результат, обращение к члену — любой; у `sv` невалидный RTL
  видел только yosys.
- **Массив как ВОЗВРАТ функции: у `st` именованный тип, у `sv` — `typedef`**
  ([0431](docs/features/0431-array-function-return.md)): обе цели печатали файл,
  который отвергают их же инструменты, при нулевом коде возврата; `c` отказывает
  `CC-015` (в C массив из функции не возвращают). ⚠️ Формы выбраны прогоном
  инструментов, а не чтением стандарта.
- **СРЕЗ массива печатается поэлементно, и пригодность операндов решает носитель**
  `semantic/slice/` ([0355](docs/features/0355-array-slice-in-targets.md)): границы
  — полуинтервал `[l, r)`, литералы, выход за край — `SE-029`. ⚠️ Пригодны **оба**
  операнда (срез бит-вектора и срез в скалярный приёмник давали невалидный вывод);
  координату отказу даёт `site::at`.
- **Агрегат-ЛИТЕРАЛ в аргументе поднимается во временную**
  ([0493](docs/features/0493-aggregate-argument.md)): `pick({1, 2})` у `c`
  давал невалидный вывод, у `st`/`sv` — отказ. ⚠️ Тип временной берётся у
  ОБЪЯВЛЕНИЯ функции, а форма — объявление без инициализатора плюс
  присваивание (агрегат в инициализаторе переводят не все цели). ⚠️ Контроль
  обязателен: аргумент-ПЕРЕМЕННАЯ переводился всеми и до правки.

- **Срез в АРГУМЕНТЕ вызова разворачивается в семантике**
  ([0400](docs/features/0400-slice-in-call-argument.md)): проход заводит временную
  и присваивание — печатники целей о форме не знают. ⚠️ Форма выбрана замером
  (объявление с инициализатором не переводит никто); имя обязано быть
  идентификатором целевых языков и проверяться на занятость.
- **Подстановка тела функции живёт в СЕМАНТИКЕ, а эталон её не делает**
  ([0444](docs/features/0444-function-inlining.md), версия языка 0.14.0).
  Атрибут `[inline]`/`[noinline]` действует всегда, эвристика (тело ≤ 5
  операторов, 1…3 вызова) — по флагу `--inline=auto`. ⚠️ Эталон проход не зовёт
  **намеренно**: иначе сверка перестала бы видеть дефект подстановки (урок
  0300). ⚠️ Переименование идёт **по имени**, не по ячейке: у параметра своя
  `Rc` на каждое употребление. ⚠️ Хвостовой `return` становится объявлением
  **с инициализатором** — иначе `rust` даёт `needless_late_init` (0410).
- **РАННИЙ возврат подставляется через признак выхода, и форму выбрал замер**
  ([0446](docs/features/0446-inline-early-return.md),
  [0447](docs/features/0447-inline-return-in-loop.md)): результат объявляется
  **с начальным значением** (без него `rustc` — `E0381`), хвостовой возврат
  признак не взводит, обёртка **сливается** с условием (иначе `collapsible_if`,
  фикс 0446-01). Цикл: тело гасится признаком, **условие не трогается** — любая
  его правка ломает разворот у `sv`; `loop`/`while` остаются `SE-128`. ⚠️ Признак
  статических границ — общий с `sv` (`semantic::loop_bounds`, 0321).
- **Неиспользуемая функция не печатается ВСЕМИ четырьмя целями**
  ([0445](docs/features/0445-st-unused-function.md)): признак общий —
  `UsageSet::functions`; у `st` фильтра не было, и мёртвый POU оставался в
  программе ПЛК. ⚠️ `iec2c` такой файл принимает — гейт цели класса не видел;
  вызов из условия ребра считается использованием (сторож на это обязателен).
- **ВЛОЖЕННЫЙ агрегат раскрывается ДО ЛИСТЬЕВ одним носителем, а форму адресации
  собирает ЦЕЛЬ** ([0366](docs/features/0366-nested-aggregate-carrier.md)):
  `aggregate::leaves` отдаёт путь шагами (`Index`/`Field`). ⚠️ Готовую строку
  носитель вернуть не может; у `sv` поле структуры внутри массива отвергается
  (yosys объявляет защёлку); бит-вектор `[bit;N≤64]` — лист.
- **Присваивание АГРЕГАТА: место записи выбирает один носитель**
  `generator/aggregate.rs` ([0340](docs/features/0340-aggregate-assign-place.md)):
  массив по индексу, структура по имени поля, в порядке объявления; носитель
  принимает **поля**, а не модель. ⚠️ Позиций агрегата **четыре**: присваивание,
  инициализация, элемент массива структур (0343), локальное объявление (0345).
- **Константа-АГРЕГАТ печатается тем же путём, что переменная**
  ([0347](docs/features/0347-const-aggregate.md)): `coerce_to` у `rust`,
  `reset_value` у `sv`. ⚠️ У `sv` дефектов было два — типы печатались после
  констант, и verilator отвечал «Reference … before declaration».
- **Умолчание значения у цели `rust` строит ОДИН носитель, а `derive(Default)`
  печатается по нужде** ([0351](docs/features/0351-rust-default-value-types.md)):
  `default_value` знает `duration`, `q(m, n)` и структуру. ⚠️ `derive` выводится не
  всегда (перечисление, массив длиннее 32), а печатать `impl Default` всегда нельзя
  — `clippy::derivable_impls`; неверное умолчание `q` поймала только сверка.
- **Структуры печатаются в порядке ЗАВИСИМОСТЕЙ, и это один носитель**
  `generator/struct_order.rs` ([0341](docs/features/0341-nested-struct-order.md)):
  алфавитный порядок давал отказ `cc`, `iec2c` и verilator при нулевом коде
  возврата. ⚠️ Сортировка на выходе у `st` снята (разрушала порядок); цикл структур
  носитель переживает, но не диагностирует.
- **Значение в ПОЛЕ структуры печатается по типу ПОЛЯ, а перечисления у `sv`
  объявляются первыми** ([0492](docs/features/0492-enum-in-struct-field.md)):
  `conf.mode := Run;` печаталось числом — `E0308` у `rust`, `ENUMVALUE` у `sv`.
  ⚠️ Тип поля спрашивается там, где видно объявление (снимок карты у `sv`,
  модель `Scope` у `rust`): общий `expression_type` о полях не знает и честно
  отвечает `None`. ⚠️ Дефект `sv` двухслойный — порядок скрывал `ENUMVALUE`.

- **Структурные типы**: объявленный **порядок полей значим**, инициализатор `{…}`
  позиционный ([0034](docs/features/0034-sim-struct-types.md)); доступ — общий
  `eval/access.rs::read_member`, запись — `eval/place.rs::update`. ⚠️ Сравнение
  структур — `TypeMismatch` (C запрещает `==`, «умный» эталон врал бы); доступ к
  несуществующему полю — `SE-061`.
- **Массивы `[T;N]` исполняются симулятором** ([0076](docs/features/0076-sim-arrays.md)):
  запись элемента и запись поля структуры — единый сегментный механизм «места»;
  границы и вид → `SIM-010`.
- **Константная выдержка `after` вычисляется на СЕМАНТИКЕ и до целей не доезжает**
  ([0143](docs/features/0143-after-const-duration.md)): все формы дают один узел
  `After(нс)`, вычислитель — `semantic/condition/after_const.rs`, прочее → `SE-072`
  с названной причиной. ⚠️ Аргумент живёт в грамматике условий (`*`, `/`, `as` там
  нет), скобки хранятся в дереве; сторож — тождественность вывода литеральной форме.
- **Выдержка от ПЕРЕМЕННОЙ `duration` расширяется до `u64` у цели `rust`**
  ([0459](docs/features/0459-matrix-time-profiles.md)): метка времени — `u64`
  (`now_ms`), а `duration` в целях 32-битный, и `rustc` отвечал `E0308` при
  нулевом коде возврата. ⚠️ Расширять надо **выражение**, а не усекать метку:
  усечение сдвинуло бы переполнение счётчика. Класс виден лишь в сочетании
  «профиль часы + переменная» — оттого его и нашёл перебор.
- **Машинную ширину скалярного порта считает ОДИН носитель**
  ([0488](docs/features/0488-scalar-port-width.md)): `semantic::scalar_port` —
  целое, `duration`, `q(m, n)`, перечисление; имена типов строит цель.
  ⚠️ `bit`/`bool` целым НЕ считаются: у целей это своя категория порта
  (`write_bit`, `%QX`). ⚠️ Точная ширина — другой носитель
  (`sv_type::scalar_width`): аппаратной цели важен занятый разряд, прочим —
  машинный тип.

- **Порт типа `duration` — тоже скаляр, и ширину даёт ОДИН носитель**
  ([0487](docs/features/0487-duration-port.md)): `duration::VALUE_BITS`,
  единица границы — миллисекунда (0183). ⚠️ `SV-002` «ширина не определена»
  приходил от ВТОРОЙ копии таблицы ширин у `sv-mmio` — она снята, скаляры
  считает `sv_type::scalar_width`. ⚠️ Пересчёт нс → мс сторожит сверка
  значений: ошибись он, вывод остался бы валидным, а прошивка ждала бы не тот
  интервал.

- **Порт ПЕРЕЧИСЛИМОГО типа — скаляр, его переводят все восемь целей**
  ([0485](docs/features/0485-enum-port.md)): ширину и знак даёт `enum_facts`,
  у `st-at` это локация `AT %QB`. ⚠️ У `rust` значение пересекает HAL дважды:
  уходит `as u8`, приходит через `from_repr` — ПО НУЖДЕ (признак — факт чтения,
  не направление) и ТОТАЛЬНО (число вне набора → первый вариант, 0391).
  ⚠️ Путей печати записи ДВА — такт и начальное значение порта; оба дефекта
  правки поймала матрица целей 0450, корпус их не покрывает.

- **Тип `duration` в целях — целое в МИЛЛИСЕКУНДАХ; выдержка бывает вычисляемой**
  ([0183](docs/features/0183-duration-type-in-targets.md),
  [0215](docs/features/0215-duration-per-tick-conformance-st-sv.md)): пересчёт —
  только `semantic::duration::value_millis`. ⚠️ Вычисляемая выдержка требует
  множителя `hertz / 1000` (нецелый — `SE-073`); ширина счётчика — 32 бита; четыре
  обхода по `ConditionNode` кончаются `_ =>` и компилятором не охраняются.

- **Образцы ветви `match` печатаются ЗАПЯТОЙ, как их принимает грамматика**

- **Позиция бита однобитного порта нормируется в слое адресов**
  ([0176](docs/features/0176-bit-port-address-position.md)): адрес без позиции →

- **ТИП выведенного объявления берётся у ОБЪЯВЛЕННОГО операнда, а не у литерала**
  ([0287](docs/features/0287-wider-type-array-literal.md)): `wider_type` не знала

- **Тип операнда приведения знает ПОЛЕ структуры, и ядро спуска ОДНО**
  ([0371](docs/features/0371-fixed-cast-from-field.md),

  носители не сводятся (на литерале, разряде, сравнении они отвечают по-разному) —
  `rust` оставлен со своим; та же запись над переменной печаталась верно.
- **Понижение q-литерала доходит и до ПОЛЕЙ структуры**
  ([0370](docs/features/0370-struct-field-fixed.md)): границу создавала сигнатура
  помощника, а не устройство — снятие заняло один параметр. ⚠️ Сверка обязана смотреть

- **Элемент агрегата несёт ТИП ЭЛЕМЕНТА — и при понижении, и при печати**
  ([0368](docs/features/0368-aggregate-element-type.md)): корней три — понижение

- **Дробная арифметика в инициализаторе: ТОЧНОЕ считается, округляемое — `SE-114`**

- **Инициализатор объявления не читает НЕОПРЕДЕЛЁННУЮ память: `SE-099` (ячейка) и

  ([0189](docs/features/0189-anonymous-ports.md)): `#A:B as T` — поле разрядности `T`

  ([0189](docs/features/0189-anonymous-ports.md), решение 6A): присваивание и вызов;

  ([0458](docs/features/0458-matrix-address-maps.md)): порт и оператор стоят на

- **Экспорт карты — `taktc address-map --emit map|json`**

- **Порты под-моделей композиции драйвятся**
  ([0079](docs/features/0079-sim-composition-ports.md)): `PortNames::from_model`
  обходит `model.models` рекурсивно. ⚠️ Правки требовало **перечисление**, а не
  чтение/запись.
- **Порт адресуется квалифицированно** `Модель::порт`
  ([0135](docs/features/0135-sim-qualified-port-names.md)); голое имя работает как
  прежде. ⚠️ Квалификатор — имя модели, а не путь: две под-модели с одинаковым именем
  неразличимы.
- **Режимы ЭТАЛОНА проверяются сплошь и ответом инструмента**
  ([0461](docs/features/0461-matrix-simulator.md)): девять случаев — трасса
  либо код диагностики. ⚠️ На эталоне стоят все сверки: ошибись он, они
  окажутся зелёными при неверном ответе. ⚠️ Значения портов **удерживаются**
  между тактами, guard шага останавливает прогон, а умолчание границ совпадает
  с умолчанием целей (`SIM-010`).
- **Длину прогона задаёт `-n`, а сценарий — ВХОДЫ**
  ([0523](docs/features/0523-sim-scenario-run-length.md)): после последнего шага
  сценария прогон продолжается с удержанными значениями (правило 0132, доведённое
  до конца). ⚠️ Прежде сценарий обрывал прогон, и выдержку в 180 000 тактов нельзя
  было показать, не заведя файл той же длины; исход `StepsExhausted` при этом был
  мёртв. ⚠️ Без `-n` длину по-прежнему задаёт сценарий; стенд `extern` держится
  последним заданным.
- **Сценарий пишется именами портов**
  ([0132](docs/features/0132-sim-named-port-scenarios.md),
  [0150](docs/features/0150-sim-positional-scenario-deprecation.md)): неизвестное имя
  → `SIM-030`, двусмысленное → `SIM-031`, позиционная форма устарела (`SIM-037`, раз
  за прогон) и держится гейтом `check-positional-scenarios.py`. ⚠️ Код диагностики
  обязан быть отдельным литералом — вплавленный в текст невидим гейту кодов; значения
  портов удерживаются между тактами.
- **ОБЛАСТЬ инварианта состояния сторожит СВЕРКА, и она двусторонняя**
  ([0475](docs/features/0475-matrix-invariant-sites.md)): стой проверка в общем
  теле, вывод целей был бы валиден, а прошивка падала бы там, где эталон
  считает дальше. ⚠️ Проверять только «не срабатывает вне состояния» мало —
  это верно и при отсутствии проверки; ⚠️ понизить границу мало: автомат уходит
  дальше раньше, чем условие нарушится.
- **Инварианты проверяются** ([0044](docs/features/0044-sim-assert-invariant.md)):
  `invariant Имя = C;` — сахар над `cond` + `Formula::Guard`, нарушение →
  `TickResult::Failed` + `SIM-025`; мягкий режим записывает и продолжает. ⚠️ Ошибка
  **вычисления** условия — `Failed` в обоих режимах; в сверке с C мягкий режим не
  участвует.
- **Сценарии примеров проверяются прогоном** (`examples_scenario_tests.rs`): у каждого
  `examples/*.takt` обязан быть либо контракт (цепочка + бюджет + завершение), либо
  исключение **с причиной**.

### Верификация

- **Вердикты верификации проверяются СПЛОШЬ и вердиктом, а не структурой**
  ([0460](docs/features/0460-matrix-verification.md)): двенадцать случаев с
  названным ответом (держится / нарушено + контрпример / не проверено +
  причина). ⚠️ Пара «условный ↔ безусловный `ref`» стоит в наборе намеренно:
  при условном `F Done` **нарушено** (самопетля), при безусловном — держится;
  это и есть цена абстракции. Мутация «убрать самопетлю» роняет набор.
- **Абстракция управляющего графа** ([0049](docs/features/0049-model-checking-ltl.md)):
  атом = имя состояния, условия рёбер абстрагированы; «держится» надёжно, «нарушено»
  может быть ложным. ⚠️ Самопетлю получает всякое состояние без **безусловного**
  `ref` — иначе Крипке недо-аппроксимация и ложный `Holds`; ошибаться только в сторону
  лишних прогонов. ⚠️ Тесты верификации пиши **на вердикт**, а не на структуру
  автомата (фикс [0010-01](docs/fixes/0010-01-buchi-acceptance.md)); область формулы —
  по месту объявления ([0051](docs/features/0051-verify-scope.md)).
- **Домен перечисления в верификации ищется ПОДЪЁМОМ к родителям**
  ([0497](docs/features/0497-verify-enum-domain.md)): `enum` объявляют рядом с
  моделями, и карта самой модели его не содержит — предикат отвергался
  причиной, которую тот же вывод опровергал строкой ниже. ⚠️ Ветвь
  `DomainNotEnumerable` НЕ защитная, как считал замер 0258: она достижима.
  ⚠️ Сторож обязан спрашивать вердикт у ВЛОЖЕННОЙ модели — иначе мутация
  проходит.

- **Домен типа и его отслеживаемость — ОДИН носитель `verification::domain`**
  ([0498](docs/features/0498-verify-bit-vector-domain.md)): «перечислим ли тип» и
  «какие у него значения» — один вопрос; пока ответчиков было два, они разъехались
  и дали ложную причину (0497). ⚠️ `[bit;N≤64]` — скаляр, а не массив (0078): его
  верификатор отвергал, тогда как `u8` того же представления проверял; домен — по
  ОБЪЯВЛЕННОЙ ширине (`[bit;3]` — восемь значений), и это видно в вердикте.
  ⚠️ `duration` в охват не входит намеренно (домен 2³²), но причина его называет.
- **ПАРАМЕТР модели в предикате — постоянная величина**
  ([0517](docs/features/0517-verify-parameter-domain.md), решение заказчика):
  домен из одного значения — умолчания, поэтому задачу он не растит. Прежде
  `ticks < limit` при `parameter limit` давал «за потолком», а тот же вход с
  `const` — «держится». ⚠️ Признак — `ParameterNode::mutated` (0185), умолчание
  «изменяемый»: параметр с присваиванием остаётся свободной переменной, и на это
  есть контроль. ⚠️ Вердикт относится к сборке С УМОЛЧАНИЕМ — сказано в `book/`.
- **Свойства над данными — абстракция по формуле**
  ([0068](docs/features/0068-verify-data-properties.md)): отслеживаются только
  переменные из φ, ход данных полностью недетерминирован — `Holds` надёжен,
  `Violated` над меняющимися данными почти всегда возможно ложный. ⚠️ Наивный
  explicit-state неосуществим (у `elevator` вершина имеет 3.7·10⁵⁰ преемников);
  сторож направления — `abstracted_source_yields_extra_run_not_missed`.
- **Потолок верификации по данным считается по РЁБРАМ**
  ([0145](docs/features/0145-verify-vertex-budget.md)): `EDGE_LIMIT = 1_000_000`
  против `max(E, V) × D²` — работа идёт по рёбрам, а они растут квадратично по
  доменам. ⚠️ Метрику выбрал замер (по вершинам время расходилось в 2000 раз);
  потолок один, и `max` делает это свойством кода; сторож на взрыв рёбер **виснет, а
  не падает** — второй тест на ту же формулу удалять нельзя.
- **Вердикт-отказ НАЗЫВАЕТ причину, и носитель текста один**
  ([0258](docs/features/0258-verify-unsupported-reason.md)):
  `Verdict::Unsupported { atoms, reason }`, текст даёт `UnsupportedReason::text()` —
  его берут CLI и экспорт графа. ⚠️ Ветвь `DomainNotEnumerable` недостижима (отсекается
  подмножеством предикатов) и оставлена защитной; текст проверяется прогоном
  инструмента.

### Документ и процесс

  **не** версия крейта `takt-lang` (`CARGO_PKG_VERSION`, сейчас `0.60.0`).
- **Релиз и тег выпускает АВТОМАТИКА при подъёме минорной версии языка**

- **Подъём версии языка помечается тегом, и у правила есть сторож**

  последний раздел гоняет инструменты целей; нет арбитра — печатается «пропуск»,
  никогда «принял». Контрольный вход и дата замера — на человеке.
- **Реестр стадии СВЕРЯЕТСЯ с диском, и пропуск в нём слепит соседний гейт**
  ([0164](docs/features/0164-registry-rebuild-gate.md)): `scripts/check-registries.py`
  сверяет файлы папки-стадии с реестром **в обе стороны** (`R0`…`R2`). ⚠️ Гейт, чью
  проверку обходит отсутствие записи, не гейт: `check-registry-verdicts.py` проверяет
  **строки**, и без записи вердикт не проверялся вовсе.
- **Разбор в приложении даётся по НАЗВАННОМУ признаку**
  ([0398](docs/features/0398-diagnostics-detailed-analysis.md), решение заказчика):

  инструмент; гейт — `scripts/check-diagnostic-analysis.py`. ⚠️ Признак читает
  **реестр**, а не исходники: реестр и есть каталог смыслов.

  ([0311](docs/features/0311-diagnostic-descriptions.md)): гейт
  `scripts/check-diagnostic-descriptions.py` — `D1` (служебное слово, **без

- **Комментарий шага `precheck.sh` объясняет ШАГ, правило живёт в заголовке гейта**

> уедет в эвристику без областей видимости (сторож `testDeclarationIsNotRenamableNatively`).

## Форматтер

Ядро печати — `takt-lang/src/format/` (`format_source`), потребители: `taktc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`; `precheck.sh` проверяет канон
`examples/` (фикстуры `tests/data/` намеренно не нормализованы). Правило «добавил
узел АСД — добавь его печать» — во врезке раздела «Добавление конструкции языка».

⚠️ **Канон описан словами** — раздел «Стиль кода» документа
([0197](docs/features/0197-language-code-style.md)). Машинной сверки «текст ↔
форматтер» нет и в общем виде быть не может, поэтому фича, меняющая `taktc fmt`,
**обязана** проверить этот раздел: цена измерена фиксом
[0197-01](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md) — смена трёх правил
затронула **пять** записей канона.

**Раскладка — K&R** (фикс 0197-01): `} else {`, цепочка плоская. Склейку делает
`Out::join` — снимает поставленный `'\n'` и взводит `glued`, из-за которого
следующая `line` идёт без отступа. ⚠️ Флаг нужен потому, что заголовок звена печатает
рекурсивный `stmt::print`, не знающий, что его позвали из ветки `else`.

**Перечисление и структура печатаются по элементу на строке** (фиксы 0197-01,
[0198-01](docs/fixes/0198-01-struct-comment-placement.md)). ⚠️ Висячей запятой быть
не должно — напечатанная запятая делает файл неразбираемым, а `fmt` пишет на месте.
⚠️ Варианты печатаются `node_line_within(…, brace)` с границей по байту самой `}`:
`loc` записи покрывает её целиком, и без границы хвостовой комментарий забрал бы
первый вариант, а печать перестала бы быть идемпотентной.

**Ведущие комментарии оператора выдаёт ОДНА точка — `stmt::print`**
([0406](docs/features/0406-format-comment-before-block.md)): прежде их выдавал только
`Out::node_line`, а он печатает неблочные операторы — комментарий перед `if`/`while`
всплывал первой строкой **тела**. ⚠️ `node_line` для заголовка не годится: позиция
блочного оператора покрывает и тело. ⚠️ Ветвь `else` зовёт `print_inner` — выдача в
ждущую продолжения строку рвёт K&R.

**Закрывающая скобка тела печатается ОДНОЙ функцией `close_body`**
([0295](docs/features/0295-format-element-comment-binding.md)): комментарий последней
строкой тела принадлежит **этому** телу, иначе его подхватывает следующий элемент.
⚠️ Класс правился трижды в трёх ветках, и замер нашёл его живым ещё в двух; сторож
двухслойный — поведение по **отступу** (порядок строк дефект не ловит) и греп по
`format/mod.rs`, падающий списком.

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД хранит
выбор автора (`ast::LoopKeyword`, `Guard::explicit`), семантика эти признаки
игнорирует.

**Форма записи ЧИСЛА принадлежит автору** ([0463](docs/features/0463-format-number-form.md)):
`0xF0` не превращается в `240`, разделитель разрядов сохраняется. Печать идёт
**по исходнику** через позицию узла (в АСД она есть), а не хранением основания в
токене — `Number` самый частый узел языка. ⚠️ Значение **сверяется**: разойдись
позиция с текстом, напечаталось бы чужое число; при несовпадении печатается
десятичное, то есть прежнее поведение. ⚠️ Носитель исходника потоковый —
сброс обязателен на всех путях выхода (печать вынесена в замыкание).
