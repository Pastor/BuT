# CLAUDE.md — контекст проекта Takt

Живой контекст проекта для сессий Claude Code (claude.ai/code) и других
AI-инструментов. Здесь — **только контекст** (что за проект, архитектура,
ключевые файлы, инварианты, состояние), без правил процесса.

- **Правила работы — эталон:** [`docs/RULE.md`](docs/RULE.md). Процесс = жизненный
  цикл фич; `FEATURES.md` — витрина незакрытых фич, карточки фич — в
  `docs/features/`. Плоских списков задач (`TASKS.md`/`STATUS.md`) нет.
- **Правила написания Rust-кода:** [`docs/CODE.md`](docs/CODE.md).
- **Журнал изменений:** [`CHANGES.md`](CHANGES.md) (формат Keep a Changelog).
- **Описание языка (для пользователя):** [`book/`](book/) — **Typst** → PDF
  (шрифт Fira Code), сборка `make -C book build` (нужен только `typst` ≥ 0.13;
  сборка — шаг `precheck.sh`). Содержит **только язык**
  (синтаксис/семантику/примеры), без деталей реализации, номеров фич и процесса. Каждая языковая фича проходит стадию «Документирование»;
  каждый новый раздел — отдельная фича.
> **Завершение фичи → коммит + пуш (стойкое разрешение проекта).** Закончив
> работу над фичей (стадия закрытия: статус `ГОТОВО`, документы обновлены,
> `./scripts/precheck.sh` зелёный), **закоммить и запушь** изменения без
> дополнительного запроса. Это переопределяет умолчание AI-инструмента «коммить и
> пушить только по явному запросу пользователя». Сообщение коммита — по правилу
> 22 свода (`feat(NNNN): …`), **плюс трейлер `Feature: NNNN`** в конце тела
> (номер фичи обязателен в каждом коммите — заголовок для человека,
> трейлер для машины, `git log --grep '^Feature: NNNN'`). Если `precheck.sh` не
> зелёный или фича не закрыта — **не** коммить.

## Проект

**Takt** (Typed, Automata, Known Timing) — DSL для спецификации и синтеза конечных
автоматов (FSM) промышленных систем управления. Цели генерации: `c`/`c-hal`
(прошивка МК), `st`/`st-at` (ПЛК, IEC 61131-3), `rust` (`no_std`), **`sv`**
(синтезируемый SystemVerilog — FPGA/ASIC) и `plantuml` (диаграмма).
Rust-workspace из трёх крейтов:

- `takt-lang` — компилятор (бинарник `taktc`) и LSP-сервер (`takt-lsp`).
- `takt-sim` — симулятор моделей и GIF-визуализация.
- `takt-wasm` — привязки для браузера ([онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](docs/features/0531-web-playground.md)): те же компилятор, слой LSP и
  эталон одним модулем WebAssembly, без своего знания о языке.

**Язык сделан в учебных целях**, и его основная задача — показать принципы
**автоматного подхода к разработке**: поведение задаётся состояниями и переходами,
исполнение детерминировано и разбито на такты, из одной модели порождается код для
разных платформ, а сама модель пригодна для проверки (симуляция, инварианты, LTL).
**При этом язык применим и промышленно, и отсюда вся строгость проекта**:
учебный пример, который врёт, ничему не учит, а прошивка, которая врёт, стоит
дороже — потактовые сверки, проверки чужих инструментов и запрет молчаливых
расхождений между целями держатся именно на этом.

## Команды

```sh
# Сборка
cargo build --bin taktc
cargo build --features lsp --bin takt-lsp

# Канонический форматтер .takt (фича 0024)
cargo run --bin taktc -- fmt examples/          # на месте
cargo run --bin taktc -- fmt --check examples/  # проверка для CI (код ≠ 0 при отличии)

# Тесты (параллельно — фича 0190 сняла `--test-threads=1`)
cargo test
cargo test --all-features                       # включая тесты LSP
cargo test <имя>                                # один тест по имени

# Предкоммит-проверка (fmt + clippy + test + гейты целей и документа), ~330 с
./scripts/precheck.sh

# Прогон всех симуляций из examples/simulations/
./scripts/run_simulations.sh
```

**Толчейн и CI** описаны один раз — в разделе «Документ и процесс»: пин
`rust-toolchain.toml` (стабильный `1.97.1`) и прогон всего `precheck.sh` под
`PRECHECK_STRICT=1`. Здесь только то, чего там нет: `Cargo.lock` **отслеживается**
(workspace даёт бинарники, а `lalrpop` берётся из git — без lock состав
зависимостей плавает), `resolver = "3"`, MSRV `rust-version = "1.97"` в обоих
манифестах (нижняя граница не измерялась).

**Внешние зависимости** (для сборки и тестов `taktc` не нужны — только для
проверки порождённого кода):

- `cmake` + `ninja` + `cc` — проверка цели `c` в `precheck.sh`.
- **MatIEC `iec2c`** — арбитр валидности порождённого ST; ставить
  руками не надо: `precheck.sh` зовёт `scripts/ensure-iec2c.sh` (≈15 с) и
  **никогда не валит предкоммит** (нет сети/bison → мягкий пропуск; переменные
  `IEC2C_PREFIX`, `IEC2C_SRC`, `IEC2C_SKIP=1`). Проверка —
  `iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st` (0 = валиден).
  **`-I` обязателен**: `make install` ставит только бинарники, и без
  `lib/ieclib.txt` `iec2c` падает на любом входе (скрипт копирует библиотеку сам).
  Ручные пробы — `takt-lang/tests/data/st/probes/*.st`.
## Архитектура

Конвейер компиляции: `.takt` → **лексер** (`parser/lexer.rs`) → **парсер**
(LALRPOP LR(1), `grammar.lalrpop`) → AST (`parser/ast.rs`) → **семантика**
(7 проходов, `semantic/`) → **генераторы** C (`generator/c/`) и PlantUML
(`generator/plantuml/`). Верификация свойств — `verification/` (LTL, автоматы Бюхи).

### Семантические проходы (по порядку)

| Проход | Файл | Назначение |
|---|---|---|
| 0 | `tree.rs` | Имена моделей/состояний, загрузка импортов |
| 1 | `tree.rs` | Составные состояния (`M1 + M2`, `M1 \| M2`) |
| 2 | `type_inference.rs` | Переменные, вывод типов, порты |
| 3 | `tree.rs` | Именованные условия (`cond`) |
| 4 | `tree.rs` | Именованные блоки (`enter`/`exit`/`always`) |
| 5 | `tree.rs` | Тела функций |
| 6 | `tree.rs` | Замена `Condition::Unresolved` разрешёнными условиями |

### Критические инварианты (не нарушать)

Чек-лист перед правкой ядра. Каждый пункт подробно разобран ниже, в
«Технических подводных камнях», — здесь только имя инварианта, чтобы шесть самых
дорогих были видны вместе.

**Связь двусторонняя и контролируется машиной**
([чек-лист критических инвариантов — вторая точка сопровождения](docs/features/0289-claude-md-invariant-checklist-gate.md)): подробный
пункт несёт метку `` `[критический инвариант N]` ``, и
`scripts/check-claude-md.py` требует, чтобы номера чек-листа и метки совпадали
**в обе стороны**. Прежде запись надо было внести дважды, а забытую половину
никто не ловил, только списки не в коде, а в контексте.

1. **Условия рёбер `ref` не разрешаются** — прохода `resolve_state_references`
   не заводить (раздел «Семантика и диагностика»).
2. **`Condition` и `Expression` не унифицировать** — у них разная семантика `=`
   (там же).
3. **Присваивание `:=`, сравнение `=`, `==` из языка выведено** (там же).
4. **Адрес порта: inline `:=` < оператор `address` < внешняя карта** — вместе с
   квалификацией ключа, диапазоном бита и экспортом (раздел «Цели генерации»).
5. **Вход в стартовое состояние не расходует такт** — контракт для всех
   генераторов (там же).
6. **Model-level `always` исполняется каждый такт** до диспетчеризации
   состояния (там же).

## Технические подводные камни

> Формат пункта ([сокращение живого контекста CLAUDE.md](docs/features/0180-claude-md-context-diet.md)):
> **инвариант** → чем платим за нарушение → **контроль** → ссылка на разбор.
> История находки, отвергнутые варианты и замеры живут в артефактах стадий
> (разделы «Архитектура (ADR)», «Анализ», «Отчёт о тестировании» карточки
> фичи — свод), а не здесь — свод.

### Общее

- **Пути** — через `std::path::Path`, не разбивкой строк; при генерации C явно
  обрабатывай анонимную/корневую модель (имя `Root`) и пустые случаи.
- **Новые тесты** — сперва зонд для захвата реального вывода, затем проверки
  против захваченного: не угадывать строки, адреса и позиции.
- **Контроль фикстуры проверяет её обещание, а не факт разбора**
  ([фикстуры контролируются проверкой «разбирается без ошибок»](docs/features/0288-fixture-guards-audit.md)). Ратчет —
  `scripts/check-fixture-guards.py` + реестр `scripts/fixture-guard-baseline.txt`.
  «В дереве нет `Unresolved`» проверять нельзя (условия рёбер `ref` таковы по
  инварианту), и узел искать надо там, где он написан.
- **Параметр функции виден и при индексации**
  ([индексация параметра-массива внутри функции](docs/features/0346-array-param-index.md)): ветвь `ArraySubscript`
  спрашивала только переменные модели, и `a[0]` по параметру давало `SE-003`.
  Параметры нужны и разбору **индекса**, и срезу; отказ приходил из семантики,
  то есть одинаково у эталона и всех восьми целей.
- **Разрешение переменных** проверяй в обоих путях — верхнеуровневый и вложенный
  доступ к модели (`tick`/`init`): починка одного часто ломает другой.
- **Поведение цели сверяется потактово, а не только компилируется**
  (`takt-sim/tests/conformance_*`). Проверка целевого языка доказывает, что вывод
  компилируется, но не что он верен: сверку заводить вместе с генератором — у
  [генератор генерации в SystemVerilog](docs/features/0045-sv-backend.md) дефект приняли оба инструмента SV, у
  [генератор генерации в Rust](docs/features/0050-rust-backend.md) сверки не было вовсе.
- **Тесты идут параллельно; каталог теста уникален по потоку И процессу**
  ([разделение предкоммита на компоненты и выборочный запуск](docs/features/0190-precheck-selective-gates.md),
  [разовое падение сверки sv осталось необъяснённым](docs/features/0429-sv-conformance-flake.md)). Имя потока уникально лишь
  внутри процесса — каталог обязан лежать внутри `takt_pid<PID>`; контроль —
  `scripts/check-test-temp-dirs.py`. Покраснел параллельный прогон — чини
  каталог теста, а не возвращай `--test-threads=1`.
- **Интеграционные тесты — одна цель на тему, набор внутри остаётся файлом**
  ([стоимость тестовых целей: 147 бинарников — 65.6 % времени предкоммита](docs/features/0244-test-target-build-cost.md),
  [файл в tests/ верхнего уровня молча возвращает стоимость цели](docs/features/0271-test-target-gate.md)): тем семь, файл темы —
  `tests/<тема>/main.rs` с одними `mod`. Контроль — `check-test-targets.py`
  (`T1`…`T3`); набор без `mod` не собирается вовсе при зелёном `cargo test`.
- **Генерация детерминирована** ([детерминированная генерация кода (единый порядок эмиссии)](docs/features/0048-deterministic-codegen.md)):
  порядок задаёт **тип контейнера** (`BTreeMap`/`BTreeSet`), а не сортировка на
  выходе. Контроль — жёсткий шаг `precheck.sh` (два прогона × все цели → `diff -r`);
  следствие — дифф `examples/generated/` несёт смысл.
- **Размер модуля** — ≤ ~1000 строк вместе с тестами (`docs/CODE.md`, [правило о размере модуля живёт не в своде правил кода](docs/features/0091-module-size-rule-in-code-md.md),
  [проверка размера модуля молчит до отказа: жёлтой зоны нет](docs/features/0261-module-size-warning-zone.md)). Проверка —
  `scripts/check-module-size.sh` (жёлтая зона 970…1000 не влияет на код возврата),
  долг — `scripts/module-size-baseline.txt` и расти он не вправе.
  Правя большой файл, готовься к отказу «вырос»: новое выносится в модуль.
- **Генератор фич `scripts/new-feature.sh` идемпотентен**
  ([доработка `scripts/new-feature.sh` (статус ADR, поздние стадии, идемпотентность)](docs/features/0094-new-feature-script-fixes.md)): повторный `--register`
  не дублирует строки; регресс — `scripts/test-new-feature.sh` в предкоммите.

### Семантика и диагностика

- **Значение аргумента параметра понижается, но только вне специализации**
  ([значение параметра модели и константы особых типов](docs/features/0489-parameter-and-const-value.md)): аргумент — позиция
  приёмника (0381), и q-литерал обязан доехать представлением; прежде цели
  печатали 2 вместо 640, а `sv` отвечал `SV-002`. Под `specialize` значение
  понижает общий проход объявлений — двойное масштабирование даёт `SE-058`.
  Соседний класс шире параметров: константа `duration` не переводилась
  целью `c` (`CC-023`), пока у неё не появилась ветвь печати.

- **Параметр модели — поле экземпляра, а под `--parameters=specialize` —
  константа копии** ([параметризация моделей (ключевое слово `parameter`)](docs/features/0185-model-parameters.md), версия языка
  0.8.0): аргумент вычислен и понижен в литерал, за границей семантики выражения
  аргумента нет. Флаг меняет **форму** вывода, не поведение (контроль сверяет
  четыре трассы); проход константности стоит после специализации и до стадии 2;
  параметр там, где нужна величина сборки, — `SE-088`.
- **Ошибка разрешения оператора не зависит от глубины вложенности**
  ([семантическое разрешение тел вложенных операторов](docs/features/0155-semantic-nested-statement-resolution.md)): ошибка
  пробрасывается `?` во **всех** телах. `unwrap_or_else(|_| Unresolved(…))`
  нельзя: цель `c` печатает `Unresolved` пустотой, и терялась не диагностика, а
  **сам оператор**.
- **Прерывание вне цикла — отказ `SE-132`, а не поведение**
  ([`SE-132` — прерывание вне цикла](docs/features/0530-break-outside-loop.md), версия языка 0.17.0):
  признак ведёт потоковый страж `semantic::loop_context` на построении тел
  циклов. Запись принималась молча, и потребители расходились: эталон
  прерывал тело и проверял переходы, а `break;` внутри ветви `case` у цели `c`
  выводил управление из `switch` мимо присваивания состояния — автомат не уходил
  из состояния никогда. Страж снимается по `Drop`: «залипший» счётчик делает
  отказ невозможным, и на это есть контроль.
- **Глубина вложенности ограничена** `MAX_NESTING_DEPTH = 32` → `SE-062`
  ([устранение переполнения стека на глубине выражений и операторов](docs/features/0129-semantic-deep-nesting.md)); без предела инструменты
  падали `SIGABRT` без диагностики. Счётчик меряет глубину **узлов дерева**, а
  не скобок.
- **Второй предел — на разборе: `MAX_PARSE_DEPTH = 96` → `SY-005`**
  ([ограничение глубины вложенности на уровне лексера/парсера](docs/features/0156-parser-depth-limit.md)), проверка в единой точке
  `takt_lang::parse`, поэтому дерево глубже предела наружу не выходит.
  Предел разбора обязан быть **выше** семантического (инвариант держит
  `const _: () = assert!(…)`), а отвергнутое дерево утилизируется итеративно —
  производный `Drop` роняет процесс на ≈ 18 750 узлах.
- **Guard границ массива — по флагу, и живёт он в семантике**
  ([проверка границ массива: статическая диагностика и guard в порождённом коде по флагу](docs/features/0433-array-bounds-guard.md)): `--bounds-check` оборачивает
  оператор проверкой, признак уходит в порт `bounds_fault`, печатники целей не
  трогаются. Умолчание — выключено (решение заказчика); нижняя граница — только
  у знакового индекса; эталон обязан получить тот же проход.
- **Форма обёртки guard зависит от оператора, а сам guard идёт после подстановки**
  ([сценарии сборки и флаги CLI в переборе](docs/features/0466-matrix-build-scenarios.md)): `return` получает возврат
  умолчания (носитель `semantic::default_value`), объявление остаётся снаружи с
  умолчанием. Проход обязан обновить **оба** представления функции (владелец и
  ячейка вызова); порядок «форма, затем защита» держит эвристику 0444.
- **Сценарии сборки перебираются сочетаниями флагов**
  ([сценарии сборки и флаги CLI в переборе](docs/features/0466-matrix-build-scenarios.md)): шесть проб × семь
  сценариев × восемь целей; пять классов невалидного вывода жили там, где каждый
  флаг по отдельности проходил. Корпус матрицы 0450 флагам безразличен (замер:
  295 случаев × три флага — ноль находок), потому у оси свои пробы.
- **Применимость флага к цели решает одна таблица**

  вперёд разрешается проходами 0204); порт и вызов функции остаются законными.
- **Длина агрегата сверяется с объявлением: `SE-123`**
  ([длина агрегата сверяется с объявлением](docs/features/0320-aggregate-length-check.md)) — одна проверка на массив
  и структуру. Запрет, а не нормирование: усечь, расширить или отказать — три
  разных языка, а порядок элементов значим (0034).
- **Приведение агрегата к массиву вычисляется, тип элемента разрешается `target_of`**
  ([приведение агрегата к массиву вычисляется при компиляции](docs/features/0319-array-cast-folding.md)). `ast_type_to_node_ctx` не
  знает имён `u8`…`i64`  — без `target_of` ветвь не срабатывает ни на
  одном входе; элементы приводятся правилом целого (0310).
- **Мост «число ↔ длительность» считает компилятор, обе стороны**
  ([приведение к `duration` и обратно вычисляется при компиляции](docs/features/0318-duration-cast-folding.md)): единица — миллисекунда,
  пересчёт делает `semantic::duration`, своего деления в вычислителе нет.
  Переполнение судит правило целого (`SE-121`, 0310).
- **Приведение литерала к `q(m, n)` считает компилятор, и в теле тоже**
  ([приведение дробного литерала к `q(m, n)` в теле](docs/features/0383-fixed-cast-literal-in-body.md),
  [приведение имени константы к `q(m, n)`](docs/features/0384-fixed-cast-const.md)): цели зовут
  `const_eval::fixed_literal`. Свернуть узел в дереве нельзя (проверки идут после
  понижения, и `q * Number` ловит `SE-059`); свёртка переносит отказ — константа
  становится неиспользованной, и `rust` под `-D warnings` отвечает отказом.
- **Представление `q(m, n)` считается одним носителем**
  ([правило представления `q(m, n)` — общий носитель](docs/features/0317-fixed-cast-shared-layer.md)):
  `const_eval::fixed_repr` (масштаб на 2ⁿ, floor к −∞, перенос либо насыщение по
  `W = m + n`), `takt-sim::eval::fixed` зовёт его. Свести приведение к литералу
  нельзя: авторский литерал обязан быть точным (`SE-058`), приведение округляет;
  счёт точный (`Decimal`), результат возвращается литералом.
- **Целочисленное приведение считается одним носителем у компилятора и эталона**
  ([правило целочисленного приведения — общий носитель](docs/features/0310-int-cast-shared-layer.md)):
  `const_eval::int_cast::integer`, его же зовёт `takt-sim::eval`. Знаковое
  переполнение — `SE-121`, а не «не константа»; вычислитель отвечает **двумя**
  родами сообщений (неизвестно против ошибки записи). Дробное, длительность и
  агрегаты остаются эталону.
- **Приведение `as` вычисляется при компиляции, пока оно тождественно**
  ([цель sv отвергает вычислимое выражение в инициализаторе](docs/features/0286-sv-const-initializer-expression.md)): значение целое,
  тип целочисленный, значение помещается (границы — `literal_range::type_range`).
  Правила изменения значения принадлежат **эталону**, копии их в `takt-lang`
  быть не должно — отсюда узость (`300 as u8` невычислимо).
- **Вычисленный инициализатор нормируется по типу объявления, литерал автора — нет**
  ([отрицание ~0 для беззнакового типа: два правила языка столкнулись](docs/features/0207-bitwise-not-unsigned-literal.md), версия языка 0.9.0):
  беззнаковое — обёртка, знаковое — `SE-089`; различает их свёртка (`is_literal`).
  Границы — у одного носителя `validate::literal_range::type_range`.
- **Инициализатор `var`/`const` доезжает до потребителей литералом**
  ([константное выражение в инициализаторе объявления](docs/features/0192-const-init-fold.md)): свёртку делает
  `semantic/const_eval/`, имя в инициализаторе значит **начальное значение** и
  ссылается только назад. Порядок трёх шагов: разрешить → вывести типы →
  свернуть; значение запоминается всегда; послабление «имя вычислимо» живёт в
  `const_eval::Locals`, а не в `resolve_name`.
- **Операция константного вычисления живёт в одной таблице — `int_ops`**
  ([три константных вычислителя компилятора живут порознь](docs/features/0208-const-evaluators-unification.md),
  [степень в инициализаторе константы не сворачивается](docs/features/0407-const-power-fold.md)): знака, которого в ней нет,
  свёртка не считает, и узел доезжает до целей неразвёрнутым. Семантика операции
  берётся у того, кто её задал (степень — 0328); язык **адресов** знак не
  наследует; контроль — тождественность выводу для готового литерала.
- **Обходы по числу состояний — итеративные, не рекурсивные**
  ([итеративные обходы — снятие потолка стека](docs/features/0052-verify-iterative-traversal.md)): рекурсия роняла
  инструмент `SIGABRT`; контроль — `deep_model_tests.rs`. `expand` в `buchi.rs`
  рекурсивен осознанно; `outer_dfs` делает работу после потомков — нарушение
  постпорядка даёт неверный вердикт.

### Типы и представление

- **Носитель числового значения — `i128`; граница приёма литерала — типы языка**
  ([представление числового литерала: полная маска `[bit;64]`](docs/features/0157-literal-u64-representation.md)): приём —
  `[i64::MIN, u64::MAX]`, вне — `LE-009` (`parser/literal_range.rs`). Носитель
  шире приёма намеренно: промежуточный результат не должен переполняться. Значение
  варианта перечисления — тот же `i128`; адрес порта остался `i64` (`SE-055`).
- **Литерал вне диапазона типа приёмника — `SE-089`**
  ([представление числового литерала: полная маска `[bit;64]`](docs/features/0157-literal-u64-representation.md),
  `semantic/validate/literal_range.rs`): проверяются позиции с объявленным типом,
  накопительно. `bit`/`bool` пропущены намеренно (их судит `validate_bit_values`);
  проверяется **литерал**, не значение выражения.
- **Печать широкого литерала зависит от цели**
  ([представление числового литерала: полная маска `[bit;64]`](docs/features/0157-literal-u64-representation.md)): `c` — суффикс `ULL`
  выше `LLONG_MAX`, `sv` — размерная форма по ширине приёмника (иначе `WIDTHEXPAND`
  уже с 33 бит), прочие — как есть. Особая форма печатается только по нужде —
  иначе поедут снапшоты `examples/generated/`.
- **`[bit;N]` — упакованный вектор** ([семантика `[bit;N]` расходится втрое](docs/features/0078-bit-array-semantics.md)):
  скаляр при N ≤ 64, массив `uint64_t[⌈N/64⌉]` при N > 64; правило — в едином слое
  `semantic::bit_vector`.
- **Разряд за объявленной шириной — `SE-125`**
  ([разряд за объявленной шириной бит-вектора принимают молча](docs/features/0394-bit-beyond-declared-width.md)): ширина — контракт,
  раскладка по словам — деталь представления; проверка живёт в существующем обходе
  доступа к члену, в **обеих** ветвях (выражений и условий). «Переменного
  индекса» тут нет: `w.idx` есть поле; выражение без выводимого типа остаётся с
  `SIM-011`.
- **`q(m, n)` В параметре функции опознаёт семантика, а не грамматика**
  ([fixed-point в параметре функции](docs/features/0380-fixed-point-parameter.md)): тип параметра грамматика
  хранит выражением, и `q(8, 8)` приходит вызовом; непохожая форма — `SE-034`, а не
  воронка `SE-119`. Вторым слоем вскрылось: Q-хелперы `st` печатались после
  пользовательских `FUNCTION` — вызов шёл раньше объявления.
- **Fixed-point `q(m, n)`: арифметика побитово едина** у симулятора и всех целей
  ([fixed-point Q(m.n) как тип языка](docs/features/0061-fixed-point-type.md),
  [перенос `q(m, n)` идёт к ширине хранения, а не к `W`](docs/fixes/0061-01-q-wrap-storage-width.md)); эталон —
  `takt-sim/src/eval/fixed.rs`, `*` — floor к −∞, `/` — к нулю. У `c` floor —
  хелпером, не `>>` (сдвиг знакового implementation-defined); **перенос идёт к
  `W = m + n`**, а не к ширине хранения — три цели на `q(6, 6)` давали 38.0 против
  −26.0.
- **Насыщение — свойство типа: `q(m, n) sat` прижимает, `q(m, n)` переносит**
  ([насыщение (saturation) для fixed-point `q(m, n)`](docs/features/0170-fixed-point-saturation.md)): признак — поле типа,
  смешение запрещает `SE-059`, слово, отличное от `sat`, — `SE-104`. Прижатие
  идёт **до** сужения (у `sv` промежуток в `2W`), и насыщение эмитится всегда, в
  отличие от переноса.
- **q-литерал понижается в представление везде, где известен приёмник**
  ([понижение q-литерала в телах и условиях](docs/features/0381-fixed-literal-in-body.md),
  [понижение q-литерала в поле структуры и элементе массива](docs/features/0382-fixed-literal-in-place.md)): присваивание, сравнение,
  аргумент, возврат, локальное объявление, условие ребра. Приёмник — **место**,
  а не имя (поле и элемент тоже), тип даёт `base_type` (0358); проход стоит после
  стадии 6; арифметика в объём не входит (`SE-059`).
- **Прозрачный `float` через глобальную Q-точность**
  ([q-арифметика через нативный float и флаг генерации (embedded ↔ float)](docs/features/0096-fixed-point-native-float.md)): автор пишет `float`,
  представление выбирают `--float-as-q=m.n` / `--float-embedded` — осознанное
  исключение из «CLI не меняет логику». `VariableNode` живёт в **двух**
  представлениях (owned и `Rc<RefCell>` тела) — проход обязан мутировать оба `ty`;
  литерал понижается только в инициализаторе, проход идемпотентен.
- **Раскрытие условия контролирует контроль значения, а не факт компиляции**
  ([именованные условия во всех местах — в переборе](docs/features/0476-matrix-named-conditions.md)): в выводе обязано быть
  значение условия и не быть его имени. Мутация «печатать `true`» даёт
  валидный вывод с другим автоматом — инструмент цели её не видит; у `st`
  охранной формулы в выводе нет (`ST-022`), и там раскрытия не бывает.
- **`formula` цели пропускают, тело `assembly` печатает цель по имени**
  ([семантика блоков formula и assembly в телах: пропуск и вставка по цели](docs/features/0484-target-blocks-semantics.md), версия языка 0.15.0):
  имя — язык вывода, режим сборки — `SE-129`; без имени печатают все и
  исполняет эталон. Отбор живёт в семантике (`target_block::prune`):
  признак использования цели не знает, и чужая вставка в дереве давала у `c`
  печать без объявления, а её отсутствие — ложное `SE-036`. Эталон
  исполняет только безымянную — иначе вердикт зависел бы от цели.
- **Места блоков выровнены: уровень модели, состояния и любое тело**
  ([места блоков `formula` и `assembly` выровнены](docs/features/0518-block-places-alignment.md), решение заказчика):
  своей семантики выравнивание не вводит — вставка разворачивается в блок
  `always` Своего уровня, формула пропускается. Место задаёт момент
  исполнения (уровень модели — каждый такт, включая терминальное состояние);
  подмена уровня даёт валидный вывод и другое поведение, контроль — сверка.
  Новые узлы АСД валят сборку в слоях использований, стиля, символов LSP.

- **Именованное условие в теле печатается тем же печатником, что на ребре**
  ([именованное условие в теле переводят все цели](docs/features/0331-named-condition-in-body.md)): `if ready { … }` давал
  пять ответов, у цели `c` — ссылку на неопределённый идентификатор при нулевом
  коде возврата. Своего разбора условия не заводить; у `rust` понадобилась вторая
  правка — `expression_type` не знал `Condition`.
- **Массив копируется поэлементно и когда справа переменная**
  ([копирование массива целиком: переменная и константа справа](docs/features/0490-array-copy.md)): `a := b;` печаталось целиком, и
  `cc`/`iec2c` вывод отвергали при нулевом коде возврата. Разворот берёт
  только переменную: результат вызова индексировать нельзя (0431) — первая
  редакция это сломала. Структура в объём не входит (замер: её присваивают
  целиком и C, и IEC); константа-массив у `c` объявляется `static const`.

- **Присваивание агрегата печатается поэлементно у `st` и `sv`**
  ([присваивание агрегата массива в целях `st` и `sv`](docs/features/0330-aggregate-assignment.md)): агрегатной формы в IEC нет
  вовсе, а шаблон `'{…}` у `sv` работает лишь в ветви сброса. Класс найден
  **чтением текстов отказов**: два обещали давно закрытые задачи; сверка берёт
  разные значения по элементам и меняет их по тактам.
- **Операнды степени у цели `rust` печатаются С оглядкой на приёмник**
  ([цель `rust`: печать операндов степени не проходит её же проверка](docs/features/0415-rust-power-operands.md)): база-литерал получает суффикс,
  приведение показателя — по нужде; тип доезжает полем `Scope::power_target`.
  Позиций приёмника **пять** ([цель `rust`: тип приёмника доезжает до степени во всех позициях](docs/features/0418-rust-power-receiver-positions.md)),
  тест перечисляет их и падает списком; разворот в умножения отвергнут семантикой.
- **Целую степень переводят все восемь целей**
  ([цели `rust` и `sv` переводят целую степень](docs/features/0329-power-in-rust-sv.md)): `rust` печатает `wrapping_pow`
  (обычный `pow` паникует при переполнении), `sv` разворачивает в умножения при
  литеральном показателе. Расширение цели ломает чужие контроля — тест брал
  `**` как пример непереводимого.
- **Целая степень `**` считается целыми**
  ([целая степень считается целочисленно](docs/features/0328-integer-power.md)): у `c` — хелпер `takt_ipow`, у `st` —
  разворот в умножения (оператор IEC определён над вещественным). Прежде `3 ** 40`
  давало 12157665459056928768 против …801 у эталона; широкий тип в сверке
  обязателен — на `u8` `double` точен.
- **Сдвиг на ширину типа цель `rust` печатает насыщенным**
  ([сдвиг на ширину типа в цели `rust`](docs/features/0326-rust-shift-width.md)): `>> (ширина − 1)` для знакового,
  `0` для беззнакового. `wrapping_shr` не годится — маскирует величину (`8 % 8`);
  переменная величина не трогается (граница названа).
- **Знак и ширина перечисления считаются общим слоем** `semantic::enum_facts`
  ([расчёт ширины перечисления — вынести в общий слой](docs/features/0060-enum-width-shared-layer.md)); знак обязан дойти и до
  **значения** ([цель `sv`: отрицательное значение варианта перечисления](docs/features/0423-sv-signed-enum.md)): `sv` печатал
  `logic signed`, а вариант — `4'd-5`, чего `verilator` не разбирает; отрицательное
  печатается `-W'sdN`, положительное форму не меняет.
- **У структуры обязано быть хотя бы одно поле — `SE-115`**
  ([структура без полей](docs/features/0284-empty-struct-semantics.md)): язык принимал, а вывод не
  принимали чужие инструменты (`cc -pedantic`, `iec2c`), эталон исполнял.
  Квантификатор грамматики оставлен намеренно — правило языка не должно быть
  свойством LR-разбора.
- **У перечисления обязан быть хотя бы один вариант — `SE-105`, и судит семантика**
  ([семантика перечисления без вариантов](docs/features/0172-empty-enum-semantics.md)): прежде отвергала грамматика,
  то есть правило языка было свойством квантификатора. Отказ стоит на
  **объявлении**: при использовании сообщение вырождалось в `SE-043` с пустым
  списком; порядок сообщений задаёт `diagnostics::normalize` по позиции.
- **Структуры переводят все цели, и форма агрегата у каждой своя**
  ([структуры не транслируются целями st и rust дальше объявления](docs/features/0293-struct-in-st-rust.md)): `c` — `struct`, `st` —
  `TYPE … STRUCT`, `sv` — `typedef struct packed` с конкатенацией, `rust` — литерал.
  Именованную форму SV отвергает yosys (verilator принимает); `Eq` не выводится
  (поле `float`); запись в поле делает переменную `let mut`; порядок полей — у
  объявления.
- **Член результата вызова поднимается во временную — в семантике**
  ([массив как возврат функции: st и sv порождают невалидный вывод](docs/features/0431-array-function-return.md),
  [доступ к полю результата вызова: st и sv порождают невалидный вывод](docs/features/0432-call-result-field.md)): подъём живёт в общем модуле с
  разворотом среза (0400), печатники целей о форме не знают. Индексация поднимает
  только составной результат, обращение к члену — любой; у `sv` невалидный RTL
  видел только yosys.
- **Массив как возврат функции: у `st` именованный тип, у `sv` — `typedef`**
  ([массив как возврат функции: st и sv порождают невалидный вывод](docs/features/0431-array-function-return.md)): обе цели печатали файл,
  который отвергают их же инструменты, при нулевом коде возврата; `c` отказывает
  `CC-015` (в C массив из функции не возвращают). Формы выбраны прогоном
  инструментов, а не чтением стандарта.
- **Срез массива печатается поэлементно, и пригодность операндов решает носитель**
  `semantic/slice/` ([срез массива переводят четыре цели](docs/features/0355-array-slice-in-targets.md)): границы
  — полуинтервал `[l, r)`, литералы, выход за край — `SE-029`. Пригодны **оба**
  операнда (срез бит-вектора и срез в скалярный приёмник давали невалидный вывод);
  координату отказу даёт `site::at`.
- **Агрегат-литерал в аргументе поднимается во временную**
  ([агрегат-литерал в аргументе вызова поднимается во временную](docs/features/0493-aggregate-argument.md)): `pick({1, 2})` у `c`
  давал невалидный вывод, у `st`/`sv` — отказ. Тип временной берётся у
  объявления функции, а форма — объявление без инициализатора плюс
  присваивание (агрегат в инициализаторе переводят не все цели). Контроль
  обязателен: аргумент-переменная переводился всеми и до правки.

- **Срез в аргументе вызова разворачивается в семантике**
  ([срез в аргументе вызова не переводит ни одна цель](docs/features/0400-slice-in-call-argument.md)): проход заводит временную
  и присваивание — печатники целей о форме не знают. Форма выбрана замером
  (объявление с инициализатором не переводит никто); имя обязано быть
  идентификатором целевых языков и проверяться на занятость.
- **Подстановка тела функции живёт в семантике, а эталон её не делает**
  ([инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](docs/features/0444-function-inlining.md), версия языка 0.14.0).
  Атрибут `[inline]`/`[noinline]` действует всегда, эвристика (тело ≤ 5
  операторов, 1…3 вызова) — по флагу `--inline=auto`. Эталон проход не зовёт
  **намеренно**: иначе сверка перестала бы видеть дефект подстановки. Переименование идёт **по имени**, не по ячейке: у параметра своя
  `Rc` на каждое употребление. Хвостовой `return` становится объявлением
  **с инициализатором** — иначе `rust` даёт `needless_late_init` (0410).
- **Ранний возврат подставляется через признак выхода, и форму выбрал замер**
  ([подстановка тела с ранним возвратом](docs/features/0446-inline-early-return.md),
  [подстановка тела с возвратом из счётного цикла](docs/features/0447-inline-return-in-loop.md)): результат объявляется
  **с начальным значением** (без него `rustc` — `E0381`), хвостовой возврат
  признак не взводит, обёртка **сливается** с условием (иначе `collapsible_if`). Цикл: тело гасится признаком, **условие не трогается** — любая
  его правка ломает разворот у `sv`; `loop`/`while` остаются `SE-128`. Признак
  статических границ — общий с `sv` (`semantic::loop_bounds`, 0321).
- **Неиспользуемая функция не печатается всеми четырьмя целями**
  ([цель st печатает неиспользуемую функцию](docs/features/0445-st-unused-function.md)): признак общий —
  `UsageSet::functions`; у `st` фильтра не было, и мёртвый POU оставался в
  программе ПЛК. `iec2c` такой файл принимает — проверка цели класса не видел;
  вызов из условия ребра считается использованием (контроль на это обязателен).
- **Вложенный агрегат раскрывается до листьев одним носителем, а форму адресации
  собирает цель** ([раскрытие вложенного агрегата — общий носитель](docs/features/0366-nested-aggregate-carrier.md)):
  `aggregate::leaves` отдаёт путь шагами (`Index`/`Field`). Готовую строку
  носитель вернуть не может; у `sv` поле структуры внутри массива отвергается
  (yosys объявляет защёлку); бит-вектор `[bit;N≤64]` — лист.
- **Присваивание агрегата: место записи выбирает один носитель**
  `generator/aggregate.rs` ([присваивание агрегата — место записи выбирает общий носитель](docs/features/0340-aggregate-assign-place.md)):
  массив по индексу, структура по имени поля, в порядке объявления; носитель
  принимает **поля**, а не модель. Позиций агрегата **четыре**: присваивание,
  инициализация, элемент массива структур (0343), локальное объявление (0345).
- **Константа-агрегат печатается тем же путём, что переменная**
  ([константа структурного и массивного типа у целей `rust` и `sv`](docs/features/0347-const-aggregate.md)): `coerce_to` у `rust`,
  `reset_value` у `sv`. У `sv` дефектов было два — типы печатались после
  констант, и verilator отвечал «Reference … before declaration».
- **Умолчание значения у цели `rust` строит один носитель, а `derive(Default)`
  печатается по нужде** ([значение по умолчанию у цели rust: структура, длительность и q](docs/features/0351-rust-default-value-types.md)):
  `default_value` знает `duration`, `q(m, n)` и структуру. `derive` выводится не
  всегда (перечисление, массив длиннее 32), а печатать `impl Default` всегда нельзя
  — `clippy::derivable_impls`; неверное умолчание `q` поймала только сверка.
- **Структуры печатаются в порядке зависимостей, и это один носитель**
  `generator/struct_order.rs` ([вложенная структура — порядок объявления и тип поля](docs/features/0341-nested-struct-order.md)):
  алфавитный порядок давал отказ `cc`, `iec2c` и verilator при нулевом коде
  возврата. Сортировка на выходе у `st` снята (разрушала порядок); цикл структур
  носитель переживает, но не диагностирует.
- **Значение в поле структуры печатается по типу поля, а перечисления у `sv`
  объявляются первыми** ([перечисление в поле структуры — значение и порядок объявлений](docs/features/0492-enum-in-struct-field.md)):
  `conf.mode := Run;` печаталось числом — `E0308` у `rust`, `ENUMVALUE` у `sv`.
  Тип поля спрашивается там, где видно объявление (снимок карты у `sv`,
  модель `Scope` у `rust`): общий `expression_type` о полях не знает и честно
  отвечает `None`. Дефект `sv` двухслойный — порядок скрывал `ENUMVALUE`.

- **Структурные типы**: объявленный **порядок полей значим**, инициализатор `{…}`
  позиционный ([структурные типы в симуляторе](docs/features/0034-sim-struct-types.md)); доступ — общий
  `eval/access.rs::read_member`, запись — `eval/place.rs::update`. Сравнение
  структур — `TypeMismatch` (C запрещает `==`, «умный» эталон врал бы); доступ к
  несуществующему полю — `SE-061`.
- **Массивы `[T;N]` исполняются симулятором** ([симулятор не исполняет массивы вовсе](docs/features/0076-sim-arrays.md)):
  запись элемента и запись поля структуры — единый сегментный механизм «места»;
  границы и вид → `SIM-010`.
- **Константная выдержка `after` вычисляется на семантике и до целей не доезжает**
  ([`after` принимает константу типа `duration`, а не только литерал](docs/features/0143-after-const-duration.md)): все формы дают один узел
  `After(нс)`, вычислитель — `semantic/condition/after_const.rs`, прочее → `SE-072`
  с названной причиной. Аргумент живёт в грамматике условий (`*`, `/`, `as` там
  нет), скобки хранятся в дереве; контроль — тождественность вывода литеральной форме.
- **Выдержка от переменной `duration` расширяется до `u64` у цели `rust`**
  ([профили времени и clock в переборе](docs/features/0459-matrix-time-profiles.md)): метка времени — `u64`
  (`now_ms`), а `duration` в целях 32-битный, и `rustc` отвечал `E0308` при
  нулевом коде возврата. Расширять надо **выражение**, а не усекать метку:
  усечение сдвинуло бы переполнение счётчика. Класс виден лишь в сочетании
  «профиль часы + переменная» — оттого его и нашёл перебор.
- **Машинную ширину скалярного порта считает один носитель**
  ([ширина скалярного порта — один носитель; порт q(m,n) у rust и st-at](docs/features/0488-scalar-port-width.md)): `semantic::scalar_port` —
  целое, `duration`, `q(m, n)`, перечисление; имена типов строит цель.
  `bit`/`bool` целым не считаются: у целей это своя категория порта
  (`write_bit`, `%QX`). Точная ширина — другой носитель
  (`sv_type::scalar_width`): аппаратной цели важен занятый разряд, прочим —
  машинный тип.

- **Порт типа `duration` — тоже скаляр, и ширину даёт один носитель**
  ([порт типа duration у целей rust, st-at и sv-mmio](docs/features/0487-duration-port.md)): `duration::VALUE_BITS`,
  единица границы — миллисекунда (0183). `SV-002` «ширина не определена»
  приходил от второй копии таблицы ширин у `sv-mmio` — она снята, скаляры
  считает `sv_type::scalar_width`. Пересчёт нс → мс контролирует сверка
  значений: ошибись он, вывод остался бы валидным, а прошивка ждала бы не тот
  интервал.

- **Порт перечислимого типа — скаляр, его переводят все восемь целей**
  ([порт перечислимого типа у целей rust и st-at](docs/features/0485-enum-port.md)): ширину и знак даёт `enum_facts`,
  у `st-at` это локация `AT %QB`. У `rust` значение пересекает HAL дважды:
  уходит `as u8`, приходит через `from_repr` — по нужде (признак — факт чтения,
  не направление) и тотально (число вне набора → первый вариант, 0391).
  Путей печати записи два — такт и начальное значение порта; оба дефекта
  правки поймала матрица целей 0450, корпус их не покрывает.

- **Тип `duration` в целях — целое в миллисекундах; выдержка бывает вычисляемой**
  ([тип `duration` в целях генерации и вычисляемая выдержка](docs/features/0183-duration-type-in-targets.md),
  [потактовые сверки длительностей для целей st и sv](docs/features/0215-duration-per-tick-conformance-st-sv.md)): пересчёт —
  только `semantic::duration::value_millis`. Вычисляемая выдержка требует
  множителя `hertz / 1000` (нецелый — `SE-073`); ширина счётчика — 32 бита; четыре
  обхода по `ConditionNode` кончаются `_ =>` и компилятором не охраняются.

### Цели генерации

- **В выводе только шапка и комментарии автора — генератор не сочиняет**
  ([комментарии в порождённом коде: шапка и комментарии автора](docs/features/0535-generated-code-comments.md), решение заказчика):
  шапка — латиница, версия языка, без дат; текст автора едет по смещению.
  Форма принадлежит цели, хвостовой комментарий однострочен: блочный IEC
  оставлял в строке кода голое `(*`, и `iec2c` отвергал файл при нулевом коде
  возврата. Проверка на отсутствие конструкции смотрит на код — семь тестов
  искали подстроку с комментариями. Контроль — `check-generated-comments.py`.

- **Цель печатает в строки, а на диск пишет один носитель**

  `fs::write` было **семь** мест в пяти модулях, и потребитель без файловой
  системы вывода не получал вовсе. Контроль — тест «записанное равно
  напечатанному» по пяти целям; выбор цели тоже один (`generator_of`).
- **Имён площадок в коде страницы НЕТ: кнопки строит ответ сервера**

  кнопка вела бы в никуда (приём «нет списка ключевых слов Takt в вебе»).
  Контроля — греп имён и сверка подписей с исходником сервера; оба проверены
  снятием. Прогон нашёл: просроченная сессия показывалась живой.

- **Файл проекта бывает трёх родов, и род выводится из расширения одним правилом**
  ([онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](docs/features/0531-web-playground.md), задача 09n, решения заказчика):
  модель, сценарий (входов и проверок — они в формате уже есть) и пояснение
  `.md`. Активный сценарий называет проект, роль проверяется при назначении:
  перепутанные роли дают не отказ, а пустую страницу либо прогон по пояснению.
  Показ Markdown строит узлы, `innerHTML` нет: текст автора видят читатели
  витрины. Разбор один на подсветку и показ. Контроль — `tests/projects.rs`.

- **Цель и ключи сборки — свойство проекта, а разбирает их модуль**

  открывается сборкой автора (прежде — целью читателя: `sv-mmio` с `--bus=apb`
  показывался как `c`), черновик перекрывает. Негодные ключи отвергаются на

  написанное».
- **Инициализатор объявления не читает неопределённую память: `SE-099` (ячейка) и
  `SE-113` (порт)** ([анонимные порты](docs/features/0189-anonymous-ports.md),
  [чтение порта в инициализаторе объявления](docs/features/0266-port-in-declaration-initializer.md)): правило одно, обход
  один, кодов два. Нормировать форму нечем (у эталона до первого такта входа нет);
  порт узнаётся по **виду объявления**; замеряя `c-hal`, дай порту адрес — иначе
  `SE-052` прячет ответ.
- **Инициализатор не зовёт функцию, которую компилятор исполнить не может, и причина
  называется** ([невычислимый вызов функции в инициализаторе называет причину](docs/features/0306-unfoldable-call-in-initializer.md)):
  диагностику вычислителя выбрасывал `let Ok(…) else`. Признак синтаксический («в
  записи есть вызов»); вычислимый вызов законен — это контроль; место эмиссии одно
  (копия в `validate` снята, контроль это проверяет).
- **Инициализатор не зовёт внешнюю функцию: `SE-084`**
  ([вызов внешней функции в инициализаторе — SE-084](docs/features/0305-extern-call-in-initializer.md)): значение `extern` при
  компиляции неизвестно, а начальное значение выставляется до первого такта.
  Форм внешней функции в ячейке **две** (на стадии 2 лежит `Unresolved`, а не
  `External`); вызов локальной функции законен.
- **Обращение к ячейке без имени — `#АДРЕС`**
  ([анонимные порты](docs/features/0189-anonymous-ports.md)): `#A:B as T` — поле разрядности `T`
  с бита `B`, `#A.B` — один бит, `#A` без ширины — `SE-097`; свёртка форм — воронка
  `semantic/anon_port.rs`, запись → `SE-096`, в инициализаторе → `SE-099`.
  Поддерживают три цели (`c-hal`, `st-at`, `sv-mmio`), прочие отказывают с причиной;
  имя ячейки строит компилятор и оно общее у эталона и целей.
- **Оператором-выражением может быть только форма с эффектом**
  ([анонимные порты](docs/features/0189-anonymous-ports.md), решение 6A): присваивание и вызов;
  `x + 1;` → `SY-007`, голый адресный литерал → `SY-008` (прежде цель `c` **теряла
  оператор целиком**). Печатник операторов `c` глотал любую ошибку — теперь
  пропускается только вызов встроенной функции.
- **Оператор `address` действует в области своего объявления**
  ([адресные карты и --address-map в переборе](docs/features/0458-matrix-address-maps.md)): порт и оператор стоят на
  одном уровне, иначе `SE-048`. Путь внешней карты берётся от **рабочего
  каталога процесса**, а не от каталога модели (в отличие от `import`, 0055);
  контроль — перебор с контролем **значения** адреса, а не факта компиляции.
- **Экспорт карты — `taktc address-map --emit map|json`**
  ([экспорт карты адресов во внешний формат](docs/features/0043-address-map-export.md)): выгружает фактически
  разрешённую карту тем же `resolve_addresses`, что у `c-hal`; `map` замыкается
  круговым рейсом. Мёртвый порт → `"address": null`, не `0x0`.

### Симулятор

- **Такт прогона делает `SimulationRunner::step`, а `run` — цикл печати**
  ([онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](docs/features/0531-web-playground.md), задача 02): потребитель без
  консоли (модуль в браузере) тикает тем же шагом и получает ту же строку.
  Второго цикла исполнения в проекте быть не должно: заведи мост свой —
  трасса разошлась бы с той, на которой стоят все сверки, и разошлась бы молча.
  Бюджет тактов — свойство прогона, а не модели: страница просит столько,
  сколько готова ждать, и остановка называется словами.
- **Предупреждения прогона и вывод программы эталон возвращает, а не печатает**
  ([предупреждения прогона возвращаются вызывающему, а не печатаются из библиотеки](docs/features/0537-sim-warnings-return.md)): `Step` несёт `warnings`
  (`RunWarning` — код полем, номер шага) и `output` (строки `debug`); печатает
  `run`, форму даёт `trace::warning_line`. Печати внутри библиотеки для страницы
  не существует, и `SIM-037` с `SIM-032` до браузера не доходили. Каналы
  раздельны: вывод модели не замечание к ней. Контроля — греп «библиотека не
  печатает» и сверка напечатанного с возвращённым.

- **Строку шага и сводку прогона строит библиотека**
  ([онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](docs/features/0531-web-playground.md), задача 01): `takt_sim::trace`
  (`step_line`, `result_report`), а `SimulationRunner` и CLI их печатают.
  Потребитель без консоли (модуль в браузере) иначе собирал бы трассу
  сам — и две сборки разошлись бы молча: сверки гоняли бы одно, а показывалось
  бы другое. Контроль — тест «каждый исход высказывается и в свой поток».
- **Графика — выключаемая фича `graphics`, а кадр воспроизводим**
  ([онлайн-редактор Takt: подсветка, LSP, генерация, симуляция, обмен ссылками](docs/features/0531-web-playground.md), задача 01): под фичей `gif`,
  `svg`, `unit::viewport` и растеризатор; бинарник её требует, библиотека без
  неё отказывает на запрос кадров словами. Сеяного генератора раскладки
  **мало**: порядок узлов брался обходом `HashMap` переходов, и два прогона
  давали разные кадры при одинаковой трассе — узлы и рёбра сортируются.
  Сортировка живёт в раскладке; порядка проверки переходов она не касается.
- **Семантика вычислений живёт только в `takt-sim/src/eval/`**
  ([починка вычислителя выражений симулятора](docs/features/0025-simulator-expression-eval.md)): адаптеры семантики не
  содержат, тела исполняет `unit/statement.rs`; `eval` и `unit/initial.rs` — под
  `deny(clippy::wildcard_enum_match_arm)`, проверка `check-exhaustive-nodes.sh` контролирует
  оба. Тесты симуляции пиши **на значения**, а не на факт перехода; второй
  вычислитель не «только литералы» — он зовёт тот же `eval::cast_to_type`.
- **Проверка состояния под-модели исполняется эталоном и адресуется по имени модели**
  ([симулятор исполняет S(Модель) — проверку состояния под-модели](docs/features/0245-sim-state-of-model.md)): узел публикует своё состояние
  при постройке, переходе и восстановлении из снимка. Публикация стоит **после**
  смены поля `state`; незапущенная модель даёт `SIM-036`, а не «условие ложно»;
  форму паттерна разбирает одна функция на проект.
- **Разряд — число 0/1, а правило S8 остаётся в силе**
  ([разряд участвует в арифметике как 0/1](docs/features/0356-sim-bit-in-arithmetic.md)): `read_bit` отдавал
  `Boolean`, и `src.7 + 1` давало `SIM-005` там, где переводят все восемь целей.
  Верное место правки — источник (`eval/access.rs`), а не `as_num` (это отменило бы
  S8); контрпример «S8 в силе» стоит рядом с изменённым тестом.
- **Отказ доступа к разряду называет разрядность значения**
  ([текст `SIM-011` называет ширину значения](docs/features/0307-sim-bit-range-text.md)): `SIM-011` печатал «0..64»
  литералом — на `[bit;96]` это ложь. Граница печатается включительно; ширина
  берётся у значения, не у объявления; контроля сквозные (модуль `eval` приватен).
- **Умолчание типа у эталона строит один носитель, и вид значения — часть типа**
  ([умолчание `duration` у эталона несёт свой вид значения](docs/features/0354-sim-duration-default.md), `unit/builder.rs::default_field`):
  у `duration` свой вид значения, и `var d: duration;` давало `SIM-005` в такте.
  Расширять арифметику вместо этого нельзя (`SE-065`); контроль — сверка, а не
  «отказа больше нет».
- **Значение `extern`-функции задаёт сценарий**
  ([внешний интерфейс модели: extern fn в симуляторе и агрегат как аргумент](docs/features/0209-model-external-interface.md)): секция `extern` шага —
  одно значение на такт либо таблица по первому аргументу. Умолчания нет (ноль
  сделал бы сверку зелёной при расхождении); стенд принадлежит **шагу** и обязан
  доехать до всех трёх областей видимости.
- **Единый источник истины по значениям — `ModelNodeContext`**
  ([сохранение переменных модели в --save-state/--load-state](docs/features/0032-state-io-variables.md)): писать только через
  `Context::set_value`, читать через `get_value`/`dump`.
- **Узел языка в симуляторе разбирают три места, и они расходятся**
  ([литерал длительности в теле блока давал `SIM-007`](docs/fixes/0134-02-duration-literal-in-body.md)): адаптер условий,
  адаптер выражений и вычислитель начальных значений. Проверка исчерпаемости класс не
  ловит: ветвь есть, она отвечает отказом «до будущей задачи», и отказ переживает
  задачу — заводя ветвь-заглушку, заводи и тест, который её снимет.
- **Реализация модели (`model M = A | B { … }`) разворачивается в состояние**
  ([форма model M = A & B { … } не работает ни в одной стороне](docs/features/0199-model-implements-brace-form.md)): разворот делает
  `extend::expand_model_implement` на построении дерева. Разрешить `implements` в
  поле мало — карта строит состояния из `model.states`; модель с реализацией **и**
  собственным состоянием — `SE-101`.
- **У состояния-композиции есть собственные рёбра, и цели их печатают**
  ([условное ребро состояния-композиции теряется целями](docs/features/0303-composition-state-conditional-edge.md)): сначала `ref` в
  порядке объявления, затем `next`; `END` подставляется только состоянию без
  переходов. Правок целей было мало — `minimap::visit_state` клал в обход только
  `next`; класс невидим инструментам, вердикт дают сверки.
- **Реализация состояния — дочерний юнит узла с общим контекстом**
  ([симулятор исполняет реализацию состояния с переходом next](docs/features/0181-sim-state-implementation-tick.md)): такт тикает её **до**
  проверки переходов и берёт переход по завершении — на том же такте; повторный вход
  композицию не перезапускает. `next` живёт отдельным полем `StateNode::Implement`;
  шаги `+` делят родительский контекст.
- **`Unit::execution` в дочерние юниты не спускается** ([симулятор исполняет `always` композиции дважды за такт](docs/fixes/0181-01-sim-parallel-always-twice.md)): вернуть спуск — значит
  исполнить `always` под-модели дважды за такт. Дефект был невидим всему покрытию
  (тела корпуса идемпотентны); контроля — значенческие тесты на накапливающем теле.
- **Порты под-моделей композиции драйвятся**
  ([`elevator_mini.lam` не исполняется: порты под-модели композиции](docs/features/0079-sim-composition-ports.md)): `PortNames::from_model`
  обходит `model.models` рекурсивно. Правки требовало **перечисление**, а не
  чтение/запись.
- **Порт адресуется квалифицированно** `Модель::порт`
  ([квалифицированные имена портов в симуляторе](docs/features/0135-sim-qualified-port-names.md)); голое имя работает как
  прежде. Квалификатор — имя модели, а не путь: две под-модели с одинаковым именем
  неразличимы.
- **Режимы эталона проверяются сплошь и ответом инструмента**
  ([симулятор и сценарии в переборе](docs/features/0461-matrix-simulator.md)): девять случаев — трасса
  либо код диагностики. На эталоне стоят все сверки: ошибись он, они
  окажутся зелёными при неверном ответе. Значения портов **удерживаются**
  между тактами, guard шага останавливает прогон, а умолчание границ совпадает
  с умолчанием целей (`SIM-010`).
- **Длину прогона задаёт `-n`, а сценарий — входы**
  ([длину прогона задаёт `-n`, а не длина сценария](docs/features/0523-sim-scenario-run-length.md)): после последнего шага
  сценария прогон продолжается с удержанными значениями (доведённое
  до конца). Прежде сценарий обрывал прогон, и выдержку в 180 000 тактов нельзя
  было показать, не заведя файл той же длины; исход `StepsExhausted` при этом был
  мёртв. Без `-n` длину по-прежнему задаёт сценарий; стенд `extern` держится
  последним заданным.
- **Сценарий пишется именами портов**
  ([именованные порты в сценариях симулятора](docs/features/0132-sim-named-port-scenarios.md),
  [признание позиционной формы сценария устаревшей](docs/features/0150-sim-positional-scenario-deprecation.md)): неизвестное имя
  → `SIM-030`, двусмысленное → `SIM-031`, позиционная форма устарела (`SIM-037`, раз
  за прогон) и держится проверкой `check-positional-scenarios.py`. Код диагностики
  обязан быть отдельным литералом — вплавленный в текст невидим проверке кодов; значения
  портов удерживаются между тактами.
- **Область инварианта состояния контролирует сверка, и она двусторонняя**
  ([инварианты во всех местах — в переборе](docs/features/0475-matrix-invariant-sites.md)): стой проверка в общем
  теле, вывод целей был бы валиден, а прошивка падала бы там, где эталон
  считает дальше. Проверять только «не срабатывает вне состояния» мало —
  это верно и при отсутствии проверки; понизить границу мало: автомат уходит
  дальше раньше, чем условие нарушится.
- **Инварианты проверяются** ([юнит-конструкции языка для симуляции (assert/invariant)](docs/features/0044-sim-assert-invariant.md)):
  `invariant Имя = C;` — сахар над `cond` + `Formula::Guard`, нарушение →
  `TickResult::Failed` + `SIM-025`; мягкий режим записывает и продолжает. Ошибка
  **вычисления** условия — `Failed` в обоих режимах; в сверке с C мягкий режим не
  участвует.
- **Сценарии примеров проверяются прогоном** (`examples_scenario_tests.rs`): у каждого
  `examples/*.takt` обязан быть либо контракт (цепочка + бюджет + завершение), либо
  исключение **с причиной**.

### Верификация

- **Вердикты верификации проверяются сплошь и вердиктом, а не структурой**
  ([верификация в переборе — LTL и Бюхи](docs/features/0460-matrix-verification.md)): двенадцать случаев с
  названным ответом (держится / нарушено + контрпример / не проверено +
  причина). Пара «условный ↔ безусловный `ref`» стоит в наборе намеренно:
  при условном `F Done` **нарушено** (самопетля), при безусловном — держится;
  это и есть цена абстракции. Мутация «убрать самопетлю» роняет набор.
- **Абстракция управляющего графа** ([верификация модели (Model Checking) на основе LTL](docs/features/0049-model-checking-ltl.md)):
  атом = имя состояния, условия рёбер абстрагированы; «держится» надёжно, «нарушено»
  может быть ложным. Самопетлю получает всякое состояние без **безусловного**
  `ref` — иначе Крипке недо-аппроксимация и ложный `Holds`; ошибаться только в сторону
  лишних прогонов. Тесты верификации пиши **на вердикт**, а не на структуру
  автомата ([вырожденное условие принятия автомата Бюхи (GPVW)](docs/fixes/0010-01-buchi-acceptance.md)); область формулы —
  по месту объявления ([область проверки `lamc verify` (`--scope`)](docs/features/0051-verify-scope.md)).
- **Домен перечисления в верификации ищется подъёмом к родителям**
  ([верификация — домен перечисления ищется подъёмом к родителям](docs/features/0497-verify-enum-domain.md)): `enum` объявляют рядом с
  моделями, и карта самой модели его не содержит — предикат отвергался
  причиной, которую тот же вывод опровергал строкой ниже. Ветвь
  `DomainNotEnumerable` Не защитная, как считал замер: она достижима.
  Контроль обязан спрашивать вердикт у вложенной модели — иначе мутация
  проходит.

- **Домен типа и его отслеживаемость — один носитель `verification::domain`**
  ([верификация — домен типа как один носитель, бит-вектор в охвате](docs/features/0498-verify-bit-vector-domain.md)): «перечислим ли тип» и
  «какие у него значения» — один вопрос; пока ответчиков было два, они разъехались
  и дали ложную причину (0497). `[bit;N≤64]` — скаляр, а не массив (0078): его
  верификатор отвергал, тогда как `u8` того же представления проверял; домен — по
  объявленной ширине (`[bit;3]` — восемь значений), и это видно в вердикте.
  `duration` в охват не входит намеренно (домен 2³²), но причина его называет.
- **Параметр модели в предикате — постоянная величина**
  ([верификация — параметр модели как значение по умолчанию](docs/features/0517-verify-parameter-domain.md), решение заказчика):
  домен из одного значения — умолчания, поэтому задачу он не растит. Прежде
  `ticks < limit` при `parameter limit` давал «за потолком», а тот же вход с
  `const` — «держится». Признак — `ParameterNode::mutated` (0185), умолчание
  «изменяемый»: параметр с присваиванием остаётся свободной переменной, и на это
  есть контроль. Вердикт относится к сборке С умолчанием — сказано в `book/`.
- **Свойства над данными — абстракция по формуле**
  ([верификация свойств над данными (атом-предикат LTL)](docs/features/0068-verify-data-properties.md)): отслеживаются только
  переменные из φ, ход данных полностью недетерминирован — `Holds` надёжен,
  `Violated` над меняющимися данными почти всегда возможно ложный. Наивный
  explicit-state неосуществим (у `elevator` вершина имеет 3.7·10⁵⁰ преемников);
  контроль направления — `abstracted_source_yields_extra_run_not_missed`.
- **Потолок верификации по данным считается по рёбрам**
  ([потолок верификации по данным: бюджет вместо `VERTEX_LIMIT`](docs/features/0145-verify-vertex-budget.md)): `EDGE_LIMIT = 1_000_000`
  против `max(E, V) × D²` — работа идёт по рёбрам, а они растут квадратично по
  доменам. Метрику выбрал замер (по вершинам время расходилось в 2000 раз);
  потолок один, и `max` делает это свойством кода; контроль на взрыв рёбер **виснет, а
  не падает** — второй тест на ту же формулу удалять нельзя.
- **Вердикт-отказ называет причину, и носитель текста один**
  ([verdict::Unsupported не различает причину отказа](docs/features/0258-verify-unsupported-reason.md)):
  `Verdict::Unsupported { atoms, reason }`, текст даёт `UnsupportedReason::text()` —
  его берут CLI и экспорт графа. Ветвь `DomainNotEnumerable` недостижима (отсекается
  подмножеством предикатов) и оставлена защитной; текст проверяется прогоном
  инструмента.

### Документ и процесс

- **Версия языка — единственный источник истины в коде**:
  `takt_lang::LANGUAGE_VERSION`, **сейчас `0.18.0`**
  ([константы `LANGUAGE_VERSION` в коде нет](docs/features/0085-language-version-constant.md)). Проверка
  `scripts/check-language-version.sh` сверяет **три** источника — константу, README и
  живой контекст. Меняя версию языка, правь все три синхронно; это
  **не** версия крейта `takt-lang` (`CARGO_PKG_VERSION`, сейчас `0.60.0`).
- **Релиз и тег выпускает автоматика при подъёме минорной версии языка**
  ([релиз и тег при подъёме минорной версии языка](docs/features/0302-release-on-language-minor.md)): решение принимает
  `scripts/release-check.sh`, тело собирает `scripts/release-notes.sh`, YAML — обёртка
  без логики. Устройство подчинено тому, что **CI не исполняется** (Actions
  заблокированы), поэтому всё проверяемое лежит в скриптах; тег, поставленный
  человеком, останавливает автоматику; тело берётся из **истории**, а не из журнала.
- **Подъём версии языка помечается тегом, и у правила есть контроль**
  ([пропущенные метки версий языка и контроль](docs/features/0162-git-tag-v040.md)): `scripts/check-version-tag.sh` требует
  аннотированный `v<версия>`, достижимый из `HEAD`. Проверка обязан молчать в момент
  подъёма (признак — расхождение версии в дереве и в `HEAD`); замеряя теги,
  разыменовывай `^{commit}`.
- **Замер расхождения снимается командой, и проба проверяется**
  ([снятие замера расхождения: инструмент и чек-лист](docs/features/0301-probe-checklist.md),
  [проба прогоняет инструменты целей](docs/features/0362-probe-target-tools.md)):
  `scripts/probe.sh [-n ШАГОВ] МОДЕЛЬ.takt` сводит эталон и восемь целей в таблицу и
  проверяет саму пробу. **Код возврата `taktc` — не вердикт о валидности**:
  последний раздел гоняет инструменты целей; нет арбитра — печатается «пропуск»,
  никогда «принял». Контрольный вход и дата замера — на человеке.
- **Реестр стадии сверяется с диском, и пропуск в нём слепит соседний проверка**
  ([согласованность реестров `docs/*/README.md` с файлами на диске](docs/features/0164-registry-rebuild-gate.md)): `scripts/check-registries.py`
  сверяет файлы папки-стадии с реестром **в обе стороны** (`R0`…`R2`). Проверка, чью
  проверку обходит отсутствие записи, не проверка: `check-registry-verdicts.py` проверяет
  **строки**, и без записи вердикт не проверялся вовсе.
- **Разбор в приложении даётся по названному признаку**
  ([разбор с примером есть у 83 кодов из 229](docs/features/0398-diagnostics-detailed-analysis.md), решение заказчика):
  его получают коды, чьё описание ссылается на устройство либо называет чужой
  инструмент; проверка — `scripts/check-diagnostic-analysis.py`. Признак читает
  **реестр**, а не исходники: реестр и есть каталог смыслов.
- **Запись реестра диагностик называет смысл**
  ([запись реестра диагностик называет смысл](docs/features/0311-diagnostic-descriptions.md)): проверка
  `scripts/check-diagnostic-descriptions.py` — `D1` (служебное слово, **без
  исключений**), `D2` (короче 25 символов вне долга), `D3` (протухшая запись).
  «Разобрать все коды» — не предмет проверки: какие заслуживают разбора, решает
  польза (вывод 0290).
- **Комментарий шага `precheck.sh` объясняет шаг, правило живёт в заголовке проверки**
  ([комментарий шага не пересказывает заголовок проверки](docs/features/0316-precheck-comment-duplication.md)): контроль
  `scripts/check-precheck-comments.py` ловит общий дословный кусок ≥ 60 символов.
  Это порог, а не запрет совпадений: комментарий обязан называть предмет и место
  шага в порядке.
- **Заглушка узнаётся и по обещанию задачи в тексте диагностики**
  ([заглушка, обещающая задачу, ловится проверкой](docs/features/0332-stub-task-promise.md)): проверка искал одну
  формулировку, и четыре заглушки цели `st` прожили год невидимыми — за двумя стояли
  настоящие расхождения. Признак сужен до строк рядом с `with_code`; номера фич не
  место в тексте, который читает автор модели.
- **У каждого проверки есть контроль либо самопроверка, и она идёт первой**
  ([коды симулятора, вплавленные в текст, невидимы проверке и реестру](docs/features/0255-sim-diagnostic-codes-registry.md),
  [проверки без контрольных тестов получают контрольных тестов](docs/features/0315-gate-guards.md)): контроль гоняет проверка на **копии** дерева
  (переменная корня `EN_ROOT`, `LV_ROOT`, …). Проверяется **предмет** проверки, а не
  запуск, и условий два: «плохое ловится» и «хорошее проходит»; вырожденный вход
  обязан давать отказ. Список проверок меняется — беря работу, снимай замер заново.
- **Артефакт фичи — один файл, и стадии живут его разделами**

  изменился — поменялось место записи; исправления остались отдельными (`docs/fixes/`);
  ссылка на чужую стадию — **якорем**; проверки статусов читают третью ячейку строки.
- **Пункт живого контекста уложен в 8 строк, и это контролирует проверка**
  ([пункт живого контекста уложен в предел; проверка размера](docs/features/0408-claude-md-item-size.md),
  [диета живого контекста: пункт до восьми строк](docs/features/0436-claude-md-diet-2.md)): форма пункта — инвариант → чем
  платим → контроль → ссылка, а замеры и история живут в карточке. Проверка — `scripts/check-claude-md-items.py`, реестр долга **пуст** и это его
  нормальное состояние. Счётчик пунктов дважды ошибался в одну сторону (сообщал о
  пунктах, которых нет) — оба класса закреплены условиями контроля.
- **Выборка проверки сверяется с нижней границей, а не с уловом**
  ([проверка, читающая документ, отказывает на пустой выборке](docs/features/0536-gate-empty-selection.md)): разобрано ноль — находок
  ноль — код ноль, и ответ неотличим от настоящего; отчёт называет разобранные

  только число в ней, и держит его контрольная проба.

## Форматтер

Ядро печати — `takt-lang/src/format/` (`format_source`), потребители: `taktc fmt`
(`--check`/`--stdin`) и LSP `textDocument/formatting`; `precheck.sh` проверяет канон
`examples/` (фикстуры `tests/data/` намеренно не нормализованы). Правило «добавил
узел АСД — добавь его печать» — во врезке раздела «Добавление конструкции языка».

**Канон описан словами** — раздел «Стиль кода» документа
([стиль кода языка Takt — свод правил оформления и раздел документа](docs/features/0197-language-code-style.md)). Машинной сверки «текст ↔
форматтер» нет и в общем виде быть не может, поэтому фича, меняющая `taktc fmt`,
**обязана** проверить этот раздел: цена измерена исправлением
[канон стиля — K&R `else`, заглавные имена `cond`/`invariant`, перечисление по варианту на строке](docs/fixes/0197-01-kr-else-cond-case-enum-lines.md) — смена трёх правил
затронула **пять** записей канона.

**Раскладка — K&R**: `} else {`, цепочка плоская. Склейку делает
`Out::join` — снимает поставленный `'\n'` и взводит `glued`, из-за которого
следующая `line` идёт без отступа. Флаг нужен потому, что заголовок звена печатает
рекурсивный `stmt::print`, не знающий, что его позвали из ветки `else`.

**Перечисление и структура печатаются по элементу на строке** ([печать структуры теряет место комментария](docs/fixes/0198-01-struct-comment-placement.md)). Висячей запятой быть
не должно — напечатанная запятая делает файл неразбираемым, а `fmt` пишет на месте.
Варианты печатаются `node_line_within(…, brace)` с границей по байту самой `}`:
`loc` записи покрывает её целиком, и без границы хвостовой комментарий забрал бы
первый вариант, а печать перестала бы быть идемпотентной.

**Ведущие комментарии оператора выдаёт одна точка — `stmt::print`**
([комментарий перед блочным оператором уезжает внутрь блока](docs/features/0406-format-comment-before-block.md)): прежде их выдавал только
`Out::node_line`, а он печатает неблочные операторы — комментарий перед `if`/`while`
всплывал первой строкой **тела**. `node_line` для заголовка не годится: позиция
блочного оператора покрывает и тело. Ветвь `else` зовёт `print_inner` — выдача в
ждущую продолжения строку рвёт K&R.

**Закрывающая скобка тела печатается одной функцией `close_body`**
([печать элемента модели в обход привязки комментариев не запрещена](docs/features/0295-format-element-comment-binding.md)): комментарий последней
строкой тела принадлежит **этому** телу, иначе его подхватывает следующий элемент.
Класс правился трижды в трёх ветках, и замер нашёл его живым ещё в двух; контроль
двухслойный — поведение по **отступу** (порядок строк дефект не ловит) и греп по
`format/mod.rs`, падающий списком.

**Синонимы не канонизируются:** `while`/`loop` и `: [Guard] x;`/`: x;` — АСД хранит
выбор автора (`ast::LoopKeyword`, `Guard::explicit`), семантика эти признаки
игнорирует.

**Форма записи числа принадлежит автору** ([форма записи числа переживает форматирование](docs/features/0463-format-number-form.md)):
`0xF0` не превращается в `240`, разделитель разрядов сохраняется. Печать идёт
**по исходнику** через позицию узла (в АСД она есть), а не хранением основания в
токене — `Number` самый частый узел языка. Значение **сверяется**: разойдись
позиция с текстом, напечаталось бы чужое число; при несовпадении печатается
десятичное, то есть прежнее поведение. Носитель исходника потоковый —
сброс обязателен на всех путях выхода (печать вынесена в замыкание).
