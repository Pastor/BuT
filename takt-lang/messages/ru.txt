# Каталог сообщений: русский (базовый язык).
#
# Формат: `ключ = текст`, по строке на ключ; строки, начинающиеся с `#`, и
# пустые - пропускаются. Подстановка пишется как `{имя}` и приходит строкой:
# `{:?}` в каталог не попадает по построению.
# Перевод строки внутри текста записывается как `\n`.
#
# Русский каталог - база: набор ключей остальных языков сверяется с ним
# (проверка `scripts/check-messages.py`), и константы ключей `build.rs` строит
# тоже отсюда. Ключ - не код диагностики: у одного кода бывает несколько
# сообщений (см. `se-034.*`), и `with_code` остаётся литералом.

# ─── Верификация: причины отказа проверки (`verification/verify.rs`) ─────────
verify.unknown-atom = атом не является ни именем состояния этой модели, ни предикатом над её данными: опечатка в имени либо состояние вложенной модели (состояния вложенных моделей в охват не входят)
verify.predicate-outside-subset = предикат над данными вне поддержанного подмножества: в нём есть арифметика, вызов функции, обращение к порту, доступ к биту либо неперечислимый тип (`float`, `q`, `duration`, массив, структура) — отслеживаются сравнения и логические связки над переменными
verify.domain-not-enumerable = домен отслеживаемой переменной не перечислим: `float`, `q(m, n)`, `duration`, массив или структура — проверка перебирает значения, а перебирать здесь нечего
verify.size-over-limit = размер задачи за потолком: рёбер получается `рёбра графа × (произведение доменов)²`, и при более чем 1 000 000 проверка отвергается до счёта. Сузьте домены переменных формулы (например `u8` → `enum`/`bit`) либо возьмите свойство над меньшим их числом
verify.initial-value-unknown = начальное значение отслеживаемой переменной неизвестно: инициализатор не сворачивается в константу либо значение вне домена своего типа
