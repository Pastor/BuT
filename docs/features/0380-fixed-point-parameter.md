# Фича: Fixed-point в параметре функции

- **Номер:** 0380
- **Статус:** ГОТОВО
- **Зависит от:** нет (0061, 0344 закрыты)
- **Связанные issue (анализ):** замер-обход 2026-08-22 (проба функции над `q`)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32): «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».
Отдельным артефактом остаются только исправления —

## Краткое описание

Замер-22 на `fn whole(v: q(8, 8)) -> u8`:

```
Ошибка компиляции [SE-119]: внутренний инвариант семантики нарушен: параметр
функции без типа. Это дефект компилятора, а не ошибка модели …
```

Отказ приходил **у всех девяти потребителей**, включая эталон: тип параметра
грамматика хранит **выражением**, а `q(8, 8)` как выражение есть **вызов** (`q`
— обычный идентификатор). Семантика такую форму не разбирала и
объявляла дефект компилятора.

Контроли: `q` в **возврате** (`-> q(8, 8)`) работал и прежде; `duration` в
параметре — тоже. Ломался именно параметр параметризованного типа.

## Документирование (правило 24)

**Не требуется** — множество принимаемых записей расширяется, но правило языка
прежнее: `q(m, n)` — тип, а не вызов. Раздел о fixed-point
описывает тип, не запрещая его в параметре.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-22
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича](0380-fixed-point-parameter.md);
  связь с [ADR](0061-fixed-point-type.md#архитектура-adr) (`q` — не ключевое слово),
  [ADR](0344-st-call-order.md#архитектура-adr) (порядок POU у цели `st`),
  [ADR](0276-semantic-diagnostics-without-code.md#архитектура-adr) (воронка `SE-119`)

### Context

Тип параметра функции грамматика хранит `ast::Expression` (правило
`ParameterTypeExpr`): имя типа приходит `Expression::Variable`, массив —
`Expression::Type`. Форма `q(8, 8)` при этом разбирается как **вызов**
(`Expression::Function`), потому что `q` — обычный идентификатор, и семантика отвечала `SE-119` — отказом, объявляющим дефект
компилятора.

Запись естественна: библиотека операций над fixed-point (образец 0182 —
ПИД-регулятор) выражается функциями над `q`. Сегодня она обходится типом
`float` и глобальным флагом `--float-as-q`, то есть представление выбирается
не автором.

### Decision Drivers

1. **`SE-119` — отказ о дефекте инструмента**, и появляться на законной записи
   он не должен.
2. **Правило языка не меняется:** `q(m, n)` — тип; вопрос лишь в том, кто эту
   форму опознаёт.
3. **Грамматика не должна конфликтовать:** правило `Type` в позицию параметра
   не подставить.

### Considered Options

#### Option A. Опознавать форму в семантике (принято)

`Expression::Function(loc, ctor, [Number, Number])` → `ast::Type::Fixed`, далее
прежний `construct_type`/`construct_fixed`.

**Pros:**
- Грамматика не трогается — конфликта LR(1) не возникает.
- Имя конструктора и границы `m`/`n` проверяет **тот же** `construct_fixed`,
  что и в объявлении переменной: второго знания о типе не заводится.
- Форма, не похожая на конструктор, получает `SE-034`, называющую ожидаемое, —
  вместо отказа о дефекте компилятора.

**Cons:** модификатор `sat` в параметре остаётся невыразимым: `q(8, 8) sat` в
позиции выражения — идентификатор за вызовом, и разбор отвергает его `SY-002`.

#### Option B. Подставить правило `Type` в `ParameterTypeExpr`

**Cons:** `identifier "(" number "," number ")"` — это и вызов функции; LALRPOP
даёт конфликт. Обходить его пришлось бы отдельным нетерминалом для «типа
параметра», то есть дублировать правило типа.

#### Option C. Оставить как есть (отказ `SE-034` вместо `SE-119`)

**Cons:** запись остаётся невыразимой, а библиотека над `q` — только через
`float` и флаг.

### Decision

Принимается **Option A**. Дополнительно исправляется вскрытый им дефект цели
`st`: Q-хелперы вставляются **перед первым POU** (строкой, начинающейся с
`FUNCTION`), а не перед первым `FUNCTION_BLOCK`.

### Consequences

#### Положительные

- Функция над fixed-point выразима явно, без глобального флага.
- `SE-119` перестала появляться на законной записи.
- Вывод цели `st` с Q-хелпером, вызываемым из функции, принимается `iec2c`.

#### Отрицательные / Action items

- `q(m, n) sat` в параметре невыразим — названная граница.
- Приведение **дробного литерала** к `q` в времени выполнения переводит только цель `c`
  (у прочих — названные отказы: нет floor в `no_std`, нет плавающей точки в
  RTL) — соседний класс, вынесен кандидатом. Арифметика над параметром-`q` без
  литерала переводится всеми (контроль).

#### Acceptance criteria

1. `fn whole(v: q(8, 8)) -> u8` переводится всеми восемью целями, и их
   инструменты вывод принимают.
2. Потактовая сверка с целью `c` совпадает (масштаб 2ⁿ не теряется).
3. Хелпер объявлен **раньше** функции, которая его зовёт; `iec2c` принимает.
4. Мутации «вставка перед `FUNCTION_BLOCK`» роняют тесты.
5. Вывод корпуса не изменился; предкоммит зелёный.

## Анализ

### Цель и контекст

Класс найден пробой «функция над `q`», снимавшейся в общем замере конструкций.

#### Замер (`scripts/probe.sh`, 2026-08-22)

Вход: `fn half(v: q(8, 8)) -> u8 { return v as u8; }`

| Потребитель | Ответ |
|---|---|
| эталон и **все восемь** целей | **`SE-119`**: «внутренний инвариант семантики нарушен: параметр функции без типа. Это дефект компилятора» |

Контроли той же формы:

| Вход | Ответ |
|---|---|
| `-> q(8, 8)` в возврате | переводится всеми |
| `duration` в параметре | переводится всеми |
| `[u8; 3]` в параметре | переводится всеми (0348, 0369) |

То есть ломался **параметризованный тип в параметре**, и только он.

#### Причина

`ParameterTypeExpr` грамматики хранит тип параметра **выражением**: имя типа —
`Expression::Variable`, массив — `Expression::Type`. Форма `q(8, 8)` приходит
`Expression::Function` (вызовом), потому что `q` — обычный идентификатор
(решение: иначе `q` перестал бы работать именем переменной). Ветвь
`_ => internal(…)` объявляла это дефектом компилятора.

#### Второй слой

После правки цель `st` дала невалидный вывод: `iec2c` — «')' missing at the end
of function invocation». Причина — **порядок POU**: `insert_helper` вставляла
`TAKT_Q_FLOORDIV` перед первым `FUNCTION_BLOCK`, а пользовательские `FUNCTION`
печатаются раньше блока. Опережающих ссылок в IEC 61131-3 нет.
Комментарий кода обещал «перед первым POU» — проза называла роль, которой у
кода не было.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. 0061 (тип `q`) и 0344 (порядок функций у `st`) закрыты.
- **Влияние на порядок разработки:** заводит кандидата «арифметика над
  параметром-`q` не переводится тремя целями».

### Требования и проверяемые условия

- **R1. Приём формы.** `fn f(v: q(m, n))` строит `TypeNode::Fixed`.
- **R2. Диагностика вместо внутренней.** Непохожая форма даёт `SE-034` с
  названным ожиданием, а не `SE-119`.
- **R3. Все цели.** Вход переводится восемью целями, инструменты вывод
  принимают.
- **R4. Значения.** Потактовая сверка с целью `c` совпадает — масштаб 2ⁿ не
  теряется.
- **R5. Порядок POU у `st`.** Хелпер объявлен раньше вызывающей функции.
- **R6. Неизменность.** Вывод корпуса не меняется.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1, R3 | `probe.sh`: восемь целей + инструменты |
| A2 | R4 | `fixed_parameter_values_match_generated_c` |
| A3 | R5 | `helper_precedes_the_function_that_calls_it` |
| A4 | R5 | `generated_st_is_accepted_by_iec2c` (прогон MatIEC) |
| A5 | R6 | `git diff examples/generated/` пуст |

### Особенности по обратной функциональности

Расширяется множество принимаемых записей; прежде принимавшееся не меняется.
Правка порядка хелперов меняет **место** их вставки в выводе `st` — но только
там, где хелпер вообще эмитится; корпус не затронут (проверено проверкой
детерминизма и диффом).

### Риски и зависимости

- **Форма `sat`** (`q(8, 8) sat`) в параметре остаётся невыразимой — названная
  граница; замер подтверждает `SY-002`.
- **Дробный литерал в приведении** (`2.0 as q(8, 8)`) переводит только цель
  `c`: фикстура сверки меняет значение приведением **из целого**, и это
  записано в её шапке. Контроль: `v * v` над параметром-`q` переводится всеми
  восемью целями.

## Разработка

### Задача

#### Что было

`fn half(v: q(8, 8))` давала `SE-119` — отказ о дефекте компилятора — у всех
девяти потребителей.

#### Что сделано

- `semantic/function.rs`: ветвь `ast::Expression::Function` в разборе типа
  параметра. Помощник `fixed_from_call` опознаёт форму «идентификатор + два
  числовых аргумента» и строит `ast::Type::Fixed`; дальше работает прежний
  `construct_type` → `construct_fixed` (имя `q` и границы `m`/`n` проверяет
  он).
- Форма, не похожая на конструктор типа, даёт **`SE-034`** с названным
  ожиданием («имя типа, `[тип; N]` или `q(m, n)`») вместо `SE-119`.
- `generator/st/st_fixed.rs`: `insert_helper` вставляет хелперы перед **первым
  POU** (`first_pou` — строка, начинающаяся с `FUNCTION`), а не перед первым
  `FUNCTION_BLOCK`.

**Статус по функциональности (правило 11).** Семантика — общая для всех
потребителей; отдельно правлена цель `st` (порядок хелперов). Прочие цели
изменений не потребовали: форму они получают уже разрешённым типом.

#### Проверки

```sh
cargo test                                    # 3376 тестов, 0 провалов
./scripts/probe.sh -n 3 <проба>.takt          # восемь целей: инструменты приняли
./scripts/precheck.sh
```

Мутация «вставка перед `FUNCTION_BLOCK`» роняет оба теста порядка хелперов.

## Итог (что сделано)

- `q(m, n)` в параметре функции распознаётся семантикой и строит
  `TypeNode::Fixed`; чужое имя конструктора отвергает прежний `SE-057`,
  неподходящая форма — `SE-034`, называющая ожидаемое.
- **Правило языка не менялось:** `q` не ключевое слово, и правило `Type` в
  позицию параметра не подставить — оно даёт конфликт LR(1) с вызовом функции.
  Форму опознаёт семантика, как и само имя `q` (`construct_fixed`).
- **Вторым слоем вскрылся дефект цели `st`:** Q-хелперы вставлялись перед
  первым `FUNCTION_BLOCK`, а пользовательские `FUNCTION` печатаются **до**
  него — функция, зовущая `TAKT_Q_FLOORDIV`, ссылалась на него раньше
  объявления, и `iec2c` отвечал «')' missing at the end of function
  invocation». Комментарий кода при этом обещал «перед первым POU» — проза
  называла роль, которой у кода не было.
- **Модификатор `sat` в параметре невыразим** (`q(8, 8) sat` — идентификатор
  за вызовом, `SY-002`): граница названа, замер её подтверждает.
- Соседний класс, вынесенный кандидатом: приведение **дробного литерала** к
  `q` в времени выполнения (`v * (2.0 as q(8, 8))`) переводит только цель `c` —
  одинаково в теле функции и в теле состояния. Арифметика над параметром-`q`
  **без литерала** (`v * v`) переводится всеми восемью целями (контроль).
- Вывод корпуса не изменился.

Детали — в [отчёте](0380-fixed-point-parameter.md#отчёт-о-тестировании).
