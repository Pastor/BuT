# Фича: Цель `sv` — частично прочитанный параметр-структура

- **Номер:** 0506
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `sv`: параметр-структура, прочитанный частично, даёт `UNUSEDSIGNAL`» (2026-09-02)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

`fn pick(v: Inner) -> u8 { return v.b; }` даёт `verilator` под `-Wall`
предупреждение «Bits of function variable are not used: 'v'[15:8]», а проверка цели
считает предупреждение **ошибкой** — то есть вывод не проходит проверка самой цели
при **нулевом** коде возврата `taktc`. Непрочитанные поля гасит тот же
поглотитель, которым цель уже гасит вовсе неиспользуемый параметр (0337),
непрочитанный структурный порт (0453) и непокрытые биты шины (0486).

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

## Документирование

**Не требуется.** Язык не меняется, диагностик не заводится: речь о форме
порождённого RTL.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, разработчик

### Context

Замер-02 (`scripts/probe.sh`), `struct Inner { a: u8, b: u8 }`,
`fn pick(v: Inner) -> u8 { return v.b; }`:

| Потребитель | Ответ |
|---|---|
| эталон, `c`, `c-hal`, `st`, `st-at`, `rust`, `plantuml` | исполняют / переводят, инструменты принимают |
| `sv`, `sv-mmio` | `verilator`: `UNUSEDSIGNAL` «Bits of function variable are not used: 'v'[15:8]» |

**Гранулярность правила измерена**, а не выведена:

| Вход | `verilator` |
|---|---|
| читается `v.b`, поле `a` не читается | **отвергает** (`v[15:8]`) |
| вложенная структура, читается `v.tail.y`, поле `head` не читается | **отвергает** (`v[23:16]` — это `head`) |
| вложенная, читаются `v.head` и `v.tail.y`, не читается лишь `tail.x` | **принимает** |
| читаются оба поля | принимает |

То есть инструмент судит по **полям верхнего уровня**: непрочитанный лист
глубже он не считает. Поглотитель печатается ровно по этой границе.

### Decision Drivers

- `lint_off` запрещён правилом проекта (0169): прагма гасит контроля, а не
  причину.
- Гасить **только непокрытое** — урок: поглотитель на весь сигнал скрыл бы
  и настоящий дефект печати.
- Приём и форма уже есть у трёх соседей (0337, 0387, 0453) — редукция с
  константой, которую синтезатор выбрасывает сам.

### Considered Options

1. **Поглотитель на непрочитанные поля верхнего уровня** (принято).
2. **Поглотитель на весь параметр** (`&{1'b0, v}`). Отвергнуто уроком:
   гасит и честные предупреждения.
3. **Печатать параметром только читаемые поля** (разложить структуру).
   Отвергнуто: меняет сигнатуру функции, которую читает человек, и расходится с
   прочими целями.

### Decision

Параметр структурного типа, который тело читает **только по полям**, получает
поглотитель на каждое поле верхнего уровня, которого тело не читает:
`logic _unused_<параметр>_<поле>;` и `_unused_<параметр>_<поле> = &{1'b0,
<параметр>.<поле>};`. Параметр, прочитанный целиком (упомянутый без точки),
поглотителя не получает.

### Consequences

- Вывод `sv` и `sv-mmio` проходит проверка цели на частично прочитанном параметре.
- У полностью прочитанного параметра вывод не меняется.

#### Acceptance criteria

1. Проба: `verilator` и `yosys` принимают вывод `sv` и `sv-mmio`.
2. Контроли: параметр, прочитанный целиком, и параметр, прочитанный по обоим
   полям, поглотителя не получают.
3. Непрочитанный лист глубже верхнего уровня поглотителя не получает — так
   отвечает инструмент.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Заглушка вовсе неиспользуемого параметра живёт в
`generator/sv/sv_unused.rs` (0337) и судит по **напечатанному** тексту.
Частичное использование (имя только как индекс массива) судит признак по
**дереву** — `sv_stmt::index_only_variables` (0466): объявление поглотителя
обязано встать до операторов, то есть до того, как тело напечатано. Поля —
тот же случай, и признак строится тем же способом.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | Поглотитель печатается на поля верхнего уровня, которых тело не читает |
| Т2 | Параметр, упомянутый как целое, поглотителя не получает |
| Т3 | Объявление — до операторов, присваивание — после тела (порядок 0387) |
| Т4 | Инструменты проверки (`verilator`, `yosys`) принимают вывод |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh`, набор целей с прогоном
`verilator`, `precheck.sh`.

### Редакторский слой

**Не требуется:** язык и диагностики не затронуты.

### Особенности по обратной функциональности

Расширение: вывод, не проходивший проверка цели, начинает проходить. Для программ
без частично прочитанных параметров вывод не меняется.

### Риски и зависимости

- **Риск:** поглотитель погасит честное предупреждение. Снимается гранулярностью
  (только непрочитанные поля) и контролями в наборе.

## Разработка

### Задача: признак «имя читается только по полям»

`generator/sv/sv_stmt.rs::field_only_reads` — по образцу
`index_only_variables` (0466) и тем же обходом дерева: считает употребления
имени и употребления под доступом к полю. Совпали — имя читается только по
полям, и множество полей возвращается; нет — имя упомянуто как целое, и
поглощать нечего.

### Задача: поглотитель непрочитанных полей

`generator/sv/sv_func.rs`: для параметра структурного типа поля, которых нет в
множестве прочитанных, получают `logic _unused_<параметр>_<поле>;` до операторов
и присваивание редукцией после тела — тот же порядок, что у поглотителя
локальной (0387) и частично прочитанного параметра-индекса (0466).

## Тест-план

| Проверка | Ожидание |
|---|---|
| читается одно поле из двух | поглотитель на непрочитанное, у прочитанного его нет |
| контроль: читаются оба поля | поглотителя нет |
| контроль: параметр упомянут как целое (`return v;`) | поглотителя нет |
| `verilator --lint-only -Wall` на обоих входах | принимает |
| проба по девяти потребителям | `verilator` и `yosys` принимают `sv` и `sv-mmio` |

## Отчёт о тестировании

### Резюме

`./scripts/precheck.sh` — зелёный. Пробы: частично прочитанный параметр,
вложенная структура и полностью прочитанный параметр — `verilator` и `yosys`
принимают вывод обеих целей `sv`.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка — три мутации, каждая поймана:

| Мутация | Ответ набора |
|---|---|
| поглотителя нет (прежнее поведение) | форма вывода **и** прогон `verilator` |
| поглощаются все поля | контроль «читаются оба» и проверка «у прочитанного поглотителя нет» |
| признак не различает «имя целиком» | контроль `return v;` |

Вторая и третья мутации — про **границу**: поглотитель, поставленный шире
нужного, гасит честные предупреждения инструмента, и класс молча вернётся уже
как чужой дефект. Оба контроля стоят в наборе ради этого.

### Найденные дефекты

Дефектов правки нет. Гранулярность правила снята **прогоном**: `verilator`
судит по полям верхнего уровня и непрочитанный лист глубже не считает — вход
«не читается лишь `tail.x`» инструмент принимает и без поглотителя.

### Выводы и дальнейшие шаги

Корпус такой формы не содержит — снимки `examples/generated/` не изменились.

## Итог (что сделано)

Параметр структурного типа, который тело читает только по полям, получает
поглотитель на каждое непрочитанное поле верхнего уровня. Прежде `verilator`
под `-Wall` отвечал `UNUSEDSIGNAL`, а проверка цели считает предупреждение
ошибкой — то есть вывод не проходил проверка самой цели при нулевом коде возврата
`taktc`.

Граница измерена, а не выведена: инструмент судит по полям верхнего уровня, и
поглотитель печатается ровно по ней — шире гасить нельзя, иначе замолчат и
честные предупреждения.
