сознательно отложена: решение о судьбе `~0` (запись выше) меняет то, что в

### Context

Фича сделала инициализатор объявления **вычисляемым при сборке** и ввела
правило «имя в инициализаторе значит начальное значение и ссылается только
назад по тексту». Документ об этом молчал: раздел «Типы данных» описывал лишь
вывод типа из инициализатора.

Часть предмета всё же описана — фича добавила в раздел «Выражения и
условия» абзац о **нормировке вычисленного** значения (`~0` даёт 255 при `u8`)
против литерала автора (`SE-089`). Значит недостающее — именно **свёртка**:
что значение известно до запуска, что имя даёт начальное значение и что
порядок объявлений значим.

**Проба при взятии фичи вскрыла дефект** (2026-08-17): ссылка **вперёд**
принималась молча и давала `0` у эталона против `1` в прошивке. Описывать
правило, которое инструменты не соблюдают, нельзя, поэтому диагностику завела
отдельная [ссылка вперёд в инициализаторе переменной — ошибка компиляции](0246-init-forward-reference.md) (решение
заказчика: «сначала диагностика, потом документ»).

### Decision Drivers

1. **Документ обязан описывать язык, каким он есть.** Свёртка меняет
   наблюдаемое поведение объявления — читатель обязан о ней знать.
2. **Правило 25.** Подробности нормировки уже живут в «Выражениях»; дублировать
   их в «Типах» нельзя — только сослаться.
3. **Правило 27(д).** Числа в разделе обязаны браться из прогона, а не из
   рассуждения.
4. **Соразмерность.** Предмет — свойство объявления; заводить ради него новый
   раздел (правило 24 — отдельная фича) несоразмерно.

### Considered Options

#### Option A. Подраздел в «Типах данных» рядом с «Выводом типов»

**Pros:**
- предмет — свойство **объявления**, а объявления и вывод типа описаны там же;
- читатель встречает правило в том месте, где узнаёт про инициализатор;
- ссылка на «Выражения» покрывает нормировку без дублирования (правило 25).

**Cons:**
- раздел «Типы данных» и без того велик.

#### Option B. Дописать в раздел «Выражения и условия»

**Pros:**
- там уже описана нормировка вычисленного — предмет рядом.

**Cons:**
- «Выражения» описывают **формы записи**, а свёртка — свойство объявления;
- правило «ссылка только назад» касается порядка **объявлений**, о котором
  раздел выражений не говорит вовсе.

#### Option C. Новый раздел «Объявления»

**Pros:**
- предмет виден в оглавлении.

**Cons:**
- правило 24: новый раздел — отдельная фича с полным циклом;
- объявления описаны по частям в «Типах», «Моделях» и «Портах» — перенос их в
  новый раздел выходит далеко за объём этой фичи.

### Decision

Принимается **Option A**.

Состав правки:

1. Подраздел **«Инициализатор вычисляется при сборке»** в
   `book/src/03-types/index.typ` после «Вывода типов»: значение известно до
   запуска; имя значит **начальное** значение (пример со снимком переменной,
   которая позже растёт); ссылка только **назад** по тексту, иначе `SE-109`;
   у констант порядок не важен; невычислимое (порт, `extern`) остаётся как
   есть; нормировка — ссылкой на «Выражения» (правило 25).
2. Блок «Частые ошибки» раздела дополняется `SE-109`.
3. Все числа примеров берутся из прогона симулятора.

### Consequences

#### Положительные

- Правило «только назад» получает в документе то же звучание, что в
  компиляторе, — и подкреплено кодом диагностики.

#### Отрицательные / Action items

2. Примеры подраздела — инлайн-блоки, а не отдельный файл: они иллюстрируют

   Числа проверены прогоном при разработке и приведены в отчёте.

#### Acceptance criteria

1. Подраздел существует, описывает: вычисление при сборке, «имя = начальное
   значение», «ссылка только назад» с `SE-109`, порядок у констант,
   невычислимые инициализаторы.
2. Нормировка не дублируется — стоит ссылка на «Выражения».
3. «Частые ошибки» дополнены `SE-109`.
4. Все числа примеров подтверждены прогоном.
5. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Описать в документе свёртку инициализатора: значение известно до
запуска, имя значит начальное значение, ссылка — только назад по тексту.
Решение о месте — ADR (Option A: подраздел в «Типах данных»).

### Зависимости фичи (правило 17/19)

- **Зависит от:** [ссылка вперёд в инициализаторе переменной — ошибка компиляции](0246-init-forward-reference.md) —
  **закрыта** 2026-08-17. Обоснование: правило «ссылка только назад» до неё не
  соблюдалось инструментами (эталон `0`, прошивка `1`), и документ описывал бы
  обещание, а не правило.
- **Влияние на порядок разработки:** никого не блокирует.

### Требования и проверяемые условия

- **R1. Свёртка описана**: инициализатор вычисляется при сборке, до цели
  доезжает значение.
- **R2. Имя = начальное значение**: показано на переменной, которая меняется в
  теле, — инициализатор берёт её стартовое значение.
- **R3. Порядок объявлений**: ссылка назад законна, ссылка вперёд — `SE-109`;
  у констант порядок не важен.
- **R4. Невычислимое названо**: значение порта и `extern` остаются вычисляемыми
  при инициализации на устройстве.
- **R5. Нормировка не дублируется** — ссылка на раздел «Выражения» (правило 25).
- **R6. Числа подтверждены прогоном** (правило 27д в части проверки).
- **R7. «Частые ошибки» дополнены** `SE-109` (правило 26).

## Разработка

### Задача

#### Что было

Раздел «Типы данных» описывал только вывод типа из инициализатора. О том, что
инициализатор **вычисляется при сборке**, что имя в нём значит **начальное
значение** и что ссылаться можно только **назад по тексту**, документ молчал.

#### Что сделано

Подраздел **«Инициализатор вычисляется при сборке»** после «Вывода типов»
(`book/src/03-types/index.typ`, метка
`<инициализатор-вычисляется-при-сборке>`):

- значение известно до запуска, до цели доезжает число (`const AREA := WIDTH *
  WIDTH;` → 16);
- **имя = начальное значение**: показано переменной, которая растёт в теле, —
  снимок берёт стартовое значение (`snapshot = 11` при `n`, идущей 1, 2, 3 …);
- **порядок объявлений значим**: ссылка назад законна (`early = 8`), ссылка
  вперёд — ошибка `SE-109`;
- **у констант порядок не важен**: `const A := B + 1;` перед `const B := 3;`
  даёт 4;
- **невычислимое остаётся как есть**: значение входного порта и результат
  `extern` берутся при инициализации на устройстве;
- **нормировка вычисленного** не дублируется — ссылка на раздел «Выражения и
  условия» (правило 25).

Блок «Частые ошибки» раздела дополнен `SE-109`.

#### Проверки

Все числа подраздела собраны в одну модель и прогнаны:

```takt
const WIDTH: u8 := 4;
const AREA := WIDTH * WIDTH;
var level: u8 := WIDTH + 1;
var n: u8 := 1;
var snapshot: u8 := n + 10;
var later: u8 := 7;
var early: u8 := later + 1;
```

```text
Шаг 1: [Run]  early=8  later=7  level=5  n=2  probe=16  snapshot=11
```

`AREA` наблюдается через `probe := AREA` (константы в трассу не печатаются).
Утверждение о константах проверено отдельной пробой: `var v := LATER + 1;
const LATER := 3;` даёт 4 и у эталона, и у цели `c`.

```sh
make -C book pdf                # сборка, ссылка на «Выражения» разрешается
./scripts/check-book-glyphs.py  # 60 файлов, символов вне шрифта нет
```

#### Трасса, из которой взяты числа

```text
Шаг 1: [Run]  early=8  later=7  level=5  n=2  probe=16  snapshot=11
```

`probe := AREA` показывает значение константы (константы в трассу не
печатаются); `n = 2` на первом такте — переменная уже выросла, а `snapshot`
остался `11`, то есть инициализатор взял её **начальное** значение.

### Правило 29 (редакторский слой)

**Не требуется, ответ зафиксирован.** Язык не меняется, правится документ.

### Вердикт

**Готово.** Требования R1…R7 выполнены, критерии A1…A6 закрыты, предкоммит
зелёный.

## Итог (что сделано)

В разделе «Типы данных» появился подраздел **«Инициализатор вычисляется при
сборке»**: значение известно до запуска; имя в инициализаторе значит
**начальное** значение (показано переменной, которая растёт в теле, — снимок
остаётся `11`); ссылаться можно только **назад по тексту**, иначе `SE-109`; у
констант порядок объявлений не важен; невычислимое (порт, `extern`) остаётся
вычисляемым при инициализации на устройстве. Нормировка вычисленного значения
не дублируется — стоит ссылка на «Выражения и условия» (правило 25). Блок
«Частые ошибки» дополнен `SE-109`.

Все числа подраздела взяты из прогона (`AREA = 16`, `level = 5`,
`snapshot = 11`, `early = 8`), утверждение о константах проверено на эталоне и
цели `c`.

Оговорка кандидата — «правка отложена до решения о судьбе `~0`» — снята: тот
вопрос закрыт фичей [отрицание ~0 для беззнакового типа: два правила языка столкнулись](0207-bitwise-not-unsigned-literal.md), и её
результат описан в разделе «Выражения», куда подраздел и ссылается.

Фича стала возможна после [ссылка вперёд в инициализаторе переменной — ошибка компиляции](0246-init-forward-reference.md): проба при
взятии показала, что ссылка вперёд даёт `0` у эталона и `1` в прошивке —
описывать правило, которого инструменты не соблюдают, было нельзя.

Детали — в [отчёте](0222-book-variables-const-fold.md#отчёт-о-тестировании) и
[задаче](0222-book-variables-const-fold.md#разработка).
