# Фича: Пропущенные метки версий языка и контроль правила 22

- **Статус:** ГОТОВО

## Краткое описание

Версия языка `0.3.0 → 0.4.0` поднята фичей [семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md),
но коммит подъёма **не помечен тегом** — нарушение правила 22 («подъём
помечается тегом»). В истории есть `v0.3.0` и `v0.5.0`, между ними разрыв.

> Фича зарегистрирована из бэклога кандидатов (отобрана заказчиком 2026-07-28); далее проходит жизненный цикл по правилу 17.

## Что известно на входе

- Тегов `v0.3.0` и `v0.5.0` в истории есть, `v0.4.0` — нет.
- Правило 22 требует тег **на тот самый коммит**, который меняет номер версии:
  только так по истории видно, где проходит граница версии.
- Коммит подъёма ищется по `git log -S '0.4.0' -- takt-lang/src/version.rs`.

## Направление решения (наметка, не решение)

- Ретроспективный **аннотированный** тег `v0.4.0` на коммит подъёма 0078.
- Тег на старый коммит — **решение заказчика**: это переписывание меток
  истории, и если тег уже был где-то опубликован, последствия шире репозитория.

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

## Документирование (правило 24)

**Не требуется.** Метка истории; язык не меняется.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-18
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича](0162-git-tag-v040.md); правило 22 свода; прецедент проверки — [ADR](0085-language-version-constant.md#архитектура-adr)

### Context

Правило 22 требует: коммит, поднимающий версию языка, снабжается аннотированным
тегом `v<версия>`, и **на тот самый коммит**, а не на последующие — «только так
по истории видно, где проходит граница версии». Карточка 0162 сообщала об одном
пропуске: `v0.4.0`.

**Замер-18: пропусков два, и второй свежий.** Сопоставление тегов с
коммитами подъёма (`git rev-parse "v$V^{commit}"` против
`git log -S"Версия языка: $V" -- README.md`):

| Версия | Коммит подъёма | Фича | Тег |
|---|---|---|---|
| 0.3.0 | `32e69225` | 0029 | `v0.3.0` |
| **0.4.0** | `dfec3988` | **0078** | **нет** |
| 0.5.0 | `ff4a53ad` | 0100 | `v0.5.0` |
| 0.6.0 | `aa3e027a` | 0128 | `v0.6.0` |
| 0.7.0 | `68e9852b` | 0144 | `v0.7.0` |
| 0.8.0 | `55098c56` | 0185 | `v0.8.0` |
| 0.9.0 | `c7557aed` | 0207 | `v0.9.0` |
| **0.10.0** | `47e5a5fb` | **0243** | **нет** |

Шесть существующих тегов **аннотированные** и стоят ровно на коммитах подъёма —
правило соблюдается, когда о нём вспоминают. Пропущено **два из восьми**, то
есть четверть, и последний пропуск сделан **позавчера** (0243, 2026-08-17).
Вывод очевиден: у правила 22 нет контроля, а правило без контроля исполняется
через раз — тот самый довод, которым заведена константа версии.

**Подъём 0.3.0 → 0.4.0 разорван на два коммита, и это осложняет выбор.**
`dfec3988`  объявил подъём **в `CHANGES.md`** («Версия языка
**0.3.0 → 0.4.0**»), но строку README `**Версия языка: 0.3.0**` не тронул —
её исправил только `8f8a03a1`, заводившая константу и проверка
синхронизации. То есть README отставал на две фичи, и отставание это —
ровно тот дефект, ради которого 0085 и появилась.

### Decision Drivers

1. **Тег обозначает границу версии, а не момент починки документа.** Граница
   задана фичей, поднявшей версию, — иначе история приписывает подъём фиче,
   языка не менявшей.
2. **Правило без команды — не правило**. Пропуск в 25 %
   при живом правиле измерен, а не предположен.
3. **Контроль не имеет права мешать самому подъёму.** Тег ставится на коммит,
   а `precheck.sh` идёт **до** коммита: наивная проверка «тег текущей версии
   существует» падала бы у каждой фичи, поднимающей версию, — то есть ровно
   там, где правило исполняется верно.
4. **Ретроспективный тег — решение заказчика** (зафиксировано в карточке и
   строке `FEATURES.md`): это метка на старый коммит, и последствия шире
   репозитория, если тег уже публиковался.

### Considered Options

#### Option A. Поставить только `v0.4.0`, как записано в карточке

**Pros:**
- Буквальное исполнение карточки.

**Cons:**
- Оставляет **свежий** пропуск `v0.10.0` — тот же класс, найденный тем же
  замером; он потребовал бы второй фичи с тем же ADR.
- Не заводит контроля: третий пропуск случится так же молча, как второй.

#### Option B. Оба тега + контроль правила 22

**Pros:**
- Снимает класс целиком: история версий размечена без разрывов.
- Правило 22 становится машинным, как правило про константу (0085) и про адрес
  репозитория (0179).

**Cons:**
- Область шире карточки (расширение фиксируется здесь).
- Контроль требует аккуратности: он обязан молчать в момент подъёма (драйвер 3) и
  не ломать CI, где `actions/checkout` по умолчанию тегов не выкачивает.

#### Option C. Вариант B + сверка всех прошлых версий по истории

**Pros:**
- Ловил бы и пропуск, найденный задним числом.

**Cons:**
- Перечня версий в дереве нет: README документирует **два** перехода из восьми,
  а восстанавливать список из `git log -S` — значит завести проверка, зависящий от
  формулировок старых коммитов. Такой проверка ломается от переписывания истории и
  от смены фразы в README.
- Прошлое размечается **один раз** — этой фичей; контролировать его дальше нечего.

### Decision

Принимается **Option B**.

1. `v0.4.0` — аннотированный тег на **`dfec3988`**, коммит,
   объявивший подъём в `CHANGES.md`. Выбор между ним и `8f8a03a1` (где строка
   README догнала константу) решён в пользу границы: подъём делает **первая
   закрытая фича цикла** (правило 22), а 0085 языка не меняла — она чинила
   отставание документа. Тег на 0085 приписал бы подъём не той фиче.
2. `v0.10.0` — аннотированный тег на **`47e5a5fb`**, где README и
   константа изменены одним коммитом (разрыва, как у 0.4.0, здесь нет).
3. Заводится `scripts/check-version-tag.sh` (шаг `precheck.sh`): тег
   `v<LANGUAGE_VERSION>` существует, **аннотированный** и указывает на коммит,
   достижимый из `HEAD`.
4. **Проверка молчит, пока подъём не закоммичен.** Признак — расхождение
   `LANGUAGE_VERSION` в рабочем дереве и в `HEAD`: версия поднята, но коммита
   ещё нет, значит и тегу взяться неоткуда. Как только подъём закоммичен,
   версии совпадают и тег становится обязателен. Так контроль не мешает подъёму и
   при этом стережёт **текущую** версию — то есть поймал бы пропуск `v0.10.0`
   на первом же прогоне после 0243.
5. CI получает `fetch-depth: 0` у `actions/checkout`: по умолчанию он делает
   поверхностный клон **без тегов**, и под `PRECHECK_STRICT=1` проверка иначе падал
   бы не по делу.

### Consequences

#### Положительные

- История версий языка размечена без разрывов: восемь версий — восемь тегов.
- Правило 22 обрело контроля; третий пропуск невозможен молча.
- Контроль стережёт **свежую** версию, а не только прошлое, — там и был пропуск.

#### Отрицательные / Action items

- Прошлые пропуски контроль не ищет: список версий в дереве неполон (Option C).
  Разметка прошлого сделана **один раз**, этой фичей.
- Проверка зависит от наличия тегов в клоне. Вне CI (`git clone` тянет теги по
  умолчанию) это не проблема; в CI поведение задано явно `fetch-depth: 0`.
  Прогоны GitHub Actions в проекте заблокированы по биллингу, поэтому
  правка workflow **проверена локально и не проверена в CI** — это записано
  как граница, а не выдано за проверку.

#### Acceptance criteria

1. `git tag -l` содержит восемь тегов `v0.3.0`…`v0.10.0` без разрывов (A1).
2. `v0.4.0` и `v0.10.0` — **аннотированные** и указывают на `dfec3988` и
   `47e5a5fb` соответственно (A2).
3. `scripts/check-version-tag.sh` зелен на текущем дереве (A3).
4. Контроль падает, если тег текущей версии убрать, и молчит, если версия в
   рабочем дереве опережает `HEAD` (A4, мутация).
5. `./scripts/precheck.sh` зелён с включённым шагом (A5).

## Анализ

### Цель и контекст

Правило 22 требует аннотированный тег `v<версия>` на коммите, поднимающем
версию языка. Карточка сообщала об одном пропуске (`v0.4.0`); замер нашёл два и
показал, что правило исполняется через раз, потому что у него нет команды
проверки — довод, которым в проекте уже заведены проверки константы версии  и адреса репозитория.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Правка не трогает язык, компилятор, симулятор и вывод
  целей; ни одна незакрытая фича таблицы её не предваряет.
- **Влияние на порядок разработки:** никого не разблокирует. Соприкасается с
  [дожатие CI-верификации 0090 после разблокировки Actions](0175-ci-verification-followup.md) (дожатие CI): правка
  `ci.yml` сделана здесь и **не проверена прогоном CI** — Actions заблокированы
  по биллингу. Это записано границей в ADR и в отчёте, а не выдано за проверку.

### Замер (основание решений)

Сопоставление тегов с коммитами подъёма. Коммит подъёма ищется по строке
README (`git log -S"Версия языка: $V" -- README.md`), тег разыменовывается
`git rev-parse "v$V^{commit}"` — **через `^{commit}`**: у аннотированного тега
`rev-parse` без разыменования отдаёт объект тега, и наивное сравнение хешей
даёт ложное «тег указывает не туда» у **всех** шести существующих тегов.

| Версия | Коммит подъёма | Фича | Тег |
|---|---|---|---|
| 0.3.0 | `32e69225` | 0029 | `v0.3.0` |
| **0.4.0** | `dfec3988` | **0078** | **нет** |
| 0.5.0 | `ff4a53ad` | 0100 | `v0.5.0` |
| 0.6.0 | `aa3e027a` | 0128 | `v0.6.0` |
| 0.7.0 | `68e9852b` | 0144 | `v0.7.0` |
| 0.8.0 | `55098c56` | 0185 | `v0.8.0` |
| 0.9.0 | `c7557aed` | 0207 | `v0.9.0` |
| **0.10.0** | `47e5a5fb` | **0243** | **нет** |

Все шесть существующих тегов — **аннотированные** и стоят ровно на коммитах
подъёма. Пропущено два из восьми (25 %), причём второй пропуск сделан
**накануне** замера (фича-17): это не наследие давнего периода, а
действующая дыра.

#### Разрыв подъёма 0.3.0 → 0.4.0

`dfec3988`  объявил подъём **в `CHANGES.md`**, но строку README
`**Версия языка: 0.3.0**` не тронул: она осталась `0.3.0` и была исправлена
только `8f8a03a1`. Проверено чтением README на `dfec3988` и на его
родителе — строка одна и та же.

Выбор коммита под тег — **решение анализа**, а не механика: правило 22 говорит
«коммит, который меняет номер версии в `README.md` и `CHANGES.md`», а здесь эти
два изменения разъехались на две фичи. Взят `dfec3988`, потому что правило там
же говорит: «подъём делает **первая закрытая фича цикла**». Фича языка не
меняла — она чинила отставание документа (и завела проверка, чтобы отставание
больше не возникло); тег на ней приписал бы подъём не той фиче.

### Требования и проверяемые условия

- **R1. Разметка без разрывов.** Каждой версии языка 0.3.0…0.10.0 отвечает тег
  `v<версия>`.
- **R2. Теги аннотированные и на месте.** Новые теги — аннотированные, стоят на
  измеренных коммитах подъёма, достижимы из `HEAD`.
- **R3. Правило 22 имеет контроля.** Закоммиченная версия без тега валит
  предкоммит.
- **R4. Контроль не мешает подъёму.** Пока подъём не закоммичен, проверка молчит и
  подсказывает команду тега.
- **R5. Строгий режим отличается от мягкого.** Клон без тегов — мягкий пропуск
  локально и ошибка под `PRECHECK_STRICT=1`; CI получает полный клон.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1: восемь тегов без разрывов | `git tag -l \| sort -V` |
| A2 | R2: теги аннотированные, на измеренных коммитах | `git for-each-ref` + `git rev-parse "v$V^{commit}"` |
| A3 | R3: проверка зелен на текущем дереве | `scripts/check-version-tag.sh` |
| A4 | R3–R5: поведение проверки | `scripts/test-version-tag.sh` — восемь проверок в temp-репозитории |
| A5 | Проверка в предкоммите | `./scripts/precheck.sh` зелён, шаг виден в выводе |

### Особенности по обратной функциональности

Обратная совместимость **не затрагивается**: код, язык и вывод целей не
меняются. Версия языка **не растёт** (правило 22): фича проставляет метки уже
случившихся подъёмов.

**Единственное необратимое действие — публикация тегов.** Тег на старый
коммит есть метка истории; если бы `v0.4.0` или `v0.10.0` уже публиковались с
другим содержимым, замена сломала бы клоны потребителей. Проверено: обоих тегов
нет ни локально, ни на `origin` (`git ls-remote --tags`), то есть публикуется
новое имя, а не подменяется существующее.

### Редакторский слой (правило 29)

**Проверка не нужна, и это ответ.** Лексика, синтаксис и семантика языка не
меняются; ни `takt-lang/src/lsp/`, ни плагины `extensions/` не затрагиваются.

### Риски и зависимости

- **Риск: проверка мешает самому подъёму** (тег ставится на коммит, предкоммит идёт
  до коммита). Снят признаком незакоммиченного подъёма — расхождением константы
  в рабочем дереве и в `HEAD`; контроль проверяет это отдельным пунктом.
- **Риск: CI падает из-за отсутствия тегов** в поверхностном клоне. Снят
  `fetch-depth: 0` у задания `ubuntu` (задание `windows` гоняет только
  `cargo test` и правки не требует). Прогоном CI **не проверено** — Actions
  заблокированы по биллингу.
- **Граница: прошлые пропуски контроль не ищет.** Перечня версий в дереве нет
  (README документирует два перехода из восьми), а восстанавливать его из
  `git log -S` значит завести проверка, зависящий от формулировок старых коммитов.
  Прошлое размечено один раз — этой фичей.

## Разработка

### Задача

#### Что было

Правило 22 требует аннотированный тег `v<версия>` на коммите подъёма версии
языка. Тегов не имели **две** версии из восьми: `v0.4.0` (подъём фичи) и
`v0.10.0` (подъём фичи, сделанный накануне). Контроля у правила не было.

#### Что сделано

**1. Ретроспективные аннотированные теги.**

| Тег | Коммит | Фича | Почему этот коммит |
|---|---|---|---|
| `v0.4.0` | `dfec3988` | 0078 | объявил подъём в `CHANGES.md`; строка README догнала константу двумя фичами позже (0085), но границу задаёт первая закрытая фича цикла |
| `v0.10.0` | `47e5a5fb` | 0243 | README и константа изменены одним коммитом — разрыва нет |

Сообщения тегов называют, **что** изменилось в языке, и несут трейлер
`Feature: 0162` — по нему видно, что метка проставлена задним числом, а не
рукой автора подъёма.

**2. Проверка `scripts/check-version-tag.sh`** (шаг `precheck.sh`). Проверяет три
свойства тега текущей версии: существует, **аннотированный** (лёгкий не несёт
ни автора, ни даты, ни сообщения — метка границы без них половину смысла
теряет), достижим из `HEAD`.

**Ключевое требование к проверке — молчать в момент подъёма.** Тег ставится
**на** коммит, а предкоммит идёт **до** коммита: наивная проверка «тег текущей
версии существует» падала бы у каждой фичи, которая правило 22 исполняет
**верно**, и её бы отключили. Признак незакоммиченного подъёма — расхождение
значения константы в рабочем дереве и в `HEAD`; в этом случае проверка печатает
пропуск и **подсказывает команду** `git tag -a v<версия> …`.

**Обратная сторона того же признака:** как только подъём закоммичен,
значения совпадают и тег обязателен — поэтому пропуск `v0.10.0` был бы пойман
на **первом же** прогоне после фичи. Проверка проверяет **свежую** версию, а
не только прошлое; прошлое размечено один раз, этой задачей (граница в ADR).

**3. Контроль `scripts/test-version-tag.sh`** — восемь проверок в
temp-репозитории через `VT_ROOT` (образец `NF_ROOT` у `test-new-feature.sh`).

**Контроль нашёл дефект в первой редакции проверки.** Проверка «тега нет» падала:
в свежем репозитории тегов **нет вовсе**, и раньше срабатывала ветвь «клон без
тегов». Это не дыра, а честная граница — различить «тег потерян» и «теги не
выкачаны» нечем, — но её нужно было **назвать**: теперь она записана в
заголовке проверки, а проверка ставит посторонний тег `probe-base`, чтобы
проверять отсутствие **тега версии**, а не пустоту списка.

**4. CI: полный клон.** `actions/checkout@v4` в задании `ubuntu` получил
`fetch-depth: 0`: по умолчанию он берёт один коммит **без тегов**, и под
`PRECHECK_STRICT=1` проверка падал бы не по делу. Задание `windows` правки не
требует — оно гоняет только `cargo test`, без `precheck.sh`.

#### Проверки

```sh
git tag -l | sort -V              # v0.3.0 … v0.10.0, восемь без разрывов
git ls-remote --tags origin       # v0.4.0 и v0.10.0 на origin отсутствовали
scripts/check-version-tag.sh      # OK: v0.10.0 → 47e5a5fb
scripts/test-version-tag.sh       # восемь проверок, все пройдены
./scripts/precheck.sh
```

Соответствие условиям анализа: R1 — A1, R2 — A2, R3 — A3/A4, R4 — A4
(пункт «незакоммиченный подъём»), R5 — A4 (мягкий/строгий) и A5.

**Правка `ci.yml` прогоном CI не проверена** — Actions заблокированы по
биллингу ([дожатие CI-верификации 0090 после разблокировки Actions](0175-ci-verification-followup.md)). Проверены
отступы YAML и то, что второе задание правки не требует; это граница, а не
проверка.

## Тест-план

### Область и цель

Фича языка не меняет, поэтому правило 16 (примеры и контрпримеры языка) к ней
**не применяется**. Проверяется разметка истории (R1, R2) и поведение контроля
правила 22 (R3–R5).

**Ключевая проверка — T6, «контроль молчит в момент подъёма».** Тег ставится
**на** коммит, а предкоммит идёт **до** коммита: проверка, падающий при
незакоммиченном подъёме, мешал бы ровно тем фичам, которые правило исполняют
верно, — и его бы отключили. Это единственная проверка, отказ которой означает
не дефект проверки, а его непригодность.

**T4 требует посторонний тег в репозитории.** Различить «тег версии потерян»
и «теги не выкачаны» нечем, поэтому в репозитории **без единого** тега проверка по
построению выбирает мягкий пропуск. Проверка отсутствия тега версии обязана
идти при наличии хотя бы одного другого тега — иначе она проверяет ветвь T8, а
не себя (дефект первой редакции контроля).

### Выводы и дальнейшие шаги

1. **Контроль нашёл дефект в собственном проверке.** Первая редакция проверки «тега
   нет» падала: в свежем temp-репозитории тегов нет **вовсе**, и срабатывала
   ветвь «клон без тегов». Различить «тег потерян» и «теги не выкачаны» нечем —
   это честная граница, но её нужно было **назвать**. Теперь она в заголовке
   проверки, а проверка ставит посторонний тег, чтобы проверять отсутствие **тега
   версии**, а не пустоту списка.
2. **Замер потребовал `^{commit}`.** У аннотированного тега `git rev-parse v0.5.0`
   отдаёт объект **тега**, а не коммит; наивное сравнение хешей дало ложное
   «тег указывает не туда» у всех шести существующих тегов и едва не увело
   вывод в «историю переписывали». Разыменование — часть замера, а не деталь.
3. **Проверка стережёт свежую версию, а не только прошлое.** После коммита подъёма
   версии в дереве и в `HEAD` совпадают, и тег становится обязателен — пропуск
   `v0.10.0` был бы пойман на первом же прогоне после фичи.
4. **Исправлений не требуется.** Дефектов, заводящих `docs/fixes/0162-YY-*`,
   не найдено.
5. **Вынесено кандидатом** (правило 28): комментарий задания `windows` в
   `ci.yml` ссылается на однопоточный прогон «как требуют CLAUDE.md и
   precheck.sh», хотя фича сняла `--test-threads=1`; сам флаг там остался.
   Правка меняет поведение CI, проверить которое сейчас нечем, — потому вынесена,
   а не сделана попутно.

## Итог (что сделано)

История версий языка размечена без разрывов: восемь версий — восемь
аннотированных тегов. Проставлены `v0.4.0` на `dfec3988` (подъём фичи) и
`v0.10.0` на `47e5a5fb` (подъём фичи). Правило 22 обрело контроля —
`scripts/check-version-tag.sh` со контролем `scripts/test-version-tag.sh`, оба
шагами предкоммита.

**Пропусков оказалось два, и второй сделан накануне.** Карточка знала об
одном (`v0.4.0`). Замер показал: из восьми версий тегов не имели две, причём
`v0.10.0` — подъём фичи от 2026-08-17, то есть дыра действующая, а не
наследие давнего периода. Один пропуск закрывается тегом; два из восьми, с
последним вчерашним, закрываются **проверкой**.

**Коммит под `v0.4.0` пришлось выбирать, а не находить.** Подъём
0.3.0 → 0.4.0 разорван: `dfec3988`  объявил его в `CHANGES.md`, а
строку README `**Версия языка: 0.3.0**` исправил только `8f8a03a1` (заводившая константу и проверка синхронизации) — то есть документ отставал на две
фичи, и это ровно тот дефект, ради которого 0085 и появилась. Взят `dfec3988`:
правило 22 говорит, что подъём делает **первая закрытая фича цикла**, а 0085
языка не меняла. Тег на ней приписал бы подъём не той фиче.

**Проверка обязан молчать в момент подъёма — иначе он вреден.** Тег ставится
**на** коммит, а предкоммит идёт **до** коммита: наивная проверка «тег текущей
версии существует» падала бы у каждой фичи, которая правило исполняет **верно**.
Признак незакоммиченного подъёма — расхождение константы в рабочем дереве и в
`HEAD`; в этом случае проверка печатает пропуск и подсказывает команду тега. Как
только подъём закоммичен, тег обязателен, — поэтому пропуск `v0.10.0` был бы
пойман на первом же прогоне после 0243.

**Замер потребовал `^{commit}`.** У аннотированного тега `git rev-parse v0.5.0`
отдаёт объект **тега**, а не коммит: наивное сравнение хешей дало ложное «тег
указывает не туда» у всех шести существующих тегов и едва не увело вывод в
«историю переписывали». Разыменование — часть замера.

**Граница названа:** прошлые пропуски контроль не ищет. Перечня версий в
дереве нет (README документирует два перехода из восьми), а восстанавливать его
из `git log -S` значит завести проверка, зависящий от формулировок старых коммитов.
Прошлое размечено один раз — этой фичей.

**CI получил `fetch-depth: 0`** (иначе `actions/checkout` берёт один коммит
без тегов, и под `PRECHECK_STRICT=1` проверка падал бы не по делу), но **прогоном
не проверен**: Actions заблокированы по биллингу
([дожатие CI-верификации 0090 после разблокировки Actions](0175-ci-verification-followup.md)).
