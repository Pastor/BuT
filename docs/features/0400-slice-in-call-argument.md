## Краткое описание

- **Срез в аргументе вызова не переводит ни одна цель.** Замер
  [срез массива переводят четыре цели](0355-array-slice-in-targets.md) (2026-08-21): фича
  научила четыре цели присваиванию среза (`part := src[1:3];`), а
  `first(src[1:3])` эталон исполняет и все восемь целей отвергают. Форма
  требует передачи массива: у `st` это `VAR_IN_OUT` с именованным типом
  (0348), у `c` — указатель, у `rust` — ссылка на массив; то есть предмет не
  «напечатать срез», а «передать временный массив». Обход есть и он
  дешёвый: присвоить срез переменной и передать её.

> Фича зарегистрирована из блока кандидатов `FEATURES.md` **без проработки**
> (решение заказчика 2026-08-22: «завести фичи из кандидатов без проработки»).
> Текст кандидата перенесён **дословно**, вместе с замером и его датой: замер
> есть свидетельство, а пересказ его теряет. Стадии 2 и 3 не пройдены —
> зависимости и объём **не оценивались**; далее фича проходит жизненный цикл по
> правилу 17.

### Context

`first(src[1:3])` при `fn first(a: [u8; 2])`. Замер **переснят 2026-08-22**:

| Потребитель | Ответ |
|---|---|
| эталон | исполняет (`o = 6`, затем `7`) |
| `c`, `c-hal` | `CC-022` |
| `st`, `st-at` | `ST-011` |
| `rust` | `RS-011` |
| `sv`, `sv-mmio` | `SV-002` |
| `plantuml` | принимает |

Прежний замер (0355) подтверждён полностью: **язык имеет конструкцию,
поведение которой существует только в прогоне** — ни одна цель её не переводит.

Предмет — не «напечатать срез», а **передать временный массив**: у `c` это
указатель на подмассив, у `st` — `VAR_IN_OUT` с именованным типом, у `rust` —
ссылка на массив (0389), у `sv` — плоский вектор с прологом (0369).

### Decision Drivers

1. **Форма языка без поведения у всех восьми целей** — худший вид неполноты:
   модель, работающая в симуляторе, не собирается никуда.
2. **Обход дёшев и известен:** присвоить срез переменной и передать её —
   присваивание среза переводят четыре цели (0355).
3. **Механика передачи массива уже есть у каждой цели** — фича сводится к
   тому, чтобы дать ей временное значение.
4. **Границы срезов — литералы** (0355), значит длина известна при компиляции,
   и временный массив можно объявить статически.

### Considered Options

#### Option A. Развернуть в семантике: срез в аргументе → временная переменная

Проход заводит локальное объявление `var <tmp>: [T; N] := src[a:b];` перед
вызовом и подставляет `<tmp>` аргументом.

**Pros:**
- за границей семантики формы не существует — цели не трогаются **вовсе**;
- присваивание среза уже переводят четыре цели, а `c` и `rust` — тем более;
- длина известна (границы литеральны), объявление статическое.

**Cons:**
- временная переменная попадает в вывод — у `sv` это `automatic logic`, у `c`
  локальная, у `st` — секция `VAR`; имя обязано быть уникальным и **не видимым
  автору** (не попадать в `usages`, `SE-036`, `rename`);
- порядок вычисления: срез снимается до вызова — при аргументе с побочным
  эффектом порядок обязан сохраниться.

#### Option B. Печатать срез каждой целью в её форме аргумента

`c` — указатель `&src[1]`; `st` — временная переменная всё равно нужна
(`VAR_IN_OUT` требует именованного места); `rust` — `&src[1..3]`, но параметр
объявлен `&[u8; 2]`, значит нужна `try_into`; `sv` — конкатенация разрядов.

**Pros:** нет временных переменных в выводе.
**Cons:** четыре разные формы, у `st` временная переменная всё равно
понадобится; у `rust` появляется `try_into().unwrap()` — паника в прошивке,
чего цель избегает (0050).

#### Option C. Отвергать в семантике (сузить язык)

**Cons:** эталон форму исполняет; сужение отняло бы работающую в симуляторе
запись ради того, чего цели не умеют. Отвергается.

### Decision

Принимается **Option A**: разворот в семантике во временную переменную.

Довод: механика передачи массива у каждой цели уже есть и проверена (0348,
0369, 0389), а присваивание среза — тоже (0355). Option B умножает знание о
срезе на четыре печатника и у двух целей всё равно приводит к временной
переменной.

**Имя временной переменной синтетическое** и обязано быть невидимым автору:
слой `semantic::usages`, `SE-036` и `rename` не должны её замечать — иначе
редактор покажет имя, которого автор не писал.

### Consequences

#### Положительные

- Форма переводится всеми целями; печатники не трогаются.
- Обход, который сегодня автор пишет руками, делает компилятор.

#### Отрицательные / Action items

- Вывод целей на таких вызовах становится длиннее на одно объявление.
- Синтетическое имя обязано быть уникальным в блоке (затенение — реальный
  случай, 0131) и не видимым слоям редактора.
- Порядок вычисления аргументов обязан сохраниться (срез снимается до вызова).

#### Acceptance criteria

1. `first(src[1:3])` переводят все восемь целей; инструменты вывод принимают.
2. Потактовая сверка эталона с целью `c` совпадает.
3. Синтетическая переменная не видна: `SE-036` о ней молчит, `rename` её не
   задевает, в `documentSymbol` её нет.
4. Контроль: обход вручную (`var part := src[1:3]; first(part);`) продолжает
   работать и печатается как прежде.
5. Вывод корпуса не изменился; `./scripts/precheck.sh` зелёный.

**Правки требуются в виде проверки:** синтетическая переменная не должна
попасть ни в `semantic::usages` (иначе `rename` её «переименует»), ни в

Образец невидимого имени — `AnonPortAccess::synthetic_name` (0189).

### Особенности по обратной функциональности

Вход, сегодня отвергаемый всеми целями, начнёт переводиться — расширение
множества принимаемых программ, обратно совместимое. Версия языка не
поднимается: форма уже разбирается и исполняется эталоном.

### Риски и зависимости

- **Видимость синтетического имени** — главный риск.
- **Порядок вычисления**: срез обязан сниматься до вызова, иначе аргумент с
  побочным эффектом изменит смысл.
- **Корпус класс не покрывает** — срезов в аргументах в `examples/` нет.

## Разработка

### Задача: носитель среза переехал в семантику

`generator/slice.rs` → `semantic/slice/`; в генераторе остался реэкспорт,
поэтому ни одна цель не правилась. Границы среза — свойство **языка**, и
разворот обязан спрашивать те же значения, что печатники; пока носитель лежал
в `generator/`, семантика не могла его позвать, не перевернув слои.

### Задача: проход разворота

`semantic/slice/argument.rs` — после стадии 6 (раньше аргументов вызова в
дереве нет). Форма:

```text
o := first(src[1:3]);
⇓
var takt_slice_1: [u8; 2];
takt_slice_1 := src[1:3];
o := first(takt_slice_1);
```

**Форма выбрана замером, а не ADR.** Та предлагала объявление **с
инициализатором**, но срез в инициализаторе локального объявления не переводит
**ни одна** цель — обход, названный в ADR «дешёвым и известным», сам не
работал. Пара «объявление + присваивание» работает: присваивание среза цели
переводят с 0355.

**Имя проверяется на занятость.** Первая редакция брала `#slice1` в расчёте
на то, что `#` автору недоступен, — и `cc` ответил «expected identifier», а
`iec2c` «invalid variable(s) declaration»: имя обязано быть идентификатором
**целевых** языков, а значит написать такое же может и автор. Занятые имена
собираются со всей модели до обхода.

### Задача: контроля

- `takt-lang/tests/targets/slice_argument_tests.rs` — четыре цели переводят,
  имя валидно, занятое имя пропускается, присваивание среза не тронуто.
- `takt-sim/tests/conformance/conformance_slice_argument_tests.rs` — сверка
  **значений** с целью `c` на **трёх** срезах с разными смещениями и длиной.

### Смежные фичи, без которых разворот не работал

Каждая найдена прогоном инструментов целей при работе над этой:

| Фича | Класс |
|---|---|
| [локальный массив в аргументе функции: вывод st отвергает iec2c](0409-st-local-array-argument.md) | локальный массив в аргументе у `st` — `iec2c` отвергал вывод |
| [отложенная инициализация локальной переменной: rust печатает лишний mut](0410-rust-deferred-let-mut.md) | лишний `mut`, затем `needless_late_init` у `rust` |
| [отложенное объявление массива у rust не инициализируется (E0381)](0411-rust-deferred-array-init.md) | `E0381` на отложенном массиве у `rust` |

## Итог (что сделано)

Срез в аргументе вызова разворачивается в семантике во временную переменную:
`semantic/slice/argument.rs` заводит объявление и присваивание перед
оператором, а аргумент заменяет ссылкой. За границей семантики формы не
существует — печатники целей не трогались вовсе.

Носитель границ среза переехал из `generator/` в `semantic/`: это свойство
языка, и разворот обязан спрашивать те же значения, что цели.

**ADR ошиблась в форме разворота, и это показал замер:** предложенное
объявление с инициализатором не переводит ни одна цель. Работающая форма —
«объявление + присваивание».

**Разворот открыл три самостоятельных дефекта**, каждый из которых давал
невалидный вывод при нулевом коде возврата `taktc` и был закрыт своей фичей:
[локальный массив в аргументе функции: вывод st отвергает iec2c](0409-st-local-array-argument.md), [отложенная инициализация локальной переменной: rust печатает лишний mut](0410-rust-deferred-let-mut.md),
[отложенное объявление массива у rust не инициализируется (E0381)](0411-rust-deferred-array-init.md). Ни один не следовал из чтения кода —
все нашлись прогоном инструментов целей.

Детали — в разделах «Разработка» и «Отчёт о тестировании» этой карточки.
