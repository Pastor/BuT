# Фича: Цель st печатает неиспользуемую функцию

- **Номер:** 0445
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 4 (валидность вывода и поведение не затронуты: `iec2c` мёртвый POU
  принимает; цена — лишний код в программе ПЛК и расхождение с тремя целями)
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат, заведённый фичей
  [инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Цель `st` печатала **каждую** объявленную функцию, включая ту, которую никто не
вызывает. У целей `c`, `rust` и `sv` такой фильтр есть с самого начала — они
спрашивают `UsageSet::functions`. Расхождение стало заметным после подстановки
тела ([инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md)): вызовов не осталось, а
объявление `FUNCTION` в файле — да.

> Фича заведена из блока кандидатов.

## Документирование

**Не требуется:** язык не меняется, наблюдаемое поведение программы — тоже.
Меняется только состав порождённого файла ST, и это уже описанное правило
(«функция, которую никто не зовёт, не печатается»), приведённое к общему виду
у четвёртой цели.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

Замер-31 (проба: модель с функцией `unused_helper`, которую никто не
зовёт):

| Цель | Функция в выводе |
|---|---|
| `c` | нет |
| `rust` | нет |
| `sv` | нет |
| **`st`** | **есть** (объявление `FUNCTION … END_FUNCTION`) |

`iec2c` такой файл **принимает** — поэтому проверка цели класса не видел, и
дефект дожил до фичи, где стал заметен: подстановка убирает вызовы, а
объявление остаётся.

### Decision

Спрашивать тот же признак, что и три другие цели: `UsageSet::functions` (карта
`st_map` его уже считает — `compute_usage`). Фильтр ставится в
`st_func::emit_functions`, рядом с дедупликацией по итоговому имени.

Спрашивается **голое** имя функции: `pou_name` уже несёт префикс
модели-владельца, а `UsageSet` хранит имена как они написаны.

### Considered Options

- **A. Общий признак `UsageSet::functions`** — принят: правило одно на четыре
  цели, второго знания не заводится.
- **B. Свой обход у цели `st`** — отвергнут: копия правила «что считать
  использованием» разошлась бы с оригиналом молча.
- **C. Предупреждение автору вместо фильтра** — отвергнуто как **замена**:
  мёртвая функция законна, а вывод всё равно расходился бы с тремя целями.
  Отдельным правилом язык такое предупреждение завести может — это не предмет
  этой фичи.

### Consequences

Вывод корпуса меняется у **одного** примера: `examples/generated/st/stacker.st`
теряет `Stacker_abs_diff` и `Stacker_max2` — функции, объявленные в
`examples/stacker.takt` и не вызываемые ниоткуда (в выводе `c`, `rust`, `sv`
их и не было). Снимок обновлён.

#### Acceptance criteria

- A1. Функция без единого вызова из вывода `st` исчезает.
- A2. Функция, вызываемая **только из условия ребра**, остаётся: иначе вывод
  ссылался бы на несуществующий POU.
- A3. `iec2c` принимает вывод.
- A4. Вызываемая функция остаётся — контроль.

## Анализ

### Цель и контекст

Предмет — состав порождённого файла ST. Проверяемое условие: печатается ровно
то, что вызывается, и вывод остаётся валидным для `iec2c`.

### Замер

1. Мёртвая функция: `c`/`rust`/`sv` — нет в выводе, `st` — **есть**.
2. Функция, вызываемая только из условия ребра (`ref Done: ready(n) = 1;`):
   печатают **все четыре** цели. Значит `compute_usage` условие ребра видит
   (условия рёбер разрешаются стадией 6 — неразрешённым остаётся лишь образец
   `S(Модель) = Состояние`), и фильтр безопасен.
3. Корпус: изменение затрагивает единственный файл — `stacker.st`
   (`abs_diff`, `max2`).

### Зависимости фичи

Нет. Смежное: [инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md) — там класс стал заметен.

### Требования и проверяемые условия

- R1. A1…A4 выше.
- R2. Изменение снимков корпуса ограничено `stacker.st`.

### Критерии приёмки и способ проверки

Тесты `takt-lang/tests/targets/st_unused_function_tests.rs` (эмиссия + прогон
`iec2c`), мутация фильтра, полный `precheck.sh` (проверка цели `st` гоняет `iec2c`
и `cc` по всему корпусу).

### Редакторский слой

**Не затронут:** ни лексика, ни синтаксис, ни семантика не меняются.

### Особенности по обратной функциональности

Вывод `st` для моделей с мёртвыми функциями становится короче. Поведение
программы не меняется: вызовов у такой функции нет по определению признака.

### Риски и зависимости

Единственный риск — признак, не видящий какого-то вида использования: тогда
вывод сослался бы на удалённый POU. Он снят замером (условие ребра) и
контролем A2; сам признак общий с тремя целями, то есть проверяется всеми их
проверками.

## Разработка

`takt-lang/src/generator/st/st_func.rs` — `emit_functions` получила
`usage: &UsageSet` и пропускает функцию, чьего голого имени в нём нет;
`takt-lang/src/generator/st/mod.rs` передаёт `map.usage()`. Снимок
`examples/generated/st/stacker.st` пересобран.

## Итог

Четвёртая цель приведена к общему правилу: печатается то, что вызывается.
Побочный эффект — программа ПЛК больше не несёт мёртвых POU, в том числе
после подстановки тела.
