## Краткое описание

Замер-22 на `var m: Mode;` (перечислимый тип **без инициализатора**) и
на `out mode: Mode at 0;`:

| Потребитель | Ответ |
|---|---|
| эталон | исполняет (значение 0) |
| `c`, `c-hal` | `cc` принял |
| `st`, `st-at` | `iec2c` принял · `cc` собрал |
| `rust` | `rustc` принял · `clippy` принял |
| `sv`, `sv-mmio` | **verilator ОТВЕРГ:** `%Error-ENUMVALUE: Implicit conversion to enum 'mode_e' from 'bit'` |

Цель печатала `enumnoinit_m <= '0;`: перечисления SystemVerilog строго
типизированы, и проверка цели считает предупреждение ошибкой — вывод не проходил
проверку своей же цели при **нулевом** коде возврата `taktc`.

### Context

`reset_value` печатала `'0` для любого регистра без инициализатора. Для
перечислимого типа verilator отвечает **ошибкой** `%Error-ENUMVALUE`, а проверка
цели считает предупреждение ошибкой. При этом `taktc` возвращает ноль, а
эталон, `c`, `st` и `rust` тот же вход исполняют.

Ветвь «есть инициализатор» была права с фичи (`enum_literal`
восстанавливает вариант по значению) — расходились именно две ветви одного
правила.

### Decision Drivers

1. **Вывод обязан проходить проверка своей цели.**
2. **Значение не должно измениться:** у эталона переменная без инициализатора
   равна нулю, и любое «удобное» умолчание — это молчаливое расхождение.
3. **Форма выбирается по наличию варианта**, а не по вкусу.

### Considered Options

#### Option A. Ноль в форме, которую принимает тип (принято)

Мнемоника варианта со значением 0, если такой есть; иначе приведение
`<тип>'(0)`.

**Pros:**
- Значение то же, что у эталона, — сверка это доказывает.
- Обе формы приняты обоими инструментами (прогон 2026-08-22).
- Правило симметрично ветви «есть инициализатор» (0338).

**Cons:** приведение читается хуже мнемоники — но мнемоники для нуля в таком
перечислении не существует.

#### Option B. Первый вариант перечисления

**Cons:** **меняет значение**. Мутация: `RTL=[[1, 0], …]` против
`sim=[[0, 0], …]`. Это ровно то расхождение, которое кандидат 0353 держит
как **вопрос заказчика** (эталон, `st`, `sv` и `c` дают ноль, `rust` — первый
вариант); решать его молча правкой одной цели нельзя.

#### Option C. Отказ цели на перечислимом регистре без инициализатора

**Cons:** запись законна, исполняется эталоном и переводится четырьмя другими
целями; форма выразима.

### Decision

Принимается **Option A**: ветвь `ExpressionNode::None` в `sv_const::reset_value`
для `TypeNode::Enum` печатает `enum_literal(ty, 0, …)`, а при отсутствии
нулевого варианта — `<тип>'(0)`.

### Consequences

#### Положительные

- Вывод цели проходит линт и синтез на перечислимом регистре и порте.
- Правило симметрично: обе ветви (`Number` и `None`) дают значение в форме,
  которую принимает тип.

#### Отрицательные / Action items

- Расхождение «ноль против первого варианта» между эталоном и целью `rust`
  остаётся вопросом заказчика (кандидат 0353) — эта фича его не решает и не
  усугубляет.

#### Acceptance criteria

1. `verilator --lint-only -Wall` принимает вывод; `yosys synth` — тоже.
2. Потактовая сверка: значение сброса — **ноль**, как у эталона.
3. Форма выбирается по наличию нулевого варианта (проверяется текстом).
4. Мутация «первый вариант» роняет сверку значений.
5. Вывод корпуса не изменился; предкоммит зелёный.

## Анализ

### Цель и контекст

Класс найден **обходным замером**: проба порта перечислимого типа снималась
ради другого вопроса, а показала отказ линта на ветви сброса.

#### Замер (`scripts/probe.sh -n 3`, 2026-08-22)

Вход: `enum Mode { Idle = 1, Work = 2 } var m: Mode;` — без инициализатора.

| Потребитель | Ответ | Печать сброса |
|---|---|---|
| эталон | `m = 0` до первой записи | — |
| `c`, `c-hal` | `cc` принял | `model->m = 0;` |
| `st`, `st-at` | принят · собран | `m : USINT := 0;` |
| `rust` | принят · clippy принял | `Default` |
| `sv`, `sv-mmio` | **verilator ОТВЕРГ** | `enumnoinit_m <= '0;` |

Текст: `%Error-ENUMVALUE: Implicit conversion to enum 'mode_e' from 'bit'
(IEEE 1800-2023 6.19.3) … Suggest use enum's mnemonic, or static cast`.

Тот же отказ — на **порте** перечислимого типа (`out mode: Mode at 0;`):
порт у цели `sv` тоже регистр.

Ветвь «есть инициализатор» была права с фичи: `var m: Mode := Work;`
печатается мнемоникой. Расходились две ветви **одного** правила.

## Разработка

### Задача

#### Что было

`sv_const::reset_value` в ветви `ExpressionNode::None` печатала `'0` для
любого типа. Для перечислимого регистра verilator отвечал ошибкой
`%Error-ENUMVALUE`.

#### Что сделано

- В ветви `None` добавлен разбор `TypeNode::Enum`: значение сброса —
  `enum_literal(ty, 0, enums)` (мнемоника варианта со значением 0), а при его
  отсутствии — приведение `<тип>'(0)`.
- Комментарий называет причину и **почему не первый вариант**: он изменил бы
  значение, а у эталона там ноль.

**Статус по функциональности (правило 11).** Затронуты `sv`/`sv-mmio`; прочие
цели и эталон — **н/п**.

#### Проверки

```sh
cargo test --test conformance conformance_sv_enum_reset
./scripts/probe.sh -n 3 <проба>.takt      # sv: verilator принял · yosys синтезировал
./scripts/precheck.sh
```

Мутация «первый вариант вместо нуля» роняет сверку значений (`RTL=[[1, 0], …]`
против `sim=[[0, 0], …]`) и сверку текста.

## Итог (что сделано)

- Регистр перечислимого типа сбрасывается **своим** значением: мнемоникой
  варианта, если вариант со значением 0 есть, и приведением `mode_e'(0)`,
  если его нет.
- **Значение остаётся нулём — тем же, что даёт эталон.** Подстановка
  **первого** варианта (`MODE_IDLE = 1`) прошла бы линт и изменила бы
  поведение: мутация даёт `RTL=[[1, 0], …]` против `sim=[[0, 0], …]`.
- Формы две, и обе нужны: мнемоники для значения, которого нет среди
  вариантов, не существует, а приведение там, где мнемоника есть, было бы
  менее читаемым выводом.
- Класс жил на **умолчании**: запись с инициализатором (`var m: Mode :=
  Work;`) печаталась верно с фичи — расходились ветви «есть значение» и
  «значения нет».
- Вывод корпуса не изменился: перечислимых регистров без инициализатора в
  `examples/` нет.
