# Фича: Понижение q-литерала доходит до полей структуры

- **Номер:** 0370
- **Статус:** ГОТОВО
- **Зависит от:** нет (0061, 0096, 0293, 0368 закрыты)
- **Связанные issue (анализ):** кандидат, заведённый закрытием
  [элемент агрегата печатается по типу элемента](0368-aggregate-element-type.md); замер подтверждён прогоном
  2026-08-21

## Краткое описание

Замер-21: `var g: Gains := {1.5, 2.5};` при
`struct Gains { kp: q(8, 8), ki: q(8, 8) }` исполняет эталон, а **все** цели,
кроме диаграммы, вывод не дают:

| Цель | Ответ |
|---|---|
| `c`, `c-hal` | `cc -Werror` отвергает порождённый файл |
| `st`, `st-at` | `iec2c` отвергает |
| `rust` | `rustc` отвергает |
| `sv`, `sv-mmio` | `SV-002` |

Причина: понижение дробного литерала в q-представление (0061/0096, место —
свёртка инициализаторов) шло по типу объявления, а объявление полей живёт в
`ModelNode`, которого слой свёртки не видел. Фича закрыла тот же класс
для **элементов массива** и границу «структуры» назвала прямо.

## Документирование (правило 24)

**Не требуется** — язык не меняется: запись законна и исполняется эталоном;
правится место понижения литерала.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича](0370-struct-field-fixed.md);
  связь с [ADR](0061-fixed-point-type.md#архитектура-adr), [ADR](0096-fixed-point-native-float.md#архитектура-adr)
  (понижение литерала), [ADR](0368-aggregate-element-type.md#архитектура-adr) (тот же
  класс для элементов массива)

### Context

Понижение дробного литерала в q-представление живёт в свёртке инициализаторов
(`lower_folded_fixed`). Фича научила его массивам и **назвала границу**:
поля структуры остаются вне, потому что их объявление лежит в `ModelNode`.
Прогон 2026-08-21 показал, что за этой границей — не редкий случай, а вход,
который отвергают все восемь целей.

### Decision Drivers

1. **Скаляр, элемент массива и поле структуры обязаны отвечать одинаково.**
2. **Модель у слоя свёртки есть** — `fold_variable_initializers` принимает
   `&Rc<RefCell<ModelNode>>`; границу создавала сигнатура помощника, а не
   устройство.
3. **Правило округления — один носитель** (0061): своя копия разошлась бы.

### Considered Options

#### Option A. Передать модель в `lower_folded_fixed` и понижать поля по их типам

**Pros:**
- Граница снимается там же, где была названа; рекурсия покрывает и массив
  структур (`[Gains; 2]`), потому что ветвь массива зовёт ту же функцию.
- Носитель округления прежний.

**Cons:**
- Помощник получает ещё один параметр.

#### Option B. Понижать в целях

**Pros:** локально.

**Cons:** восемь копий правила округления — прямо против 0061.

#### Option C. Отказ семантики на дробном литерале в поле `q`

**Pros:** громче молчания.

**Cons:** запись исполняет эталон, и она — обычный способ задать
коэффициенты (пример `pid_law` в корпусе).

### Decision

Принимается **Option A**: `lower_folded_fixed` принимает модель и понижает
элементы агрегата структуры по типам её полей (порядок — объявления, агрегат
позиционный по 0034); длину агрегата по-прежнему сверяет `SE-123`.

### Consequences

#### Положительные

- Поле `q` и массив структур с полями `q` переводят все восемь целей.
- Граница, названная 0368, снята.

#### Отрицательные / Action items

- **Найден соседний класс:** приведение `as` из **поля** структуры цель `c`
  печатает без деления на 2ⁿ (`(uint8_t)(g.kp + g.ki)` вместо
  `takt_q_floordiv(…)`), и значение расходится с эталоном молча — 0 против 4.
  Вынесено кандидатом; сверка этой фичи намеренно смотрит на q-значения, а не
  на результат приведения.

#### Acceptance criteria

1. Инструменты всех целей принимают вывод на входах: поле `q`, массив структур
   с полями `q`.
2. Потактовая сверка с целью `c` совпадает по **представлениям**: `1.5` → 384,
   `1.0` → 256.
3. Мутация «не понижать поля структуры» роняет сверку.
4. Предкоммит зелёный; вывод корпуса не изменился.

## Анализ

### Цель и контекст

Снять границу, названную фичей: понижение q-литерала не доходило до полей
структуры. Замер — в карточке; контроль (скаляр `q` и элемент массива `q`)
переводится всеми целями.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. 0061/0096 (понижение), 0293 (структуры в целях), 0368
  (тот же класс для массива) закрыты.
- **Влияние на порядок разработки:** порождает кандидата «приведение `as` из
  поля структуры у цели `c`».

### Требования и проверяемые условия

- **R1. Поля понижаются по своим типам**, порядок — объявления (агрегат
  позиционный, 0034).
- **R2. Рекурсия покрывает массив структур**: ветвь массива зовёт ту же
  функцию.
- **R3. Длину агрегата фича не судит** — это `SE-123` (0320); лишние значения
  переносятся как есть.
- **R4. Носитель округления один** (`lower_fixed_literal`).
- **R5. Сверка смотрит на q-значения**, а не на результат приведения `as`:
  приведение из поля — соседний, ещё не закрытый класс.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Инструменты всех целей принимают вывод | `scripts/probe.sh` на `qfield.takt`, `qstructarr.takt` |
| A2 | Представления совпадают | `conformance_c_arrays_tests::struct_field_fixed_matches_generated_c` |
| A3 | Мутация ловится | «не понижать поля структуры» |
| A4 | Вывод корпуса не изменился | предкоммит |

### Особенности по обратной функциональности

- **Язык не меняется**; правило 29 — не применимо.
- **Корпус затронут не был**: в `examples/pid_law.takt` коэффициенты `q`
  объявлены скалярами, а не полями структуры.

### Риски и зависимости

- **Смешение классов в сверке.** Первая редакция теста наблюдала
  `(g.kp + g.ki) as u8` и падала не из-за понижения, а из-за приведения из
  поля — его цель `c` печатает без деления на 2ⁿ. Наблюдаемые заменены на
  q-значения, класс вынесен кандидатом.

## Разработка

### Задача

#### Что было

`lower_folded_fixed` понижал литерал по типу объявления и по типам элементов
массива (0368), но полей структуры не видел: у помощника не было модели.

#### Что сделано

**`takt-lang/src/semantic/declaration/mod.rs`** — `lower_folded_fixed`
принимает `&Rc<RefCell<ModelNode>>` и понижает элементы агрегата структуры по
типам её полей (`search_struct`), в порядке объявления. Ветвь массива зовёт ту
же функцию, поэтому `[Gains; 2]` покрывается рекурсией.

**Сверка**: `struct_field_fixed_matches_generated_c` — представления `1.5` →
384 и `1.0` → 256 у поля и у поля внутри массива.

**Границу создавала сигнатура, а не устройство:** модель у
`fold_variable_initializers` была всё это время.

**Тест сначала мерил не тот класс.** Наблюдаемые `(g.kp + g.ki) as u8`
давали 4 у эталона и 0 у C — но из-за **приведения из поля**, которое цель `c`
печатает без деления на 2ⁿ. Наблюдаемые заменены на q-значения, соседний класс
вынесен кандидатом.

#### Проверки

```sh
cargo test --test conformance struct_field_fixed
cargo test --test conformance   # 169
cargo test --test targets       # 391
cargo test -p takt-lang --lib   # 1108
scripts/probe.sh -n 2 qfield.takt; scripts/probe.sh -n 2 qstructarr.takt
./scripts/precheck.sh
```

Мутация «не понижать поля структуры» — сверка красная («порождённый C не
компилируется»).
