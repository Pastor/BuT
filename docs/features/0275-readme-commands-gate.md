## Краткое описание

**Команды в `README.md` никем не проверяются.** Замер при закрытии
[скрипт релизной сборки и установки инструментов](0239-install-script.md) (2026-08-17): раздел сборки
предлагал `cargo install --path grammar --bin taktc` — команду, не работающую
с фичи **0100** (крейт переименован в `takt-lang`), то есть полтора десятка
фич подряд документ вёл читателя в тупик; симулятор в разделе установки не
упоминался вовсе. Проверка ссылок этого не ловит **по устройству**:
он проверяет пути к файлам, а не работоспособность вызовов. Кандидат: прогон
помеченных блоков `sh` из README в предкоммите — по образцу проверки примеров
документа. Прогонять можно не всё: часть команд ставит
инструменты и требует сети; помечать пригодные явным маркером.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

## Что известно на входе

Всё, что проверено, — в разделе выше: это **дословный текст кандидата** со
своим замером и ссылками на фичу, при закрытии которой он был вынесен. Ничего
сверх этого не проверялось.

Замер снят на дату, указанную в тексте. Прежде чем брать фичу в работу,
**перепроверь** его: условие карточки перепроверяется, а не наследуется — урок
[остаточные старые имена языка в данных и комментариях](0161-fixture-comments-rename.md), где обоснование отказа держало
работу отложенной два месяца и оказалось неверным уже в момент отказа.

## Направление решения (наметка, не решение)

Наметка — в тексте кандидата выше (там, где он её содержит). Решение о том,
**делать ли фичу вообще**, отложено заказчиком и принимается до стадии 2.

### Context

README предлагает читателю набрать команды — 25 блоков `sh`, 55 непустых
строк. Проверял их только человек.

**Замер при закрытии 0239** (2026-08-17): раздел сборки предлагал
`cargo install --path grammar --bin taktc` — команду, мёртвую с фичи
(крейт переименован в `takt-lang`); полтора десятка фич подряд документ вёл
читателя в тупик. Проверка ссылок этого не ловит **по устройству**:
он проверяет пути в markdown-ссылках, а не работоспособность вызовов.

**Первый же прогон новой проверки нашёл вторую беду, и она хуже**:

```
$ taktc compile -t st-at --address-map examples/elevator.plc.map examples/elevator.takt -o out/
thread 'main' panicked at takt-lang/src/diagnostics/mod.rs:519:23:
end byte index 928 is not a char boundary; it is inside 'р' (bytes 927..929 of string)
```

Причина: карта адресов разбиралась с `file_no = 0` — **тем же номером, что и
корневой `.takt`**. Предупреждения карты (`SE-050`) несли смещения в тексте
карты, а печать брала по этому номеру текст модели: на латинице выходила
ложная координата, на кириллице — паника. То есть команда из README роняла
инструмент, и об этом никто не знал.

### Decision Drivers

1. **Документ обещает работоспособность.** Команда, которую нельзя набрать, —
   дефект, а не опечатка.
2. **Класс невидим существующим проверкам** (ссылки — про пути, примеры — про
   `book/`).
3. **Прогонять можно не всё:** часть команд ставит инструменты, требует сети
   или внешних программ (`verilator`, `yosys`, `gtkwave`).

### Considered Options

#### Option A. Прогонять все блоки `sh`

**Pros:** максимальная строгость.
**Cons:** предкоммит начнёт ставить софт и ходить в сеть; часть команд
намеренно показана с плейсхолдерами (`model.takt`) — их исполнить нечем.

#### Option B. Три проверки по возрастанию строгости

1. пути, названные флагами (`--path`, `--manifest-path`) и вызовами
   `scripts/*.sh`, существуют;
2. подкоманда `taktc` известна;
3. команды `taktc`, **все входные файлы которых существуют**, прогоняются с
   выводом во временный каталог.

**Pros:**
- Ловит исходный класс (устаревший путь крейта) и найденный прогоном (паника).
- Не требует сети и внешних инструментов; плейсхолдеры пропускаются осознанно.
- Замер: 55 строк, из них 5 команд действительно исполняются.

**Cons:** команды внешних инструментов остаются непроверенными (граница
названа).

#### Option C. Явная разметка блоков маркером «проверяемо»

**Pros:** полный контроль над тем, что гоняется.
**Cons:** маркер надо поддерживать руками — то есть тот же ручной труд, что и
сейчас; забытый маркер молча выключает проверку.

### Decision

Принимается **Option B**: `scripts/check-readme-commands.sh` со контролем
`scripts/test-readme-commands.sh` (оба — шаги предкоммита).

**Найденный дефект исправлен здесь же** — иначе проверка не включить:

1. **Корень:** карта адресов регистрируется в реестре файлов и разбирается под
   **своим** номером; реестр создаётся до разбора карты и передаётся в печать
   результата (`report_hal_result`, `report_simple_result`). Предупреждение
   `SE-050` теперь печатается как `examples/elevator.plc.map:14:1`.
2. **Страховка:** `line_column` приводит смещение к **границе символа** —
   печать диагностики не вправе падать никогда, каким бы смещение ни было.

### Consequences

#### Положительные

- Команды README проверяются машиной; устаревший путь крейта роняет предкоммит.
- Устранён отказ инструмента на команде из документа, а не только его симптом.
- Предупреждения карты адресов получили верную координату — в своём файле.

#### Отрицательные / Action items

- Команды внешних инструментов (`verilator`, `yosys`, `gtkwave`,
  `cargo install`) не прогоняются: для них работает только проверка путей.
- Прогоняются 5 команд из 55 строк — остальные либо с плейсхолдерами, либо не
  про `taktc`. Это осознанная граница, а не недоделка.

#### Acceptance criteria

1. Проверка ловит: устаревший путь крейта, неизвестную подкоманду, неработающую
   команду компилятора, несуществующий скрипт.
2. **Контроль:** команда с плейсхолдером проверка не роняет.
3. Настоящий README проверка проходит.
4. Паника на команде `st-at --address-map` устранена, координата
   предупреждения указывает в файл карты.
5. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Сделать так, чтобы команда из README не могла устареть молча. ADR принял
Option B: три проверки по возрастанию строгости плюс контроль проверки.

### Замер (снят 2026-08-19)

Кандидат подтверждён, и **прогон нашёл дефект хуже описанного**.

**Состав README:** 25 блоков `sh`, 55 непустых строк без комментариев. Из них
командами компилятора с существующими входами оказались **5** — они и
исполняются; остальные либо с плейсхолдерами (`model.takt`, `hello.takt`,
`a.takt`), либо адресуют внешние инструменты (`verilator`, `yosys`, `gtkwave`,
`cargo install`).

**Находка прогона:**

```
$ taktc compile -t st-at --address-map examples/elevator.plc.map examples/elevator.takt -o out/
thread 'main' panicked at takt-lang/src/diagnostics/mod.rs:519:23:
end byte index 928 is not a char boundary; it is inside 'р' (bytes 927..929 of string)
```

Разбор:

1. карта адресов разбиралась `parse_address_map(&map_src, 0)` — под номером
   файла **корневого `.takt`**;
2. предупреждения карты (`SE-050` — «внешняя карта переопределяет адрес порта»)
   несут смещения **в тексте карты**;
3. печать берёт текст по номеру файла, то есть текст модели, и режет его по
   чужому смещению.

На латинице это давало **ложную координату** (класс — «чужая верная
координата хуже отсутствующей»), на кириллице — **панику**. Контроль: без
`--address-map` та же команда работает; после правки координата стала
`examples/elevator.plc.map:14:1`.

### Зависимости фичи

- **Зависит от:** нет.
- **Влияние на порядок разработки:** никого не разблокирует; снимает ручную
  обязанность у каждой фичи, меняющей CLI или имена крейтов.

### Требования и проверяемые условия

- **R1. Устаревший путь ловится** (`--path`, `--manifest-path`, `scripts/*.sh`).
- **R2. Неизвестная подкоманда `taktc` ловится.**
- **R3. Неработающая команда компилятора ловится** — прогоном, а не разбором.
- **R4. Плейсхолдеры не мешают:** команда с несуществующим входом проверка не
  роняет (контроль).
- **R5. Проверка самопроверяется** мутацией на копии дерева.
- **R6. Найденный дефект устранён по существу:** карта получает свой номер
  файла; печать диагностики не падает ни при каком смещении.

### Критерии приёмки и способ проверки

### Особенности по обратной функциональности

**Меняется наблюдаемое:** предупреждения карты адресов печатаются с путём
карты и её строкой (прежде — с путём модели и чужой строкой либо паникой).
Ломает это только того, кто сверяет вывод дословно; в дереве таких проверок

Публичные сигнатуры библиотеки не менялись: правки — во внутренних функциях

в `line_column`, чьё поведение стало **строго безопаснее** (паника исключена).

Язык не затронут; версия языка прежняя.

**Не требуется.** Лексика, синтаксис и семантика не менялись.

### Документирование

**Не требуется.** README — предмет проверки, а не правки: все его команды

### Риски и зависимости

- **Риск: проверка станет тормозом** при росте числа исполняемых команд.
  **Снижение:** исполняются только команды `taktc` с существующими входами —
  сегодня их пять; внешние инструменты не запускаются вовсе.
- **Риск: ложное срабатывание на новом синтаксисе README.** **Снижение:**
  контроль гоняет проверка на копии **настоящего** README, то есть ложное
  срабатывание ловится сразу.
- **Риск: копия дерева в контроле беднее рабочего.** **Снижение:** первый же
  прогон это и показал (не хватало `examples/generated/rust/Cargo.toml`) —
  копия дополнена.

## Разработка

### Задача

#### Что было

README предлагает читателю 25 блоков `sh` (55 непустых строк), и проверял их
только человек. Замер (2026-08-17): `cargo install --path grammar --bin
taktc` — команда, мёртвая с переименования крейта. Проверка ссылок такого не видит: он проверяет пути в markdown-ссылках, а не
работоспособность вызовов.

#### Что сделано

**`scripts/check-readme-commands.sh`** — три проверки по возрастанию строгости:

1. **пути**, названные флагами `--path`/`--manifest-path` и вызовами
   `scripts/*.sh`, существуют в дереве;
2. **подкоманда** `taktc` известна инструменту;
3. команды `taktc`, **все входные файлы которых существуют**, **прогоняются**
   — вывод перенаправляется во временный каталог; `fmt` без `--check`
   пропускается (правит файлы на месте).

Плейсхолдеры (`model.takt`, `hello.takt`) и внешние инструменты
(`verilator`, `yosys`, `gtkwave`, `cargo install`) не исполняются — граница
названа в заголовке проверки.

**`scripts/test-readme-commands.sh`** — контроль (шаг предкоммита). На **копии**
дерева (`RC_ROOT`) проверяет: настоящий README проходит; устаревший путь
крейта, неизвестная подкоманда, неработающая команда и несуществующий скрипт
ловятся; **контроль** — команда с плейсхолдером проверка не роняет.

Первый прогон контроля показал, что копия дерева беднее рабочего (не хватало
`examples/generated/rust/Cargo.toml`, который README называет в
`--manifest-path`) — копия дополнена. Это ровно тот случай, ради которого
контроль и гоняет **настоящий** README, а не синтетический.

#### Проверки

```sh
sh scripts/check-readme-commands.sh   # OK: строк 55, команд прогнано 5
sh scripts/test-readme-commands.sh    # 6 проверок сторожа
```

### Задача

#### Что было

Первый же прогон проверки нашёл, что команда из README **роняет
компилятор**:

```
$ taktc compile -t st-at --address-map examples/elevator.plc.map examples/elevator.takt -o out/
thread 'main' panicked at takt-lang/src/diagnostics/mod.rs:519:23:
end byte index 928 is not a char boundary; it is inside 'р' (bytes 927..929 of string)
```

Разбор: карта адресов разбиралась `parse_address_map(&map_src, 0)` — под
номером файла **корневого `.takt`**. Предупреждения карты (`SE-050`) несут
смещения в тексте **карты**, а печать берёт по этому номеру текст **модели**.
На латинице выходила ложная координата, на кириллице — паника.

#### Что сделано

**Корень.** Реестр файлов `FileTable` создаётся в `run_compile` **до** разбора
карты; путь карты регистрируется (`files.add(map_path)`), и карта разбирается
под своим номером. Тот же реестр передаётся в печать результата —
`report_hal_result` и `report_simple_result` получили его параметром вместо
того, чтобы заводить свой из одного корневого файла.

Было: `Предупреждение [SE-050]: …` без координаты либо с координатой модели.
Стало: `examples/elevator.plc.map:14:1: Предупреждение [SE-050]: …`.

**Страховка.** `line_column` приводит смещение к **границе символа**: печать
диагностики не вправе падать никогда, каким бы смещение ни было. Это не замена
починке корня, а второй рубеж — паника в печати сообщения обесценивает любую
диагностику.

**Обратная функциональность:** предупреждение импортированного
файла по-прежнему остаётся без префикса — граница фичи (цель строит своё
дерево внутри и таблицу наружу не отдаёт). Публичные сигнатуры библиотеки не
менялись.

#### Проверки

```sh
taktc compile -t st-at --address-map examples/elevator.plc.map examples/elevator.takt -o out/
### → examples/elevator.plc.map:14:1: Предупреждение [SE-050]: …
cargo test --all-features    # регрессия, 0 провалов
```

**Контроль:** без `--address-map` та же команда работала и до правки — значит
измерялась именно карта, а не цель `st-at`.

## Тест-план

### Область и цель

Две группы: (1) проверка ловит негодные команды и не мешает годным; (2) дефект,
найденный проверкой (паника на команде с картой адресов), устранён по существу —
координата указывает в файл карты.

Проверка «проверка падает» без контроля «настоящий README проходит» ничего не
доказывает: проверка, падающий всегда, прошёл бы её тоже.

1. **Исправлений не требуется** (`docs/fixes/0275-YY-*` не заводились):

## Итог (что сделано)

**Команды README проверяются машиной, и первый же прогон нашёл отказ
инструмента.** Проверка `scripts/check-readme-commands.sh` делает три вещи:
проверяет пути, названные флагами `--path`/`--manifest-path` и вызовами
`scripts/*.sh`; сверяет подкоманду `taktc` с инструментом; **прогоняет** те
команды `taktc`, чьи входные файлы существуют (сегодня их пять из 55 строк).
Контроль `scripts/test-readme-commands.sh` доказывает мутацией на копии дерева,
что негодная команда ловится, а годная — нет.

**Найденный дефект устранён здесь же** — иначе проверка не включить:
`taktc compile -t st-at --address-map …` роняло компилятор паникой
«byte index … is not a char boundary». Карта адресов разбиралась под номером
файла **корневого `.takt`**, поэтому предупреждение `SE-050` печаталось по
тексту модели: на латинице — ложная координата, на кириллице —
паника. Теперь карта регистрируется в реестре и разбирается под своим номером,
а печать выдаёт `examples/elevator.plc.map:14:1`. Вторым рубежом `line_column`
приводит смещение к границе символа: печать диагностики не вправе падать
никогда.

Сделано задачами [команды в README.md никем не проверяются](0275-readme-commands-gate.md#разработка) и
[команды в README.md никем не проверяются](0275-readme-commands-gate.md#разработка); подробности — в
[отчёте](0275-readme-commands-gate.md#отчёт-о-тестировании), разбор вариантов — в
[ADR](0275-readme-commands-gate.md#архитектура-adr).

**Ключевые решения:**

- **Прогонять не всё** (Option A ADR отвергнут): команды внешних инструментов
  требуют сети и софта, а часть команд намеренно показана с плейсхолдерами.
  Граница названа в заголовке проверки, а контрольная проверка контроля требует,
  чтобы плейсхолдер проверка **не ронял**.
- **Явная разметка блоков отвергнута** (Option C): забытый маркер молча
  выключает проверку — тот же ручной труд, что и был.
- **Симптом и корень правились раздельно:** укрепление печати не отменяет
  починки номера файла, иначе координата осталась бы чужой.

(«строк проверено 55, команд компилятора прогнано 5»); 3316 тестов, 0
