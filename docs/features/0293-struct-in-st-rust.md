# Фича: Структуры не транслируются целями st и rust дальше объявления

- **Номер:** 0293
- **Статус:** ГОТОВО
- **Зависит от:** нет (проверено на стадии анализа)
- **Tier:** 3 — ST-011 и RS-011 честные отказы; структуры в двух целях не работают (расставлен по признаку вреда 2026-08-18, см. `FEATURES.md`)
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат блока 2 `FEATURES.md`, переведён в фичу пакетно 2026-08-18

## Краткое описание

**Структуры не транслируются целями `st` и `rust` дальше объявления.** Замер
при исправлении [пИД-регулятор — тип данных с операциями, а не модель-автомат](../fixes/0182-01-pid-law-as-type-and-functions.md):
агрегатный инициализатор `var p: T := {…}` даёт `ST-011`, доступ к полю —
`RS-011`. Класс дожил незамеченным потому, что единственная запись `struct` в
корпусе (`examples/extend_complex.takt`) полей не трогает: тип объявлен, но
не используется. Цена измерена — переписанный `pid_law.takt` потерял обе цели.

**Замер [структура без полей](0284-empty-struct-semantics.md) (2026-08-18) расширил запись
на цель `sv`:** она печатает ссылку на **необъявленный** тип (`empty_t`,
`pt_t` — `typedef` не эмитится вовсе), и `verilator` отвечает
`Can't find typedef/interface`. Воспроизводится на **любой** структуре, не
только на пустой; отказ `RS-014` у `rust` — там же и так же. То есть целей,
не переводящих структуры дальше объявления, **три**, а не две.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по правилу 17.

## Что известно на входе

Всё, что проверено, — в разделе выше: это **дословный текст кандидата** со
своим замером и ссылками на фичу, при закрытии которой он был вынесен. Ничего
сверх этого не проверялось.

Замер снят на дату, указанную в тексте. Прежде чем брать фичу в работу,
**перепроверь** его: условие карточки перепроверяется, а не наследуется — урок
[остаточные старые имена языка в данных и комментариях](0161-fixture-comments-rename.md), где обоснование отказа держало
работу отложенной два месяца и оказалось неверным уже в момент отказа.

## Направление решения

Принято решение ADR (Option B): перевести структуры во всех трёх целях, по
задаче на цель, в порядке убывания вреда — `sv` (невалидный вывод), `st`
(молча иное значение), `rust` (честный отказ).

## Документирование (правило 24)

Раздел `book/src/03-types/` («Структуры») дополнен: структуры переводятся всеми
целями, и названо, чем они становятся в каждом целевом языке.

### Context

Структуры объявляются языком, исполняются эталоном и переводятся целью `c`.
Кандидат утверждал: `st` даёт `ST-011` на агрегатном инициализаторе, `rust` —
`RS-011` на доступе к полю, `sv` печатает ссылку на необъявленный тип.

**Замер-19 (`scripts/probe.sh`, правило 30) поправил запись.** Вход:
структура из двух полей, агрегатный инициализатор, чтение обоих полей.

| Потребитель | Ответ | Класс |
|---|---|---|
| эталон | `g = Gains{kp=2,ki=3}`, `sum = 5` | норма |
| `c`, `c-hal`, `plantuml` | переводят | — |
| **`st`, `st-at`** | переводят объявление, тип и доступ, но **молча теряют** агрегатный инициализатор (`g : Gains;` без `:=`) | **`Tier 1`**: `sum` в прошивке 0 вместо 5 |
| **`sv`, `sv-mmio`** | печатают `gains_t` — **`typedef` не эмитится вовсе**; `verilator`: `Can't find typedef/interface: 'gains_t'` при **нулевом** коде возврата | **`Tier 2`** |
| `rust` | `RS-011` «доступ к члену '.kp': поля структур в цели rust пока не транслируются» | `Tier 3`: честный отказ |

Кандидат называл поведение `st` отказом `ST-011` — сегодня цель **переводит**
структуры и теряет только инициализатор. Условие карточки перепроверено, а не
унаследовано.

Проба с первого раза оказалась негодной дважды, и обе ловушки назвал сам
`probe.sh`: имя файла совпало с именем типа  и висячая запятая в
объявлении полей (грамматика — `Comma<StructField>`, без висячей).

### Decision Drivers

1. **Молчаливое расхождение дороже отказа.** `st` даёт другое значение, `sv` —
   невалидный вывод; обе цели при этом рапортуют об успехе.
2. **Средства целей есть.** В IEC структура объявляется `TYPE … STRUCT`, и цель
   это уже делает; в SystemVerilog структура выражается `typedef struct packed`.
3. **`c` — рабочий образец.** Он переводит все три места (объявление, агрегатный
   инициализатор, доступ), и поведение сверяется с эталоном.
4. **Соразмерность.** Три цели — три задачи; каждая проверяется своим
   инструментом (`iec2c`, `verilator`/`yosys`, `clippy`) и потактовой сверкой.

### Considered Options

#### Option A. Отвергать структуры в целях, которые их не переводят

**Pros:** дёшево, молчание исчезает.

**Cons:** язык уже допускает структуры, эталон и `c` их исполняют; отказ
означал бы, что модель, отлаженная в симуляторе, не собирается для ПЛК и FPGA.
Регресс возможностей ради удобства инструмента.

#### Option B. Перевести структуры во всех трёх целях

**Pros:** цели сходятся с эталоном; молчаливые классы исчезают.

**Cons:** объём: три независимые реализации плюс сверки. Риск снижается тем, что
каждая цель проверяется чужим инструментом, а поведение — трассой.

#### Option C. Перевести там, где молчание, отказ оставить там, где он честный

`st` и `sv` чинятся (Tier 1 и 2), `rust` продолжает отказывать `RS-011`.

**Pros:** снимает молчаливые классы наименьшей ценой.

**Cons:** оставляет цель `rust` без структур при живом отказе — то есть
сохраняет разрыв возможностей между целями, названный кандидатом.

### Decision

Принимается **Option B**, разбитый на три задачи по убыванию вреда:

1. **`0293-01` — `sv`**: эмиссия `typedef struct packed` для каждой структуры и
   корректное значение сброса (агрегат раскладывается по полям). Сегодня вывод
   невалиден при коде возврата 0.
2. **`0293-02` — `st`**: агрегатный инициализатор не теряется. Форма выбирается
   **пробой** `iec2c` (инициализация структурного типа в объявлении либо
   присваивание полей в ветви первого скана) — как это делалось для всех
   решений цели `st`.
3. **`0293-03` — `rust`**: объявление структуры и доступ к полям.

Каждая задача закрывается **потактовой сверкой** с эталоном, а не фактом
компиляции: вывод трёх целей принимают чужие инструменты и в неверном виде.

### Consequences

#### Положительные

- структуры перестают быть привилегией цели `c`;
- два молчаливых класса (иное значение у `st`, невалидный вывод у `sv`)
  исчезают;
- `RS-011` на полях структур снимается.

#### Отрицательные / Action items

- вывод трёх целей меняется; в корпусе структура объявлена один раз и полей не
  трогает (`examples/extend_complex.takt`) — снапшоты почти не двигаются, но
  проверить обязательно;
- документ (`book/`, раздел о типах) должен назвать, что структуры переводятся
  всеми целями;
- если какая-то из форм окажется невыразимой в целевом языке, отказ обязан
  быть **громким и с причиной**, а невозможность — названной в документе.

#### Acceptance criteria

1. `sv`: вывод со структурой принимают `verilator --lint-only -Wall` и `yosys`.
2. `st`: агрегатный инициализатор доезжает; `iec2c` принимает; трасса совпадает
   с эталоном.
3. `rust`: доступ к полям переводится; `clippy -D warnings` принимает.
4. Потактовые сверки эталон ≡ цель для каждой из трёх целей.
5. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Свести три цели с эталоном на структурных типах. Замер-19
поправил карточку: `st` **переводит** структуры и теряет только агрегатный
инициализатор (`Tier 1` — иное значение), `sv` печатает ссылку на необъявленный
тип (`Tier 2` — невалидный вывод при коде 0), `rust` честно отказывает
`RS-011` (`Tier 3`).

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Опирается на закрытые 0034 (структурные типы языка) и
  0182-01 (библиотека PID, где класс и был замечен).
- **Влияние на порядок разработки:** снимает разрыв возможностей между целями;
  никого не блокирует.

### Требования и проверяемые условия

- **R1. `sv` объявляет структуру.** Каждая структура получает
  `typedef struct packed`; поле печатается тем же отображением типов, что и
  переменная.
- **R2. `sv` кладёт агрегат в цепь сброса.** Форма выбирается по тому, что
  принимают **оба** инструмента (`verilator` и `yosys`).
- **R3. `st` не теряет инициализатор.** Форма выбирается **пробой** `iec2c`.
- **R4. `rust` переводит структуры.** Объявление типа, литерал-агрегат и доступ
  к полю; вывод принимает `clippy -D warnings`.
- **R5. Значения совпадают с эталоном.** У каждой из трёх целей — потактовая
  сверка.
- **R6. Прежнее поведение цело.** Корпус компилируется; изменения снапшотов
  объяснены.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `sv`: `verilator` и `yosys` принимают | прогон обоих инструментов |
| A2 | `st`: `iec2c` принимает, инициализатор на месте | прогон `iec2c`, чтение вывода |
| A3 | `rust`: `clippy -D warnings` принимает | проверка цели на корпусе |
| A4 | Трассы совпадают | три потактовые сверки |
| A5 | Регресс | `./scripts/precheck.sh` |

### Особенности по обратной функциональности

Правило 11. Изменение **расширяющее**: входы, прежде отвергавшиеся (`sv`,
`rust`) или переводившиеся неверно (`st`), теперь переводятся верно. Ни один
работавший вход не ломается.

Меняется **вывод корпуса**: `examples/generated/rust/pid_law.rs` и
`pid_heater.rs` переписаны (структуры теперь переводятся), а
`examples/generated/st/pid_heater.st` получил потерянный инициализатор PID.
Последнее — доказательство `Tier 1` **на корпусе**: коэффициенты регулятора
молча не доезжали до ПЛК, и `iec2c` этого не видел.

**Версия языка не меняется**: синтаксис и семантика прежние, расширяется охват
целей.

### Правило 29: редакторский слой

Правок **не требует**: лексика, синтаксис и семантика не менялись — правятся
печатники трёх целей. Новых узлов АСД и диагностик нет.

### Документирование (правило 24)

**Требуется:** раздел `book/` о типах должен сказать, что структуры переводятся
всеми целями (прежде текст молчал об охвате, а три цели их не умели).

### Риски и зависимости

- **Риск: форма агрегата не принимается инструментом.** Снимается пробой обоих
  инструментов SV и `iec2c` до реализации — именно так и найдено, что
  именованную форму `'{kp: 2}` **yosys отвергает**, тогда как `verilator`
  принимает.
- **Риск: вывод `Eq` для структуры с `float`.** `f64` не реализует `Eq`; вывод
  корпуса перестал бы компилироваться. Проверяется проверкой цели `rust`.
- **Риск: запись в поле локальной переменной.** Требует `let mut` — прежде
  случай не возникал, потому что поля не переводились; ловится тем же проверкой.

## Разработка

### Задача

#### Что было

`sv_type` отображал `TypeNode::Struct` в имя `<имя>_t`, но **объявления не
эмитил**: `verilator` отвечал `Can't find typedef/interface: 'gains_t'` — при
**нулевом** коде возврата `taktc`. Агрегатный инициализатор отвергался `SV-002`.

#### Что сделано

- `sv_type::emit_structs` печатает `typedef struct packed { … } <имя>_t;` для
  каждой структуры дерева; поле печатается тем же `sv_type`, что и переменная;
- `sv_const::struct_reset` кладёт агрегат в цепь сброса.

**`packed` обязателен:** непакованная структура не синтезируется и не годится
на роль регистра, а именно регистром становится переменная модели.

**Форма агрегата выбрана пробой обоих инструментов.** Именованную
(`'{kp: 2, ki: 3}`) `verilator` принимает, а **yosys отвергает**
(`syntax error, unexpected ':'`). Принята позиционная конкатенация
`{8'd2, 8'd3}` — тот же урок, что у `assert … else` (0235).

**Размерные литералы обязательны всегда**, а не по нужде (в отличие от печати
литерала, 0157): `verilator -Wall` отвечает `WIDTHCONCAT` на любое безразмерное
число внутри `{…}`.

Порядок полей — **объявленный**: в `struct packed` он определяет разряды.

#### Проверки

```sh
cargo test --test conformance struct
./scripts/precheck.sh
```

`verilator --lint-only -Wall` и `yosys synth` принимают вывод; потактовая сверка
`conformance_sv_tests::struct_init` — трасса совпадает с эталоном.

### Задача

#### Что было

Цель переводила объявление структуры, тип и доступ к полю, но **молча теряла**
агрегатный инициализатор: `g : Gains;` без `:=`. Прошивка ПЛК считала с нулей,
эталон — с заданных значений; `iec2c` такой ST принимает.

Класс жил **в корпусе**: `examples/generated/st/pid_heater.st` объявлял
`loop_pid : PidState;` — то есть коэффициенты регулятора (`kp`, `ki`, `kd`,
`ts`, границы) до ПЛК не доезжали вовсе.

#### Что сделано

`st_decl::struct_init` печатает именованную форму IEC:
`g : Gains := (kp := 2, ki := 3);`.

Форма выбрана **пробой**: `iec2c` её принял (2026-08-19). Это то же правило,
по которому принимались все решения цели `st`: факты MatIEC
снимаются зондом, а не выводятся из стандарта.

`literal_init` получил параметр «модель»: имена и порядок полей берутся у
**объявления** структуры — инициализатор языка позиционный, и вторая раскладка
разошлась бы с эталоном.

#### Проверки

```sh
cargo test --test conformance struct_init
```

Потактовая сверка `conformance_st_tests::struct_init` (через `iec2c` + `cc`):
трасса совпадает с эталоном. Дифф корпуса показывает восстановленные
коэффициенты `pid_heater`.

### Задача

#### Что было

`RS-011`: «доступ к члену '.kp': поля структур в цели rust пока не
транслируются». Структура объявлялась переменной, но дальше не шла.

#### Что сделано

- `rust_decl::emit_structs` печатает `pub struct` с полями;
- `rust_bit::field_access` — доступ `<база>.<поле>` (прежде `member_index`
  отвечал отказом на `Member::Identifier`); то же в печатнике условий;
- `rust_struct::struct_literal` — агрегат `Gains { kp: 2, ki: 3 }`: без типа
  приёмника общий печатник выражений давал массив `[2, 3]`, то есть невалидный
  Rust.

**`Eq` не выводится:** у поля `float` (`f64`) его нет, и вывод корпуса
перестал бы компилироваться. Сравнение структур язык и так запрещает (`SE-059`).

**Запись в поле делает переменную изменяемой:** `collect_assigned` учитывает
`r.output := …`, иначе `rustc` отвечает `E0594` («cannot assign … not declared
as mutable»). Случай не возникал, пока поля не переводились, — и всплыл на
корпусе (`pid_heater`).

#### Проверки

```sh
cargo test --test conformance struct_fields_match_generated_rust
./scripts/precheck.sh
```

Проверка цели (`rustc` + `clippy -D warnings`) на корпусе зелёный; потактовая сверка
через порт-наблюдатель совпадает с эталоном.

## Тест-план

### Область и цель

У каждой цели — **потактовая сверка** с эталоном, а не факт компиляции: чужие
инструменты принимают и неверный вывод (порядок полей в `struct packed`,
потерянный инициализатор в ST — `iec2c` его принимал).

| T1 | `sv`: объявление типа | структура из двух полей | в выводе `typedef struct packed { … } gains_t;` | R1 / A1 |

### Класс жил в корпусе — и проверка его не видел

Дифф снапшотов: `examples/generated/st/pid_heater.st` объявлял
`loop_pid : PidState;` — то есть **коэффициенты регулятора** (`kp = 0.5`,
`ki = 0.0625`, `kd = 0.25`, границы выхода) до ПЛК не доезжали вовсе. Прошивка
считала с нулей. `iec2c` такой ST принимал, проверка был зелёным.

### Находки сверх ожидаемого

1. **Именованную форму агрегата SV отвергает yosys.** `'{kp: 2, ki: 3}`
   `verilator` принимает, `yosys` — `syntax error, unexpected ':'`. Принята
   позиционная конкатенация с **размерными** литералами (`{8'd2, 8'd3}`):
   безразмерные дают `WIDTHCONCAT`. Тот же урок, что у `assert … else` (0235):
   форма выбирается по тому, что принимают **оба** инструмента.
2. **`Eq` нельзя выводить для структуры с `float`.** `f64` его не реализует —
   вывод корпуса перестал бы компилироваться.
3. **Запись в поле требует `let mut`.** `rustc`: `E0594` на `pid_heater`.
   Случай не возникал, пока поля не переводились.
