## Краткое описание

Модель без единого порта даёт `pub fn new() -> Self` **без аргументов**, и
`clippy -D warnings` требует `impl Default` — проверка цели `rust` на таком входе
красный. Класс ровно как у закрытой [генератор C: typedef корневой структуры для одиночной модели](0026-c-root-typedef.md): дыра не в
коде, а в покрытии, и снова на **простейшем** классе моделей.

> Фича зарегистрирована из бэклога кандидатов (отобрана заказчиком 2026-07-28); далее проходит жизненный цикл по своду.

## Что известно на входе

- Контрольная проба: один добавленный порт → `pub fn new(hal: H)` → аргумент
  есть → линт **молчит**, проверка зелёный. Триггер — именно **отсутствие портов**.
- Корпус слеп по **двум** причинам сразу: у каждого примера есть порты, а
  `new()` под-модели **приватен** (линт срабатывает только на публичных).
- В объём 0058 не взято: другой механизм, другое лечение.

## Направление решения (наметка, не решение)

- Решение того же рода, что принимала 0050 (политика (а): не эмитить то, на что
  линт ругается): эмитить `impl Default` рядом с `new()` **либо** не делать
  `new()` публичным.
- Обязательно завести пример-контроль (модель без портов) — иначе корпус
  останется слеп и дефект вернётся.

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

### Context

Корневая модель, которой транзитивно не нужен HAL, даёт
`pub fn new() -> Self` **без аргументов**. Линт `clippy::new_without_default`
на такой конструктор ругается, а проверка цели `rust` в `precheck.sh` гоняет
`clippy -D warnings` — то есть на подобном входе он **красный**. Следствие шире
проверки: пользователь со своей политикой `-D warnings` не собрал бы порождённый
код вовсе.

Проба 2026-07-29 (модель `var n: u8; model Counter { … } start Main = Counter;`):

```
error: you should consider adding a `Default` implementation for `Noports`
  --> noports.rs:97:5
   | pub fn new() -> Self {
   = note: `-D clippy::new-without-default` implied by `-D warnings`
```

`rustc` при этом **молчит** — синтаксис и типы верны. Дефект видит только
clippy.

#### Почему корпус слеп

Карточка фичи предполагала причину «у каждого примера есть порты». Замер её
**уточнил**: у `comprehensive.takt` портов **ноль**, и проверка всё равно зелёный —
пример зовёт `extern fn`, поэтому получает `new(hal: H)`, аргумент у
конструктора есть и линт молчит.

Настоящий признак — предикат `needs_hal` (транзитивный по портам **и**
`extern fn`). Слепым корпус делает то, что **ни один** пример не обходится разом
без портов и без `extern fn`. Контрольный замер: перегенерация всего корпуса
после правки даёт **пустой дифф** — то есть исправление ни одного примера не
касается, и без отдельного контроля регресс вернулся бы незамеченным.

### Decision Drivers

1. **Проверка обязан быть зелёным на простейшем входе.** Модель без ввода-вывода —
   самый простой класс моделей, и именно на нём цель отказывает.
2. **Политика линтов R9 фичи: «не эмитить то, на что линт ругается».**
   Точечные `#[allow]` глушат контроля: заглушив линт, мы спрячем и будущие его
   срабатывания.
3. **Правка не должна касаться корпуса.** Порождённый код существующих примеров
   обязан остаться байт-в-байт прежним — иначе фича вышла бы за свои границы.
4. **Контроль обязателен.** Без него корпус остаётся слеп, и дефект вернётся с
   первой же правкой генератора.

### Considered Options

#### Option A. Эмитить `impl Default` рядом с `new()` без аргументов

**Pros:**
- ровно то, что предлагает сам clippy, и идиоматичный Rust: тип, строящийся без
  параметров, обязан быть `Default`;
- **аддитивно**: добавляется новый элемент вывода, существующий не меняется;
- условие эмиссии буквально совпадает с условием срабатывания линта
  (конструктор публичен и без аргументов), поэтому «разъехаться» им негде.

**Cons:**
- нужен точный предикат: при `new(hal: H)` печатать `Default` **нельзя** —
  значение `H` взять неоткуда, вывод не скомпилируется. То есть ошибка в условии
  ломает весь корпус, а не молчит.

#### Option B. Сделать `new()` приватным

**Pros:**
- линт срабатывает только на публичных конструкторах — замолчит.

**Cons:**
- **уничтожает публичный API**: модель станет непостроимой снаружи крейта, то
  есть порождённый модуль перестанет быть пригодным для использования;
- лечит симптом (видимость), а не причину.

#### Option C. `#[allow(clippy::new_without_default)]` у конструктора

**Pros:**
- одна строка.

**Cons:**
- прямо противоречит политике R9 фичи: атрибут глушит контроля навсегда,
  включая будущие, ещё не появившиеся срабатывания;
- переносит проблему на пользователя: он получает код с чужим `allow` в своём
  крейте.

### Decision

Принимается **Option A**.

Условие эмиссии — `is_root && !uses_hal`, то есть буквально то же, при котором
срабатывает линт: конструктор **публичен** (публичен только корневой) и
аргументов не имеет (аргумент появляется ровно тогда, когда модели транзитивно
нужен HAL).

#### Контроль: фикстура, а не корпусный пример

Карточка предлагала завести **корпусный пример** без портов. Отвергнуто:

- модель без единого порта и без `extern fn` — **замкнутая система**, ничего не
  наблюдающая и ни на что не влияющая. В `examples/` такой файл был бы
  документацией о том, как писать бесполезную модель;
- контроль ставится там же, где стоят прочие контроля порождённого кода, — в
  тестах на **фикстурах** (прецедент: `conformance_rust_tests` собирает
  порождённый Rust настоящим `rustc` на своих фикстурах, а не на корпусе).

Контроль — **двухслойный**, и оба слоя нужны:

1. **эмиссия** — быстрый текстовый тест: `impl Default` есть при конструкторе
   без аргументов и **отсутствует** при `new(hal: H)`;
2. **проверка** — тот же `clippy -D warnings`, что в `precheck.sh`, применённый к
   фикстуре. Первый слой ловит регресс дёшево и точно, второй доказывает, что
   ловится **настоящее** правило линта, а не наше представление о нём.

### Consequences

#### Положительные

- цель `rust` перестаёт отказывать на простейшем классе моделей;
- порождённый модуль получает идиоматичный `Default` — польза, а не заглушка;
- корпус впервые получает контроля на класс «модель без HAL».

#### Отрицательные / Action items

- предикат `uses_hal` становится **условием компилируемости** вывода в ещё
  одном месте: ошибка в нём теперь ломает не только `-D warnings`, но и сборку
  (`Default` при `new(hal: H)` не скомпилируется). Это цена Option A, и она
  покрыта контрпримером в тестах;
- обоснование «порт нужен цели `rust`» в комментариях `regulator.takt`,
  `float_regulator.takt` и `pid_regulator.takt` **устарело**. Правка их
  комментариев в объём не берётся: она косметическая и тронула бы три файла
  корпуса ради одной фразы — записано находкой в `FEATURES.md`.

#### Acceptance criteria

1. Модель без портов и без `extern fn` даёт `impl Default` рядом с `new()`.
2. Модель с портом (или `extern fn`) `impl Default` **не** получает.
3. Порождённый модуль первой модели принимается `clippy -D warnings`.
4. `examples/generated/rust/**` не изменился.
5. Оба слоя контроля **взведены** — доказано мутацией генератора.
6. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Реализовать **Option A** ADR: печатать `impl Default` рядом с публичным
конструктором без аргументов и завести двухслойного контроля.

Работа целиком в крейте `takt-lang`, генератор цели `rust`. Язык **не
меняется**, версия языка не растёт.

### Зависимости фичи

- **Зависит от:** нет.
- **Влияние на порядок разработки:** ничего не разблокирует и ничем не
  блокируется.

### Разбор (что именно сломано и где)

| # | Место | Факт |
|---|---|---|
| Д1 | `takt-lang/src/generator/rust/rust_model.rs`, `emit_new` | `args` пусты при `!(is_root && uses_hal)` → у корня без HAL печатается `pub fn new() -> Self` без аргументов |
| Д2 | там же, конец блока `impl` | `impl Default` не печатается **никогда** — линт `clippy::new_without_default` остаётся неудовлетворённым |

**Уточнение к карточке.** Причина слепоты корпуса — не «у всех примеров есть
порты»: у `comprehensive.takt` их **ноль**. Настоящий признак — предикат
`needs_hal`, транзитивный по портам **и** `extern fn`. `comprehensive` зовёт
`extern fn`, получает `new(hal: H)`, и линт молчит. Слепым корпус делает то,
что **ни один** пример не обходится разом без портов и без `extern fn`.

Контрольный замер: перегенерация всего корпуса после правки даёт **пустой
дифф** — правка ни одного примера не касается.

### Требования и проверяемые условия

- **R1. `impl Default` при конструкторе без аргументов.** Условие эмиссии —
  `is_root && !uses_hal`, буквально то же, при котором срабатывает линт.
- **R2. `impl Default` Не печатается при `new(hal: H)`.** Не «не нужно», а
  **нельзя**: значение `H` взять неоткуда, вывод не скомпилируется.
- **R3. Вывод принимается `clippy -D warnings`** — тем же линтом и с той же
  политикой, что в проверке `precheck.sh`.
- **R4. Корпус не изменился.** `examples/generated/rust/**` даёт пустой дифф.
- **R5. Контроль взведён.** Отключение эмиссии обязано валить тесты; эмиссия
  «всегда» — тоже.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `impl Default` эмитится (R1) | `rust_default_impl_tests::model_without_ports_emits_default_impl` |
| A2 | не эмитится при `hal` (R2) | `model_with_port_does_not_emit_default_impl` (контрпример) |
| A3 | вывод проходит линт (R3) | `generated_module_passes_clippy_gate` — тот же `clippy -D warnings`, что в проверке |
| A4 | корпус не изменился (R4) | `git diff examples/generated/rust` пуст |
| A5 | контроль взведён (R5) | мутации генератора: «не эмитить никогда» и «эмитить всегда» |
| A6 | корпус зелёный | `./scripts/precheck.sh` |

### Устройство контроля

Новый файл `takt-lang/tests/targets/rust_default_impl_tests.rs`, два слоя:

1. **эмиссия** (быстро, без внешних инструментов) — текст вывода: `impl Default`
   есть/нет;
2. **проверка** — `clippy-driver -D warnings` на обёртке с `#![no_std]` в корне,
   дословно как в `precheck.sh`. Мягкая деградация: нет `clippy-driver` →
   пропуск с сообщением (образец — `conformance_rust_tests`).

Оба слоя нужны. Один текстовый тест доказывал бы лишь, что мы печатаем
задуманную строку; один прогон линта не сказал бы, **почему** он зелен, и не
поймал бы эмиссию `Default` там, где её быть не должно (R2).

### Особенности по обратной совместимости

Изменение **аддитивно**: печатается новый элемент вывода, существующие не
меняются. Порождённый код всего корпуса байт-в-байт прежний (замер выше). Язык,
симулятор и прочие цели не затронуты — **н/п**.

Публичный API порождённого модуля **расширяется** (`Default` — новый трейт у
корневого типа), что совместимо: ни одна существующая сигнатура не меняется.

### Риски

- **Риск ошибки в предикате.** `impl Default` при `new(hal: H)` не
  скомпилируется, то есть ошибка условия ломает корпус громко, а не молча.
  Снижение: контрпример A2 + мутация «эмитить всегда».
- **Риск, что контроль стережёт не то.** Текстовый тест может пройти при том, что
  линт всё равно недоволен (например, если clippy сменит правило). Снижение:
  второй слой гоняет **настоящий** `clippy -D warnings`.
- **Устаревшие комментарии корпуса.** Три примера (`regulator`,
  `float_regulator`, `pid_regulator`) объясняют свой выходной порт нуждой цели
  `rust`; после фичи объяснение неверно. В объём **не берётся** (косметика по
  трём файлам корпуса) — записано находкой в `FEATURES.md`.

## Разработка

### Задача

#### Что было

Корень без транзитивной нужды в HAL получал `pub fn new() -> Self` без
аргументов, а `impl Default` не печатался **никогда**. Под `clippy -D warnings`
(политика проверки цели `rust`) такой вывод — красный.

#### Что сделано

##### Генератор

`takt-lang/src/generator/rust/rust_model.rs` — новая функция
`emit_default_impl`, вызывается сразу после закрытия блока `impl`:

```rust
if !is_root || uses_hal { return; }
```

Условие буквально совпадает с условием срабатывания линта: конструктор
**публичен** (публичен только корневой) и аргументов не имеет (аргумент
появляется ровно при `uses_hal`). При `uses_hal` печатать не просто не
нужно, а **нельзя**: значение `H` взять неоткуда — вывод не скомпилируется.

Выбран `impl Default`, а не `#[allow(clippy::new_without_default)]`: политика R9
фичи — «не эмитить то, на что линт ругается»; атрибут заглушил бы и будущие
срабатывания.

##### Контроль

Новый `takt-lang/tests/targets/rust_default_impl_tests.rs`, два слоя:

| Тест | Что доказывает |
|---|---|
| `model_without_ports_emits_default_impl` | `impl Default` печатается при конструкторе без аргументов |
| `model_with_port_does_not_emit_default_impl` | **контрпример**: при `new(hal: H)` не печатается |
| `generated_module_passes_clippy_gate` | тот же `clippy -D warnings`, что в `precheck.sh`, принимает вывод |

Второй слой нужен потому, что первый доказывает лишь печать задуманной строки, а
не согласие **настоящего** линта. Мягкая деградация: нет `clippy-driver` →
пропуск с сообщением (образец — `conformance_rust_tests`).

Обратная функциональность: изменение **аддитивно** — печатается
новый элемент, существующие не меняются. Симулятор и прочие цели не затронуты —
**н/п**.

#### Проверки

| Что | Результат |
|---|---|
| `cargo test --all-features --test rust_default_impl_tests` | 3 из 3 |
| `cargo test --all-features -- --test-threads=1` | зелёный |
| `cargo clippy --all-targets --all-features -- -D warnings` | чисто |
| перегенерация корпуса целью `rust` | `git diff examples/generated/rust` **пуст** |
| `./scripts/precheck.sh` | зелёный |

**Взведённость доказана двумя мутациями генератора** — каждая валит свой класс
тестов и только его:

| Мутация | Падают | Остаются зелёными |
|---|---|---|
| эмиссия отключена (`return` сразу) | `model_without_ports_emits_default_impl`, `generated_module_passes_clippy_gate` | контрпример |
| эмиссия безусловна (снято `uses_hal`) | контрпример | остальные два |

Пустой дифф корпуса — не «нечего было чинить», а подтверждение диагноза: **ни
один** пример не обходится разом без портов и без `extern fn`, поэтому проверка этот
класс не видел и без отдельного контроля не увидел бы впредь.

### Область и цель

Доказать, что цель `rust` перестала отказывать на модели без ввода-вывода и что
контроль на этот класс **взведён**. Проверяются R1–R5 анализа и критерии

## Итог (что сделано)

Цель `rust` печатает `impl Default` рядом с публичным конструктором **без
аргументов** — условие эмиссии (`is_root && !uses_hal`) буквально совпадает с
условием срабатывания `clippy::new_without_default`. Выбран `impl Default`, а не
`#[allow(...)]`: политика R9 фичи — «не эмитить то, на что линт ругается»,
атрибут заглушил бы и будущие срабатывания.

Контроль — **двухслойный** (`takt-lang/tests/targets/rust_default_impl_tests.rs`):
текстовый тест на эмиссию (плюс контрпример «при `hal` печатать нельзя») и
прогон **настоящего** `clippy -D warnings`, того же, что в проверке. Взведённость
доказана двумя мутациями генератора, каждая валит свой класс тестов и только его.

**Диагноз карточки уточнён замером.** Причина слепоты корпуса — не «у всех
примеров есть порты» (у `comprehensive.takt` их ноль), а предикат `needs_hal`,
транзитивный по портам **и** `extern fn`. Ни один пример не обходится разом без
того и другого, поэтому перегенерация корпуса после правки даёт **пустой дифф** —
это подтверждение диагноза, а не признак ненужности фичи.

Контроль поставлен **фикстурой**, а не корпусным примером (наметка карточки
отклонена, обоснование — в [ADR](0174-rust-new-without-default.md#архитектура-adr)):
модель без единого порта — замкнутая система, и в `examples/` она была бы
документацией о том, как писать бесполезную модель.

Детали — [отчёт](0174-rust-new-without-default.md#отчёт-о-тестировании).
