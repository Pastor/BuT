# Фича: Комментарий перед блочным оператором уезжает внутрь блока

- **Номер:** 0406
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** синтаксис
- **Связанные issue (анализ):** находка [форматтер печатает блоки formula и assembly](0405-format-formula-assembly.md)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Комментарий, написанный **перед блочным оператором**, форматтер переносил
внутрь его тела, а пустую строку перед оператором терял. Комментарий менял
хозяина: он относился к оператору, а становился первой строкой тела.

## Документирование

Языка фича не меняет. Раздел [«Комментарии»](../../book/src/21-code-style/index.typ)
свода стиля правки **не потребовал**: он и прежде обещал, что форматтер
сохраняет привязку комментария к записи, — обещание стало исполняемым, а не
декларативным. Проверено чтением раздела, а не предположением.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-23
- **Authors:** архитектор, разработчик, тестировщик

### Context

Замер-23 (прогон `taktc fmt --stdin`):

```takt
a := 1;

// комментарий перед if
if a > 0 {
    a := 2;
}
```

печаталось как

```takt
a := 1;
if a > 0 {

    // комментарий перед if
    a := 2;
}
```

Причина видна в коде: заголовок блочного оператора печатал
`stmt::block_with_head` через `Out::line` — **без позиции узла**. Ведущие
комментарии выдаёт `Out::node_line`, и у неблочных операторов привязка была
верна; у блочных выдать их было некому, и они всплывали внутри тела при первом
же `node_line` — то есть на первом операторе тела.

Класс правился трижды: фичи (операторы), 0197-01 (перечисление), 0198-01
(структура), 0295 (закрывающая скобка тела). Здесь **четвёртое** место.

### Considered Options

1. **Печатать заголовок через `node_line(loc, …)`.** Отвергнут: `node_line`
   берёт и **хвостовой** комментарий по концу `loc`, а `loc` блочного
   оператора покрывает **весь** оператор вместе с телом — комментарий,
   стоящий после закрывающей скобки, приклеился бы к строке `if … {`.
2. **Выдавать ведущие комментарии в общей точке входа `stmt::print`** —
   `blank_before(loc)` + `leading_for(loc)`, как это уже делает
   `print_state_element` для элементов состояния.

### Decision

Вариант 2. `stmt::print` стал тонкой обёрткой: выдаёт пустую строку и ведущие
комментарии, затем зовёт `print_inner` — прежнее тело.

**Ветвь `else` зовёт `print_inner` напрямую.** Там строка ждёт продолжения
(`} else `), и выдача комментария в неё разрывает K&R-раскладку: получается
`} else // комментарий` и перенос `if` на следующую строку. Проверено
мутацией — без этого различения канон ломается.

**Двойной выдачи у неблочных операторов нет**: `leading` потребляет
комментарии до смещения, и повторный вызов внутри `node_line` уже ничего не
находит.

### Consequences

- Комментарий и пустая строка перед `if`, `while`/`loop`, `for`, `match`,
  `assembly`, `formula` остаются на месте.
- **Вывод корпуса не изменился**: `taktc fmt --check examples/` зелён без
  единой правки — в живых примерах комментариев в этой позиции не было
  (ровно поэтому дефект и дожил).

#### Acceptance criteria

1. Комментарий перед блочным оператором печатается на его уровне.
2. Пустая строка перед оператором сохраняется.
3. Комментарий внутри тела остаётся внутри.
4. K&R-цепочка не разрывается — в том числе при комментарии перед `else`.

## Анализ

### Замер

| Вход | До | После |
|---|---|---|
| `// c` + `if` | комментарий внутри тела, пустая строка потеряна | комментарий перед `if`, пустая строка на месте |
| то же для `while`, `loop`, `for`, `match`, `assembly`, `formula` | то же | то же |
| комментарий внутри тела | внутри | внутри (не изменилось) |
| цепочка `} else if` | плоская | плоская |

### Требования и проверяемые условия

| № | Требование |
|---|---|
| R1 | Ведущие комментарии выдаются перед **любым** оператором, а не только неблочным |
| R2 | Пустая строка перед оператором восстанавливается |
| R3 | Комментарии тела наружу не выносятся |
| R4 | K&R-раскладка цепочки `else` сохраняется |
| R5 | Печать идемпотентна |

### Особенности по обратной функциональности

Ломающих изменений нет: прежний вывод отличался только в файлах с
комментариями в этой позиции, а таких в корпусе не было.

### Риски и зависимости

**Названная граница:** комментарий, стоящий между `}` и `else`, по-прежнему
уходит внутрь тела ветки. Поставить его на своё место нельзя, не разорвав
K&R-раскладку: своей строки у ветки `else` в каноне нет.
Контрольный тест закрепляет именно это — цепочка остаётся плоской.

## Разработка

### Задача

#### Что было

`stmt::print` печатал оператор сразу; ведущие комментарии выдавал только
`Out::node_line`, недоступный блочным операторам.

#### Что сделано

- `format/stmt.rs`: `print` = `blank_before` + `leading_for` + `print_inner`;
  ветвь `else` зовёт `print_inner`.
- `takt-lang/tests/syntax/format_comment_before_block_tests.rs` — контроль из
  семи проверок.

#### Проверки

`cargo test --test syntax format` (73 теста), две мутации, `fmt --check` на
корпусе, полный `./scripts/precheck.sh`.

## Тест-план

| № | Условие | Ожидание |
|---|---|---|
| T1 | Комментарий перед `if`/`while`/`loop`/`for`/`match`/`assembly` | отступ комментария равен отступу оператора |
| T2 | Комментарий перед блоком `formula` | то же |
| T3 | Пустая строка перед оператором | сохранена |
| T4 | Комментарий внутри тела | остаётся глубже заголовка |
| T5 | Цепочка `else if` без комментариев | плоская |
| T6 | Комментарий перед веткой `else` | цепочка плоская |
| T7 | Двойной прогон | текст не меняется |
| M1 | Мутация: снять выдачу ведущих | падение T1 и T3 |
| M2 | Мутация: выдавать ведущие и в ветви `else` | падение T6 |

## Отчёт о тестировании

### Резюме

Семь проверок зелёные, обе мутации ловятся, полный `precheck.sh` — код 0.

### Фактические результаты по проверкам

| № | Результат | Наблюдение |
|---|---|---|
| T1–T5, T7 | пройдены | — |
| T6 | пройдена | **добавлен по итогу мутации**: первая редакция контроля M2 не ловила — в цепочке без комментариев выдавать нечего, и разрыв не проявлялся |
| M1 | ловится | падают T1 и T3 |
| M2 | ловится | падает T6: `} else // комментарий` с переносом `if` |

Проверка идёт **по отступу**, а не по порядку строк: уезжая внутрь тела,
комментарии сохраняют взаимный порядок, и проверка порядка дефекта не видит
(урок фичи).

### Найденные дефекты

Новых не найдено. Подтверждена **граница**: комментарий между `}` и `else`
остаётся внутри тела ветки — поставить его иначе нельзя, не разорвав K&R.

### Выводы и дальнейшие шаги

Класс закрыт в четвёртом и последнем известном месте: ведущие комментарии
теперь выдаются в **общей точке входа** печати оператора, а не в каждой ветви
по отдельности.

## Итог (что сделано)

- Комментарий и пустая строка перед блочным оператором остаются на месте;
  выдача ведущих комментариев переехала в общую точку `stmt::print`.
- Ветвь `else` зовёт печать напрямую — иначе рвётся K&R-раскладка
  (доказано мутацией).
- Контроль из семи проверок, обе мутации ловятся; вывод корпуса не изменился.
