## Краткое описание

Пространство имён портов симулятора **плоское**: одноимённые порты разных
под-моделей делят значение. [ключ карты адресов — голое имя порта](0084-address-map-qualified-key.md)
квалифицировала ключ **карты адресов** (для цели `c-hal`), но не значения портов
симулятора — это разные слои, и второй остался неисправленным.

> Фича зарегистрирована из бэклога кандидатов (отобрана заказчиком 2026-07-27); далее проходит жизненный цикл по правилу 17.

## Что известно на входе

- `Unit::get_value` / `set_value` на `Parallel` адресуют **все** ветви по голому
  имени порта.
- В корпусе дефект замаскирован: одноимённых портов у под-моделей нет.
- Прецедент решения уже есть — `qualified_port_key(model_unique, port)` в
  `address_map/resolve.rs`: продюсер и потребитель обязаны строить
  **одну** строку.

## Направление решения (наметка, не решение)

- Квалифицированный ключ `модель::порт` в симуляторе по образцу.
- Согласовать с [именованные порты в сценариях симулятора](0132-sim-named-port-scenarios.md): обе правки трогают
  **один** контракт (адресация порта по имени), поэтому порядок «сначала 0135,
  затем 0132» зафиксирован зависимостью.
- Регрессия — тест по образцу `composition_ports_tests.rs`; драйв портов
  проверяется `run_simulations.sh` (не входит в `precheck.sh`).

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

## Архитектура (ADR)

- **Status:** Accepted

### Context

Пространство имён значений симулятора было **плоским**. `Unit::get_value`
спускалось по ветвям композиции и возвращало **первое** найденное совпадение,
`set_value` рассылало запись **всем** ветвям. Пока имена под-моделей уникальны,
это незаметно; при совпадении — половина состояния модели становится
недоступной.

Проба (две под-модели с одноимёнными портами, `Left::val = 1`,
`Right::val = 2`): симулятор печатал `out:val=1`. Значение `Right::val`
существовало (в снимке `--save-state` видны обе ветви), но **адресовать его было
нечем**. Симметрично: задать вход отдельной под-модели тоже нечем — голое имя
уходит в обе.

Смежное решение в проекте уже есть: [ключ карты адресов — голое имя порта](0084-address-map-qualified-key.md#архитектура-adr)
квалифицировала ключ **карты адресов** (`model_unique::port`) — там тот же дефект
проявлялся потерей адреса. Значения симулятора остались неквалифицированными:
это разные слои, и второй не был исправлен.

В корпусе дефект замаскирован — одноимённых портов у под-моделей нет.

### Decision Drivers

1. **Молчание хуже отказа.** Сегодня модель с одноимёнными портами выглядит
   работающей, хотя часть её состояния не наблюдается и не управляется.
2. **Аддитивность (правило 11).** Голые имена используются везде: сценарии JSON
   (позиционные), `--load-state`, `Unit::variable` в десятках тестов,
   потактовые сверки. Ломать их нельзя.
3. **Одна форма записи на две подсистемы.** Разделитель обязан совпасть с уже
   принятым в карте адресов, иначе пользователю придётся помнить две формы.
4. **Границы объёма.** Формат сценариев (позиционные массивы) — территория [именованные порты в сценариях симулятора](0132-sim-named-port-scenarios.md), которая от этой зависит.

### Considered Options

#### Option A. Квалифицированное имя + голое как прежде + видимая двусмысленность

`Модель::порт` адресует одну ветвь (чтение и запись). Голое имя работает
по-прежнему. Двусмысленные имена **называются**: предупреждение при запуске и
квалифицированные формы в потактовом выводе.

**Pros:**
- Полностью аддитивно: ни один существующий сценарий, снимок или тест не
  затронут.
- Дефект перестаёт быть молчаливым — пользователь видит и проблему, и способ
  адресовать точно.
- Разделитель `::` совпадает с ключом карты адресов (0084).

**Cons:**
- Голое имя остаётся двусмысленным (первая ветвь при чтении, все — при записи).
  Это осознанный компромисс ради совместимости; двусмысленность теперь видна.

#### Option B. Только квалифицированные имена

**Pros:**
- Никакой двусмысленности вовсе.

**Cons:**
- **Ломающее**: позиционные сценарии, снимки состояния, `Unit::variable` во всех
  тестах и потактовых сверках. Цена несоизмерима с задачей.

#### Option C. Диагностика вместо чтения при двусмысленности

Голое имя при совпадении — ошибка.

**Pros:**
- Двусмысленность невозможна незаметно.

**Cons:**
- `get_value` возвращает `Option<Value>` и канала для диагностики не имеет;
  вводить его пришлось бы во всём дереве вызовов.
- Ломает те же места, что Option B, только не сразу, а на первой модели с
  совпадением.

### Decision

Принимается **Option A**.

- Узел дерева симуляции получает **имя своей модели** (`UnitKind::Node.model_name`
  из `ModelNode::name`); без него квалифицировать нечем.
- `get_value`/`set_value` распознают форму `Модель::порт` (разделитель `::`, как
  у карты адресов) и адресуют **ровно одну** ветвь; неизвестный квалификатор не
  адресует ничего — опечатка не должна писать «куда-нибудь».
- `PortNames` вычисляет **двусмысленные** имена (объявленные более чем одной
  моделью) и их квалифицированные формы; `takt-sim` печатает предупреждение при
  запуске, а потактовый вывод показывает такие значения квалифицированно.
- Публичный `Unit::set_port` — симметрия к `Unit::variable`: раньше запись
  требовала тащить внутренний трейт `Context` в вызывающий код.

**Вне объёма:** формат сценариев остаётся позиционным (драйв по голому имени
по-прежнему рассылается всем ветвям) — это фича, зависящая от этой.

### Consequences

#### Положительные

- Значения одноимённых портов различимы: `Left::val` и `Right::val` читаются и
  пишутся независимо.
- Двусмысленность **видна**: предупреждение называет обе модели и показывает,
  как адресовать точно; потактовый вывод больше не скрывает половину состояния.
- Совместимость полная: сценарии, снимки и тесты на голых именах не тронуты.

#### Отрицательные / Action items

- **Голое имя остаётся двусмысленным** при совпадении (первая ветвь / все ветви).
  Устранение — за фичей (именованные порты в сценариях) и, при
  необходимости, отдельным решением о запрете голого имени.
- **Квалификатор — имя модели, а не путь.** Две под-модели с одинаковым **именем
  модели** в разных ветвях по-прежнему неразличимы; полный путь (`Root::Left::val`)
  не вводится — в языке нет синтаксиса пути, и в карте адресов 0084 принят тот же
  однокомпонентный ключ.
- **Анонимная модель не адресуема квалифицированно** (у неё нет имени) — голое
  имя работает как прежде.

#### Acceptance criteria

1. `Модель::порт` читается и пишется, адресуя одну ветвь.
2. Неизвестный квалификатор не пишет ничего и читает `None`.
3. Голое имя ведёт себя как прежде (совместимость).
4. Двусмысленные имена перечисляются и попадают в предупреждение и вывод.
5. Корпус `examples/` предупреждений не даёт (в нём совпадений нет).
6. `./scripts/precheck.sh` зелёный.

> Диаграмма по правилу 18 **не требуется**: язык не меняется — меняется
> адресация значений в инструменте.

## Анализ

### Цель и контекст

Сделать значения одноимённых портов разных под-моделей **различимыми** и, там где
различить нельзя, — сделать двусмысленность **видимой**. Решение — Option A
[ADR](0135-sim-qualified-port-names.md#архитектура-adr).

### Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`.
- **Разблокирует [именованные порты в сценариях симулятора](0132-sim-named-port-scenarios.md)**
  (именованные порты в сценариях): именовать порт в сценарии бессмысленно, пока
  имя неоднозначно.

### Воспроизведение дефекта (проба)

Модель: `Left | Right`, у каждой `in cmd: u8` и `out val: u8`; `Left` пишет
`val := 1`, `Right` — `val := 2`.

| Действие | Было | Причина |
|---|---|---|
| потактовый вывод | `out:val=1` | `get_value` возвращает первое совпадение по дереву |
| чтение `Right::val` | невозможно | квалифицированной формы не существовало |
| запись `cmd` | уходит в **обе** ветви | `set_value` на `Parallel` рассылает всем |
| `--save-state` | видны **обе** ветви (`val: 1`, `val: 2`) | снимок идёт по структуре, а не по именам |

Последняя строка важна: **модель считала правильно**, ломалась только адресация.
То есть дефект был в наблюдении и управлении, а не в вычислении.

### Требования и проверяемые условия

- **R1. Различимость.** `Модель::порт` читается и пишется, адресуя ровно одну
  ветвь.
- **R2. Опечатка не пишет никуда.** Неизвестный квалификатор — не «в первую
  попавшуюся ветвь», а никуда.
- **R3. Совместимость (правило 11).** Голое имя ведёт себя как прежде: сценарии
  JSON, `--load-state`, `Unit::variable` в тестах и потактовых сверках не
  затронуты.
- **R4. Двусмысленность видна.** Имена, объявленные несколькими моделями,
  перечисляются; при запуске печатается предупреждение; потактовый вывод
  показывает такие значения квалифицированно.
- **R5. Нет шума.** У модели с уникальными именами предупреждений нет (иначе их
  перестанут читать).
- **R6. Одна форма записи.** Разделитель совпадает с ключом карты адресов  — `::`.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | квалифицированное чтение | тест `qualified_name_reads_the_named_branch` |
| A2 | квалифицированная запись — одна ветвь | тест `qualified_write_touches_only_the_named_branch` |
| A3 | неизвестный квалификатор | тест `unknown_qualifier_addresses_nothing` |
| A4 | голое имя как прежде | тот же A1 (первая ветвь) + зелёные существующие тесты и сверки |
| A5 | перечисление двусмысленных | тест `duplicate_names_are_reported_as_ambiguous` |
| A6 | отсутствие шума | тест `unique_names_are_not_reported_as_ambiguous` |
| A7 | предупреждение и вывод | проба `takt-sim` на модели с совпадением |
| A8 | корпус чист | прогон `takt-sim` по `examples/*.takt` — ни одного предупреждения |
| A9 | предкоммит | `./scripts/precheck.sh` → `EXIT=0` |

### Особенности по обратной функциональности

**Ломающих изменений нет.** Расширяется форма имени (появляется распознавание
`::`), поведение голых имён сохранено дословно. Изменяется **вывод** симулятора,
но только для моделей с одноимёнными портами — то есть ровно там, где прежний
вывод был неполон.

Ограничение области: имя `Модель::порт` содержит **имя модели**, а не путь.
Две под-модели с одинаковым именем модели в разных ветвях останутся
неразличимыми — тот же компромисс, что принят в карте адресов (0084), и в языке
нет синтаксиса пути, чтобы записать иное.

### Риски и зависимости

- **Риск: сломать позиционные сценарии.** Снят тем, что состав и порядок
  `in_ports`/`out_ports` не менялись — двусмысленность живёт в **отдельном** поле
  `PortNames::ambiguous`, а не подмешивается в существующие векторы.
- **Риск: предупреждение станет шумом.** Снят контролем направления A6.
- **Риск: имя модели недоступно узлу.** Реализовался: `UnitKind::Node` его не
  хранил. Добавлено поле `model_name` (из `ModelNode::name`), заполняется
  строителем; у анонимной модели остаётся `None`, и квалифицированная адресация
  к ней невозможна — сказано в ADR, а не замолчано.

## Разработка

### Задача

#### Что было

`Unit::get_value` возвращало **первое** совпадение по дереву композиции,
`set_value` рассылало запись **всем** ветвям. Узел дерева не знал имени своей
модели, поэтому квалифицировать значение было нечем. Одноимённые порты разных
под-моделей делили адрес: `Right::val` не читался никак, а вход отдельной
под-модели задать было нельзя.

#### Что сделано

1. **Узел знает свою модель:** `UnitKind::Node.model_name: Option<String>`
   заполняется строителем из `ModelNode::name`.
2. **Квалифицированная адресация:** `get_value`/`set_value` распознают форму
   `Модель::порт` (`split_qualified`, разделитель `::` — как у ключа карты
   адресов) и спускаются ровно в тот узел, чьё имя совпало.
   Неизвестный квалификатор не адресует ничего.
   У последовательной композиции квалифицированное чтение опрашивает **все**
   шаги, а не только активный: наблюдать уже отработавший шаг законно.
3. **Публичный `Unit::set_port`** — симметрия к `Unit::variable`; прежде запись
   требовала тащить внутренний трейт `Context` в вызывающий код.
4. **Выявление двусмысленности:** `PortNames::ambiguous` — имена, объявленные
   более чем одной моделью, с их квалифицированными формами. Владельцы
   дедуплицируются, поэтому одна и та же модель, встреченная дважды при обходе,
   двусмысленности не даёт.
5. **Видимость:** `takt-sim` печатает предупреждение при запуске, а потактовый
   вывод показывает двусмысленные значения квалифицированно — прежде он печатал
   `val=1`, скрывая `val=2` второй под-модели.

#### Поведение до и после (та же модель `Left | Right`)

```text
было:  Шаг   1:  [S, S]  in:cmd=0  out:val=1
стало: ВНИМАНИЕ: имя 'val' объявлено несколькими моделями (Left::val, Right::val). …
       Шаг   1:  [S, S]  in:Left::cmd=0  Right::cmd=0  out:Left::val=1  Right::val=2
```

#### Что не делалось (границы объёма)

- Формат сценариев остался позиционным: драйв по голому имени по-прежнему
  рассылается всем ветвям. Это territory фичи, которая от этой зависит.
- Полный путь (`Root::Left::val`) не вводился: квалификатор — имя модели, как в
  карте адресов 0084.

|---|---|

| A2 квалифицированная запись — одна ветвь | ✅ |
| A3 неизвестный квалификатор | ✅ ничего не пишет, читает `None` |
| A4 голое имя как прежде | ✅ (существующие тесты и сверки зелёные) |
| A5 перечисление двусмысленных | ✅ |

## Тест-план

### Область и цель

Фича меняет **инструмент**, а не язык: синтаксис, семантика и порождаемый код не
затронуты. Поэтому правило 16 применяется в части «примеры и контрпримеры» к
адресации значений, а не к конструкциям языка.

Проверяется три вещи: различимость (квалифицированное имя работает),
совместимость (голое имя ведёт себя как прежде) и **видимость** двусмысленности
(предупреждение и вывод).

### Проверки (условие → ожидаемый результат)

| # | Условие | Ожидаемый результат |
|---|---|---|
| A1 | `unit.variable("Left::val")` и `"Right::val"` на модели `Left \| Right` с одноимёнными портами | `1` и `2` — обе ветви различимы |
| A2 | `unit.set_port("Left::cmd", 7)` | `Left::cmd = 7`, `Right::cmd = 0` (вторая ветвь не тронута) |
| A3 | `unit.set_port("Middle::cmd", 9)` (модели нет) | ни одна ветвь не изменилась; чтение `Middle::cmd` → `None` |
| A4 | `unit.variable("val")` (голое имя) | `1` — первая ветвь, как прежде |
| A5 | `PortNames::ambiguous` на модели с совпадением | `[("cmd", [Left::cmd, Right::cmd]), ("val", [Left::val, Right::val])]` |
| A6 | `PortNames::ambiguous` на модели с уникальными именами | пусто |

### Примеры и контрпримеры (правило 16)

**Модель-пример** (на ней держатся A1–A5, A7):

```takt
model Left  { in cmd: u8; out val: u8; start S { always { val := 1; } } }
model Right { in cmd: u8; out val: u8; start S { always { val := 2; } } }
start Root = Left | Right;
```

**Контрпример адресации** — `Middle::cmd`: квалификатор, которому не
соответствует ни одна модель. Ожидаемое поведение — **не адресовать ничего**;
запись «в первую попавшуюся ветвь» была бы худшим исходом, чем отказ, потому что
опечатка тихо меняла бы чужое значение.

**Контроль направления** — модель с уникальными именами (`Cabin | Motor`): она
обязана **не** порождать предупреждений. Без этого контроля предупреждение
превратилось бы в шум и его перестали бы читать.

### Выводы и дальнейшие шаги

**Открытые следствия (из ADR):**

1. **Голое имя остаётся двусмысленным** при совпадении: чтение — первая ветвь,
   запись — все. Это сознательный компромисс ради совместимости; теперь
   двусмысленность видна. Устранение — за фичей

   карте адресов 0084; синтаксиса пути в языке нет).
3. **Анонимная модель квалифицированно не адресуема** — у неё нет имени.

## Итог (что сделано)

- **Значения одноимённых портов различимы.** Узел дерева симуляции получил имя
  своей модели (`UnitKind::Node.model_name` из `ModelNode::name`), а
  `get_value`/`set_value` распознают форму **`Модель::порт`** и адресуют ровно
  одну ветвь. Разделитель `::` тот же, что у ключа карты адресов ([ключ карты адресов — голое имя порта](0084-address-map-qualified-key.md)): две подсистемы адресуют одно и то
  же, и разъехавшиеся формы записи стоили бы пользователю догадок.
- **Опечатка не пишет никуда:** неизвестный квалификатор не адресует ни одной
  ветви (запись «в первую попавшуюся» была бы хуже отказа).

  объявленные несколькими моделями; `takt-sim` печатает предупреждение при

  прежде; позиционные сценарии, снимки `--load-state` и все потактовые сверки не
  затронуты — двусмысленность живёт в отдельном поле, а не подмешана в
  существующие векторы имён.
