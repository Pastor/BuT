### Context

Примеры корпуса `examples/` объясняют свои конструкции комментариями: пример —
это не только вход проверок, но и **учебный текст**, который читают и по которому
пишут следующие примеры. Комментарий, объясняющий конструкцию **неверной**
причиной, хуже отсутствующего: следующий автор либо воспроизведёт причину в
новом примере, либо снимет конструкцию, поверив, что нужды в ней больше нет.

Четыре примера объясняют свой выходной порт `ready` нуждой цели `rust`:

```
// Выходной порт `ready` нужен и цели `rust` (модель без портов →
// clippy::new_without_default).
```

После фичи [цель `rust`: корневая модель без портов (`clippy::new_without_default`)](0174-rust-new-without-default.md) модель без
портов получает `impl Default` рядом с `new()`, и линт молчит — то есть порт по
названной причине больше не нужен. Объяснение устарело.

#### Что показала проба (замер кандидата перепроверен)

Карточка фичи требует перепроверки замера кандидата. Проба
2026-08-17, `taktc` из рабочего дерева:

| Пример | `impl Default` в выводе `-t rust` без порта | `clippy-driver -D warnings` |
|---|---|---|
| `regulator` | есть | принял |
| `float_regulator` | есть | принял |
| `pid_regulator` | есть | принял |
| `batch_cycle` | есть | принял |

Контр-проба (мутация вывода — блок `impl Default` вырезан вручную):
`error: you should consider adding a Default implementation for RegulatorNoport`.
То есть проба содержательна: линт на этом входе жив, и молчит он **именно
благодаря** 0174.

**Замер кандидата занижен: файлов четыре, а не три.** Кандидат (2026-07-29)
называет `regulator.takt`, `float_regulator.takt`, `pid_regulator.takt`;
`batch_cycle.takt` несёт то же объяснение в собственной формулировке
(«Выходной порт `ready` нужен ещё и цели `rust`: модель без портов даёт
`clippy::new_without_default`») и потому под греп кандидата не попал. История
объясняет, как так вышло: `batch_cycle` заведён фичей в коммите `92c3379c`
(2026-07-29 15:30), а 0174 закрыта коммитом `728100a2` того же дня в 15:51 —
четвёртая копия объяснения написана **по образцу трёх старших за двадцать минут
до того, как объяснение перестало быть верным**. Это тот же класс, что «четвёртая
копия `report` заведётся по образцу трёх» (0168): устаревшая формулировка в
корпусе воспроизводится, пока её не снимут.

#### Чем порт удерживается на самом деле

Порты снимать не предлагается — но, чтобы назвать причину, её надо знать.
Проверено чтением проверок и тестбенчей:

| Пример | Что держит порт `ready` сегодня |
|---|---|
| `regulator` | тестбенч SV (`saw_ready`, `$error` при отсутствии) **и** проверка `sv-mmio`: это единственный пример со всеми **выходными** портами  |
| `pid_regulator` | тестбенч SV (`saw_ready`) |
| `batch_cycle` | тестбенч SV (`saw_ready` + порядок фаз) |
| `float_regulator` | **ничем не удерживается**: в `SV_TRANSLATABLE` его нет (без `--float-as-q` цель `sv` отвечает `SV-003`, а `FLOAT_AS_Q_EXAMPLES` содержит только `pid_regulator`), тестбенча у него нет, контракт сценария проверяет цепочку состояний, а не порт |

### Decision Drivers

1. **Комментарий примера — учебный текст.** Неверная причина воспроизводится
   следующим примером (что и произошло с `batch_cycle` через двадцать минут
   после закрытия 0174).
2. **Причина обязана быть проверяемой.** Названная причина должна либо
   опираться на живой проверка, либо честно сообщать, что проверки нет, — иначе она
   устареет так же молча, как нынешняя.
3. **Ни одного порта не снимать.** У трёх примеров на `ready` смотрят
   тестбенчи SV; снятие уронило бы проверка.
4. **Цена правки нулевая для поведения.** Меняются только комментарии; вывод
   всех целей обязан остаться байт-в-байт прежним.

### Considered Options

#### Option A. Просто удалить устаревшую фразу

**Pros:**
- Минимальная правка; неверного утверждения в корпусе не остаётся.

**Cons:**
- Порт остаётся **без объяснения вовсе**, и следующий редактор вправе счесть
  его лишним — а у трёх примеров на нём висит тестбенч SV. Отсутствующая
  причина здесь опаснее устаревшей: она приглашает снять порт.

#### Option B. Заменить фактической причиной (по каждому примеру своей)

**Pros:**
- Комментарий снова объясняет то, что есть: у трёх примеров — тестбенч SV
  (у `regulator` дополнительно проверка `sv-mmio` фичи), у `float_regulator` —
  честное «проверкой не удерживается, стоит ради паритета с `regulator.takt`».
- Причина у трёх из четырёх **проверяется исполнением**: тестбенч завершается
  `$error`, если `ready` не поднялся, — устареть молча она не может.
- Правка захватывает **все четыре** файла, а не три названных кандидатом.

**Cons:**
- Причины разные, общей формулировки нет — текст в каждом файле свой.

#### Option C. Option B + греп-контроль «в корпусе нет `new_without_default`»

**Pros:**
- Формулировка не вернётся третьим заходом.

**Cons:**
- Контроль проверяет **отсутствие строки**, а не верность объяснений: класс
  («комментарий примера отстал от кода») он не покрывает и создаёт ложное
  чувство защиты. Замер: в корпусе это единственная строка такого рода, то есть
  контроль охраняет запись, которой после правки не будет ни одной.
- Пример, которому линт **действительно** понадобится упомянуть (скажем,
  разбор политики `-D warnings`), уронил бы проверка без вины.

### Decision

Принимается **Option B**. В каждом из **четырёх** файлов устаревшая фраза
заменяется фактической причиной существования порта `ready`; у
`float_regulator.takt` причина называется честно — проверкой порт не удерживается.
Порты и любой порождаемый код не трогаются.

Греп-контроль (Option C) отвергнут: он контролирует строку, а не свойство. Причина
верности комментария у трёх примеров и так исполняется проверкой SV — тестбенч
падает `$error`, если `ready` не поднялся; это лучший контроль, чем греп по тексту.

### Consequences

#### Положительные

- Корпус перестаёт обещать нужду, которой нет, и перестаёт быть образцом для
  пятой копии объяснения.
- Причина порта названа там, где её ищут, — рядом с портом.
- Снят кандидат блока 2 `FEATURES.md`.

#### Отрицательные / Action items

- Комментарий `float_regulator.takt` называет **отсутствие** проверки; если пример
  когда-нибудь войдёт в `FLOAT_AS_Q_EXAMPLES`/`SV_TRANSLATABLE`, запись
  придётся обновить. Это свойство честной формулировки, а не её дефект.
- Правка косметическая — **машинного** контроля у неё нет и не заводится
  (см. Option C). Актуальность комментариев корпуса остаётся на ревью.

#### Acceptance criteria

1. Строки `new_without_default` в `examples/` не остаётся ни одной
   (`grep -rn new_without_default examples/` пуст).
2. Каждый из четырёх примеров называет причину порта `ready`, соответствующую
   проверенной таблице «чем порт удерживается на самом деле».
3. Вывод всех целей по корпусу **не изменился**: `git status` по
   `examples/generated/` чист после прогона `precheck.sh`.
4. `./scripts/precheck.sh` зелёный (в том числе проверки `sv`, `sv-mmio`, `rust` и
   канон `taktc fmt` по `examples/`).

## Анализ

### Цель и контекст

Снять из комментариев корпуса объяснение выходного порта `ready` нуждой цели
`rust` (`clippy::new_without_default`): после фичи модель без портов
получает `impl Default`, и линт молчит. Вместо удаления — замена **фактической**
причиной (решение ADR, Option B): у трёх примеров порт держит тестбенч SV, у
одного не держит ничего, и это надо сказать прямо.

Правка затрагивает **только комментарии** примеров. Язык, компилятор, симулятор
и порождаемый код не меняются.

### Зависимости фичи

- **Зависит от:** нет. Фича, снявшая нужду, закрыта 2026-07-29 (коммит
  `728100a2`); фича, давшая `regulator` вторую роль в проверке `sv-mmio`, —
  закрыта. Иных контрактных связей нет: правка не касается кода.
- **Влияние на порядок разработки:** никого не разблокирует. Фича независима и
  может быть выполнена в любой момент; её место в очереди определяется только
  приоритетом (Tier 4 — «прочее»).

### Требования и проверяемые условия

- **R1. Устаревшего объяснения не остаётся.** Ни один файл `examples/` не
  ссылается на `clippy::new_without_default` как на причину существования порта.
- **R2. Правка охватывает четыре файла.** `regulator.takt`,
  `float_regulator.takt`, `pid_regulator.takt` — названы кандидатом;
  `batch_cycle.takt` несёт то же объяснение в своей формулировке и потому под
  греп кандидата не попал (замер ADR).
- **R3. Причина названа по факту.** Формулировка каждого файла соответствует
  таблице ADR: `regulator` — тестбенч SV + проверка `sv-mmio` (0214);
  `pid_regulator`, `batch_cycle` — тестбенч SV; `float_regulator` — проверкой не
  удерживается, стоит ради паритета с `regulator.takt`.
- **R4. Порты не снимаются.** Состав портов всех четырёх моделей прежний.
- **R5. Вывод целей не меняется.** Комментарий Takt в порождённый код не
  переносится, поэтому `examples/generated/` обязан остаться байт-в-байт
  прежним.
- **R6. Канон форматтера соблюдён.** `taktc fmt --check examples/` зелёный
  (комментарии печатает форматтер, привязка комментария к узлу — известное
  тонкое место).

### Риски и зависимости

- **Риск: комментарий снова устареет.** Формулировка `float_regulator.takt`
  прямо говорит, что проверка порт не держит; войди пример в `SV_TRANSLATABLE` или
  `FLOAT_AS_Q_EXAMPLES` — запись придётся обновить. Снижение: у трёх остальных
  причина проверяется **исполнением** тестбенча (`$error`, если `ready` не
  поднялся), то есть молча устареть не может. Машинного контроля на текст
  комментария не заводится (ADR, Option C отвергнут).
- **Риск: сдвиг комментариев ломает канон `fmt`.** Привязка комментария к узлу
  — известное тонкое место. Снижение: правка идёт в
  шапке файла и в комментариях уровня модели; проверка — `fmt --check` в
  предкоммите (A6).
- **Зависимостей от незакрытых фич нет.**

## Разработка

### Задача

#### Что было

Четыре примера корпуса объясняли свой выходной порт `ready` нуждой цели `rust`:
«модель без портов → `clippy::new_without_default`». После фичи модель без
портов получает `impl Default`, и линт молчит — объяснение перестало быть
верным. Кандидат, из которого заведена фича, называл **три** файла; четвёртый
(`batch_cycle.takt`) несёт то же объяснение своей формулировкой и под греп
кандидата не попал (замер ADR).

Порт при этом у трёх примеров реально удерживается тестбенчем цели `sv`, а у
`regulator` — ещё и проверкой `sv-mmio`: удалить фразу, не назвав
настоящую причину, значило бы пригласить следующего редактора снять порт.

#### Что сделано

Заменены комментарии в **четырёх** файлах `examples/` (правка только текстовая,
ни одного оператора Takt не тронуто):

| Файл | Новая формулировка причины |
|---|---|
| `regulator.takt` | наблюдаемая точка завершения: тестбенч `sv` (`$error`, если не поднялся) + единственный пример проверки `sv-mmio` со всеми выходными портами (0214) |
| `pid_regulator.takt` | наблюдаемая точка схождения контура: тестбенч `sv` |
| `batch_cycle.takt` | наблюдаемая точка завершения цикла: тестбенч `sv`, вместе с порядком фаз |
| `float_regulator.takt` | паритет с `regulator.takt`; проверкой порт **не** удерживается (в `sv` пример без `--float-as-q` не транслируется — `SV-003`) |

Обратная функциональность: затронуты **только комментарии**.
Компилятор, симулятор, генераторы, CLI и форматы файлов — «н/п»: код не
менялся, версия языка не поднимается (язык не изменён).

#### Проверки

```sh
grep -rn 'new_without_default' examples/          # пусто (код 1) — R1
```
