### Context

Модуль `takt-lang/src/generator/rust/rust_live.rs` решает, печатать ли
инициализатор локальной переменной: `let mut ds: u8 = 0;` перед `if/else`,
пишущим обе ветки, — это `unused_assignments`, то есть **отказ** проверки цели
(`clippy -D warnings`).

**Замер-20** (кандидат 2026-07-29 перепроверен, правило 30):
`cargo llvm-cov` даёт по модулю **39.84 %** регионов, **42.62 %** строк и
**16 из 33 функций, не исполняемых ни одним тестом**. Цифра кандидата
подтвердилась в точности.

**Прогон нашёл то, о чём кандидат предупреждал: два дефекта.** Обе формы
законны, обе дают вывод, который **не проходит проверка самого проекта**, при
нулевом коде возврата `taktc`:

1. **`match` с ветвью `_`.** Анализ живости для `match` не даёт вердикта
   никогда (`Verdict::Unknown`), а печатник разворачивает его в цепочку
   `if/else`. На входе `var t: u8 := 0; match a { 1 => { t := 5; } _ => { t :=
   7; } }` печатается `let mut t: u8 = 0;` — и `clippy -D warnings` отвечает
   «value assigned to `t` is never read».
2. **`for` с инициализатором.** `for i := 0; …` печатается как
   `{ i = 0; while … }`, а объявление `var i: u8 := 0;` выше сохраняет своё
   значение — та же ошибка на `i`.

Класс ровно тот, что дал исправления и 0148-02: **слепой печатник цели
`rust`**. Корпус его не ловит — ни один пример не пишет переменную из всех
ветвей `match`.

### Decision Drivers

1. **Покрытие само по себе не цель**: нужен контроль **поведения**,
   иначе повторится «покрыли процент, а не поведение» — прямое предупреждение
   карточки.
2. **Проверка цели — `clippy -D warnings`**, и он же есть у пользователя: вывод,
   который не собирается под этой политикой, — дефект, а не придирка.
3. **Ошибка анализа в сторону «мёртв» громкая** (ошибка компиляции), в сторону
   «жив» — тихая (лишний линт). Это позволяет расширять анализ без риска тихо
   неверного кода.

### Considered Options

#### Option A. Только тесты, дефекты — отдельной фичей

**Pros:** узкий объём.
**Cons:** контроль заводится **красным** (тесты обязаны отражать верное
поведение), а найденный дефект остаётся жить в цели, о которой известно, что
она уже дважды роняла сборку пользователя.

#### Option B. Тесты поведения + исправление обеих находок

Контроль печати (текст вывода + прогон настоящего `clippy -D warnings`) и
правка анализа: `match` с `_`-ветвью и `for` с присваивающим `init`
признаются заведомой перезаписью.

**Pros:** контроль зелёный и осмысленный; вывод собирается у пользователя.
**Cons:** правка `match` тянет за собой **свёртку**: отложенная форма
`let t: u8;` перед `if/else` — это `clippy::needless_late_init`, то есть
замена одного отказа другим (проверено пробой).

#### Option C. Заглушить линт атрибутом `#[allow(unused_assignments)]`

**Pros:** одна строка.
**Cons:** отвергнуто ещё в 0050-07: атрибут глушит линт на всей функции, и
настоящая ошибка эмиссии (генератор забыл записать переменную) прошла бы молча.

### Decision

Принимается **Option B**.

1. **Контроль поведения** `takt-lang/tests/targets/rust_live_tests.rs`: фикстуры
   на каждую форму (обе ветки пишут, безусловная запись, `if` без `else`,
   чтение до записи, цикл, `match` с `_`, `for` с `init`, две переменные на
   одном `if/else`, двойное присваивание на пути), проверка **текста** вывода и
   прогон настоящего `clippy -D warnings` — как в проверке.
2. **`match` признаётся перезаписью**, когда есть ветвь `_`, все ветви
   переписывают переменную, а разбираемое выражение и тела ветвей её раньше не
   читают.
3. **Свёртка `match`** — новый вариант `Folded::Chain`: печатается цепочкой
   `if s == p { v } else if s == q { v } else { v }`, тем же приёмом сравнения с
   образцом, что и обычная печать `match` (образцы Takt — выражения, поэтому
   `match` Rust здесь неприменим: он связал бы имя вместо сравнения).
4. **`for` признаётся перезаписью**, когда его `init` — присваивание этой
   переменной: `init` исполняется всегда и раньше условия, шага и тела.
   Свёртка не нужна — отложенную форму перед блоком `clippy` принимает
   (проверено пробой).

### Consequences

#### Положительные

- Два входа, ронявшие сборку пользователя, переводятся верно.
- Поведение печатника закреплено тестами **на текст и на линт**, а не на
  процент покрытия.
- Расширен разбор `match` и `for` — формы, до которых анализ не доходил вовсе.

#### Отрицательные / Action items

- `Folded` получает третий вариант; печать усложняется на цепочку сравнений.
- Анализ остаётся консервативным: `match` без `_`-ветви, `if` без `else`,
  цикл — по-прежнему «жив». Это осознанно: недоказанная перезапись обязана
  оставлять инициализатор.

#### Acceptance criteria

1. `match` с `_`, пишущий переменную во всех ветвях, даёт `let t: u8 = if … {}
   else {};` без мёртвого инициализатора.
2. `for` с присваивающим `init` не печатает мёртвый инициализатор.
3. Порождённый код всех фикстур принимается `clippy -D warnings`.
4. Прежние формы (контрпримеры) не изменились: `if` без `else`, цикл, чтение
   до записи оставляют инициализатор.
5. Покрытие модуля выросло **и это следствие, а не цель**.
6. `./scripts/precheck.sh` — код 0.

## Разработка

### Задача

#### Что сделано

`takt-lang/tests/targets/rust_live_tests.rs` — одиннадцать проверок на одной
фикстуре, где собраны **все** формы живости: обе ветки пишут, безусловная
запись, второе присваивание, `if` без `else`, цикл, чтение до записи,
исчерпывающий `match`, `match` без `_`, `for` с `init`, две переменные на одном
операторе.

Два слоя, и оба нужны:

1. **эмиссия** — проверка текста: `let ds: u8 = if …`, `let mut t: u8 = 0;`,
   `let x: u8;`. Ловит регресс точно и называет место;
2. **проверка** — тот же `clippy -D warnings`, что в `precheck.sh`, на всём выводе
   разом. Именно он и нашёл оба дефекта фичи: текст говорит, что напечатано, а
   линт — примет ли это пользователь.

**Контрпримеров четыре, и они обязательны:** без них правка читалась бы как
«затирает всё подряд», и консервативность анализа перестала бы контролироваться.

Мягкая деградация: нет `clippy-driver` → второй слой пропускается с
сообщением, первый работает всегда.

#### Проверка

```sh
cargo test --test targets rust_live_tests::
```

### Задача

#### Что исправлено

**1. `match` с ветвью `_`.** `verdict_of` не давал вердикта никогда, а
печатник разворачивает `match` в цепочку `if/else` — анализ и печать
разошлись, и на входе

```takt
var t: u8 := 0;
match a { 1 => { t := 5; } _ => { t := 7; } }
```

печаталось `let mut t: u8 = 0;` — мёртвое значение, то есть
`unused_assignments` и отказ `clippy -D warnings` при нулевом коде возврата
`taktc`.

Теперь `match` — заведомая перезапись, когда есть ветвь `_` и **каждая** ветвь
переписывает переменную, а разбираемое выражение и тела ветвей её раньше не
читают.

**2. Свёртка `match`.** Одного вердикта было мало: отложенная форма
`let t: u8;` перед `if/else` — это `clippy::needless_late_init`, то есть
замена одного отказа другим (проверено пробой на чистом Rust). Заведён третий
вариант `Folded::Chain`, печатаемый цепочкой сравнений:

```rust
let t: u8 = if a == 1 { 5 } else { 7 };
```

Именно **цепочка сравнений**, а не `match` языка Rust: образцы Takt —
произвольные выражения, и `match s { p => … }` связал бы `p` как новое имя
вместо сравнения (то же решение, что у печати оператора `match`).

**3. `for` с присваивающим `init`.** `init` исполняется всегда и раньше
условия, шага и тела — значит перезапись заведомая. Прежде вердикта не было, и
`var i: u8 := 0;` перед `for i := 0; …` печатался с мёртвым значением.
Свёртка здесь не нужна: `let mut i: u8;` перед блоком `{ i = 0; while … }`
линт принимает (проба).

**4. `max_path_assigns` учитывает `init`** цикла: присваивание в `init` даёт
единицу, а любое присваивание в теле или шаге — сразу два (тело исполняется
многократно). От этого зависит, нужен ли `mut`.

#### Границы

Анализ остаётся консервативным: `match` **без** `_`, `if` без `else` и цикл
перезаписи не доказывают — инициализатор печатается. Ошибка в сторону «мёртв»
даёт ошибку компиляции порождённого кода, то есть громкий отказ, а не тихо
неверный автомат.

#### Проверка

```sh
cargo test --test targets rust_live_tests::
cargo test --all-features
```

### Предмет проверки

Формы, в которые печатается локальное объявление, и приёмка вывода линтом.
Проверяется **поведение**, а не процент покрытия (ADR: порога нет
намеренно, и предупреждение карточки — «покрыли процент, а не поведение»).

### Условия проверок

| # | Условие | Как проверяется | Ожидаемый результат |
|---|---|---|---|
| П1 | Обе ветки пишут → свёртка в значение | `both_branches_fold_into_value` | `let ds: u8 = if a > b {`, без `mut` |
| П2 | Безусловная запись → свёртка | `unconditional_assign_folds_into_value` | `let t: u8 = a;` |
| П3 | Второе присваивание → `mut` | `second_assignment_requires_mut` | `let mut t: u8 = a;` |
| П4 | `match` с `_` → цепочка | `exhaustive_match_folds_into_chain` | `let t: u8 = if a == 1 { 5 } else { 7 };` |
| П5 | `for` с `init` → нет мёртвого значения | `for_init_kills_initializer` | `let mut i: u8;` |
| П6 | Две переменные на одном операторе | `two_variables_share_one_statement` | `let x: u8;` и `let y: u8;` |
| П7 | **Контрпример:** `if` без `else` | `if_without_else_keeps_initializer` | `let mut t: u8 = 0;` |
| П8 | **Контрпример:** цикл | `loop_keeps_initializer` | значение живо |
| П9 | **Контрпример:** чтение до записи | `read_before_assign_keeps_initializer` | значение живо |
| П10 | **Контрпример:** `match` без `_` | `open_match_keeps_initializer` | значение живо |
| П11 | Вывод принимается линтом | `generated_module_passes_clippy_gate` | `clippy -D warnings` — код 0 |
| П12 | Регрессия | `cargo test --all-features` | все наборы зелёные |
| П13 | Корпус и проверка цели | `./scripts/precheck.sh` | код 0 |

### Примеры и контрпримеры (правило 16)

**Пример** (исправленный фичей):

```takt
fn matched(a: u8) -> u8 {
    var t: u8 := 0;
    match a { 1 => { t := 5; } _ => { t := 7; } }
    return t;
}
```

Прежде: `let mut t: u8 = 0;` → `error: value assigned to t is never read`.
Теперь: `let t: u8 = if a == 1 { 5 } else { 7 };`.

**Контрпример** (перезапись не доказана — значение обязано остаться):

```takt
fn matched_open(a: u8) -> u8 {
    var t: u8 := 0;
    match a { 1 => { t := 5; } 2 => { t := 6; } }
    return t;
}
```

Без контрпримера правка читалась бы как «любой `match` затирает»: путь мимо
всех образцов оставил бы переменную неинициализированной.

### Мутационные проверки

- **М1.** Убрать требование ветви `_` в разборе `match` → П10 обязана
  провалиться.
- **М2.** Вернуть `Verdict::Unknown` для `for` → П5 и П11 обязаны провалиться.
- **М3.** Печатать свёртку `match` отложенной формой (`let t: u8;`) → П11
  обязана провалиться (`needless_late_init`).

### Что нашёл прогон

**Два дефекта цели `rust`**, оба — законный вход, невалидный по политике
линтов вывод, нулевой код возврата `taktc`:

1. **`match` с ветвью `_`** печатал мёртвое начальное значение
   (`unused_assignments`). Причина: анализ живости для `match` не давал
   вердикта никогда, а печатник разворачивает его в цепочку `if/else` — анализ
   и печать разошлись.
2. **`for` с присваивающим `init`** — то же самое на счётчике цикла.

Оба исправлены. Класс ровно тот, что дал исправления и
0148-02, и карточка предупреждала о нём прямо.

**Контроль «замена одного отказа другим».** Признать перезапись было мало:
отложенная форма `let t: u8;` перед `if/else` — это
`clippy::needless_late_init`. Проверено пробой на чистом Rust **до** правки;
поэтому `match` сворачивается в выражение, а `for` — нет (там та же проба
показала, что отложенная форма принимается).

**Мутационные проверки** (все три прогнаны, каждая обязана валить контроля):
