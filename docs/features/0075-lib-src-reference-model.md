# Фича: Эталонный `SRC` в `lib.rs` порождает C с 11 ошибками `cc`

- **Статус:** ГОТОВО (2026-07-20; `precheck.sh` зелёный)
- **Зависит от:** нет; полный ремонт генератора C упирается в [семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md) (семантика `[bit;N]`) — 0075 её обходит разделением эталона

## Краткое описание

Модель-«всё сразу», на которой стоит тест `syntax_simple`, **никогда** не давала
компилируемый C, и это не замечалось: тест проверял лишь факт `Ok`.

Причины **не связаны** с состояниями: в порождённой структуре нет порт-колбэков
`read_numeric`/`write_numeric`, а `const`-массив `MATRIX: u8 := {0,…}` печатается
как **скаляр** (`CONST_..._MATRIX`), давая `expected ')'`. Проверено: строка
перевода `S(Ping) = End` ошибок **не даёт** (ошибки — на соседних строках,
обращения к портам).

Следствие: `syntax_simple` вынужден проверять **строку** в `.c`, а не компиляцию.

Смежно с [структурные типы в симуляторе](0034-sim-struct-types.md) (структуры) и с фичей
[тело `always` на уровне модели не эмитится в C](0083-model-always-block-c.md) (`always` на уровне модели).

Выявлено при [трансляция `S(Модель) = Состояние` в цель `c`](0047-c-state-of-model.md).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-20
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0075-lib-src-reference-model.md); выявлено при [трансляция `S(Модель) = Состояние` в цель `c`](0047-c-state-of-model.md); дефекты генератора упираются в [семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md)

### Context

Тест `lib.rs::syntax_simple` стоял на модели-«всё сразу» (`SRC`), которая
**никогда** не давала компилируемый C. Проба `cc -fsyntax-only` (2026-07-20) даёт
**11 ошибок** двух классов:

1. **`no member named 'read_numeric' in 'struct …'`** — `out`-порт `A` типа `u8`
   (`= [bit;8]`) с бит-доступом (`A.0 := true`) транслируется в read-modify-write
   через `read_numeric`, но для `out`-порта структура эмитит только
   `write_numeric`.
2. **`{…} >> 5` (expected ';')** — `const MATRIX: u8 := {0,…}` печатается макросом-
   массивом (`#define CONST_…_MATRIX {0,…}`), а бит-доступ `MATRIX.5` трактует его
   **числом** (`(MATRIX >> 5) & 1`). Массив сдвигать нельзя.

Оба класса упираются в **семантику `[bit;N]`**: в `SRC` тип `u8 = [bit;8]`
используется и как **число** (порт `A`, `NUMB := 0xFF`), и как **массив**
(`MATRIX := {0,…}`). Это ровно то, что «расходится втрое» в
[фиче](0078-bit-array-semantics.md). Строка `S(Ping) = End`
ошибок **не даёт** — ошибки на соседних строках.

Следствие: `syntax_simple` был вынужден проверять **строку** в `.c`, а не
компиляцию — то есть слабее, чем должен.

### Decision Drivers

1. **Цель фичи — компиляционная проверка** вместо строковой (то, чего тест не
   мог, пока эталон не компилировался).
2. **Не втягивать 0078.** Полный ремонт генератора для numeric-порт-бит-доступа и
   const-массив-бит-доступа — это семантика `[bit;N]`, отдельная крупная фича.
3. **Сохранить покрытие парсера.** `SRC` разбирает **все** конструкции языка —
   `parse_simple` этого лишаться не должен.
4. **Сохранить контроль `S(Ping) = End`** — межмодельная ссылка (инвариант
   `ref`-условий).

### Considered Options

#### Option A (принято). Разделить эталон

`parse_simple` остаётся на полном `SRC` (покрытие **парсера**). Компиляционная
проверка переезжает на **отдельную** компилируемую модель `SYNTH_SRC`
(`tests/reference_model_tests.rs`), очищенную от конструкций, упирающихся в 0078
(numeric-порт-бит-доступ, const-массив-бит-доступ), но сохраняющую композицию
`(Ping | Pong) + Toggle` и `S(Ping) = End`; тест компилирует вывод настоящим `cc`.

**Pros:**
- Цель достигнута (драйвер 1): проверяется **компиляция**, а не строка.
- 0078 не втянута (драйвер 2): дефекты генератора остаются кандидатами.
- Покрытие парсера сохранено (драйвер 3); контроль `S(Ping)=End` сохранён (драйвер 4).

**Cons:**
- Два эталона вместо одного. Смягчение: у них **разные роли** (разбор vs.
  компиляция) — это не дублирование, а разделение ответственности.

#### Option B. Починить генератор C (read_numeric + const `[bit;N]`)

**Cons:** упирается в семантику `[bit;N]` (0078) — «число или массив?». Решать её
здесь значит проглотить крупную фичу под видом мелкого исправления; цена ошибки
(неверная семантика типа) высока.

#### Option C. Оставить строковую проверку

**Cons:** статус-кво; тест слабее, чем должен (не ловит несобираемость).

### Decision

Принимается **Option A** (решение заказчика: «переопределить эталон за проход»).

**Нормативные правила:**

1. **`parse_simple`** остаётся на полном `SRC` — покрытие парсера; компилируемость
   он **не** утверждает.
2. **Компиляционный тест** — на `SYNTH_SRC` (`tests/reference_model_tests.rs`):
   `compile_to_c` + `cc -c` (скип без `cc`) + строка `S(Ping) = End`.
3. **`SYNTH_SRC` не содержит** numeric-порт-бит-доступа и const-массив-бит-доступа
   (упираются в 0078); сохраняет композицию и межмодельную ссылку.
4. **Дефекты генератора** (`read_numeric` для `out`-порта; const `[bit;N]`
   бит-доступ) остаются **кандидатами** — первый локален (`c_header`), второй за
   0078.
5. Язык **не меняется** → версия не растёт (правило 22).

### Consequences

#### Положительные

- Компиляционная проверка эталона — впервые настоящая (`cc`).
- Инвариант `ref` (`S(Ping)=End`) охраняется тем же тестом.

#### Отрицательные / Action items

- **A-1. `SRC` по-прежнему не компилируется** — это осознанно: он живёт для
  разбора. Дефекты его C — кандидаты (см. правило 4).
- **A-2. Дефект `read_numeric`** (`out`-порт с бит-доступом) локален и чинибелен
  вне 0078 — кандидат на отдельный исправление/0080.
- **A-3. Дефект const `[bit;N]`** — за 0078.

#### Acceptance criteria

1. **A1.** `SYNTH_SRC` порождает C, компилируемый `cc -c`.
2. **A2.** Вывод содержит перевод `S(Ping) = End` сравнением состояния.
3. **A3.** `parse_simple` (полный `SRC`) — по-прежнему разбирается.
4. **A4.** `precheck.sh` зелёный; язык и версия не изменились.

## Разработка

### Задача

#### Что было

`lib.rs::syntax_simple` стоял на модели-«всё сразу» (`SRC`), которая не
компилируется целью `c` (11 ошибок `cc`: `read_numeric` для `out`-порта с
бит-доступом; const `[bit;8]` печатается массивом, бит-доступ — числом). Тест мог
проверять лишь **строку** в `.c`.

#### Что сделано

1. **`tests/reference_model_tests.rs`** — новый интеграционный тест
   `reference_model_compiles_and_translates_state_ref`: `SYNTH_SRC` →
   `compile_to_c` → **`cc -c`** (скип без `cc`) + строка `S(Ping) = End`.
2. **`SYNTH_SRC`** — компилируемая модель: композиция `(Ping | Pong) + Toggle`,
   `S(Ping) = End`, `ref`/`next` по условию/состоянию/`cond`. Без
   numeric-порт-бит-доступа и const-массив-бит-доступа (упираются в 0078).
3. **`syntax_simple` удалён** из `lib.rs`: он стоял на некомпилируемом `SRC`;
   инвариант `ref` теперь охраняет компиляционный тест. `lib.rs` уменьшен (1450 →
   1405, `module-size-baseline.txt` обновлён вниз).
4. **`parse_simple`** остаётся на полном `SRC` (покрытие парсера).

#### Проверки

- **T1/A1:** `SYNTH_SRC` → `cc -c` rc=0.
- **T2/A2:** вывод содержит `S(Ping) = End` сравнением состояния.
- **T4/A3:** `parse_simple` разбирает полный `SRC`.
- **T5/A4:** `precheck.sh` зелёный.

### Замер (11 ошибок исходного `SRC`)

`cc -fsyntax-only` на выводе полного `SRC`:
- `no member named 'read_numeric'` — `out`-порт `A: u8` с бит-доступом
  (`A.0 := true`) зовёт `read_numeric` (RMW), а структура эмитит только
  `write_numeric` → **локальный баг генератора** (кандидат, вне 0078).
- `{…} >> 5` — `const MATRIX: u8 := {0,…}` печатается макросом-массивом, бит-доступ
  `MATRIX.5` трактует числом → **семантика `[bit;N]`** (0078).

Строка `S(Ping) = End` ошибок не даёт — подтверждено грепом позиций.

### Решение

Эталон **разделён** (Option A): `parse_simple` — покрытие парсера на полном
`SRC`; компиляционная проверка — на `SYNTH_SRC` (`cc -c`), сохранившей композицию
и `S(Ping) = End`. `syntax_simple` удалён из `lib.rs` (стоял на некомпилируемом
`SRC`); `lib.rs` уменьшен 1450 → 1405.

### Кандидаты (вне объёма)

- **A-2:** `read_numeric` для `out`-порта с бит-доступом — локальный исправление/0080.
- **A-3:** const `[bit;N]` бит-доступ — за 0078.
