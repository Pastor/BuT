# Фича: Распакованный массив у цели sv — сброс и переменный индекс

- **Номер:** 0365
- **Статус:** ГОТОВО
- **Зависит от:** нет (0076, 0078, 0309, 0359, 0364 закрыты)
- **Связанные issue (анализ):** два кандидата, заведённые закрытием
  [вложенный массив у цели c](0364-c-nested-array.md)

## Краткое описание

Замер-21 (`scripts/probe.sh` с разделом инструментов) — два
входа, и на обоих вывод цели `sv` **не проходит проверка собственной цели** при
нулевом коде возврата `taktc`:

| Вход | Ответ verilator | Прочие потребители |
|---|---|---|
| `var row: [u8; 2];` (без инициализатора) | **Ошибка** «CONST '8'h0' is not an unpacked array, but is in an unpacked array context» — печаталось `row <= '0;` | эталон, `c`, `st`, `rust` исполняют |
| `s := row[i];` при `i: u8` | `%Warning-WIDTHTRUNC: Bit extraction of array[1:0] requires 1 bit index, not 8 bits` (проверка считает предупреждение ошибкой) | то же |

Оба класса воспроизводятся и на **одномерном** массиве — к вложенности
(0363/0364) отношения не имеют, хотя нашлись при её проверке.

**Не требуется** — язык не меняется: обе записи законны и исполняются
эталоном; меняется представление у одной цели.

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича](0365-sv-unpacked-array.md); связь с

### Context

Массив скаляров цель печатает **распакованным** (`logic [7:0] a [0:1]`) с фичи, а его агрегатный инициализатор — с 0309. Две операции остались с формами
упакованного значения:

- **сброс без инициализатора** печатался `a <= '0;`;
- **переменный индекс** печатался полной шириной операнда.

Обе формы проверка цели отвергает, и обе воспроизводятся на одномерном массиве.
Корпус класс не покрывает: в `examples/` массивы объявлены с инициализатором и
индексируются переменной, ширина которой совпадает с требуемой.

### Decision Drivers

1. **Вывод обязан проходить проверка собственной цели.** Иначе `taktc` рапортует
   об успехе, а сборка у пользователя падает.
2. **Форму выбирают оба инструмента SV**: `verilator` и
   `yosys` расходятся, и годна лишь форма, принятая обоими.
3. **Правило сильнее.** `[bit;N≤64]` — упакованный скаляр: у него сброс
   `'0` и индексация разряда законны, и трогать их нельзя.
4. **Приведение печатается по нужде**: лишнее сужение там, где
   предупреждения нет, — шум в выводе.

### Considered Options

#### Option A. Сброс — `'{default: '0}`

**Pros:**
- Каноничная форма SystemVerilog, не зависящая от числа элементов.

**Cons:**
- **`yosys` её не принимает вовсе** — «syntax error, unexpected TOK_DEFAULT»
  (проба 2026-08-21). Форма, принятая одним инструментом, не годна.

#### Option B. Сброс — агрегат нулей (`'{8'd0, 8'd0}`), индекс — сужение `W'(i)`

**Pros:**
- Агрегат — **та же** форма, которой печатается инициализатор (0309): оба
  инструмента её принимают (проверено прогоном).
- Сужение индекса снимает `WIDTHTRUNC` и печатается только когда ширина
  операнда заведомо больше требуемой.

**Cons:**
- Длина вывода растёт с числом элементов (агрегат перечисляет нули).
- Сужение меняет поведение на **невалидном** входе: индекс за границей
  массива усекается, вместо `X`. Эталон такой вход не исполняет (`SIM-010`),
  то есть случай за контрактом.

#### Option C. Отказ цели на массиве без инициализатора

**Pros:**
- Громче молчания.

**Cons:**
- Вход исполняют четыре потребителя; отказ сузил бы цель без нужды.

### Decision

Принимается **Option B**. Оба правила живут в новом модуле
`generator/sv/sv_array.rs`:

- `reset_literal(ty)` — агрегат нулей для распакованного массива, рекурсивный
  для вложенного; `None` для бит-вектора и не-массива (там прежний путь);
- `index_text(base_ty, index_ty, printed)` — сужение `W'(…)`, где `W` —
  `ceil(log2(size))` (минимум 1); печатается **по нужде**.

Печатников индексации у цели **три**: выражения, условия и **цель записи**.
Правка двух оставляла `WIDTHTRUNC` на записи, и сверка значений этого не
видела — тестбенч собирается с `-Wno-fatal`.

### Consequences

#### Положительные

- Порождённый модуль проходит `verilator --lint-only -Wall` — те же флаги, что
  у проверки цели.
- Массив без инициализатора получает нули **явно**, как и у остальных целей
  (0353 у `c`, правила IEC у `st`).

#### Отрицательные / Action items

- Индекс за границей массива усекается (прежде — `X`). Вход за контрактом:
  эталон отвечает `SIM-010`.
- Агрегат нулей длиннее `'0`; на больших массивах вывод растёт.

#### Acceptance criteria

1. `verilator --lint-only -Wall` и `yosys synth` принимают вывод на входах:
   массив без инициализатора, переменный индекс (чтение и запись), вложенный
   массив.
2. Потактовая сверка значений совпадает; фикстура читает **нетронутый**
   элемент (проверка сброса) и пишет по переменному индексу.
3. Мутации (вернуть `'0`, снять сужение при чтении, снять при записи) роняют
   тесты.
4. Предкоммит зелёный; вывод корпуса не изменился.

## Анализ

### Цель и контекст

Привести цель `sv` к остальным потребителям на двух записях: массив без
инициализатора и переменный индекс. Замер — в карточке; оба класса
воспроизводятся на одномерном массиве, то есть к вложенности отношения не
имеют.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. 0076 (массивы), 0078 (бит-вектор), 0309 (агрегат
  массива), 0359 (носитель типа операнда), 0364 (вложенный массив) закрыты.
- **Влияние на порядок разработки:** снимает двух кандидатов, заведённых 0364.

### Требования и проверяемые условия

- **R1. Сброс распакованного массива — агрегат нулей.** Форма выбрана прогоном
  **обоих** инструментов; `'{default: '0}` отвергнута yosys.
- **R2. Бит-вектор не затронут.** `[bit;N≤64]` — упакованный скаляр (0078):
  сброс `'0`, индексация разряда.
- **R3. Индекс сужается до `ceil(log2(size))`.** Печатается по нужде: индекс,
  чья ширина уже не больше требуемой, остаётся как есть.
- **R4. Печатников индексации три.** Выражения, условия и **цель записи**.
- **R5. Вложенный массив — рекурсия.** Сброс `'{'{…}, '{…}}`, индекс сужается
  на каждом уровне (тип базы берётся спуском по цепочке).
- **R6. Значения совпадают с эталоном.** Фикстура читает нетронутый элемент
  (сброс) и пишет по переменному индексу.
- **R7. Линт цели — отдельный контроль.** Сверка значений собирает тестбенч с
  `-Wno-fatal` и `WIDTHTRUNC` не видит.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | verilator и yosys принимают вывод | `scripts/probe.sh` (раздел инструментов) |
| A2 | Трасса цели совпадает с эталоном | `conformance_sv_array_tests::unpacked_array_reset_and_variable_index_match_generated_sv` |
| A3 | Модуль проходит линт цели | `unpacked_array_passes_target_lint` |
| A4 | Мутации ловятся | три мутации носителя и печатника записи |
| A5 | Вывод корпуса не изменился | проверка детерминизма и снапшоты предкоммита |

### Особенности по обратной функциональности

- **Язык не меняется**; правило 29 (редакторский слой) — не применимо.
- **Изменение поведения на невалидном входе названо:** индекс за границей
  усекается вместо `X`; эталон такой вход не исполняет (`SIM-010`).
- **Вывод корпуса не меняется:** в `examples/` массивы объявлены с
  инициализатором, а индекс — переменная нужной ширины.

### Риски и зависимости

- **Три печатника индексации.** Согласованность держит тест линта: сверка
  значений `WIDTHTRUNC` не видит (доказано мутацией).
- **Ширина индекса считается по размеру массива**, а не по типу переменной:
  второе знание о раскладке разъехалось бы с объявлением.

## Разработка

### Задача

#### Что было

Сброс массива без инициализатора печатался `a <= '0;` (verilator: «CONST is
not an unpacked array»), переменный индекс — полной шириной операнда
(`WIDTHTRUNC`, который проверка цели считает ошибкой). Обе формы принадлежат
**упакованному** значению, а массив скаляров у цели распакован.

#### Что сделано

**`takt-lang/src/generator/sv/sv_array.rs`** (новый модуль) — два носителя:

- `reset_literal(ty)` — агрегат нулей (`'{8'd0, 8'd0}`), рекурсивный для
  вложенного массива; `None` для бит-вектора  и не-массива;
- `index_text(base_ty, index_ty, printed)` — сужение `W'(…)`, где `W` —
  ширина, которую требует размер (`ceil(log2(size))`, минимум 1); печатается
  **по нужде**;
- `array_type_expr` / `array_type_cond` — тип базы индексации со спуском по
  цепочке: у вложенной индексации база сама является индексацией.

**`sv_const.rs`** — ветвь `ExpressionNode::None` спрашивает носитель.
**`sv_expr.rs`** — оба печатника индексации (выражения и условия).
**`sv_stmt.rs`** — печать **цели записи**.

**`takt-sim/tests/data/eval/conformance_sv_array_index.takt`** +
два теста в `conformance_sv_array_tests.rs`: потактовая сверка значений и
прогон **линта цели**.

**Форму сброса выбрал прогон, а не стандарт.** Каноничная `'{default: '0}`
принимается verilator и **отвергается yosys** («syntax error, unexpected
TOK_DEFAULT»); годной оказалась та же форма, которой печатается инициализатор
(0309).

**Печатников индексации оказалось три.** После правки чтения линт всё ещё
отвергал модуль — на строке записи `slots[idx] := …`, которую печатает
`print_assign_target`. Сверка значений этого не показывала: тестбенч
собирается с `-Wno-fatal`.

#### Проверки

```sh
cargo test --test conformance unpacked_array   # сверка значений + линт цели
cargo test --test conformance                  # 162 теста
cargo test --test targets                      # 391 тест
for f in examples/*.takt; do scripts/probe.sh -n 1 "$f"; done   # корпус чист
./scripts/precheck.sh
```

Мутации (все три пойманы): вернуть `'0` в сброс; снять сужение индекса; снять
сужение только в цели записи.

- **Форму сброса выбрал прогон обоих инструментов.** Каноничная

- Исправлений (`docs/fixes/`) не потребовалось.

## Итог (что сделано)

- Сброс распакованного массива печатается **агрегатом нулей** (`'{8'd0, 8'd0}`),
  переменный индекс **сужается** до ширины, которую требует размер
  (`row[1'(i)]`), — и то, и другое по нужде и рекурсивно для вложенного
  массива.
- **Форму выбрал прогон обоих инструментов:** каноничная `'{default: '0}`
  принимается verilator и **отвергается yosys**.
- **Печатников индексации оказалось три** (выражения, условия, цель
  записи); третий нашёлся прогоном **линта цели** — сверка значений его не
  видит, потому что тестбенч собирается с `-Wno-fatal`. Отсюда два контроля.
- Бит-вектор `[bit;N≤64]` не затронут; индекс за границей
  массива теперь усекается вместо `X` — вход за контрактом (`SIM-010`).
- Вывод корпуса не изменился; оба кандидата, заведённые 0364, сняты.

Детали — в [отчёте](0365-sv-unpacked-array.md#отчёт-о-тестировании).
