# Фича: Предупреждение taktc compile несёт позицию

- **Номер:** 0228
- **Статус:** ГОТОВО
- **Зависит от:** нет незакрытых (опирается на механизмы закрытых [позиции в диагностиках (`файл:строка:колонка`) и настоящий `file_no`](0053-diagnostics-file-id.md), [`lamc` не печатает предупреждения вообще](0081-lamc-print-warnings.md), [накопление семантических диагностик (несколько ошибок за прогон)](0130-diagnostics-batch.md))

## Краткое описание

`taktc compile` печатал предупреждения **без координат** — `Предупреждение
[SE-036]: …`, — тогда как ошибка того же прогона несёт `путь:строка:колонка:`.
Координата у предупреждения была; терялась она на печати: путь ей никто не ставил,
а без пути `position_prefix` отдаёт пустую строку. У целей `c-hal`/`st-at`/`sv-mmio`
формат печати был вообще отдельной копией. Фича сводит печать в одну точку и
разрешает путь **реестром файлов**, поэтому предупреждение импортированного файла
называет его собственный путь.

> Фича зарегистрирована из бэклога кандидатов (взята заказчиком 2026-08-05);
> далее проходит жизненный цикл по своду.

## Документирование

**Не требуется.** Язык не меняется, новых диагностик нет — исправляется печать
существующих. Документ при этом правки **не требует по особой причине**: раздел
[«Диагностики»](../../book/src/16-diagnostics/index.typ) и вводная часть приложения
об ошибках уже объявляют формат единым («Сообщение строится единообразно:
`путь:строка:колонка: <вид> [<код>]: <текст>`»). Для предупреждений `compile` это
было **неверно**; фича делает обещание документа верным.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-05
- **Authors:** Архитектор + Заказчик (решение — 2026-08-05)
- **Related issues:** [Фича](0228-compile-warning-position.md); источник — кандидат, найденный при закрытии [канон именования — предупреждение в fmt и LSP](0226-naming-convention-warning.md) ([канон именования — предупреждение в fmt и LSP](0226-naming-convention-warning.md#разработка)); смежные — [ADR](0053-diagnostics-file-id.md#архитектура-adr) (позиция несёт путь файла), фича [`lamc` не печатает предупреждения вообще](0081-lamc-print-warnings.md) (единая точка предупреждений), задача (формат диагностики расходился по целям)

### Context

`taktc compile` печатал предупреждения **без координат**:

```text
Предупреждение [SE-036]: переменная 'BadVar' объявлена, но нигде не используется
```

— тогда как ошибка того же прогона выглядит как
`probe.takt:2:17: Ошибка компиляции [SE-034]: …`.

Координата у предупреждения **есть** (`var.loc()`); терялась она на печати:
`format_warning` зовёт `position_prefix`, а тот без **пути к файлу** возвращает
пустую строку (ADR: путь — часть позиции, потому что колонка и строка
считаются по тексту файла). Путь ошибкам ставит библиотека через реестр файлов
(`pipeline::stamp_file`), а предупреждениям — **никто**.

#### Что определяет форму решения

**Два потребителя одного `format_warning` расходились не форматом, а полнотой
входа.** `taktc fmt` путь ставит (`report_style_warnings`) и потому
печатает `probe.takt:2:9: Предупреждение [CS-001]: …`; `compile` не ставит — и
печатает то же предупреждение без позиции. Один код, два разных сообщения.

**У целей `c-hal`/`st-at`/`sv-mmio` формат был вообще отдельной копией.**
`report_hal_result` печатал `eprintln!("Предупреждение [{}]: {}", …)` — литералом,
минуя `format_warning`. То есть даже правка общей точки эти цели не задела бы:
ровно тот класс, который проект правил в задаче (печать расходилась по
целям генерации).

**Штамповать именем входного файла нельзя.** У диагностики импортированного файла
смещения принадлежат **чужому** тексту: подстановка пути импортёра дала бы верный
код с координатами, указывающими не туда. Путь обязан разрешаться **реестром
файлов** (`FileTable::path_of`), как это делают ошибки.

**Реестра в этой ветви не было.** Предупреждения собираются по модели, которую
`compile_cli` строит вызовом `construct_model` — а тот заводит реестр-однодневку
(`FileTable::default()`) и наружу его не отдаёт.

### Decision Drivers

1. **Диагностика без координат бесполезна в пачке.** Правило живого контекста:
   «заводя диагностику, ставь позицию» — но поставленная позиция обязана ещё и
   доехать до печати.
2. **Формат — свойство диагностики, а не печатающего**. Копия формата
   в отдельной цели есть доказанный источник расхождения.
3. **Координата обязана указывать туда, где причина.** Верный код с неверной
   строкой хуже отсутствия строки: он посылает читателя не туда.
4. **Объём узкий.** Заказчик назвал `compile`; поведение `fmt`, LSP и симулятора
   не трогается.

### Considered Options

#### Option A. Реестр файлов в ветви предупреждений + единая точка печати

`compile_cli` строит модель через `construct_model_with_files`, получая реестр, и
печатает предупреждения одной функцией `print_warnings`, которая разрешает
`file_no` в путь через `path_of`. `report_hal_result` переводится на неё же.

**Pros:**
- Координаты верны и для импортированных файлов.
- Копия формата у HAL-целей исчезает.
- Правка локальна: одна функция, две точки вызова.

**Cons:**
- Ветвь HAL-целей получает реестр **только с корневым файлом**: цель строит своё
  дерево внутри и таблицу наружу не отдаёт, поэтому предупреждение
  импортированного файла останется без префикса (как прежде — но не соврёт).

#### Option B. Штамповать путь входного файла всем предупреждениям

**Pros:** одна строка правки, префикс появляется у всех.

**Cons:**
- Предупреждение импортированного файла получило бы **неверные** координаты:
  строка и колонка считаются по тексту, а текст был бы взят чужой. Это не
  улучшение, а новый дефект — молчаливо неверная позиция.

#### Option C. Ставить путь внутри библиотеки, при создании диагностики

**Pros:** печатающему думать не о чем; путь приходит вместе с диагностикой.

**Cons:**
- Библиотека путей не знает: `collect_model_warnings` работает по дереву, а имя
  файла — свойство вызова CLI. Пришлось бы протаскивать реестр во все
  производители предупреждений (семантика, слой адресов, длительности) — правка
  на порядок шире объёма.
- Дублировало бы механизм, который для ошибок уже решён на границе
  (`pipeline::stamp_file`).

### Decision

Принимается **Option A**.

Печать предупреждений `compile` идёт **одной** функцией `print_warnings(warnings,
files, quiet)`; путь разрешается `FileTable::path_of`, то есть по номеру файла
диагностики. Модель для сбора предупреждений строится
`construct_model_with_files` — тем же способом, каким её строит `pipeline`, — и
реестр остаётся у вызывающего.

`report_hal_result` печатает через ту же функцию; литеральная копия формата
удалена.

**Ограничение названо явно:** в ветви HAL-целей реестр содержит только корневой
файл, поэтому предупреждение импортированного файла остаётся без префикса.
Расширять это — значит менять сигнатуры `compile_to_c_hal`/`st_at`/`sv_mmio`,
чего фича не делает.

**Объём — `taktc compile`.** `taktc fmt` (0226) и `takt-sim` путь ставят сами;
LSP работает не через печать.

### Consequences

#### Положительные

- Предупреждение указывает на строку и колонку — как ошибка.
- Предупреждение импортированного файла называет **его** путь, а не путь
  импортёра.
- Формат печати предупреждений — в одной точке на все цели.

#### Отрицательные / Action items

- Наблюдаемый вывод `compile` меняется на всём корпусе (в stderr добавляется
  префикс). Порождённые файлы не задеты, снапшоты не двигаются.
- Ограничение HAL-ветви остаётся; при нужде закрывается отдельной фичей.

#### Acceptance criteria

1. Предупреждение своего файла печатается как `путь:строка:колонка: Предупреждение [код]: текст`.
2. То же — на цели `c-hal` (бывшая копия формата).
3. Предупреждение импортированного файла называет путь **библиотеки**.
4. Форма префикса совпадает с формой префикса ошибки.
5. `--quiet` глушит предупреждения, включая ветвь HAL-целей.
6. `./scripts/precheck.sh` — код возврата 0.

## Анализ

### Цель и контекст

Предупреждение `taktc compile` печаталось без координат, хотя они у него есть;
ошибка того же прогона координаты несёт. Причина и выбор решения — в
[ADR](0228-compile-warning-position.md#архитектура-adr); анализ фиксирует условия и
границы.

**Язык фича не меняет.** Ни лексики, ни синтаксиса, ни семантики, ни набора
диагностик: меняется **печать** существующих предупреждений. Версия языка
остаётся `0.8.0`.

**Замер до правки (2026-08-05), прогоном инструмента:**

| Вход | Что печаталось |
|---|---|
| `var BadVar: u8 := 1;` (не используется), цель `c` | `Предупреждение [SE-036]: переменная 'BadVar' …` — без позиции |
| однобитный порт без позиции бита, цель `c-hal` | `Предупреждение [SE-090]: порт 'lamp' …` — без позиции, **и через свою копию формата** |
| та же модель с семантической ошибкой | `probe.takt:2:17: Ошибка компиляции [SE-034]: …` — позиция есть |
| то же имя вне канона, `taktc fmt` | `probe.takt:2:9: Предупреждение [CS-001]: …` — позиция есть |

То есть расхождение было **между потребителями одной функции печати**: `fmt`
ставил путь, `compile` — нет.

### Зависимости фичи

- **Зависит от:** нет незакрытых. Опирается на механизмы закрытых фич —
  [позиции в диагностиках (`файл:строка:колонка`) и настоящий `file_no`](0053-diagnostics-file-id.md) (путь как часть позиции),
  [`lamc` не печатает предупреждения вообще](0081-lamc-print-warnings.md) (единая точка предупреждений),
  [накопление семантических диагностик (несколько ошибок за прогон)](0130-diagnostics-batch.md) (реестр файлов у ошибок).
- **Влияние на порядок разработки:** ничего не разблокирует.

### Требования и проверяемые условия

- **R1. Позиция доезжает до пользователя** — путь, строка и колонка у
  предупреждений «своего» файла.
- **R2. Путь разрешается реестром файлов, а не именем входа.** Предупреждение
  импортированного файла называет **его** путь; иначе координаты указывают в
  чужой текст.
- **R3. Формат печати — один на все цели.** Литеральная копия в
  `report_hal_result` устранена; печать идёт через `format_warning`.
- **R4. Форма префикса совпадает с формой префикса ошибки.**
- **R5. `--quiet` глушит предупреждения во всех ветвях печати**, включая
  HAL-цели.
- **R6. Порождённый код не задет.** Предупреждения идут в stderr; снапшоты
  `examples/generated/` не двигаются.

| A2 | то же на цели `c-hal` | `…::hal_target_warning_carries_position` |

### Особенности по обратной функциональности

| Функциональность | Задета | Что проверяется |
|---|---|---|
| `taktc compile`, цель `c` и прочие «простые» | да | новый префикс; `--quiet`; тексты не изменились |
| `taktc compile`, цели `c-hal`/`st-at`/`sv-mmio` | да | копия формата устранена; префикс появился |
| `taktc fmt` | нет | путь ставил и раньше  |
| LSP | нет | печатью не пользуется: позиция уходит диапазоном протокола |
| `takt-sim` | нет | стамп пути у него свой (`takt_sim.rs`) |
| Порождённый код, снапшоты | нет | предупреждения идут в stderr |
| Ошибки `--define` (`DF-…`) | нет | у аргумента командной строки нет места в файле; формат оставлен свой |

### Риски и зависимости

- **Вывод `compile` меняется на всём корпусе.** Риск принят: изменение —
  добавление префикса в stderr, проверки предкоммита сверяют файлы, а не текст
  сообщений.
- **Ограничение HAL-ветви.** Реестр там содержит только корневой файл (цель
  строит своё дерево внутри и таблицу наружу не отдаёт), поэтому предупреждение
  импортированного файла остаётся без префикса. Названо в ADR; расширение
  требует смены сигнатур трёх функций генерации.
- **Соблазн упростить до «штампуем имя входа».** Это Option B, отвергнутый:
  верный код с неверной строкой хуже отсутствия строки. Контроль — тест A3.

## Разработка

### Задача

#### Что было

```text
Предупреждение [SE-036]: переменная 'BadVar' объявлена, но нигде не используется
probe.takt:2:17: Ошибка компиляции [SE-034]: Локальный тип 'NoSuchType' не найден
```

Две строки одного инструмента: у ошибки позиция есть, у предупреждения нет.
Координата у предупреждения при этом **была** — `position_prefix` без пути к файлу
отдаёт пустую строку, а путь предупреждению никто не ставил (ошибкам его ставит
`pipeline::stamp_file`).

У целей `c-hal`/`st-at`/`sv-mmio` было хуже: `report_hal_result` печатал формат
**литералом**, минуя `format_warning`, — то есть правка общей точки эти цели не
задела бы вовсе.

#### Что сделано

**Одна точка печати.** Заведена `compile_cli::print_warnings(warnings, files,
quiet)`: разрешает `file_no` диагностики в путь через `FileTable::path_of`,
печатает общим `format_warning`, уважает `--quiet`. Литеральная копия формата в
`report_hal_result` удалена — цель печатает через ту же функцию.

**Реестр файлов вместо однодневки.** Модель для сбора предупреждений строится
`construct_model_with_files` с реестром, который остаётся у вызывающего (прежде
`construct_model` заводил `FileTable::default()` внутри и наружу не отдавал).
Благодаря этому предупреждение импортированного файла называет **его** путь:

```text
./lib.takt:1:1: Предупреждение [SE-036]: переменная 'lib_unused' объявлена, но нигде не используется
```

**Штамповать именем входа нельзя** — это отвергнутый Option B: смещения
диагностики принадлежат тексту **своего** файла, и путь импортёра дал бы верный
код с координатами, указывающими не туда. `path_of` отвечает `None` на
незарегистрированный номер, поэтому непокрытая диагностика остаётся без
префикса — как прежде, но не врёт.

**Ограничение HAL-ветви названо в коде:** там реестр содержит только корневой
файл (цель строит своё дерево внутри и таблицу наружу не отдаёт), поэтому
предупреждение импортированного файла остаётся без префикса. Расширение —
смена сигнатур трёх функций генерации, в объём не входит.

**Ошибки `--define` (`DF-…`) оставлены со своим форматом** (`Ошибка --define
[DF-002]: …`): у аргумента командной строки нет места в файле, и префикс позиции
для него выдумывать нечем.

#### Документ

**Правок не требует, и это стоит записать.** Раздел
[«Диагностики»](../../book/src/16-diagnostics/index.typ) и вводная часть приложения
об ошибках уже объявляют формат единым: «Сообщение строится единообразно:
`путь:строка:колонка: <вид> [<код>]: <текст>`». Для предупреждений `compile` это
было **неверно** — фича делает обещание документа верным, а не меняет его.

Второй раз подряд документ оказался впереди инструмента (первый — фраза
приложения про `CS-001`). Документ, написанный про **свойство**, а
не про реализацию, тем самым работает контролем: расхождение видно при чтении.

### Выводы и дальнейшие шаги

**Названное ограничение.** В ветви HAL-целей реестр содержит только корневой файл:
цель строит своё дерево внутри и таблицу наружу не отдаёт, поэтому предупреждение
импортированного файла там остаётся без префикса. Расширение требует смены
сигнатур `compile_to_c_hal`/`compile_to_st_at`/`compile_to_sv_mmio` — отдельная
фича, если случай встретится на практике (в корпусе таких предупреждений нет).

**Наблюдение о документе.** Второй раз подряд документ оказался впереди
инструмента: раздел «Диагностики» уже объявлял формат единым
(`путь:строка:колонка: <вид> [<код>]: <текст>`), и для предупреждений `compile`
это было неверно. Документ, написанный про **свойство**, а не про реализацию,
работает контролем — расхождение видно при чтении.

**Оба кандидата, найденных при закрытии 0226, закрыты** (второй — фичей
[редактор показывает CS-001 и при ошибках в файле](0227-lsp-style-warning-with-errors.md)).

## Итог (что сделано)

Предупреждение `taktc compile` печатается так же, как ошибка: с путём, строкой и
колонкой.

**`takt-lang`:** печать предупреждений сведена в одну функцию
`compile_cli::print_warnings` — она разрешает `file_no` диагностики в путь через
`FileTable::path_of`, печатает общим `format_warning` и уважает `--quiet`. Модель
для сбора предупреждений строится `construct_model_with_files`, поэтому реестр
файлов остаётся у вызывающего и предупреждение импортированного файла называет
**его** путь. Литеральная копия формата в `report_hal_result` (цели
`c-hal`/`st-at`/`sv-mmio`) удалена.

**Ключевое решение:** путь берётся из реестра, а не из имени входного файла.
Штамп имени входа (Option B ADR) дал бы верный код с координатами, указывающими в
чужой текст, — это не улучшение, а новый дефект. Граница названа: в ветви
HAL-целей реестр содержит только корневой файл, и предупреждение импортированного
файла остаётся без префикса.

**Язык не изменён** (`0.8.0`); порождённый код и снапшоты не задеты —
предупреждения идут в stderr.

**Проверка:** 5 тестов `takt-lang/tests/targets/cli_warning_position_tests.rs`, три
мутации (в том числе на границу Option A / Option B), `precheck.sh` — код 0.
Подробности — в [отчёте](0228-compile-warning-position.md#отчёт-о-тестировании).

**Наблюдение:** второй раз подряд документ оказался впереди инструмента —
формат он объявлял единым, а предупреждения ему не следовали. Документ,
написанный про свойство, работает контролем.
