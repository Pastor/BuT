# Фича: Расширение Zed не собирается: пин толчейна и каталог сборки

- **Номер:** 0414
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** proc
- **Класс:** прочее
- **Связанные issue (анализ):** новая фича (по запросу заказчика 2026-08-23)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32).

## Краткое описание

Расширение Zed (`extensions/zed-takt`) не устанавливалось: редактор отвечал
`failed to compile Rust extension`. Причин **две**, и обе — не в расширении, а
в конфигурации корня репозитория, которая действует на подкаталог: пин толчейна
не перечисляет wasm-таргеты, а общий каталог сборки уводит артефакт туда, где
чужой инструмент его не ищет. Фича устраняет обе и заводит проверка с самопроверкой.

## Документирование (правило 24)

Не требуется: язык не затронут — фича инфраструктурная (сборка редакторского
расширения).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-23
- **Authors:** архитектор, разработчик

### Context

Заказчик сообщил: «zed extension не собирается, при попытке установки в
редакторе вылезает ошибка».

**Замер-23** (прогоном, правило 30). Лог редактора
`~/Library/Logs/Zed/Zed.log`:

```
16:15:30 INFO  [extension::extension_builder] compiling Rust extension /Volumes/HOME/GitHub/BuT/extensions/zed-takt
16:15:33 ERROR failed to compile Rust extension: failed to build extension    Compiling syn v2.0.117
16:15:33 ERROR [extensions_ui] Failed to install dev extension: failed to compile Rust extension
```

**Текст отказа непригоден для диагноза:** Zed печатает первую строку вывода
cargo (`Compiling syn`) и обрезает остальное — настоящая ошибка компилятора до
пользователя не доходит вовсе. Диагноз снят **воспроизведением** сборки теми же
командами, что даёт редактор.

Найдено **два** независимых препятствия, второе — за первым:

**Причина A — пин толчейна не знает wasm-таргетов.** Zed 1.16.1 собирает
расширения под `wasm32-wasip2` (свидетельство — каталог
`extensions/zed-takt/target/wasm32-wasip2/`, оставшийся от попытки). Активный
толчейн в каталоге расширения — **1.97.1**, потому что `rustup` ищет
`rust-toolchain.toml` **вверх по дереву** и находит корневой пин:

```
$ rustup show active-toolchain
1.97.1-aarch64-apple-darwin (overridden by '/Volumes/HOME/GitHub/BuT/rust-toolchain.toml')
$ rustup target list --installed
aarch64-apple-darwin
```

Сборка падает `error[E0463]: can't find crate for core` — то самое, что Zed
обрезает. После `rustup target add wasm32-wasip2` сборка проходит за 2.85 с.

**Причина B — каталог сборки чужой.** Корневой `.cargo/config.toml`
задаёт `target-dir = "target/precheck"`, и cargo берёт **ближайший вверх по
дереву** конфиг — то есть корневой действует и в каталоге расширения. Zed же
ищет артефакт по **фиксированному** пути внутри каталога расширения. Замер: с
установленным таргетом сборка успешна, а файл лежит в
`<repo>/target/precheck/wasm32-wasip2/release/zed_takt.wasm` (225 КБ), тогда как
`extensions/zed-takt/target/wasm32-wasip2/release/*.wasm` — пусто.

Причина B **невидима, пока жива A**: она вскрывается ровно в тот момент, когда
первая устранена. Замер снимался дважды.

### Decision Drivers

- Отказ приходит от **чужого инструмента** и его текст бесполезен — правило
  должно контролироваться у нас, а не «выясняться заново».
- Версия толчейна названа **один раз**.
- Предкоммит обязан оставаться быстрым: расширение в нём не участвует.

### Considered Options

1. **Свой `rust-toolchain.toml` у расширения.** Отвергнут: назвал бы версию
   вторым источником, и при первом же подъёме пина они разъехались бы — ровно
   тот класс, который проект ловит проверками.
2. **Снять корневой пин с подкаталога.** Невозможно: `rustup` не знает
   исключений по каталогам.
3. **Перечислить таргеты в корневом пине + свой каталог сборки у расширения**
   (принято). Версия остаётся одна, таргеты ставятся `rustup` автоматически при
   первой сборке, артефакт возвращается туда, где его ищет редактор.
4. **Собирать расширение шагом предкоммита.** Отвергнут по цене: загрузка
   таргета и минуты компиляции ради кода, который в конвейере не участвует.

### Decision

Принят вариант 3.

- В корневой `rust-toolchain.toml` добавлено
  `targets = ["wasm32-wasip1", "wasm32-wasip2"]` — оба, потому что версия Zed у
  пользователя может быть старше (до перехода на компонентную модель редактор
  собирал под `wasm32-wasip1`).
- Заведён `extensions/zed-takt/.cargo/config.toml` с `target-dir = "target"` —
  переопределение корневого. Приём в проекте уже есть: `scripts/install.sh`
  задаёт свой каталог явно, чтобы не конкурировать за блокировку (0251).
- Заведён проверка `scripts/check-zed-extension.sh` (условия `Z1`, `Z2`) и контроль
  `scripts/test-zed-extension.sh`; оба — шагом предкоммита.

### Consequences

- Установка `rustup` для этого репозитория тянет два wasm-таргета (~30 МБ).
  Цена принята: без них расширение не собирается, а отказ не диагностируем.
- Проверка проверяет **конфигурацию**, а не факт сборки — граница названа в его
  заголовке и в тест-плане.

#### Acceptance criteria

- Сборка `cargo build --release --target wasm32-wasip2` в каталоге расширения
  проходит и кладёт `zed_takt.wasm` в `extensions/zed-takt/target/…`.
- Проверка ловит каждое из двух условий по отдельности и пропускает здоровое дерево.

## Анализ

### Цель и контекст

Вернуть расширению Zed собираемость **редактором** и сделать класс видимым
машине: обе причины — молчаливые отступления конфигурации, замеченные только
через жалобу пользователя.

### Замер (правило 30, 2026-08-23)

| Шаг | Результат |
|---|---|
| Установка в Zed | `Failed to install dev extension: failed to compile Rust extension` |
| Текст отказа | обрезан на `Compiling syn v2.0.117` — причины не называет |
| `cargo build --target wasm32-wasip2` (до правки) | `E0463: can't find crate for core` |
| `rustup target list --installed` | только `aarch64-apple-darwin` |
| Активный толчейн в каталоге расширения | `1.97.1`, «overridden by» корневым пином |
| После `rustup target add wasm32-wasip2` | сборка **успешна** (2.85 с) |
| Куда лёг wasm | `target/precheck/wasm32-wasip2/release/zed_takt.wasm` (225 КБ) |
| Где ищет Zed | `extensions/zed-takt/target/wasm32-wasip2/release/*.wasm` — **пусто** |
| После обеих правок | `extensions/zed-takt/target/wasm32-wasip2/release/zed_takt.wasm`, 230 543 байта |

**Побочная находка (в объём не входит).** В редакторе установлены два
dev-расширения по **старым** именам: `but` → `extensions/zed-but` и `lam` →
`extensions/zed-lam`; обоих каталогов не существует с переименования 0100, и
каждая переиндексация даёт `ERROR ... No extension manifest found`. Это
состояние машины пользователя, а не репозитория — вынесено в «Итог» подсказкой,
файлы не трогались.

### Зависимости фичи (правило 17/19)

Затрагивает решения (пин толчейна) и 0251 (единый каталог сборки) — оба
остаются в силе, меняется лишь их действие на подкаталог расширения.

### Требования и проверяемые условия

- `Z1` — пин толчейна перечисляет `wasm32-wasip1` и `wasm32-wasip2`.
- `Z2` — расширение собирается в собственный `target/`.
- Сборка под обоими таргетами проходит.
- Дерево без каталога расширения проверка не роняет.

### Критерии приёмки и способ проверки

Проверка + контроль на копии дерева (`ZE_ROOT`), плюс ручной прогон настоящей сборки.

### Редакторский слой (правило 29)

Предмет фичи **и есть** редакторский слой; язык, LSP и плагин IntelliJ не
затронуты.

### Особенности по обратной функциональности

Изменения аддитивны: корневой пин получает поле, расширение — свой конфиг.
Сборка ядра и `precheck.sh` не меняются (переменная окружения
`CARGO_TARGET_DIR` предкоммита по-прежнему сильнее любого конфига).

### Риски и зависимости

Версия Zed у пользователя может собирать под иным таргетом — тогда `Z1`
дополняется записью. Риск назван, а не устранён: список таргетов редактора
знанием репозитория не является.

## Разработка

### Задача

#### Что было

Корневой `rust-toolchain.toml` перечислял только компоненты; каталога
`.cargo/` у расширения не было. Обе конфигурации корня действовали на
подкаталог молча.

#### Что сделано

- `rust-toolchain.toml` — поле `targets` с обоими wasm-таргетами и объяснением,
  почему запись живёт здесь, а не своим файлом у расширения.
- `extensions/zed-takt/.cargo/config.toml` — `target-dir = "target"`.
- `scripts/check-zed-extension.sh` — проверка (`Z1`, `Z2`), граница названа в
  заголовке.
- `scripts/test-zed-extension.sh` — контроль на копии дерева, шесть условий.
- `scripts/precheck.sh` — шаг рядом с проверкой адреса репозитория.

#### Проверки

Сборка под `wasm32-wasip2` и `wasm32-wasip1`, контроль проверки, полный предкоммит.

## Итог (что сделано)

Расширение Zed не устанавливалось из-за **двух** конфигураций корня, каждая из
которых действует на подкаталог молча: пин толчейна (0137) навязывал каталогу
расширения версию без wasm-таргетов, а единый каталог сборки (0251) уводил
готовый wasm туда, где редактор его не ищет. Обе устранены минимально: поле
`targets` в существующем пине (второго источника версии не заведено) и свой
`.cargo/config.toml` у расширения.

**Текст чужого отказа непригоден для диагноза** — Zed печатает первую строку
вывода cargo и обрезает остальное; диагноз снят воспроизведением сборки.

**Причина B невидима, пока жива A**: замер снимался дважды, и второй барьер
вскрылся ровно после устранения первого.

Класс отдан машине: проверка `check-zed-extension.sh` с шестиусловным контролем.

**Подсказка пользователю (вне репозитория).** В Zed остались два битых
dev-расширения по старым именам — `but` и `lam`, ссылающиеся на каталоги,
которых нет с переименования 0100; они дают `ERROR ... No extension manifest
found` при каждой переиндексации. Снимаются удалением симлинков в
`~/Library/Application Support/Zed/extensions/installed/`.
