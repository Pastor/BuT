### Context

Значения типа `duration` и сравнения над ними сверяются с эталоном **только**
для целей `c` и `rust` (`conformance_{c,rust}_duration_tests`). Для `st` и `sv`
до сих пор проверялся **текст** порождённого файла на конкретные числа
миллисекунд плюс прогон `iec2c` / `verilator`.

Это слабее по существу: оба инструмента принимают молча неверный код — ровно
на этом стояли дефекты и 0045. Граница, о которой идёт речь, узкая и
тихая: представление эталона — **наносекунды**, представление целей —
**миллисекунды**; ошибка на ней (`250us` → 0 мс, множитель не тот)
даёт валидный вывод с другим поведением.

**Замер-20** (кандидат перепроверен). Фикстура
`conformance_duration_value.takt` (`elapsed := pause + 750ms`,
`ms := elapsed as u32`, `late := elapsed > 500ms`):

| Потребитель | `ms` | `late` | Как получено |
|---|---|---|---|
| эталон | 1750 | 1 | `takt-sim`, шаг 1 |
| `st` | 1750 | 1 | `iec2c` → `cc` → драйвер, поля `TIMERS0.MS`, `TIMERS0.LATE` |
| `sv` | — | — | **не переводится**: `SV-002` на `as` |

То есть цель `st` считает верно, и сверка заводится **контролем, а не
починкой**. Цель `sv` ту же фикстуру не берёт вовсе — приведение `as` в неё не
транслируется (известный класс, отдельный кандидат).

**Контрольная проба для `sv`** (та же арифметика без `as`, наблюдение —
внутренний сигнал `elapsed` и биты сравнений): `verilator` даёт
`elapsed=1750 late=1 exact=1 over=0` — совпадает с эталоном.

### Decision Drivers

1. **Проверка целевого языка не судит о верности** — это записанный урок проекта
   (0041, 0045, 0050); сверку заводят вместе с генератором, а здесь она пропущена.
2. **Граница нс↔мс тиха**: ошибка не даёт ни отказа, ни предупреждения.
3. **Наблюдать нужно то, что видно потребителю**, а не текст файла.

### Considered Options

#### Option A. Оставить текстовые проверки, усилив их числами

**Pros:** дёшево.
**Cons:** проверяет **печать**, а не поведение: молча неверная трансляция
печатает верное число там, где считает другое (класс — вывод `st` был
сдвинут на такт, и `iec2c` его принимал).

#### Option B. Две сверки значений: `st` — через `iec2c`+`cc`, `sv` — тестбенчем

`st`: порождение → `iec2c` → драйвер на C с точными именами полей
(`STDURVALUE_data__`, `TIMERS0.MS`, `TIMERS0.LATE`) → сверка с эталоном.
`sv`: порождение → тестбенч `verilator --binary` → сверка `elapsed` и битов
сравнений с эталоном.

**Pros:** наблюдается результат вычисления, а не текст; образцы обвязки уже
есть (`conformance_st_every_tests.rs`, `conformance_sv_time_tests.rs`).
**Cons:** внешние инструменты; при их отсутствии — мягкий пропуск.

#### Option C. Одна фикстура на обе цели

**Pros:** сопоставимость.
**Cons:** невозможна: `sv` отвергает `as`, а без `as` теряется наблюдение
числа у `st`, где оно доступно прямо. Одна фикстура означала бы **ослабить**
сверку `st` ради ограничения чужой цели.

### Decision

Принимается **Option B**, с раздельными фикстурами:

1. **`st` берёт существующую фикстуру** `conformance_duration_value.takt` — ту
   же, что `c` и `rust`. Сопоставимость трёх целей важнее единообразия с `sv`.
2. **`sv` получает свою** — `conformance_duration_value_sv.takt`: та же
   арифметика без `as`, наблюдение тройное (нижняя граница `> 500ms`, точное
   равенство `= 1750ms`, верхняя граница `> 1800ms`) плюс внутренний сигнал
   `elapsed` в миллисекундах. Граница названа в шапке фикстуры: приведение `as`
   целью `sv` не переводится, и обходить это молча нельзя.
3. Оба набора — модули существующей темы `conformance`, мягкая
   деградация при отсутствии `iec2c`/`cc`/`verilator`.
4. **Небутафорность доказывается мутацией инструмента**, а не фикстуры: порча
   пересчёта в миллисекунды обязана красить новые сверки при зелёных
   `iec2c`/`verilator`.

### Consequences

#### Положительные

- Значения `duration` сверяются с эталоном у **четырёх** целей вместо двух.
- Тихая граница нс↔мс закрыта наблюдением результата.
- Для `sv` заодно сверяется **равенство** длительностей — форма, которой нет в
  фикстуре `c`/`rust`.

#### Отрицательные / Action items

- У `sv` наблюдение косвенное (сравнения + внутренний сигнал): приведение `as`
  в эту цель не транслируется. Кандидат на перевод `as` в `sv` остаётся.
- Сверки требуют внешних инструментов; без них — пропуск (под
  `PRECHECK_STRICT=1` отсутствие инструмента и без того валит прогон).

#### Acceptance criteria

1. `st`: `(ms, late)` эталона и порождённого ST совпадают.
2. `sv`: `elapsed` и три бита сравнений эталона и RTL совпадают.
3. **Контроль:** мутация пересчёта в миллисекунды красит обе сверки.
4. Наборы живут в теме `conformance`, новых тестовых целей не появляется.
5. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Довести число целей, у которых **значения** `duration` сверяются с эталоном, с
двух до четырёх. ADR принял Option B: сверка через реальный прогон
порождённого кода (`iec2c` + `cc` для `st`, тестбенч `verilator` для `sv`).

### Замер (снят 2026-08-20)

Кандидат (2026-07-29) подтверждён; уточнения — ниже.

**1. Цель `st` фикстуру `c`/`rust` переводит и считает верно.** Прогон
`iec2c` → `cc` → драйвер: `TIMERS0.MS = 1750`, `TIMERS0.LATE = 1`,
`TIMERS0.ELAPSED = 1750` — совпадает с эталоном (1750 мс, истина). Значит
сверка заводится **контролем**, а не починкой.

**2. Цель `sv` ту же фикстуру не берёт вовсе:** `SV-002` — приведение `as` не
транслируется. Это не предмет 0215 (отдельный класс), поэтому фикстура для
`sv` своя, а граница названа в её шапке.

**3. Контрольная проба `sv` без `as`** (три сравнения + наблюдение сигнала
`elapsed` иерархически): `verilator` даёт `elapsed=1750 late=1 exact=1 over=0`
— совпадает с эталоном.

**4. Мутация доказывает ценность сверок.** Пересчёт в миллисекунды испорчен
(`nanos / CLOCK_QUANTUM_NS / 10` в `semantic::duration::value_millis`):

| Свидетель | Ответ на испорченном выводе |
|---|---|
| `iec2c` на порождённом ST | **код 0** (принял) |
| `verilator --lint-only -Wall` на порождённом SV | **код 0** (принял) |
| новая сверка `st` | провал |
| новая сверка `sv` | провал |
| прежние сверки `c`, `rust` | провал |

Порождённый ST при этом содержит `elapsed := pause + (75)` и
`IF (elapsed > (50))` — валидный код с другим поведением, ровно тот класс, ради
которого сверки и заведены.

- **R1.** Значения `(ms, late, elapsed)` эталона и порождённого ST совпадают на

- **R5.** Наборы — модули темы `conformance`, новых тестовых

- **R6.** Отсутствие внешнего инструмента — мягкий пропуск, не отказ.

## Разработка

### Задача

#### Что сделано

`takt-sim/tests/conformance/conformance_st_duration_tests.rs` — сверка значений
на фикстуре `conformance_duration_value.takt` (**той же**, что у целей `c` и
`rust`):

1. порождение ST под именем `stdurvalue.takt` — корень ST берёт имя из имени
   файла, и от него же зависят C-символы `iec2c` (`STDURVALUE_data__`);
2. трансляция `iec2c -I <lib>` → `POUS.c`;
3. драйвер на C вызывает `STDURVALUE_body__` три скана и печатает
   `TIMERS0.MS`, `TIMERS0.LATE` и приватное `TIMERS0.ELAPSED`;
4. сверка с эталоном, причём ожидание эталона записано **числами**
   (`(1750, 1, 1750)`) — иначе сверка проверяла бы цель против себя.

Наносекунды эталона переводятся в миллисекунды **в тесте**, а не в цели:
этот перевод и есть предмет сверки.

Каталог сборки уникален по тесту, двоеточие из имени потока вычищается
(инварианты и 0244).

Набор объявлен модулем темы `conformance` — новой тестовой цели не появилось.

#### Проверка

```sh
cargo test --test conformance conformance_st_duration_tests::
```

### Задача

#### Что сделано

**Фикстура** `takt-sim/tests/data/eval/conformance_duration_value_sv.takt` — та
же арифметика длительностей, но **без приведения** `as`: цель `sv` его не
транслирует (`SV-002`), и число миллисекунд через порт не выдать. Значение
наблюдается косвенно и потому тройной проверкой:

| Порт | Условие | Смысл |
|---|---|---|
| `late` | `elapsed > 500ms` | нижняя граница |
| `exact` | `elapsed = 1750ms` | точное значение |
| `over` | `elapsed > 1800ms` | верхняя граница |

Плюс сам сигнал `elapsed` читается тестбенчем иерархически
(`dut.svdurvalue_timers_elapsed`) — у цели это `logic [31:0]` в миллисекундах.

**Сверка** `takt-sim/tests/conformance/conformance_sv_duration_tests.rs`:
порождение → тестбенч `verilator --binary -j 0 --timing` → печать четвёрки
значений на каждом такте → сверка с эталоном. Ожидание эталона записано
числами `(1750, 1, 1, 0)`.

Равенство длительностей (`exact`) — форма, которой **нет** в фикстуре
`c`/`rust`: там сравнение одно. То есть сверка `sv` заодно покрывает то, что не
покрыто у соседей.

#### Проверка

```sh
cargo test --test conformance conformance_sv_duration_tests::
```

## Тест-план

### Предмет проверки

Сами сверки: доказать, что они **сверяют**, а не сопровождают зелёный прогон.
Поведение целей фича не меняет.

### Условия проверок

| # | Условие | Как проверяется | Ожидаемый результат |
|---|---|---|---|
| П1 | `st`: значения совпадают с эталоном | `conformance_st_duration_tests::duration_values_match_generated_st` | `(1750, 1, 1750)` на каждом из 3 сканов |
| П2 | `sv`: значения совпадают с эталоном | `conformance_sv_duration_tests::duration_values_match_generated_sv` | `(1750, 1, 1, 0)` на каждом из 3 тактов |
| П3 | Ожидание эталона задано числами | чтение теста | `assert_eq!` с литералами до обращения к цели |
| П4 | Мутация красит сверки | испортить `value_millis` (делить на 10) | обе новые сверки провал |
| П5 | Мутацию не видят внешние инструменты | `iec2c`, `verilator --lint-only -Wall` на том же выводе | код 0 у обоих |
| П6 | Прежние сверки не сломаны | `cargo test --test conformance duration_values_match` | 4/4 зелёные |
| П7 | Новых тестовых целей нет | `main.rs` темы `conformance` | оба набора — `mod` |
| П8 | Предкоммит зелёный | `./scripts/precheck.sh` | код 0 |

### Примеры и контрпримеры

Язык фича не меняет, поэтому примеров на языке она не вводит. Роль
контрпримера играет **мутация инструмента** (П4/П5): вывод остаётся валидным
для `iec2c` и `verilator`, но считает другое —

```
elapsed := pause + (75);      (* вместо 750 *)
IF (elapsed > (50)) THEN      (* вместо 500 *)
```

Без П5 проверка П4 ничего не доказывала бы: «сверка упала» означало бы лишь,
что упало всё, включая проверки.

### Границы

Сверка `sv` наблюдает значение косвенно (сравнения + внутренний сигнал):
приведение `as` в цель не транслируется. Это названо в фикстуре и в ADR.

## Итог (что сделано)

**Значения `duration` сверяются с эталоном у четырёх целей вместо двух.**

- **`st`** — `takt-sim/tests/conformance/conformance_st_duration_tests.rs`: та же
  фикстура, что у `c` и `rust`; порождение → `iec2c` → драйвер на C читает
  `TIMERS0.MS`, `TIMERS0.LATE`, `TIMERS0.ELAPSED` и сверяет с эталоном.
- **`sv`** — `conformance_sv_duration_tests.rs` на своей фикстуре
  `conformance_duration_value_sv.takt`: приведение `as` цель не транслирует
  (`SV-002`), поэтому значение зажимается тремя сравнениями (нижняя граница,
  **равенство**, верхняя) и читается сигналом `elapsed` через тестбенч
  `verilator`. Равенство длительностей не покрыто даже у `c`/`rust`.
- Оба набора — модули темы `conformance`: новых тестовых целей
  не появилось.

**Ценность измерена, а не заявлена.** Порча пересчёта в миллисекунды
(`value_millis`) даёт валидный вывод с другим поведением — `elapsed := pause +
(75)`, `IF (elapsed > (50))`; `iec2c` и `verilator --lint-only -Wall`
принимают его **с кодом 0**, а обе новые сверки краснеют.

**Дефектов не найдено:** обе цели считают верно, сверки заведены контролем.
