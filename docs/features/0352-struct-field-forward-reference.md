# Фича: Имя типа видно во всём файле; цикл структур — диагностика

- **Номер:** 0352
- **Статус:** ГОТОВО

## Краткое описание

Тип поля структуры разрешается **в порядке текста**, поэтому ссылка на тип,
объявленный **ниже**, не разрешается вовсе: `construct_type` возвращает ошибку,
а вызывающий подменяет её `TypeNode::Unsupported`
(`tree.rs`, `.unwrap_or(TypeNode::Unsupported)`).

**Замер-21** (`scripts/probe.sh -n 3`):

| Вход | эталон | цели |
|---|---|---|
| `struct Aa { b: Bb }` **выше** `struct Bb { m: u8 }` | `v=Aa{b=0,n=0}` — поле-структура стала **числом** | `c`/`c-hal` `CC-015`, `st`/`st-at` `ST-002`, `rust` `RS-014`, `sv`/`sv-mmio` `SV-002`, `plantuml` OK |
| `struct Cfg { m: Mode }` выше `enum Mode` | то же | то же |
| `struct Holder { cells: [Cell; 2] }` выше `struct Cell` | то же | то же |
| `type Alias = Point;` выше `struct Point` | — | **`SE-034`** «Локальный тип 'Point' не найден» — тип есть, объявлен ниже |

**Контрольный вход** (правило 30): тот же файл с **обратным** порядком
объявлений принимают все девять потребителей — значит ломает **порядок**, а не
форма записи.

**Эталон хуже целей:** он не отказывает, а **молча** подменяет тип поля,
то есть модель исполняется с другим устройством данных.

Документ (`book/`, раздел «Типы») правила порядка для **типов** не задаёт вовсе:
там описан порядок **значений** (переменная ссылается назад — `SE-109`,
константа свободна). Пробел заполняется в пользу «тип виден во всём файле» —
как у констант.

Второй предмет — **цикл структур**: `struct A { b: B }` и `struct B { a: A }`.
Сегодня запись принимается семантикой, а после снятия зависимости от порядка
она станет **разрешаемой**, то есть даст тип бесконечного размера. Вводится
диагностика **`SE-124`**.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл
> по правилу 17.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Фича:** [../features/0352-struct-field-forward-reference.md](0352-struct-field-forward-reference.md)

### Контекст

Объявления типов строятся **одним проходом в порядке текста**
(`tree.rs::construct_model_stage0`): встретив `struct`, строитель тут же
разрешает типы её полей через `construct_type`, а тот спрашивает `model.types`
— карту, наполняемую тем же проходом. Поэтому имя, объявленное **ниже**, не
разрешается.

**Замер-21** (`scripts/probe.sh -n 3`, контроль — тот же файл с
обратным порядком объявлений, принимается всеми девятью потребителями):

| Вход | эталон | цели |
|---|---|---|
| `struct Aa { b: Bb, n: u8 }` выше `struct Bb` | `v=Aa{b=0,n=0}` — поле-структура стала **числом**, молча | `CC-015`, `ST-002`, `RS-014`, `SV-002`; `plantuml` OK |
| `struct Cfg { m: Mode }` выше `enum Mode` | то же | то же |
| `struct Holder { cells: [Cell; 2] }` выше `struct Cell` | то же | то же |
| `type Alias = Point;` выше `struct Point` | — | **`SE-034`** «Локальный тип 'Point' не найден» |
| `type A = B;` выше `type B = u8;` | — | **`SE-034`** |

Два исхода одной причины, и худший — тихий: `construct_type` возвращает
`Err`, а строитель полей подменяет её `.unwrap_or(TypeNode::Unsupported)`, то
есть **глотает диагностику** и кладёт в поле неподдержанный тип.

Правила языка на этот счёт **нет**: раздел `book/` «Типы» описывает порядок
для **значений** (переменная ссылается назад — `SE-109`; константа свободна) и
о типах молчит. Пробел и порождает разнобой.

### Решение

**Имя типа видно во всём файле независимо от места объявления — как у
констант. Структура, содержащая себя прямо или через цепочку полей, — `SE-124`.**

1. **Предпроход регистрации имён** (`type_registry::predeclare_named_types`):
   до основного цикла обойти элементы модели, занять имена всех `struct`, `enum`
   и `type` (`claim_type_name` — единственная воронка, 0243) и положить в
   `types` те, чьё значение известно **по имени**: `TypeNode::Struct(name)` и
   `TypeNode::Enum(name)`. Порядок обхода — текстовый, чтобы `SE-108` о дубле
   называл первым верное объявление.
2. **Псевдонимы разрешаются до неподвижной точки.** Значение псевдонима — это
   уже разрешённый тип, поэтому одного прохода мало (`type A = B;` выше
   `type B = u8;`). Проход повторяется, пока карта растёт; завершение
   гарантировано тем, что циклы среди псевдонимов отсекает **раньше**
   существующая `SE-039` (Ce16), а число объявлений конечно. Остаток
   неразрешённых после стабилизации отдаёт свою `SE-034` — имя действительно не
   объявлено.
3. **Поля структур разрешаются в основном цикле**, как сейчас, но уже при
   полной карте имён. Подмена ошибки `.unwrap_or(TypeNode::Unsupported)`
   **снимается**: диагностика возвращается вызывающему.
4. **Цикл структур — `SE-124`** (`semantic/validate/struct_cycle.rs`): граф по
   **сырым** полям АСД, узлы — структуры и псевдонимы, ребро — «тип поля
   (в том числе элемент массива) ссылается на имя». Цикл, содержащий хотя бы
   одну структуру, отвергается с называнием участника; чисто псевдонимный цикл
   остаётся за `SE-039`, которая проверяется раньше.

### Отвергнутые варианты

**А. Разрешать поля структур вторым проходом, а имена — как сейчас.**
Чинит только структуры: `type Alias = Point;` выше `struct Point` и
`type A = B;` остаются `SE-034`. Класс один, и половинчатая правка оставила бы
автору правило «порядок важен, но не всегда» — худшее из возможных.

**Б. Оставить порядок значимым и назвать это правилом языка** (диагностика
«тип объявлен ниже», как `SE-109` у переменных). Возможно, но противоречит уже
принятому решению для **констант** (порядок не важен) и ничем не оправдано: у
типа нет «значения на момент объявления», ради которого правило вводилось для
переменных. Вдобавок это **сузило** бы язык там, где семь целей уже отказывают,
а эталон исполняет молча — то есть узаконило бы худший из наблюдаемых исходов.

**В. Разворачивать структуры в дереве (подстановка полей).** Тогда цикл виден
по построению, но тип бесконечного размера сломал бы построитель раньше
диагностики, а формы `Struct(name)` ждут все восемь целей.

### Последствия

- Порядок объявления типов в файле перестаёт быть значимым; записи, отвергаемые
  сегодня семью целями, начинают переводиться.
- Молчаливая подмена типа поля у эталона исчезает: `construct_type` больше не
  теряет диагностику.
- Появляется `SE-124` — запись, сегодня принимаемая семантикой и порождающая
  вывод, который отвергнут инструментами целевых языков.
- **Язык меняется** (правило 22): снимается ограничение порядка и вводится
  новая диагностика. Версия языка поднимается — накопительно, по правилу 22.
- Раздел `book/` «Типы» дополняется абзацем о видимости имени типа и записью в
  блоке «Частые ошибки»; приложение «Ошибки и предупреждения» получает `SE-124`
  (проверка сверяет состав кодов).

### Замер (правило 30)

Снят `scripts/probe.sh -n 3` 2026-08-21, пять входов плюс контрольный (обратный
порядок объявлений принимается всеми девятью потребителями). Сводка — в
[ADR](0352-struct-field-forward-reference.md#архитектура-adr). Выводы, влияющие на объём:

1. **Класс шире кандидата.** Кандидат в `FEATURES.md` называл только цикл
   структур; проба показала, что ломается **любая** ссылка на тип, объявленный
   ниже: поле-структура, поле-перечисление, элемент массива, псевдоним на
   структуру и псевдоним на псевдоним.
2. **Эталон хуже целей.** Он не отказывает, а молча кладёт в поле число: тип
   поля становится `Unsupported`, потому что вызывающий подменяет ошибку
   `.unwrap_or(TypeNode::Unsupported)`.
3. **Цикл — следствие правки, а не самостоятельная беда.** Сегодня цикл
   недостижим: одна из двух структур всегда ссылается вперёд и получает
   `Unsupported`. Сняв зависимость от порядка, мы делаем цикл **разрешимым** —
   значит диагностика обязана появиться в той же фиче, иначе фича породит
   вывод, отвергаемый инструментами целевых языков.

### Объём правки

| Место | Что делается |
|---|---|
| `semantic/type_registry.rs` | `predeclare_named_types` — предпроход: занять имена `struct`/`enum`/`type`, положить `Struct`/`Enum` в `types` |
| `semantic/type_registry.rs` | разрешение псевдонимов **до неподвижной точки** |
| `semantic/tree.rs` | ветви `Struct`/`Enum`/`Type` основного цикла: занятие имени уходит в предпроход; подмена `.unwrap_or(Unsupported)` снимается |
| `semantic/validate/struct_cycle.rs` | новый носитель: граф по сырым полям, `SE-124` |
| `docs/diagnostics/README.md` | запись `SE-124` |
| `book/src/03-types/`, `book/src/appendix-errors/` | абзац о видимости имени типа, «Частые ошибки», справочник |

**Занятие имени обязано остаться одной воронкой** (0243): предпроход зовёт
`claim_type_name`, а прежние вызовы из основного цикла **снимаются** — иначе
второй вызов на том же имени даст ложную `SE-108` «тип уже объявлен».

**Завершение цикла разрешения псевдонимов держит `SE-039`** (Ce16): она
проверяется раньше и отсекает циклические псевдонимы, поэтому «до неподвижной
точки» не зациклится. Это зависимость по **порядку проверок**, и она названа
здесь, потому что в коде видна не сразу.

### Зависимости (правило 17)

**Нет.** Используемые решения закрыты: 0243 (воронка занятия имени), 0293
(структуры у целей), 0341 (порядок печати структур по зависимостям — он
переживает цикл и потому требует диагностики выше по конвейеру).

### Обратная совместимость (правило 11) и версия языка (правило 22)

**Язык меняется, версия поднимается `0.10.0` → `0.11.0`** (тег `v0.10.0` уже
стоит, то есть версия выпущена; правило 22 — подъём делает первая закрытая
фича цикла и она же ставит тег).

- **Расширение:** порядок объявления типов перестаёт быть значимым. Записи,
  которые сегодня отвергаются, начинают работать — ломающих изменений нет.
- **Сужение:** цикл структур отвергается `SE-124`. Формально это ломающее
  изменение, но обоснованное: сегодня такая запись принимается семантикой и
  порождает вывод, который **отвергают инструменты целевых языков** (тип
  бесконечного размера непредставим ни в C, ни в IEC, ни в RTL). То есть
  запрещается запись, у которой нет корректного поведения ни у одного
  потребителя.

### Редакторский слой (правило 29)

Проверить и зафиксировать в отчёте: новых токенов и форм объявления нет,
узлов АСД тоже — значит `lsp/semantic_tokens.rs`, `TAKT_KEYWORDS` и
`TaktSymbolScanner` правок не требуют. **Новая диагностика `SE-124` обязана
доезжать до редактора** — то есть рождаться в `validate` и попадать в
`collect_compile_diagnostics`, а не печататься из библиотеки.

### Риски

- **Ложная `SE-108`** при забытом снятии старого `claim_type_name` — ловится
  первым же прогоном корпуса (структуры есть в `examples/`).
- **Ложная `SE-124`** на законной цепочке `A → B → C` без цикла — обязателен
  контрпример в тест-плане.
- **Самоссылка через массив** (`struct A { xs: [A; 2] }`) — тот же цикл; обход
  обязан спускаться в элемент массива, иначе класс просочится.

## Разработка

### Задача

- **Фича:** [../features/0352-struct-field-forward-reference.md](0352-struct-field-forward-reference.md)
- **ADR:** [0352-struct-field-forward-reference.md#архитектура-adr](0352-struct-field-forward-reference.md#архитектура-adr)
- **Анализ:** [0352-struct-field-forward-reference.md#анализ](0352-struct-field-forward-reference.md#анализ)
- **Дата:** 2026-08-21

#### Что сделано

##### 1. Предпроход регистрации имён (`semantic/type_registry.rs`)

`predeclare_named_types` обходит элементы модели **в порядке текста**, занимает
имена всех `struct`, `enum` и `type` (`claim_type_name` — та же воронка 0243,
просто переехавшая выше по конвейеру) и кладёт в `types` типы, чьё значение
известно **по имени**: `Struct(имя)` и `Enum(имя)`.

Прежние вызовы `claim_type_name` из основного цикла **сняты**: второй вызов на
том же имени дал бы ложную `SE-108` «тип уже объявлен». Снята и вторая запись в
`types`/`type_locs` из ветви `Struct` — регистрация живёт в одном месте.

##### 2. Псевдонимы разрешаются до неподвижной точки

`resolve_aliases` повторяет проход, пока карта растёт: значение псевдонима —
уже разрешённый тип, поэтому `type A = B;` выше `type B = u8;` требует второго
прохода. Остаток после стабилизации отдаёт свою диагностику — как правило
`SE-034`, и это верно: имя действительно не объявлено.

##### 3. Подмена ошибки снята (`semantic/tree.rs`)

Строитель полей вызывал `construct_type(...).unwrap_or(TypeNode::Unsupported)`
— то есть **глотал диагностику**. Ошибка возвращается вызывающему.

##### 4. Цикл структур — `SE-124` (`semantic/validate/struct_cycle.rs`)

Граф по **сырым** полям АСД, проверка стоит до регистрации имён — тем же
приёмом, что `SE-039` (Ce16) для псевдонимов.

##### 5. Три шага собраны в `type_registry::prepare_types`

`tree.rs` сверх лимита размера (1500 строк при пороге 1000), и проверка
`check-module-size.sh` отверг рост на 13 строк — это его замысел: новое
выносится, а не дописывается. Порядок шагов (цикл → занятие имён → псевдонимы)
живёт одной функцией с обеими гарантиями в док-строке, а `tree.rs` несёт **один**
вызов и стал на строку короче прежнего; запись реестра долга уменьшена.

#### Ловушки (проверено прогоном)

**Завершение `resolve_aliases` держит чужая проверка.** Циклы среди
псевдонимов отсекает `SE-039`, стоящая **выше** в том же файле; без неё цикл
«до неподвижной точки» не завершился бы. Зависимость по порядку, в коде она не
видна — отсюда явная оговорка в док-строке.

**Узлами графа `SE-124` служат и псевдонимы.** `struct P { r: Ref }`,
`type Ref = Q;`, `struct Q { p: P }` — цикл, замкнутый через псевдоним;
без этих рёбер он просочился бы. Сообщается при этом о **структуре**: её автор
вправе исправить, а чисто псевдонимный цикл судит `SE-039`.

**Обход спускается в элемент массива:** `struct Node { kids: [Node; 2] }` —
тот же цикл.

#### Границы

- Умолчание переменной у цели `c`: `_init` не обнуляет **ни одну** переменную
  без инициализатора, тогда как эталон и остальные семь целей дают ноль.
  Обнаружено при постройке сверки (харнесс читал мусор стека); в объём фичи не
  входит, вынесено кандидатом. В харнессе сверки причина снята явным `= {0}` с
  комментарием — правило 30, «одна причина за раз».

### Слои проверки

| Слой | Что доказывает |
|---|---|
| 1. вердикт семантики | запись принимается либо отвергается нужным кодом |
| 2. потактовая сверка | поле, объявленное ниже, **читается верно** — эталон и цель `c` дают одну трассу |

Второй слой обязателен: до фичи эталон вход **исполнял**, но поле-структура
становилась числом. Компиляция такого не видит — расхождение в значениях.

### Примеры (правило 16)

| № | Вход | Ожидание |
|---|---|---|
| П1 | `struct Aa { b: Bb }` выше `struct Bb` | принято |
| П2 | `struct Cfg { m: Mode }` выше `enum Mode` | принято |
| П3 | `struct Holder { cells: [Cell; 2] }` выше `struct Cell` | принято |
| П4 | `type Alias = Point;` выше `struct Point` | принято |
| П5 | `type A = B;` выше `type B = u8;` | принято |
| П6 | взаимный цикл `A → B → A` | `SE-124` |
| П7 | самоссылка через массив `[Node; 2]` | `SE-124` |
| П8 | цикл через псевдоним `P → Ref → Q → P` | `SE-124` |

### Контрпримеры

| № | Вход | Ожидание | Что ловит |
|---|---|---|---|
| К1 | `struct Aa { b: Nope }` | `SE-034` | «регистрируем любое имя» — опечатка перестала бы ловиться |
| К2 | два `struct S` | `SE-108` | забытое снятие старого `claim_type_name` дало бы ложную `SE-108` **везде**, а забытый предпроход — потерю проверки |
| К3 | `struct u8 { … }` | `SE-107` | занятие встроенного имени |
| К4 | цепочка `C1 → C2 → C3` без цикла | принято | «вложенные структуры запрещены» |
| К5 | `type A = B; type B = A;` | `SE-039` | порядок проверок: цикл псевдонимов судит Ce16 **раньше**, и на нём стоит завершение разрешения до неподвижной точки |

### Потактовая сверка

| № | Вход | Ожидание |
|---|---|---|
| С1 | структура, объявленная ниже места использования, поля растут по тактам | трасса эталона = трасса цели `c` |

В харнессе сверки модель обнуляется явным `= {0}`: цель `c` переменную без
инициализатора не обнуляет вовсе, и без этого мерился бы **чужой** класс

### Найденные дефекты

Исправлений не потребовалось. Две находки **в ходе** разработки:

1. **Тест на пару псевдонимов не контролировал неподвижную точку.** Мутация «один
   виток вместо повторения» его **не роняла**: финальная попытка разрешить
   остаток служит вторым проходом. Добавлен тест на цепочку из **трёх**
   (`A → B → C`) — он мутацию ловит. Это ровно тот случай, когда контроль
   выглядит достаточным и не является им.
2. **Умолчание переменной у цели `c` — мусор стека.** Обнаружено при постройке
   сверки: харнесс читал 339 вместо 3. `Nodefault_init` ставит только `state`,
   переменные без инициализатора не обнуляются вовсе, тогда как эталон и семь
   остальных целей дают ноль. В объём фичи не входит (её предмет — видимость
   имени типа), вынесено кандидатом; в харнессе причина снята явным `= {0}` с
   комментарием — правило 30, «одна причина за раз».

## Итог (что сделано)

**Порядок объявления типов перестал быть значимым, а структура больше не может
содержать себя.** Версия языка `0.10.0` → `0.11.0`.

- **Имена всех типов занимаются предпроходом** (`type_registry::predeclare_named_types`
  — воронка 0243 переехала выше по конвейеру), псевдонимы разрешаются **до
  неподвижной точки**. Прежде объявления строились одним проходом в порядке
  текста, и ломались **пять** форм: поле-структура, поле-перечисление, элемент
  массива, псевдоним на структуру, псевдоним на псевдоним.
- **Подмена ошибки снята:** `construct_type(...).unwrap_or(TypeNode::Unsupported)`
  глотал диагностику, из-за чего эталон исполнял модель с полем-структурой,
  ставшей числом, — молча.
- **`SE-124`** (`validate/struct_cycle.rs`): цикл структур, в том числе через
  элемент массива и через псевдоним. Пока порядок был значим, такая запись была
  **недостижима**; снятие зависимости сделало её разрешимой, поэтому запрет
  введён той же фичей.
- **Завершение разрешения псевдонимов держит `SE-039`** — она отсекает
  циклы среди них раньше. Зависимость по порядку проверок, в коде не видная.
- **Контроль на пару псевдонимов оказался недостаточным:** мутация «один виток
  вместо повторения» его не роняла, потому что финальная попытка служит вторым
  проходом. Настоящий контроль — цепочка из **трёх**.
- Заведён кандидат: цель `c` не обнуляет переменные без инициализатора вовсе
  (мусор стека), тогда как эталон и семь остальных целей дают ноль.
