# Фича: предкоммит не видит файлов вне индекса

- **Номер:** 0538
- **Статус:** ОТМЕНА
- **Зависит от:** нет

## Краткое описание

Часть проверок предкоммита берёт список файлов из индекса (`git ls-files`), и
новый файл, ещё не добавленный, для них не существует. Прогон отвечает успехом,
а тот же прогон после `git add` находит нарушения: «зелёный предкоммит» оказался
обещанием, которого он не давал. Предмет фичи — сделать границу видимой: либо
проверка судит рабочее дерево, либо предкоммит говорит вслух, чего он не смотрел.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

### Замер при заведении (2026-09-07)

Снят заново; класс воспроизведён на живом дереве.

- **Один и тот же файл судится по-разному.** Проба `scripts/probe-untracked.sh`
  с комментарием, нарушающим правило (номер работы в тексте): вне индекса —
  `check-comments.py` **зелёный**; после `git add` — отказ с находками `C2` и
  `C10` на том же файле, той же строке.
- **Цена уже уплачена.** Так коммит фичи
  [проверка, читающая документ, отказывает на пустой выборке](0536-gate-empty-selection.md) попал в историю не проходящим
  собственный предкоммит: три новых файла были вне индекса
  ([исправление](../fixes/0536-01-gate-empty-selection.md)).
- **Область — три проверки из 49**: `check-comments.py`,
  `check-legacy-names.sh`, `check-build-artifacts.py`. Двадцать обходят рабочее
  дерево напрямую и класса не имеют; остальные судят названные точки.
- **Одна из трёх судит индекс правильно.** `check-build-artifacts.py` ищет
  артефакты сборки, и её заголовок это объясняет: файл вне индекса вреда не
  делает, его отсекает `.gitignore`. Предмет её правила — свойство
  **репозитория**, и индекс тут верная область.
- **Две другие судят свойство самого файла** — комментарий описывает назначение
  кода; старое имя языка не встречается в рабочем файле. Для них выпадение
  нового файла из выборки означает пропуск, а не сужение.

## Документирование

Не требуется: язык не меняется. Предмет — область, которую судят проверки
предкоммита; процесс разработки в [`book/`](../../book/) не попадает по своду.

## Итог (отмена)

**Фича отменена решением заказчика 2026-09-07**, на стадии регистрации, до
архитектурной проработки. Причина решением не названа, и придумывать её здесь
нечем: запись отражает то, что было сказано.

**Что остаётся в силе.** Класс не опровергнут — он воспроизведён замером и
записан выше: один и тот же файл вне индекса даёт зелёный прогон проверки
комментариев, а после `git add` — отказ с находками на той же строке. Цена
однажды уже уплачена: коммит фичи
[проверка, читающая документ, отказывает на пустой выборке](0536-gate-empty-selection.md) попал в историю не проходящим
собственный предкоммит ([исправление](../fixes/0536-01-gate-empty-selection.md)).

**Чем это компенсируется сейчас.** Порядком работы, а не машиной: `git add`
делается **до** прогона предкоммита, и тогда его выборка совпадает с тем, что
уйдёт в коммит. Приём дешёвый и надёжный ровно настолько, насколько его помнят;
машинной опоры у него нет, и это остаётся известной слабостью процесса.

**Что уточнил замер — на случай возврата к теме.** Область меньше, чем говорил
кандидат: список из индекса берут три проверки из 49, и одна из них судит индекс
**правильно** — `check-build-artifacts.py` ищет артефакты сборки, а файл вне
индекса вреда не делает. Правило нужно двум проверкам, чей предмет есть свойство
самого файла: комментарий описывает назначение кода, старое имя не встречается в
рабочем файле. Работа, если её возобновят, начинается отсюда, а не с общего
списка.
