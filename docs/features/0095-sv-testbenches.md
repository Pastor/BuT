## Краткое описание

Для каждого транслируемого целью `sv` примера (`stacker`, `elevator_mini`)
заведён рукописный тестбенч, который прогоняет порождённый модуль на осмысленном
сценарии, проверяет наблюдаемое поведение `assert`-ами и снимает осциллограмму
`<module>.vcd` для просмотра в [GTKWave](https://gtkwave.sourceforge.net/).
Сборка и прогон тестбенчей встроены в проверка цели `sv` в `precheck.sh`.

> Фича зарегистрирована по запросу заказчика; проведена без полного жизненного
> цикла (аддитивная, без изменений языка и генератора).

## Итог (что сделано)

- **Тестбенчи в `examples/generated/sv/tb/`** — `stacker_tb.sv`,
  `elevator_mini_tb.sv`, плюс `README.md` и `.gitignore` (осциллограммы и сборка
  Verilator — артефакты, не исходники). Каталог — подкаталог `tb/`, поэтому глоб
  `$SV_OUTPUT/*.sv` проверки цели `sv` их **не** подхватывает и не пытается
  линтовать/синтезировать как самостоятельные модули.

- **Тестбенчи написаны руками, а не порождаются `lamc`** — тестбенч есть
  принадлежность проверки, а не продукта (решение открытого вопроса 0045-07, тот
  же принцип, что у `conformance_sv_tests.rs`). Генератор не должен уметь то, что
  нужно только тестам.

- **Двойная роль каждого тестбенча.** (1) *Проверка функционирования*: `assert`
  на наблюдаемое поведение, провал → `$fatal` → ненулевой код выхода → красный
  предкоммит. (2) *Осциллограмма*: `$dumpfile`/`$dumpvars` пишут `<module>.vcd`
  для GTKWave.

- **Замкнутая среда ведёт автомат через весь цикл без ручной подгонки тактов.**
  У `stacker` положение тележки берётся обратной связью из скомандованной цели
  (`pos_* ⇐ cmd_target_*`), а датчик груза следует фазе вил
  (`sense_loaded = ~lift_op`) — так автомат проходит забор → ячейку → завершение
  и поднимает `cmd_ack`/`cmd_fork`/`cmd_done`. У `elevator_mini` «физика лифта»
  довозит кабину по этажу за такт через концевики, вычисляемые из внутренних
  текущего/целевого этажа; проверяются `ElevatorMotor_Up`, `DoorOpen`, приезд
  (`AT_FLOOR`). Обратная связь идёт **только через регистры** — комбинационной
  петли (`UNOPTFLAT`) нет.

- **Проверка — «событие когда-нибудь произошло»**, а не привязка к номеру такта:
  устойчиво к сдвигу на один такт. Потактовую *эквивалентность* RTL и симулятора
  по-прежнему доказывает строгая сверка `conformance_sv_tests.rs` — эти
  тестбенчи её не дублируют, а дают демонстрацию поведения и источник
  осциллограмм.

- **Проверка тестбенчей цели `sv` в `precheck.sh`** — после проверок линта (`verilator
  --lint-only`) и синтеза (`yosys`). Собирает `tb/<name>_tb.sv` вместе с модулем
  через `verilator --binary --timing --trace`, запускает в каталоге `tb/`
  (осциллограмма ложится рядом), валит предкоммит на провале `assert`. Список
  модулей — тот же `$SV_TRANSLATABLE`: у каждого обязан быть парный
  `tb/<name>_tb.sv`, иначе проверка краснеет. Деградация мягкая (нет `verilator` →
  пропуск локально); в CI отсутствие инструмента уже ловит проверка линта выше
  (`SV_GATE_REQUIRED=1`).
