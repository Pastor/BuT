## Краткое описание

**Ребро, стоящее после безусловного, недостижимо — и об этом молчат все пять
потребителей.** Замер при закрытии
[цель c печатает лишний break после безусловного перехода](0213-c-redundant-break.md) (2026-08-17): запись
`ref Done; ref Late: n = 1;` законна, но второе ребро не срабатывает никогда —
эталон берёт первое, а цели `rust`/`st`/`sv` и (с этой фичи) `c` его вовсе не
печатают. Автор об этом не узнаёт: диагностики нет ни у семантики, ни у целей.
Проверка недетерминизма (`check_nondeterministic_transitions`, Ce14) класс
не покрывает — она ищет **несколько** безусловных рёбер, а здесь безусловное
одно. В корпусе `examples/` такой записи нет ни одной, то есть класс живёт
только в фикстурах — тем важнее сказать о нём автору. Кандидат:
предупреждение уровня семантики «ребро недостижимо: стоит после безусловного
перехода», по образцу Ce14 (место — `semantic/validate/`, доставка — через
`collect_model_warnings`).

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

## Что известно на входе

своим замером и ссылками на фичу, при закрытии которой он был вынесен. Ничего
сверх этого не проверялось.

### Context

Переходы состояния проверяются **по порядку записи**, и первое безусловное ребро
завершает выбор: записанное после него не сработает никогда. Правило исполняют
эталон и все четыре цели — фича сравняла с ними цель `c`, изъяв из её
вывода недостижимый хвост.

**Замер-19:**

```takt
start Run {
    always { n := n + 1; }
    ref Done;
    ref Late: n = 1;   // не сработает никогда
}
```

`taktc compile` завершался **успешно и молча**; эталон уходил в `Done` на первом
такте; ни семантика, ни цели не сообщали ничего.

**Ce14 (`SE-037`) класс не покрывает:** она ищет **несколько** безусловных
рёбер, а здесь безусловное одно — лишними оказываются условные за ним.

**Корпус класс не покрывает:** прогон `taktc` по всем `examples/*.takt` даёт
ноль срабатываний, то есть запись живёт только в фикстурах. Тем важнее сказать о
ней автору: сам он её не встретит и правила не узнает.

### Decision Drivers

1. **Молчание об исполняемом правиле дороже строгости.** Правило есть, его
   исполняют шесть потребителей, а знает о нём только тот, кто читал 0213.
2. **Запись законна и её смысл определён** — недостижимое ребро ничего не
   делает; отказ ломал бы работающие входы.
3. **Что считать безусловным, решает один предикат** (`is_unconditional`): второго знания об этом заводить нельзя.

### Considered Options

#### Option A. Ничего не делать

**Cons:** автор пишет ребро, оно выглядит работающим, а не работает. Ошибка
находится наблюдением за прошивкой, а не сборкой.

#### Option B. Ошибка семантики

**Cons:** сужает язык там, где смысл определён; ломает существующие фикстуры.
Правило «безусловное завершает цепочку» — про исполнение, а не про законность.

#### Option C. Предупреждение `SE-116`, по образцу Ce14

**Pros:**
- автор узнаёт о правиле в момент, когда оно на него влияет;
- ничего не ломается: код возврата не меняется;
- доставка — существующей точкой `collect_model_warnings`, то есть и в CLI, и в
  редакторе.

**Cons:** ещё одно предупреждение в общем потоке — цена приемлема, потому что
класс редок (в корпусе ноль).

### Decision

Принимается **Option C**. Проверка — `semantic/validate/unreachable_edge.rs`:
находит **первое** безусловное ребро и высказывается о **каждом** следующем
(правило: одна диагностика на элемент, все элементы высказываются).
Позиция — у самого ребра (`ReferenceNode::location`), текст называет оба имени.

### Consequences

#### Положительные

- Правило, исполняемое шестью потребителями, стало видимым автору.
- Позиция указывает на само недостижимое ребро.

#### Отрицательные / Action items

- Предупреждение появится у существующих фикстур с такой записью — это
  замысел, а не регресс.
- **Ce14 не поглощена:** два безусловных ребра по-прежнему дают `SE-037`;
  второе из них вдобавок недостижимо и получает `SE-116`. Разные вопросы —
  разные коды.

#### Acceptance criteria

1. `ref Done; ref Late: n = 1;` даёт `SE-116` с обоими именами (A1).
2. Высказываются **все** недостижимые рёбра, а не первое (A2).
3. Контроль: условное перед безусловным молчит (A3).
4. Контроль: корпус чист (A4).
5. Ce14 остаётся при своём (A5).
6. `./scripts/precheck.sh` зелён (A6).

## Разработка

### Задача

#### Что было

Правило «первое безусловное ребро завершает выбор» исполняли эталон и все
четыре цели, а диагностики о нём не было ни у семантики, ни у целей: `taktc
compile` на записи `ref Done; ref Late: n = 1;` завершался успешно и молча.

#### Что сделано

Новый модуль `semantic/validate/unreachable_edge.rs`: находит **первое**
безусловное ребро состояния и высказывается о **каждом** следующем — правило («одна диагностика на элемент, все элементы высказываются»). Позиция берётся
у самого ребра (`ReferenceNode::location`), текст называет оба имени и способ
исправить.

- **что считать безусловным** — спрашивается у `ConditionNode::is_unconditional`: второго знания об этом не заводится;
- **доставка** — через `collect_model_warnings`, то есть и в
  CLI, и в редакторе;
- **обход вложенных моделей** — рекурсивный, как у соседних проверок.

Реестр диагностик пополнен записью `SE-116`; документ — приложение «Ошибки» и
блок «Частые ошибки» раздела о моделях.

#### Проверки

```sh
cargo test --test semantic unreachable_edge   # 5 тестов, включая обход корпуса
cargo test --all-features                     # 3273 теста
./scripts/check-diagnostic-codes.sh           # реестр согласован (257 кодов)
./scripts/precheck.sh                         # полный гейт
```

**Ложных срабатываний на корпусе нет** — проверено прогоном `taktc` по всем
`examples/*.takt` и закреплено тестом T4: класс живёт только в фикстурах, и
если проверка начнёт срабатывать в корпусе, значит она ловит не то.
