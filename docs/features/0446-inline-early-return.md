# Фича: Подстановка тела с ранним возвратом

- **Номер:** 0446
- **Статус:** ГОТОВО
- **Зависит от:** [инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md)
- **Tier:** 4 (речь о форме порождённого кода: подстановка становится доступна
  телу, которое прежде оставалось вызовом)
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат, заведённый фичей
  [инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Первая редакция подстановки ([инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md))
подставляла только тело с **единственным хвостовым** `return`; всё остальное
получало `SE-128` (под атрибутом) либо оставалось вызовом (под эвристикой).
Замер показал, что под это правило не подпадают **восемь функций корпуса
из четырнадцати**. Фича снимает ограничение: тело с ранним выходом
подставляется через **признак выхода**.

> Фича заведена из блока кандидатов (правило 28).

## Документирование (правило 24)

**Требуется** — меняется наблюдаемая граница языка: раздел
[«Функции»](../../book/src/07-functions/) (что подставляется, а что нет) и
приложение [«Ошибки»](../../book/src/appendix-errors/) (смысл `SE-128` стал
уже, а причина отказа — названной).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

Подстановка заменяет вызов значением, а ранний `return` означает, что значение
берётся из середины тела. Классический приём — признак выхода: результат
объявляется переменной, каждый возврат пишет в неё, а операторы после
возможного выхода идут под условием «выхода ещё не было».

### Decision

Понижение живёт в `semantic/inline/early.rs` и строит:

```text
var <ret>: T := <умолчание>;
var <done>: bit := 0;          // только если признак кто-то читает
… тело, где `return e` → `<ret> := e; <done> := 1;`
… операторы после возможного выхода — под `if !<done> { … }`
```

Форма выбрана **прогоном** (правило 30, замеры ниже), а не рассуждением:

1. **Результат объявляется с начальным значением.** Вариант «объявление без
   инициализатора» валиден у семи потребителей, а `rustc` отвечает `E0381:
   used binding is possibly-uninitialized`: его анализ не знает, что один из
   путей срабатывает всегда.
2. **Возврат в хвостовой позиции признак не взводит.** Иначе последняя запись
   мертва, и `rustc` под `-D warnings` отвечает «value assigned to … is never
   read».
3. **Признак объявляется, только если читается.** Тело, где обе ветви `if/else`
   возвращают, обёрток не порождает — признак там лишний.

### Considered Options

- **A. Признак выхода** — принят.
- **B. Разворот в тернарное выражение** (`ret := c ? a : b`) — отвергнут:
  выражается лишь для тел, где ветвление и есть весь возврат; операторы между
  возвратами так не переносятся.
- **C. Оставить границу как есть** — отвергнут: под правило не подпадает
  больше половины корпуса, то есть подстановка есть, а применить её почти
  негде.

### Consequences

`SE-128` сужается до трёх случаев: `return` внутри цикла, отсутствие `return`
вовсе, тип результата без начального значения. Причина теперь **называется** —
прежде текст говорил только «возврат обязан быть последним».

#### Acceptance criteria

- A1. Тело с ранним выходом подставляется, и трасса совпадает с эталоном.
- A2. Признак не заводится там, где его никто не читает.
- A3. Вывод принимают все восемь целей и их инструменты.
- A4. Возврат внутри цикла: под атрибутом — `SE-128` с причиной, под
  эвристикой — вызов остаётся вызовом.

## Анализ

### Цель и контекст

Предмет — форма порождённого кода. Проверяемое условие: значения не меняются,
а вывод остаётся валидным у всех потребителей.

### Замер (правило 30, 2026-08-31)

| Что мерилось | Результат |
|---|---|
| форма «объявление без инициализатора + условные присваивания» | 7 потребителей приняли, `rustc` — `E0381` |
| та же форма с начальным значением | приняли **все восемь**, включая `iec2c`+`cc`, `clippy -D warnings`, `verilator`, `yosys` |
| хвостовой возврат, взводящий признак | `rustc`: «value assigned to `takt_inline_1_done` is never read» |
| `return` внутри цикла, эвристика | **дефект первой сборки:** `return` доезжал до тела состояния, и цель `c` печатала `return` посреди `tick` — выход из такта при нулевом коде возврата |

Последняя строка — довод в пользу правила 30: класс нашёлся прогоном, а не
чтением кода, и ни одна проверка цели его бы не увидел (вывод валиден).

### Зависимости фичи (правило 17/19)

[инлайнинг функций: эвристика по размеру и атрибуты inline/noinline](0444-function-inlining.md) — сама подстановка и её носители имён.

### Требования и проверяемые условия

- R1. A1…A4 выше.
- R2. Препятствие спрашивается **и** судьёй атрибута (`SE-128`), **и** самим
  проходом: под эвристикой отказа быть не должно, а подставить непригодное
  тело нельзя.

### Критерии приёмки и способ проверки

Потактовая сверка на фикстуре с тремя порогами
(`conformance_inline_tests::early_return_inlining_matches_reference`),
эмиссионные тесты формы и границы, мутации, полный `precheck.sh`.

### Редакторский слой (правило 29)

**Не затронут:** ни лексика, ни синтаксис не меняются — правило целиком живёт
в семантике.

### Особенности по обратной функциональности

Вывод корпуса при умолчании (`--inline=off`, без атрибутов) не меняется:
подстановка по-прежнему делается только по указанию автора либо по флагу.

### Риски и зависимости

Главный риск — форма, валидная у одного потребителя и негодная у другого; он
снимается прогоном всех восьми целей и их инструментов (`probe.sh`) плюс
потактовой сверкой, которую эталон судит **вызовом**, а не подстановкой.

## Разработка

- `semantic/inline/early.rs` — понижение и препятствия (`Obstacle`), умолчание
  типа результата (у перечисления — **первый по тексту** вариант);
- `semantic/inline/mod.rs` — выбор формы: хвостовой возврат прямо, иначе
  признак выхода; препятствие спрашивается до подстановки;
- `semantic/function.rs` — `SE-128` теперь несёт **названную** причину.

## Итог

Подстановка перестала быть привилегией тела с единственным хвостовым
возвратом: ранний выход выражается признаком, а `SE-128` сузился до трёх
случаев и называет причину. Названной границей остаётся `return` внутри цикла —
её снятие потребовало бы `break` под тем же признаком, а у цели `sv` цикл ещё и
разворачивается при элаборации (0321).
