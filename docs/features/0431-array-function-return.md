# Фича: Массив как возврат функции: st и sv порождают невалидный вывод

- **Номер:** 0431
- **Статус:** ГОТОВО
- **Зависит от:** 0348 (массив в параметре у `st`), 0369 (массив в параметре у `sv`), 0400 (подъём во временную)
- **Tier:** 2 — невалидный вывод при рапорте об успехе: чужой инструмент отвергает порождённый файл, а `taktc` возвращает ноль
- **Класс:** генерация
- **Связанные issue (анализ):** новая фича, найдена пробой 2026-08-23

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**.

## Краткое описание

`fn pair(base: u8) -> [u8; 2]` — эталон исполняет, `rust` переводит, `c`
честно отказывает, а **`st` и `sv` печатали файл, который отвергают их же
инструменты**. Теперь `st` объявляет возврат именованным типом, `sv` — через
`typedef`, а индексация результата вызова разворачивается во временную
переменную в семантике.

## Документирование

**Не требуется.** Язык не менялся: возврат массива был законен и прежде —
менялось то, что цели с ним делают.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-23
- **Authors:** архитектор, разработчик

### Context

**Замер-23** (проба + прогон инструментов целей):

| Потребитель | Возврат массива | Индексация результата `pair(k)[1]` |
|---|---|---|
| эталон | исполняет (2, 3, 4) | исполняет |
| `c`, `c-hal` | `CC-015` — честный отказ | `CC-015` |
| `rust` | переводит, `rustc` принимает | переводит |
| **`st`, `st-at`** | **невалидный ST**: «invalid return type defined in function declaration» | **невалидный ST**: «';' missing at the end of statement» |
| **`sv`, `sv-mmio`** | **невалидный RTL**: verilator «Illegal assignment», yosys «Insufficient number of array indices» | verilator **принимает**, yosys «syntax error, unexpected '['» |

Второй слой (индексация результата) виден **только одному** инструменту из
двух — тот случай, ради которого проверка цели `sv` держит и verilator, и yosys.

### Decision Drivers

- Отказ был бы сужением языка: эталон и `rust` запись исполняют.
- Годная форма есть у обеих целей — это установлено **пробой**, а не чтением
  стандарта.

### Considered Options

1. **Отказать у `st` и `sv`.** Отвергнуто: два потребителя запись уже
   исполняют.
2. **Формы, найденные пробой** (принято): у `st` — именованный тип (как у
   параметра-массива, 0348), у `sv` — `typedef` возвращаемого типа.

### Decision

- `st`: тип возврата-массива печатается **именованной формой**
  (`TAKT_ARR_2_USINT`), а сбор форм берёт тип возврата наравне с параметрами —
  объявление типа и ссылка на него совпадают по построению.
- `sv`: перед функцией печатается `typedef <prefix> <имя>_ret_t <suffix>;`, и
  функция возвращает его. Прежде печатался один `prefix`, а распакованная
  размерность терялась молча.
- Индексация результата вызова **разворачивается в семантике**:
  `probe := pair(k)[1];` → временная переменная, присваивание, индексация её.
  За границей семантики этой формы не существует, и печатники целей о ней не
  знают.
- `c` остаётся с отказом `CC-015`: массив из функции в C не возвращают, а
  обёртка-структура была бы изобретением цели.

### Consequences

- Возврат массива переводят `rust`, `st`, `sv`; `c` отказывает названной
  границей.
- Вывод корпуса не изменился: функций, возвращающих массив, в `examples/` нет.

#### Acceptance criteria

Трассы эталона, `rust`, `st` и `sv` совпадают; модуль синтезируется `yosys`.

## Разработка

### Задача

#### Что было

`st_func`: `FUNCTION f : ARRAY [0..1] OF USINT` — анонимная форма.
`sv_func`: печатался только `ret_ty.prefix`, размерность терялась.
Индексация результата вызова печаталась буквально.

#### Что сделано

- `st_decl_types.rs` — сбор форм берёт и тип возврата.
- `st_func.rs` — возврат печатается именованной формой.
- `sv_func.rs` — `typedef` возвращаемого типа при непустом суффиксе.
- `semantic/slice/argument.rs` — подъём результата вызова во временную.

#### Проверки

Пробы форм обоими инструментами, три мутации, шесть тестов набора, предкоммит.

### Результаты по функциональности

Три мутации подтвердили контрольных тестов: анонимный тип возврата у `st`, потерянный
`typedef` у `sv`, снятый разворот индексации — каждая роняет свой тест.

### Найденные дефекты

**Класс двухслойный, и второй слой видит один инструмент из двух:**
`pair(k)[1]` verilator принимает молча, отвечает только yosys. Без второго
инструмента правка выглядела бы законченной.

**Форма для `sv` выбрана прогоном, а не чтением стандарта:** возврат
именованного типа принимают оба, а индексацию результата вызова — только
verilator; поэтому разворот и сделан в семантике, где его видят все цели.

### Выводы и дальнейшие шаги

Отказ цели `c` оставлен названной границей: в C массив из функции не
возвращают.

## Итог (что сделано)

`fn f() -> [T; N]` порождал у `st` и `sv` файл, который отвергают их же
инструменты, — при нулевом коде возврата `taktc`. Теперь `st` печатает возврат
**именованным** типом, `sv` — через `typedef`, а индексация результата вызова
разворачивается во временную переменную **в семантике**.

**Второй слой класса виден только yosys:** `pair(k)[1]` verilator принимает.

**Цель `c` отказывает намеренно** — массив из функции в C не возвращают, и
обёртка-структура была бы изобретением цели.

Контроля — потактовые сверки с `rust`, `st` и `sv`, синтез `yosys` и
тест-граница на отказ `c`.
