>
> Замеры кандидата **не перепроверялись** при переводе в фичу: их
> актуальность подтверждает пробой стадия архитектуры (урок — записи
> кандидатов устаревают, и две из них оказались неверны).

**Класс:** семантика языка (Tier 2 — приоритет по решению заказчика
2026-08-03: синтаксис → семантика → генерация → остальное).

**Вывод типов не протягивает тип через ссылку константа→константа.** Замер при
разработке [`after` принимает константу типа `duration`, а не только литерал](0143-after-const-duration.md) (2026-07-29):
`const BASE := 2s; const DWELL := BASE;` даёт `DWELL` тип **`Inference`**, а
`const DWELL := BASE + 1s;` — **`Unsupported`**, хотя в обоих случаях значение
очевидно `duration`. Вычислителю выдержки пришлось из-за этого трактовать оба
типа как «вывод не дошёл» и решать **по значению**: иначе автор получал бы
сообщение о слабости вывода типов вместо ошибки в своей записи.
Последствия шире выдержки: любая проверка, которая доверится типу такой
константы, увидит `_`. Молчаливым дефект **не является** — тип
недоопределён, а не неверен.

## Архитектура (ADR)

- **Status:** Accepted (Option C)
- **Date:** 2026-08-16
- **Authors:** Архитектор
- **Related issues:** [Фича](0204-const-ref-type-inference.md); замер при разработке [`after` принимает константу типа `duration`, а не только литерал](0143-after-const-duration.md); смежно с [ADR](0192-const-init-fold.md#архитектура-adr) (свёртка инициализатора идёт после вывода типов), [ADR](0096-fixed-point-native-float.md#архитектура-adr) (две редакции `VariableNode`)

### Context

Документ обещает вывод типа **из выражения**: «Если у объявления есть
инициализатор, тип можно не указывать — компилятор выведет его из выражения»
(раздел «Типы», подраздел «Вывод типов»). Обещание исполняется только для
литералов.

#### Замер 1: что получают объявления сегодня (2026-08-16)

| Запись | Тип сегодня | Ожидаемо |
|---|---|---|
| `const BASE := 2s;` | `Duration` | ✅ |
| `const DWELL := BASE;` | **`Inference`** | `Duration` |
| `const S := 2s + 1s;` | **`Unsupported`** | `Duration` |
| `const Z := 5; const A := Z;` | **`Inference`** у `A` | `[bit;8]` |
| `var a := 5; var b := a;` | **`Inference`** у `b` | `[bit;8]` |
| цепочка `A → B → C` | `Inference` у `B` и `C` | `[bit;8]` |
| `const A: u16 := 5; const B := A;` | `u16` ✅ | работает — у источника **явный** тип |

#### Замер 2: причин **две**, и они независимы

**П1 — снимок ячейки.** `ExpressionNode::Variable` несёт
`Rc<RefCell<VariableNode>>`, который `expression::construct_expression` создаёт
как `Rc::new(RefCell::new(var.clone()))` — то есть **копию на момент разрешения
имени**. Разрешение идёт **до** вывода типов (`declaration::prepare_variables`:
разрешить → вывести → свернуть), поэтому в ячейке навсегда остаётся `Inference`.
Обновить ячейку нельзя: копий у переменной столько, сколько упоминаний. Отсюда и
работающий случай «источник с явным типом»: там снимок сделан уже с типом.

**П2 — `wider_type` не знает длительностей.** Правила `(Duration, Duration)` нет
вовсе, поэтому `const S := 2s + 1s;` — **без единой ссылки** — даёт
`Unsupported`. Смешение длительности с числом до этой ветви не доходит: его
отвергает `SE-065` (проба).

Числовая арифметика через ссылку (`const B := A + 1;`) работает **случайно**:
`wider_type(Inference, Array(8,Bit))` попадает в правило `(_, Array(n, t))` и
берёт тип **литерала**. То есть «работает» и «выведено верно» здесь — разные
вещи.

#### Замер 3: цена — форма не исполняется никем

`var x := 42; var y := x;` — запись, которую фикстура
`takt-lang/tests/data/semantic/valid/ce6_type_inference_chain.takt` объявляет
образцом («тип `y` выводится из переменной `x`; ожидается: типы выведены
корректно»):

| Потребитель | Ответ |
|---|---|
| цель `c` | `CC-015` «тип не представим в C» |
| цель `rust` | `RS-014` «тип `_` не представим» |
| цель `st` | `ST-002` «вывод типов не завершён» |
| цель `sv` | `SV-002` «внутренний либо неразрешённый тип» |
| симулятор | `SIM-007` **в такте**, шаг 1 |

То есть дефект **не** «тип недоопределён, но безвреден» (так его описывал
кандидат): язык принимает программу, а исполнить её не может **ни один** из пяти
потребителей.

**Контроль был декоративен.** Тест фикстуры (`semantic_tests/part4.rs`)
проверяет, что файл **разбирается без ошибок**, — и проходил всё это время,
пока обещанный им вывод типа не работал. Класс знаком проекту: тесты на
структуру вместо теста на язык.

#### Замер 4: корпус

226 файлов корпуса строят дерево; объявлений без выведенного типа — **одно**, и
это та самая фикстура. То есть исправление не может изменить вывод корпуса.

### Decision Drivers

1. **Обещание документа обязано исполняться.** Раздел «Вывод типов» говорит «из
   выражения», а не «из литерала».
2. **Пять потребителей отказывают на законной записи** — цена измерена, а не
   предположена.
3. **Порядок «разрешить → вывести → свернуть» трогать нельзя**:
   свёртка раньше вывода даёт `bool` вместо `bit` — значение верное, тип нет.
4. **Ячейка ссылки — снимок, и это неисправимо дёшево**: обновлять пришлось бы
   все копии, а их столько, сколько упоминаний.
5. **Порядок объявлений произволен.** Таблица переменных — `BTreeMap`, то есть
   обход **алфавитный**: `const Z := 5; const A := Z;` требует, чтобы решение
   работало независимо от того, в каком порядке имена попались.

### Considered Options

#### Option A. Свернуть инициализаторы до вывода типов

Тогда `const DWELL := BASE;` пришёл бы в вывод уже литералом.

**Pros:** одна перестановка, ноль нового кода.

**Cons:** **прямо отвергнуто ADR** и проверено пробой: `var b: bit := false;
var a := b;` даст `a` тип `bool` вместо `bit`. Порядок трёх шагов — инвариант,
за который проект уже заплатил.

#### Option B. Обновлять ячейки после вывода типов

Пройти по выражениям и записать выведенный тип в каждый `Rc<RefCell<…>>`.

**Pros:** ссылка начинает отвечать правду всем потребителям, а не только выводу.

**Cons:** обход **всех** выражений модели ради типа, который потребители и так
берут из таблицы; ячеек у переменной столько, сколько упоминаний — пропущенная
даёт молча разный тип у двух копий одного имени (где ровно это и
случилось). Цена несопоставима с предметом.

#### Option C. Спрашивать таблицу объявлений, а не снимок + неподвижная точка

`extract_type` получает необязательную ссылку на таблицу в том состоянии, в
каком её видит вывод; на `Variable` со значением `Inference` тип берётся **по
имени** из таблицы. Проходы повторяются, пока хоть одно объявление получает тип
(число `Inference` строго убывает — завершение по построению). Плюс правило
`(Duration, Duration) → Duration` в `wider_type`.

**Pros:**
- лечит обе причины и не трогает порядок 0192;
- работает при любом порядке имён — цепочка `A → B → C` и обратная
  `Z → A` сходятся одинаково;
- цикл (`const A := B; const B := A;`) не зацикливает: прохода без прогресса
  достаточно для выхода, оба останутся `Inference`;
- внешние вызовы `extract_type` (генераторы, `validate`) не меняются — им
  передаётся `None`.

**Cons:**
- у функции появляется второй вход (`extract_type_known`), и рекурсивные вызовы
  обязаны тащить таблицу — забытый аргумент вернёт прежнее поведение молча;
- вывод перестаёт быть однопроходным (на корпусе — второй проход впустую).

#### Option D. Топологический порядок объявлений

Отсортировать объявления по зависимостям инициализаторов и выводить в нём.

**Pros:** один проход.

**Cons:** без Option C бесполезен — снимок ячейки остаётся устаревшим при любом
порядке. То есть это оптимизация поверх C, а не альтернатива.

### Decision

Принимается **Option C**.

- `extract_type_known(expr, model, known)` — тип с оглядкой на таблицу
  объявлений; `extract_type(expr, model)` остаётся тонкой обёрткой с `None` для
  внешних вызовов.
- На `ExpressionNode::Variable` тип берётся из снимка, а если тот `Inference` —
  **по имени из таблицы**.
- `type_inference` крутит проходы до неподвижной точки; понижение `q(m, n)`
  (0061) остаётся на **первом** проходе, чтобы поведение однопроходного случая
  не изменилось.
- `wider_type` получает правило `(Duration, Duration) → Duration`.

**Вне объёма (граница названа):** `wider_type(Integer, Array)` берёт тип
**литерала**, из-за чего `const A: u16 := 300; const B := A + 1;` даёт `[bit;8]`
и **ложную** диагностику `SE-089` («литерал 301 не помещается в `[bit;8]`»).
Механизм другой (не ссылка, а правило расширения), и лечение требует решения о
знаковости и ширине — заведено кандидатом.

### Consequences

#### Положительные

- Форма `var y := x;` и цепочки любой длины переводятся всеми целями и
  исполняются эталоном.
- `const S := 2s + 1s;` получает `Duration` — вычислитель выдержки (0143)
  перестаёт быть единственным, кто понимает такую запись.
- Обещание документа исполняется без правки документа.

#### Отрицательные / Action items

- **Совместимость:** вывод корпуса обязан остаться байт-в-байт (замер 4 говорит,
  что задет один файл фикстур, и там тип раньше отсутствовал вовсе).
- **Декоративный контроль обязан быть заменён**: тест фикстуры проверяет разбор,
  а не вывод типа. Иначе фича закроется, оставив после себя ту же дыру.
- Диагностика на записи, которая **не** выводится (цикл `A := B; B := A;`),
  остаётся прежней — типа не будет, и о нём скажут цели. Заведение
  специального кода — отдельное решение, здесь не принимается.
- Язык **не меняется**: раздел «Вывод типов» уже обещает это поведение, версия
  языка не поднимается (правило 22). В документ добавляется пример ссылки —
  ровно то, что теперь работает.

#### Acceptance criteria

1. `const DWELL := BASE;`, `var b := a;` и цепочка из трёх получают тип
   источника — при любом порядке имён.
2. `const S := 2s + 1s;` получает `Duration`.
3. Форма `var x := 42; var y := x;` переводится целями `c`/`rust`/`st`/`sv` и
   исполняется симулятором.
4. Контроль фикстуры проверяет **тип**, а не факт разбора.
5. Вывод корпуса `examples/generated/` байт-в-байт неизменен.
6. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Исполнить обещание документа «тип выводится из **выражения**» для случая, когда
выражение — ссылка на другое объявление. Решение — Option C ADR: вывод
спрашивает **таблицу объявлений**, а не снимок ячейки, и повторяет проходы до
неподвижной точки; плюс правило `(Duration, Duration)` в `wider_type`.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Смежные [константное выражение в инициализаторе объявления](0192-const-init-fold.md)
  (порядок «разрешить → вывести → свернуть») и
  [`after` принимает константу типа `duration`, а не только литерал](0143-after-const-duration.md) (вычислитель выдержки,
  единственный сегодня потребитель, умеющий такие константы) — обе закрыты.
- **Влияние на порядок разработки:** ничего не блокирует. Смежная
  [три константных вычислителя компилятора живут порознь](0208-const-evaluators-unification.md) («три константных
  вычислителя живут порознь») от этой фичи не зависит: она о **вычислении
  значения**, а здесь речь о **типе**.

### Замеры

Полностью — в ADR (замеры 1–4). Кратко:

- **З1.** Ссылка на объявление без явного типа не даёт типа вовсе; арифметика
  над длительностями даёт `Unsupported`.
- **З2.** Причины две и независимы: снимок ячейки (`Rc::new(RefCell::new(var.clone()))` до вывода типов) и отсутствие правила для длительностей в
  `wider_type`.
- **З3.** Цена: `var y := x;` отвергают **все пять** потребителей (`CC-015`,
  `RS-014`, `ST-002`, `SV-002`, `SIM-007` в такте), а контроль фикстуры проверяет
  лишь разбор.
- **З4.** В корпусе таких объявлений одно — сама фикстура; вывод корпуса
  измениться не может.

### Требования и проверяемые условия

- **R1. Ссылка протягивает тип.** `const DWELL := BASE;` и `var b := a;`
  получают тип источника.
- **R2. Порядок имён не важен.** Обход таблицы алфавитный, поэтому цепочка
  «вперёд» (`BASE → DWELL`) и «назад» (`Z → A`) обязаны сходиться одинаково;
  цепочка длины 3 — тоже.
- **R3. Арифметика длительностей.** `const S := 2s + 1s;` → `Duration`.
  Смешение с числом остаётся ошибкой `SE-065` — правило добавляется **только**
  для пары длительностей.
- **R4. Завершение.** Проходы прекращаются, когда ни одно объявление не получило
  типа. Взаимная ссылка (`A := B; B := A;`) не зацикливает и оставляет оба без
  типа.
- **R5. Порядок трёх шагов цел.** Свёртка (0192) по-прежнему **после** вывода:
  `var b: bit := false; var a := b;` даёт `a` тип `bit`, а не `bool`.
- **R6. Внешние вызовы не задеты.** `extract_type(expr, model)` сохраняет
  сигнатуру: генераторы и `validate` зовут её как прежде.
- **R7. Форма исполняется.** `var x := 42; var y := x;` переводится всеми
  целями и исполняется симулятором.
- **R8. Контроль проверяет тип.** Тест фикстуры `ce6_type_inference_chain.takt`
  перестаёт быть проверкой разбора.
- **R9. Понижение `q(m, n)` — на первом проходе.** Иначе повторные проходы
  трогали бы уже понижённые объявления.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Ссылка даёт тип источника (const и var) | значенческий тест: тип объявления после построения дерева |
| A2 | Любой порядок имён, цепочка длины 3 | тот же тест, три фикстуры-строки |
| A3 | `2s + 1s` → `Duration` | там же |
| A4 | Взаимная ссылка не зацикливает | тест с таймаутом прогона (падение = зависание) |
| A5 | `bit` не превращается в `bool` | тест порядка шагов  |
| A6 | Форма переводится и исполняется | компиляция четырьмя целями + прогон симулятора |
| A7 | Контроль фикстуры проверяет тип | замена проверки в `semantic_tests` |
| A8 | Вывод корпуса неизменен | `git status` по `examples/generated/` после предкоммита |
| A9 | Предкоммит зелёный | `./scripts/precheck.sh` |

### Особенности по обратной совместимости (правило 11)

Программы, которые компилировались, компилируются по-прежнему: изменение
**добавляет** тип там, где его не было. Программы, которые не компилировались
(`var y := x;` — отказ всех целей), начинают компилироваться — расширение
принимаемого множества, а не сужение.

Единственный класс, где ответ может измениться с одного отказа на другой:
константа-ссылка в позиции выдержки (`after N`, где `N` — ссылка на числовую
константу). Прежде тип был `Inference`, и вычислитель 0143 шёл «по значению»,
отвечая `NotLiteral`; теперь тип известен и ответом станет `WrongType` с
названием типа. Оба — ошибки, вторая точнее.

Язык не меняется: раздел «Вывод типов» уже обещает вывод «из выражения». Версия
языка не поднимается (правило 22).

### Редакторский слой (правило 29)

**Правок не требуется, обоснование:** ни лексика, ни синтаксис, ни набор узлов
АСД не меняются — меняется вывод типа, то есть содержимое поля `ty`. Списков,
параллельных ядру, у редакторского слоя по этой части нет: `hover` LSP берёт тип
из того же семантического дерева, поэтому подсказка редактора **улучшается сама**
(вместо `_` показывается выведенный тип). Новых диагностик фича не заводит.

### Документирование (правило 24)

Раздел `book/src/03-types/` («Вывод типов») **дополняется** примером ссылки на
другое объявление: сегодня раздел показывает только литералы, и читатель не
может отличить «так можно» от «так не работает». Правило раздела при этом не
меняется — оно уже сформулировано как «выведет из выражения».

### Риски

- **Р1. Забытый аргумент в рекурсии.** `extract_type_known` обязан передавать
  `known` во **все** рекурсивные вызовы; пропуск возвращает прежнее поведение
  молча. Снижение — тест цепочки через арифметику и скобки (не только голая
  ссылка).
- **Р2. Незавершение.** Снижение — выход по «прохода без прогресса» + тест
  взаимной ссылки.
- **Р3. Изменение вывода корпуса.** Снижение — A8; замер З4 говорит, что задет
  один файл фикстур.

## Разработка

### Задача

#### Что было

Обещание документа «тип выводится из **выражения**» исполнялось только для
литералов. Ссылка на объявление без явного типа не давала типа вовсе
(`const DWELL := BASE;` → `Inference`), арифметика длительностей — `Unsupported`.
Форму `var x := 42; var y := x;` отвергали **все пять** потребителей: `CC-015`,
`RS-014`, `ST-002`, `SV-002` и `SIM-007` **в такте**.

Причин две, независимых (замеры ADR):

1. **Снимок ячейки.** `ExpressionNode::Variable` несёт
   `Rc::new(RefCell::new(var.clone()))`, созданный при разрешении имени, а
   разрешение идёт **до** вывода типов — в снимке навсегда `Inference`.
2. **`wider_type` не знал длительностей** — правила `(Duration, Duration)` не
   было вовсе.

#### Что сделано

**1. Вывод спрашивает таблицу, а не снимок.** Появился
`type_inference::extract_type_known(expr, model, known)`; `extract_type` остался
тонкой обёрткой с `known = None` — внешние вызовы (генераторы, `validate`) не
тронуты. На `ExpressionNode::Variable` тип берётся из снимка, а если тот
`Inference` — **по имени** из таблицы объявлений. Таблица протаскивается во
**все** рекурсивные ветви (скобки, арифметика, тернарный, массивы,
присваивание).

**2. Неподвижная точка.** `type_inference` повторяет проходы, пока хоть одно
объявление получает тип. Завершение по построению: множество `Inference` строго
убывает, и обратно в него никто не возвращается; взаимная ссылка даёт проход без
прогресса и выход. Понижение `q(m, n)` (0061) осталось на **первом** проходе —
повторные проходы не должны трогать уже понижённые объявления.

**3. `wider_type`: `(Duration, Duration) → Duration`.** Только пара
длительностей: смешение с числом до этой ветви не доходит — его отвергает
`SE-065` (проба).

**4. Декоративный контроль заменён.** Тест фикстуры
`ce6_type_inference_chain.takt` проверял, что файл **разбирается**; теперь
проверяет **тип** `y` — то, ради чего фикстура и заведена.

**5. Документ** (`book/src/03-types/`): раздел «Вывод типов» показывал только
литералы — добавлен пример ссылки и цепочки. Правило раздела не менялось, оно
уже было сформулировано как «выведет из выражения».

**Обратная функциональность (правило 11):** множество принимаемых программ
**расширяется** (форма, которую не переводил никто, переводится всеми);
сужений нет. Язык не меняется — версия языка прежняя.

#### Проверки

- `takt-lang/tests/semantic/type_inference_chain_tests.rs` — 10 тестов (тип, порядок
  имён, цепочка из трёх, `var`, длительности, вложенные ветви, взаимная ссылка,
  контроль порядка 0192, трансляция четырьмя целями, текст объявления в C).
- `takt-sim/tests/sim/inference_chain_tests.rs` — 2 значенческих: трасса `43, 44, 45`
  и тождественность выдержки-ссылки литеральной форме.
- **Мутация:** правка `type_inference.rs` снята (`git stash`) — краснеют 8 из 10
  тестов компилятора и 1 из 2 тестов эталона.
- `cargo test` целиком и `./scripts/precheck.sh` — зелёные; вывод корпуса

1. **Кандидат был неточен, и это выяснила проба.** Запись гласила: «молчаливым

3. **Декоративный контроль заменён** — фикстура, объявлявшая себя образцом вывода

## Итог (что сделано)

Вывод типов протягивает тип **через ссылку** на другое объявление — при любом
порядке имён и на цепочке любой длины; арифметика длительностей получила тип
`Duration`. Крейты `takt-lang` (вывод типов) и `takt-sim` (только тесты).

Причин было **две**, независимых:

- **снимок ячейки** — `ExpressionNode::Variable` несёт копию переменной, снятую
  при разрешении имени, то есть **до** вывода типов; лечится тем, что вывод
  спрашивает **таблицу объявлений** по имени, а проходы повторяются до
  неподвижной точки (`extract_type_known`, `type_inference`);
- **`wider_type` не знал длительностей** — правила `(Duration, Duration)` не
  было вовсе, поэтому `2s + 1s` давало `Unsupported` **без единой ссылки**.

Цена прежнего устройства измерена: `var x := 42; var y := x;` — форма, которую
фикстура проекта объявляла образцом, — отвергалась **всеми пятью**
потребителями (`CC-015`, `RS-014`, `ST-002`, `SV-002`, `SIM-007` **в такте**), а
контроль фикстуры проверял лишь то, что файл разбирается. Контроль заменён на
проверку типа.

Отвергнуто и почему: «свернуть инициализаторы до вывода типов» — это первое
напрашивающееся решение, и оно даёт `bool` вместо `bit` (порядок трёх шагов —
инвариант ADR); контр-пример стоит в тестах. «Обновлять ячейки» — копий у
переменной столько, сколько упоминаний, а пропущенная даёт молча разные типы у
одного имени.

Живая проверка: `./scripts/precheck.sh` зелёный, вывод корпуса байт-в-байт
неизменен, мутация роняет 8 из 10 тестов компилятора. Подробности — в
[отчёте](0204-const-ref-type-inference.md#отчёт-о-тестировании); исправлений не потребовалось.

Названная граница: `wider_type(Integer, Array)` берёт тип **литерала**, из-за
чего `const A: u16 := 300; const B := A + 1;` получает `[bit;8]` и ложную
`SE-089`. Механизм другой — заведено кандидатом.
