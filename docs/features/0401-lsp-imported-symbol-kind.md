## Краткое описание

- **Вид импортированного символа неточен: `Imported` вместо «порт»/«функция».**
  Замер [символ формы import { A } объявляется видом Model](0256-lsp-import-binding-kind.md) (2026-08-19):
  имя из `import { a } from "…";` получает вид, отвечающий **любому**
  пространству имён, потому что настоящий вид записан в **чужом** файле, а
  слой `semantic::usages` однофайловый по устройству (его зовут и там, где
  рабочей области нет вовсе — подсветка, форматирование, плагины поверх
  библиотеки). Точный вид требует чтения источника, то есть либо многофайлового
  слоя, либо состояния, обязанного не устаревать, — ровно того, что ADR
  отверг замером. Сегодня вид символа читает **одно** место
  (`lsp/rename.rs` — отказ на имени модели), поэтому цена неточности мала;
  подорожает она, если вид начнёт влиять на подсветку или на автодополнение.

**Прочее — пусто.** Последняя запись — «Переезд репозитория `github.com/Pastor/BuT`» —
снята 2026-07-29 по своду: переезд **состоялся** (`origin` →
`https://github.com/Pastor/Takt.git`, проверено пушем), то есть запись описывала
как несделанное то, что уже сделано. Административная часть исполнена
заказчиком; остаточная работа по коду и докам переведена в фичу
[дочистка URL репозитория после переезда BuT → Takt](0179-repo-url-cleanup.md) — 13 живых вхождений старого имени
в манифестах крейтов, README, doc-ссылках и манифестах обоих плагинов. Старый
адрес пока работает (`GET …/Pastor/BuT` → **301**, `git ls-remote` отдаёт
коммит), то есть это не отказ, а зависимость от редиректа GitHub.

## Архитектура (ADR)

- **Status:** Proposed — исполнителю; **брать по решению заказчика** (цена сегодня мала)
- **Date:** 2026-08-22
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича](0401-lsp-imported-symbol-kind.md);
  замер — [символ формы import { A } объявляется видом Model](0256-lsp-import-binding-kind.md#архитектура-adr); отвергнутый индекс —
  [индексация рабочей области для LSP (`references`/`rename` между файлами)](0153-lsp-workspace-index.md#архитектура-adr)

### Context

Имя из `import { a } from "lib.takt";` получает вид `SymbolKind::Imported`,
отвечающий **любому** пространству имён. Настоящий вид (порт, функция,
переменная, тип) записан в **чужом** файле, а слой `semantic::usages`
однофайловый по устройству: его зовут и там, где рабочей области нет вовсе —
подсветка, форматирование, плагины поверх библиотеки.

Замер (2026-08-19) подтверждён чтением 2026-08-22: вид символа читает
**одно** место — `lsp/rename.rs` (отказ на имени модели), поэтому цена
неточности мала.

Точный вид требует чтения источника, то есть либо многофайлового слоя, либо
состояния, обязанного не устаревать, — ровно того, что ADR отверг замером
(12 мс на 347 файлов по требованию против индекса, который надо поддерживать).

### Decision Drivers

1. **Цена неточности сегодня мала** — один потребитель вида.
2. **Цена точности известна и высока** — многофайловый слой либо кэш; 0153
   отверг его замером, а 0257 (кэш по mtime) **заморожена** заказчиком.
3. **Ошибка допущения односторонняя:** `Imported` отвечает любому
   пространству, то есть даёт **лишнюю** связь внутри файла, где имя и так
   занято импортом, — а не теряет настоящую.
4. **Класс подорожает**, если вид начнёт влиять на подсветку или
   автодополнение: тогда `Imported` покажет неверную иконку.

### Considered Options

#### Option A. Оставить (статус-кво)

**Pros:** ноль работы; поведение корректно для единственного потребителя.
**Cons:** запись остаётся в бэклоге и всплывает при каждой правке слоя.

#### Option B. Читать источник по требованию — только в LSP-путях

Там, где рабочая область есть (а это ровно `references`/`rename`, 0153),
разрешать имя в источнике и брать настоящий вид.

**Pros:** не заводит состояния; пользуется уже имеющимся обходом области;
точность появляется там, где она нужна.
**Cons:** вид символа становится зависимым от контекста вызова — в
однофайловых путях (подсветка, форматирование) он останется `Imported`. То есть
знание раздваивается: «вид без области» и «вид с областью».

#### Option C. Многофайловый слой `usages`

**Cons:** отвергнут замером; воскрешать его ради вида символа
несоразмерно.

### Decision

Предлагается **Option A** (оставить) до появления **второго** потребителя вида;
если он появится — **Option B**.

Довод: сегодня вид читает одно место, и `Imported` там работает верно; Option B
раздваивает понятие «вид символа», а Option C уже отвергнут замером. Решение
брать фичу — за заказчиком.

**Сигнал к пересмотру назван:** как только вид символа начнёт влиять на
подсветку (`semantic_tokens`) или автодополнение, `Imported` станет видимой
неточностью — иконка и группа в списке окажутся неверными.

### Consequences

#### Положительные (A)

- Ноль работы; слой остаётся однофайловым, как решено 0153.

#### Отрицательные / Action items

- Неточность сохраняется; при появлении второго потребителя вида фичу надо
  брать (Option B).

#### Acceptance criteria (для Option B)

1. В путях с рабочей областью вид импортированного символа совпадает с видом
   объявления в источнике.
2. В однофайловых путях поведение прежнее (`Imported`), и это **названо** в
   коде — иначе разница читается как дефект.
3. `rename` по-прежнему «полнота в пределах рабочей области или отказ» (0153).
4. Тесты `lsp55`, `ws0153`, `goto56` зелены; `precheck.sh` зелёный.

## Анализ

### Цель и контекст

Имя из `import { a } from "…";` получает вид `Imported`, отвечающий любому
пространству имён, потому что настоящий вид записан в чужом файле, а слой
`semantic::usages` однофайловый.

### Замер (проверен чтением 2026-08-22)

- вид символа читает **одно** место — `lsp/rename.rs` (отказ на имени модели);
- слой `usages` зовётся и там, где рабочей области нет: подсветка,
  форматирование, плагины поверх библиотеки;
- точный вид требует чтения источника — многофайлового слоя либо кэша; первое
  отвергнуто замером [индексация рабочей области для LSP (`references`/`rename` между файлами)](0153-lsp-workspace-index.md), второе
  ([кэш рабочей области LSP по mtime](0257-lsp-workspace-cache.md)) **заморожено** заказчиком.

Ошибка допущения **односторонняя**: `Imported` даёт лишнюю связь внутри
файла, где имя и так занято импортом, а не теряет настоящую.

### Зависимости фичи

- **Зависит от:** нет; связана с [кэш рабочей области LSP по mtime](0257-lsp-workspace-cache.md)
  (`ЗАМОРОЖЕНА`) — если кэш когда-нибудь появится, Option C станет дешевле.
- **Влияние на порядок:** брать по решению заказчика; сигнал к пересмотру —
  появление второго потребителя вида символа.

### Требования и проверяемые условия (для Option B)

- **R1.** В путях с рабочей областью вид совпадает с видом объявления в
  источнике.
- **R2.** В однофайловых путях поведение прежнее и это названо в коде.
- **R3.** Гарантия `rename` («полнота в пределах области или отказ») не
  ослаблена.
- **R4.** Новых причин отказа не появилось; существующие
  (`UnparsableConsumer`, `AmbiguousImport`, `NameTaken`) работают.
- **R5.** Производительность не ухудшилась заметно (замер: 12 мс на 347
  файлов) — чтение источника идёт **по требованию**.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 | тесты LSP на многофайловом входе (`lsp55`, `ws0153`) |
| A2 | R2 | тест однофайлового пути + комментарий в коде |
| A3 | R3, R4 | существующие тесты |
| A4 | R5 | замер времени `references` на области (как в 0153) |

### Объём работ (Option B)

| Место | Что делается | Риск |
|---|---|---|
| `lsp/workspace.rs` | разрешение имени в источнике по требованию | средний |
| `semantic::usages` | вид символа получает контекст «есть область» | **высокий**: слой однофайловый по устройству |
| `lsp/rename.rs` | пользуется точным видом | низкий |

### Редакторский слой

Фича **сама принадлежит** редакторскому слою. Проверить надо оба плагина:
IntelliJ переименование делегирует серверу (0154), Zed своих списков не ведёт —
то есть неточность вида доедет до обоих через LSP.

### Особенности по обратной функциональности

Поведение `rename` и `references` в однофайловых путях не меняется; в
многофайловых становится точнее. Наблюдаемых регрессов не ожидается.

### Риски и зависимости

- **Раздвоение понятия «вид символа»** (с областью и без) — главный риск:
  разница обязана быть названа в коде, иначе читается как дефект.
- **Производительность:** чтение источника по требованию не должно превратиться
  в обход области на каждый запрос (замер — ориентир).

## Замер, опровергший опасение (2026-08-23)

Опасение фичи: вид `SymbolKind::Imported` подходит **любому** пространству
имён (0256), значит вхождения одноимённого символа другого рода попадут в тот
же символ — и `rename`, обещающий «полнота или отказ» (0153), испортил бы
исходник.

Вход построен так, чтобы следствие было наблюдаемо: имя `shared`
импортировано **переменной**, а в импортёре носит его **состояние**.
Компилятор такую запись принимает — пространства разные:

```takt
import { shared } from "lib.takt";

var o: u8 := 0;

start shared {
    always { o := shared; }
    ref shared;
}
```

Прогон `references_at` с двух курсоров:

| Курсор | Вхождения |
|---|---|
| имя в директиве импорта | директива + чтение `o := shared` |
| имя состояния | объявление `start shared` + `ref shared` |

**Символы разные.** Разрешение идёт по пространству **позиции**, а не
только по виду символа, поэтому неточность вида ненаблюдаема: `Imported`
подходит любому пространству лишь как **кандидат**, а выбирает вхождения
позиция.

Тест-замер оставлен в репозитории контролем этого свойства —
`takt-lang/tests/lsp/imported_symbol_kind_tests.rs`: именно оно и держит
решение «оставить как есть», и его поломка будет означать, что фичу пора
пересматривать.

## Итог (отмена)

**Отменена решением заказчика 2026-08-23** по результату замера: у неточного
вида нет наблюдаемого следствия, а Option B раздваивает знание («вид без
области» и «вид с областью») ради нулевого сегодня выигрыша.

Сделано при разборе:

- построен вход, где следствие было бы видно, и снят замер (см. выше);
- контроль `imported_name_and_state_are_separate_symbols` закреплён в
  репозитории — он проверяет свойство, на котором стоит это решение;
- фикстура `takt-lang/tests/data/ws0401/` заведена вместе с ним.

**Сигнал к пересмотру назван и не изменился:** как только вид символа
начнёт влиять на подсветку (`semantic_tokens`) или автодополнение,
`Imported` станет видимой неточностью — иконка и группа в списке окажутся
неверными. Возвращать работу тогда — **новой фичей** (`ОТМЕНА`
терминальна).
