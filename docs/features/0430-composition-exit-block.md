# Фича: Блок exit состояния-композиции исполняется 0, 1 или 2 раза

- **Номер:** 0430
- **Статус:** ГОТОВО
- **Зависит от:** 0181 (реализация состояния у эталона), 0194 (блоки уровня модели), 0303 (собственные рёбра композиции)
- **Tier:** 1 — инструменты противоречат друг другу молча: один вход давал три разных значения при нулевом коде возврата
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат блока 2 `FEATURES.md` (заведён при работе над 0427), замер расширил класс

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**.

## Краткое описание

Блоки состояния-композиции (`start All = A | B { always {…} exit {…} }`)
исполнялись по-разному: эталон **не исполнял их вовсе**, `c` и `rust` —
верно, `st` **терял** `exit`, `sv` печатал его **дважды**. Теперь все пятеро
считают одинаково: `always` — каждый такт, пока состояние активно, `exit` —
один раз при завершении.

## Документирование

**Не требуется.** Правило языка не менялось — оно уже действовало у целей `c`
и `rust`; менялось его исполнение эталоном и двумя целями. Раздел о композиции
в [`book/`](../../book/) описывает семантику, а не расхождения инструментов.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-23
- **Authors:** архитектор, разработчик

### Context

Кандидат называл **косметику**: цель `sv` печатает `state_next = …_END;` двумя
строками подряд. Замер-23 показал, что за дублем стоит **исполнение
блока**, и класс шире:

| Потребитель | `always` композиции | `exit` композиции | `exit` простого терминального |
|---|---|---|---|
| эталон | **не исполнялся** | **не исполнялся** | **не исполнялся** |
| `c`, `c-hal` | каждый такт | один раз | один раз |
| `rust` | каждый такт | один раз | один раз |
| `st`, `st-at` | каждый такт | **терялся** | один раз |
| `sv`, `sv-mmio` | каждый такт | **дважды** | один раз |

Числа замера: на `hits := hits + 1` в `exit` прошивка `c` давала `1`, RTL `sv`
— `2`, ПЛК `st` и эталон — `0`. Все инструменты вывод приняли, `taktc` вернул
ноль.

**Правило уже было установлено целями:** на простом терминальном состоянии
`exit` исполняют все четыре, и расходился только эталон (`11` против `1`).
Значит «уход в терминал — тоже выход из состояния» — не новое решение, а
существующее поведение, от которого отставал эталон.

### Decision Drivers

- Три разных значения на одном входе — класс, ради которого заведены сверки.
- Большинство и здравый смысл совпали: `exit` исполняется ровно один раз.

### Considered Options

1. **Свести всех к поведению `c`/`rust`** (принято).
2. Спросить заказчика о семантике. Отвергнуто: поведение целей единодушно на
   простом случае, то есть правило действует и решать нечего.

### Decision

- **Эталон:** уход в терминал исполняет `exit` состояния — ровно один раз
  (флаг `exited_terminal`); блоки состояния после выхода **молчат** (как ветвь
  `END` в C); модель с единственным состоянием-реализацией **не сворачивается**
  в `Parallel`, если у состояния есть свои блоки, — иначе они теряются.
- **`st`:** `emit_state_exit` печатает `exit` перед сменой состояния.
- **`sv`:** `emit_transitions` возвращает `true` и в терминальной ветви —
  вызывающий из `sv_compose` больше не печатает `exit` и `END` второй раз.

**Блоки уровня модели после завершения исполняются по-прежнему**: они и в C
печатаются до `switch` (0083/0194). Молчат только блоки состояния.

### Consequences

- Пять потребителей согласованы; вывод корпуса не изменился.
- Изменилось наблюдаемое поведение эталона на форме «состояние без переходов с
  `always`»: теперь тело исполняется **один раз**, как в прошивке.

#### Acceptance criteria

Трассы эталона, `c`, `rust`, `st` и `sv` совпадают такт в такт.

## Разработка

### Задача

#### Что было

`tick.rs`: `transitions.is_empty()` → `Terminated` без `exit`. `builder.rs`:
модель с единственным состоянием-реализацией сворачивалась в `Parallel`, теряя
блоки состояния. `st_compose.rs`: выход из композиции печатался без `exit`.
`sv_fsm.rs`: терминальная ветвь возвращала `false`, и `sv_compose` печатал всё
второй раз.

#### Что сделано

- `takt-sim/src/unit/mod.rs` — поле `exited_terminal`; блоки состояния после
  выхода не исполняются.
- `takt-sim/src/unit/tick.rs` — `exit` при уходе в терминал, один раз.
- `takt-sim/src/unit/builder.rs` — свёртка только для состояния без блоков.
- `takt-lang/src/generator/st/st_compose.rs` — печать `exit` (и `emit_block`
  стал `pub(crate)`).
- `takt-lang/src/generator/sv/sv_fsm.rs` — терминальная ветвь отдаёт `true`.

#### Проверки

Пробы на трёх формах, сверка с четырьмя прошивками, полный прогон, предкоммит.

### Найденные дефекты

**Кандидат называл косметику, а дефект был в поведении.** Дубль печати
`state_next = …_END;` выглядел шумом, но вместе с ним дублировался блок `exit`
— значения расходились. Урок тот же, что у 0392/0394: замер кандидата
перепроверяется, и ошибка бывает в сторону «это мелочь».

**Автоматическая правка чуть не сломала соседний инвариант:** вставка поля
`exited_terminal` регуляркой попала и в **паттерн** `match` функции
`enter_initial_state`, отчего `enter` стал исполняться повторно. Поймал
существующий тест «enter ровно один раз».

**Два теста закрепляли прежнее поведение эталона**: состояние
без переходов с накапливающим `always`. Оба получили самопереход — форма, при
которой автомат живёт и в прошивке.

### Выводы и дальнейшие шаги

Кандидат снят: дубль печати устранён вместе с классом.

## Итог (что сделано)

`always` и `exit` состояния-композиции исполнялись **тремя** разными
способами: эталон не исполнял их вовсе, `st` терял `exit`, `sv` печатал его
дважды, и только `c` с `rust` были правы. Теперь все пятеро считают одинаково.

**Правило уже действовало у целей** — «уход в терминал есть выход из
состояния»: на простом терминальном состоянии `exit` исполняли все четыре, и
расходился только эталон.

**После выхода блоки состояния молчат**, а блоки уровня модели — нет: так же
устроен порождённый C, где `switch` в состоянии `END` пуст, а model-level
`always` печатается до него.

**Свёртка модели в композицию теряла блоки состояния** — это класс в
другом месте: механизм есть, но данные до него не доходят.

Контроль — потактовая сверка эталона с **четырьмя** прошивками на одной фикстуре.
