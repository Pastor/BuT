## Краткое описание

Верный расчёт ширины перечисления — **по диапазону значений** — сегодня реализован
в каждом генераторе **отдельно** (`rust_type::enum_repr`, `sv_type::enum_width`).
Кандидат: вынести в `semantic/`, чтобы четвёртый генератор не наступил на то же.

Повод — **три генератора подряд**, споткнувшихся об одно и то же: ST брал `USINT`,
Rust — `#[repr(u8)]`, SV — `⌈log₂(вариантов)⌉`; все три предположения опровергнуты
одним и тем же `enum Action { Idle = 670 }` из `elevator.lam:121` (в байт не
влезает).

Выявлено при закрытой [генератор генерации в SystemVerilog](0045-sv-backend.md).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0060-enum-width-shared-layer.md); вскрыт [исправление](../fixes/0005-01-c-enum-signedness.md) (Tier 1, молчаливо неверный вывод цели `c`)

### Context

Кандидат заявлял: «верный расчёт — по диапазону значений — сегодня реализован в
каждом генераторе отдельно (`rust_type::enum_repr`, `sv_type::enum_width`); вынести в
`semantic/`, чтобы четвёртый генератор не наступил на то же».

**Проработка уточнила заявку дважды, и оба уточнения меняют решение.**

#### Уточнение 1: копий не две, а четыре

| Цель | Функция | Что возвращает | Знак |
|---|---|---|---|
| `c` | `get_c_type`, ветка `Enum` (`c/mod.rs:218`) | `uint{8,16,32,64}_t` | **не проверяет вовсе** |
| `st` | `st_type::enum_type` + `variants_range` | `SINT`/`USINT`/… через `integer_type(bits, signed)` | `min < 0` |
| `rust` | `rust_type::enum_repr` | `"u8"`/`"i16"`/… | `any(v < 0)` |
| `sv` | `sv_type::enum_width` | `(биты, знак)` — **точная** ширина | `any(v < 0)` |

Четыре независимых извлечения диапазона (`variants.iter().map(…).min()/max()`) —
проверено грепом.

#### Уточнение 2: «четвёртый генератор наступит на то же» — уже наступил, и это **первый**

Цель `c` **теряет знак молча**. Проба на `enum Level { Low = -5, Mid = 0, High = 5 }`:
C даёт `uint8_t lv;` и `model->lv = -5;`, а условие `if (model->lv == -5)`
**тождественно ложно** — проверено живым `cc`: `lv = 251`, `(lv == -5) = 0`.
**Автомат, верный в симуляторе и в трёх других целях, в C молча стоит.** Подробности
и критерии — [исправление](../fixes/0005-01-c-enum-signedness.md).

То есть дублирование — не «долг на будущее», а **действующий дефект Tier 1** в
**эталонной** цели.

#### Уточнение 3: цели задают разные вопросы

Общей «ширины перечисления» не существует:

- `sv` нужна **точная** ширина (`670` → **10** бит);
- `rust`/`st`/`c` нужна **машинная** ширина из {8,16,32,64} (`670` → 16);
- `rust` нужно **имя типа** (`i16`), `st` — своё (`INT`), `c` — своё (`int16_t`).

Значит выносить надо **не «ширину»**, а **факт**: диапазон и знак. Отображение
факта в тип цели обязано остаться в цели.

#### Расхождение, которое уже есть (пустое перечисление)

| Цель | `enum E { }` |
|---|---|
| `c` | `uint8_t` (`unwrap_or_default`) |
| `st` | `USINT` (`unwrap_or(0)`) |
| `rust` | `u8` (`unwrap_or(0)`) |
| `sv` | **`SV-004`** (ошибка) |

Один вход — четыре ответа, из них три молчат.

### Decision Drivers

1. **Тихо неверный вывод — худший класс дефекта** (Tier 1). Правило проекта:
   ошибаться в сторону **громкого** отказа. Сейчас C ошибается тихо.
2. **Эталон обязан быть эталоном.** `CLAUDE.md` объявляет `Enum` доверенным при
   сверке с C — проба это опровергает.
3. **Дублирование — механизм расхождения, а не стиль.** Четыре копии уже дали
   четыре ответа на пустое перечисление и два — на знак.
4. **Не всё общее.** Отображение «диапазон → тип цели» **target-специфично** и
   должно остаться в цели: слияние его в общий слой породило бы `match` по целям в
   `semantic/` — то есть ту же связность, только централизованную.

### Considered Options

#### Option A. Общий слой считает факт (диапазон + знак + минимальная ширина); цели отображают

`semantic/` получает описание перечисления: `min`, `max`, `signed`, минимальная
ширина в битах; `sv` берёт ширину напрямую, `rust`/`st`/`c` округляют до машинной
и печатают своё имя типа.

**Pros:**
- Убивает все четыре извлечения диапазона — источник расхождений (драйвер 3).
- **Чинит 0005-01 как следствие**: C, спросив общий слой про знак, не может его
  потерять (драйверы 1, 2).
- Оставляет в цели ровно то, что целевое (драйвер 4).
- Диапазон — свойство **семантического узла** `EnumNode`, а не цели: место
  естественное.

**Cons:**
- Требует миграции **четырёх** целей за раз, иначе смысла нет.
- Поведение цели `c` меняется (это и есть исправление) — нужна новая сверка.

#### Option B. Вынести целиком «ширину», включая имя типа

**Pros:**
- Ещё меньше кода в целях.

**Cons:**
- Общий слой начнёт знать про `uint8_t`/`USINT`/`u8`/`logic [9:0]` — то есть про
  все цели сразу (нарушен драйвер 4). Каждая новая цель правила бы `semantic/`.

#### Option C. Оставить как есть; чинить только C

**Pros:**
- Минимальная правка; исправление закрывается.

**Cons:**
- Четыре копии остаются (драйвер 3) — расхождение на пустом перечислении живёт,
  пятая цель повторит путь. Кандидат заведён ровно против этого.

#### Option D. Общий слой + унифицировать пустое перечисление в диагностику

**Pros:**
- Снимает и четвёртое расхождение.

**Cons:**
- Меняет поведение `c`/`st`/`rust` (сегодня молча `u8`) — это **вопрос семантики
  языка** («допустимо ли `enum E { }`»), а не кодогенерации. Решать его в ADR про
  вынос расчёта — превышение полномочий (прецедент: 0029 сознательно не решала
  семантику `[bit;N]`).

### Decision

Принимается **Option A**.

Общий слой считает **факт** (диапазон, знак, минимальную ширину), цели —
**отображение**. Исправление [цель `c` теряет знак перечисления — переход мёртв молча](../fixes/0005-01-c-enum-signedness.md) закрывается
**в объёме этой фичи**: миграция цели `c` на общий расчёт делает знак верным как
**следствие**, а не отдельной заплатой. Прецедент такого совмещения —
[кросс-файловый переход к декларации — точный путь вместо угадывания](0056-lsp-goto-exact-file.md#архитектура-adr), закрывшая попутно исправление.

Option D отклонена как выход за полномочия: пустое перечисление — вопрос
**семантики**, выносится кандидатом. Общий слой обязан вернуть «пусто» честно
(`Option`), а каждая цель сохраняет **сегодняшнее** поведение — чтобы 0060 не
протащила незаявленного изменения.

**Нормативные правила:**

1. Общий слой живёт в `semantic/` рядом с `EnumNode` и **не знает ни одной цели**
   (никаких `uint8_t`/`USINT`/`u8`).
2. Он отдаёт: `min`, `max`, `signed = min < 0`, `min_bits` (точная ширина; для
   знакового — дополнительный код).
3. Пустое перечисление → **`None`**; трактовку выбирает цель, и она **остаётся
   сегодняшней** (`c`/`st`/`rust` — 8 бит без знака, `sv` — `SV-004`).
4. Отображение «факт → имя типа цели» остаётся **в цели**.
5. Извлечений диапазона (`variants.iter()…min()/max()`) в `generator/` не остаётся
   **ни одного**.

**Язык не меняется** → версия не растёт. Изменение поведения цели `c`
— это **исправление**, а не смена контракта: сегодняшнее поведение
не является контрактом, оно является дефектом.

### Consequences

#### Положительные

- Тихий Tier 1 в эталонной цели устранён.
- Расчёт один; пятая цель получает его готовым.
- Расхождение на пустом перечислении становится **видимым** (зафиксировано, а не
  размазано по четырём файлам).

#### Отрицательные / Action items

- **A-1. Нужна сверка на отрицательном перечислении.** Проверка `c` (cmake+ninja, без
  `-Werror`) дефект **принимает**: `cc` даёт лишь предупреждение
  `-Wtautological-constant-out-of-range-compare`. Правило:
  **сверку заводить вместе с правкой**. `conformance_c_tests` пополняется моделью
  с отрицательным перечислением.
- **A-2. Поправить `CLAUDE.md`.** Там записано «сверка — только
  `Integer`/`Enum`/`Bool`», то есть `Enum` объявлен доверенным. Проба опровергает:
  доверять можно лишь **неотрицательным**. Формулировка правится вместе с исправлением —
  иначе следующий читатель снова поверит.
- **A-3. Корпус не докажет исправление.** Ни одно перечисление корпуса не имеет
  отрицательных вариантов, поэтому вывод корпуса обязан остаться **побайтово
  прежним**, а исправление доказывается **новой фикстурой**. Это делает A2 (неизменность
  корпуса) сильным контролем «рефакторинг не задел ничего лишнего».
- **A-4. Пустое перечисление — кандидат.** Вопрос семантики (`enum E { }` —
  ошибка или `u8`?) выносится, а не решается здесь.
- **A-5. Проверка `c` без `-Werror`** — отдельная находка: контроль существует, но
  выключен. Кандидат.

#### Acceptance criteria

1. **A1.** `enum Level { Low = -5, … }` → цель `c` даёт **`int8_t`**; переход
   `ref Done: lv = Low;` **срабатывает** (сегодня — никогда).
2. **A2.** Вывод **всех** целей на корпусе — **побайтово прежний** (в корпусе нет
   отрицательных перечислений; опора — детерминизм закрытой
   [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr)).
3. **A3.** Потактовая сверка `conformance_c_tests` на **новой** модели с
   отрицательным перечислением — зелёная.
4. **A4.** `grep` по `generator/`: извлечений диапазона вариантов
   (`variants.iter()…min()/max()`) — **ноль**.
5. **A5.** Общий слой не содержит ни одного имени типа цели
   (`grep "uint\|USINT\|u8\|logic"` по новому модулю — пусто).
6. **A6.** Поведение на **пустом** перечислении у каждой цели — **как сегодня**
   (`c`/`st`/`rust` → 8 бит без знака; `sv` → `SV-004`).
7. **A7.** Сохранены известные факты: `670` → `rust` `u16`, `st` `UINT`, `c`
   `uint16_t`, `sv` **10 бит** (тесты `enum_repr_670_is_u16_not_u8`,
   `enum_width_670_needs_ten_bits_not_one` — зелёные).
8. **A8.** `cc` не выдаёт `-Wtautological-constant-out-of-range-compare` на
   порождённом коде фикстуры.
9. **A9.** Проверки всех целей (`c`, `st`/`iec2c`, `rust`, `sv`) — зелёные.

## Анализ

### Цель и контекст

Кандидат: «расчёт ширины перечисления реализован в каждом генераторе отдельно
(`rust_type::enum_repr`, `sv_type::enum_width`) — вынести в `semantic/`, чтобы
четвёртый генератор не наступил на то же».

**Проработка заявку не подтвердила, а усилила.** Копий **четыре**, а не две; и
«четвёртый генератор» уже наступил — это **первый** (`c`), и он **молча неверен**.
ADR принял Option A: общий слой считает **факт** (диапазон/знак/минимальная
ширина), цели — **отображение**; исправление
[цель `c` теряет знак перечисления — переход мёртв молча](../fixes/0005-01-c-enum-signedness.md) закрывается в объёме фичи.

### Локализация (прочитано в коде, 2026-07-17)

| Цель | Где | Что делает | Знак |
|---|---|---|---|
| `c` | `generator/c/mod.rs:218–239` (`get_c_type`, ветка `Enum`) | `sorted_by(...).last()` → `max` → `uint{bits}_t` | **не проверяет** |
| `st` | `generator/st/st_type.rs:195` (`enum_type`) + `variants_range` | каскад → `integer_type(bits, signed)` | `min < 0` |
| `rust` | `generator/rust/rust_type.rs:106` (`enum_repr`) | каскад → `"i8"`/`"u16"`/… | `any(v < 0)` |
| `sv` | `generator/sv/sv_type.rs:229` (`enum_width`) | `leading_zeros` / поиск ширины с `w=2` | `any(v < 0)` |

Извлечений диапазона (`variants.iter().map(|(_, v)| *v)`) — **четыре** (греп).

### Замер расхождений (факты, а не оценка)

**Проба 1 — отрицательное перечисление** `enum Level { Low = -5, Mid = 0, High = 5 }`:

| Цель | Результат | Верно? |
|---|---|---|
| **`c`** | **`uint8_t lv;`**, `model->lv = -5;` | **НЕТ** |
| `rust` | `#[repr(i8)]` | да |
| `st` | `SINT`, `Level_Low : SINT := -5` | да |
| `sv` | `level_e` (знаковая) | да |

**Следствие проверено живым `cc`** (а не рассуждением): `lv = 251`,
`(lv == -5) = 0` → условие `if (model->lv == -5)` **тождественно ложно**, переход
**мёртв**, автомат стоит. `cc` предупреждает
(`-Wtautological-constant-out-of-range-compare`), но проверка `c` (`cmake`+`ninja`) —
**без `-Werror`**, поэтому принимает.

**Проба 2 — пустое перечисление** `enum E { }`: `c` → `uint8_t`, `st` → `USINT`,
`rust` → `u8`, `sv` → **`SV-004`**. Один вход — четыре ответа.

**Вывод для решения:** цели задают **разные вопросы** (точная ширина у `sv`;
машинная + имя типа у прочих), поэтому выносится **факт**, а не «ширина».

### Зависимости фичи

- **Зависит от:** **нет**.
  - **Код.** Правка: новый модуль в `semantic/` + четыре точки в `generator/`.
    Пересечений с незакрытыми фичами нет: [цель `rust`: хвостовой `if/else` с `return` даёт `needless_return`](0058-rust-tail-return-if-else.md)
    — `rust_func.rs`/`rust_stmt.rs`; [общие переменные корня → структура `Shared` вместо параметров по одной](0059-rust-shared-struct.md)
    — `rust_model.rs`/`rust_needs.rs`; 0060 — `*_type.rs` четырёх целей и
    `c/mod.rs`. Все три по цели `rust` **не конфликтуют**: разные файлы.
    [последовательная композиция (`+`) в цели SystemVerilog](0057-sv-sequential-composition.md) правит `sv_fsm.rs`, не
    `sv_type.rs`.
  - **Опора.** Детерминизм (**закрытая** [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md))
    — без него критерий A2 («вывод всех целей побайтово прежний») неисполним.
  - **Инфраструктура.** Проверки всех четырёх целей уже есть; для `st` нужен `iec2c`
    (собирается `scripts/ensure-iec2c.sh`, мягкий пропуск не валит предкоммит).
- **Влияние на порядок разработки:** **закрывает исправление** (Tier 1) — это
  довод поднять фичу в очереди (критерий 4 своду). Никого не блокирует.
  Смежные [симулятор не исполняет массивы вовсе](0076-sim-arrays.md)/[семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md)
  (семантика типов) от неё не зависят.

### Приоритет (Tier) — обоснование

**Tier 2** (кандидат подразумевал «долг» — Tier 3; проработка переоценила).

- Фича **закрывает Tier 1-дефект** ([цель `c` теряет знак перечисления — переход мёртв молча](../fixes/0005-01-c-enum-signedness.md)):
  молчаливо неверный вывод **эталонной** цели, из-за которого автомат стоит.
- Против Tier 1 для самой фичи: дефект **условен** — он бьёт только по моделям с
  **отрицательными** перечислениями, каких в корпусе нет, и у пользователя есть
  обход (не писать отрицательных вариантов) — правда, **не зная о ловушке**.
- Против Tier 3: «вынести дубликат» — это не косметика, когда один из дубликатов
  неверен.

### Требования и проверяемые условия

- **R1. Факт, а не тип.** Общий слой отдаёт `min`, `max`, `signed`, `min_bits` и
  **не знает ни одной цели**.
- **R2. Знак — `min < 0`.** Единая формула для всех целей.
- **R3. Точная ширина для `sv`.** `670` → 10 бит; знаковое — дополнительный код.
- **R4. Машинная ширина для `c`/`st`/`rust`.** `670` → 16 бит.
- **R5. Отображение — в цели.** Имена типов (`int8_t`/`SINT`/`i8`/`logic signed`)
  в общий слой не попадают.
- **R6. Пустое перечисление — `None`;** трактовка целей **не меняется**.
- **R7. Дубликатов не остаётся.** Извлечений диапазона в `generator/` — ноль.
- **R8. Цель `c` перестаёт терять знак**.
- **R9. Корпус неизменен побайтово** — по всем целям.
- **R10. Известные факты сохранены:** `670` → `u16`/`UINT`/`uint16_t`/10 бит.
- **R11. Детерминизм.** Порядок и результат воспроизводимы.

### Особенности по обратной функциональности

**Правка аддитивна для всего, кроме доказанного дефекта**.

- **Корпус не меняется** (R9/A2) — в нём нет отрицательных перечислений; это
  сильный контроль «рефакторинг не задел лишнего».
- **Цель `c` меняет поведение** на моделях с отрицательным перечислением — и это
  **исправление**, а не смена контракта: сегодняшнее поведение (мёртвый переход)
  контрактом не является. Обоснование смены — в
  [исправлении](../fixes/0005-01-c-enum-signedness.md) (свод требует
  обосновать несовместимость — здесь она в сторону «было сломано, стало верно»).
- Цели `st`/`rust`/`sv`, симулятор, LSP, форматтер — **не задеты** (их ответы уже
  верны; меняется только источник факта).
- Язык **не меняется** → версия не растёт.

### Риски и зависимости

- **R-1. Рефакторинг протащит незаявленное изменение** (главный риск: правятся
  **четыре** цели сразу). Снижение: A2 — вывод всех целей **побайтово** прежний;
  любое отличие обязано быть объяснено. Опора — детерминизм 0048.
- **R-2. Исправление C не докажется корпусом** (в нём нет отрицательных перечислений) —
  то есть зелёный проверка **ничего не значит** для 0005-01. Снижение: A3 — **новая**
  фикстура + потактовая сверка, заводимая **вместе** с правкой (уроки:
  сверку заводить вместе с генератором, а не после).
- **R-3. Контроль существует, но выключен.** `cc` дефект **видит**
  (`-Wtautological…`), а проверка без `-Werror` его пропускает. Снижение: A8 —
  проверять предупреждение явно. Системно — кандидат «проверка `c` без `-Werror`».
- **R-4. Соблазн решить пустое перечисление.** Это семантика языка, не
  кодогенерация (прецедент: 0029 не решала `[bit;N]`). Снижение: R6/A6 — поведение
  сохраняется дословно; вопрос вынесен кандидатом.
- **R-5. Тонкости, которые легко потерять при слиянии:** `sv` для знакового ищет
  ширину **с `w = 2`** (то есть `-1` → 2 бита, а не 1 — осознанно: однобитного
  знакового в SV не бывает); `rust` для знакового проверяет **обе** границы
  (`fits(i8::MIN, i8::MAX)`), `st` — эквивалентным каскадом. Снижение: R3/R10 +
  существующие тесты границ (`enum_width_negative_is_signed`,
  `enum_repr_boundaries`) обязаны остаться зелёными **без правки ожиданий**.

### Побочные находки проработки (вне объёма, заведены кандидатами)

1. **Проверка цели `c` идёт без `-Werror`** — поэтому принял код с тождественно ложным
   условием. Контроль есть, но выключен (класс урока: «проверка доказывает
   компилируемость, но не верность»).
2. **Пустое перечисление трактуется четырьмя целями по-разному** (`u8`/`USINT`/
   `uint8_t` молча vs `SV-004`) — вопрос семантики языка.
3. **`CLAUDE.md` вводит в заблуждение**: `Enum` объявлен доверенным для сверки с C.
   Правится в объёме 0060 (A-2 ADR), но сам факт — урок: «доверенный список»
   старел молча.

## Разработка

### Задача

#### Что было

Диапазон вариантов извлекается **четырьмя** независимыми копиями
(`variants.iter().map(|(_, v)| *v).min()/max()`): `c/mod.rs:218`,
`st_type.rs::variants_range`, `rust_type.rs::enum_repr`, `sv_type.rs::enum_width`.
Копии уже разошлись: на пустом перечислении дают `uint8_t`/`USINT`/`u8`/`SV-004`,
а цель `c` **вовсе не проверяет знак**.

#### Что сделано

Новый модуль в `semantic/` рядом с `EnumNode`, отдающий **факт** (свод ADR —
никаких имён типов целей):

```
EnumFacts { min: i64, max: i64, signed: bool, min_bits: u32 }
enum_facts(variants) -> Option<EnumFacts>     // None — пустое перечисление
```

- `signed = min < 0` (свод ADR) — **единая** формула вместо сегодняшних двух
  эквивалентных записей (`min < 0` у `st`, `any(v < 0)` у `rust`/`sv`);
- `min_bits` — **точная** ширина: беззнаковое — по `max`; знаковое — наименьшая
  ширина дополнительного кода, вмещающая `[min, max]`;
- пустое → `None` (свод ADR): трактовку выбирает цель.

**Тонкости, которые обязаны пережить слияние** (иначе тихо поедет вывод):

1. `sv` для знакового ищет ширину **с `w = 2`**: `-1` → **2** бита, не 1
   (однобитного знакового в SV не бывает). Если `min_bits` отдаёт 1 — цель `sv`
   обязана поднять до 2 **у себя**, либо это правило переезжает в `min_bits`
   осознанно, с тестом. Молча менять **нельзя**.
2. `sv` для `max == 0` даёт ширину **1** (ширины 0 в SV не бывает).
3. Тесты `enum_width_negative_is_signed`, `enum_width_unsigned_boundaries`,
   `enum_repr_boundaries`, `enum_repr_negative_is_signed`,
   `enum_width_of_sequential_states_matches_log2` обязаны остаться зелёными **без
   правки ожиданий** (T11): правка ожидания = признание, что вывод поехал.

Детерминизм: факт зависит только от значений вариантов; порядок
обхода на результат не влияет (`min`/`max` коммутативны) — но `Vec` вариантов
стабилен и так.

Статус по обратной функциональности: шаг **ничего не печатает** —
вывод всех целей неизменен; задача подготовительная.

#### Проверки

- `cargo build --bin lamc` — зелёная.
- Юнит-тесты факта: `{-5, 0, 5}` → `signed`, `min_bits = 4` (диапазон −8…7);
  `{670, 671}` → `!signed`, `min_bits = 10`; `{}` → `None`; `{0}` → `min_bits`
  по своду (см. тонкость 2 — согласовать с `sv`).
- `git diff --exit-code examples/generated` — **пусто** (A2): цели ещё не тронуты.
- **A5/T6:** `grep "uint\|USINT\|u8\|logic\|SINT"` по новому модулю — пусто.

### Задача

#### Что было

Каждая цель считает диапазон сама; цель `c` при этом **теряет знак молча** —
[исправление](../fixes/0005-01-c-enum-signedness.md), Tier 1.

#### Что сделано

Все четыре цели спрашивают факт у общего слоя ([расчёт ширины перечисления — вынести в общий слой](0060-enum-width-shared-layer.md#разработка))
и **только отображают** его в свой тип (свод ADR):

| Цель | Было | Стало |
|---|---|---|
| `c` (`c/mod.rs:218`) | `max` → **всегда** `uint{bits}_t` | факт → `int{bits}_t` при `signed`, иначе `uint{bits}_t` — **это и есть исправление** |
| `st` (`st_type::enum_type`) | свой каскад | факт → `integer_type(machine_bits, signed)` |
| `rust` (`rust_type::enum_repr`) | свой каскад | факт → `i8`/`u16`/… |
| `sv` (`sv_type::enum_width`) | свой расчёт | факт → `(min_bits, signed)`; `SV-004` при `None` |

`variants_range` (`st_type`) и локальные извлечения диапазона **удаляются**
(свод ADR: в `generator/` не остаётся ни одного — контроль A4/T5).

**Машинная ширина** (округление `min_bits` до {8,16,32,64}) нужна трём целям
(`c`/`st`/`rust`) — считается **один раз** в общем слое как производная факта, а
не тремя каскадами.

**Пустое перечисление — поведение сохраняется дословно** (свод ADR):
`c` → `uint8_t`, `st` → `USINT`, `rust` → `u8`, `sv` → `SV-004`. Унификация — это
вопрос **семантики языка**, вынесен кандидатом; 0060 не вправе протащить его
рефакторингом (прецедент: 0029 сознательно не решала семантику `[bit;N]`).

Статус по обратной функциональности: вывод `st`/`rust`/`sv` и всего
корпуса — **побайтово прежний**; у цели `c` меняется поведение **только** на
моделях с отрицательным перечислением, и это **исправление** доказанного дефекта,
а не смена контракта.

#### Проверки

- **T1/A1:** `enum Level { Low = -5, … }` → `c` даёт **`int8_t`** (было `uint8_t`).
- **T2:** переход `ref Done: lv = Low;` **срабатывает** (было — никогда: `251 == -5`).
- **T3/A3 — основная:** потактовая сверка на новой модели с отрицательным
  перечислением (`conformance_c_tests`) — зелёная. Заводится **вместе** с
  правкой: проверка `c` дефект **принимает** (`cc` даёт лишь предупреждение
  `-Wtautological-constant-out-of-range-compare`, а проверка идёт без `-Werror`), то
  есть зелёный проверка про этот дефект **не говорит ничего**.
- **T4/A2:** `git diff --exit-code examples/generated` — **пусто** по **всем**
  целям (в корпусе нет отрицательных перечислений). Сильный контроль «рефакторинг не
  задел лишнего»; опора — детерминизм закрытой 0048.
- **T5/A4:** `grep -rn "variants.iter().map(|(_, v)| \*v)" grammar/src/generator/`
  — ноль.
- **T7/A6:** пустое перечисление — четыре ответа **как сегодня**.
- **T8/A7:** `670` → `u16` / `UINT` / `uint16_t` / **10 бит**.
- **T9/A8:** `cc` не выдаёт `-Wtautological…` на фикстуре.
- **T11:** существующие тесты границ — зелёные **без правки ожиданий**.
- **T12:** `sv`, `V = -1` → `(2, signed)`.
- **T14:** мутация «вернуть `c` расчёт по `max`» обязана **валить T3**.
- **T13/A10:** поправить `CLAUDE.md` — там `Enum` объявлен доверенным для сверки с
  C («сверка — только `Integer`/`Enum`/`Bool`»); доверять можно лишь
  **неотрицательному**. Без этой правки следующий читатель снова поверит тексту.
- **A9:** `./scripts/precheck.sh` — проверки `c`/`st`/`rust`/`sv` зелёные.

## Тест-план

### Область и цель

Проверяются: (1) вынос **факта** (диапазон/знак/минимальная ширина) в общий слой
без изменения вывода четырёх целей; (2) закрытие
[исправления](../fixes/0005-01-c-enum-signedness.md) — цель `c` перестаёт молча
терять знак.

Язык **не меняется**, поэтому примеров/контрпримеров синтаксиса свод не
требует. Но свод требует проверять **корректность компилятора**, а здесь
доказан случай, когда компилятор порождает молча неверный код, — поэтому ядро
плана составляют **поведенческие** проверки (T3), а не сверка строк.

**Проверка здесь бесполезен как доказательство.** Он **уже** принимает дефект: `cc`
даёт лишь предупреждение `-Wtautological-constant-out-of-range-compare`, а проверка
`c` идёт **без `-Werror`**. Урок в чистом виде: проверка доказывает, что вывод
компилируется, но **не** что он верен.

### Тестовые данные и окружение

- **Новая фикстура (T1–T3, T9)** — модель с **отрицательным** перечислением.
  Это единственный способ доказать исправление: **корпус его не докажет** — ни одно

  дыра **в покрытии, а не в коде**  дала дефекту дожить.
- Если фикстура кладётся в `examples/` — ей обязан быть дан **сценарный контракт**
  (цепочка + бюджет + завершение) либо исключение с причиной: корпусной проверка
  достижимости  третьего не допускает. Иначе — в `grammar/tests/data/`.

### Что этот план сознательно не проверяет

- **Пустое перечисление как ошибку языка** — вопрос семантики, вынесен кандидатом

- **`-Werror` в проверке `c`** — отдельный кандидат (ADR, A-5); здесь предупреждение

## Итог проработки (2026-07-17)

Проработка заявку кандидата **не подтвердила, а усилила** — тремя уточнениями.

**1. Копий четыре, а не две.** Кандидат называл `rust_type::enum_repr` и
`sv_type::enum_width`; греп даёт **четыре** независимых извлечения диапазона —
плюс `st_type::enum_type`/`variants_range` и ветка `Enum` в `get_c_type`
(`c/mod.rs:218`).

**2. «Четвёртый генератор наступит на то же» — уже наступил, и это первый.** Цель `c`
смотрит **только на `max`** и знак **не проверяет вовсе**. Проба на
`enum Level { Low = -5, Mid = 0, High = 5 }`:

| Цель | Результат | Верно? |
|---|---|---|
| **`c`** | **`uint8_t lv;`**, `model->lv = -5;` | **НЕТ** |
| `rust` | `#[repr(i8)]` | да |
| `st` | `SINT`, `Level_Low : SINT := -5` | да |
| `sv` | `level_e` (знаковая) | да |

**Следствие проверено живым `cc`:** `lv = 251`, `(lv == -5) = 0` — условие
`if (model->lv == -5)` **тождественно ложно**, переход **мёртв**, автомат стоит.
Модель, верная в симуляторе и в трёх других целях, в C **молча стоит**. Заведён
**[исправление](../fixes/0005-01-c-enum-signedness.md)** (Tier 1), закрывается в
объёме этой фичи — прецедент: [кросс-файловый переход к декларации — точный путь вместо угадывания](0056-lsp-goto-exact-file.md) попутно закрыла
[позиции в диагностиках (`файл:строка:колонка`) и настоящий `file_no`](0053-diagnostics-file-id.md)-01.

**3. Цели задают разные вопросы,** поэтому выносить надо **не «ширину»**: `sv`
нужна точная ширина (`670` → 10 бит), прочим — машинная (16) плюс своё имя типа.

**Принято** ([ADR](0060-enum-width-shared-layer.md#архитектура-adr), Option A): общий слой
считает **факт** (диапазон, знак, минимальная ширина) и **не знает ни одной цели**;
отображение факта в тип остаётся в цели. Миграция `c` на общий факт **чинит
[перечисления (enum)](0005-enums.md)-01 как следствие**, а не заплатой. Отклонены: вынос вместе с именами типов
(общий слой узнал бы про все цели), «починить только C» (четыре копии остаются),
унификация пустого перечисления (это вопрос **семантики языка**, не кодогенерации —
вынесено кандидатом; прецедент: 0029 не решала семантику `[bit;N]`).

**Корпус исправление не докажет:** ни одно его перечисление не имеет отрицательных
вариантов (`Mode` 0…2, `Floor` 80…81, `Action` 670…671, `Command` 0…2,
`Constant` 0…2, `Point` 0…1) — снова «дыра **в покрытии**, а не в коде» (класс
[генератор C: typedef корневой структуры для одиночной модели](0026-c-root-typedef.md)). Поэтому вывод корпуса обязан остаться **побайтово
прежним** (сильный контроль рефакторинга), а исправление доказывается **новой фикстурой** и
**потактовой сверкой**, заводимой вместе с правкой.

**Проверка цели `c` дефект принимает:** `cc` **предупреждает**
(`-Wtautological-constant-out-of-range-compare`), но проверка идёт **без `-Werror`** —
контроль есть, но выключен. Отдельный кандидат.

Язык не меняется → версия не растёт.

## Итог (что сделано, 2026-07-18)

Обе задачи закрыты; исправление (Tier 1) закрыт **как следствие** миграции.

- **0060-01.** Общий слой в `semantic/enum_node.rs` (рядом с `EnumNode`):
  `EnumFacts { min, max, signed, min_bits }` + `enum_facts(variants) -> Option`.
  `signed = min < 0` (единая формула), `min_bits` — **точная** ширина (знаковое —
  доп. код, минимум 2 бита; беззнаковое — по `max`, `0 → 1`), `machine_bits()`
  округляет до {8,16,32,64} для `c`/`st`/`rust`. Пустое → `None`. **Ни одного
  имени типа цели** (свод ADR). 6 юнит-тестов.
- **0060-02.** Четыре цели спрашивают факт и **только отображают**:
  `c` → `int{bits}_t` при `signed` (**это и есть исправление**), `st` →
  `integer_type(machine_bits, signed)`, `rust` → `i8`/`u16`/…, `sv` →
  `(min_bits, signed)` напрямую. `variants_range` и все локальные извлечения
  диапазона удалены — грепом в `generator/` их **ноль** (A4). Пустое перечисление
  — поведение сохранено дословно (`c`/`st`/`rust` → 8 бит, `sv` → `SV-004`).
- **0060-03.** Потактовая сверка `conformance_c_tests`
  (`neg_enum_signedness_matches_generated_c`) на модели с отрицательным
  перечислением: `lv = -5`, `reached = 1`; мутация «вернуть расчёт по `max`»
  валит сверку **и** срывается на `-Werror=tautological-*`. `CLAUDE.md` поправлен
  (T13): `Enum` доверен лишь для неотрицательных диапазонов.

**Проверки:** 1971 тест зелёный, вывод **всех** целей на корпусе побайтово
прежний (A2 — в корпусе нет отрицательных перечислений; сильный контроль
рефакторинга), `cc` не выдаёт `-Wtautological` на фикстуре (A8), проверки
`c`/`st`/`rust`/`sv` зелёные. Известные факты сохранены (`670` → `u16`/`UINT`/
`uint16_t`/**10 бит**, T11 без правки ожиданий). Язык не менялся → версия не поднята.
