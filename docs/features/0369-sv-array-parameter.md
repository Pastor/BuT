# Фича: Массив в параметре функции у цели sv

- **Статус:** ГОТОВО

## Краткое описание

Замер-21: `fn head(a: [u8; 3]) -> u8 { return a[0]; }` с вызовом
`head(data)` исполняют эталон, `c`, `st` (форма `VAR_IN_OUT`) и
`rust`; цель `sv` печатала `input logic [7:0] a [0:2]` —
**verilator принимает, yosys отвергает**: «input/output/inout ports cannot
have unpacked dimensions». Всё при **нулевом** коде возврата `taktc`.

Класс видит один инструмент из трёх: линт цели и потактовая сверка идут через
verilator.

- **Status:** Accepted
- **Date:** 2026-08-21
- **Authors:** Архитектор + лид разработки
- **Related issues:** [Фича](0369-sv-array-parameter.md);

### Context

Массив у цели `sv` печатается **распакованным** (`logic [7:0] a [0:2]`), и та
же форма шла в параметр функции. yosys такой порт не принимает вовсе, а
verilator принимает — вывод компилировался и не синтезировался при нулевом
коде возврата.

У цели `st` этот класс закрыт фичей (`VAR_IN_OUT` с именованным типом);
здесь нужна своя форма, и выбрать её может только прогон **обоих**
инструментов.

### Decision Drivers

1. **Вывод обязан синтезироваться**, а не только линтоваться.
2. **Форму выбирает прогон обоих инструментов**.
3. **Тело функции не должно знать о форме передачи**: второе знание об
   адресации разошлось бы с первым.

### Considered Options

#### Option A. Плоский вектор в параметре, распаковка в прологе функции

**Pros:**
- Оба инструмента принимают (проба 2026-08-21).
- **Тело печатается как прежде**: пролог кладёт элементы в распакованный
  массив с именем параметра, и индексация не меняется — ни в печатнике
  выражений, ни в печатнике условий, ни в цели записи.
- Переменный индекс внутри функции работает (проверено прогоном).

**Cons:**
- Пролог занимает по строке на элемент.

#### Option B. Плоский вектор без пролога, индексация срезом `a[W*i +: W]`

**Pros:** короче вывод.

**Cons:** печатники индексации обязаны знать, что имя — параметр-массив, и
хранить его раскладку в `Scope`; это второе знание об адресации, и правку
пришлось бы вносить в **три** печатника (0365).

#### Option C. Отказ цели с причиной

**Pros:** громче молчания.

**Cons:** запись переводят четыре других потребителя, и форма выразима.

### Decision

Принимается **Option A**:

- в сигнатуре — `input logic [W*N-1:0] <param>_flat`;
- в прологе — объявление `<param>` распакованным массивом и присваивание
  элементов срезами плоского вектора;
- в вызове — аргумент печатается конкатенацией `{a[N-1], …, a[0]}`, чтобы
  `a[0]` лёг в младшие разряды.

Носитель форм — `sv_array` (`flat_param_width`, `flat_param_name`,
`flatten_argument`).

### Consequences

#### Положительные

- Функция с параметром-массивом переводится и **синтезируется**.
- Тело функции печатается прежними печатниками — знание о форме передачи
  живёт только на границе.

#### Отрицательные / Action items

- Массив **структур** и массив массивов в параметре под правило не подпадают:
  `flat_param_width` даёт `None` (ширина элемента не скалярна), и вывод
  остаётся прежним. Формы не измерены — вынесено кандидатом.
- Пролог добавляет N строк на параметр.

#### Acceptance criteria

1. `verilator --lint-only -Wall` **и** `yosys synth` принимают вывод.
2. Потактовая сверка значений совпадает; наблюдаемые различают **края**
   массива и меняются по тактам.
3. Мутации «прямой порядок конкатенации» и «вернуть распакованный параметр»
   роняют тесты.
4. Предкоммит зелёный; вывод корпуса не изменился.

## Анализ

### Цель и контекст

Привести цель `sv` к остальным потребителям на функции с параметром-массивом.
Замер — в карточке.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. 0337 (гашение неиспользованного параметра), 0348 (тот
  же класс у `st`), 0365 (распакованный массив), 0368 (тип элемента) закрыты.
- **Влияние на порядок разработки:** порождает кандидата «массив структур в
  параметре».

### Требования и проверяемые условия

- **R1. Параметр — плоский вектор** ширины `размер × ширина элемента`.
- **R2. Пролог распаковывает** его в массив с именем параметра, поэтому тело
  печатается прежними печатниками.
- **R3. Аргумент — конкатенация в обратном порядке**: `a[0]` в младших
  разрядах.
- **R4. Границы названы:** массив структур и массив массивов в параметре под
  правило не подпадают (ширина элемента не скалярна).
- **R5. Значения совпадают с эталоном** — сверка, а не факт компиляции.
- **R6. Синтез — отдельный контроль** (класс видит только yosys).

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Оба инструмента принимают вывод | `scripts/probe.sh` на `arrparam.takt` |
| A2 | Трасса совпадает с эталоном | `array_parameter_values_match_generated_sv` |
| A3 | Синтез | `array_parameter_is_synthesizable` |
| A4 | Мутации ловятся | порядок конкатенации; распакованный параметр |
| A5 | Вывод корпуса не изменился | предкоммит |

### Особенности по обратной функциональности

- **Язык не меняется**; правило 29 — не применимо.
- **Печатники индексации не трогаются** — в этом и смысл пролога.

### Риски и зависимости

- **Порядок конкатенации** — единственное место, где ошибка даёт валидный RTL
  с зеркальными значениями; его и контролирует сверка.
- **Ширина плоского вектора** считается у носителя (`scalar_width`), а не
  заново.

## Разработка

### Задача

#### Что было

Параметр-массив печатался распакованным (`input logic [7:0] a [0:2]`). yosys
такой порт функции не принимает вовсе, verilator принимает.

#### Что сделано

**`takt-lang/src/generator/sv/sv_array.rs`** — три носителя:
`flat_param_width` (ширина плоского вектора, размер и ширина элемента; `None`
для бит-вектора и неcкалярного элемента), `flat_param_name` (`<param>_flat`),
`flatten_argument` (конкатенация в обратном порядке).

**`takt-lang/src/generator/sv/sv_fsm.rs`** — сигнатура функции печатает
плоский вектор, а пролог тела распаковывает его в массив **с именем
параметра**: тело печатается прежними печатниками, и второго знания об
адресации не заводится.

**`takt-lang/src/generator/sv/sv_expr.rs`** — аргумент-массив печатается
конкатенацией.

**Сверка**: `takt-sim/tests/data/eval/conformance_sv_array_param.takt` и два
теста — потактовая сверка значений и прогон **синтеза**.

**Форму выбрал прогон.** Проверялись три: распакованный параметр (yosys
отвергает), плоский вектор с индексацией срезом (работает, но требует знания
о раскладке в трёх печатниках) и плоский вектор с прологом (принят обоими и
не трогает печатники). Заодно измерено, что переменный индекс внутри функции
работает.

**Наблюдаемые обязаны меняться по тактам:** первая редакция фикстуры читала
неизменные края массива, и перепутанный порядок конкатенации давал бы ту же
трассу.

#### Проверки

```sh
cargo test --test conformance array_parameter   # сверка + синтез
cargo test --test conformance                   # 168
cargo test --test targets                       # 391
for f in examples/*.takt; do scripts/probe.sh -n 1 "$f"; done   # корпус чист
./scripts/precheck.sh
```

Мутации (обе пойманы): прямой порядок конкатенации — трассы разошлись;
распакованный параметр — «не синтезируется».

### Выводы и дальнейшие шаги

- **Пролог дешевле знания.** Вариант «индексация срезом» работает, но
  потребовал бы хранить раскладку параметра в `Scope` и править **три**
  печатника индексации (0365). Пролог оставляет тело прежним.
- **Класс видит один инструмент из трёх** — как и 0367; отсюда отдельный тест
  синтеза.
- **Кандидат:** массив структур (и массив массивов) в параметре функции у
  `sv` — `flat_param_width` даёт `None`, вывод остаётся прежним, формы не
  измерены.
- Исправлений (`docs/fixes/`) не потребовалось.

## Итог (что сделано)

- Параметр-массив передаётся **плоским вектором**, аргумент — конкатенацией
  `{a[N-1], …, a[0]}`, а пролог функции распаковывает вектор в массив с именем
  параметра.
- **Пролог дешевле знания:** вариант «индексация срезом» принят обоими
  инструментами, но потребовал бы раскладку параметра в `Scope` и правку трёх
  печатников индексации (0365). Тело функции печатается прежними печатниками.
- **Класс видит один инструмент из трёх** (только `yosys`) — отсюда
  отдельный тест синтеза.
- Наблюдаемые сверки различают **края** массива и меняются по тактам: на
  постоянных значениях перепутанный порядок конкатенации неразличим.
- Массив структур и массив массивов в параметре остаются прежними — вынесено
  кандидатом; вывод корпуса не изменился.
