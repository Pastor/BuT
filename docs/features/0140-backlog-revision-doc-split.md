## Что известно на входе

**Кандидаты не снимаются.** Аудит нашёл две записи блока 2, описывавшие уже
сделанное:

Витрина — вход в проект для новой сессии, и устаревшая запись стоит **дороже
отсутствующей**: по ней заводят уже сделанную работу.

**Задвоение описания языка.** `README.md` — 2599 строк, из них разделы
«4. Синтаксис» и «5. Семантика» (≈500 строк) описывают язык; параллельно тем же

README, правило 24 — актуального `book/`; обе обязанности исполняются вручную,
проверки согласованности нет. Прецедент дрейфа уже есть: `Takt.ebnf` отстал от
языка на реформу операторов фичи.

## Направление решения (наметка, не решение)

1. Разовая ревизия блока 2 `FEATURES.md` с вычёркиванием закрытого.
2. Правило: **закрывающая фича обязана снять или актуализировать кандидатов**,

3. По возможности — машинная проверка (по образцу `check-links.py`): хотя бы
   «кандидат ссылается на фичу в статусе `ГОТОВО`» как повод к ревизии.
4. **Решение заказчика** по дублю: либо README сокращается до обзора и ссылок на
   `book/` (правило 15 переформулируется), либо заводится проверка согласованности.

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

### Context

Две смежные проблемы **процесса**, а не кода.

#### Кандидаты не снимаются

Блок 2 `FEATURES.md` — 28 записей. Сверка с кодом (2026-07-27, пробы и греп)
показала, что часть из них описывает не то, что есть:

| Кандидат | Что показала сверка |
|---|---|
| «Цель `c` **не эмитит констант перечисления вовсе**» | эмитит: `#define ENUM_EN_M_GO 1` — но **в `.c`, а не в `.h`**, где кандидат их искал; и **не использует** их в присваиваниях (`model->c = 1;`) |
| «Пустое перечисление `enum E { }` трактуется четырьмя целями по-разному» | такую программу **нельзя написать**: парсер требует хотя бы один вариант (`SY-002`) |
| «`rust` глушит `too_many_arguments` **пять раз**» | восемь |

Плюс две записи, названные в карточке фичи (сверка `st`, проверка `c-hal`), которые
аудит уже опознал как описывающие сделанное.

Витрина — вход в проект для новой сессии, и **устаревшая запись дороже
отсутствующей**: по ней заводят работу, которая уже сделана, либо ищут дефект,
которого нет.

Отдельная находка сверки, **вне** блока 2: `CLAUDE.md` утверждает «версия
языка **сейчас `0.4.0`**», тогда как `LANGUAGE_VERSION` и README дают `0.6.0`
(проверка `check-language-version.sh` сверяет только эти два и потому молчит). По
этой записи в закрытых недавно карточках писалось «версия `0.5.0` остаётся» —
ошибка распространилась.

#### Задвоение описания языка

`README.md` — 2708 строк; разделы «4. Синтаксис» (306) и «5. Семантика» (207)
описывают язык. Параллельно тем же занят `book/` — 3356 строк, 17 разделов и
приложения. Правило 15 требует детального README, правило 24 — актуального
`book/`; обе обязанности исполняются вручную, проверки согласованности нет.
Прецедент дрейфа есть: `Takt.ebnf` отстал от реформы операторов фичи
(проверено: `==` в эталоне присутствует, `:=` отсутствует).

### Decision Drivers

1. **Витрина должна быть достоверной.** Неверная запись направляет работу мимо.
2. **Один предмет — одно место.** Дублирование без проверки расходится; вопрос лишь
   когда.
3. **README остаётся входом в проект.** Он читается на GitHub без сборки PDF, и
   лишать его содержания нельзя — вопрос в том, **какого**.
4. **Процесс правится правилом, а не разовой уборкой.** Иначе то же накопится
   снова.

### Considered Options

Развилки две, и по каждой решение принимал заказчик.

#### Развилка A: дубль README ↔ `book/`

| Вариант | Существо | Итог |
|---|---|---|
| **A1. Разделить роли** | README — проект и инструменты; `book/` — единственное место, где описан язык. Языковые разделы README сжимаются до обзора со ссылками | **принят** |
| A2. Проверка согласованности | Оба документа остаются детальными, машинная проверка сверяет примеры и таблицы | отвергнут: сверить прозу нельзя, только фрагменты — дубль остаётся, растёт лишь стоимость |
| A3. Оставить как есть | Дублирование признаётся осознанным | отвергнут: дрейф уже случался |

#### Развилка B: правило в своде

| Вариант | Существо | Итог |
|---|---|---|
| **B1. Ввести правило** | Закрывающая фича обязана снять или актуализировать кандидатов, которых называет её карточка; плюс машинная подсказка | **принят** |
| B2. Разовая ревизия | Ограничиться уборкой | отвергнут: накопится снова |

### Decision

1. **Роли документов разделяются (A1).** README описывает **проект и
   инструментарий**: назначение, сборку, цели генерации, CLI, интеграцию,
   тестирование, диагностику инструментов. **Описание языка живёт в `book/`** —
   там синтаксис, семантика, конструкции и примеры. Языковые разделы README
   сжимаются до краткого обзора со ссылками на разделы документа. Правило 15
   свода переформулируется соответственно.
2. **Вводится правило свода (B1):** закрывающая фича обязана пройти по
   кандидатам, которых называет её карточка, и **снять либо актуализировать**
   их. Плюс машинная **подсказка** (не запрет): кандидат, ссылающийся на фичу в
   статусе `ГОТОВО`, помечается к ревизии.
3. **Разовая ревизия блока 2** проводится по факту сверки: опровергнутые записи
   снимаются, неточные переписываются по замеру.
4. **Расхождение версии в `CLAUDE.md` исправляется** попутно: находка сверки, и
   оставлять её нельзя — по ней уже написаны неверные строки в карточках.

**Подсказка, а не проверка.** Кандидат вполне может ссылаться на закрытую фичу и
оставаться верным — его туда и вынесли при закрытии. Машинная проверка,
запрещающая такую ссылку, отвергала бы законное; поэтому она лишь перечисляет
кандидатов к просмотру и **не влияет на код возврата** `precheck.sh`.

### Consequences

#### Положительные

- Витрина перестаёт направлять работу мимо: три записи исправлены по замеру,
  устаревшие сняты.
- Дубль описания языка исчезает **по построению**, а не поддерживается проверкой.
- Правило не даёт накопиться заново; подсказка делает ревизию дешёвой.

#### Отрицательные / Action items

- README теряет автономность в части языка: читателю с GitHub придётся открыть
  `book/`. Смягчается тем, что документ лежит в репозитории и читается как
  Markdown без сборки PDF.
- Правило 15 меняется — свод правится, а он эталон процесса.
- Ревизия проверила **не всех** кандидатов: часть требует IDE (плагин IntelliJ)
  или дорогого замера (потолки стека). Непроверенные остаются как есть, и это
  **называется** в отчёте, а не выдаётся за полную сверку.

#### Acceptance criteria

1. Опровергнутые кандидаты сняты, неточные переписаны по замеру; каждая правка
   опирается на пробу или греп, названные в отчёте.
2. `CLAUDE.md` называет версию языка, совпадающую с `LANGUAGE_VERSION`.
3. Правило о снятии кандидатов внесено в `docs/RULE.md`.
4. Скрипт-подсказка перечисляет кандидатов, ссылающихся на закрытые фичи, и не
   влияет на код возврата предкоммита.
5. Языковые разделы README сжаты до обзора со ссылками; правило 15
   переформулировано; ссылки целы (правило 14).
6. `./scripts/precheck.sh` зелёный.
