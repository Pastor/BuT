## Краткое описание

Состав областей страницы пересматривается. Справа появляется структура проекта —
дерево файлов (`takt`, `takt-ui`, `md`, `json`); выбор файла в дереве открывает
его в той же области, где правится код. Отдельная область симуляции упраздняется:
сценарий входов правится как файл, выбранный в дереве. Отдельная область схемы
упраздняется тоже: схема показывается при выборе файла раскладки. Из полки кнопок
остаётся показ области генерации, и он переезжает вправо; рядом встаёт кнопка
показа и сокрытия панели диагностики.

> жизненный цикл по своду.

- **Status:** Accepted

### Context

Областей было три, и каждая знала свой род работы: код, вывод цели, прогон,
схема. Файл проекта при этом открывался из списка в панели учётной записи —
там, куда ходят за входом, а не за работой. Сценарий правился в своей области,
схема — в своей, и читателю приходилось помнить, где что живёт.

### Decision

Область показа одна: **что открыто, то и показано** — модель кодом, сценарий
своим полем, раскладка схемой, пояснение разметкой. Род файла решает, чем его
показать. Справа
появляется структура проекта: дерево файлов по родам, выбор открывает файл в
области кода. Отдельные области прогона и схемы упраздняются.

Из кнопок остаются две, и обе справа: показ области генерации и показ области
диагностик.

### Consequences

Список сценариев исчезает: выбор сценария — тот же выбор файла. Полка режимов
узкого экрана называет три области: код, вывод, проект.

Схема больше не открывается кнопкой — её открывает файл раскладки. Прогон,
запущенный из другой области, схему открывает сам: ход автомата показывает она.

## Разработка

### Задача — структура проекта

Область `.pane-tree` справа, дерево строит `account.js` по составу открытого
проекта: роды перечислены ключами словаря (собранный ключ сверке невидим, и
подпись рода пропала бы молча). Ширина — своя ручка `#treesplit` с памятью в
браузере: дерево читают, а не растягивают под содержимое.

### Задача — одна область показа

Сценарий, схема и показ пояснения переехали в область кода; `showSource`
показывает то, чем открытый файл смотрят, а `showKind` выбирает это по роду
файла. Области `trace` и `scheme` сняты вместе со своими кнопками. Область
вывода у пояснения закрыта: компилировать его нечем.

### Задача — кнопки справа

Показ генерации переехал вправо, рядом встал показ диагностик: список
диагностик прячется вместе со своей шапкой и разделителем — ручка, которой
нечего делить, тянулась бы в пустоту. Выбор запоминается.

### Проверки

`check-web.sh` (92 теста; два переписаны под новый состав, один заведён на
структуру проекта), `check-design.py` (402 правила), показ страницы на 1500×950
и 375×812.

## Отчёт о тестировании

### Резюме

Состав областей приведён к требованию, проверки зелёные. Две проверки остаются
за читателем: открытие файла из дерева и показ схемы по файлу раскладки требуют
входа и проекта на сервере.

### Фактические результаты по проверкам

1. Три области в порядке: код с диагностиками, вывод цели, структура проекта.
2. Дерево без входа говорит «Проект не открыт»; пустая область читалась бы как
   поломка.
3. Кнопка диагностик прячет список вместе с шапкой и разделителем, выбор
   переживает перезагрузку.
4. На узком экране полка называет три области, и структура открывается своей.
5. `check-web.sh` — 92 теста, `check-design.py` — 402 правила, консоль чистая.

### Найденные дефекты

Четыре своих, закрыты по ходу: сохранённый выбор несуществующей области открывал
страницу без вывода; рабочая область осталась о трёх дорожках, и структура
уезжала на вторую строку; холст схемы в области кода схлопывался под легенду;
закрытая генерация схлопывала сетку в одну дорожку — правило писалось, когда
областей было две, и структура уезжала под них. Последнее нашлось показом на
стенде.

## Итог (что сделано)

Область показа стала одна: что открыто, то и показано, а род файла решает, чем
его показать. Структура проекта переехала из панели учётной записи в свою
область справа. Отдельные области прогона и схемы упразднены вместе с кнопками;
из полки остались две — генерация и диагностика, обе справа.
