# Фича: Длину прогона задаёт `-n`, а не длина сценария

- **Номер:** 0523
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** прочее
- **Связанные issue (анализ):** кандидат «Прогон обрывается на последнем шаге
  сценария» (заведён фичей [проверка сверки трасс прогонов в главах book/](0522-book-traces-gate.md), снят этой)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Исправлений нет.

## Краткое описание

Симулятор обрывал прогон на последнем шаге сценария: `-n` мог только уменьшить
длину, но не увеличить. Теперь длину задаёт `-n`, а сценарий задаёт **входы**;
когда его шаги кончились, прогон идёт дальше с удержанными значениями — так же,
как они удерживаются между тактами внутри сценария. Долг проверки после этого
пуст: последняя невоспроизводимая трасса документа стала воспроизводимой.

## Документирование (правило 24)

Поведение инструмента изменилось, поэтому правлены прикладной раздел
«Инструментарий» (правило нового прогона с примером вызова), «Симуляция»
(окружение не нужно расписывать по шагам) и «Механизмы времени»: трасса выбега
вентилятора заменена на **фактическую** — с настоящими номерами шагов
(180 003 вместо выдуманного «шага 6») и сценарием `fan-sim.json` рядом.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** аналитик, разработчик

### Context

Правило «сценарий определяет лимит шагов; `-n` может только уменьшить это число»
жило в `runner.rs` с комментарием, но без обоснования в артефактах. Цена его
измерена фичей: трасса выбега вентилятора (3 минуты при 1 кГц —
180 000 тактов) не воспроизводилась ничем, кроме файла сценария той же длины, и
осталась единственной записью долга проверки. Документ при этом обещал обратное:
раздел «Инструментарий» показывает `takt-sim model.takt -s scenario.json -n 50`
как способ задать 50 шагов.

Вторым следом того же правила был мёртвый исход `RunResult::StepsExhausted`
(«шагов в JSON меньше, чем запрошено — симуляция прервана»): вернуть его цикл не
мог, потому что лимит уже был обрезан длиной сценария.

### Decision Drivers

- сценарий описывает **окружение**, а не длину опыта;
- значения входов уже удерживаются между тактами  — продолжение
  прогона с последними значениями есть то же правило, доведённое до конца;
- поведение не должно измениться там, где `-n` не задан.

### Considered Options

1. **Оставить обрыв, исправив сообщение** («сценарий исчерпан» вместо «лимит
   достигнут»). Отвергнуто: честная формулировка не снимает ограничения, а
   документ всё равно не смог бы показать длинную выдержку.
2. **Повторять сценарий по кругу.** Отвергнуто: приём неочевиден и делает
   трассу зависимой от длины файла — ровно та хрупкость, из-за которой снята
   позиционная форма (0150).
3. **Длину задаёт `-n`, входы удерживаются** (принято).

### Decision

`limit = max_steps.unwrap_or(если сценарий не пуст — его длина, иначе usize::MAX)`.
Без `-n` поведение прежнее. Мёртвый исход `StepsExhausted` удалён вместе с его
печатью: он описывал снятое правило.

### Consequences

Долг проверки — ноль. Модель с `extern`-функцией после конца сценария
работает на последнем заданном стенде: стенд ставится шагом и не очищается —
поведение то же, что и внутри сценария, где шаг без секции `extern` его не
трогает.

#### Acceptance criteria

- `-n` больше сценария даёт ровно `-n` шагов, входы удержаны;
- без `-n` длина равна длине сценария; `-n` короче — усекает;
- `cargo test` зелёный, проверки книги зелёные.

## Анализ

### Цель и контекст

Снять ограничение, из-за которого документ не мог показать длинный прогон.

### Замер (правило 30, 2026-09-03)

До правки: `takt-sim watchdog.takt -s wd.json -n 12` при сценарии из восьми
шагов выполнял **восемь** и печатал «(лимит достигнут)» — сообщение называло
причиной лимит, которого прогон не достиг.

После: те же входы и `-n 12` дают двенадцать шагов, `kick` держится последним
значением. Выбег вентилятора со сценарием из **трёх** шагов и `-n 180010`:
переход в `Idle` на шаге **180 003** (момент `3m2ms`) — ровно 180 000 тактов
после того, как погас свет; прогон занял 0.9 с.

Проверка после правки: «Трасс в главах: 13; сверено с прогоном: 13; долга: 0».

### Зависимости фичи (правило 17/19)

Нет.

### Требования и проверяемые условия

- П1: `-n` больше длины сценария — прогон идёт до `-n`;
- П2: удерживается **последнее** значение входа, а не первое;
- П3: без `-n` длину задаёт сценарий;
- П4: `-n` короче сценария усекает прогон;
- П5: документ описывает новое правило, а трасса выбега воспроизводится.

### Редакторский слой (правило 29)

**Не требуется:** лексика, синтаксис и семантика языка не менялись — изменено
поведение симулятора при исчерпании сценария.

### Особенности по обратной функциональности

Обратная совместимость сохранена там, где `-n` не задан: длина по-прежнему равна
длине сценария. Меняется единственный случай — `-n` больше сценария: прежде
прогон молча укорачивался, теперь идёт до запрошенного. Прогон 3900 тестов
подтвердил, что на существующие сценарии правка не влияет.

### Риски и зависимости

Риск: модель с `extern`-функцией после конца сценария продолжит работать на
последнем стенде вместо остановки. Принято намеренно (см. «Consequences»):
внутри сценария шаг без секции `extern` ведёт себя так же.
