## Краткое описание

Замер-21: `pts := {{1, 2}, {3, 4}};` при `pts: [Point; 2]` исполняют
эталон, `rust` и `c`, а `st`/`st-at` отвечают `ST-011`, `sv`/`sv-mmio` —
`SV-002`. Причина одна: раскрытие агрегата у каждой цели **своё** и
одноуровневое — элемент, который сам является агрегатом, печатался как
выражение.

Копий раскрытия было **четыре** (две у `c` — инициализация переменной и
присваивание в теле, по одной у `st` и `sv`, плюс ещё по одной у локальных
объявлений), и рекурсию завели только две из них, три дня назад.

## Документирование

**Не требуется** — язык не меняется: записи законны и исполняются эталоном;
правится представление у двух целей и снимается дублирование в двух других.

### Context

Носитель `aggregate::places` (0340) отвечает на вопрос «куда писать **один**
уровень агрегата»: массиву — индекс, структуре — имя поля. Рекурсию — «а если
элемент сам агрегат» — каждая цель писала сама, и написали её **две из
четырёх** (обе у `c`). Цели `st` и `sv` отвергали такой вход
(`ST-011`, `SV-002`).

Форма адресации при этом у целей **разная**: `c` и `sv` пишут `[i][j]`, а `st`
— `[i, j]` (в IEC массивы не вкладываются). Значит общий носитель
не может вернуть готовую строку.

### Decision Drivers

1. **Правило одно — носитель один.** Четыре копии рекурсии разошлись бы (и уже
   разошлись: две есть, двух нет).
2. **Форма адресации принадлежит цели.** `[i, j]` у `st` против `[i][j]` у
   прочих.
3. **Молчаливо невалидный вывод хуже отказа.** Там, где синтезатор форму не
   принимает, цель обязана отказать, а не печатать.

### Considered Options

#### Option A. Носитель возвращает готовый суффикс строкой

**Pros:** проще вызывающему.

**Cons:** форма адресации у `st` другая — носитель пришлось бы параметризовать
строковым шаблоном, то есть знать о целях.

#### Option B. Носитель возвращает путь шагами, цель собирает форму

**Pros:**
- Правило раскрытия — одно; форма — у цели, где ей и место.
- Путь пригоден и для проверки («есть ли поле внутри массива»).

**Cons:** на одну сущность больше (`Step`, `Leaf`).

#### Option C. Оставить как есть, дописав рекурсию в `st` и `sv`

**Pros:** правка меньше.

**Cons:** четыре копии одного правила — ровно то, из чего выросли классы.

### Decision

Принимается **Option B**. `aggregate::leaves(ty, items, fields_of)` раскрывает
агрегат до листьев и отдаёт `Leaf { path: Vec<Step>, ty, value }`; `Step` —
`Index(usize)` либо `Field(String)`. Форму собирают цели:
`aggregate::c_like_suffix` (для `c`, `c-hal`, `sv`, `sv-mmio`) и
`st_multidim::iec_suffix` (подряд идущие индексы — в одну пару скобок).

Поиск полей структуры передаётся замыканием: цели хранят объявления по-разному
(`ModelNode` у `st` и `c`, снимок карты у `sv`).

**У цели `sv` поле структуры внутри массива отвергается** (`SV-002` с
названной причиной): замер-21 показал, что yosys принимает шаблон
присваивания только для массива целиком, а частичную запись поля элемента при
умолчании массива целиком объявляет защёлкой. Печатать такой вывод значило бы
заменить громкий отказ молчаливым несинтезом.

### Consequences

#### Положительные

- `pts := {{1, 2}, {3, 4}};` и `grid := {{1, 2}, {3, 4}};` переводят `st` и
  `c`; рекурсия живёт в одном месте вместо четырёх.
- Путь шагами пригодился сразу: по нему же строится проверка «поле внутри
  массива» для цели `sv`.

#### Отрицательные / Action items

- У цели `sv` массив структур остаётся непереводимым — и **шире** объёма этой
  фичи: запись `pts[0].x := 5;` без агрегата сегодня печатается и не
  синтезируется. Вынесено кандидатом (формы, принимаемые обоими инструментами,
  уже найдены пробами: сброс поэлементно конкатенацией, умолчание по полям).

#### Acceptance criteria

1. `st` и `c` переводят вложенный агрегат обеих форм (массив массивов, массив
   структур); `iec2c` + `cc` принимают вывод.
2. Потактовая сверка значений `st` с эталоном совпадает; фикстура различает
   перепутанные поле и индекс.
3. Мутации (одноуровневое раскрытие; C-подобная форма пути у `st`) роняют
   сверку.
4. У цели `sv` вход с полем внутри массива даёт `SV-002`, а не несинтезируемый
   вывод.
5. Предкоммит зелёный; вывод корпуса не изменился.

## Анализ

### Цель и контекст

Свести раскрытие вложенного агрегата в один носитель и закрыть отказы целей
`st` и `sv`. Замер — в карточке; контроль (плоский агрегат) переводят все цели
и до, и после.

### Зависимости фичи

- **Зависит от:** нет. 0340 (места записи), 0343/0345 (инициализатор и
  локальное объявление), 0363 (форма IEC), 0364 (рекурсия у `c`) закрыты.
- **Влияние на порядок разработки:** порождает кандидата «массив структур у
  цели `sv`» — там предмет шире агрегата.

### Требования и проверяемые условия

- **R1. Раскрытие — один носитель.** `aggregate::leaves`; копий рекурсии в
  целях не остаётся.
- **R2. Форма адресации — у цели.** `c_like_suffix` против `iec_suffix`.
- **R3. Поиск полей — у вызывающего.** Цели хранят объявления по-разному.
- **R4. Бит-вектор — лист.** `[bit;N≤64]` агрегатом не считается.
- **R5. Значения совпадают с эталоном.** Проверяется трасса, а не факт
  компиляции: неверно собранный путь даёт валидный вывод с другими числами.
- **R6. `sv` отказывает там, где синтезатор форму не принимает.** Молчаливый
  несинтез — регресс относительно прежнего отказа.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `st` и `c` переводят обе формы | `scripts/probe.sh` (раздел инструментов) |
| A2 | Трасса `st` совпадает с эталоном | `conformance_st_multidim_tests::st_nested_aggregate_trace_matches_reference` |
| A3 | Мутации ловятся | одноуровневое раскрытие; C-подобный путь у `st` |
| A4 | `sv` отказывает с причиной | проба `nestagg2.takt` |
| A5 | Юнит-тесты носителя | 4 теста в `aggregate.rs`, 2 в `st_multidim.rs` |
| A6 | Вывод корпуса не изменился | предкоммит |

### Особенности по обратной функциональности

- **Язык не меняется**; свод: не применимо.
- **Копии рекурсии, заведённые 0364, сняты**: это часть предмета, а не
  побочная правка.
- **Отказ цели `sv` сохранён намеренно** — см. R6.

### Риски и зависимости

- **Путь шагами** — новая сущность в носителе; её единственный потребитель
  сегодня — печать суффикса и проверка «поле внутри массива».
- **Массив структур у `sv`** остаётся непереведённым; формы, принимаемые
  обоими инструментами, уже найдены пробами и записаны в кандидате.

## Разработка

### Задача

#### Что было

Носитель `aggregate::places` раскрывал **один** уровень агрегата; рекурсию
писала каждая цель. Написали её две из четырёх (обе в цели `c`), а
`st` и `sv` отвергали вход (`ST-011`, `SV-002`).

#### Что сделано

**`takt-lang/src/generator/aggregate.rs`** — `leaves(ty, items, fields_of)`:
раскрытие до листьев с путём `Vec<Step>` (`Index` / `Field`); `c_like_suffix`
— форма адресации C-подобных целей. Поиск полей структуры принимается
замыканием: цели хранят объявления по-разному.

**`takt-lang/src/generator/st/st_multidim.rs`** — `iec_suffix`: подряд идущие
индексы сливаются в одну пару скобок (форма IEC).

**Цели**: `st_stmt` (присваивание и локальное объявление), `sv_stmt` (те же
две позиции), `c_model_init` и `c_expr/aggregate` переведены на носитель;
собственные рекурсии, заведённые 0364, сняты.

**`sv_stmt::refuse_struct_in_array`** — поле структуры внутри массива у цели
`sv` отвергается `SV-002` с названной причиной.

**Сверка**: `takt-sim/tests/data/eval/st_nested_aggregate.takt` +
`st_nested_aggregate_trace_matches_reference`.

**Формы для цели `sv` измерены, но не применены.** Пробы 2026-08-21 (yosys):
шаблон присваивания поддерживается только для массива целиком; сброс элемента
структуры работает **конкатенацией** (`pts[0] <= {8'd1, 8'd2};`), а умолчание
в `always_comb` обязано печататься **по полям** (`pts_next[0].x = pts[0].x;`).
Это шире агрегата — вынесено кандидатом.

**`git checkout` файла посреди мутаций стёр правку** — восстановлена
повторным применением. Мутации на рабочем дереве проверять безопаснее
временными копиями (`cp`), а не откатом из индекса.

#### Проверки

```sh
cargo test --test conformance st_nested_aggregate
cargo test --test conformance       # 163
cargo test --test targets           # 391
cargo test -p takt-lang --lib       # 1104
for f in examples/*.takt; do scripts/probe.sh -n 1 "$f"; done   # корпус чист
./scripts/precheck.sh
```

Мутации (обе пойманы): отключить спуск в носителе; печатать у `st` путь
C-подобной формой.

- **Копии рекурсии заводятся быстрее, чем снимаются.** Две из них появились

  синтезируется.
- Исправлений (`docs/fixes/`) не потребовалось.

## Итог (что сделано)

- Раскрытие агрегата **до листьев** живёт в одном носителе
  (`aggregate::leaves`), а форму адресации собирает цель: `[i][j]` у `c` и
  `sv`, `[i, j]` у `st`. Четыре копии рекурсии сведены к одной.
- **Две из этих копий появились тремя днями раньше**: носитель
  отвечал на вопрос «один уровень», и рекурсия оставалась вызывающему.
- **Носитель отдаёт путь шагами, а не строку** — формы адресации у целей
  разные; по тому же пути строится проверка «поле внутри массива».
- **У цели `sv` поле структуры внутри массива отвергается** `SV-002` с
  причиной: yosys принимает шаблон присваивания только для массива целиком, а
  частичную запись поля элемента считает защёлкой. Иначе правка заменила бы
  громкий отказ молчаливым несинтезом.
- Контроль — потактовая сверка `st` с эталоном на фикстуре, где значения
  различаются по позициям и меняются по тактам; обе мутации проверены.
- Вывод корпуса не изменился.
