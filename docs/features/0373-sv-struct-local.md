## Краткое описание

Локальные переменные тел цель `sv` объявляет `automatic` внутри ветви `case`. Переменной, **содержащей структуру**, этого мало: тело пишет её
поля, а внутри ветви yosys полным присваиванием такую запись не считает.

Замер-21 (`probe.sh`) на трёх формах записи:

| Вход | эталон, `c`, `st`, `rust` | `sv`, `sv-mmio` |
|---|---|---|
| `var tmp: Pair := {n, n + 10};` — запись по полям | исполняют | **yosys: Latch inferred** |
| `var made: Pair := make(n);` — присваивание целиком | исполняют | **yosys: Latch inferred** |
| `var cells: [Pair; 2] := …;` — поле элемента массива | исполняют | **yosys: Latch inferred** |

Всё — при **нулевом** коде возврата `taktc` и при том, что
`verilator --lint-only -Wall` модуль **принимает**.

Контроли: локальный массив скаляров и локальное перечисление проходят оба
инструмента — ломается именно структура.

### Context

Фича научила цель печатать локальные переменные тел: `automatic <тип>
<имя>;` в начале ветви `case`. Для переменной со структурой этого мало —
yosys объявляет её защёлкой:

```
ERROR: Latch inferred for signal `\m.$unnamed_block$1.tmp.lo'
       from always_comb process ...
```

Причина в том, что присваивание идёт **в ветви** `case`, то есть условно, а
объявление внутри безымянного блока синтезатор к процессу не поднимает. При
этом `verilator --lint-only -Wall` модуль принимает, а `taktc` возвращает ноль:
класс виден **одному инструменту из трёх**.

### Decision Drivers

1. **Вывод обязан синтезироваться**, а не только линтоваться.
2. **Тело печатается прежними печатниками:** второе знание об имени или
   адресации разошлось бы с первым.
3. **Вывод корпуса не должен измениться** — правило действует по нужде.
4. **Форму выбирает прогон обоих инструментов**.

### Considered Options

Все формы измерены 2026-08-21 **по коду возврата** инструмента (а не по
грепу вывода: у yosys строка `ERROR:` идёт с префиксом файла, и наивный
`grep '^ERROR'` объявил годными сразу три негодные формы).

| Форма | verilator | yosys |
|---|---|---|
| `automatic pair_t tmp;` в ветви (было) | принял | **отверг** |
| `automatic pair_t tmp = '0;` в ветви | принял | **отверг** |
| `begin : ярлык` вокруг блока | принял | принял для записи по полям, **отверг** для массива структур |
| объявление на уровне модуля без умолчаний | принял | **отверг** |
| объявление на уровне модуля + умолчания по полям | принял | принял |
| **`automatic` в начале `always_comb` + умолчания** | принял | **принял** |

#### Option A. Объявление в начале `always_comb` (принято)

**Pros:**
- Принимают оба инструмента на **всех трёх** формах записи (по полям, целиком,
  внутри массива).
- Имя остаётся прежним — тело печатают прежние печатники.
- Переменная остаётся `automatic`, то есть временной процесса, а не сигналом
  модуля: пространство имён модуля не засоряется.

**Cons:**
- Локальные разных блоков делят имя. Безопасно, потому что умолчания
  печатаются **безусловно** в начале процесса: каждый блок видит нули — ровно
  то, что предписывает объявление в теле.
- Одно имя с разным типом становится невыразимым → отказ `SV-002`.

#### Option B. Именованный блок `begin : ярлык`

**Cons:** лечит только запись по полям; локальный массив структур yosys всё
равно объявляет защёлкой. Кроме того, ярлык обязан быть уникален, а одно и то
же тело печатается в нескольких местах (`exit` — у каждого перехода).

#### Option C. Подъём на уровень модуля

**Cons:** временная становится сигналом модуля и делит пространство имён с
переменными; выигрыша перед Option A нет.

#### Option D. Отказ цели с причиной

**Cons:** запись исполняют эталон и три другие цели, а форма выразима.

### Decision

Принимается **Option A**:

- локальные тел, у которых тип **содержит структуру**, собираются печатником
  тел в `Fsm::hoisted_locals` (тело печатается в буфер);
- в начале `always_comb` печатаются их объявления (`automatic …;`) — до любых
  операторов, как требует SystemVerilog;
- следом печатаются нулевые умолчания: **целиком** (`tmp = '0;`) и **по
  листьям** (`tmp.lo = 8'd0;`), потому что тело вправе писать обеими формами, а
  синтезатор считает незаданной ту, которой присваивает тело;
- прочие локальные печатаются на месте, как прежде.

### Consequences

#### Положительные

- Три формы записи структуры в локальной переменной синтезируются.
- Накопитель заполняет сам печатник — второго обхода того же набора нет.

#### Отрицательные / Action items

- Умолчания печатаются в двух формах: у структуры из N полей это N + 1 строк на
  переменную. Цена принята: лишнее присваивание нуля смысла не меняет.
- Одно имя локальной с разными типами в разных блоках — отказ `SV-002`.

#### Acceptance criteria

1. `yosys synth` принимает вывод для всех трёх форм записи; verilator — тоже.
2. Потактовая сверка значений совпадает с эталоном.
3. Объявление стоит **до** операторов процесса (проверяется текстом).
4. Мутации «не поднимать», «умолчание только целиком», «умолчание только по
   полям» роняют тесты.
5. Вывод корпуса не изменился; предкоммит зелёный.

### Цель и контекст

Класс найден **соседним замером**: при работе над параметром-массивом (0372)
проба с функцией, возвращающей структуру, показала отказ yosys не в параметре,
а в **локальной переменной тела**.

#### Замер (`scripts/probe.sh -n 2|3`, 2026-08-21)

| Проба | эталон | `c`/`c-hal` | `st`/`st-at` | `rust` | `sv`/`sv-mmio` |
|---|---|---|---|---|---|
| локальная структура, запись по полям | исполняет | `cc` принял | `iec2c` принял · `cc` собрал | приняли | **yosys: Latch inferred** |
| локальная структура, присваивание целиком (возврат функции) | исполняет | принял | принял | приняли | **yosys: Latch inferred** |
| локальный массив структур | исполняет | принял | принял | приняли | **yosys: Latch inferred** |

| локальное перечисление (контроль) | исполняет | принял | принял | приняли | принял · синтезировал |

`verilator --lint-only -Wall` принимал вывод во всех строках: класс видит
**один инструмент из трёх**, и `taktc` возвращает ноль.

**Проба переписывалась дважды, и обе ошибки вели к неверному выводу:**

1. первая редакция назвала локальную `pair` при типе `Pair` — идентификаторы
   IEC **регистронезависимы**, и `iec2c` отвергал файл по совершенно другой
   причине (класс у цели `st`). Расхождение приписали бы структуре в теле;
2. вторая читала только одно поле структуры, и verilator отвечал
   `UNUSEDSIGNAL` на неиспользованные разряды — снова не тот предмет.

Обе ловушки вынесены кандидатами; предмет измерен на пробе, где имена не
сталкиваются, а все поля читаются.

**Формы решения мерились по коду возврата.** Первая попытка считала
`grep '^ERROR'` по выводу yosys — а он печатает `путь:строка: ERROR: …`, то
есть с префиксом. Наивный греп объявил годными **три негодные формы**;
ошибку показал прогон `probe.sh`, который смотрит на код возврата.

- **Влияние на порядок разработки:** новых зависимостей не вводит; заводит трёх
  кандидатов (`UNUSEDSIGNAL` на частично использованной локальной структуре,
  имя переменной, совпадающее с именем типа, у цели `st`, приведение

### Требования и проверяемые условия

- **R1. Синтез.** `yosys synth` принимает вывод для трёх форм записи структуры
  в локальной переменной.
- **R2. Линт.** `verilator --lint-only -Wall` принимает тот же вывод.
- **R3. Значения.** Потактовая сверка с эталоном совпадает: подъём объявления

- **R4. Порядок.** Объявление стоит **до** операторов процесса — этого требует

- **R5. Неизменность.** Вывод корпуса не меняется: локальные скаляры,

### Особенности по обратной функциональности

Обратная совместимость сохраняется: расширяется множество синтезируемых
записей, вывод для уже работавших входов не меняется. Новый отказ `SV-002`
(одно имя с разными типами) касается записи, которая и прежде не работала.

### Риски и зависимости

- **Разделение имени между блоками.** Локальные разных блоков делят объявление.
  Снижение: умолчания печатаются безусловно в начале процесса, поэтому каждый
  блок видит нули — как предписывает объявление в теле; поведение контролирует
  потактовая сверка.
- **Порядок объявлений.** Нарушение — синтаксическая ошибка verilator,
  громкая; контролирует текстовый тест.
- **Расхождение накопителя с печатью.** Исключено по устройству: накопитель
  заполняет сам печатник (тело идёт в буфер).

## Разработка

### Задача

#### Что было

`sv_blocks::emit_named_blocks` печатала объявления локальных тела прямо в
ветви `case` (`automatic pair_t tmp;`). Для переменной со структурой
yosys объявлял защёлку — «Latch inferred for signal
`$unnamed_block$1.tmp.lo`», — а verilator модуль принимал.

#### Что сделано

- `Fsm` получил накопитель `hoisted_locals: RefCell<Vec<HoistedLocal>>` и метод
  `hoist_local`: он отображает тип в SystemVerilog, дедуплицирует по имени и
  собирает нулевые умолчания. Одно имя с разным типом — отказ `SV-002`,
  называющий обход.
- `sv_blocks::emit_block_body` (общий для блоков состояния и модели) делит
  локальные надвое: содержащие структуру идут в накопитель, прочие печатаются
  на месте прежним путём.
- `sv_fsm::emit_comb` печатает тело **в буфер**, затем объявления поднятых
  (первыми в процессе — этого требует SystemVerilog), затем умолчания
  регистров и поднятых, затем буфер.
- `sv_array::leaf_zero_defaults` даёт умолчания: **целиком** (`'0`) для
  упакованного значения и **по листьям** для структуры внутри распакованного
  массива; упакованное значение получает **обе** формы.
- `sv_array::contains_struct` открыт для признака «тип содержит структуру».

**Статус по функциональности (правило 11).** Затронуты цели `sv`/`sv-mmio`;
`c`/`c-hal`, `st`/`st-at`, `rust`, `plantuml` и эталон — **н/п**: тот же вход
они переводят и исполняют.

#### Проверки

```sh
cargo test                                        # 3358 тестов, 0 провалов
./scripts/probe.sh -n 3 <проба>.takt              # три формы записи: все инструменты приняли
./scripts/precheck.sh
```

Мутации (каждая проверена):

| Мутация | Что падает |
|---|---|
| не поднимать (печать на месте, как прежде) | `struct_local_is_synthesizable`, `struct_local_declaration_precedes_statements` |
| умолчание только целиком | те же два |
| умолчание только по листьям | те же два |

Сверка значений мутациями **не** падает — и это верно: прежний вывод считал
правильно, он просто не синтезировался. Сверка контролирует другое: подъём не
изменил поведения.

### Выводы и дальнейшие шаги

1. **Класс виден одному инструменту из трёх.** `taktc` возвращал ноль,
   verilator принимал, отвечал только yosys. Ровно ради этого проверка цели держит
   два инструмента (0045), а проба (0362) — оба.
2. **Форма выбирается прогоном, и мерить надо код возврата.** Первая попытка
   считала `grep '^ERROR'` по выводу yosys, который печатает `путь:строка:
   ERROR: …`; наивный греп объявил годными три негодные формы. Ошибку показала
   проба, смотрящая на код возврата.
3. **Умолчаний два, и это не избыточность:** yosys считает незаданной ту
   «форму» сигнала, которой присваивает тело, — целую или полевую.
4. **Проба переписывалась дважды**, и обе ошибки вели к неверному выводу: имя
   локальной, совпадающее с именем типа (в IEC идентификаторы
   регистронезависимы), и частично прочитанная структура (`UNUSEDSIGNAL`). Оба
   класса вынесены кандидатами.
5. Корпус класс не покрывает — структурных локальных в `examples/` нет ни
   одной. Исправлений не потребовалось.

## Итог (что сделано)

- Локальная переменная, содержащая структуру, объявляется `automatic` **в
  начале `always_comb`** и получает нулевые умолчания; тело печатается прежними
  печатниками под тем же именем.
- **Форму выбрал прогон обоих инструментов:** именованный блок
  (`begin : ярлык`) лечит только запись по полям, `= '0` и `'{N{'0}}` в
  объявлении, объявление на уровне модуля без умолчаний и умолчание внутри
  ветви yosys отвергает.
- **Умолчаний два — целиком и по полям:** тело вправе писать структуру
  обоими способами, а yosys считает незаданной ту форму, которой присваивает
  тело. Значение одно и то же, поэтому смысл не меняется.
- **Накопитель заполняет сам печатник тел** (тело печатается в буфер):
  отдельный обход был бы вторым списком того же набора.
- Одно имя с разным типом — отказ `SV-002`, называющий обход.
- Прочие локальные (скаляр, перечисление, массив скаляров) печатаются на месте;
  вывод корпуса не изменился.
