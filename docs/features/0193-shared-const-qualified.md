## Краткое описание

Две модели, у каждой своя константа `K`, — и в целях `rust` и `sv` остаётся
**одна**: вторая модель молча считает с чужим значением. Цели `c` и `st` тот же
вход переводят верно, то есть расходятся не язык и цель, а цели между собой.

> Фича зарегистрирована из бэклога кандидатов (решение заказчика 2026-08-02:
> Tier-1 находки переводятся в фичи вперёд Tier 2); далее проходит жизненный
> цикл по правилу 17.

## Что известно на входе

Перепроверено пробой 2026-08-02, находка жива. Вход:
`model A { const K: u8 := 2; … } model B { const K: u8 := 3; … } start Main = A | B;`

| Сторона | Результат |
|---|---|
| эталон | `x = 2`, `y = 3` |
| цель `c` | `#define CONST_CONST_DUP_A_K 2` и `#define CONST_CONST_DUP_B_K 3` — верно (форма уточнена пробой 2026-08-03) |
| цель `rust` | единственный `const K: u8 = 2;`, обе модели читают его |
| цель `sv` | единственный `localparam logic [7:0] K = 2;` |

- Причина одна на две цели: константа печатается **голым именем**
  (`rust_expr::const_name`, `sv_expr::const_signal`), а объявления
  дедуплицируются по нему же — тогда как оба вывода суть **одно** пространство
  имён (модуль Rust; уплощённый модуль SV).
- Цель `st` держит константы полями `FUNCTION_BLOCK` — там дефекта нет по
  устройству.
- В задаче квалифицированы **только** константы, выведенные из
  параметра модели: там молчание было бы неверным выводом ради того самого, зачем
  параметр и заводят. Общий случай не тронут **сознательно** — переименование всех
  констант изменило бы вывод корпуса, а требование R7 фичи держит его
  байт-в-байт.

### Context

Две модели, у каждой своя константа `K`, — и в целях `rust` и `sv` остаётся
**одна**: вторая модель молча считает с чужим значением. Расходятся не язык и
цель, а **цели между собой**.

Проба воспроизведена заново 2026-08-03 (не по записи в карточке):

```takt
var x: u8 := 0;
var y: u8 := 0;
model A { const K: u8 := 2;  start Run { always { x := K; } } }
model B { const K: u8 := 3;  start Run { always { y := K; } } }
start Main = A | B;
```

| Сторона | Наблюдаемое |
|---|---|
| эталон (`takt-sim`) | `x=2  y=3` |
| цель `c` | `#define CONST_CONST_DUP_A_K 2` и `#define CONST_CONST_DUP_B_K 3` — **верно** |
| цель `rust` | единственный `const K: u8 = 2;`, обе модели читают его → `y` станет **2** |
| цель `sv` | единственный `localparam logic [7:0] K = 2;` — то же |
| цель `st` | дефекта нет по устройству: константы — поля `FUNCTION_BLOCK` |

Причина одна на две цели и лежит **в двух местах сразу**: константа печатается
голым именем (`rust_expr::const_ident`, `sv_expr::const_signal` — обе
квалифицируют владельцем **только** константу-параметр), а объявления
дедуплицируются по этому же имени (`rust_decl::emit_constants:349`,
`sv_const::emit_constants:189`). Оба вывода при этом суть **одно** пространство
имён: модуль Rust — один на программу, модуль SV — уплощённый.

**Проверки целей дефект не ловят и поймать не могут:** `clippy -D warnings`,
`verilator` и `yosys` принимают вывод — он валиден, просто считает не то. Контроль
обязан быть **значенческим** (потактовая сверка), а не «собралось».

### Decision Drivers

1. **Имя не должно зависеть от того, что написано в соседней модели.** Иначе
   добавление модели переименовывает константу в другой — «действие на
   расстоянии», от которого снапшоты `examples/generated/` перестают быть
   диффом по существу.
2. **Правило печати имени и правило дедупликации обязаны быть одним правилом.**
   Сегодня они совпадают случайно; разойдясь, они дают либо потерянное
   объявление, либо ссылку в пустоту.
3. **Язык не сужать под слабейшую цель.** Две независимые модели вправе иметь
   одноимённые константы — `c` и `st` переводят такой вход верно.
4. **Внутрицелевая последовательность.** В `sv` переменные модели **уже**
   квалифицированы владельцем (`sv_expr::signal_of`), константы — единственное
   исключение. В `c` квалифицированы **все** константы всегда.
5. **Цена диффа корпуса измерима и мала:** затрагиваются 4 файла —
   `examples/generated/rust/{comprehensive,extend_complex,stacker}.rs` и
   `examples/generated/sv/stacker.sv` (15 `const` и 9 `localparam`).

### Ограничение, вскрытое замером (действует на любой вариант с квалификацией)

Фильтр «константа используется» — `UsageSet.constants`
(`semantic/unused.rs:26`) — это `HashSet<String>` **голых** имён, общий у четырёх
целей. После квалификации он становится **над-аппроксимацией**: если `A::K`
используется, а `B::K` нет, обе константы пройдут фильтр и будут напечатаны, а
неиспользуемая в Rust — это **отказ**, а не предупреждение (проба 2026-08-03):

```
error: constant `UNUSED_K` is never used
  = note: `-D dead-code` implied by `-D warnings`
```

То есть квалификация **обязана** идти вместе с уточнением фильтра до пары
`(владелец, имя)`. В корпусе такого входа нет — проверка бы молчал, и дефект уехал
бы к пользователю.

### Considered Options

#### Option A. Квалифицировать все константы владельцем (как в цели `c`)

`rust`: `STACKER_CHARGE_STACK` вместо `CHARGE_STACK`; `sv`:
`stacker_CHARGE_STACK` — по правилу, уже действующему для констант-параметров.
Механизм есть: снять условие `is_parameter` в `const_ident`/`const_signal`.

**Pros:**
- дефект закрыт **по построению**, а не проверкой: одинаковых имён не возникает;
- одно правило на цель вместо двух — исчезает исключение, заведённое 0185-06;
- совпадает с целью `c` (прецедент) и с уже квалифицированными регистрами `sv`;
- имя не зависит от контекста — драйвер 1 соблюдён.

**Cons:**
- **вывод корпуса меняется** — 4 файла снапшотов обновляются, дифф надо
  прочитать глазами (проверка детерминизма 0048 это не заменяет);
- имена длиннее и менее читаемы в порождённом коде;
- требует уточнения `UsageSet` до пары `(владелец, имя)` — общий слой, который
  сегодня используют четыре цели.

#### Option B. Квалифицировать только при коллизии

Голое имя, если оно уникально по программе; префикс владельца — только у тех,
кто столкнулся.

**Pros:**
- дифф корпуса **нулевой**, снапшоты не трогаются;
- читаемость порождённого кода сохраняется.

**Cons:**
- нарушает драйвер 1 **напрямую**: добавление модели с одноимённой константой
  молча переименовывает константу в **другой**, уже написанной модели;
- имя перестаёт быть свойством объявления и становится свойством программы —
  два прохода вместо одного, а правило печати и правило дедупликации разъезжаются
  (драйвер 2);
- разное правило для «того же» текста в разных файлах — объяснимо только
  историей.

#### Option C. Диагностика на семантике: коллизия — ошибка

Одноимённые константы разных моделей отвергаются компилятором.

**Pros:**
- дёшево, дефект наблюдаем автору сразу и с позицией;
- вывод корпуса не меняется.

**Cons:**
- **сужает язык под слабейшую цель** (драйвер 3): `c` и `st` тот же вход
  переводят верно, а запрет действовал бы всегда — даже когда генерируют в `c`;
- это не ошибка автора, а ограничение цели: две независимые модели вправе иметь
  одноимённые константы;
- требует документирования (правило 24) — появляется новое ограничение языка.

#### Option D. Отказ **в целях** `rust`/`sv` (`RS-0xx` / `SV-0xx`)

Язык не трогаем; коллизию отвергает генератор той цели, где она неразрешима.

**Pros:**
- язык не сужается, `c`/`st` не задеты;
- вывод корпуса не меняется, ошибка громкая.

**Cons:**
- отвергает вход, который **можно** оттранслировать верно — отказ вместо работы;
- переносит проблему на пользователя: обход (переименование констант вручную) —
  ровно то, что генератор умеет сделать сам;
- две цели из шести молча теряют выразительность языка.

### Decision

Принимается **Option A** — квалифицировать все константы владельцем, как это
делает цель `c`. Рекомендация архитектора и решение заказчика (2026-08-03)
совпали.

Обоснование: это единственный вариант, где имя есть свойство **объявления**, а
не программы (драйвер 1), где правило печати и правило дедупликации — одно
правило (драйвер 2), и где цели `rust`/`sv` перестают отличаться от `c` без
причины. Развилка по существу была такой: Option A **меняет читаемость
порождённого кода ради корректности**, Option D **сохранял бы её ценой отказа на
законном входе**. Выбрана корректность: отвергать вход, который генератор умеет
оттранслировать верно, — это перекладывание работы на пользователя.

Цена измерена и ограничена: дифф 4 файлов корпуса и уточнение `UsageSet` до пары
`(владелец, имя)`.

### Consequences

#### Положительные

- цели `rust`/`sv` перестают молча считать чужим значением;
- исчезает исключение «квалифицируется только константа-параметр», заведённое
  0185-06 под требование «вывод корпуса байт-в-байт» (R7 фичи) — то есть
  снимается долг, а не добавляется;
- `UsageSet` становится точным, и это чинит тот же класс над-аппроксимации у
  целей `c`/`st` (сегодня безвредный: `#define` не жалуется на неиспользование).

#### Отрицательные / Action items

- **A1.** Обновить снапшоты `examples/generated/` (4 файла) и **прочитать дифф
  глазами**: проверка детерминизма 0048 доказывает воспроизводимость, но не верность.
- **A2.** Уточнить `UsageSet.constants` до пары `(владелец, имя)` — иначе
  неиспользуемая константа-тёзка валит проверка `rust` (`-D warnings`, замер выше).
- **A3.** Контроль обязан быть **значенческим**: потактовая сверка sim ≡ rust и
  sim ≡ sv на входе с одноимёнными константами. «Собралось» здесь не значит
  ничего — оба инструмента SV и `clippy` нынешний вывод принимают.
- **A4.** Правило 29 (редакторский слой) — проверить и зафиксировать ответ **на
  стадии анализа**, а не при закрытии.
- **A5.** Документирование (правило 24) при Option A **не требуется**: язык не
  меняется, меняется трансляция. При Option C/D — требуется.

#### Acceptance criteria

1. На пробе из раздела Context цели `rust` и `sv` дают `x=2`, `y=3` — как
   эталон и цель `c`.
2. Печать имени и дедупликация объявлений идут **одной** функцией на цель:
   разъехаться им не по чему.
3. Неиспользуемая константа-тёзка не печатается — проверка `rust` под `-D warnings`
   зелёный на входе, где `A::K` используется, а `B::K` нет.
4. Заведена потактовая сверка sim ≡ `rust` и sim ≡ `sv` на одноимённых
   константах; мутация (возврат голого имени) её **роняет**.
5. Дифф `examples/generated/` состоит **только** из переименований констант и их
   вхождений; предкоммит зелёный.

## Анализ

### Цель и контекст

ADR принял **Option A** (рекомендация архитектора и решение заказчика совпали):
константа печатается **именем, квалифицированным владельцем**, — как это уже
делает цель `c`. Исключение «квалифицируется только константа-параметр»,
заведённое задачей [параметризация моделей (ключевое слово `parameter`)](0185-model-parameters.md#разработка) под
требование «вывод корпуса байт-в-байт», снимается: оно было временным.

### Зависимости фичи (правило 17/19)

**Нет.** Механизм квалификации уже в дереве (`const_ident`/`const_signal`),
прецедент ключа — `address_map::resolve::qualified_port_key`.

### Места правки

| # | Что | Файл | Замечание |
|---|---|---|---|
| М1 | имя константы в цели `rust` | `generator/rust/rust_expr.rs::const_ident` | снять условие `is_parameter`: квалифицировать **всегда**. Форма прежняя — `TUNER_P1_GAIN` (`unique_uppercase_snakecase` + `_` + `const_name`) |
| М2 | имя константы в цели `sv` | `generator/sv/sv_expr.rs::const_signal` | то же; форма прежняя — `svspec_tuner_p1_gain` (`unique_lowercase_snakecase` + `_` + имя как написано) |
| М3 | ключ «константа используется» | `semantic/unused.rs` (`UsageSet.constants`, **4** точки вставки) | ключ становится парой `(владелец, имя)`; строится **одной** функцией — прецедент `qualified_port_key` |
| М4 | потребители фильтра | `rust_decl.rs:341`, `sv_const.rs:189`, `c_decl.rs:75` | всего три, и ключ обязан строиться **из `upper` узла**, а не из «модели, которую печатаем» |
| М5 | снапшоты корпуса | `examples/generated/rust/{comprehensive,extend_complex,stacker}.rs`, `examples/generated/sv/stacker.sv` | 15 `const` + 9 `localparam`; дифф читается глазами |

**Правка М1/М2 — снятие условия, а не новая ветвь.** Обе функции уже умеют
печатать квалифицированное имя; заводить второе правило нельзя — именно
раздвоение правила и было дефектом.

### Ограничения, которые определяют форму решения

- **О1. Продюсер и потребитель ключа обязаны строить одну строку.** Урок
  (`qualified_port_key`): разъехавшись на символ, они дают либо потерянное
  объявление, либо ссылку в пустоту. Поэтому ключ — **одна** функция, а её
  аргумент — `upper` узла константы, тот же источник, из которого строится
  печатаемое имя.
- **О2. Фильтр использования — над-аппроксимация, и после квалификации она
  становится ошибкой.** Замер-03: неиспользуемая `const` в Rust под
  `-D warnings` — **ошибка** (`dead-code`), а не предупреждение. Сегодня `A::K`
  и `B::K` делят запись `"K"`, и если используется хотя бы одна — фильтр
  пропускает обе; после квалификации напечатаются обе, и неиспользуемая уронит
  проверка.
- **О3. Форма имени не изобретается.** У цели `rust` — `unique_uppercase_snakecase`,
  у `sv` — `unique_lowercase_snakecase`; обе уже действуют для констант-параметров
  и пришпилены тестами (`model_parameter_specialize_tests.rs`,
  `model_parameter_const_tests.rs`). Вторая форма развела бы вывод одной цели сам
  с собой.
- **О4. В корпусе одноимённых констант нет** (замер: `comprehensive` 5,
  `extend_complex` 2, `stacker` 12, дублей ноль). Следствие: уточнение фильтра
  М3 **ничего не удалит** из вывода — дифф корпуса состоит только из
  переименований. Это делает критерий приёмки A5 проверяемым.
- **О5. Цель `st` не задета** — константы там поля `FUNCTION_BLOCK`, коллизии нет
  по устройству, фильтра констант у неё нет вовсе (потребителей ровно три).

| R7 | Поведение сверено значенчески, а не «собралось» | потактовая сверка sim ≡ `rust` и sim ≡ `sv` на одноимённых константах |

### Критерии приёмки и способ проверки

| # | Критерий (из ADR) | Способ проверки |
|---|---|---|
| A1 | проба даёт `x=2`, `y=3` в `rust`/`sv` | сверка значений (новый тест) |
| A2 | одно правило имени на цель | чтение + тест печати |
| A3 | тёзка-неиспользуемая не печатается | новый тест + проверка `rust` |
| A4 | сверка роняется мутацией | вернуть голое имя → сверка краснеет |
| A5 | дифф корпуса — только переименования | `git diff examples/generated/` глазами + `precheck.sh` |

**A4 обязателен.** Проверки целей дефект не ловят и поймать не могут: `clippy`,
`verilator` и `yosys` нынешний вывод принимают — он валиден, просто считает не
то. Зелёный тест ничего не стоит, пока не доказано, что он краснеет.

### Особенности по обратной совместимости (правило 11)

- **Язык не меняется**, публичный API крейта не меняется.
- **Вывод целей `rust`/`sv` меняется** — это и есть предмет фичи. Потребитель,
  который зовёт порождённую константу по имени из своей обвязки (например,
  `CHARGE_STACK` из Rust-кода), обязан обновить имя. В дереве проекта такой
  потребитель один — снапшоты корпуса; внешних гарантий на имена констант проект
  не давал.
- **Цели `c`/`st` не задеты**: у `c` квалификация уже была, у `st` вопроса нет.

### Документирование (правило 24)

**Не требуется.** Язык не меняется: одноимённые константы разных моделей законны
и были законны; меняется трансляция. (При отвергнутых Option C/D документирование
потребовалось бы — появилось бы новое ограничение языка.)

### Редакторский слой (правило 29)

**Правок не требуется.** Проверено чтением кода **на этой стадии**,
где пункт был пропущен и восполнялся при закрытии:

| Что проверялось | Вывод |
|---|---|
| лексика, синтаксис, семантика языка | **не меняются** — фича живёт в генераторах `rust`/`sv` и во внутреннем ключе `semantic/unused.rs`, наружу не выходящем |
| новое ключевое слово / токен / узел АСД | **нет** — `lsp/semantic_tokens.rs`, `lsp/keywords.rs::BUT_KEYWORDS`, `TaktTokenTypes.KEYWORDS`, `format/`, `semantic/usages/walk.rs` не задеты |
| переход к объявлению, ссылки, переименование | **не задеты**: слой вхождений (0131) адресует символы позициями в исходнике и об именах цели не знает вовсе |
| hover, структура документа | **не задеты**: печатают тип и объявление, а не имя в порождённом коде |
| новая диагностика | **нет** — Option A отказов не заводит (их заводили бы отвергнутые C/D) |

`semantic/unused.rs` даёт предупреждение «переменная не используется», и оно
до редактора доезжает. Уточнение касается поля `constants` (его потребители —
только генераторы), а не текста предупреждения; что предупреждения не
изменились — условие R5.

### Риски

- **Риск «дифф корпуса больше, чем переименования».** Снижение: О4 (дублей в
  корпусе нет) + A5 (дифф читается глазами, а не только проверкой детерминизма
  0048).
- **Риск разъезда ключа** (О1). Снижение: одна функция построения, вызванная из

  дефектный вывод принимают.

## Разработка

### Задача

#### Что было

Константа печаталась **голым** именем и по нему же дедуплицировалась — в цели
`rust` (модуль один на программу) и в цели `sv` (модуль уплощён). Две модели с
константой `K` разных значений давали **одно** объявление, и вторая молча
считала чужим значением. Квалификацию имели **только** константы, выведенные из
параметра модели: общий случай тогда не тронули ради
требования «вывод корпуса байт-в-байт» (R7 фичи).

#### Что сделано

**Имя (М1, М2).** В `rust_expr::const_ident` и `sv_expr::const_signal` снято
условие `is_parameter` — квалифицируются **все** константы. Форма не
изобреталась: она та же, что уже действовала для констант-параметров
(`unique_uppercase_snakecase` у `rust`, `unique_lowercase_snakecase` у `sv`), и
пришпилена тестами, которые правок не потребовали.

**Ключ использования (М3, М4).** `UsageSet.constants` ключуется парой
`(владелец, имя)` — новая `semantic::unused::const_key`, по образцу
`address_map::resolve::qualified_port_key` (0084). Причина не косметическая:
голым именем `A::K` и `B::K` делят запись, и если используется хотя бы одна —
фильтр пропускает **обе**; после квалификации имени неиспользуемая тёзка
напечаталась бы объявлением, к которому никто не обращается, а это **отказ**
сборки цели `rust` (`-D warnings` ⇒ `dead-code`), а не предупреждение.

**Потребителей оказалось шесть, а не три.** Анализ насчитал три
(`rust_decl`, `sv_const`, `c_decl`) — замер был неполон: цель `st` фильтрует
через связанную переменную (`usage.constants`, без `()`), и grep по `usage()`
её не видел. Настоящий список: `rust_decl.rs`, `sv_const.rs`, `c_decl.rs`,
`st_decl.rs` (свои константы и **унаследованные** от предков), `st_func.rs`
(константы, которые использует функция). Пропуск вскрыл **прогон**, а не
чтение: `st_func::tests::test_function_var_precedes_var_constant` покраснел
сообщением «нет секции VAR CONSTANT функции».

**Заодно снята старая неточность в `st_func::const_params`.** Отбор шёл от
множества использованных имён (`set.constants ∩ model.variables`), то есть по
**голому** имени: константа модели-тёзки, использованная в теле, засчитывалась
этой модели. Теперь отбор идёт **от объявлений модели**: для каждой её
константы строится тот же ключ и спрашивается множество.

**Дедупликация четырёх копий.** Один и тот же `match` по `VariableNode` стоял
в `unused.rs` **четырежды**; вынесен в `note_variable_usage`. Правило построения
ключа обязано быть одно — четыре копии разъехались бы при первой правке.

**Снапшоты (М5).** Обновлены 5 файлов (анализ ожидал 4 — забыт `sv-mmio`,
печатающий те же `localparam`): `examples/generated/rust/{comprehensive,
extend_complex,stacker}.rs`, `examples/generated/sv/stacker.sv`,
`examples/generated/sv-mmio/stacker.sv`. Дифф проверен построчно: изменений,
кроме имён констант и их вхождений, нет.

#### Проверки

```sh
cargo test --all-features
./scripts/precheck.sh
```

Проба ADR после правки (та же, что до неё):

| Цель | Было | Стало |
|---|---|---|
| `rust` | один `const K = 2`, обе модели читают его | `CONST_DUP_A_K = 2` и `CONST_DUP_B_K = 3` |
| `sv` | один `localparam K = 2` | `const_dup_a_K = 2` и `const_dup_b_K = 3` |
| `c` | было верно | без изменений |

- `cargo test --all-features`: зелено (1110 тестов ядра + пакеты).
- `./scripts/precheck.sh`: код возврата 0.
- R5 (цели `c`/`st` не задеты по поведению): вывод корпуса для них байт-в-байт
  прежний — в диффе `examples/generated/` их каталогов нет.

### Задача

#### Что было

Контрольных тестов у этого класса не было вовсе — и завести их «проверкой целевого языка»
нельзя по устройству: `clippy -D warnings`, `verilator` и `yosys` дефектный
вывод **принимают**. Он валиден, компилируется и синтезируется — просто считает
не то. Тот же урок, что записан после 0045 и 0191.

#### Что сделано

**Потактовая сверка значений** — `takt-sim/tests/conformance/conformance_shared_const_tests.rs`
(2 теста). Фикстура: два выходных порта, две модели с константой `K` разных
значений, каждая пишет в свой порт. Слияние констант наблюдаемо **сразу**:
у порта `b` появляется 2 вместо 3.

| Тест | Что доказывает |
|---|---|
| `each_model_uses_its_own_constant_in_rust` | трасса эталона ≡ трасса прошивки (`rustc` + драйвер, реализующий `Hal`) |
| `each_model_uses_its_own_constant_in_sv` | трасса эталона ≡ трасса RTL (`verilator` + тестбенч) |

**Мутационная проверка (критерий A4) — выполнена.** Возврат голого имени в
`rust_expr::const_ident` и `sv_expr::const_signal` роняет **обе** сверки, и
трасса показывает ровно дефект:

```
эталон=[(2, 3), (2, 3), (2, 3)]
Rust=[(2, 2), (2, 2), (2, 2)]
SV=[(2, 2), (2, 2), (2, 2)]
```

Без этого шага зелёный тест не доказывал бы ничего.

**Текстовый слой** — `takt-lang/tests/semantic/shared_const_qualified_tests.rs` (5 тестов):
состав объявлений в обеих целях, отсутствие голого имени, совпадение имени
объявления и имени в обращении, отсутствие **неиспользуемой** тёзки и тот же
`clippy -D warnings`, что в `precheck.sh` (образец — 0174). Текстовый слой ловит
регресс дёшево, значенческий доказывает, что мы ловим настоящее правило.

#### Найденная попутно гонка (не наш регресс)

`model_parameter_modes_tests` краснел в параллельном прогоне: оба теста файла
строили **один** временный каталог (тег из цели и режима), а каждый вызов
начинается с `remove_dir_all` — один тест сносил вывод другого во время
компиляции, и цель отвечала `SV-001 (NotFound)`.

Дефект **пре-существующий**, и это измерено, а не предположено: на дереве
**без** правок фичи — 1 падение из 6 прогонов; под `--test-threads=1` — зелено
всегда. Лечение — приём, уже описанный в `CLAUDE.md` после 0190: ключ каталога
включает **имя потока**. Тот же приём применён и в новой сверке.

#### Проверки


## Тест-план

### Область и цель

Проверяется, что одноимённые константы разных моделей **не сливаются** в целях

свидетели**. `clippy -D warnings`, `verilator` и `yosys` дефектный вывод

### Выводы и дальнейшие шаги

**1. Замер потребителей в анализе был неполон, и это вскрыл прогон.** Анализ
насчитал **три** места фильтрации по `usage().constants`; настоящих — **шесть**:
цель `st` обращается к множеству через связанную переменную (`usage.constants`,
без `()`), и поиск по `usage()` её не находил. Пропуск покраснел на
`st_func::tests::test_function_var_precedes_var_constant` («нет секции
VAR CONSTANT функции»). Урок для анализа: искать надо **по имени поля**, а не
по форме обращения к нему. Заодно снята старая неточность `st_func::const_params`
(отбор шёл по голому имени, и константа модели-тёзки засчитывалась чужой
модели), а `sv-mmio` добавился к списку снапшотов пятым.

**2. Один тест пришпиливал ровно то правило, которое ADR отменил.**
`model_parameter_const_tests::plain_constants_keep_their_names` утверждал «имя
обычной константы не меняется» — это было требование R7 фичи («вывод
корпуса байт-в-байт»), из-за которого квалификацию тогда получили только
константы-параметры. Тест **переписан, а не удалён**: предмет (правило имени
обычной константы) остался, ожидание обновлено, в док-комментарии названа
причина смены. Прочие 16 тестов параметров зелены без правок.

**3. Мутация — единственное доказательство, что контроль работает.** Возврат
голого имени роняет обе сверки с наблюдаемым `(2,2)` вместо `(2,3)`. Проверки
целевых языков при этом остаются **зелёными**: `clippy`, `verilator` и `yosys`
дефектный вывод принимают. Это подтверждает выбор значенческого контроля, а не
«собралось».

**4. Найдена и устранена чужая гонка в тестах — пре-существующая, измерено.**
`model_parameter_modes_tests` краснел в параллельном прогоне (`SV-001 NotFound`):
оба теста файла строили один временный каталог, а каждый вызов начинается с
`remove_dir_all`. На дереве **без** правок фичи — 1 падение из 6 прогонов; под
`--test-threads=1` — зелено всегда. Лечение — ключ каталога включает имя потока
(приём из `CLAUDE.md` после 0190). Это класс, который **прячется** локальным
однопоточным прогоном, и он всплывает уже второй раз подряд (0192, вывод 6).

**5. Дифф корпуса ограничен ровно тем, чем обещал ADR.** 5 файлов, 133 строки,
и все изменения — имена констант и их вхождения; проверено фильтрацией диффа, а
не «на глаз по первым строкам».

**Исправления (`docs/fixes/`) не требуются:** все находки устранены внутри
разработки.

## Итог (что сделано)

Константа печатается **именем, квалифицированным владельцем**, — во всех целях,
а не только в `c`. Одноимённые константы разных моделей больше не сливаются:

| Вход | Было | Стало |
|---|---|---|
| `model A { const K := 2 } model B { const K := 3 }` | эталон и `c` — `2`/`3`; `rust` и `sv` — `2`/**`2`** | **все дают `2`/`3`** |

Принят Option A (ADR; рекомендация архитектора и решение заказчика совпали):
исключение «квалифицируется только константа-параметр», заведённое задачей
[параметризация моделей (ключевое слово `parameter`)](0185-model-parameters.md#разработка) под требование «вывод
корпуса байт-в-байт», **снято** — два правила на один вид объявления и были
дефектом. Механизм не заводился заново: обе функции печати уже умели
квалифицированную форму, снято лишь условие.

Вместе с именем уточнён **ключ фильтра «константа используется»**
(`semantic::unused::const_key`, пара `владелец + имя` — по образцу
`qualified_port_key` фичи). Без этого неиспользуемая константа-тёзка
напечаталась бы объявлением, к которому никто не обращается, а в цели `rust`
это **отказ** сборки (`-D warnings` ⇒ `dead-code`), а не предупреждение.

Контроль заведён **значенческий**: потактовая сверка sim ≡ `rust` и sim ≡ `sv`.
Проверки целевых языков этот класс не ловят и поймать не могут — `clippy`,
`verilator` и `yosys` дефектный вывод принимают. Ценность контроля доказана
мутацией: возврат голого имени роняет обе сверки трассой `(2,2)` вместо `(2,3)`.

Замер потребителей фильтра в анализе был **неполон** (три вместо шести:
цель `st` обращается к множеству через связанную переменную) — пропуск вскрыл
прогон, подробности в [отчёте](0193-shared-const-qualified.md#отчёт-о-тестировании).

Вывод корпуса изменился в 5 файлах (`rust` ×3, `sv`, `sv-mmio`) — только имена
констант и их вхождения. Цели `c`/`st` не задеты. Язык не менялся, поэтому
документирование (правило 24) не требуется.

Детали: [ADR](0193-shared-const-qualified.md#архитектура-adr),
[анализ](0193-shared-const-qualified.md#анализ),
[тест-план](0193-shared-const-qualified.md#тест-план). Исправлений
(`docs/fixes/`) не потребовалось.

## Направление решения (наметка, не решение)

- Либо квалифицировать константы в `rust`/`sv` как в `c` (`<МОДЕЛЬ>_<ИМЯ>`) —
  **вывод корпуса меняется**, снапшоты обновляются, значит нужен ADR; либо
  отвергать коллизию диагностикой на семантике.
- Диагностика дешевле, но запрещает законную запись: две независимые модели
  вправе иметь одноимённые константы — это не ошибка автора, а ограничение цели.
- Проверки цели дефект **не ловят**: `clippy -D warnings` и `verilator`/`yosys`
  принимают вывод — он валиден, просто считает не то. Контроль обязан быть
  значенческим (потактовая сверка), а не «собралось».

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**.

## Документирование (правило 24)

**Не требуется** (уточняется ADR). Язык не меняется: одноимённые константы разных
моделей законны и сейчас — меняется трансляция. Если ADR выберет диагностику
вместо квалификации, документирование станет обязательным (появится новое
ограничение языка), и раздел определит анализ.
