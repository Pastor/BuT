1. **С `--register` новый ADR получает статус `Accepted`** — ещё до того, как ADR

   стадии 2.
2. **Не умеет добавлять артефакт одной поздней стадии.** Стадии наступают по
   очереди, а генератор работает «всё сразу при заведении фичи»: `--with-dev`
   создаёт development **и** tests вместе, а повторный `--register` **дублирует**
   строки в реестрах уже заведённых стадий (`insert_row` вызывается безусловно).
   Тест-план 0025 пришлось рендерить вручную (свод допускает как запасной
   путь). Нужны флаги вида `--stage tests|dev|report` и **идемпотентный**
   `--register`.
3. **Реестры не пересобираются по факту файлов** (подтверждено на масштабе при
   заведении 0026–0045): генератор создаёт ровно **одну** подзадачу `XXXX-01`, тогда
   как аналитики декомпозировали работу на **76** подзадач — реестр
   `docs/features/README.md` пришлось перестраивать скриптом. Плюс
   переименование подзадачи аналитиком оставляет в реестре **битую ссылку**
   (случай 0044-01). Нужен режим «пересобрать реестр по факту файлов».

**Дефект 1 подтверждён на этой же партии:** карточки 0058–0094 заводились

- **Status:** Accepted

### Context

Генератор заготовок `scripts/new-feature.sh`  имеет три дефекта:

1. **ADR-строка реестра получает статус `Accepted`** (строка 115) **до** написания
   ADR; шаблон `adr.md` тоже несёт `Status: Accepted`. Стадия 2 ещё не пройдена —
   статус должен быть `Draft`.
2. **`insert_row` не идемпотентен** (строки 84–99): безусловно дописывает строку.
   Повторный `--register` (или заведение фичи, чья карточка уже есть) **дублирует**
   строки реестров. Воспроизведено **трижды подряд** при заведении фич в этой же сессии — каждый раз дубль строки `docs/features/README.md`
   правился вручную.
3. **Реестры не пересобираются по факту файлов** и генерируется ровно **одна**
   подзадача `XXXX-01`, тогда как аналитики декомпозируют на десятки; переименование
   подзадачи оставляет битую ссылку.

Дефект 2 — конкретная повторяющаяся боль: генератор используется на **каждую**
фичу, и ручная чистка дубля — трение в каждом цикле.

### Decision Drivers

1. **Идемпотентность.** Повторный `--register` не должен плодить дубли — генератор
   зовётся многократно (заведение + добор поздних стадий).
2. **Честный статус ADR.** Заготовка не должна утверждать `Accepted` до принятия
   решения (стадия 2).
3. **Добор одной поздней стадии.** Стадии наступают по очереди; нужен способ
   добавить артефакт+строку **одной** стадии (в т.ч. `report`, которого генератор
   не умел вовсе), не трогая прочие.
4. **Обратная совместимость и надёжность.** Принятый по умолчанию путь заведения фичи не
   должен измениться; правка — POSIX sh без внешних зависимостей (как 0015).
   Реконструкция реестра из markdown-файлов — **ненадёжна** в POSIX sh (парсинг
   заголовка/статуса/ссылок), поэтому в объём не берётся.
5. **Проверяемость.** Идемпотентность должна стеречь **машинный** проверка, иначе
   регресс вернётся (прецедент правила размера модуля).

### Considered Options

#### Option A. Идемпотентный `insert_row` по ключу-номеру + `--stage`/`--subtask` + статус `Draft` + `NF_ROOT` + проверка

`insert_row` получает **ключ** (литерал первого столбца, напр. `| [0094]`,
`| 0094 |`, `| 0094-01 |`) и пропускает вставку, если строка с ключом уже есть.
ADR-строка и шаблон — `Draft`. Флаг `--stage NAME` рендерит и (идемпотентно)
регистрирует **одну** стадию (`feature|adr|analyze|dev|tests|report`), `--subtask
NN` задаёт номер dev-подзадачи. Переменная `NF_ROOT` переопределяет корень (для
тестируемости в temp-дереве). Регресс-тест `scripts/test-new-feature.sh` в
`precheck.sh` гоняет генератор в temp и проверяет отсутствие дублей + `Draft` +
добор стадии.

**Pros:**
- Убирает повторяющуюся боль (драйвер 1), честный статус (2), добор стадии и
  `report` (3), умолчание неизменен (4), машинный проверка (5).
- POSIX sh, без зависимостей.

**Cons:**
- Не чинит «пересборку реестра из файлов» (дефект 3b) — но её убирает
  идемпотентность (дубля больше нет), а надёжной реализации в sh нет.

#### Option B. Полная пересборка реестров из файлов (`--rebuild`)

Режим, реконструирующий строки реестра из markdown-файлов на диске.

**Pros:**
- Чинит битые ссылки от переименований, восстанавливает реестр «по факту».

**Cons:**
- **Ненадёжно в POSIX sh:** извлечение заголовка/статуса/ссылок из markdown —
  хрупкий парсинг, свой формат строки у каждого реестра. Высокий риск испортить
  реестр. Драйвер 4 против.
- Повторяющуюся боль (дубли) не адресует напрямую — это Option A.

#### Option C. Переписать генератор на язык с библиотеками (Python)

**Pros:**
- Надёжный парсинг/идемпотентность.

**Cons:**
- Ломает принцип 0015 «POSIX sh без зависимостей»; `precheck.sh` уже мягко-требует
  python3 только для одной проверки. Несоразмерно объёму.

### Decision

Принимается **Option A**. Идемпотентный `insert_row` по ключу-номеру + честный
`Draft` + `--stage`/`--subtask` + `NF_ROOT` + машинный проверка. Принятый по умолчанию путь
заведения фичи (`[--with-dev] [--register] XXXX slug "Заголовок"`) **не меняется**
по поведению, кроме двух улучшений: `--register` больше не дублирует, а ADR-строка
и шаблон несут `Draft`.

**Пересборка реестра из файлов (Option B, дефект 3b)** — **отложена в кандидат**:
надёжной POSIX-sh реализации нет, а повторяющуюся боль (дубли) снимает
идемпотентность. **Множественные dev-подзадачи (дефект 3a)** — покрыты `--stage dev
--subtask NN` (добор подзадачи `XXXX-NN`), автогенерация N подзадач не требуется
(аналитик заводит их по мере декомпозиции).

### Consequences

#### Положительные

- Дубли строк реестра исключены конструктивно; ручная чистка после генератора
  больше не нужна (снято трение каждого цикла).
- Заготовка ADR честна (`Draft` до принятия).
- Поздние стадии (включая `report`) добираются одной командой.
- Регресс стережёт `precheck.sh`.

#### Отрицательные / Action items

- `--rebuild` (Option B) не реализован — **кандидат** `FEATURES.md`.
- Ключ идемпотентности — литерал первого столбца; при смене формата строки реестра
  ключ надо согласовать (документируется в скрипте).

#### Acceptance criteria

1. Повторный `--register` для уже зарегистрированной фичи **не** добавляет вторую
   строку ни в один реестр (тест: два прогона → одна строка).
2. ADR-строка реестра и шаблон `adr.md` — `Draft` (не `Accepted`).
3. `--stage report` создаёт `docs/reports/XXXX-*.md` и регистрирует его (прежде
   невозможно); `--stage dev --subtask NN` добирает подзадачу `XXXX-NN`.
4. Принятый по умолчанию путь заведения фичи по поведению неизменен (кроме `Draft` и
   недублирования).
5. `scripts/test-new-feature.sh` в `precheck.sh` зелёный; язык/крейты не
   затронуты (инфраструктура).

## Анализ

### Цель и контекст

Устранить три дефекта генератора заготовок `scripts/new-feature.sh`:
преждевременный `Accepted` у ADR, **недублирование** при повторном `--register`
(конкретная боль — ×3 за сессию), добор одной поздней стадии (включая `report`).
Решение — Option A ADR: идемпотентный `insert_row` по ключу-номеру, `Draft`,
`--stage`/`--subtask`, `NF_ROOT` + машинный проверка. Пересборка реестра из файлов
(3b) отложена (ненадёжна в POSIX sh).

### Зависимости фичи

- **Зависит от:** **нет.** Инфраструктура (`scripts/`, `docs/templates/`), крейты
  `grammar`/`simulation` и язык не затрагиваются.
- **Влияние на порядок разработки:** не блокирует других фич, но снимает трение
  генератора для **всех** будущих (критерий 3 — процессная фича по
  влиянию на цикл).

### Требования и проверяемые условия

- **R1. Идемпотентный `--register`.** `insert_row` пропускает вставку, если строка
  с ключом-номером уже есть в реестре (ключ — литерал первого столбца:
  `| [NNNN]` / `| NNNN |` / `| NNNN-YY |`). Повторный прогон → одна строка.
- **R2. Честный статус ADR.** ADR-строка реестра и шаблон `adr.md` — `Draft`
  (не `Accepted`); `Accepted` проставляет автор на стадии 2.
- **R3. Добор одной стадии.** `--stage NAME` (`feature|adr|analyze|dev|tests|
  report`) рендерит и идемпотентно регистрирует **только** её. `report` поддержан
  впервые. `--subtask NN` задаёт номер dev-подзадачи (`XXXX-NN`).
- **R4. Обратная совместимость.** Принятый по умолчанию вызов
  `[--with-dev] [--register] XXXX slug "Заголовок"` по поведению неизменен, кроме
  R1 (недублирование) и R2 (`Draft`). POSIX sh без внешних зависимостей.
- **R5. Проверяемость.** `scripts/test-new-feature.sh` в `precheck.sh` гоняет
  генератор в temp-дереве (`NF_ROOT`) и проверяет R1/R2/R3.

### Особенности по обратной функциональности

Аддитивно: умолчание неизменен (кроме недублирования и `Draft` — оба **исправления**,
не сломы). Новые флаги opt-in. Язык и крейты не затрагиваются — версии не
поднимаются. `NF_ROOT` по умолчанию = каталог скрипта/.. (прежнее поведение).

### Риски и зависимости

- **Риск: ключ идемпотентности ложно совпадёт** (напр. `| 0094 |` внутри другой
  ячейки). Снижение: ключ — литерал первого столбца с граничными `|`; номер

- **Риск: `--stage`/`NF_ROOT` сломают умолчание.** Снижение: принятая по умолчанию ветка

- **Граница (не риск): пересборка реестра из файлов (3b)** — отложена в кандидат

- **Tier:** **Tier 3** (инфраструктура/процесс; боль конкретная и повторяющаяся,

## Разработка

#### Что было

→ повторный `--register` **дублировал** (правилось вручную ×3 за сессию); ADR-строка

#### Что сделано

Реализована **Option A** [ADR](0094-new-feature-script-fixes.md#архитектура-adr).

- **Идемпотентный `insert_row <README> <key> <row>`:** если строка с ключом-номером
  (`| [NNNN]` / `| NNNN |` / `| NNNN-YY |`) в реестре уже есть — вставка
  пропускается. Убирает дубли конструктивно.
- **Статус ADR — `Draft`:** ADR-строка реестра и шаблон `docs/templates/adr.md`
  (`Status: Accepted → Draft`). `Accepted` проставляется по факту (стадия 2).
- **`--stage NAME`** (`feature|adr|analyze|dev|tests|report`) — рендер + идемпотентная
  регистрация **одной** стадии; `report` поддержан впервые. **`--subtask NN`** —
  номер dev-подзадачи (`XXXX-NN`). Общий помощник `do_stage`, умолчание переиспользует
  его.
- **`NF_ROOT`** — переопределение корня (для тестируемости в temp-дереве).
- **Регистрация — `if … then … fi`, а не `[ … ] && insert_row`:** под `set -e`
  последняя форма при `REGISTER=0` возвращает 1 и обрывает `do_stage` (ломало
  принятый по умолчанию путь без `--register`). **Поймано регресс-тестом** при разработке.
