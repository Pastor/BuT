## Краткое описание

В корне лежит `.travis.yml`, который не исполняется нигде и противоречит
действующему контракту проверок.

> Фича зарегистрирована из процессного бэклога (отобрана заказчиком 2026-07-27); далее проходит жизненный цикл по своду.

## Что известно на входе

- `.travis.yml` содержит `cargo clippy` и `cargo test --verbose`.
- Реальный CI — `.github/workflows/ci.yml`: единый вызов `./scripts/precheck.sh`
  под строгим режимом (фича [cI прогоняет весь `precheck.sh` (живые проверки + check-links)](0090-ci-precheck.md)), где проверок полтора
  десятка.
- То есть файл описывает **другой, более слабый** набор проверок и вводит
  читателя в заблуждение.

## Направление решения (наметка, не решение)

- Удалить `.travis.yml`.
- Проверить, что он нигде не упоминается (`README.md`, `docs/`, бейджи).

Окончательный выбор — за стадиями **архитектуры** (ADR) и **анализа**: раздел
выше фиксирует то, что уже проверено, а не предрешает реализацию.

**Не требуется.** Инфраструктура; язык не меняется.

### Context

В корне репозитория лежит `.travis.yml`:

```yaml
language: rust
script:
  - rustup component add clippy
  - cargo clippy
  - cargo test --verbose
```

Действующий CI — [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml):
единственный вызов `./scripts/precheck.sh` под строгим режимом
(`PRECHECK_STRICT=1`), где полтора десятка проверок — компиляция порождённого кода
настоящими инструментами (`cc`/`cmake`, `rustc`+`clippy -D warnings`,
`verilator`+`yosys`, `iec2c`), детерминизм генерации, размер модулей, версия
языка, реестр диагностик. Этот контракт установила фича
[cI прогоняет весь `precheck.sh` (живые проверки + check-links)](0090-ci-precheck.md#архитектура-adr), явно устранившая **дрейф**: прежде CI нёс
собственную реализацию проверок, и она разошлась с локальной.

Travis CI не подключён к репозиторию: прогонов нет, бейджа нет, в документации
файл не упоминается. То есть перед нами **описание другого, более слабого набора
проверок**, которое читатель может принять за действующий контракт — ровно тот
класс вреда, который фича устраняла.

### Decision Drivers

1. **Один источник истины проверок** (принцип фичи): любая вторая
   конфигурация проверок — источник дрейфа.
2. **Витрина не должна врать.** Файл в корне читается как часть контракта
   проекта; неисполняемый файл вводит в заблуждение сильнее, чем его отсутствие
   (тот же довод, что для устаревших кандидатов в `FEATURES.md`).

### Considered Options

#### Option A. Удалить файл

**Pros:**
- Устраняет второй, более слабый набор проверок.
- Ноль поддержки в дальнейшем.

**Cons:**
- Если Travis когда-нибудь понадобится, конфигурацию придётся писать заново —
  впрочем, из `ci.yml` она выводится за минуты.

#### Option B. Оставить, но привести в соответствие с `precheck.sh`

**Pros:**
- Запасной CI на случай отказа GitHub Actions (учитывая, что прогоны Actions
  были заблокированы по биллингу — см. кандидат «Дожать CI-верификацию 0090»).

**Cons:**
- **Два места, где описаны проверки** — ровно то, что фича признала дефектом
  процесса; разойдутся при первой же правке.
- Travis не подключён: конфигурация всё равно не исполняется, то есть её
  «соответствие» никем не проверяется.

#### Option C. Оставить как есть

**Pros:**
- Ничего не делать.

**Cons:**
- Сохраняется ложный контракт: читатель видит `cargo clippy` + `cargo test` и
  делает вывод, что этого достаточно для коммита.

### Decision

Принимается **Option A** — удалить. Аргумент Option B (запасной CI) не
выдерживает проверки: запасной CI, который никем не исполняется и ни с чем не
сверяется, не является запасным. Если понадобится второй провайдер CI, он
должен звать **тот же** `precheck.sh`, а не свой набор команд, — и заводиться
отдельной фичей с проверкой живым прогоном.

### Consequences

#### Положительные

- В репозитории остаётся единственное описание проверок — `scripts/precheck.sh`,
  вызываемый из `ci.yml`.
- Снята ловушка «прочитал `.travis.yml`, решил, что проверки — это clippy и tests».

#### Отрицательные / Action items

- Если Actions останутся недоступны (биллинг), вопрос запасного провайдера
  придётся решать заново — **отдельной фичей**, с требованием звать
  `precheck.sh`.

#### Acceptance criteria

1. Файла `.travis.yml` в репозитории нет.
2. Упоминаний Travis в `README.md`, `docs/`, `CLAUDE.md` нет (кроме истории в
   `CHANGES.md` и артефактов этой фичи).
3. `./scripts/precheck.sh` зелёный.

> Диаграмма по своду **не требуется**: ADR не меняет ни синтаксиса, ни
> семантики языка.

## Анализ

### Цель и контекст

Убрать из репозитория конфигурацию CI, которая не исполняется и описывает более
слабый набор проверок, чем действующий контракт проверок (`precheck.sh`, фича
[cI прогоняет весь `precheck.sh` (живые проверки + check-links)](0090-ci-precheck.md)). Решение — Option A
[ADR](0139-remove-travis-config.md#архитектура-adr).

### Зависимости фичи

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** никого не разблокирует; выполняется рано
  потому, что стоит минут и снимает ложный контракт (критерий 4 своду).

### Требования и проверяемые условия

- **R1. Полнота удаления.** Удаляется сам файл **и** все ссылки на Travis в
  живых документах (`README.md`, `docs/`, `CLAUDE.md`). Записи в `CHANGES.md` —
  история, они остаются.
- **R2. Проверки не ослабляются.** `precheck.sh` и `ci.yml` не трогаются: контракт
  проверок остаётся ровно тем же.
- **R3. Аддитивность неприменима.** Удаление файла — не изменение поведения
  инструментов: ни компилятор, ни симулятор, ни порождённый код не затронуты.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `.travis.yml` отсутствует | `test ! -e .travis.yml` |
| A2 | Файл удалён из индекса git | `git ls-files .travis.yml` — пусто |
| A3 | Нет упоминаний Travis в живых документах | `grep -ri travis` по `README.md`, `docs/`, `CLAUDE.md`, `scripts/`, `.github/` — только артефакты фичи |
| A4 | Проверки не ослаблены | `git diff` не содержит `scripts/precheck.sh` и `.github/workflows/ci.yml` |
| A5 | Предкоммит зелёный | `./scripts/precheck.sh` → `EXIT=0` |
| A6 | Ссылки целы | `python3 scripts/check-links.py` |

### Особенности по обратной функциональности

Обратная совместимость **не затрагивается**: язык, порождаемый код и публичный
API не меняются. Единственный потребитель удаляемого файла — сервис Travis CI,
который к репозиторию **не подключён** (прогонов нет, бейджа нет).

### Риски и зависимости

- **Риск: файл кому-то нужен как запасной CI.** Снят разбором Option B в ADR:
  неисполняемая и ни с чем не сверяемая конфигурация запасной не является; при
  необходимости второй провайдер заводится отдельной фичей и обязан звать
  `precheck.sh`.
- **Риск: скрытые ссылки.** Снимается проверкой A3 (грепом по всему дереву, а не
  по памяти).

## Разработка

### Задача

#### Что было

В корне репозитория — `.travis.yml` (5 строк): `cargo clippy` + `cargo test
--verbose`. Файл отслеживался git, но не исполнялся: Travis CI к репозиторию не
подключён (прогонов нет, бейджа нет). Действующий CI — `.github/workflows/ci.yml`
→ единственный вызов `./scripts/precheck.sh` под `PRECHECK_STRICT=1`.

Итого в репозитории существовало **два** описания того, «что нужно проверить
перед коммитом», и более слабое из них было ложным.

#### Что сделано

- `git rm .travis.yml` — файл удалён из дерева и из индекса.
- Проверено грепом по всему дереву, что живых упоминаний Travis не осталось:
  найденные совпадения принадлежат **артефактам самой фичи** и строкам
  реестров (`docs/*/README.md`), то есть истории решения, а не контракту
  проверок.
- `scripts/precheck.sh` и `.github/workflows/ci.yml` **не трогались** (требование
  R2 анализа): набор проверок остался ровно прежним.

## Тест-план

### Область и цель

Фича **инфраструктурная**: удаляется файл конфигурации, не влияющий ни на язык,
ни на инструменты, ни на порождаемый код. Поэтому (тесты синтаксиса и
семантики, примеры и контрпримеры) **неприменимо**: проверять нечего в языке —
проверяется полнота удаления и неизменность контракта проверок.

| A3 | `grep -rni travis README.md docs/ CLAUDE.md scripts/ .github/` | совпадения **только** в артефактах фичи и строках реестров |

| A6 | `python3 scripts/check-links.py` | «Битых ссылок нет» |

### Разбивка проверок по функциональности

Отдельных тестовых данных не требуется. Окружение — рабочая копия репозитория,

контракт проверок описан там; проверка A3 существует именно для этого случая.
