## Краткое описание

README называет проект числами — сколько наборов тестов в каждой теме, сколько
разделов в документе. Пересчитываются они по дереву за секунду, но никем не
пересчитывались и протухали молча. Заведён
`scripts/check-readme-numbers.py`: он сверяет счёт наборов с числом `mod` в
`tests/<тема>/main.rs` и число разделов — с составом `book/src/main.typ`. Первый
прогон нашёл ещё одно расхождение: «17 разделов» при двадцати одном.

### Context

Класс тот же, ради которого заведены проверки документа 0520…0522: утверждение
живёт отдельно от предмета и расходится с ним без единого сигнала. Разница в
том, что здесь предмет — **само дерево**, а не вывод инструмента, поэтому
проверка стоит доли секунды и не требует бинарников.

Повод не теоретический: фича, правя README по другому поводу, нашла, что
таблица наборов отстала по **всем** строкам (`conformance` — 111 против 27,
`semantic` — 81 против 51). Правку тогда сделали руками, и ничто не мешало ей
протухнуть снова.

### Considered Options

1. **Проверять все числа README.** Отвергнуто: часть чисел — датированные
   замеры («предкоммит целиком — 4 мин 50 с», «32 кода не значились в сводной»),
   они описывают прошлое, и пересчитывать их нельзя.
2. **Помечать проверяемые числа разметкой.** Отвергнуто: README читают люди, а
   служебные метки в тексте — тот же процесс в документе, что запрещён
   правилом 24 для `book/`.
3. **Правило на каждое утверждение с однозначным предметом** (принято): сегодня
   их два, новое число заводит новое правило.

### Decision

**R1** — строка таблицы `| крейт | тема | … | N |` сверяется с числом `mod` в
`<крейт>/tests/<тема>/main.rs`; **R2** — «(N разделов и приложения» сверяется с
числом нумерованных глав в `book/src/main.typ`. Правило, не нашедшее в README ни
одной строки, роняет прогон: разметка изменилась, и проверка выродилась бы в
тривиальный успех.

### Consequences

Два класса чисел перестали протухать молча. Цена — доли секунды, бинарники не
нужны.

#### Acceptance criteria

- проверка зелёный на текущем дереве;
- контроль доказывает три расхождения и вырожденный вход;
- шаг в `precheck.sh`, контроль перед ним.

## Анализ

### Замер (правило 30, 2026-09-03)

- **R1** — семь строк таблицы, все совпадают (после правки 0523).
- **R2** — README обещал «17 разделов и приложения», в `main.typ` двадцать одна
  нумерованная глава и пять приложений. Число не пересматривалось с тех пор, как
  разделов действительно было семнадцать.

Утверждение живёт **в цитате и с переносом строки** («(17 разделов и\\n>
приложения»), поэтому построчный поиск его не видит — проверка читает по абзацу, как
`check-claude-md.py` после исправления.

### Требования и проверяемые условия

- П1: расхождение счёта наборов ловится и называет обе величины;
- П2: расхождение числа разделов ловится;
- П3: тема из README, которой нет в дереве, ловится;
- П4: README без проверяемых утверждений роняет прогон.

человек узнаёт о разрыве связи, а не теряет проверку молча.
