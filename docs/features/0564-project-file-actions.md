## Краткое описание

Полоса структуры проекта отвечает на один вопрос за раз. Пока проекта нет —
завести или открыть; когда открыт — сохранить, закрыть, выгрузить архивом и
работать с файлами: завести файл и удалить файл. Заведение спрашивает род файла
и имя без расширения — расширение ставит род. Удаление файла спрашивает и
называет файл по имени. Удаление проекта переезжает в строку списка проектов.

> Фича зарегистрирована по требованию заказчика 2026-09-09; далее проходит
> жизненный цикл по своду.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-09
- **Authors:** заказчик (требование и состав), разработка

### Context

Предыдущая фича дала полосе действия над проектом, но не над его файлами: завести
файл со страницы было нечем, а удалить — тем более. При этом полоса показывала
все действия разом: и «завести проект», и «удалить проект» — при открытом
проекте первое бессмысленно, а второе опасно соседством.

### Decision

**Полоса отвечает на один вопрос за раз.** Проекта нет — как его завести или
открыть. Проект открыт — что делать с ним (сохранить, закрыть, выгрузить) и с
его файлами (завести, удалить). Обе группы разом заставляли бы искать нужную
среди ненужных.

**Расширение ставит род файла, а не автор.** Заведение спрашивает род (модель,
сценарий, пояснение) и имя без расширения; имя собирается из них. Спрашивать
расширение значило бы перекладывать правило проекта на того, кто заводит файл.

**Удаление проекта переезжает в строку списка.** Полоса отвечает за открытый
проект, а удаляют выбранный — там его видно по имени, и мусорка стоит только у
того, чей владелец — читатель.

### Consequences

Появляется закрытие проекта: страница возвращается к безымянному буферу, текст
при этом остаётся — закрытие проекта не потеря работы.

Вместе с моделью уходит её раскладка: осиротевший файл `.takt-ui` показывал бы
схему того, чего нет.

#### Acceptance criteria

1. Без проекта в полосе — «завести» и «открыть»; с проектом — «сохранить»
   (в шапке), «закрыть», «выгрузить», «завести файл», «удалить файл».
2. Заведение файла спрашивает род и имя без расширения; имя показывается целиком
   до нажатия.
3. Заведённый файл открывается сразу.
4. Удаление файла спрашивает, называет файл и уносит парную раскладку.
5. Удаление проекта — из строки списка, с подтверждением по имени, и только
   владельцу.
6. Закрытие проекта возвращает полосу к действиям над проектами, а шапку — к
   безымянному буферу.

## Разработка

### Задача — полоса отвечает на один вопрос за раз

Видимость кнопок считается из двух признаков: открыт ли проект и вправе ли
читатель писать. Заводить и удалять файлы предлагается только тому, кто вправе
писать: чужой проект открывается на чтение, и предлагать ему правку значит
обещать отказ сервера.

### Задача — заведение и удаление файла

Окно заведения: ряд родов и поле имени; имя, которое получится, показывается до
нажатия. Удаление спрашивает и уносит парную раскладку модели. Удаление файла
добавлено в API страницы.

### Задача — закрытие проекта и удаление из списка

Закрытие возвращает страницу к безымянному буферу и снимает имя файла из шапки.
Удаление проекта переехало в строку списка: мусорка стоит у проектов читателя.

### Проверки

`check-web.sh` (102 теста), `check-design.py` (422 правила), прогон страницы на
локальном сервере с PostgreSQL.

## Тест-план

### Область и цель

Состав полосы, заведение и удаление файла, закрытие проекта, удаление проекта.

### Проверки (условие → ожидаемый результат)

1. Вошли, проекта нет → в полосе «завести» и «открыть».
2. Проект открыт → «выгрузить», «закрыть», «завести файл», «удалить файл».
3. Заведение файла: род «сценарий», имя `run` → `run.json` в дереве.
4. Заведение файла: род «модель», имя `extra` → `extra.takt` открыт и пуст.
5. Удаление файла → спрошено по имени, файл ушёл, открыт следующий.
6. Закрытие проекта → полоса вернулась, шапка без имени файла.
7. Удаление проекта из списка → спрошено по имени, проект ушёл.

## Отчёт о тестировании

### Резюме

Все семь проверок пройдены на живом сервере с базой.

### Фактические результаты по проверкам

1. Без проекта видны ровно две кнопки — заведение и выбор.
2. С проектом видны выгрузка, закрытие и обе файловые кнопки; заведение и выбор
   проекта скрыты.
3. Род «сценарий» дал `run.json`; имя показано до нажатия (`run.takt` → `run.json`
   при смене рода).
4. `extra.takt` заведён, открыт и пуст.
5. Удаление спросило «Удалить файл «extra.takt» из проекта?»; после согласия
   дерево осталось с `model.takt` и `run.json`, открыт `model.takt`.
6. Закрытие вернуло полосу к двум кнопкам, дерево — к «Проект не открыт», шапку —
   к пустому имени; кнопка сохранения скрылась.
7. Удаление проекта из строки списка спросило по имени и очистило список.

Проверки: `check-web.sh` — 102 теста, `check-design.py` — 422 правила.

Один свой, закрыт по ходу: после закрытия проекта в шапке оставалось имя файла —
она называла файл, которого на странице больше нет.
