# Фича: Порт `en` (clock enable) для цели `sv`

- **Номер:** 0063
- **Статус:** **ГОТОВО** (2026-07-19, `precheck.sh` зелёный) — см. «Итог (что сделано)» ниже
- **Зависит от:** **нет** (проверено аналитиком 2026-07-17 — см. [анализ](0063-sv-clock-enable.md#анализ)). Опоры **закрыты**: [генератор генерации в SystemVerilog](0045-sv-backend.md) (каркас `generator/sv/`, `RESERVED_NAMES`, `SV-007`), [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md) (критерий A7). **Очерёдность:** вести **после** [последовательная композиция (`+`) в цели SystemVerilog](0057-sv-sequential-composition.md) — обе правят `always_ff` в `sv_fsm.rs`.

## Краткое описание

Служебный порт `en` с умолчанием `1'b1`, дающий возможность тактировать модель
**реже** тактового домена. Аддитивен поверх принятого решения (`clk`/`rst_n`
— служебные порты, которых в языке нет).

Вынесено закрытой [генератор генерации в SystemVerilog](0045-sv-backend.md) (ADR, вопрос 1, Option C — признан
«преждевременным, но **не неверным**»).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0063-sv-clock-enable.md); пересматривает отложенный **Option C** [ADR](0045-sv-backend.md#архитектура-adr) (вопрос 1)

### Context

ADR (вопрос 1) принял **Option A**: такт Lam ≡ `posedge clk`; `clk`/`rst_n` —
неявные служебные порты, имена зарезервированы (`SV-007`). **Option C** (`clk` +
`en`) отвергнут тремя возражениями:

1. «Ещё один служебный порт, которого нет в модели → расширяет зону
   зарезервированных имён.»
2. «**Не нужен по умолчанию:** `en`, тождественно равный `1`, покрывает основной
   случай, а **тот, кому нужен делитель, добавит его снаружи — это одна строка в
   модуле верхнего уровня**. Вводить порт ради частного случая — усложнение
   интерфейса без запроса.»
3. «Усложняет тестбенч и сверку (нужно ещё дёргать `en`).»

Кандидат предложил вернуться к Option C в форме «порт с умолчанием `1'b1`».
Проработка **проверила** это пробами — и два возражения из трёх не устояли.

#### Проба 1: умолчание входного порта работает в обоих инструментах

`module counter(input logic clk, input logic rst_n, input logic en = 1'b1, output logic [7:0] cnt);`
(IEEE 1800 §23.2.2.4)

| Инструмент | Результат |
|---|---|
| `verilator --lint-only -Wall` | **принял** (и модуль, и инстанцирование с **неподключённым** `en`) |
| `yosys ... synth` | **принял** |

#### Проба 2: умолчание работает семантически, а не только синтаксически

«Принял» ≠ «значит `1`» — урок (`real` verilator принимает молча;
комбинационную петлю yosys синтезирует молча). Поэтому семантика проверена
**двумя способами**.

**Синтез** (`yosys synth -flatten`, три top-модуля):

| `en` | Ячеек | Триггеры |
|---|---|---|
| **не подключён** | **23** | `8 × $_DFF_PN0_` (**без** разрешения) |
| `1'b1` | **23** | `8 × $_DFF_PN0_` — **идентично** |
| `1'b0` | **1** | всё оптимизировано (счётчик заморожен) |

Без `-flatten` все три давали одинаковый результат (`8 × $_DFFE_PN0P_`) —
`synth` иерархию не уплощает, константы не распространяются, и проба **ничего не
доказывала**. Это ловушка самой пробы, а не инструмента.

**Симуляция** (`verilator --binary`, три экземпляра в одном тестбенче):

```
en не подключён = 10 | en=1 = 10 | en=0 = 0
ВЕРДИКТ: неподключённый en ЭКВИВАЛЕНТЕН en=1 (умолчание сработало)
```

Проверять симуляцией **обязательно**: сверка (`conformance_sv_tests`) гоняет
модуль именно `verilator --binary`, то есть семантика симулятора — то, на чём
стоит основной критерий.

#### Проба 3: цена возражения 1 — одна строка

Механизм уже есть:
`sv_module.rs:57` — `RESERVED_NAMES: &[&str] = &["clk", "rst_n", "is_done", "state", "state_next"];`
→ `check_sv_name` → `SV-007`. Добавление `en` — **одна запись**. Греп по
`examples/`: порта/переменной с именем `en` в корпусе **нет**.

### Decision Drivers

1. **Возражения ADR проверяемы — и обязаны быть проверены, а не унаследованы.**
   Решение пересматривается не потому, что «хочется порт», а потому что пробы
   опровергли его основания.
2. **Аддитивность обязана быть доказанной, а не обещанной** (правило 11).
3. **Не платить за то, чем не пользуются.** Кто не трогает `en` — не должен
   заметить фичу вовсе.

### Пересмотр возражений ADR

| # | Возражение 0045 | Вердикт проработки |
|---|---|---|
| 1 | Расширяет зону зарезервированных имён | **В силе.** Цена — одна строка в `RESERVED_NAMES`; корпус свободен. Принимается как осознанная плата. |
| 2 | «Тот, кому нужен делитель, **добавит его снаружи — одна строка**» | **Не устояло.** Снаружи clock enable добавить **нельзя**: либо делить `clk` (второй тактовый домен → CDC, ровно то, чего Option A избегал), либо ставить **клоковый проверка** (нужны ICG-ячейки; в FPGA-потоках не рекомендуется, задевает DFT). Ни то, ни другое не «одна строка». **Штатный** способ тактировать синхронный блок реже — это и есть вход `en`. |
| 3 | «Усложняет тестбенч и сверку (нужно ещё дёргать `en`)» | **Опровергнуто пробой 2.** С умолчанием `en` **не подключают** — и поведение **побитово** совпадает с сегодняшним (симуляция: `10 = 10`; синтез: 23 ячейки = 23 ячейки). Тестбенч и сверка не меняются вовсе. |

### Considered Options

#### Option A. `en` с умолчанием `1'b1`

**Pros:**
- Даёт штатный способ тактировать модель реже системного `clk` **без** второго
  домена и без клокового проверки (возражение 2 не работает).
- **Аддитивность доказана пробой**: неподключённый `en` ≡ сегодняшнее поведение —
  и в симуляции, и в синтезе (драйверы 2, 3).
- Цена — одна строка в `RESERVED_NAMES` + `if (en)` в `always_ff`.
- Форма вывода одна (никаких флагов и вариантов).

**Cons:**
- Имя `en` становится зарезервированным (возражение 1 — в силе).
- Умолчания портов — не самая известная часть IEEE 1800; читатель может
  удивиться. Смягчение: комментарий в порождаемом модуле.

#### Option B. `en` без умолчания (обязательный порт)

**Pros:** ничего не прячет.

**Cons:** **ломает** всякое существующее инстанцирование и сверку (правило 11);
цена — ради частного случая. Отвергается.

#### Option C. Флаг генератора (`--sv-clock-enable`)

**Pros:** кто не просил — не получил.

**Cons:** **две формы вывода → два пути кода → две поверхности дефектов** (тот же
довод, по которому [общие переменные корня → структура `Shared` вместо параметров по одной](0059-rust-shared-struct.md#архитектура-adr) отверг «`Shared` по
порогу»). С умолчанием рост интерфейса и так бесплатен — флаг решает
несуществующую проблему.

#### Option D. Статус-кво (решение ADR)

**Pros:** ноль работы.

**Cons:** оставляет в силе возражение 2, которое **не соответствует
действительности**: пользователю предлагается «одна строка снаружи», которой не
существует.

### Decision

Принимается **Option A**.

Решение ADR (вопрос 1) в части Option C **пересматривается**: два из трёх его
возражений опровергнуты пробами — «добавить снаружи» невозможно без второго
домена или клокового проверки, а «усложняет сверку» неверно при наличии умолчания.
Третье возражение (зарезервированное имя) принимается как плата ценой в одну
строку.

**Нормативные правила:**

1. Модуль цели `sv` получает вход **`en` с умолчанием `1'b1`**
   (IEEE 1800 §23.2.2.4).
2. Шаг автомата происходит на `posedge clk` **при `en == 1`**.
3. **`en` не проверяет сброс**: `if (!rst_n) … else if (en) …`. Асинхронный сброс
   обязан работать независимо от разрешения — иначе модуль нельзя сбросить, пока
   он не разрешён.
4. **`en` добавляется в `RESERVED_NAMES`** (`sv_module.rs:57`); коллизия →
   **`SV-007`**, как у `clk`/`rst_n`.
5. **Сверка `en` не подключает** — то есть проверяет, что умолчание держится.
6. **Цель `sv-mmio`** ([цель `sv-mmio`: адреса портов → регистровый файл на шине](0062-sv-mmio-target.md#архитектура-adr)), когда появится,
   наследует правила 1–4.
7. Язык **не меняется** → версия не растёт (правило 22); `en` — служебный порт
   цели, как `clk`/`rst_n`, и в `.lam` не выразим.

### Consequences

#### Положительные

- Штатный способ тактировать автомат реже тактового домена — без CDC и без
  клокового проверки.
- Тик Lam становится буквально «такт с разрешением», что ближе к скан-циклу
  C/ST (довод «pro» самого ADR).
- Существующие потребители не замечают правки (доказано пробой).

#### Отрицательные / Action items

- **A-1. `en` — зарезервированное имя.** Модель с портом `en` перестанет
  транслироваться целью `sv` (→ `SV-007`). Корпус свободен, но это **изменение
  контракта** для гипотетической модели; правило 11 требует его назвать — названо.
- **A-2. Умолчание порта обязано быть проверено сверкой, а не только проверкой.**
  Проверка (verilator lint + yosys) доказывает валидность и синтезируемость; что
  неподключённый `en` **значит `1`** — доказывает симуляция. У 0045 дефект такого
  класса приняли **оба** инструмента.
- **A-3. Ловушка пробы, стоящая записи:** `yosys synth` **без `-flatten`**
  иерархию не уплощает → константы не распространяются → проба даёт одинаковый
  результат для `en=0` и `en=1` и **ничего не доказывает**. Записано в
  `CLAUDE.md`, чтобы следующий проверяющий не поверил ложному «подтверждению».

#### Acceptance criteria

1. **A1.** Порождённый модуль имеет вход `en` с умолчанием `1'b1`; **verilator
   `-Wall`** и **yosys** принимают (оба — ловят непересекающиеся классы).
2. **A2.** **Симуляция:** неподключённый `en` ≡ `en = 1'b1` **побитово**;
   `en = 0` — автомат стоит.
3. **A3.** **Потактовая сверка** (`conformance_sv_tests`, `en` **не подключён**) —
   вердикты **не изменились**.
4. **A4.** Сброс работает при `en = 0` (правило 3) — проверяется симуляцией.
5. **A5.** Модель с портом `en` → **`SV-007`** (правило 4).
6. **A6.** `is_done` (комбинационный выход) от `en` не зависит.
7. **A7.** Вывод прочих целей (`c`/`c-hal`/`st`/`st-at`/`rust`/`plantuml`)
   **побайтово прежний**; язык не изменился, версия не поднята.

## Анализ

### Цель и контекст

ADR (вопрос 1) отверг Option C (`clk` + `en`) тремя возражениями. Кандидат
предложил вернуться к нему в форме «порт с умолчанием `1'b1`», назвав вариант
«преждевременным, но **не неверным**».

Проработка **проверила возражения пробами**: два из трёх не устояли. ADR
принял **Option A** — `en` с умолчанием `1'b1`.

### Замер (пробы 2026-07-17)

| # | Что проверялось | Результат |
|---|---|---|
| 1 | Умолчание входного порта (IEEE 1800 §23.2.2.4) | **verilator `-Wall`** и **yosys** принимают; принимают и инстанцирование с **неподключённым** `en` |
| 2а | Семантика — **синтез** (`yosys synth -flatten`) | `en` не подключён → **23 ячейки, `8 × $_DFF_PN0_`** (без разрешения); `en = 1'b1` → **идентично**; `en = 1'b0` → **1 ячейка** (всё оптимизировано) |
| 2б | Семантика — **симуляция** (`verilator --binary`) | `en не подключён = 10 \| en=1 = 10 \| en=0 = 0` → **умолчание сработало** |
| 3 | Цена «зарезервированного имени» | `sv_module.rs:57` — `RESERVED_NAMES` уже есть (`clk`, `rst_n`, `is_done`, `state`, `state_next`) → `check_sv_name` → `SV-007`. Добавление `en` = **одна строка** |
| 4 | Имя `en` в корпусе | **отсутствует** (греп по `examples/`) |

**Ловушка самой пробы:** без `-flatten` `yosys synth` иерархию не уплощает,
константы не распространяются, и все три случая дают одинаковый результат
(`8 × $_DFFE_PN0P_`) — то есть проба выглядит проведённой, но **ничего не
доказывает**. Первый прогон именно так и выглядел.

**Почему обязательна и симуляция:** сверка (`conformance_sv_tests`) гоняет
модуль **`verilator --binary`** — значит семантика симулятора и есть то, на чём
стоит основной критерий. Синтез её не заменяет.

|---|---|---|---|

### Зависимости фичи (правило 17/19)

- **Зависит от:** **нет**. Опора — **закрытая** [генератор генерации в SystemVerilog](0045-sv-backend.md)
  (каркас `generator/sv/`, `RESERVED_NAMES`, `SV-007`) и **закрытая**
  [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md) (критерий A7).
- **Пересечения по коду:** [последовательная композиция (`+`) в цели SystemVerilog](0057-sv-sequential-composition.md)
  правит `sv_fsm.rs` (где живёт `always_ff`) — **пересечение реальное**, но
  тривиальное: 0063 добавляет `if (en)` в ветку `else`. Разумно вести **после**
  0057, чтобы не мержить регистр шага с разрешением.
  [цель `sv-mmio`: адреса портов → регистровый файл на шине](0062-sv-mmio-target.md) наследует правила 1–4 (правило 6
  ADR), но **не зависит**: порядок любой.
- **Влияние на порядок:** никого не блокирует и не разблокирует.

### Приоритет (Tier) — обоснование

**Tier 3.**

- Ничего не сломано: модель тактируется каждым фронтом, и это работает.
- **Но обход, обещанный ADR, не существует** — и это поднимает фичу над
  «чистой косметикой»: сегодня пользователю, которому нужен автомат на 1 кГц в
  дизайне на 100 МГц, предложить нечего, кроме второго домена или клокового проверки.
- Против Tier 2: запроса нет; корпус не страдает; ни одна фича не зависит.

### Требования и проверяемые условия

- **R1. Порт `en` с умолчанием `1'b1`** (IEEE 1800 §23.2.2.4).
- **R2. Шаг — на `posedge clk` при `en == 1`.**
- **R3. `en` Не проверяет сброс:** `if (!rst_n) … else if (en) …` — иначе модуль
  нельзя сбросить, пока он не разрешён.
- **R4. `en` — зарезервированное имя** (`RESERVED_NAMES`), коллизия → `SV-007`.
- **R5. Сверка `en` не подключает** — то есть проверяет, что умолчание держится.
- **R6. `is_done` от `en` не зависит** (комбинационный выход).
- **R7. Прочие цели не задеты; язык не меняется** → версия не растёт.

### Особенности по обратной функциональности

**Аддитивность доказана, а не обещана** (правило 11): проба 2 показала, что

(`10 = 10`), и в синтезе (23 ячейки = 23 ячейки, `$_DFF_PN0_` без разрешения).
Существующие потребители правки не заметят.

**Одно изменение контракта всё же есть** (правило 11 требует назвать): имя `en`
становится **зарезервированным** — модель с портом `en` перестанет транслироваться
целью `sv` (`SV-007`). Корпус свободен, но гипотетическая модель пострадает. Это
осознанная плата (возражение 1 ADR — единственное, устоявшее).

Прочие цели, симулятор, LSP, форматтер — не задеты. Язык не меняется (`en` — как
`clk`/`rst_n`, в `.lam` не выразим) → версия не растёт (правило 22).

### Риски и зависимости

- **R-1. «Принял» ≠ «значит `1`».** Главный риск класса `sv`: у 0045 дефект
  («`always_comb` читает регистр вместо `_next`») приняли **оба** инструмента.
  Снижение: A2 — семантика доказывается **симуляцией** (и подтверждена синтезом),
  а не приёмкой линтера.
- **R-2. Ложное «подтверждение» пробой.** `yosys synth` **без `-flatten`** даёт
  одинаковый результат для `en=0` и `en=1` — проба выглядит проведённой и не
  доказывает ничего. Снижение: записать ловушку в `CLAUDE.md` (A-3 ADR).
- **R-3. Сброс, загейченный разрешением.** Если `en` попадёт **выше** проверки
  `rst_n`, модуль станет несбрасываемым при `en=0` — тихо. Снижение: R3 + A4.
- **R-4. Конфликт слияния с 0057** (обе правят `always_ff`). Снижение: вести 0063
  **после** 0057.
- **R-5. Умолчания портов малоизвестны.** Читатель порождённого модуля может
  решить, что `en` обязателен. Снижение: комментарий в выводе.

## Разработка

### Задача

#### Что было

Такт Lam ≡ `posedge clk` (решение ADR, вопрос 1, Option A); служебные порты —
только `clk`/`rst_n`. Тактировать автомат реже тактового домена **нечем**: ADR предполагал, что «делитель добавят снаружи — одна строка», но проработка 0063
показала, что такой строки **не существует** (снаружи — либо второй домен, либо
клоковый проверка).

#### Что сделано

1. **Порт:** `input logic en = 1'b1` (IEEE 1800 §23.2.2.4) — умолчание проверено
   **обоими** инструментами и **двумя** способами (симуляция + синтез).
2. **Такт:** `always_ff @(posedge clk or negedge rst_n)` →
   `if (!rst_n) <сброс> else if (en) <шаг>`.
   **`en` Не проверяет сброс** (правило 3 ADR): иначе модуль нельзя сбросить, пока
   он не разрешён, — и это прошло бы **молча**.
3. **Зарезервированное имя:** добавить `"en"` в `RESERVED_NAMES`
   (`sv_module.rs:57`) — механизм `check_sv_name` → `SV-007` уже есть; правка =
   одна строка.
4. **Комментарий в выводе:** умолчания портов — малоизвестная часть IEEE 1800;
   читатель может решить, что `en` обязателен.
5. `is_done` — комбинационный выход, от `en` **не зависит** (правило 6 ADR).

**Вести после [последовательная композиция (`+`) в цели SystemVerilog](0057-sv-sequential-composition.md#разработка)**: обе задачи правят
`always_ff` в `sv_fsm.rs` (0057 добавляет регистр шага). Конфликт тривиален, но
разводить его дешевле последовательностью.

#### Проверки

- **T1/A1:** проверка — **verilator `-Wall` И yosys**.
- **T2/A2 — семантика:** симуляция трёх экземпляров: `не подключён` ≡ `en=1`
  побитово, `en=0` → стоит. Синтезом проверять **только с `-flatten`** — без
  него `en=0` неотличим от `en=1`, и проба даёт ложное подтверждение.
- **T3/A3 — основная:** `conformance_sv_tests` с **неподключённым** `en` —
  вердикты не изменились.
- **T4/A4 + T9:** сброс при `en=0` работает; мутация «`if (en)` выше `rst_n`»
  обязана валить T4.
- **T6/A5:** модель с портом `en` → `SV-007`.
- **T8/A7:** вывод прочих целей побайтово прежний; версия не поднята.

### Реализация (одна тема, три точки)

1. **Порт** — `emit_module_header` (`sv_module.rs`): после `rst_n` печатается
   `input logic en = 1'b1` с комментарием, что порт **не** обязателен.
2. **Проверка шага** — `emit_ff` (`sv_fsm.rs`): `end else begin` → `end else if (en) begin`.
   Ветвь `if (!rst_n)` выше — **не** тронута (правило 3: `en` не проверяет сброс).
3. **Зарезервированное имя** — `"en"` добавлено в `RESERVED_NAMES`
   (`sv_module.rs`); текст `SV-007` дополнен упоминанием `en`.

### Отклонения от плана (с обоснованием)

- **Список чувствительности `always_ff` Не менялся на `posedge clk or negedge
  rst_n`** (вопреки буквальной записи задачи 0063-01, п. 2). Цель `sv` использует
  **синхронный** сброс (`always_ff @(posedge clk)`, охраняется `mod.rs::
  reset_is_synchronous`); нормативное правило 3 ADR требует лишь `if (!rst_n) …
  else if (en) …`, что синхронный сброс удовлетворяет: ветвь сброса вычисляется
  на фронте `clk` первой, независимо от `en`. Запись задачи `negedge rst_n` —
  иллюстрация типового async-паттерна, а не требование к этому генератору.
- **A2/A4 — один тестбенч, а не два прогона синтеза.** Семантика проверена
  `verilator --binary` (именно им гоняет основную сверку `conformance_sv_tests`);
  синтезная проба `-flatten` (23/23/1 ячейка) выполнена вручную при проработке
  ADR и в автотест не вынесена (сборка verilator дешевле и покрывает семантику).

### Найденные дефекты

Нет. Аддитивность подтверждена: `sv_trace` не подключает `en`, и все прежние
сверки остались зелёными без единой правки.

### Примеры и контрпримеры (правило 16)

- **Пример:** `dut (.clk(clk), .rst_n(rst_n), .is_done(done))` — `en` не
  подключён, поведение прежнее (умолчание `1'b1`); либо `dut (…, .en(divider_en))`
  — модель тактируется реже домена.
- **Контрпример:** `in en: bit; … y := en;` → `SV-007` (имя зарезервировано целью;
  модель остаётся валидной для `c`/`c-hal`/`plantuml`/`st`/`rust`).

**ADR отверг Option C тремя возражениями. Проработка проверила их пробами —

| # | Возражение ADR | Вердикт |
|---|---|---|
| 1 | Расширяет зону зарезервированных имён | **в силе** — цена — **одна строка** в `RESERVED_NAMES` (`sv_module.rs:57`); механизм `SV-007` уже есть; имени `en` в корпусе **нет** |
| 2 | «Тот, кому нужен делитель, **добавит его снаружи — одна строка**» | **Не устояло** — снаружи clock enable добавить **нельзя**: либо делить `clk` (второй домен → CDC, ровно то, чего Option A избегал), либо клоковый проверка (ICG-ячейки; в FPGA-потоках не рекомендуется, задевает DFT). **Штатный** способ — именно вход `en` |
| 3 | «Усложняет тестбенч и сверку» | **Опровергнуто пробой** — с умолчанием `en` не подключают, и поведение **побитово** прежнее |

**Аддитивность доказана, а не обещана** (правило 11) — двумя способами, потому что
«принял» ≠ «значит `1`» (урок: `real` verilator принимает молча, петлю yosys
синтезирует молча):

- **Симуляция** (`verilator --binary` — именно им гоняет сверка):
  `en не подключён = 10 | en=1 = 10 | en=0 = 0`;
- **Синтез** (`yosys synth -flatten`): не подключён → **23 ячейки, `8 × $_DFF_PN0_`**
  (без разрешения); `en=1'b1` → **идентично**; `en=1'b0` → **1 ячейка**.

**Ловушка самой пробы, стоящая записи:** без `-flatten` `yosys synth` иерархию
не уплощает, константы не распространяются, и все три случая дают одинаковый
результат — проба выглядит проведённой и **не доказывает ничего**. Первый прогон
именно так и выглядел.

**Принято** ([ADR](0063-sv-clock-enable.md#архитектура-adr), Option A): `en` с умолчанием
`1'b1` (IEEE 1800 §23.2.2.4); шаг — на `posedge clk` при `en == 1`; **`en` не
проверяет сброс** (иначе модуль нельзя сбросить, пока он не разрешён); `en` — в
`RESERVED_NAMES` → коллизия даёт `SV-007`. Отклонены: обязательный `en` (ломает
всех), флаг генератора (две формы вывода → два пути кода — довод 0059),
статус-кво.

**Изменение контракта, названное честно** (правило 11): имя `en` становится
**зарезервированным** — модель с портом `en` перестанет транслироваться целью `sv`.
Корпус свободен; это единственная устоявшая плата.

Язык не меняется (`en` — как `clk`/`rst_n`, в `.lam` не выразим) → версия не
растёт (правило 22).
