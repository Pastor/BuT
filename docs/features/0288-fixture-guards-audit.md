## Краткое описание

**Фикстуры `Ce6`/`FE6` контролируются проверкой «разбирается без ошибок».**
Найдено при закрытии [вывод типов не протягивает тип через ссылку константа-константа](0204-const-ref-type-inference.md)
(2026-08-16): тест `example_ce6_type_inference_chain_valid` объявлял, что
«тип `y` выводится из переменной `x`», а проверял лишь отсутствие ошибок
разбора — и проходил всё время, пока вывод не работал вовсе. Контроль заменён,
но **соседи не осмотрены**: рядом лежат `ce6_type_from_func`, `fn_array_param`
и другие с той же формой проверки. Класс знаком (исправление: тесты на
структуру автомата вместо теста на язык). Кандидат: пройти по фикстурам
`valid/`, у каждой спросить «что именно она обещает» и проверять **это**.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

## Что известно на входе

Всё, что проверено, — в разделе выше: это **дословный текст кандидата** со
своим замером и ссылками на фичу, при закрытии которой он был вынесен. Ничего
сверх этого не проверялось.

Замер снят на дату, указанную в тексте. Прежде чем брать фичу в работу,
**перепроверь** его: условие карточки перепроверяется, а не наследуется — урок
[остаточные старые имена языка в данных и комментариях](0161-fixture-comments-rename.md), где обоснование отказа держало
работу отложенной два месяца и оказалось неверным уже в момент отказа.

## Направление решения (наметка, не решение)

Наметка — в тексте кандидата выше (там, где он её содержит). Решение о том,
**делать ли фичу вообще**, отложено заказчиком и принимается до стадии 2.

### Context

Фикстура `valid/` **что-то обещает**: «тип выводится из возвращаемого значения
функции», «локальная переменная доступна в блоке», «перечисление несёт
варианты». Контроль обычно выглядел так:

```rust
/// Ce6: Файл ce6_type_from_func.takt разбирается без ошибок.
#[test]
fn example_ce6_type_from_func_valid() {
    build_file("…/ce6_type_from_func.takt").expect("должен разбираться");
}
```

— то есть **констатация разбора**. Такой контроль проходит и в мире, где
обещанное поведение не работает вовсе: ровно это случилось с
`ce6_type_inference_chain` (фича — вывод типа по ссылке отсутствовал, тест
был зелёным). Класс тот же, что у исправления.

**Замер-20:** из **62** тестов на фикстурах `valid/` **28** не имеют ни
одного содержательного утверждения — только `unwrap`/`expect` либо
`assert!(… .is_ok())`.

### Decision Drivers

1. **Зелёный контроль, ничего не проверяющий, хуже отсутствующего:** он создаёт
   уверенность.
2. **Переписать все 28 разом — не работа одной фичи:** у каждой фикстуры своё
   обещание, и его надо прочитать.
3. **Класс обязан перестать расти** — иначе усиление догоняет прибавление.

### Considered Options

#### Option A. Переписать все 28 контрольных тестов

**Pros:** класс закрыт целиком.
**Cons:** объём; и часть фикстур обещает именно «принимается без ошибок» —
переписывать их не во что.

#### Option B. Усилить говорящие + ратчет на остальные

Усиливаются те, чьё обещание сформулировано конкретно; прочие замораживаются
реестром, который не имеет права расти.

**Pros:** класс перестаёт расти сегодня; усиление идёт по мере надобности.
**Cons:** реестр из 28 записей — видимый долг (это и есть замысел).

#### Option C. Запретить констатации целиком

**Cons:** фикстура, обещающая «эта запись законна», проверяется именно
построением; запрет заставил бы выдумывать проверки.

### Decision

Принимается **Option B**:

1. `takt-lang/tests/semantic/fixture_promises_tests.rs` — пять усиленных
   контрольных тестов: тип из функции (`Bool`), локальная переменная блока (узел в дереве
   **и** разрешённое тело), варианты перечисления, узел индексации массива, три
   именованных блока.
2. `scripts/fixture-guard-baseline.txt` — реестр констатаций (28 записей).
3. `scripts/check-fixture-guards.py` (шаг предкоммита, самопроверка первой):
   **F1** — новый слабый контроль, **F2** — протухшая запись (тест усилен или
   переименован; иначе храповик проворачивается назад).

### Consequences

#### Положительные

- Пять обещаний проверяются по существу.
- Новый контроль-констатация роняет предкоммит.
- Долг виден числом и убывает удалением записей.

#### Отрицательные / Action items

- Проверка **синтаксическая**: она отличает утверждение от констатации, но не
  судит о смысле. Тест с `assert_eq!(1, 1)` её обманет — от этого защищает
  ревью.
- 28 записей остаются долгом; их усиление — работа последующих фич.

#### Acceptance criteria

1. Пять усиленных контрольных тестов зелёные и проверяют обещание.
2. F1 ловится (проба: новый слабый тест).
3. F2 ловится (самопроверка).
4. **Контроль:** согласованное дерево проверка не роняет.
5. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Прекратить рост класса «контроль констатирует разбор» и усилить те контроля, чьё
обещание сформулировано конкретно. ADR принял Option B.

### Замер (снят 2026-08-20)

| Что | Значение |
|---|---|
| тестов на фикстурах `valid/` | **62** |
| из них без содержательного утверждения | **28** |

Кандидат называл `ce6_type_from_func` и `fn_array_param`; замер показал, что
класс шире и охватывает семь файлов наборов `semantic`, `syntax`, `targets`.

**Находка при усилении:** фикстура `ce4_enum_basic.takt`, вопреки имени,
перечислений **не содержит вовсе** — её комментарий прямо говорит «enum
добавляется программно». Контроль на неё усилить нечем; настоящая фикстура
перечислений — `enum_basic.takt`, и усилен контроль на неё.

**Две ловушки, найденные прогоном** (обе — свод в действии):

1. **«В дереве нет `Unresolved`» — неверная проверка.** Условия рёбер `ref` по
   инварианту проекта остаются `Condition::Unresolved`, и такой контроль падал бы
   на любой корректной модели. Проверять надо **тело блока** (`Always { body:
   Block(…) }`).
2. **Смотреть надо туда, где написано.** Индексация фикстуры `array_access`
   стоит в **инициализаторах объявлений**, а не в теле состояния; перечисление
   `enum_basic` объявлено во **вложенной модели**. Первая редакция контрольных тестов
   искала не там и падала.

## Разработка

### Задача

#### Что сделано

**`takt-lang/tests/semantic/fixture_promises_tests.rs`** — пять контрольных тестов,
проверяющих **обещание** фикстуры:

| Фикстура | Обещание | Что проверяется |
|---|---|---|
| `ce6_type_from_func.takt` | тип из возвращаемого значения функции | `ty_of(result) == "Bool"` |
| `local_var_in_block.takt` | локальная переменная доступна в блоке | узел `name: "x"` **и** разрешённое тело `Always { body: Block(…) }` |
| `enum_basic.takt` | перечисление несёт варианты | все четыре варианта в дереве вложенной модели |
| `array_access.takt` | индексация элемента | узел `ArraySubscript` в инициализаторах |
| `named_blocks.takt` | `enter`/`exit`/`always` | все три варианта в дереве состояния |

**Две ловушки, найденные прогоном:**

1. проверка «в дереве нет `Unresolved`» **неверна**: условия рёбер `ref` по
   инварианту проекта остаются неразрешёнными, и контроль падал бы на любой
   корректной модели;
2. смотреть надо **туда, где написано**: индексация `array_access` стоит в
   инициализаторах объявлений, перечисление `enum_basic` — во вложенной модели.

Фикстура `ce4_enum_basic.takt`, вопреки имени, перечислений не содержит
вовсе (её комментарий: «enum добавляется программно») — усиливать там нечего.

**`scripts/fixture-guard-baseline.txt`** — реестр 28 констатаций с причиной и
правилом правки (только удаление вместе с усилением).

**`scripts/check-fixture-guards.py`** (шаг предкоммита, самопроверка первой):
`F1` — новый слабый контроль, `F2` — протухшая запись реестра.

#### Проверка

```sh
cargo test --test semantic fixture_promises_tests::   # 5 тестов
python3 scripts/check-fixture-guards.py --self-test
python3 scripts/check-fixture-guards.py               # 62 теста, 28 в реестре
```
