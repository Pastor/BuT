## Краткое описание

**Ссылка на вложенную модель подключённого файла невыразима.** Замер там же:
`import "helper.takt";` вносит модель по имени **файла**, и если состояния
файла объявлены у его вложенной модели, то снаружи видна обёртка без
состояний, а вложенная недоступна вовсе (`import … as Lib; start Main =
Helper;` → `SE-001`). Сегодня это лечится переносом состояний на верхний
уровень подключаемого файла, и `SE-106` прямо об этом говорит сноской.
Кандидат: решить, нужна ли языку **квалифицированная** ссылка (`Lib::Helper`)
или достаточно диагностики. Запись «состояния у вложенной модели» выглядит
естественно и встречается: две фикстуры корпуса (`tests/data/goto56/`)
написаны именно так и не компилировались **никогда**.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по правилу 17.

## Что известно на входе

Всё, что проверено, — в разделе выше: это **дословный текст кандидата** со
своим замером и ссылками на фичу, при закрытии которой он был вынесен. Ничего
сверх этого не проверялось.

Замер снят на дату, указанную в тексте. Прежде чем брать фичу в работу,
**перепроверь** его: условие карточки перепроверяется, а не наследуется — урок
[остаточные старые имена языка в данных и комментариях](0161-fixture-comments-rename.md), где обоснование отказа держало
работу отложенной два месяца и оказалось неверным уже в момент отказа.

### Context

Кандидат утверждал: **«ссылка на вложенную модель подключённого файла
невыразима»**, и предлагал решить, не нужна ли языку квалифицированная форма
`Lib::Helper`.

**Замер-19 это опроверг.** Прогон четырёх форм на паре файлов
(`lib.takt` объявляет `model Helper { start Idle … }`, приложение подключает
его):

| Запись в приложении | Ответ |
|---|---|
| `import "lib.takt"; start Main = Helper;` | **`SE-001`** «Модель 'Helper' не найдена» |
| `import "lib.takt"; start Main = Lib;` | **`SE-106`** «модель 'Lib' не содержит ни одного состояния» + сноска про вложенную |
| `import "lib.takt" as Lib; start Main = Helper;` | **`SE-001`** |
| **`import { Helper } from "lib.takt"; start Main = Helper;`** | **исполняется**: `Idle`, `n = 1, 2, 3` |

То есть форма для ссылки на вложенную модель в языке **уже есть** — выборочный
импорт. Невыразимости нет; есть **недоинформированность автора**: `SE-001`
говорит «не найдена» и молчит о том, что модель рядом и подключается одной
строкой.

**Второй факт того же замера.** Сноска `SE-106`, единственная, что указывает
выход, печатается компилятором и **не печатается симулятором**: `takt-sim`
строит текст диагностики своей функцией, где цикла по заметкам нет. Один вход —
два разных объёма сведений. Это ровно тот класс, о котором предупреждает
док-комментарий `format_compile_error` («копия формата в `taktc` уже расходилась
однажды»), — вторая копия жива и разошлась.

Записи «состояния у вложенной модели» встречаются: две фикстуры корпуса
(`tests/data/goto56/`) написаны так и не компилировались никогда.

### Decision Drivers

1. **Синтаксис не вводится там, где форма уже есть.** Язык — не место для
   второго способа сделать то же самое (`Lib::Helper` дублировал бы выборочный
   импорт).
2. **Диагностика обязана называть выход**, если он существует и известен
   компилятору: имя вложенной модели у него под рукой.
3. **Формат диагностики — свойство диагностики**. Потребитель,
   печатающий её своей копией, теряет часть — что и произошло.

### Considered Options

#### Option A. Ввести квалифицированную ссылку `Lib::Helper`

**Pros:** буквально исполняет кандидата.

**Cons:** второй способ выразить уже выразимое; новый токен, правки грамматики,
LSP и плагинов — ради формы, эквивалентной `import { Helper } from …`.
Отвергнуто замером.

#### Option B. Ничего не делать: форма есть, автор её найдёт в документе

**Cons:** `SE-001` говорит «не найдена» — утверждение, которое автор читает как
«такой модели нет», и идёт переносить состояния на верхний уровень. Замер
показал, что именно так и поступают.

#### Option C. Подсказка в диагностике + починка печати заметок

**Pros:**
- автор получает ответ там, где задал вопрос;
- язык не растёт;
- заметки перестают теряться у второго потребителя — класс, названный в
  собственном док-комментарии библиотеки.

**Cons:** объём фичи меняется относительно карточки — но карточка написана до
замера, а замер её опроверг (правило 30).

### Decision

Принимается **Option C**.

1. `SE-001` получает **сноску**, когда имя найдено среди вложенных моделей
   моделей верхнего уровня: она называет владельца и форму подключения
   (`import { Имя } from "…";`).
2. Печать заметок выносится в **общий носитель** `diagnostics::format_notes`,
   который зовут и `format_compile_error`, и `takt-sim`.

**Квалифицированная ссылка не вводится** — решение по замеру, а не по вкусу.

### Consequences

#### Положительные

- Автор, написавший естественную запись, получает готовый ответ.
- Заметки диагностик доходят до пользователя эталона.

#### Отрицательные / Action items

- Сноска строится по вложенным моделям **верхнего уровня** — то есть по одному
  уровню вложенности. Глубже (модель в модели в модели) она молчит; граница
  названа в коде.
- Подсказка не называет **файл**: у обёртки нет обратной ссылки на путь
  импорта, а имя файла автор знает по своей строке `import`.

#### Acceptance criteria

1. `import "lib.takt"; start Main = Helper;` даёт `SE-001` со сноской о
   выборочном импорте (A1).
2. Обычная опечатка в имени модели сноски **не** получает (A2, контроль).
3. `takt-sim` печатает заметки диагностики так же, как `taktc` (A3).
4. Форма `import { Helper } from "lib.takt";` работает, как и прежде (A4).
5. `./scripts/precheck.sh` зелён (A5).

## Анализ

### Цель и контекст

Кандидат утверждал, что ссылка на вложенную модель подключённого файла
**невыразима**, и предлагал ввести квалифицированную форму `Lib::Helper`. Замер
это опроверг: форма есть — выборочный импорт. Фича заменяет несуществующую
проблему существующей: автор о форме не знает, потому что диагностика о ней
молчит.

### Замер (снят заново, правило 30)

2026-08-19, пара файлов: `lib.takt` объявляет `model Helper { start Idle … }`,
приложение подключает его.

| Запись | Ответ до фичи | После |
|---|---|---|
| `import "lib.takt"; start Main = Helper;` | `SE-001` «не найдена», молча | `SE-001` **со сноской** о выборочном импорте |
| `import "lib.takt"; start Main = Lib;` | `SE-106` + сноска (у `taktc`); **у `takt-sim` сноски нет** | сноска у обоих |
| `import "lib.takt" as Lib; start Main = Helper;` | `SE-001` | то же + сноска |
| **`import { Helper } from "lib.takt";`** | **исполняется** (`Idle`, `n = 1, 2, 3`) | не изменилось |
| **контроль** `start Main = Helpr;` (опечатка) | `SE-001` без сноски | **не изменилось** |

Два вывода:

1. **Невыразимости нет.** Кандидат проверял три формы из четырёх; четвёртая —
   работает. Новый синтаксис не нужен.
2. **Заметки терялись у эталона.** `takt-sim` строил текст диагностики своей
   функцией без цикла по заметкам, и сноска `SE-106` — единственный указатель
   выхода — до пользователя не доезжала. Класс назван в док-строке самой
   библиотеки: «копия формата в `taktc` уже расходилась однажды».

ошибки.

### Риски и зависимости

- **Риск: сноска станет шумом.** Снят контролем (T2): подсказка появляется
  только когда имя действительно найдено среди вложенных.
- **Риск: обход по вложенным дорог.** Он идёт **только** на пути отказа, то

- **Граница:** обход — один уровень вложенности; глубже подсказка молчит.
  Названо в коде.

## Разработка

### Задача

#### Что было

`SE-001` строился в двух местах `semantic/extend.rs` одинаковым литералом:
«Модель 'X' не найдена». На естественной записи

```takt
import "lib.takt";
start Main = Helper;   // Helper объявлен ВНУТРИ lib.takt
```

это утверждение автор читает как «такой модели нет» и идёт переносить состояния
на верхний уровень библиотеки — замер показал, что так и поступают.

#### Что сделано

Обе точки зовут `model_not_found(&model, &id)`. Она добавляет **сноску**, если
имя найдено среди вложенных моделей соседей: называет владельца и форму
подключения (`import { Helper } from "…";`).

- позиция сноски — **объявление вложенной модели**, то есть чужой файл:
  координата там не печатается (правило — чужую строку под своим путём
  показывать нельзя), а до редактора позиция доезжает;
- файл в подсказке **не называется**: обратной ссылки на путь импорта у обёртки
  нет, а имя файла автор видит в своей строке `import`;
- обход — **один уровень** вложенности, по `BTreeMap` (детерминированно, 0048).

**Замер снял с фичи её первоначальный объём.** Кандидат предлагал ввести
`Lib::Helper`; прогон показал, что `import { Helper } from "lib.takt";`
**работает** — вводить второй способ выразить то же самое не нужно.

#### Проверки

```sh
cargo test --test semantic nested_import   # 3 теста, включая контроль и проверку самого совета
```

Мутация «не добавлять сноску» валит T1.

### Задача

#### Что было

Цикл по заметкам жил **внутри** `format_compile_error`, а `takt-sim` строил
текст диагностики своей функцией `format_diagnostic` — позицию он брал у общего
носителя (`position_prefix`), а заметок не печатал вовсе.

Замер-19, один вход (`import "lib.takt"; start Main = Lib;`):

| Потребитель | Что печатал |
|---|---|
| `taktc` | `SE-106` **и** сноску «состояния есть у вложенной модели 'Helper'» |
| `takt-sim` | только `SE-106` |

Сноска — единственный указатель выхода из этой ситуации, и её не видел
пользователь эталона.

#### Что сделано

Печать заметок вынесена в `diagnostics::format_notes` — **общий носитель**; её
зовут `format_compile_error` и `takt-sim`. Формат заметки (позиция по правилу, префикс `примечание:`) теперь физически один, а не по договорённости.

Это ровно тот класс, о котором предупреждает док-строка
`format_compile_error`: «копия формата в `taktc` уже расходилась однажды ». Вторая копия жила в другом крейте и разошлась молча.

#### Проверки

```sh
cargo test --test sim diagnostic_notes   # сквозной: гоняет бинарник takt-sim
```

Мутация «не печатать заметки» валит контроль.

### Найденные дефекты

**Заметки диагностик не доезжали до пользователя эталона.** Обнаружено тем же
замером: печать заметок жила внутри `format_compile_error`, а `takt-sim` строил
текст своей функцией. Класс назван в док-строке самой библиотеки («копия формата
в `taktc` уже расходилась однажды») — вторая копия жила в другом крейте и
разошлась молча. Исправлено в рамках фичи: печать заметок
вынесена в общий носитель `diagnostics::format_notes`.

## Итог (что сделано)

**Замер опроверг формулировку кандидата.** Он утверждал, что ссылка на
вложенную модель подключённого файла **невыразима**, и предлагал ввести
квалифицированную форму `Lib::Helper`. Прогон четырёх форм показал: форма
**есть** — `import { Helper } from "lib.takt";` работает и исполняется. Кандидат
проверял три формы из четырёх.

Поэтому объём фичи заменён: не синтаксис, а **осведомлённость автора**.

1. **`SE-001` называет выход**: если имя найдено среди
   вложенных моделей соседей, диагностика получает сноску с владельцем и готовой
   строкой `import { Имя } from "…";`. Обычная опечатка сноски **не** получает —
   иначе она стала бы шумом (контроль в тестах).
2. **Заметки доезжают до пользователя эталона**: печать заметок
   вынесена в общий носитель `diagnostics::format_notes`. Прежде цикл жил внутри
   `format_compile_error`, а `takt-sim` строил текст своей функцией — и сноска
   `SE-106`, единственный указатель выхода, до него не доходила. Класс назван в
   док-строке самой библиотеки; вторая копия жила в другом крейте.

**Контроля:** `takt-lang/tests/semantic/nested_import_hint_tests.rs` (подсказка,
контроль на опечатке и проверка того, что советуемая форма действительно
работает) и сквозной `takt-sim/tests/sim/diagnostic_notes_tests.rs`, гоняющий
бинарник. Обе мутации пойманы.

**Язык не вырос:** правок грамматики и лексера нет. Версия языка `0.10.0`;
крейт `takt-lang`: `0.46.4` → `0.46.5`.
