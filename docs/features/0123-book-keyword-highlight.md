## Краткое описание

Ключевые слова языка, встречающиеся **в тексте** документа `book/` (в прозе, не в
блоках кода), выделяются **моноширинным + жирным + цветом** (как подсветка
синтаксиса), чтобы читатель отличал ключевое слово Takt от постороннего
англоязычного слова. Реализовано lua-фильтром pandoc — автоматически, по всему
тексту. Инфраструктура/стиль — язык не меняется (Tier 3).

> Фича зарегистрирована **2026-07-24 по запросу заказчика**.

## Документирование

**Не требуется** — стиль отображения документа, язык (синтаксис/семантика/
поведение) не меняется. Содержимое разделов не переписывается — подсветка
применяется автоматически при сборке.

### Context

Заказчик запросил: ключевые слова языка, встречающиеся **в тексте** (в прозе, не в
блоках кода), выделять моноширинным + жирным + цветом (как подсветка синтаксиса),
чтобы читатель отличал ключевое слово Takt (`model`, `if`, `state`) от постороннего
англоязычного слова. Сейчас ключевые слова в прозе — обычный инлайн-код (backticks),
неотличимый по стилю от имён/типов/операторов в таком же моноширинном виде.

### Decision Drivers

1. **Автоматизм.** Ручная разметка сотен упоминаний неподдерживаема.
2. **Точность.** Подсвечивать только реальные ключевые слова, не трогая обычный код
   и англ. слова.
3. **Согласованность** с подсветкой блоков кода (тот же цвет keyword).

### Considered Options

- **(A) Lua-фильтр pandoc `keywords.lua`.** Профиль mdbook-pandoc = pandoc
  defaults-файл, принимает `filters = […]`. Фильтр обрабатывает **инлайн-код**
  (`Code`), равный ключевому слову, и печатает его цветным жирным моноширинным.
  Автоматически, по всему тексту; блоки кода (`CodeBlock`) не трогаются.
  **Выбрано** (проверено: фильтр применяется, вывод компилируется).
- **(B) Ручная разметка span'ами** — неподдерживаемо.
- **(C) Стилизовать весь инлайн-код** — задело бы имена/типы/операторы, не отличая
  ключевые слова (противоречит запросу).

### Decision

В профиль `pdf` (`book.toml`) добавлен `filters = ["keywords.lua"]`. Фильтр
`book/keywords.lua`: множество ключевых слов из таблицы `KEYWORDS` лексера, для
инлайн-`Code`, равного ключевому слову, — `\textbf{\textcolor[HTML]{204A87}{
\texttt{…}}}` (tango KeywordTok). **Исключены** одиночные заглавные `X`/`F`/`G`/`U`/
`R` (операторы LTL) и `_` (wildcard) — высок риск ложных срабатываний в прозе. Типы
(`bit`/`bool`/`u8`…) — **не** ключевые слова лексера, поэтому не подсвечиваются
(отдельная категория).

### Consequences

#### Положительные

- Ключевые слова в прозе визуально отличимы от англ. слов и прочего кода.
- Цвет совпадает с подсветкой ключевых слов в блоках кода.

#### Отрицательные / Action items

- **Ведение списка**: при добавлении ключевого слова в лексер — обновить
  `keywords.lua` (кандидат: проверка сверки списка с `KEYWORDS`).
- Фильтр специфичен для latex-вывода (единственный у документа).

#### Acceptance criteria

1. `keywords.lua` подсвечивает инлайн-код-ключевое-слово (моно+жирный+цвет).
2. `filters` в профиле `pdf`; `make build` собирает PDF без ошибок.
3. Блоки кода и неключевой инлайн-код не затронуты; `??`-ссылки = 0.

## Анализ

### Цель

Ключевые слова языка в прозе документа — моноширинным + жирным + цветом, чтобы
отличать от постороннего слова. Инфраструктура/стиль (не язык, Tier 3).

### Список ключевых слов (источник — лексер)

Взят из `takt-lang/src/parser/lexer.rs` таблица `KEYWORDS`:
`address as assembly break cond const continue else enum extern false fn for
formula from if import in inout invariant loop match model next out ref return
start state string struct template true type var while LTL Guard`.

**Исключены** из подсветки: одиночные `X`/`F`/`G`/`U`/`R` (операторы LTL — высок
риск ложных срабатываний, напр. состояние с именем `F`) и `_` (wildcard). Типы
`bit`/`bool`/`float`/`u8`… — **не** ключевые слова лексера (резолвятся как
псевдонимы/примитивы), поэтому не подсвечиваются.

### Механизм (проверено)

- Профиль mdbook-pandoc = pandoc defaults-файл → принимает `filters = […]`.
- `book/keywords.lua`: функция `Code(el)` — если `el.text` в множестве ключевых
  слов и `FORMAT` = latex, вернуть `RawInline('latex', '\textbf{\textcolor[HTML]
  {204A87}{\texttt{…}}}')`. Цвет — tango KeywordTok (как в блоках кода).
- Блоки кода — `CodeBlock`, фильтром **не** трогаются (уже подсвечены skylighting).

### Проверка

- Фильтр применяется: в сгенерированном `.tex` — **80** вхождений
  `\textcolor[HTML]{204A87}` (образцы: `model`, `state`).
- Разметка валидна: xelatex компилирует её без ошибок (единственные ошибки
  latex-профиля — про `dispenser-filling.svg`, артефакт `to=latex` без rsvg; в
  реальном `pdf`-профиле SVG обрабатывается).
- `make build` (pdf-профиль, latexmk) — PDF собран без ошибок; `pdftotext | grep
  '??'` = 0 (кросс-ссылки целы).

### Ведение

При добавлении ключевого слова в лексер — обновить `keywords.lua` (кандидат:
скрипт-проверка сверки множества `keywords.lua` с `KEYWORDS`).
