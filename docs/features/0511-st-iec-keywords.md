# Фича: Цель `st` — ключевые слова языка ST в именах

- **Номер:** 0511
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `st`: „invalid variable(s) declaration“ и „invalid test expression“» (заведён при закрытии [цель `rust` — операнды расширяемой арифметики: приведение по нужде и обёртка](0507-rust-widen-operands-wrap.md))

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Список зарезервированных имён IEC (`ST-014`) знал стандартные функции и типы, но
не **структуру программы**: `PROGRAM`, `FUNCTION`, `CONFIGURATION`, `CASE`,
`REPEAT`, `ARRAY`, `OF`, `CONSTANT`, `RETAIN`, `ON`, `BY` и ещё два десятка
ключевых слов ST. `var program: u8 := 0;` — имя из практики — печаталось как
есть, и `iec2c` отвечал «invalid variable(s) declaration» плюс «invalid test
expression defined for ST 'IF' statement» при **нулевом** коде возврата `taktc`.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Документирование (правило 24)

**Затронуто.** Пример раздела «Процессор» (`book/src/20-processor/`) объявлял
`parameter program: u8`, то есть показывал читателю модель, вывод которой ПЛК не
принимает. Параметр переименован в `prog_sel` — в примерах и в тексте раздела.
Языковых изменений нет: `ST-014` — отказ **цели**, он уже описан в справочнике
диагностик.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 — прогон `iec2c` по 44 ключевым словам ST в форме
`VAR name : USINT := 1; END_VAR`:

| Ответ арбитра | Имена |
|---|---|
| **отвергает** | 41, включая `program`, `configuration`, `resource`, `task`, `end_var`, `function`, `function_block`, `end_type`, `array`, `of`, `constant`, `retain`, `non_retain`, `then`, `elsif`, `end_if`, `case`, `end_case`, `do`, `end_for`, `end_while`, `repeat`, `until`, `end_repeat`, `with`, `on`, `transition`, `initial_step`, `by`, `en`, `eno`, `f_edge`, `r_edge` |
| **принимает** | `single`, `interval`, `priority` |

Вторым прогоном отсеяны имена, которые сам Takt идентификатором не считает
(`var`, `if`, `else`, `for`, `while`, `return`, `true`, `false`, `type`,
`struct`, `at`): написать их именем нельзя, и запись в списке была бы
недостижимой.

Итог: **33** новых имени. Класс найден на примерах документа — раздел
«Процессор» объявляет `parameter program: u8`.

### Decision Drivers

- Список — **из прогона арбитра**, а не из чтения стандарта: ровно так собран
  прежний (0342), и ровно там прежнее чтение отстало на двадцать имён.
- Ложный отказ хуже пропуска (урок исправления): имена, которые `iec2c`
  принимает, в список не вносятся.

### Considered Options

1. **Дополнить `IEC_RESERVED` по прогону** (принято): диагностика `ST-014` уже
   есть, воронка одна, контроль берёт список из исходника и проверит каждую
   новую запись сам.
2. **Переименовывать имя за автора** (например, `program` → `program_`).
   Отвергнуто: имя видно в SCADA и в отладке ПЛК, а `ST-024`/`ST-023` уже
   выбрали для этого класса отказ, а не догадку.
3. **Оставить как есть, положившись на `iec2c`.** Отвергнуто: его диагностика
   обманчива (говорит про объявление и `IF`, а причина — имя), и приходит она
   при нулевом коде возврата `taktc`.

### Decision

`IEC_RESERVED` пополнен 33 именами, отвергнутыми прогоном; параметр `program`
примера документа переименован в `prog_sel`.

### Consequences

- `var program: u8;` даёт `ST-014` с причиной вместо невалидного ST.
- Три примера раздела «Процессор» (`machine`, `dual_core`, `cache`) стали
  проходить `iec2c` целиком; у `pipeline` остаётся другой класс («Ambiguous
  enumerate value or Variable not declared in this scope») — кандидат.
- Снимки `examples/generated/` не меняются: таких имён в корпусе нет.

#### Acceptance criteria

1. `var program: u8;` → `ST-014`, прочие цели ту же модель переводят.
2. Имена, которые арбитр принимает (`single`, `interval`, `priority`), цель
   переводит — отказ был бы ложным.
3. Контроль прогоняет `iec2c` по каждому имени списка и остаётся зелёным.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Воронка проверки одна — `st_reserved::check_st_name`, её зовут объявления,
имена POU, состояний и полей. Пополнение списка автоматически распространяется
на все эти места; отдельного кода фича не требует.

### Замер (правило 30, 2026-09-03)

Таблицы — в разделе «Архитектура (ADR) → Context». Замер шире кандидата: тот
называл два сообщения `iec2c` на примерах, а причина у обоих одна — имя
`program`, и класс охватывает 33 имени.

### Зависимости фичи (правило 17/19)

Зависимостей нет.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | Ключевое слово ST в имени → `ST-014` с позицией |
| Т2 | Прочие цели ту же модель переводят (отказ принадлежит цели) |
| Т3 | Имя, принимаемое арбитром, не отвергается |
| Т4 | Каждая запись списка обоснована прогоном  |
| Т5 | Примеры документа не содержат имён, которые цель отвергает |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: набор `st_reserved_names_tests.rs` (4 теста, два из
них гоняют `iec2c`), прогон примеров документа через `iec2c`, `precheck.sh`.

### Редакторский слой (правило 29)

**Не требуется:** лексика и синтаксис Takt не затронуты, новых диагностик нет —
пополнен список внутри цели.

### Особенности по обратной функциональности

Модель, объявляющая такое имя, теперь получает отказ цели `st` вместо
невалидного ST. Это **сужение** принимаемого целью множества — намеренное: до
правки вывод всё равно отвергал арбитр, но молча для `taktc`.

### Риски и зависимости

- **Риск:** внести имя, которое арбитр принимает, — ложный отказ. Снят вторым
  прогоном (три таких имени исключены) и контрольным тестом.

## Разработка

### Задача: список пополнен по прогону

`takt-lang/src/generator/st/st_reserved.rs` — 33 имени с пометкой, почему
исключены `single`, `interval`, `priority` и почему не внесены ключевые слова
самого Takt.

### Задача: пример документа переименован

`book/src/20-processor/examples/{machine_lib,pipeline}.takt` и
`book/src/20-processor/index.typ`: `program` → `prog_sel`.

### Задача: контроля

`st_reserved_names_tests.rs`: предметный тест (`ST-014` + контроль прочих целей)
и контрольный тест на имена, которые арбитр принимает. Существующий контроль
списка берёт имена **из исходника**, поэтому новые записи он проверяет сам.

## Тест-план

| Проверка | Ожидание |
|---|---|
| `var program: u8;` целью `st` | `ST-014` |
| та же модель целями `c`, `rust` | переводится |
| `single`, `interval`, `priority` целью `st` | переводится |
| каждое имя списка через `iec2c` | отвергается |
| примеры `machine`, `dual_core`, `cache` | `iec2c` принимает |
| симуляция примеров после переименования | прежнее поведение |

## Отчёт о тестировании (правило 20)

### Резюме

`./scripts/precheck.sh` — зелёный. Контроль списка прогнал `iec2c` по всем
записям. Три примера раздела «Процессор» стали проходить арбитра целиком.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка:

| Мутация | Ответ набора |
|---|---|
| внести `single` в список | `names_accepted_by_iec2c_are_not_refused` |
| убрать `program` из списка | `st_keyword_in_variable_name_is_refused` |

### Найденные дефекты

Дефектов правки нет. У примера `pipeline` остался соседний класс цели `st`
(«Ambiguous enumerate value or Variable not declared in this scope») — заведён
кандидатом.

### Выводы и дальнейшие шаги

Список зарезервированных имён снова догнал арбитра; полноты он по-прежнему не
обещает — доказывает лишь, что каждая запись обоснована прогоном.

## Итог (что сделано)

`IEC_RESERVED` пополнен 33 ключевыми словами языка ST, отвергнутыми прогоном
`iec2c`; имена, которые арбитр принимает, намеренно не внесены. `var program:
u8;` — имя из практики — теперь даёт `ST-014` с названной причиной вместо
невалидного ST при нулевом коде возврата.

Пример раздела «Процессор» переименован (`program` → `prog_sel`): документ
показывал читателю модель, вывод которой ПЛК не принимает. Три примера раздела
стали проходить `iec2c` целиком.
