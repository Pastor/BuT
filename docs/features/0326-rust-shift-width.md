## Краткое описание

`v := a >> 8;` при `a: i8` цель `rust` печатала как есть, и **`rustc` отвергал**
такой код при нулевом коде возврата `taktc`. Эталон и остальные семь
потребителей дают −1 (знаковый) и 0 (беззнаковый).

## Документирование

**Не требуется:** семантика описана фичей; здесь меняется форма печати
одной цели.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0326-rust-shift-width.md](0326-rust-shift-width.md)

### Контекст

Замер-20 (класс назван самой фичей как невошедший):

Вход `var a: i8 := -8; var b: u8 := 200; v := a >> 8; w := b >> 8;`

| Потребитель | Ответ |
|---|---|
| эталон | `v = -1`, `w = 0` |
| `c`, `c-hal` | то же (операнды в C продвигаются до `int`) |
| `st`, `st-at` | то же (floor-деление на `2⁸`, `SHR` на байтовой строке) |
| `sv`, `sv-mmio` | то же (`>>>` заполняет знаком — проверено прогоном verilator) |
| **`rust`** | **не компилируется**: «attempt to shift right by `8_i32`, which would overflow» — при **нулевом** коде возврата `taktc` |

### Решение

При **литеральной** величине сдвига, не меньшей ширины типа, цель `rust`
печатает то же значение выразимой формой:

- беззнаковый — `0`;
- знаковый — сдвиг на `ширина − 1`: там остаётся только знак, то есть −1 для
  отрицательного и 0 для неотрицательного.

### Почему не отказ

Семь потребителей вход исполняют и дают **одно и то же** значение. Отказ у
одной цели сузил бы язык там, где расхождения нет; предмет — форма печати, а не
семантика.

### Почему только литеральная величина

Переменная величина известна лишь в такте: в Rust сдвиг на неё паникует в
отладке и маскируется в релизе. Выразить это можно `checked_shr`, но платить
проверкой в каждом выражении дороже пользы. Граница названа и вынесена
кандидатом.

### Отвергнутые варианты

1. **`wrapping_shr`.** Маскирует величину по ширине (`8 % 8 = 0`), то есть
   даёт −8 вместо −1 — молча другое значение.
2. **`checked_shr(...).unwrap_or(0)`.** Для знакового «0» неверен: эталон даёт
   −1.

### Последствия

- Вывод цели `rust` собирается на входах со сдвигом на ширину типа.
- Значение совпадает с восемью остальными потребителями.

## Анализ

### Цель и контекст

Класс назван фичей как невошедший («сдвиг на величину, равную ширине типа
или большую») и проверен замером: расходится **одна** цель, и расходится
невалидным выводом.

### Зависимости фичи

- **Зависит от:** 0324 (семантика сдвига), 0325 (описание). Обе закрыты.
- **Влияние на порядок разработки:** закрывает названную границу 0325.

### Требования и проверяемые условия

- **R1.** Знаковый сдвиг на ширину печатается как сдвиг на `ширина − 1`.
- **R2.** Беззнаковый — `0`.
- **R3.** Порождённый Rust **собирается** и даёт значения эталона.
- **R4. Контроль:** обычный сдвиг печатается как прежде.
- **R5. Граница:** переменная величина не трогается.
- **R6.** Регрессия и предкоммит.

### Разбор

#### Почему форма именно такая

Арифметический сдвиг знакового на `ширина − 1` оставляет один знаковый разряд —
это −1 для отрицательного и 0 для неотрицательного, то есть ровно предел, к
которому стремится сдвиг на большую величину. Беззнаковый теряет все разряды.

#### Проверено прогоном, а не рассуждением

Вывод собран `rustc` и запущен: `v = -1`, `w = 0` — как у эталона. До правки
`rustc` **отказывался** компилировать.

### Риски

- **Переменная величина** остаётся прежней: в отладке Rust паникует. Названо
  кандидатом.
