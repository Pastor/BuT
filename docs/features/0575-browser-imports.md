## Краткое описание

`import "lib.takt";` в модели проекта на странице находит файл того же проекта:
путь поиска подключения — каталог проекта. Прежде импорт в браузере не работал
вовсе: у модуля нет файловой системы, и любой `import` кончался `SE-013`.

> Фича зарегистрирована по требованию заказчика 2026-09-10; далее проходит
> жизненный цикл по своду.

## Документирование

Документ [`book/`](../../book/) — не требуется: язык не меняется, правило поиска
подключения то же — меняется только источник файлов у модуля в браузере.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-10
- **Authors:** заказчик (требование), разработка

### Context

Чтение подключения одно — `semantic::import::read_import_file`, — и оно ходит на
диск (`exists`, `canonicalize`, `read_to_string`). У модуля WebAssembly диска нет,
а три его потребителя — сборка, диагностики и прогон — передавали пустые пути
поиска. Модель, подключающая файл своего же проекта, на странице не собиралась, не
судилась и не исполнялась.

### Decision

**Состав проекта заменяет диск.** Носитель `semantic::import::memory` держит
набор «имя файла — текст» на время одного построения: потоковый, со стражем по
`Drop` — по образцу стража циклов. `read_import_file` сначала спрашивает его:

- файл есть в составе — читается из памяти, имя — ключ проекта;
- файла нет — `SE-013`, и на диск за ним не ходят: состав задан целиком.

Путь поиска у модуля один — каталог проекта, `.`; имена в проекте плоские и
сверяются точным ключом, поэтому обход каталогов из памяти невозможен по
построению. Наружу открыт модуль `semantic::import`, но виден в нём только
носитель (и прежняя подсказка `importers`): правила поиска и чтения остаются
закрытыми. Отдельного фасада нет намеренно — `lib.rs` и `semantic/mod.rs` уже
сверх предела размера, и расти им нельзя.

Страница передаёт состав проекта всем трём потребителям — один и тот же, с живым
текстом открытого файла: подключение правят рядом с моделью, и сборка обязана
видеть набранное. Тексты моделей проекта подгружаются при открытии проекта.

### Consequences

Правка подключаемого файла пересоздаёт сессию прогона: состав входит в её ключ,
иначе прогон шёл бы по старому тексту. Без проекта состав пуст — поведение прежнее,
`SE-013` словами.

## Разработка

### Задача — носитель в памяти

`semantic/import/memory.rs`, открытый наружу модуль `semantic::import`, ветвь
памяти в `read_import_file`.

### Задача — модуль

Запросы сборки, диагностик и прогона несут `files`; каждый потребитель ставит
носитель на время построения, путь поиска даёт одна функция
(`compile::project_search_paths`) — разойдись он у троих, модель, которую
редактор подчёркивает как верную, не собиралась бы.

### Задача — страница

`bridge.js` пробрасывает состав, `app.js` собирает его (`projectFiles`) для
диагностик, сборки и сессии прогона, `worker.js` включает его в ключ сессии,
`account.js` подгружает тексты моделей при открытии проекта.

### Проверки

Модульные тесты носителя и чтения (из памяти, отсутствующий файл не ищется на
диске, вложенная установка, путь вне проекта), тест модуля «подключение по
составу собирается», проверка тождественности модуля, прогон `node` и страницы.

## Отчёт о тестировании

### Резюме

Импорт работает во всех трёх потребителях; вывод модуля по-прежнему совпадает с
`taktc` байт в байт.

### Фактические результаты по проверкам

1. `pid_heater` без состава: диагностики и сборка — `SE-013`; с составом —
   диагностики чистые, сборка даёт `pid_heater.h` и `pid_heater.c`, прогон
   открывается.
2. Страница: проект с `lib.takt` и моделью `import "lib.takt"` — «Ошибок нет»,
   вывод цели собран.
3. Тождественность модуля: 88 компиляций корпуса, 6 трасс, 1032 редакторских
   входа.

### Найденные дефекты

Своих нет.
