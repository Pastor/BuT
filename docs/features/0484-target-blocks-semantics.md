# Фича: Семантика блоков formula и assembly в телах: пропуск и вставка по цели

- **Номер:** 0484
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат `FEATURES.md` (заведён при закрытии 0481); решение заказчика об объёме — 2026-09-02

## Краткое описание

Блоки `formula { … }` (обязательство внешнему анализатору) и
`assembly [«цель»] { … }` (операторы, попадающие в вывод одной цели) язык
разбирает и форматирует, но **семантики у них нет**: до целей они доезжают
неразрешённым узлом, и семь целей из восьми отказывают воронкой недостижимости
(«узел не прошёл семантическое понижение»), тогда как узел законен. Фича задаёт
семантику: `formula` цели **пропускают**, тело `assembly` печатает **та** цель,
чьё имя указано (без имени — все), а неизвестное имя цели отвергается
диагностикой.

> Фича зарегистрирована из бэклога кандидатов; объём («задать семантику», а не
> «сделать отказ честным») — **решение заказчика 2026-09-02**. Далее проходит
> жизненный цикл по правилу 17.

## Документирование (правило 24)

**Требуется.** Фича меняет **язык**: у двух конструкций появляется наблюдаемое
поведение. Затрагиваются разделы `book/`:

- «Верификация» — `formula [диалект] { … }`: обязательство адресовано внешнему
  анализатору, компилятор его не переводит и не проверяет, поведение модели оно
  не меняет;
- «Целевые платформы» — `assembly [«цель»] { … }`: тело попадает в вывод
  названной цели, у прочих пропускается; без имени — во все; имя — язык вывода
  (`c`, `st`, `rust`, `sv`, `plantuml`), а не режим сборки;
- приложение «Ошибки и предупреждения» — новый код диагностики;
- в приложении есть **устаревшее** утверждение (разбор `FM-001`): «сегодня
  это `formula` и `assembly`» — форматтер печатает их с фичи. Правится в
  рамках этой же фичи: обе конструкции — её предмет.

Новых разделов документа фича не заводит (правило 24: новый раздел — отдельная
фича); описание встраивается в существующие.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, аналитик; объём — решение заказчика

### Context

Замер-02 (`scripts/probe.sh -n 2`, порт с адресом — иначе `c-hal` и
`st-at` отказывают общим `SE-052` и их поведение не измерено):

| Вход | эталон | `plantuml` | `c` / `c-hal` | `st` / `st-at` | `rust` | `sv` / `sv-mmio` |
|---|---|---|---|---|---|---|
| `formula { step_holds(level) }` в `always` | исполняет | OK | `CC-023` | `ST-011` | `RS-011` | `SV-002` |
| `assembly "c" { level := level + 0; }` в `always` | исполняет | OK | `CC-023` | `ST-011` | `RS-011` | `SV-002` |

Тексты отказов говорят «оператор не прошёл семантическое понижение
(Unresolved)» — то есть обещают дефект компилятора там, где стоит **граница
языка**: понижения у этих узлов нет вовсе. `semantic/statement/mod.rs`
оставляет их `Unresolved` осознанно (ветвь `_ =>`), а печатники целей с фичи отвергают любой `Unresolved` — два верных по отдельности решения дают
неверный ответ автору.

**Класс шире кандидата.** Кандидат называл только `formula`; тот же замер
показал `assembly`, причём `assembly "c"` не печатает даже цель `c`, чьё имя в
нём написано. Конструкция есть в грамматике, в форматтере (0405) и в примерах
языка, а работающего сценария у неё нет ни одного.

**Контрольный вход:** те же модели без блока переводят все восемь целей —
значит замер меряет блок, а не пробу.

### Decision Drivers

- Конструкция языка, у которой нет ни одного работающего сценария, — не
  граница, а дыра: язык её принимает, форматтер печатает, документ упоминает.
- Отказ обязан говорить о предмете. Воронка недостижимости адресована
  **дефекту компилятора**, и её текст на законном входе вводит в заблуждение.
- Поведение эталона и целей обязано совпадать (иначе потактовые сверки теряют
  смысл) — кроме случая, когда расхождение и есть **предмет** конструкции.

### Considered Options

1. **Сделать отказ честным, семантику не заводить.** Дёшево (Tier 3), но
   оставляет обе конструкции нерабочими: автор по-прежнему не может ими
   воспользоваться, а документ по-прежнему описывает то, чего нет.
2. **Задать семантику** (принято решением заказчика 2026-09-02): `formula`
   пропускается всеми целями, `assembly` печатается названной целью.
3. Промежуточный: `formula` пропускать, `assembly` отвергать честно —
   отвергнут вместе с (1) тем же решением.

### Decision

1. **`formula [диалект] { … }` в теле** понижается в
   `StatementNode::Formula`: обязательство адресовано **внешнему
   анализатору**, компилятор его не переводит и не проверяет. Все восемь целей
   и эталон его **пропускают** — поведение модели блок не меняет. Так уже вели
   себя эталон и `plantuml`; семь целей приводятся к ним.
2. **`assembly [«цель»] { … }` в теле** понижается в
   `StatementNode::Assembly { target, body }`; тело — **операторы Takt**, оно
   проходит обычное понижение, и имена в нём разрешаются штатно.
   - имя названо → тело печатает **только** цель с этим языком вывода;
   - имени нет → тело печатают **все** цели, и эталон его исполняет.
3. **Имя цели проверяется семантикой** — `SE-129`. Допустимы имена языков
   вывода: `c`, `st`, `rust`, `sv`, `plantuml`. Режимные имена (`c-hal`,
   `st-at`, `sv-mmio`) — не язык, а режим сборки той же цели; они отвергаются с
   подсказкой. Без проверки опечатка (`assembly "С"` с кириллической буквой)
   молча выключала бы вставку во всех целях.
4. **Эталон исполняет только безымянный `assembly`.** Симулятор не является ни
   одной из целей: исполни он тело, помеченное `"c"`, потактовая сверка
   `c` ↔ эталон сошлась бы, а `rust` ↔ эталон разошлась бы — то есть сверка
   стала бы зависеть от того, какую цель ей поручили.

### Consequences

- У обеих конструкций появляется наблюдаемое поведение → **версия языка
  0.14.0 → 0.15.0** (правило 22), коммит помечается тегом `v0.15.0`.
- Модель с обязательством внешнему анализатору переводится всеми восемью
  целями, а не отвергается семью.
- `assembly «цель»` вносит **намеренное** расхождение целей между собой: это
  предмет конструкции, и он назван в документе. Потактовая сверка на моделях с
  именованным `assembly` неприменима — сверять такой вход надо текстом вывода
  (что и делает тест-план).
- **Названная граница:** тело `assembly` — операторы Takt, а не дословный текст
  чужого языка. Вставка произвольного текста в вывод остаётся невозможной; при
  нужде это отдельная фича со своим ADR.

#### Acceptance criteria

1. `formula` в теле: восемь целей переводят модель, вывод её не содержит,
   поведение совпадает с эталоном (потактовая сверка).
2. `assembly` без имени: тело печатают все цели и исполняет эталон — сверка
   значений зелёная.
3. `assembly "c"`: тело есть в выводе `c` и `c-hal`, и его нет у семи прочих
   выводов.
4. Неизвестное либо режимное имя цели → `SE-129` с позицией блока.
5. Вывод целей на моделях **без** этих блоков не изменился (снимки
   `examples/generated/`).
6. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Дать двум разобранным, но бессемантичным конструкциям наблюдаемое поведение и
снять класс «законный узел отвергается воронкой недостижимости».

### Замер (правило 30, 2026-09-02)

Таблица — в разделе «Архитектура (ADR)»; снята `probe.sh` по обеим формам, с
контрольным входом и снятой посторонней причиной (`SE-052`).

### Зависимости фичи (правило 17/19)

Зависимостей нет. Смежные решения, которые фича обязана сохранить: отказ целей
на **настоящем** `Unresolved` (0236, 0291) и запрет тихого пропуска оператора
(0155).

### Требования и проверяемые условия

1. Два новых семантических узла; `Unresolved` остаётся признаком дефекта.
2. Тело `assembly` проходит понижение (имена в нём разрешаются, ошибки в нём
   диагностируются) — иначе конструкция стала бы дырой в проверках.
3. Печать тела решает **язык вывода**, а не режим сборки: `assembly "c"`
   печатается и целью `c`, и целью `c-hal`.
4. Эталон: `formula` — пропуск, безымянный `assembly` — исполнение, именованный
   — пропуск.

### Редакторский слой (правило 29)

**Проверить и зафиксировать.** Новых токенов нет (`assembly` и `formula` в
лексере с самого начала), новых форм объявления нет, новых узлов **АСД** нет —
меняется только семантическое дерево. Значит подсветка, автодополнение и обход
`semantic::usages` (он ходит по АСД) не затрагиваются; новая диагностика
`SE-129` приходит из семантики и доезжает до редактора штатным путём.

### Особенности по обратной функциональности (правило 11)

Совместимость **расширяется**: входы, которые семь целей отвергали, теперь
переводятся. Сужение одно — `SE-129` на неизвестном имени цели: прежде такая
запись принималась и не делала ничего. Это осознанно: молчаливо
недействующая метка хуже отказа.

### Риски и зависимости

- **Риск: тихий пропуск вернётся под видом семантики.** Снимается тем, что
  пропускаются **новые узлы**, а `Unresolved` остаётся отказом; контроль — тест
  на настоящий неразрешённый оператор.
- **Риск: цели разойдутся молча** (одна печатает тело, другая нет). Снимается
  контролем по всем восьми целям, падающим списком.

## Разработка

### Задача — два семантических узла

`StatementNode::Formula(ast::FormulaBlock)` и
`StatementNode::Assembly { target, body }` (`semantic/mod.rs`); понижение —
`semantic/statement/mod.rs`, где обе формы ушли из ветви `_ => Unresolved`.
Тело вставки проходит обычное понижение: имена в нём разрешаются, ошибки
диагностируются.

Собственные узлы здесь обязательны. Оставь мы `Unresolved` — печатники
отвергали бы законный вход (0236); разреши мы им пропускать `Unresolved` —
вернулся бы класс, где оператор исчезает из вывода при рапорте об успехе.

### Задача — носитель правила и проверка имени

`semantic/target_block.rs`: `check_target` (`SE-129`, языки вывода против
режимов сборки), `emits_for` (кому принадлежит вставка) и **проход
`prune`** — он оставляет в дереве цели только её вставки, разворачивая их в
тело, а чужие заменяет пустым оператором.

Отбор живёт **в семантике**, и это замер, а не вкус. Признак «переменная
используется» считается по дереву и цели не знает. Проба 2026-09-02 показала
**обе** половины класса: с чужой вставкой в дереве переменная, упомянутая
только в ней, у `c` не объявлялась, а тело печаталось — `cc` отвечал «no
member named 'trace'»; без учёта вставки в `unused` та же переменная получала
ложное `SE-036`.

Проход зовётся из `condition::observe::lower_for_target` — общей точки
«проходов для цели», у которой появился параметр языка; `plantuml` зовёт его
отдельно (своего `lower_for_target` у диаграммы нет).

### Задача — потребители узлов

Обходы семантики (`walk`, `lower_float`, `fixed_body`, `validate::fixed`,
`import::adopt`) спускаются в тело вставки; `unused` считает употребление
внутри неё употреблением. Печатники четырёх целей и эталон получили ветви:
формула — пропуск, вставка — по принадлежности. У целей эти ветви после
`prune` недостижимы и оставлены **защитой в глубину**: через библиотечный API
проход можно и не позвать.

Эталон исполняет только безымянную вставку (`takt-sim/src/unit/statement.rs`) —
он не является ни одной из целей.

### Задача — версия языка и документ

Версия языка **0.14.0 → 0.15.0** (правило 22) в трёх источниках; коммит
помечается тегом `v0.15.0`. Документ: раздел «Верификация свойств» —
обязательства внешнему анализатору; «Целевые платформы» — вставка для одной
цели с таблицей принадлежности; приложение «Ошибки и предупреждения» — разбор
`SE-129`. Там же исправлено **устаревшее** утверждение разбора `FM-001`
(«сегодня это `formula` и `assembly`»): форматтер печатает их с фичи.

### Примеры и контрпримеры (правило 16)

**Примеры** (перевод обязателен): `assembly "c"`, `assembly "st"`,
`assembly "rust"`, `assembly "sv"`, `assembly "plantuml"`, `assembly` без
имени, `formula { … }` в теле, модель без блоков (контроль).

**Контрпримеры** (отказ обязателен): `assembly "cpp"` — неизвестный язык;
`assembly "c-hal"`, `"st-at"`, `"sv-mmio"` — режим сборки вместо языка;
`assembly "С"` — кириллическая буква вместо латинской (ровно тот случай,
ради которого проверка и заведена: молча ничего не включает).

### Найденные дефекты

Дефектов, потребовавших исправления, нет. По ходу разработки проба вскрыла **обе**
половины класса «признак использования не знает цели» (разбор — в задаче); обе закрыты в рамках фичи: отбор вставок перенесён в семантику, а
`unused` научен видеть тело вставки.

Отдельно исправлено устаревшее утверждение документа о `FM-001` — оно
обещало, что форматтер не печатает `formula` и `assembly`, хотя печатает их с
фичи.

### Редакторский слой (правило 29)

**Не затронут, и это проверено:** новых токенов нет (`assembly` и `formula` в
лексере с начала), новых форм объявления нет, новых узлов **АСД** нет —
изменилось только семантическое дерево, а `semantic::usages` и подсветка ходят
по АСД. Новая диагностика `SE-129` приходит из семантики и доезжает до
редактора штатным путём.

### Долг и границы, всплывшие в прогоне

- **Правило размера модуля.** Новые узлы и ветви вывели за лимит три файла.
  Разделены по границе ответственности, а не «внесены в реестр»: сбор имён,
  которым присваивают, уехал в `generator/rust/rust_assigned.rs`, узлы ветки
  `match` — в `semantic/match_node.rs`; запись реестра для `semantic/mod.rs`
  **уменьшена** (1240 → 1236). Отбор вставок при этом переехал в единую точку
  эмиссии (`pipeline::Unit::emit`), отчего `lib.rs` не вырос вовсе — и правило
  стало применяться ко всем восьми целям из одного места.
- **Долг покрытия.** `SE-129` корпусом не достигается: корпус
  состоит из моделей, которые обязаны переводиться, а отказ приходит на
  ошибочной метке. Код внесён в `scripts/diagnostic-coverage-baseline.txt` с
  причиной — как прочие отказы такого рода.

### Вердикт

**Готово.** Восемь условий тест-плана выполнены, включая мутационный контроль
и потактовую сверку.

## Итог (что сделано)

- У двух разобранных, но бессемантичных конструкций появилось наблюдаемое
  поведение — **версия языка 0.15.0**: `formula [диалект] { … }` цели и эталон
  **пропускают** (обязательство адресовано внешнему анализатору),
  `assembly [«цель»] { … }` печатает **та** цель, чей язык вывода назван; без
  имени — все цели, и тогда тело исполняет эталон.
- Неизвестное имя цели отвергается **`SE-129`**; режимные имена (`c-hal`,
  `st-at`, `sv-mmio`) отвергаются с подсказкой о базовой цели.
- Отбор вставок — проход семантики `target_block::prune` в общей точке
  «проходов для цели»; печатники о принадлежности не знают, а их ветви
  остались защитой в глубину. Причина именно такого места разобрана в задаче: признак использования переменных цели не знает, и обе половины
  класса пойманы пробой.
- Контроля два: сплошной перебор «метка × цель» по всем восьми целям
  (`target_blocks_tests`) и потактовая сверка эталона с целью `c`
  (`conformance_target_blocks_tests`). Первый ловит мутацию `emits_for`,
  второй — молчаливую потерю тела вставки, которую компиляция не видит.
- Документ описывает обе конструкции (разделы «Верификация свойств» и
  «Целевые платформы», разбор `SE-129` в приложении); там же снято устаревшее
  утверждение о форматтере.
