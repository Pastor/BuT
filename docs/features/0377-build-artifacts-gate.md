## Краткое описание

Замер-21 по вопросу заказчика: в **корне** репозитория лежали три
файла — `libshl.rlib`, `libvarshift.rlib`, `libvarshift32.rlib`, 84 КБ. Они
**отслеживаются гитом**: `git log --diff-filter=A` показывает коммит
`3c6bec19` («fix(0334): сдвиг на величину не меньше ширины типа считает как
эталон»), то есть это вывод ручных проб `rustc`, запущенных без `--out-dir`,
попавший под `git add -A` вместе с правкой.

Ни одна проверка этого не видел: `.gitignore` закрывает `/target` и `/*.o`, но не
`*.rlib`, а `git status` показывает такой файл наравне с исходником.

### Context

Вопрос заказчика 2026-08-21: почему в корне лежат `*.rlib`. Замер: три файла,
84 КБ, **отслеживаются** гитом с коммита `3c6bec19`  — вывод ручных
проб `rustc` без `--out-dir`, попавший под `git add -A`.

Класс шире одного случая: замеры целей запускают
`rustc`, `cc`, `verilator`, `yosys`, `iec2c`, и каждый кладёт вывод в текущий
каталог, если не сказать иного.

### Decision Drivers

1. **Состояние репозитория — свойство проверки, а не дисциплины автора** (тот же
   довод, что у ADR про каталог сборки).
2. **Отказ обязан называть файлы**: список — то, с чем можно работать.
3. **Проверка без контроля не проверка**.

### Considered Options

#### Option A. `.gitignore` + проверка по отслеживаемым файлам (принято)

**Pros:**
- `.gitignore` не даёт файлу попасть в индекс — причина закрыта.
- Проверка ловит то, что уже отслеживается (и то, что добавят через `add -f`).
- Проверка дешёвая: `git ls-files` плюс сравнение расширений.

**Cons:** список расширений придётся дополнять при появлении нового
инструмента. Он закрытый и лежит в одном месте — в заголовке проверки.

#### Option B. Только `.gitignore`

**Cons:** уже добавленный файл остаётся отслеживаемым — `.gitignore` его не
трогает. Ровно так три `.rlib` и прожили сутки.

#### Option C. Проверять рабочее дерево, а не индекс

**Cons:** проба, оставившая рядом `probe.rlib`, роняла бы предкоммит — контроль,
кричащий всегда, замолкает навсегда.

#### Option D. Проверять содержимое (`file(1)`), а не расширение

**Cons:** несколько секунд на 3700 файлов ради случая, где расширение известно
точно.

### Decision

Принимается **Option A**: `.gitignore` закрывает расширения в корне, проверка
`check-build-artifacts.py` проверяет **отслеживаемые** файлы и падает списком,
контроль `test-build-artifacts.sh` строит временный репозиторий и проверяет
четыре условия.

### Consequences

#### Положительные

- Репозиторий чист, и новая протечка ловится предкоммитом, а не глазами.
- Причина (`--out-dir` в пробах) закрыта `.gitignore`.

#### Отрицательные / Action items

- Список расширений закрытый: инструмент с новым расширением придётся внести.
  Он в одном месте, и проверка судит сам себя.
- Исторические файлы остаются в истории (удаление — только переписыванием,
  а оно уже делалось 2026-08-19 и стоило правки 61 ссылки).

#### Acceptance criteria

1. Проверка падает списком на отслеживаемом `*.rlib` и молчит на чистом дереве.
2. Неотслеживаемый артефакт проверка не роняет.
3. Каталог без репозитория даёт **отказ**, а не рапорт об успехе.
4. Предкоммит зелёный; три файла из репозитория удалены.

## Анализ

### Цель и контекст

#### Замер (2026-08-21, вопрос заказчика)

```
$ ls -la *.rlib
libshl.rlib         25112  Aug 20 17:12
libvarshift.rlib    28448  Aug 20 17:12
libvarshift32.rlib  28488  Aug 20 17:12          — всего 84 КБ

$ git ls-files | grep rlib          → все три ОТСЛЕЖИВАЮТСЯ
$ git log --diff-filter=A -- libvarshift.rlib
  3c6bec19 fix(0334): сдвиг на величину не меньше ширины типа считает как эталон
```

Имена (`shl`, `varshift`, `varshift32`) в точности отвечают предмету фичи
(сдвиги на переменную величину): это вывод ручных проб `rustc
--crate-type=lib`, запущенных **без `--out-dir`**, и попавший в коммит вместе с
правкой под `git add -A`.

Почему не заметили:

1. `.gitignore` закрывает `/target` и `/*.o`, но не `*.rlib`;
2. `git status` показывает такой файл наравне с исходником;
3. проверки, смотрящего на состав репозитория, не было вовсе.

Прочих артефактов замер не нашёл: `git ls-files` по расширениям `.rlib`,
`.rmeta`, `.o`, `.so`, `.dylib`, `.a`, `.exe`, `obj_dir/` даёт только эти три
файла.

### Зависимости фичи

- **Зависит от:** нет. 0315 (у каждого проверки есть контроль) закрыта.
- **Влияние на порядок разработки:** нет; фича процессная.

### Требования и проверяемые условия

- **R1. Чистота.** Отслеживаемых артефактов в репозитории нет.
- **R2. Причина закрыта.** `.gitignore` не даёт таким файлам попасть в индекс.
- **R3. Проверка.** Предкоммит падает **списком** при появлении отслеживаемого
  артефакта.
- **R4. Не мешать пробам.** Файл, лежащий рядом и не добавленный в индекс,
  проверка не роняет.
- **R5. Контроль.** Проверка проверяется мутацией, включая вырожденный вход.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 | `scripts/check-build-artifacts.py` на репозитории |
| A2 | R2 | запись в `.gitignore` + условие 3 контроля |
| A3 | R3 | условие 2 контроля: артефакт ловится и **назван** |
| A4 | R4 | условие 3 контроля |
| A5 | R5 | `scripts/test-build-artifacts.sh` — шаг предкоммита |

### Особенности по обратной функциональности

Удаление трёх файлов ни на что не влияет: на них не ссылается ни один скрипт,
тест или документ (проверено грепом по `docs`, `scripts`, обоим крейтам).

### Риски и зависимости

- **Ложная тревога на пробе.** Снижена выбором предмета: проверяются
  **отслеживаемые** файлы, а не рабочее дерево (урок: контроль, кричащий
  всегда, замолкает навсегда).
- **Новый инструмент — новое расширение.** Список закрытый и лежит в одном
  месте; проверка судит и сам себя.
- **История.** Файлы остаются в прошлых коммитах: вычистить их можно только
  переписыванием истории, а оно уже делалось 2026-08-19 и стоило правки
  61 ссылки в 21 документе. Цена не оправдана 84 килобайтами.

## Разработка

### Задача

#### Что было

Три файла `*.rlib` в корне, отслеживаемые гитом с коммита `3c6bec19`.
`.gitignore` их не закрывал, проверки на состав репозитория не было.

#### Что сделано

- `git rm` трёх файлов.
- `.gitignore`: закрыты `/*.rlib`, `/*.rmeta`, `/*.d`, `/*.so`, `/*.dylib` —
  рядом с уже существовавшим `/*.o`, с объяснением повода.
- `scripts/check-build-artifacts.py`: проверка по **отслеживаемым** файлам
  (`git ls-files`), падает списком; список расширений — в заголовке проверки,
  исключений нет.
- `scripts/test-build-artifacts.sh`: контроль, строящий **временный
  репозиторий** (копии дерева мало — нужен свой индекс); четыре условия.
- Оба подключены в `precheck.sh` рядом с проверкой устаревших имён.

**Статус по функциональности.** Вывод инструментов не затронут —
фича процессная; целям и эталону **н/п**.

#### Проверки

```sh
python3 scripts/check-build-artifacts.py   # 3703 файла, артефактов нет
./scripts/test-build-artifacts.sh          # 4 условия
./scripts/precheck.sh
```

### Выводы и дальнейшие шаги

1. **Нашёл это человек, а не машина** — вопросом «почему в корне лежат
   `*.rlib`». Проверки на состав репозитория не было вовсе, хотя гигиена каталога
   сборки (0234) заведена давно: смотрели на `target/`, а не на индекс.
2. **Причина — проба без `--out-dir`.** Замеры целей
   запускают пять внешних инструментов, и каждый пишет в текущий каталог.
   Теперь это закрыто `.gitignore`, а протечка ловится предкоммитом.
3. **История не переписывалась:** файлы остаются в прошлых коммитах. Цена
   переписывания измерена 2026-08-19 (61 ссылка в 21 документе) и 84
   килобайтами не оправдана.
4. Исправлений не потребовалось.
