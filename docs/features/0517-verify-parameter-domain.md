# Фича: Верификация — параметр модели как значение по умолчанию

- **Номер:** 0517
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат `FEATURES.md` «верификация: параметр модели отслеживается как свободно меняющаяся переменная» (замер-02)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32).

## Краткое описание

Параметр модели, которому не присваивают в теле, участвует в проверке свойств
**одним значением** — своим умолчанием. Прежде он абстрагировался как свободно
меняющаяся переменная: домен `u8` (256 значений) умножался на домены остальных,
и предикат `ticks < limit` при `parameter limit: u8 := 10` давал «не проверено:
размер задачи за потолком», тогда как тождественная запись с `const limit`
отвечала «свойство держится».

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Документирование (правило 24)

**Затронуто.** Раздел «Верификация» (`book/src/13-verification/`), блок
«Границы проверки»: параметр домена не растит, свойство проверено для сборки с
умолчанием, а параметр, которому присваивают, перебирается как переменная.

**Версия языка не поднимается:** язык не меняется — меняется точность
абстракции верификатора; диагностик не заводится, вердикт «держится» остаётся
надёжным и был надёжен прежде.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** заказчик, архитектор, разработчик

### Context

Замер-02 (`taktc verify`), предикат `cond Below = ticks < limit`:

| Объявление порога | Вердикт до правки |
|---|---|
| `const limit: u8 := 10;` | свойство держится |
| `parameter limit: u8 := 10;` | не проверено: размер задачи за потолком |

Записи тождественны по смыслу: параметр — величина сборки, признак «ему
присваивают» (`ParameterNode::mutated`) существует с фичи.

Сегодняшнее поведение **не лгало**: «держится» надёжно по построению
абстракции (0068), а «не проверено» — честный отказ. Предмет фичи — точность,
а не корректность.

### Decision Drivers

- Вопрос «чьё значение параметра проверять» — решение **заказчика**: у него три
  разумных ответа, и они дают разный смысл вердикта.
- Признак постоянства уже есть и заполняется анализом изменяемости (0185).

### Considered Options

Вынесено заказчику 2026-09-03, выбран вариант 1:

1. **Значение по умолчанию модели** (принято): параметр — константа, равная
   своему умолчанию; домен из одного значения.
2. Весь домен, но как постоянная величина (значение не меняется по тактам).
   Отвергнуто заказчиком: задача всё равно растёт, а вердикт становится
   утверждением обо всех сборках — более сильным, чем нужно сегодня.
3. Значение аргумента экземпляра. Отвергнуто: у модели, проверяемой отдельно от
   сборки, аргумента нет — потребовалось бы отдельное правило.
4. Оставить как есть. Отвергнуто: автор не получает вердикта по обычной записи.

### Decision

Параметр с `mutated == false` даёт домен из одного значения — свёрнутого
умолчания. Параметр, которому присваивают, остаётся свободной переменной.

### Consequences

- Предикат с параметром проверяется так же, как с константой.
- Размер задачи от параметров не растёт: домен единичный.
- Вердикт относится к сборке **с умолчанием**; это названо в документе.

#### Acceptance criteria

1. Предикат с параметром проверяется (не «за потолком»).
2. Вердикт содержателен: `G Below` над растущим счётчиком нарушается.
3. Параметр и константа дают один вердикт.
4. Контроль: параметр, которому присваивают, остаётся переменной.
5. `./scripts/precheck.sh` зелёный.

Критерии — в ADR. Способ: набор `takt-lang/tests/verify/parameter_domain_tests.rs`

### Редакторский слой (правило 29)

**Не требуется:** лексика, синтаксис и диагностики не затронуты.

### Особенности по обратной функциональности

Вердикты меняются только в сторону определённости: там, где приходило «не
проверено», теперь приходит «держится» либо «нарушено». Свойств, которые
держались, но перестанут, быть не может: домен сузился, а не расширился.

Оговорка: вердикт теперь относится к сборке с умолчанием. Прежде отказ
«не проверено» не утверждал ничего, поэтому потери силы нет.

### Риски и зависимости

- **Риск:** параметр, которому присваивают, молча станет константой — вердикт
  оказался бы неверным. Снят признаком `mutated` (умолчание «изменяемый») и
  контрольным тестом.

## Разработка

### Задача

`verification/data_kripke.rs`: `TrackedDecl` получил поле `fixed`, признак —
`is_fixed_parameter` (параметр модели без присваиваний). Домен такой величины —
одно свёрнутое значение; в подсчёт потолка она не входит.

### Задача

`takt-lang/tests/verify/parameter_domain_tests.rs` — четыре теста, включая
контроль изменяемого параметра и сверку «параметр ≡ константа».

## Тест-план

| Проверка | Ожидание |
|---|---|
| `G (!Below \| Below)` с параметром | держится |
| `G Below` с параметром | нарушено |
| параметр против константы | один вердикт |
| параметр с присваиванием в теле | не проверено (домен `u8`) |

Все проверки пройдены. Мутационная проверка: инверсия признака

возможной отдельной фичей — сегодня она не требуется.

## Итог (что сделано)

Параметр модели, которому не присваивают в теле, участвует в проверке свойств
одним значением — своим умолчанием (решение заказчика 2026-09-03). Прежде он
абстрагировался как свободно меняющаяся переменная, и обычная запись с
параметром упиралась в потолок задачи, тогда как тождественная с `const`
проверялась.

Признак постоянства — существующий `ParameterNode::mutated` (0185), и его
умолчание «изменяемый» сохранено: не размеченный параметр ведёт себя как
переменная.
