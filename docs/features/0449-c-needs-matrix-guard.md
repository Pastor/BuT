- **Статус:** ГОТОВО

## Краткое описание

Признак «нужен ли функции под-модели указатель на корень» (`c_needs`, [структурный параметр цели c эмитится всегда, а не по нужде](0396-c-struct-parameter-on-demand.md),
[цель `c`: нужда в указателе считается на функцию](0419-c-per-function-root-need.md),
[указатель на корень нужен и моделям-реализациям состояния](0439-root-pointer-for-implementations.md)) проверялся **входами
отдельных фич**, то есть выборкой. Фича заводит сплошной перебор «каждый вид
обращения к корню × каждая форма реализации состояния» и чинит дефект, который
этот перебор нашёл с первого прогона.

> Фича заведена из блока кандидатов.

## Документирование

**Не требуется:** язык не меняется, наблюдаемое поведение — тоже. Речь о
сигнатуре функций в порождённом C и о полноте проверки.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

У признака две стороны, и ошибаются они по-разному:

- **сказать «не нужен» там, где нужен** — громкий класс: `cc` отвечает
  «use of undeclared identifier 'main'», но **только если такой вход кто-то
  скомпилировал**;
- **сказать «нужен» там, где не нужен** — тихий класс: параметр гасится
  заглушкой `(void)main;`, вывод валиден, инструменты молчат; цена — интерфейс
  и читаемость (это и была фича).

Выборочная проверка ловит только те сочетания, которые кто-то догадался
написать. Замер-31 подтвердил цену выборки: перебор нашёл сочетание
«профиль „часы“ + выдержка `after Nms` во вложенной модели», на котором вывод
цели `c` **не собирается**.

### Decision

Контроль-перебор в `takt-lang/tests/targets/root_pointer_matrix_tests.rs`:
**8 видов обращения × 5 форм реализации = 40 случаев**, и в каждом проверяются
оба свойства — сборка `cc` флагами проверки цели и **точность** признака (есть ли
параметр там, где ожидается).

Ожидания таблицы сняты **прогоном**, а не выведены из кода
признака: контроль, повторяющий реализацию, доказывает лишь сам себя.

Найденный дефект чинится там же: `needs_root_inner` (ветвь `_tick`) получает
`clock_profile` и учитывает `uses_duration_time` — ровно так, как это делала
ветвь `_init`.

### Considered Options

- **A. Перебор в тесте** — принят: дёшев (2.4 с на 40 случаев) и проверяет обе
  стороны признака.
- **B. Проверять признак модульно, без `cc`** — отвергнут: код возврата `taktc`
  о валидности вывода не говорит, а именно валидность здесь и есть
  предмет.
- **C. Расширить корпус примерами** — отвергнут: корпус — витрина языка, а не
  матрица сочетаний; примеры на каждое сочетание сделали бы его нечитаемым.

### Consequences

Вывод корпуса меняется только там, где признак был неверен: примеров с профилем
«часы» и выдержкой во вложенной модели в `examples/` нет, поэтому снимки не
затронуты. Контроль добавляет ≈2.4 с к `cargo test`.

#### Acceptance criteria

- A1. Все 40 случаев собираются `cc` флагами проверки.
- A2. Признак точен в каждом: параметр есть ровно там, где ожидается.
- A3. Откат любой из трёх известных починок (0439, 0449) роняет контроль.
- A4. «Всегда нужен» — тихий класс — тоже роняет контроль.

## Анализ

### Цель и контекст

Предмет — полнота проверки признака и его верность. Проверяемое условие: на
всей матрице сочетаний вывод валиден, а сигнатуры точны.

### Замер

Ожидания сняты прогоном по одному входу на вид:

| Вид обращения | `_init` | `_tick` |
|---|---|---|
| нет обращений | нет | нет |
| запись выходного порта | нет | **да** |
| чтение переменной корня | нет | **да** |
| выходной порт с начальным значением | **да** | нет |
| инициализатор читает переменную корня | **да** | нет |
| порт пишет функция модели (транзитивность) | нет | **да** |
| профиль «часы» + `after Nms` | **да** | **да** ← дефект: было «нет» |
| вызов `extern fn` | нет | нет |

Строка `extern fn` — контроль: вызов печатается свободной функцией, и
признак не должен срабатывать «на всякий случай».

**Найденный дефект.** Профиль «часы»: метка состояния сравнивается с
`main->now_ms(…)` при каждой проверке выдержки, то есть **в такте**, а признак
знал об этом только в ветви `_init`. Порождённый C:

```text
probe.c:35:36: error: use of undeclared identifier 'main'
   if ((uint8_t)((uint8_t)main->now_ms(main->userdata) - model->takt_entry_ms) >= 5) {
```

Код возврата `taktc` при этом **нулевой**. Цели `rust`, `c-hal`, `st` и `sv`
тот же вход переводят и собирают — класс принадлежал признаку цели `c`.

### Зависимости фичи

Нет закрытых зависимостей. Смежное: 0396, 0419, 0439 — сам признак; 0134 —
профили времени.

### Требования и проверяемые условия

- R1. A1…A4 выше.
- R2. Ожидания снимаются прогоном, а не выводятся из реализации.

### Критерии приёмки и способ проверки

`root_pointer_matrix_tests` (40 случаев), три мутации, полный `precheck.sh`.

### Редакторский слой

**Не затронут.**

Аддитивно: чинится случай, который прежде не собирался.

## Итог

Признак перестал проверяться выборкой: теперь вопрос задаётся сплошь, и обе
стороны ошибки — громкая и тихая — ловятся. Перебор окупился сразу: он нашёл
сочетание, на котором вывод цели `c` не собирался, при том что четыре других
цели тот же вход переводят.
