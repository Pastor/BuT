# Фича: Разряд участвует в арифметике как 0/1

- **Номер:** 0356
- **Статус:** ГОТОВО
- **Зависит от:** нет (0025, 0078, 0335 закрыты)
- **Связанные issue (анализ):** кандидат «Арифметика с разрядом: эталон
  отвергает, цели считают молча» (`FEATURES.md`)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32): «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».

## Краткое описание

Доступ к разряду (`src.7`) давал у эталона `Value::Boolean`, и правило S8
(«логическое не смешивается с числом молча») било по нему.

**Замер-21** (`scripts/probe.sh -n 2`), три формы:

| Вход | эталон | восемь целей |
|---|---|---|
| `arith := src.7 + 1;` | `SIM-005` **в такте** | считают (`c` даёт 2) |
| `ref Done: src.7 = 1;` — типичная запись ребра | `SIM-005` | переводят |
| `acc := src.7 + src.6;` | `SIM-005` | считают |

**Эталон противоречил сам себе:** `bit`-**переменная** в той же арифметике
(`var f: bit := 1; arith := f + 1;`) исполнялась и давала 2 — она хранится
числом. Разница была не в типе, а в том, откуда пришло значение.

## Документирование (правило 24)

**Не требуется** — правило языка не менялось: `bit` числоподобен (значения 0 и
1, `validate_bit_values`), и восемь целей уже считали разряд числом. Фича
приводит к этому эталон; ни одна запись документа не описывала разряд как
логическое.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Фича:** [../features/0356-sim-bit-in-arithmetic.md](0356-sim-bit-in-arithmetic.md)

### Контекст

Правило **S8** (решение фичи): логическое значение не смешивается с числом
молча — `Boolean + Number` есть `TypeMismatch`. Правило разумное и снабжено
юнит-тестом.

Но доступ к разряду (`eval/access.rs::read_bit`) возвращал именно
`Value::Boolean`, и S8 бил по записям, которые все восемь целей переводят.
Замер-21:

| Вход | эталон | цели |
|---|---|---|
| `arith := src.7 + 1;` | `SIM-005` **в такте** | считают (`c` → `((model->src >> 7) & 1ull) + 1` = 2) |
| `ref Done: src.7 = 1;` | `SIM-005` | переводят |
| `acc := src.7 + src.6;` | `SIM-005` | считают |

**Контрольный вход показал внутреннее противоречие:** `bit`-**переменная** в
той же арифметике (`var f: bit := 1; arith := f + 1;`) эталоном исполнялась —
она хранится `Value::Number`. То есть у одного типа `bit` было два поведения,
и различал их источник значения, а не тип.

### Решение

**`read_bit` и `read_bit_words` возвращают `Value::Number` (0 либо 1).**

Тип `bit` в языке числоподобен: его значения — 0 и 1 (`validate_bit_values`),
и переменная этого типа хранится числом. Разряд числа есть значение того же
типа, поэтому и представление у него то же.

Правило S8 **не отменяется**: `Value::Boolean` приходит теперь только от
настоящих логических выражений — сравнения, `!`, логических связок, — и его
смешение с числом остаётся ошибкой. На это заведён контрпример рядом с
изменённым тестом.

Условия не затронуты: `to_bool` принимает число (`n != 0`), поэтому
`if src.7 { … }` работает как прежде.

### Отвергнутые варианты

**А. Разрешить `Boolean` быть числом в `as_num`.** Первая попытка фичи; она
**отменяет S8** для всех значений, а не для разряда — то есть `истина + 1`
стало бы законным везде. Отвергнуто собственным юнит-тестом правила: он упал
сразу, и это верное поведение контроля.

**Б. Диагностика семантики: запретить разряд в арифметике** (привести цели к
эталону). Так предлагал кандидат. Отвергнуто замером: правило языка уже
определено `bit`-переменной, которую эталон считает, и восемью целями; запрет
сузил бы язык там, где согласие есть, и сделал бы `ref Done: src.7 = 1;`
незаконным — а это типичная запись автомата.

**В. Оставить как есть.** Означает, что типичная запись ребра не исполняется
эталоном, то есть модель нельзя проверить симуляцией перед синтезом — ровно
то, ради чего эталон существует.

### Последствия

- Записи, переводимые восемью целями, начинают исполняться эталоном.
- Значение разряда в трассах печатается числом (`1`/`0`), а не `true`/`false`.
- Язык не меняется (правило 22): версия не поднимается — правило `bit` было
  определено, менялось только внутреннее представление у эталона.

### Замер (правило 30)

`scripts/probe.sh -n 2`, 2026-08-21, три формы — сводка в ADR. Выводы:

1. **Класс шире кандидата.** Запись 0335 называла арифметику (`src.7 + 1`);

3. **Значение у целей проверено прогоном**, а не чтением: харнесс порождённого
   C дал `2`.

### Объём правки

тесты. Арифметика (`ops.rs`) **не трогается** — там живёт правило S8.

## Разработка

#### Что сделано

`takt-sim/src/eval/access.rs`: `read_bit` и `read_bit_words` возвращают
`Value::Number` (0 либо 1) вместо `Value::Boolean`.

Тест `bit_read_on_integer_unchanged` переименован в `bit_read_on_integer_is_number`
и переписан на новое ожидание; рядом заведён **контрпример**
`s8_still_holds_for_real_booleans`.

#### Ловушки

**Правку легко сделать не в том месте.** Первая попытка меняла `as_num`
(«логическое приводится к числу») — это отменяет правило **S8** для всех
значений, а не для разряда: `истина + 1` стало бы законным везде. Юнит-тест S8
упал сразу — верное место оказалось у **источника** значения.

**Контрпример обязателен.** Без него правка читается как «S8 отменено», а
следующая фича, увидев `Value::Boolean` в арифметике, «дочинит» и то, что
чинить не следует.

**Условия проверить отдельно:** `if src.7 { … }` идёт через `to_bool`,
который принимает и число (`n != 0`), поэтому не пострадал — но убедиться в
этом нужно было прогоном, а не рассуждением.

**Имя фикстуры проверяется на занятость.** Первая редакция назвала её
`conformance_bit_value.takt` — так уже звалась фикстура фичи (разряд в
позиции числового значения), и запись **перезаписала** её: чужая сверка ST
упала «переменная 'high': неожиданное значение None». Поймал это предкоммит.
Свою назвали `conformance_bit_arith.takt`, чужую восстановили из истории.

#### Границы

- Печать трасс `takt-sim` теперь показывает разряд числом (`1`), а не `true`.
  Наблюдаемое отличие для читателя вывода; согласовано с целями.

### Условия проверок

| № | Условие | Ожидание |
|---|---|---|
| П1 | `read_member(Number(0b101), .2)` | `Number(1)` |
| П2 | `read_member(Number(0b101), .1)` | `Number(0)` |
| П3 | `arith := src.7 + 1;` | эталон исполняет, значение как у цели `c` |
| П4 | `ref Done: src.7 = 1;` | переход срабатывает |
| К1 | `Boolean(true) + Number(1)` | **`TypeMismatch`** — правило S8 в силе |
| К2 | `if src.7 { … }` | условие работает (`to_bool` принимает число) |
| С1 | трасса при `acc := acc + src.7 + src.6;`, источник растёт | эталон = цель `c`: `[2, 4, 6, 8, 8]` |

**К1 — не формальность:** без него правка читается как «S8 отменено».
Первая редакция фичи именно это и делала, и упал на ней собственный тест
правила.

Сверка берёт **два разных** разряда и меняющийся источник: на одном разряде
и постоянном значении ошибка в номере разряда невидима (мутация «сосед» —
проверена).

### Найденные дефекты

Исправлений не потребовалось. Одна поправка **в ходе** работы, важная по существу:

**Первая редакция правила меняла `as_num`** — то есть разрешала логическому
быть числом в арифметике **вообще**, отменяя S8. Упал юнит-тест правила
(`s8_bool_plus_int_is_error_not_silent_coercion`), и это верное поведение
контроля: он охраняет решение, а не строку кода. Правка перенесена к
**источнику** значения (`read_bit`), после чего S8 остался в силе и получил
контрпример рядом с изменённым тестом.

**Вторая поправка — коллизия имён фикстур.** Новая фикстура была названа
`conformance_bit_value.takt`, а так уже звалась фикстура 0335 (разряд в позиции
числового значения): запись перезаписала её, и упала **чужая** сверка ST
(`conformance_st_tests::bit_value`, «переменная 'high': неожиданное значение
None»). Поймал предкоммит. Своя переименована в `conformance_bit_arith.takt`,
чужая восстановлена из истории.
