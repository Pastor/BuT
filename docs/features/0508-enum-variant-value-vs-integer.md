# Фича: Цели `rust` и `sv` — имя варианта рядом с целым операндом

- **Номер:** 0508
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `rust`: сравнение с вариантом перечисления в модели-реализации» (заведён при закрытии [цель `rust` — операнды расширяемой арифметики: приведение по нужде и обёртка](0507-rust-widen-operands-wrap.md))

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Имя варианта перечисления, стоящее рядом с **целым** операндом, печатается
своим **значением** — у целей `rust` и `sv`. В Takt вариант есть число, поэтому
`ref Halted: op = Hlt;` при `var op: u8` — обычная запись: её исполняет эталон и
переводят `c`, `c-hal`, `st`, `st-at`. У целей со строгой типизацией имя в этой
позиции невыразимо: `rustc` отвечает `E0308`, `verilator` — `WIDTHEXPAND`, и обе
цели порождали такой вывод при **нулевом** коде возврата `taktc`.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Документирование (правило 24)

**Не требуется.** Язык не меняется: запись принималась и исполнялась как прежде,
речь о форме порождённого кода. Диагностик не заводится.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh`, вход `enum Op { Nop = 0, Hlt = 3 }`,
`var op: u8`, `ref Done: op = Hlt;`):

| Потребитель | Ответ |
|---|---|
| эталон | переходит на такте, где `op = 3` |
| `c`, `c-hal` | `cc` принял (в C перечисление есть целое) |
| `st`, `st-at` | `iec2c` принял, `cc` собрал |
| `rust` | **`E0308`**: «expected `u8`, found `Op`» |
| `sv`, `sv-mmio` | **`WIDTHEXPAND`**: EQ ждёт 8 бит, `ENUMITEMREF 'OP_HLT'` даёт 2 |

Класс найден прогоном инструментов по примерам `book/`: четыре
примера раздела «Процессор» (`cache`, `dual_core`, `machine`, `pipeline`)
печатали `self.op == Op::Hlt` при `var op: u8`. На `pipeline` к `E0308`
добавлялся **`E0433`** («cannot find type `Op`»): перечисление там нигде не
названо типом переменной, поэтому в модуль оно не попадает вовсе.

Контроль (отделяет класс от соседа): перечислимая переменная сравнивается с
именем варианта — `self.m == Mode::Run` — и это верно (0281).

### Decision Drivers

- Пара опознаётся по типу **соседа**, а не по своей стороне — ровно как в
  зеркальной ветви 0281 (число рядом с перечислимым операндом поднимается до
  варианта).
- Ошибка громкая для чужого инструмента и немая для `taktc`; проверка цели её не
  видел — в корпусе `examples/` такой записи нет.

### Considered Options

1. **Признак — общий носитель, форма — за целью** (принято).
   `generator::enum_compare::lowered` опознаёт пару; `rust` печатает число,
   `sv` — тоже число (его размер подстраивается, в отличие от `ENUMITEMREF`).
2. **Свернуть вариант в число в семантике.** Отвергнуто: это отняло бы имя у
   цели `c`, где константа перечисления печатается мнемоникой (0167) и читается
   человеком, и изменило бы снимки корпуса без нужды.
3. **Отказ цели на такую запись.** Отвергнуто: запись законна, её исполняет
   эталон и переводят четыре цели из восьми.
4. **Приводить `Op::Hlt as u8` у `rust`.** Отвергнуто: `enum` без `#[repr]`
   приводить нельзя, а `repr` — изменение публичной формы модуля ради одной
   ветви.

### Decision

Опознание пары «имя варианта ↔ целый сосед» живёт в
`generator::enum_compare`; печатники условий целей `rust` и `sv` спрашивают его
перед общим случаем и печатают значение варианта.

### Consequences

- Четыре примера `book/` раздела «Процессор» принимаются `rustc`.
- Цели `c` и `st` не затронуты: их вывод инструменты принимали и до правки.
- Снимки `examples/generated/` не меняются — записи в корпусе нет.

#### Acceptance criteria

1. Проба: все восемь целей переводят, инструменты проверок принимают.
2. Контроль: перечислимая переменная сравнивается именем (`Mode::Run`,
   `MODE_RUN`).
3. Потактовая сверка эталон ↔ `rust`: переход случается на том же такте.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

`ConditionNode::EnumVariant` печатается целями `rust` и `sv` мнемоникой
безусловно — ветвь не спрашивала, с чем вариант сравнивают. Зеркальная ветвь
0281 (`enum_comparison`) уже смотрит на тип соседа, но опознаёт **число** рядом
с перечислимым операндом, то есть противоположную пару.

### Замер (правило 30, 2026-09-03)

Таблица — в разделе «Архитектура (ADR) → Context». Замер шире кандидата:
кандидат называл только цель `rust`, прогон показал тот же класс у `sv` и
`sv-mmio` (`WIDTHEXPAND`, а проверка цели считает предупреждение ошибкой).

Соседний класс, в объём **не** входящий: `clippy::needless_else` («this `else`
branch is empty») на тех же четырёх примерах — остаётся кандидатом.

## Разработка

### Задача: общий носитель признака

`takt-lang/src/generator/enum_compare.rs` — `lowered(a, b)` опознаёт пару и
сообщает значение варианта и сторону. Модульные тесты носителя: пара
«вариант ↔ число» и «вариант ↔ вариант» правилу не подлежат.

### Задача: печать у целей

- `rust_cond.rs`: `variant_as_value` — в цепочке `Equal`/`NotEqual` перед
  ветвью 0281 и в `cond_compare` (порядковые сравнения).
- `sv_expr.rs`: та же проверка в начале `cmp`.

### Задача: контроля

Набор форм `enum_variant_value_tests.rs` (6 тестов, включая прогон
`clippy-driver` и `verilator`) и потактовая сверка
`conformance_enum_variant_value_tests.rs`.

## Тест-план

| Проверка | Ожидание |
|---|---|
| `op: u8` = `Hlt` у `rust` | `self.op == 3`, имени варианта нет |
| то же у `sv` | `== 3`, `== OP_HLT` нет (в `typedef` мнемоника остаётся) |
| `Hlt != op` | `3 != self.op` / `(3 !=` |
| перечислимая переменная | `Mode::Run`, `MODE_RUN` |
| `c`, `st` | прежняя мнемоника (`ENUM_…_OP_HLT`, `Hlt`) |
| `clippy -D warnings`, `verilator --lint-only -Wall` | принимают |
| трасса эталон ↔ `rust` | `1, 2, 3, 9` — переход на такте `op = 3` |
| примеры `book/` раздела «Процессор» | `rustc` принимает все четыре |

## Отчёт о тестировании (правило 20)

### Резюме

`./scripts/precheck.sh` — зелёный. Проба: восемь целей переводят, инструменты
принимают. Четыре примера `book/`, на которых класс найден, принимаются `rustc`
(у `clippy` остаётся соседний класс — пустая ветвь `else`, кандидат).

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка:

| Мутация | Ответ набора |
|---|---|
| значение варианта +1 | сверка: `[1, 2, 3, 9]` против `[1, 2, 3, 4]` |
| печатать мнемонику всегда (прежнее поведение) | T1, T2, T3 и прогон инструментов |
| печатать значение всегда | T4 (контроль перечислимой переменной) |

Первая мутация показывает, зачем сверка: подменённое значение даёт **валидный**
вывод и другой автомат — инструменты целей молчат.

## Итог (что сделано)

Имя варианта перечисления рядом с целым операндом печатается значением у целей
`rust` и `sv`. Прежде обе печатали мнемонику: `rustc` отвечал `E0308` (а там,
где перечисление не названо типом, ещё и `E0433`), `verilator` — `WIDTHEXPAND`,
и оба отказа приходили при нулевом коде возврата `taktc`.

Признак опознания пары — общий носитель `generator::enum_compare`; форму
печатает каждая цель. Контроля: набор форм у обеих целей с прогоном их
инструментов и потактовая сверка, ловящая подмену значения.
