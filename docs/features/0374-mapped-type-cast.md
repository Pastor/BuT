## Краткое описание

Фича сняла печать приведения, у которого тип операнда **совпадает** с
целевым. Признак сравнивал типы **Takt**, и `d as u32` при `d: duration` под
него не подпадал: типы разные. Замер-21:

| Потребитель | Печать | Ответ инструмента |
|---|---|---|
| эталон | — | исполняет |
| `rust` | `self.d as u32` | **`clippy -D warnings`: casting to the same type is unnecessary (`u32` -> `u32`)** |
| `c`, `c-hal` | `(uint32_t)model->d` | `cc -Wall -Wextra -Werror` молчит (лишний код) |
| `sv`, `sv-mmio` | `32'(durparam_d_next)` | verilator и yosys молчат (лишний код) |
| `st`, `st-at` | приведения нет вовсе | — |

То есть вывод цели `rust` **не собирался** под флагами её же проверки при нулевом
коде возврата `taktc` — ровно тот класс, ради которого заведена 0361, только
признак у неё оказался узок: типы Takt различны, а **напечатанные** совпадают
(`duration` отображается в `u32`).

## Документирование

**Не требуется** — язык не меняется: запись законна и исполняется эталоном;
меняется форма вывода трёх целей.

### Context

`d as u32` при `d: duration` — обычная запись: автор берёт число миллисекунд.
Цель `rust` печатала `self.d as u32`, и `clippy -D warnings` отвечал
«casting to the same type is unnecessary», то есть вывод не собирался под
флагами проверки самой цели при нулевом коде возврата `taktc`.

Признак фичи сравнивал типы **Takt** (`from == *ty`), а здесь они разные:
`duration` и `u32`. Совпадают они **после отображения** — правило печатает
длительность как `u32`/`uint32_t`/`logic [31:0]`.

### Decision Drivers

1. **Вывод обязан приниматься проверкой своей цели.**
2. **Признак обязан отвечать на вопрос, который задаёт инструмент:** clippy
   смотрит на типы Rust, а не на типы Takt.
3. **Правило одно на три цели**: разное поведение на одной записи
   рождает классы.
4. **Не потерять настоящее приведение:** ошибка в сторону «опустить» тиха и
   меняет значение.

### Considered Options

#### Option A. Сравнивать напечатанные типы (принято)

Признак спрашивает отображение типов у самой цели: `rust_type`,
`c_type_or_diagnostic`, `sv_type`.

**Pros:**
- Отвечает ровно на вопрос инструмента.
- Обобщает 0361: совпадение типов Takt даёт совпадение отображений, то есть
  прежние входы работают по-прежнему.
- Знание об отображении не дублируется — берётся у носителя цели.

**Cons:**
- Признак становится **зависимым от цели**: у `st` приведения нет вовсе, а у
  `c` и `rust` отображения различны (`bit` → `uint8_t` против `bool`). Это не
  недостаток, а существо дела: печатает вывод цель.

#### Option B. Расширить сравнение типов Takt списком «эквивалентных» пар

**Cons:** список пар — второе знание об отображении, и он разъедется с ним при
первом же изменении. Например, `duration` при смене
единицы  перестал бы отображаться в `u32`, а список остался бы.

#### Option C. Оставить как есть, снять `unnecessary_cast` у проверки цели

**Cons:** глушить линт значит терять контроля: тот же линт ловит настоящие
лишние приведения (0263, 0326).

### Decision

Признак «приведение ничего не меняет» строится по **напечатанному** типу
операнда и цели. Реализация — по функции на цель (`same_printed_type` у `rust`
и `sv`, сравнение с `type_c` у `c`), потому что отображение принадлежит цели.

Тип операнда берётся, как и в 0361, у **именованного значения**
(`mixed_sign::operand_type_expr`): у литерала и выражения он печатнику
неизвестен, и опускать приведение там было бы догадкой.

### Consequences

#### Положительные

- Вывод цели `rust` на записях с `duration` проходит её проверка.
- Правило одно у трёх целей; у `c` и `sv` снят лишний код.

#### Отрицательные / Action items

- Два чужих теста (сверки 0183) требовали текста `(uint32_t)model->elapsed` и
  `self.elapsed as u32` — утверждения обновлены: предмет их проверки
  (отсутствие пересчёта единиц) сохранён.
- Неотобразимый тип операнда признак не судит (`false`) — печать приведения
  сама выдаст диагностику.

#### Acceptance criteria

1. `clippy -D warnings` принимает вывод цели `rust` на входе `duration → u32`.
2. Три цели не печатают приведение на этом входе.
3. Контрпримеры: `u8 → u16` и `duration → u8` печатаются по-прежнему.
4. Вывод корпуса не изменился; предкоммит зелёный.

## Анализ

### Цель и контекст

Класс найден замером-сметой при работе над 0373: проба с функцией над
`duration` показала отказ **не** в функции, а в приведении к `u32`.

#### Замер (`scripts/probe.sh -n 3`, 2026-08-21)

Вход: `var d: duration := 5ms; d := twice(d); ms := d as u32;`

| Потребитель | Ответ | Печать |
|---|---|---|
| эталон | `ms = 10, 20, 40` | — |
| `c`, `c-hal` | `cc` принял | `(uint32_t)model->d` |
| `st`, `st-at` | `iec2c` принял · `cc` собрал | приведения нет |
| `rust` | **`clippy` ОТВЕРГ** | `self.d as u32` |
| `sv`, `sv-mmio` | verilator принял · yosys синтезировал | `32'(durparam_d_next)` |

Текст отказа: `error: casting to the same type is unnecessary (u32 -> u32)`.

Класс **не виден** по кодам возврата: `taktc` возвращает ноль у всех восьми
целей. Вердикт дал раздел «инструменты целей» пробы (0362).

Признак фичи сравнивал типы Takt и такую запись не ловил: `duration` и
`u32` различны, совпадают их **отображения**.

### Зависимости фичи

- **Зависит от:** нет. 0183 (отображение `duration`), 0359 (тип именованного
  значения), 0361 (само правило) — закрыты.
- **Влияние на порядок разработки:** снимает кандидат «Приведение
  `duration → u32` цель `rust` печатает лишним `as`».

### Требования и проверяемые условия

- **R1. Проверка цели.** `clippy -D warnings` принимает вывод цели `rust` на входе
  `duration → u32`.
- **R2. Одно правило.** Приведение не печатают все три цели, у которых оно есть
  (`c`, `rust`, `sv`).
- **R3. Контрпример «другой тип».** `b as u16` при `b: u8` печатается.
- **R4. Контрпример «сужение».** `d as u8` при `d: duration` печатается: ширина
  меняется.
- **R5. Значения.** Поведение не меняется — потактовые сверки `duration`
  остаются зелёными.
- **R6. Неизменность.** Вывод корпуса не меняется.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 | `rust_output_passes_clippy` (прогон `clippy-driver -D warnings`) на обоих входах |
| A2 | R2 | `cast_matching_after_type_mapping_is_omitted` (текст вывода трёх целей) |
| A3 | R3 | `real_cast_is_kept` |
| A4 | R4 | `narrowing_cast_from_duration_is_kept` |
| A5 | R5 | сверки `conformance_{c,rust,st,sv}_duration_tests` |
| A6 | R6 | `git diff examples/generated/` пуст, проверка детерминизма зелён |

### Особенности по обратной функциональности

Обратная совместимость сохраняется: значения не меняются, меняется только
форма вывода. Два теста фичи требовали **текста** приведения — их
утверждения обновлены (предмет проверки, отсутствие пересчёта единиц, сохранён).

### Риски и зависимости

- **Ошибка в сторону «опустить» тиха и меняет значение.** Снижение: два
  контрпримера (расширение и сужение) и сверки значений.
- **Признак зависит от цели.** Это существо дела: печатает вывод цель, и
  отображение принадлежит ей. Второго списка «эквивалентных пар» не заводится —
  он разъехался бы с отображением.

## Разработка

### Задача

#### Что было

Признак фичи (`from == *ty`) сравнивал типы **Takt**. Запись
`ms := d as u32;` при `d: duration` под него не подпадала, и цель `rust`
печатала `self.d as u32` — `clippy::unnecessary_cast`, то есть отказ проверки
цели при нулевом коде возврата `taktc`.

#### Что сделано

- **`rust`** (`rust_expr.rs`): признак `same_printed_type` сравнивает
  `rust_type(тип операнда)` и `rust_type(цель приведения)`.
- **`c`** (`c_expr/expr.rs`): то же через `c_type_or_diagnostic` — сравнение с
  уже вычисленным `type_c`.
- **`sv`** (`sv_expr.rs`): `same_printed_type` сравнивает объявления
  `sv_type(...).declare("x")` — так в одну строку сходятся ширина, знаковость
  и упакованность.
- Неотобразимый тип операнда признак не судит (`false`): печать самого
  приведения выдаст диагностику.

**Статус по функциональности.** Затронуты `c`/`c-hal`, `rust`,
`sv`/`sv-mmio`; `st`/`st-at` — **н/п** (приведения не печатает вовсе),
`plantuml` и эталон — **н/п**.

#### Проверки

```sh
cargo test                                   # 3360 тестов, 0 провалов
./scripts/probe.sh -n 3 <проба>.takt         # rust: clippy принял
./scripts/precheck.sh
```

**Два чужих теста пришлось обновить** (сверки 0183): они требовали текста
`(uint32_t)model->elapsed` и `self.elapsed as u32` — утверждения, переставшего
быть верным. Предмет их проверки — отсутствие пересчёта единиц —
сохранён и усилен: теперь они же требуют, чтобы приведения **не** было.

Имя переменной в контрпримере пришлось сменить: `small` — ключевое слово
SystemVerilog (`SV-012`), и проба падала не на предмете.

## Итог (что сделано)

- Признак «приведение ничего не меняет» строится по **напечатанному** типу:
  `rust_type`, `c_type_or_diagnostic` и `sv_type` соответственно. Записи, где
  типы Takt различны, а отображения совпадают, больше не печатаются.
- **Правится у трёх целей, хотя отказ был у одной** — тот же довод, что у
  0361: разное поведение на одной записи есть класс.
- **Контрпримеры обязательны и их два:** настоящее приведение (`u8 → u16`) и
  сужение от длительности (`duration → u8`) печатаются по-прежнему.
- **Два чужих теста закрепляли утверждение, переставшее быть верным**
  (сверки 0183 требовали текста `(uint32_t)model->elapsed` и
  `self.elapsed as u32`): предмет их проверки — отсутствие пересчёта единиц —
  сохранён, требование к тексту приведения снято.
- Вывод корпуса не изменился.

Детали — в [отчёте](0374-mapped-type-cast.md#отчёт-о-тестировании).
