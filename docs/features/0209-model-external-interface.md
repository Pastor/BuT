### Context

Фича состоит из **двух независимых** частей; проба (2026-08-16) подтвердила обе.

#### Замер 1: `extern fn` со значением останавливает прогон

| Форма | Цель `c` | Эталон |
|---|---|---|
| `extern fn led(on: bit);` (без возврата) | колбэк HAL | **исполняется** (пустое действие) |
| `extern fn mem_read(addr: u8) -> u8;` | колбэк HAL | **`SIM-019` в такте**, прогон остановлен |

Следствие названо в карточке: модель с внешним интерфейсом **непроверяема
эталоном** — сверка поведения невозможна, а примеры документа (их проверка
исполняет) такой формы содержать не могут.

#### Замер 2: агрегат как аргумент параметра не вычислялся

`Memory(prog := {9, 8, 7, 6})` → `SE-083`: общий константный вычислитель
агрегат не сворачивал. То есть «программа как аргумент» не выражалась.

**Снятие отказа обнажило неготовность цели `c`** (проба после правки):
она печатала `model->main.prog = {9, 8, 7, 6};` — не выражение, а инициализатор
объявления, и `cc` отвечал «expected expression». Дефект был **недостижим**,
пока семантика отвергала форму раньше. Цель `rust` ту же форму печатала верно
(`self.main.prog = [9, 8, 7, 6];`, `rustc` принял), цели `st` и `sv` отвечают
своими отказами (`ST-017`, `SV-002`).

### Decision Drivers

1. **Эталон обязан быть проверяемым.** Всё, что цель `c` умеет, эталон должен
   уметь прогнать — иначе сверок поведения не существует.
2. **Молчаливое умолчание недопустимо.** Ноль вместо значения внешней функции
   означал бы зелёный прогон при расхождении эталона и прошивки — тот самый
   класс, ради которого заведены потактовые сверки.
3. **Вход прогона уже есть.** Сценарий подаёт значения входных портов по тактам;
   внешняя функция — тот же вход, только вызываемый.
4. **Агрегат — значение сборки.** Параметр задаётся при инстанцировании, и
   значение его аргумента обязано доезжать до целей литералом (образец 0185).

### Considered Options (часть 1: откуда брать значения `extern fn`)

#### Option A. Из сценария, таблицей по аргументу — **принято**

Секция `extern` в шаге: одно значение на такт (`"mem_read": 42`) либо таблица по
первому аргументу (`"mem_read": {"0": 9, "1": 8}`).

**Pros:**
- значения приходят оттуда же, откуда входы портов, — новых входов инструмента
  не заводится;
- «память» описывается естественно: адрес → содержимое;
- умолчания нет: не задали — прежний отказ `SIM-019`.

**Cons:**
- таблица ищет по **первому** аргументу; вызов без аргументов таблицей не
  покрывается (для него есть форма «одно значение») — названная граница.

#### Option B. Тело-заглушка на языке Takt

Отдельный файл-дубль с телами тех же функций, подключаемый флагом.

**Pros:** заглушка может считать, а не только отдавать таблицу.

**Cons:** новый вход инструмента, своё разрешение имён и вопрос «что если
заглушка разошлась с прошивкой» — работа, несопоставимая с предметом.

#### Option C. Значение по умолчанию + предупреждение

**Cons:** прямо противоречит драйверу 2: эталон считал бы ноль, прошивка —
настоящее значение, и сверка трасс была бы зелёной.

#### Option D. Оставить отказ

**Cons:** оставляет модель с внешним интерфейсом непроверяемой — то есть не
решает предмет фичи.

### Decision

**Часть 1** — Option A (решение заказчика 2026-08-16): стенд задаётся сценарием.
Значения ставятся перед тактом тем же приёмом, что и модельное время
(`set_time_ns`), и живут **шагом**, а не прогоном.

**Часть 2** — агрегат вычисляется общим константным вычислителем
(`ConstValue::List`) и печатается целями:
- `c` — **поэлементно** (`p.prog[0] = 9;`), потому что агрегат в C не
  присваивается;
- `rust` — как есть (уже работало);
- `st`/`sv` — прежние отказы `ST-017`/`SV-002`: границы названы, а не молчат.

### Consequences

#### Положительные

- Модель с внешним интерфейсом становится **проверяемой эталоном**: сверка
  поведения и примеры документа с `extern fn` возможны.
- «Программа как аргумент» выражается: `Memory(prog := {9, 8, 7, 6})`.
- Формат сценария расширен **аддитивно**: поле необязательно, старые сценарии
  читаются без правки.

#### Отрицательные / Action items

- Таблица ищет по **первому** аргументу — для функций с несколькими значащими
  аргументами этого мало; названо границей, расширение — отдельная фича.
- Цели `st` и `sv` агрегатный аргумент не печатают; отказы пришпилены тестом,
  чтобы «научится» не прошло молча.
- Стенд обязан доезжать **до всех областей видимости**: тело блока и тело
  функции исполняются в своих контекстах, а такт — с `Unit` в роли контекста.
  Пропусти одну — подмена молча не сработает (так и случилось при первой сборке).

#### Acceptance criteria

1. Таблица по аргументу кормит последовательные чтения разными значениями.
2. Форма «одно значение» отвечает на любой вызов такта.
3. Без стенда — прежний отказ `SIM-019` (контр-пример).
4. Стенд принадлежит **шагу**, а не прогону (контр-пример).
5. Нечисловой ключ таблицы — ошибка сценария с именем функции.
6. Агрегат в аргументе вычисляется; эталон видит заданные значения.
7. Цель `c` печатает агрегат поэлементно, и `cc` принимает вывод.
8. Неконстантный элемент агрегата по-прежнему отвергается.
9. `./scripts/precheck.sh` зелёный, вывод корпуса неизменен.

## Анализ

### Цель и контекст

Сделать модель с внешним интерфейсом **проверяемой эталоном** и выразить
«программу как аргумент». Две независимые части, обе подтверждены пробой:
стенд `extern fn` из сценария (решение заказчика) и агрегат в аргументе
параметра.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Смежные [параметризация моделей (ключевое слово `parameter`)](0185-model-parameters.md)
  (параметры), [модель времени в языке: литерал длительности и частота такта](0134-language-time-model.md) (время ставит
  `runner` — образец для стенда) — закрыты.
- **Влияние на порядок разработки:** снимает ограничение, названное в
  `CLAUDE.md` («в примерах значения датчиков берут входным портом, а `extern fn`
  оставляют для команд-действий»): теперь пример документа вправе читать внешнюю
  функцию, если сценарий задаёт значения.

### Замеры

Таблицы — в ADR. Кратко: `extern fn` **со значением** останавливал прогон
(`SIM-019`), без возврата — исполнялся; агрегат в аргументе отвергался
`SE-083`. Снятие второго отказа **обнажило** неготовность цели `c`: она
печатала присваивание агрегата, которое `cc` отвергает; дефект был недостижим,
пока семантика отвергала форму раньше.

### Требования и проверяемые условия

- **R1. Стенд из сценария.** Две формы: одно значение на такт и таблица по
  первому аргументу.
- **R2. Умолчания нет.** Не задали — прежний `SIM-019`. Это главное
  требование фичи: ноль сделал бы сверку трасс зелёной при расхождении.
- **R3. Стенд принадлежит шагу**, а не прогону.
- **R4. Стенд доезжает до всех областей видимости** — тела блоков и функций
  исполняются в своих контекстах, а такт идёт с `Unit` в роли контекста.
- **R5. Ошибка сценария называется.** Нечисловой ключ таблицы и нечитаемое
  значение — отказ с именем функции, а не молчаливый пропуск.
- **R6. Агрегат вычисляется** и доезжает до эталона значением.
- **R7. Цель `c` печатает агрегат поэлементно** — иначе вывод отвергает `cc`.
- **R8. Неконстантный элемент отвергается** (значение параметра — величина
  сборки).
- **R9. Границы целей названы:** `st`/`sv` агрегатный аргумент не печатают.

## Разработка

### Задача

#### Что было

`Memory(prog := {9, 8, 7, 6})` отвергалось `SE-083`: общий константный
вычислитель агрегат не сворачивал, и «программа как аргумент» не выражалась.

#### Что сделано

**1. Агрегат в константном вычислителе.** `ConstValue::List(Vec<ConstValue>)`;
ветвь `E::Array | E::Initializer` вычисляет элементы поэлементно (вложенность
работает сама собой), `to_literal` печатает форму `{…}` — ту же, какой её пишет
автор. Арифметики над агрегатом нет: смешение видов отвергает общая ветвь.

**2. Цель `c` печатает агрегат поэлементно.** Снятие отказа семантики
обнажило неготовность цели: она печатала `model->main.prog = {9, 8, 7, 6};` — не
выражение, а инициализатор объявления, и `cc` отвечал «expected expression».
Дефект был **недостижим**, пока семантика отвергала форму раньше, и стал
достижим в тот же час. Теперь аргумент-агрегат печатается той же формой, какой
`_init` кладёт значения по умолчанию.

**Прочие цели**: `rust` печатала форму верно и до правки (`rustc`
принял); `st` и `sv` отвечают своими отказами `ST-017`/`SV-002` — границы
названы и пришпилены тестом.

#### Проверки

- `takt-sim/tests/sim/aggregate_argument_tests.rs` — 5 тестов: приём семантикой,
  значения у эталона, поэлементная печать в C (и **отсутствие** формы
  присваивания), контр-пример «неконстантный элемент», отказы `st`/`sv`.
- **Мутация:** правки сняты — краснеют 4 из 5 (контр-пример зелен по обе
  стороны, как и должно).
- Порождённый C проверен `cc -c` вручную: принят.

### Задача

#### Что было

`extern fn mem_read(addr: u8) -> u8;` цель `c` принимала колбэком HAL, а эталон
отвечал `SIM-019` **в такте** и останавливал прогон: модель с внешним
интерфейсом была непроверяема эталоном.

#### Что сделано

**1. Секция `extern` в шаге сценария** (`json_input.rs`): на функцию — либо одно
значение (`"mem_read": 42`), либо таблица по **первому** аргументу
(`"mem_read": {"0": 9, "1": 8}`). Поле необязательно: старые сценарии читаются
без правки.

**2. Стенд ставится перед тактом** тем же приёмом, что модельное время
(`Unit::set_extern_stubs`, рекурсивно по дереву — ветви композиции живут в одном
шаге сценария).

**3. Вызов спрашивает стенд** (`unit/statement.rs`), и **только** если стенд
молчит, отвечает прежним `SIM-019`. Умолчания нет намеренно: ноль сделал бы
прогон зелёным там, где эталон и прошивка расходятся.

**Стенд обязан доезжать до всех областей видимости.** При первой сборке
подмена не срабатывала: тело блока и тело функции исполняются в своих контекстах
(`BlockScope`/`FunctionScope`), а такт идёт с `Unit` в роли контекста — умолчание

значение — отказ с именем функции и номером шага, а не молчаливый пропуск.

#### Две находки, которых не было в карточке

1. **Снятие отказа семантики обнажило неготовность цели `c`.** Пока `SE-083`
   отвергал агрегат раньше, печатник до него не доходил; в тот же час, когда
   форма стала законной, цель начала печатать `p.prog = {9, 8, 7, 6};` — не
   выражение, а инициализатор объявления, который `cc` отвергает. Починено в той
   же задаче: печать поэлементная.
   Урок общий: снимая отказ, проверяй **всех** потребителей формы — отказ мог
   быть единственным, что их прикрывало.
2. **Стенд не доезжал до вложенных областей видимости.** При первой сборке
   подмена не срабатывала: тело блока и тело функции исполняются в своих

   в любом из трёх мест означает «стенда нет». Реализовано во всех трёх; тест
   гоняет вызов из тела `always`, то есть путь через все контексты.

### Выводы и дальнейшие шаги

1. **Ограничение, записанное в живом контексте, снято наполовину.** Прежде

4. Исправлений не потребовалось.

## Итог (что сделано)

Две независимые части, обе подтверждены пробой.

**1. Модель с внешним интерфейсом стала проверяемой эталоном.** `extern fn` со
значением останавливал прогон `SIM-019` — сверка поведения была невозможна, а
примеры документа такой формы содержать не могли. Теперь значения приходят **из
сценария** (решение заказчика 2026-08-16): одно на такт либо **таблицей по
первому аргументу** — так описывается «память», из которой читает модель. Умолчания нет: не задали — прежний отказ. Ноль сделал бы прогон зелёным там, где
эталон и прошивка расходятся.

**2. Агрегат стал выражаться аргументом параметра.** `Memory(prog := {9, 8, 7, 6})`
отвергалось `SE-083`; теперь вычисляется общим константным вычислителем.

**Снятие этого отказа обнажило неготовность цели `c`:** она печатала
`p.prog = {9, 8, 7, 6};` — не выражение, а инициализатор объявления, и `cc`
отвечал «expected expression». Дефект был **недостижим**, пока семантика
отвергала форму раньше. Урок общий: снимая отказ, проверяй **всех**
потребителей формы — отказ мог быть единственным, что их прикрывало.

Вторая находка того же рода: стенд не доезжал до вложенных областей видимости
(тело блока, тело функции, `Unit` в роли контекста) — умолчание трейта в любом
из трёх мест означает «стенда нет».

Границы названы: таблица ищет по **первому** аргументу; цели `st` и `sv`
агрегатный аргумент не печатают (`ST-017`, `SV-002`) — отказы пришпилены тестом.

Живая проверка: `./scripts/precheck.sh` зелёный, вывод корпуса неизменен,
мутация роняет 4 из 5 тестов агрегата. Подробности — в
[отчёте](0209-model-external-interface.md#отчёт-о-тестировании); исправлений не потребовалось.
