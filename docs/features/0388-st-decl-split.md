## Краткое описание

`takt-lang/src/generator/st/st_decl.rs` достиг **1000 строк при лимите 1000**
(замер фичи [слово `from` — контекстное ключевое](0385-contextual-from.md)): следующая правка печати
объявлений цели `st` уронила бы проверка размера. Модуль разделён по границе,
которую его же шапка называла с самого начала — «два пласта вывода»:

| Пласт | Где теперь |
|---|---|
| `TYPE … END_TYPE` (структуры, именованные типы общих массивов, формы массивов из параметров) | `st_decl_types.rs` |
| Секции `VAR…` внутри `FUNCTION_BLOCK` | `st_decl.rs` |

Вывод не изменился ни на байт: фича переносит код, а не правит его.

### Context

`st_decl.rs` — 1000 строк при лимите 1000 (запас 0). Правило размера модуля
(`docs/CODE.md`, проверка `check-module-size.sh`) роняет прогон при росте, а сам
файл в узаконенный долг не входит: он в лимит **укладывается**, но расти ему
некуда. Ближайшая правка печати объявлений цели `st` упёрлась бы в проверка — и
автору пришлось бы делить модуль под давлением, а не по существу.

### Decision Drivers

1. **Границы модулей = границы ответственности** (правило `docs/CODE.md`):
   делить надо по логике, а не «пополам».
2. **Вывод не должен измениться** — снапшоты корпуса сверяются проверкой (0048,
   0274), и любой сдвиг был бы виден как дифф.
3. **Граница уже описана**: шапка `st_decl` с задачи называет «два
   пласта вывода» — типы файла и секции `VAR…`.

### Considered Options

#### Option A. Внести файл в реестр долга

**Cons:** реестр — узаконенный долг, а не разрешение; запись имеет право
только уменьшаться. Файл в лимит укладывается — вносить его туда значило бы
записать в долг то, что долгом не является.

#### Option B. Делить по размеру (вынести «хвост»)

**Cons:** граница пройдёт по случайному месту; следующая правка снова упрётся,
а модуль потеряет связность.

#### Option C. Делить по пласту вывода

Типы файла (`TYPE … END_TYPE`) — в свой модуль; секции `VAR…` остаются.

**Pros:** граница уже названа в шапке; у пластов разный жизненный цикл (типы —
один раз на файл и до первого использования, секции — на модель); оба файла
получают запас.

**Cons:** требует аккуратности с общими элементами (`Extras`, тесты).

### Decision

Принимается **Option C**. В `st_decl_types.rs` переезжают `shared_array_names`,
`emit_struct_types`, `shared_array_types`, `function_array_forms`,
`function_array_form_names`.

**`Extras` остаётся в `st_decl`**: структура описывает дополнения к
**секциям** (`state`, `is_done`, `VAR_IN_OUT`), а не к типам. Механический
перенос увёл её вместе с соседним кодом — компилятор это назвал.

**Тесты печати объявлений остались рядом со своим предметом**
(`emit_declarations`), а не уехали с типами.

### Consequences

#### Положительные

- `st_decl.rs` — 806 строк, `st_decl_types.rs` — 216: обоим есть куда расти.
- Связность выше: типы файла и секции модели больше не соседствуют в одном
  файле.

#### Отрицательные / Action items

- Публичные пути двух функций изменились (`st_decl::` → `st_decl_types::`) —
  это внутренний интерфейс крейта, потребители поправлены.

#### Acceptance criteria

1. Вывод корпуса не изменился (`git diff --exit-code examples/generated/`).
2. Все тесты зелены.
3. Проверка размера модуля проходит без записей в реестре долга.
4. `./scripts/precheck.sh` зелёный.

## Разработка

### Задача

#### Что было

`st_decl.rs` — 1000 строк при лимите 1000. Файл держал оба пласта вывода
цели `st`: объявления типов файла и секции `VAR…` конкретной модели.

#### Что сделано

Пласт типов вынесен в `st_decl_types.rs`: `shared_array_names`,
`emit_struct_types`, `shared_array_types`, `function_array_forms`,
`function_array_form_names`. Вызовы в `st/mod.rs` переведены на новый путь.

**`Extras` возвращена в `st_decl`**: структура описывает дополнения к
**секциям** (`state`, `is_done`, `VAR_IN_OUT`, разделяемые переменные), а не к
типам; механический перенос увёл её вместе с соседним кодом, и это назвал
компилятор.

**Тесты печати объявлений возвращены к своему предмету** — они проверяют
`emit_declarations`, оставшийся в `st_decl`.

Итог: `st_decl.rs` — 806 строк, `st_decl_types.rs` — 216.

#### Проверки

```sh

./scripts/check-module-size.sh
./scripts/precheck.sh
```

- **Вывод** (T1): дифф корпуса пуст — код перенесён, не изменён.

- **Размер** (T3): оба модуля в лимите; реестр долга не менялся.

### Выводы и дальнейшие шаги

файла печатаются один раз и до первого использования, секции `VAR…`
принадлежат модели.

**2. Своих контрольных тестов фича не заводит намеренно.** Её предмет — устройство
исходника; правильность переноса доказывают существующие контроля (снапшоты
корпуса, юнит-тесты печати, проверка `iec2c`). Заводить тест «файл короче N строк»
значило бы дублировать проверка размера.

**3. Кандидаты.** Закрытие снимает процессного кандидата «Печать объявлений
цели `st` упёрлась в предел размера модуля».

## Итог (что сделано)

- Печать объявлений цели `st` разделена на два модуля по существующей границе

  байт-в-байт прежний, диффа нет.
