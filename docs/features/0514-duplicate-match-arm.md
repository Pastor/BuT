# Фича: Повторяющийся образец `match` — `SE-131` и печать целей

- **Номер:** 0514
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат `FEATURES.md` «дублирующиеся образцы `match`» (заведён при закрытии [цели `rust` и `st` — пустая ветвь `match`](0509-empty-match-arm.md))

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Ветвь `match`, чей образец уже встречался выше, **недостижима**: `match` берёт
первое совпадение. Автор получает предупреждение **`SE-131`** с позицией ветви,
а цели такую ветвь не печатают — прежде `cc` отвечал «duplicate case value»,
`clippy` — «these `if` branches have the same condition», а две ветви `_`
давали у `verilator` «Multiple default statements», и всё это при **нулевом**
коде возврата `taktc`.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh`), две формы дубля:

| Потребитель | `1 => …  1 => …` | `_ => …  _ => …` |
|---|---|---|
| эталон | берёт первую ветвь | берёт первую |
| `st`, `st-at` | `iec2c` принял | принял |
| `sv`, `sv-mmio` | `verilator` принял | **«Multiple default statements»** |
| `c`, `c-hal` | **`cc`: «duplicate case value»** | принял |
| `rust` | **`clippy`: «same condition»** | принял |

То есть при нулевом коде возврата `taktc` две цели из четырёх порождали
невалидный вывод, и ни один потребитель не говорил автору, что ветвь мёртвая.

### Decision Drivers

- Смысл записи определён (первое совпадение) и одинаков у эталона и всех целей
  — значит нормировать нечего, а вот сказать автору надо.
- Прецедент рядом: недостижимое ребро — предупреждение `SE-116` (0273), не
  отказ. Довод тот же: отказ ломал бы работающие входы.
- Невалидный вывод чинится печатью, а не отказом: опущение недостижимой ветви
  автомат **не меняет** (в отличие от опущения пустой достижимой, 0509).

### Considered Options

1. **Предупреждение + опущение ветви у целей** (принято).
2. **Ошибка семантики.** Отвергнуто: сужение языка ради записи, которую
   исполняют эталон и четыре цели; обратная совместимость пострадала
   бы без нужды.
3. **Только починка печати.** Отвергнуто: автор так и не узнал бы, что ветвь
   мёртвая, — а это его ошибка, а не особенность цели.
4. **Только предупреждение.** Отвергнуто: невалидный вывод остался бы.

### Decision

`SE-131` — предупреждение семантики с позицией ветви; признак «образец
повторяет более ранний» — общий носитель `semantic::match_arms`, его спрашивают
печатники `c`, `rust` и `sv`.

### Consequences

- Восемь целей переводят обе формы дубля, инструменты принимают.
- Правило («пустая ветвь не печатается») **упростилось**: оговорка «кроме
  случая, когда образец повторяется ниже» стала не нужна — дубли до печати
  больше не доходят. Прежняя оговорка на входе «пустая первая + дубль ниже»
  сама давала невалидный ST.
- У цели `rust` вскрылся смежный случай: пустая ветвь образца, оставшаяся в
  цепочке одна, даёт `clippy::needless_if` — теперь она тоже не печатается.

#### Acceptance criteria

1. `SE-131` приходит на каждую недостижимую ветвь, с позицией.
2. Различные образцы предупреждения не дают (контроль).
3. Восемь целей переводят обе формы, инструменты принимают.
4. Исполняется первая ветвь — контролирует потактовая сверка.
5. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Признак «образец повторяется» нужен и семантике (диагностика), и трём целям
(печать), поэтому носитель переехал из `generator::match_arms` (0509) в
`semantic::match_arms`: генератор вправе зависеть от семантики, обратное — нет.

Позиции у семантической ветви `match` не было (класс: в АСД она есть,
теряется при понижении) — добавлено поле `loc`, в равенство узлов оно не входит.

### Замер

Таблица — в разделе «Архитектура (ADR) → Context».

### Зависимости фичи

Зависимостей нет. Соседняя 0509 правится по существу (см. «Разработка»).

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | Недостижимая ветвь даёт `SE-131` с позицией |
| Т2 | Высказываются все такие ветви  |
| Т3 | Вторая ветвь `_` — тот же класс |
| Т4 | Различные образцы молчат (контроль) |
| Т5 | Цели `c`, `rust`, `sv` ветвь не печатают |
| Т6 | Исполняется первая ветвь (значение, не форма) |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh`, наборы
`semantic/duplicate_match_arm_tests.rs` и `targets/empty_match_arm_tests.rs`,
сверка `conformance_duplicate_arm_tests.rs`, `precheck.sh`.

### Редакторский слой

**Проверено:** новых токенов и форм объявления нет — подсветка и автодополнение
не затронуты. Диагностика доезжает до редактора автоматически: она добавлена в
`semantic::warnings::collect_model_warnings`, а LSP берёт список оттуда (0232).

### Особенности по обратной функциональности

Совместимость полная: код возврата не меняется (предупреждение), а порождаемый
код меняется только там, где инструмент его отвергал.

### Риски и зависимости

- **Риск:** опущение ветви изменит автомат. Снят тем, что опускается **только**
  недостижимая ветвь, и контролем-сверкой на разных приращениях.

## Разработка

### Задача: носитель признака и позиция ветви

`semantic/match_arms.rs` — `pattern_repeats_above`/`pattern_repeats_below`
(модуль переехал из `generator/`); `MatchArmNode` получил `loc`, заполняемый при
понижении.

### Задача: диагностика

`semantic/validate/duplicate_match_arm.rs` — обход тел (блоки, функции,
вложенные модели), накопительно; доставка — `collect_model_warnings`.

### Задача: печать целей

`c` (`c_expr/stmt.rs`), `rust` (`rust_match.rs`), `sv` (`sv_stmt.rs`) — ветвь с
повторяющимся образцом пропускается; `_`-ветвь берётся первая.

### Задача: упрощение правила

У цели `st` снята оговорка «пустую ветвь не опускать, если образец повторяется
ниже»: дубли до печати не доходят. Тот же вход (`1 => {}` и `1 => {…}`) прежде
давал невалидный ST — теперь исчезают обе ветви, а поведение прежнее.
У цели `rust` пустая ветвь образца тоже не печатается (`clippy::needless_if`).

## Тест-план

| Проверка | Ожидание |
|---|---|
| `1 => …  1 => …` | одно `SE-131` с позицией второй ветви |
| три одинаковых образца | два предупреждения |
| `_ => …  _ => …` | одно предупреждение |
| различные образцы | молчание |
| дубль в теле функции вложенной модели | предупреждение |
| печать `c` | одна метка `case 1:` |
| печать `rust` | одно условие `self.op == 1` |
| печать `sv` | один `default:` |
| трасса эталон ↔ `rust` | `1, 101, 101` |
| прогон инструментов на обеих формах | принимают |

## Отчёт о тестировании

### Резюме

`./scripts/precheck.sh` — зелёный. Пробы: восемь целей переводят обе формы,
инструменты принимают.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка:

| Мутация | Ответ набора |
|---|---|
| считать дубли снизу вместо «сверху» | сверка: `[1, 101, 101]` против `[10, 110, 110]`, плюс два теста формы |
| не пропускать недостижимую ветвь | прогон `cc`, `clippy`, `verilator` |
| предупреждать на каждом `match` | контрольный тест «различные образцы молчат» |

### Найденные дефекты

Работа вскрыла, что оговорка фичи (сохранять пустую ветвь при дубле)
сама давала невалидный ST на входе «пустая первая + дубль ниже», а у `rust`
осталась пустая ветвь образца (`needless_if`). Оба случая закрыты здесь же; тест, закреплявший прежнюю форму, переписан.

### Выводы и дальнейшие шаги

Правило «первое совпадение» теперь названо автору, а недостижимая ветвь до
вывода не доходит.

## Итог (что сделано)

Заведена диагностика `SE-131`: ветвь `match` с повторяющимся образцом
недостижима, потому что срабатывает первая подошедшая. Предупреждение (не
отказ) — смысл записи определён, и её исполняют эталон и все цели; довод тот
же, что у `SE-116`.

Цели `c`, `rust` и `sv` недостижимую ветвь больше не печатают: прежде она
давала «duplicate case value», «same condition» и «Multiple default statements»
при нулевом коде возврата. Признак — общий носитель `semantic::match_arms`,
позиция ветви добавлена в семантический узел.

Версия языка поднята до **0.16.0**.
