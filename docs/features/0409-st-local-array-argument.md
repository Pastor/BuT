# Фича: Локальный массив в аргументе функции: вывод st отвергает iec2c

- **Номер:** 0409
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2 — невалидный вывод при рапорте об успехе
- **Класс:** генерация
- **Связанные issue (анализ):** находка [срез в аргументе вызова не переводит ни одна цель](0400-slice-in-call-argument.md)

## Краткое описание

Локальная переменная-массив, переданная в функцию, объявлялась **анонимным**
типом, тогда как параметр — **именованной формой** (`TAKT_ARR_2_USINT`). MatIEC сверяет типы буквально, и вывод отвергался `iec2c` при
**нулевом** коде возврата `taktc`.

Найдено при работе над [срез в аргументе вызова не переводит ни одна цель](0400-slice-in-call-argument.md): обход, который
её ADR называла «дешёвым и известным», сам не работал.

## Замер (правило 30, 2026-08-23, `scripts/probe.sh`)

Вход:

```takt
fn first(a: [u8; 2]) -> u8 { return a[0]; }

var o: u8 := 0;

start Run {
    always {
        var part: [u8; 2] := {6, 7};
        o := first(part);
    }
    ref Run;
}
```

| Потребитель | `taktc` | Инструмент цели |
|---|---|---|
| эталон | исполняет | — |
| `c`, `c-hal` | OK | `cc` принял |
| **`st`, `st-at`** | **OK** | **`iec2c` ОТВЕРГ:** «Data type incompatibility for value passed in position 1 when invoking function 'B_first'» |
| `rust` | OK | `rustc` + `clippy` приняли |
| `sv`, `sv-mmio` | OK | `verilator` + `yosys` приняли |

Расходился **один** потребитель, и увидел это только его инструмент: код
возврата `taktc` был нулевым у всех восьми (ради которого проба
прогоняет инструменты целей).

## Документирование (правило 24)

**Не требуется.** Язык не меняется: правится форма объявления в выводе цели.

## Архитектура (ADR)

- **Status:** Accepted — исполнителю (решения заказчика не требует)
- **Date:** 2026-08-23

### Context

Правило «массив в параметре `FUNCTION` объявляется именованной формой» введено
фичей [массив в параметре функции у цели `st`](0348-st-array-parameter.md); [массив как общая переменная в цели st; индекс массива не только литерал или имя](0210-st-array-shared-and-index.md) записала его урок прямо: «Именованным
обязано быть **и параметр, и переменная владельца**: половинчатая правка даёт
ту же ошибку». Переменные **модели** правилу подчинялись, локальные объявления
тел — нет: их печатают два других места (`st_decl.rs` для тел модели,
`st_func.rs::emit_hoisted_var` для тел функций), и оба звали `get_st_type`
напрямую.

### Decision

Обе точки печати зовут общий носитель
`st_type::local_declaration_type(ty, model, array_forms)`: именованная форма,
если она объявлена, иначе прежний анонимный тип. Список форм — **тот же**, что
у продюсера `TYPE … END_TYPE` (`function_array_form_names`): разъехавшись, они
дали бы ссылку в пустоту (урок ADR).

**Именуется не всякий локальный массив, а только той формы, что встречается
в параметре.** Иначе поехал бы вывод корпуса, и на объявление без единого
вызова печатался бы тип, которого нет.

### Consequences

- Вывод цели `st` принимается `iec2c` на входе, который исполняют остальные
  восемь потребителей.
- Вывод корпуса **не изменился**: локальных массивов в аргументе вызова в
  `examples/` нет ни одного.

## Итог (что сделано)

Правило («именованным обязан быть и параметр, и переменная») достроено
до **локальных** объявлений тел: обе точки печати (`st_decl.rs` для тел модели,
`st_func.rs` для тел функций) зовут общий носитель
`st_type::local_declaration_type`, а список форм спрашивается тот же, что у
продюсера `TYPE … END_TYPE`.

Класс найден **при работе над другой фичей**: 0400 предполагала обойти
непереводимый срез в аргументе присваиванием во временную переменную — и сам
обход у цели `st` не работал.

**Код возврата `taktc` был нулевым у всех восьми целей**; расхождение видел
только `iec2c` — ровно тот класс, ради которого проба прогоняет инструменты
целей (0362).
