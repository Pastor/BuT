# Фича: Заметки о возможных ошибках в разделах документа

- **Номер:** 0120
- **Статус:** ГОТОВО
- **Зависит от:** 0119 (ссылается на приложение «Ошибки»)
- **Связанные issue (анализ):** новая фича (запрос заказчика 2026-07-24 — обращать внимание на возможные ошибки при описании конструкций)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**: «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».
Отдельным артефактом остаются только исправления —
[`docs/fixes/`](../fixes/README.md) (при необходимости `0120-YY-*`).

## Краткое описание

Каждый языковой раздел документа `book/`, описывая конструкции и примеры, обращает
внимание на **типичные ошибки** по теме — блоком «Частые ошибки» с кодами
диагностик и ссылкой на приложение «Ошибки и предупреждения». Вводит
**свод** и ретрофитит разделы 02–07. Язык не меняется (Tier 3).

> Фича зарегистрирована **2026-07-24 по запросу заказчика**.

## Документирование

Кросс-секционная работа по документу: язык **не меняется**. Добавляет в разделы
блоки «Частые ошибки» (указание промаха + код + ссылка на приложение); полное
раскрытие ошибок — в приложении. Номера фич/процесс в текст не
попадают.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-24
- **Authors:** Архитектор, лид документации
- **Related issues:** [Фича](0120-book-error-notes.md); опирается на приложение «Ошибки» ([приложения документа + приложение «Ошибки»](0119-book-appendices.md)) и свод ### Context

Заказчик запросил: при описании конструкций и примеров во **всех** разделах
обращать внимание на возможные ошибки (приведение типов, определение переменных,
задание моделей и т. п.). Приложение «Ошибки» (0119) уже содержит полный справочник
кодов; нужно связать разделы с ним, не дублируя содержимое.

### Decision Drivers

1. **Практическая польза.** Читатель раздела сразу видит типичные промахи по теме.
2. **Без дублирования**: полное раскрытие — в приложении, в разделе —
   указание + ссылка.
3. **Единый формат** для всех разделов; распространяется и на будущие.

### Considered Options

#### Форма заметки

- **(A) Блок «Частые ошибки» в конце раздела** — перечень типичных промахов с
  кодами и ссылкой на приложение. Единообразно, компактно. **Выбрано.**
- **(B) Инлайн-врезки у каждой конструкции** — дробит текст, тяжело поддерживать.

#### Форма ссылки на приложение

- **(A) Markdown-ссылка на файл приложения** `[…](../appendix-errors/index.md)` —
  кликабельна; в PDF резолвится в кросс-главную ссылку (проверено: после
  достаточного числа проходов xelatex `undefined = 0`). **Выбрано.**
- **(B) Ссылка на конкретный якорь кода** `#se-034…` — хрупко (авто-id из
  кириллицы/бэктиков), отвергнуто.
- **(C) Текстовое упоминание без ссылки** — теряет кликабельность.

### Decision

Заводится **свод** (`docs/RULE.md`): каждый языковой раздел обязан иметь блок
**«Частые ошибки»** — перечень типичных промахов по теме с кодами диагностик и
**ссылкой на приложение** (markdown-ссылка на файл приложения). Существующие
разделы дополняются, новые пишутся сразу с блоком. Retrofit разделов 02–07 в рамках
этой фичи.

### Consequences

#### Положительные

- Разделы связаны со справочником ошибок; читателю виднее «грабли».
- Формат единый и обязательный — новые разделы не забудут блок.

#### Отрицательные / Action items

- При добавлении/переименовании кодов заметки в разделах нужно держать
  согласованными с приложением (и с реестром диагностик).
- Разделы 08–16 получат блок при их наполнении.

#### Acceptance criteria

1. Разделы 02–07 имеют блок «Частые ошибки» с кодами и ссылкой на приложение.
2. свод в `docs/RULE.md`.
3. Кросс-ссылки резолвятся в PDF; сборка чистая; `precheck.sh` зелёный.

## Анализ

### Цель

Связать языковые разделы с приложением «Ошибки» (0119): блок «Частые ошибки» с
кодами и ссылкой. Язык **не меняется** (Tier 3). свод закрепляет практику.

### Сопоставление раздел → коды (пользовательские, из приложения)

- **02 Лексика:** `LE-002`, `LE-004`, `LE-006`, `SY-002` (`==`).
- **03 Типы:** `SE-034` (неизв. тип), `SE-057`/`SE-058` (`q`), `SE-035` (`bit`),
  `SE-043` (enum-init), `SE-040`/`SE-061` (структуры).
- **04 Модели/состояния:** `SE-011` (нет старта), `SE-002` (ссылка на состояние),
  `SE-001` (модель), `SE-046` (недостижимо), `SE-042` (недетерминизм), `SE-012`.
- **05 Выражения/условия:** `SY-002`, `SE-003`, `SE-059` (`q`/`float`),
  `SE-026`/`SE-027` (направление порта), `SE-028`/`SE-030` (массив).
- **06 Управление:** `SIM-024` (`break`/`continue` вне цикла), `SE-036`, `SE-047`.
- **07 Функции:** `SE-004`, `SE-009`, `SE-053` (рекурсия).

Все коды присутствуют в приложении (сверено с реестром `docs/diagnostics/`).

### Форма ссылки (проверено)

Markdown-ссылка на файл приложения `../appendix-errors/index.md`. В PDF
mdbook-pandoc резолвит её в кросс-главную ссылку; «undefined reference» при ручной
проверке — артефакт **недостаточного** числа проходов xelatex (после 3 чистых
проходов `undefined = 0`; реальная сборка гоняет xelatex до стабилизации). Якорь
кода (`#se-034…`) как цель **отвергнут** (хрупкий авто-id из кириллицы/бэктиков).

### Ограничения

В разделе — только указание промаха + код + ссылка; полное раскрытие (пример +
вывод) — в приложении. Номера фич/процесс в текст не попадают.
