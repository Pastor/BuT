# Фича: Порт типа duration у целей rust, st-at и sv-mmio

- **Номер:** 0487
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** генерация
- **Связанные issue (анализ):** замер по оси «тип × позиция порта» 2026-09-02

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Порт типа `duration` переводили **пять** потребителей из восьми: эталон, `c`,
`c-hal`, `st`, `sv` и `plantuml`. `rust` отвечал `RS-016`, `st-at` — `ST-004`,
`sv-mmio` — `SV-002` («ширина не определена») — при том, что длительность в
целях есть **целое в миллисекундах** (0183) с общим носителем ширины
`duration::VALUE_BITS`. Фича снимает все три границы, а у `sv-mmio` заодно
убирает вторую копию таблицы ширин.

> Фича зарегистрирована по замеру оси «тип × позиция порта» — той же, на
> которой найдена [порт перечислимого типа у целей rust и st-at](0485-enum-port.md); далее — жизненный цикл по
> своду.

## Документирование

**Не требуется.** Язык не меняется: запись `out sig: duration;` была законна и
прежде, менялись возможности трёх целей. Раздел «Порты и оборудование» уже
описывает порт как скаляр (правка 0485), а единица на границе —
миллисекунда — описана в разделе «Механизмы времени».

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, аналитик

### Context

Замер-02 (`probe.sh -n 2`, порт с адресом):

| Потребитель | Ответ |
|---|---|
| эталон | исполняет (`sig=2s`) |
| `c`, `c-hal` | OK, `cc` принял |
| `st` | OK, `iec2c` принял, `cc` собрал |
| `sv` | OK, `verilator` + `yosys` |
| `plantuml` | OK |
| **`rust`** | `RS-016` «порт обязан быть битом или числом» |
| **`st-at`** | `ST-004` «размещаются только скаляры» |
| **`sv-mmio`** | `SV-002` «ширина которого в битах не определена» |

Тексты называют причиной **тип**, но длительность — скаляр: её ширину знает
`duration::VALUE_BITS`, и цели `c`, `st`, `sv` печатают её целым. У `sv-mmio`
причина оказалась ещё точнее: своя копия таблицы ширин (`bit_width`) отстала от
общего носителя `sv_type::scalar_width`, который `Duration` знает.

Контрольный вход: тот же порт типа `u32` переводят все восемь целей.

### Decision

1. **`rust`:** `port_class` нормализует `Duration` к
   `Integer { bits: VALUE_BITS, signed: false }` — рядом с такой же
   нормализацией перечисления (0485).
2. **`st-at`:** `size_of` отвечает буквой размера по `VALUE_BITS`.
3. **`sv-mmio`:** `bit_width` перестаёт быть копией — все скаляры, кроме
   перечисления (у него ширина от набора вариантов), считает общий
   `sv_type::scalar_width`.

### Consequences

- Порт длительности переводят все восемь целей; значение на границе —
  миллисекунды, как у прочих целей (сверка).
- Копий таблицы ширин у цели `sv` больше нет: следующий скалярный тип не
  потребует правки в двух местах.

#### Acceptance criteria

1. Порт `duration` (`in`/`out`) переводится восемью целями, инструменты
   принимают.
2. Значения совпадают с эталоном потактово (мс против нс — контракт
   `value_millis`).
3. Вывод моделей без duration-портов не изменился.
4. `./scripts/precheck.sh` зелёный.

## Разработка

### Задача — три цели

`rust_port::port_class` (нормализация `Duration`), `st_at::size_of` (буква
размера), `sv_mmio::bit_width` (переход на общий носитель ширин).

Третья правка — не «заодно»: `SV-002` приходил именно от копии, и оставь мы
её, следующий скалярный тип повторил бы историю.

## Итог (что сделано)

- Порт типа `duration` переводят все восемь целей: у `rust` он ложится на метод
  HAL-трейта, у `st-at` — на локацию `AT %QD`, у `sv-mmio` — на срез регистра.
- У цели `sv` больше нет второй таблицы ширин: `bit_width` регистрового файла
  спрашивает общий `sv_type::scalar_width`, и `SV-002` «ширина не определена»
  остаётся только там, где ширины действительно нет.
- Сверка `conformance_duration_port_tests` доказывает единицу границы:
  эталон меряет наносекундами, цель — миллисекундами, и пересчёт проверяется
  значениями, а не чтением кода.
