# Фича: Цели `rust` и `st` — пустая ветвь `match`

- **Номер:** 0509
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `rust`: пустая ветвь `else` в порождённом коде» (заведён при закрытии [цель `rust` — операнды расширяемой арифметики: приведение по нужде и обёртка](0507-rust-widen-operands-wrap.md))

## Стадии жизненного цикла

## Краткое описание

Ветвь `match` без операторов (`_ => {}` — «прочие значения ничего не делают»)
не печатается целями `rust` и `st`. Прежде она давала `} else { }` и
`ELSE`/`THEN` без тела: `clippy` под `-D warnings` отвечает «this `else` branch
is empty», `iec2c` — «no statement defined after 'ELSE'», и оба отказа приходили
при **нулевом** коде возврата `taktc`. Пустого оператора в IEC 61131-3 нет
вовсе, поэтому ветвь **опускается**, а не наполняется заглушкой.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

## Документирование

**Не требуется.** Язык не меняется: пустая ветвь принималась и исполнялась как
прежде, речь о форме порождённого кода. Диагностик не заводится.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh`, прогон инструментов проверок):

| Потребитель | Пустая `_`-ветвь | Пустая ветвь образца |
|---|---|---|
| эталон, `c`, `c-hal`, `sv`, `sv-mmio` | принимают | принимают |
| `rust` | `clippy`: «this `else` branch is empty» | принимает |
| `st`, `st-at` | `iec2c`: «no statement defined after 'ELSE'» | `iec2c`: то же после `'THEN'` |

Класс найден прогоном инструментов по примерам `book/`: раздел
«Процессор» пишет `_ => {}` там, где остальные опкоды обрабатывать не нужно.

Контроль, снятый тем же прогоном: пустая ветвь `else` у **оператора** `if` уже
опускается (0473, 0474) — правило существовало, но `match` его не знал.

### Decision Drivers

- Приём известен и применён дважды (0473 у `st`, 0474 у `rust`): тело печатается
  в буфер, пустой текст означает «печатать нечего».
- Пустого оператора в IEC нет: `;` MatIEC отвергает — заглушкой не обойтись.

### Considered Options

1. **Опускать пустую ветвь, контроля дубль образцов** (принято).
2. **Печатать заглушку-комментарий.** Отвергнуто: у `st` комментарий не
   оператор — `iec2c` отвергает тот же вход.
3. **Отказ цели на пустую ветвь.** Отвергнуто: запись законна, эталон и четыре
   цели её принимают, а автор пишет её осмысленно.
4. **Опускать безусловно, без проверки дубля.** Отвергнуто: `match` берёт
   первое совпадение, и при `1 => {} 1 => { … }` опущение поменяло бы автомат —
   валидный вывод и другое поведение, то есть худший класс из возможных.

### Decision

Печатники `match` целей `rust` и `st` печатают тело ветви в буфер и опускают
ветвь с пустым текстом. Опущение разрешено, только если образец ветви не
повторяется ниже — это стережёт общий носитель
`generator::match_arms::pattern_repeats_below`.

### Consequences

- `_ => {}` даёт вывод, принимаемый `clippy -D warnings` и `iec2c`.
- Цель `sv` не затронута: её `default` печатается всегда и намеренно — без него
  синтезатор выводит защёлку (0322).
- Цель `c` не затронута: пустая ветвь в C законна.

#### Acceptance criteria

1. Проба: восемь целей переводят, инструменты проверок принимают.
2. Контроль: непустая ветвь печатается как прежде.
3. Контроль: при дубле образца пустая ветвь сохраняется.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

`match` печатается цепочкой `if`/`else if` (у `rust`) и `IF`/`ELSIF` (у `st`) —
образцы Takt суть выражения, и `match` целевого языка связал бы имя вместо
сравнения. Обе цепочки печатали тело ветви прямо в поток, поэтому пустоту не
видели.

### Замер

Таблица — в разделе «Архитектура (ADR) → Context». Замер шире кандидата вдвое:
кандидат называл `rust` и пустую `_`-ветвь, прогон показал ещё цель `st` (обе её
формы) и пустую ветвь образца.

Соседние классы, в объём **не** входящие (кандидаты):

- дублирующиеся образцы `match` — `cc`: «duplicate case value», `clippy`: «these
  `if` branches have the same condition», `st`: пустой `THEN`;
- `clippy::collapsible_if` на примерах раздела «Процессор» — виден после снятия
  пустой ветви;
- `st`: «invalid variable(s) declaration» и «invalid test expression» там же.

### Зависимости фичи

Зависимостей нет.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | `rust`: пустая `_`-ветвь не печатается |
| Т2 | `st`: пустая `_`-ветвь не даёт `ELSE` |
| Т3 | `st`: пустая ветвь образца опускается вместе со своим условием |
| Т4 | Непустая ветвь печатается как прежде |
| Т5 | При дубле образца пустая ветвь сохраняется |
| Т6 | `c` и `sv` не затронуты |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh`, набор
`takt-lang/tests/targets/empty_match_arm_tests.rs` (7 тестов, включая прогон
`clippy-driver` и `iec2c`), `precheck.sh`. Значения контролирует существующая
матрица форм `match` (0478): она сверяет выбор ветви, и опущение непустой ветви
поймала бы она.

### Редакторский слой

**Не требуется:** лексика, синтаксис и диагностики не затронуты.

### Особенности по обратной функциональности

Обратная совместимость полная: меняется вывод, который инструменты целей
отвергали.

### Риски и зависимости

- **Риск:** опущение ветви изменит автомат при дублирующихся образцах. Снят
  признаком `pattern_repeats_below` и контрольным тестом.

## Разработка

### Задача: общий носитель признака дубля

`takt-lang/src/generator/match_arms.rs` — `pattern_repeats_below(arms, index)`
сравнивает узлы образцов (форма записи до генерации не доживает — значение
свёрнуто, 0192). Три модульных теста: различные образцы, дубль ниже, дубль выше.

### Задача: печать у целей

- `rust_stmt.rs`, ветвь `Match`: тело `_`-ветки печатается в буфер; пустое —
  цепочка просто закрывается.
- `st_stmt.rs`, `print_match`: в буфер печатается тело **каждой** ветви; пустая
  опускается (с проверкой дубля), пустая `_` не даёт `ELSE`.

### Задача: контроля

`takt-lang/tests/targets/empty_match_arm_tests.rs` — формы у обеих целей,
контроли (непустая ветвь, дубль, `c`/`sv`) и прогон инструментов проверок.

## Тест-план

| Проверка | Ожидание |
|---|---|
| `_ => {}` у `rust` | `} else {` в выводе нет |
| `_ => {}` у `st` | `ELSE` нет, `END_IF;` на месте |
| `1 => {}` у `st` | условия `op = 1` нет, `op = 2` осталось |
| непустая `_` | `else` / `ELSE` печатаются |
| дубль образца | обе ветви на месте |
| `c`, `sv` | `default:` на месте |
| `clippy -D warnings`, `iec2c` | принимают оба входа |
| примеры `book/` раздела «Процессор» | `needless_else` снят |

## Отчёт о тестировании

### Резюме

`./scripts/precheck.sh` — зелёный. Проба: восемь целей переводят, инструменты
принимают. На примерах `book/` отказ `needless_else` снят; `pipeline` теперь
принимается `clippy` целиком, у трёх остальных вскрылся соседний класс
(`collapsible_if`) — заведён кандидатом.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка:

| Мутация | Ответ набора |
|---|---|
| опускать пустую ветвь всегда (без проверки дубля) | `duplicate_pattern_keeps_empty_arm` |
| печатать пустую ветвь как прежде | T1, T2, T3 и прогон инструментов |

### Найденные дефекты

Дефектов правки нет. Соседние классы перечислены в разделе «Анализ → Замер».

### Выводы и дальнейшие шаги

Правило «пустого не печатать», жившее у оператора `if` (0473, 0474), получил и
`match`. Кандидат, породивший фичу, снят; вскрытые соседние классы заведены.

## Итог (что сделано)

Пустая ветвь `match` не печатается целями `rust` и `st`: прежде она давала
`} else { }` и `ELSE` без тела — отказ `clippy -D warnings` и `iec2c` при нулевом
коде возврата `taktc`. Опущение контролирует общий признак «образец не повторяется
ниже»: при дубле ветвь остаётся, потому что `match` берёт первое совпадение и
её опущение поменяло бы автомат молча.
