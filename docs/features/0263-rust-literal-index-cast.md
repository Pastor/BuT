## Краткое описание

**Цель `rust` приводит к `usize` даже литеральный индекс.** Замер
[запись бита x.N := v: цели rust и st печатают чтение, эталон отказывает](0250-bit-write-in-targets.md) (2026-08-18): `arr[1] := 1;`
печатается `self.arr[1 as usize] = 1;`, и настоящий `clippy -D warnings`
отвечает `unnecessary_cast` — то есть порождённый модуль не проходит тот же
проверка, что стоит в `precheck.sh`. Записи разряда дефект не касается: он даёт
ту же ошибку без неё. Проверка слеп потому, что в корпусе индексируют
**переменной** (`arr[i]`), где приведение необходимо. Кандидат: печатать
приведение по нужде — литерал в `usize` не приводить.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

### Context

Цель `rust` печатала индексацию массива с приведением **всегда**:
`self.arr[1 as usize]`. Для индекса-переменной приведение необходимо (типы
Takt — `u8`…`i64`, а Rust требует `usize`), для литерала избыточно: он и так
выводится как `usize` по контексту.

**Замер-19** (`clippy-driver --edition 2021 --crate-type=lib -D warnings`
по порождённому модулю — те же флаги, что в проверке `precheck.sh`):

| Строка исходника | Порождено | Ответ `clippy` |
|---|---|---|
| `arr[1] := 7;` | `self.arr[1 as usize] = 7;` | **error:** casting integer literal to `usize` is unnecessary |
| `seen := arr[1];` | `self.seen = self.arr[1 as usize];` | **error:** то же |
| `arr[i] := 9;` (контроль) | `self.arr[self.i as usize] = 9;` | замечаний нет |

Под `-D warnings` это **отказ**: порождённый модуль не проходит тот же проверка,
который проект применяет к своему выводу. Политика цели названа в
[генератор генерации в Rust](0050-rust-backend.md) — «не эмитить недостижимое и не
ссориться с линтами».

**Проверка этого не видит по устройству:** он гоняет **только корпус**, а там
индексируют переменной (`arr[i]`) — литеральных индексов в `examples/` нет ни
одного. Тот же слепой угол дал дефекты и 0148-02.

**Отрицательный литерал до цели не доходит:** `arr[-1]` отсекает `SE-028` в
семантике. Иначе `self.arr[-1]` не скомпилировалось бы вовсе.

### Decision Drivers

1. **Вывод обязан проходить проверка проекта.** Цель, чей вывод отвергает
   собственный линтер проекта, не выполняет контракт.
2. **Приведение переменной снимать нельзя** — без него не компилируется весь
   корпус.
3. **Правило одно, печатников два** (выражения и условия): второе знание о нём
   разъедется.

### Considered Options

#### Option A. Оставить как есть

**Cons:** порождённый модуль не проходит `clippy -D warnings`; автор узнаёт об
этом от чужого инструмента.

#### Option B. Снять приведение везде

**Cons:** ломает индекс-переменную, то есть весь корпус. Отвергнуто сразу.

#### Option C. Печатать приведение по нужде, одной функцией на цель

**Pros:** вывод проходит проверка; корпус не затронут (там индекс — переменная);
правило живёт в одном месте.

**Cons:** различие «литерал / не литерал» приходится знать печатнику — но оно
уже есть в узле (`Number`).

### Decision

Принимается **Option C**. Функция `rust_expr::subscript(base, index,
index_is_literal)` — единственный носитель правила; её зовут оба печатника
(`rust_expr` для выражений, `rust_cond` для условий).

### Consequences

#### Положительные

- Порождённый модуль с литеральным индексом принимается `clippy -D warnings`.
- Вывод стал короче и читаемее там, где приведение было шумом.

#### Отрицательные / Action items

- Форма вывода цели `rust` меняется, но **только** для литерального индекса;
  корпус его не содержит, снимки не двигаются.
- Правило распознаёт литерал по узлу `Number`. Свёрнутая константа
  (`const K := 1; arr[K]`) до печати доезжает литералом (0192), а имя, не
  свёрнутое до числа, приведение сохранит — это безопасная сторона.

#### Acceptance criteria

1. `arr[1]` печатается без `as usize`, `arr[i]` — с ним (A1).
2. Печатник условий подчиняется тому же правилу (A2).
3. Порождённый модуль принимается `clippy -D warnings` (A3).
4. `./scripts/precheck.sh` зелён, снимки `examples/generated/` не изменились (A4).

## Анализ

### Цель и контекст

Цель `rust` печатала `as usize` при **каждой** индексации. На литеральном
индексе это `clippy::unnecessary_cast`, то есть отказ под `-D warnings` — теми
же флагами, что стоят в проверке предкоммита. Фича печатает приведение по нужде,
не трогая индекс-переменную.

### Замер (снят заново)

Прогон `clippy-driver --edition 2021 --crate-type=lib -D warnings` по
порождённому модулю, 2026-08-19:

| Исходник | Порождено (до) | `clippy` |
|---|---|---|
| `arr[1] := 7;` | `self.arr[1 as usize] = 7;` | **error** `unnecessary_cast` |
| `seen := arr[1];` | `self.seen = self.arr[1 as usize];` | **error** `unnecessary_cast` |
| `arr[i] := 9;` **(контроль)** | `self.arr[self.i as usize] = 9;` | принято |

Контроль работает: приведение переменной необходимо и замечаний не вызывает —
значит отвергается не индексация вообще, а именно лишнее приведение.

Замер кандидата (2026-08-18) воспроизведён полностью; формулировка не
устарела.

## Разработка

### Задача

#### Что было

Два печатника цели `rust` — выражений (`rust_expr.rs`) и условий
(`rust_cond.rs`) — печатали индексацию **каждый своей копией** одной строки
`"{}[{} as usize]"`. На литеральном индексе это `clippy::unnecessary_cast`,
то есть отказ под `-D warnings` — флагами проверки предкоммита.

#### Что сделано

Правило вынесено в **одну** функцию `rust_expr::subscript(base, index,
index_is_literal)`; оба печатника зовут её. Приведение печатается, только когда
индекс не литерал.

**Носитель обязан быть один:** копия правила в двух печатниках разъехалась бы
при первой же правке. Именно из-за двух копий дефект и
пришлось бы чинить дважды.

**Отрицательный литерал сюда не доходит** — `SE-028` отсекает его в
семантике; проверено прогоном, а не рассуждением.

#### Проверки

```sh
cargo test --test targets rust_index_cast   # 3 теста, включая настоящий clippy-driver
cargo test --all-features                   # 3245 тестов
./scripts/precheck.sh                       # полный гейт
```

Мутация «снять приведение и у переменной» валит T1 (обе формы проверяются одним
тестом) и проверка цели `rust` на корпусе.

## Итог (что сделано)

**Приведение индекса к `usize` печатается по нужде.** Литеральный индекс шёл в
вывод как `self.arr[1 as usize]`, и настоящий `clippy -D warnings` — теми же
флагами, что в проверке предкоммита, — отвечал **ошибкой** `unnecessary_cast`: то
есть порождённый модуль не проходил проверка самого проекта. Замер воспроизведён
2026-08-19 вместе с контролем (`arr[i]` приведение сохраняет и замечаний не
вызывает).

**Сделано:** правило вынесено в **одну** функцию `rust_expr::subscript`, её
зовут оба печатника индекса — выражений и условий. Прежде у каждого была своя
копия строки, и правило разъехалось бы при первой правке.

**Контроль** — `takt-lang/tests/targets/rust_index_cast_tests.rs`: обе формы в
одном тесте (мутация «снять приведение везде» валит его) плюс прогон настоящего
`clippy-driver -D warnings`. Проверка цели этого класса не видел: он гоняет
только корпус, где индексируют **переменной**.

**Версия языка не поднята** (форма вывода цели, не язык); крейт `takt-lang`:
`0.46.0` → `0.46.1`.

Детали — [отчёт](0263-rust-literal-index-cast.md#отчёт-о-тестировании), решение —
[ADR](0263-rust-literal-index-cast.md#архитектура-adr).
