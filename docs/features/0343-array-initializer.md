# Фича: Инициализатор массива — потеря у `st`, невалидный вывод у `c` и `rust`

- **Номер:** 0343
- **Статус:** ГОТОВО
- **Зависит от:** 0340, 0293, 0210 (закрыты; проставлено 2026-08-20)
- **Связанные issue (анализ):** найдено пробой «массив структур»

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32): «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».
Отдельным артефактом остаются только исправления —

## Краткое описание

Цель `st` теряла инициализатор **любого** массива молча — прогон дал `0` против
`3` у эталона. Массив структур вдобавок не переводили `c` (форма, которой в C
нет) и `rust` (`[[1, 2], …]` вместо литералов структуры).

## Документирование (правило 24)

**Не требуется** — подтверждено: правится представление у трёх целей.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0343-array-initializer.md](0343-array-initializer.md)

### Контекст

Замер-20, два входа.

**Массив скаляров** (`var a: [u8;2] := {1, 2};`): цель `st` объявляла
`a : ARRAY [0..1] OF USINT;` — **без** `:=`. Прогон порождённого ST через
`iec2c` + `cc` дал `o = 0` против `3` у эталона: расходятся **значения**, при
нулевом коде возврата `taktc`.

**Массив структур** (`var cells: [Cell;2] := {{1, 2}, {3, 4}};`):

| Потребитель | Ответ |
|---|---|
| эталон, `sv`, `sv-mmio` | верно |
| **`c`, `c-hal`** | `model->cells[0] = {1, 2};` — `cc`: «expected expression» |
| **`rust`** | `[[1, 2], [3, 4]]` — `E0308` ×2 |
| **`st`, `st-at`** | инициализатор потерян молча |

### Решение

- **`st`, массив скаляров:** печатается `:= [1, 2]` — форма выбрана **пробой**
  `iec2c` (принимается).
- **`st`, массив структур:** агрегат такого типа `iec2c` не принимает ни в
  одном из трёх проверенных видов (`[(1, 2), …]`, `[(v := 1, …), …]`,
  `((v := 1, …), …)`), поэтому значения кладутся операторами **первого скана** —
  до входа в стартовое состояние, то есть до любого тела, которое их прочитает.
- **`c`:** элементы-структуры кладутся по полям (место выбирает носитель
  `generator::aggregate`).
- **`rust`:** элементы печатаются литералом структуры.

### Границы

- **Агрегат массива в аргументе параметра модели цель `st` по-прежнему
  отвергает** (`ST-017`). В объявлении переменной форма законна, а в
  инициализаторе экземпляра `FUNCTION_BLOCK` тот же массив даёт «Initialization
  element identifier … incompatible datatype». Первая редакция правки сняла
  отказ вместе с потерей и породила невалидный файл — поймал это тест фичи, «пришпиливающий» границы целей.

### Отвергнутые варианты

1. **Отказ `ST-011` на массив с инициализатором.** Форма выразима — отказ был
   бы регрессом.
2. **Инициализация массива структур одной формой.** Три пробы `iec2c` её не
   нашли.

### Последствия

- Вывод корпуса не изменился.
- Тест фичи (`shared_array_uses_a_named_type_on_both_sides`) обновлён:
  у переменной корня теперь печатается ещё и инициализатор.

## Анализ

### Цель и контекст

Найдено пробой «массив структур»; проверка простого случая показала, что
теряется **любой** инициализатор массива у цели `st` — то есть класс шире
исходного наблюдения.

### Зависимости фичи (правило 17/19)

- **Зависит от:** 0340 (носитель мест агрегата), 0293 (структуры), 0210
  (именованный тип массива). Закрыты.
- **Влияние на порядок разработки:** нет.

### Требования и проверяемые условия

- **R1.** `st`: инициализатор массива скаляров печатается, `iec2c` принимает.
- **R2.** `st`: массив структур кладётся операторами первого скана.
- **R3.** Значения совпадают с эталоном (сверка через `iec2c` + `cc`).
- **R4.** `c` и `rust`: массив структур собирается их инструментами.
- **R5.** Агрегат в аргументе параметра у `st` по-прежнему `ST-017`.
- **R6.** Вывод корпуса не изменился.

### Разбор

#### Почему первый скан, а не объявление

Три формы агрегата массива структур `iec2c` отверг. Первый скан — то место,
где значения уже можно присвоить и где они гарантированно окажутся раньше
любого чтения (вход в стартовое состояние печатается ниже).

#### Чему научил тест

Он «пришпиливает» границы целей и **покраснел**, когда правка сняла отказ
`ST-017`. Проверка показала: снятый отказ дал невалидный вывод. То есть тест,
фиксирующий границу, сработал ровно как задумано — как сигнал «граница
сдвинулась, проверь, в ту ли сторону».

### Риски

- **Первый скан у модели без стартового состояния.** Такой вход отвергает
  `SE-011`/`SE-106` раньше печати.

## Итог (что сделано)

**Инициализатор массива доезжает до всех целей.**

- **`st`, массив скаляров:** форма `:= [1, 2]` — выбрана **пробой** `iec2c`.
  Прежде инициализатор терялся, и расходились **значения**, а не тексты.
- **`st`, массив структур:** агрегат такого типа `iec2c` не принимает ни в одном
  из **трёх** проверенных видов — значения кладутся операторами **первого
  скана**, до входа в стартовое состояние.
- **`c`:** элементы-структуры кладутся по полям (носитель мест — 0340).
  **`rust`:** элементы печатаются литералом структуры.
- **Граница `ST-017` сохранена:** агрегат массива в аргументе **параметра**
  модели цель по-прежнему отвергает — в объявлении переменной форма законна, а
  в инициализаторе экземпляра `FUNCTION_BLOCK` `iec2c` её не принимает. Первая
  редакция правки сняла отказ вместе с потерей и породила невалидный файл;
  **поймал это тест фичи**, пришпиливающий границы целей, — то есть такой
  тест сработал ровно как задумано.
- **Класс шире исходного наблюдения:** проба ставилась под массив структур, а
  проверка простого случая показала, что теряется **любой** инициализатор
  массива.
