# Фича: Элемент агрегата печатается по типу элемента

- **Номер:** 0368
- **Статус:** ГОТОВО
- **Зависит от:** нет (0061, 0096, 0300, 0343, 0366 закрыты)
- **Связанные issue (анализ):** класс найден пробами 2026-08-21 (инструмент
  [проба прогоняет инструменты целей](0362-probe-target-tools.md))

## Краткое описание

Замер-21 — две записи, у которых **скалярный** аналог работает у всех
девяти потребителей:

| Вход | Ответ |
|---|---|
| `var gains: [q(8, 8); 2] := {1.5, 2.5};` | `c`/`c-hal`: `cc -Werror` — «implicit conversion from 'double' to 'int16_t' changes value from 1.5 to 1»; `rust`: `E0308`; `sv`: `SV-002` |
| `var modes: [Mode; 2] := {Idle, Work};` плюс `modes[0] := Work;` | `rust`: `E0308` (`[0, 1]` в поле `[Mode; 2]`); `sv`: `%Error-ENUMVALUE` |

Контроль: `var gain: q(8, 8) := 1.5;` и `var mode: Mode := Idle;` переводят и
исполняют **все** потребители — то есть дело не в типе, а в том, что элемент
агрегата свой тип теряет.

Корней три, все — «тип элемента известен, но не применён»:

1. **Понижение q-литерала** (`lower_folded_fixed`, семантика) смотрело только
   на скалярный тип.
2. **Печать агрегата у цели `rust`** знала лишь один тип элемента —
   структуру.
3. **Тип приёмника у цели `sv`** при записи в элемент массива возвращался
   `None`.

## Документирование

**Не требуется** — язык не меняется: записи законны и исполняются эталоном;
правится представление у целей и место понижения литерала.

### Context

Тип элемента агрегата известен из объявления, но применялся не везде:
понижение q-литерала (0096/0300) смотрело на скалярный тип, печать массива у
цели `rust` знала только структуру, а тип приёмника у `sv` при записи в
элемент отсутствовал.

Класс невидим проверкам: в `examples/` нет ни массивов `q`, ни массивов
перечислений. Нашёлся первым же прогоном раздела «инструменты целей».

### Decision Drivers

1. **Скаляр и элемент обязаны отвечать одинаково.** Разное поведение одной
   записи в зависимости от «в массиве или нет».
2. **Понижение q — семантика, а не печать.** Один носитель (0061/0096), иначе
   цели разойдутся в округлении.
3. **Признак — тип элемента, а не частный случай.** Ветвь «массив структур»
   (0343) была именно частным случаем.

### Considered Options

#### Option A. Понижать q в свёртке (`lower_folded_fixed`), печать вести по типу элемента

**Pros:**
- Понижение живёт там же, где для скаляра, и результат доезжает до **всех**
  потребителей одинаково.
- Печать у `rust` перестаёт знать частные случаи: элемент печатается
  `coerce_to` по своему типу.

**Cons:**
- У `sv` требуется тип базы индексации — он уже есть (`sv_array::array_type_expr`).

#### Option B. Понижать q при выводе типов (`lower_fixed_var`)

**Pros:** ближе к скалярному случаю.

**Cons:** **не работает** — свёртка инициализаторов (0192) идёт позже и
перезаписывает результат сырым АСД. Проверено прогоном: понижение
выполнялось и терялось.

#### Option C. Приводить значение в каждой цели по отдельности

**Pros:** правка локальна.

**Cons:** три копии правила округления q — ровно то, чего избегает 0061.

### Decision

Принимается **Option A**:

1. `lower_folded_fixed` понижает агрегат **поэлементно** по типу элемента,
   рекурсивно (массив массивов q).
2. `rust_coerce::coerce_to` печатает элементы массива через себя же — для
   **любого** типа элемента; бит-вектор `[bit;N≤64]` исключён (упакованный
   скаляр).
3. `sv_stmt::target_type` для индексации отдаёт **тип элемента** (тип базы
   даёт `sv_array::array_type_expr`).

### Consequences

#### Положительные

- Массив `q` и массив перечислений переводят и **собирают** все восемь целей.
- Печать у `rust` перестала знать частный случай «массив структур».

#### Отрицательные / Action items

- **Массив в параметре функции у цели `sv`** остаётся несинтезируемым —
  соседний класс, найденный тем же прогоном; вынесен кандидатом.
- Понижение агрегата **не покрывает структуры**: их поля живут в `ModelNode`,
  которого слой свёртки не видит. Граница названа; вход
  `struct G { k: q(8,8) }` вынесен кандидатом.

#### Acceptance criteria

1. Массив `q` и массив перечислений принимают инструменты всех целей.
2. Потактовая сверка с целью `c`: `1.5` в `q(8, 8)` даёт **384**, а не 1;
   запись варианта в элемент даёт его значение.
3. Мутации («не понижать агрегат», «у `sv` не брать тип элемента») роняют
   тест и пробу соответственно.
4. Предкоммит зелёный; вывод корпуса не изменился.

## Анализ

### Цель и контекст

Сделать так, чтобы элемент агрегата отвечал так же, как скаляр того же типа.
Замер и контроль — в карточке.

### Зависимости фичи

- **Зависит от:** нет. 0061/0096 (q-литерал), 0300 (понижение свёрнутого),
  0343 (массив структур у `rust`), 0365 (тип базы у `sv`), 0366 (раскрытие
  агрегата) закрыты.
- **Влияние на порядок разработки:** порождает двух кандидатов — массив в
  параметре функции у `sv` и поле `q` в структуре.

### Требования и проверяемые условия

- **R1. Понижение q — поэлементно и рекурсивно** по типу элемента.
- **R2. Место понижения — свёртка.** При выводе типов результат
  перезаписывается сырым АСД (проверено прогоном).
- **R3. Печать массива у `rust` — по типу элемента**, а не по частному случаю
  «структура».
- **R4. Бит-вектор исключён**.
- **R5. Тип приёмника у `sv` при записи в элемент — тип элемента.**
- **R6. Значения совпадают с эталоном.** `1.5` в `q(8, 8)` — это 384.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Инструменты целей принимают вывод | `scripts/probe.sh` на `qarr.takt`, `enumarr.takt` |
| A2 | Значения совпадают | `conformance_c_arrays_tests::aggregate_element_types_match_generated_c` |
| A3 | Мутации ловятся | «не понижать агрегат», «`sv` без типа элемента» |
| A4 | Контроль скаляра | `qscalar.takt`, `enumscalar.takt` — ноль тревог |
| A5 | Вывод корпуса не изменился | предкоммит |

### Особенности по обратной функциональности

- **Язык не меняется**; свод: не применимо.
- **Ветвь 0343 обобщена, а не снята**: массив структур печатается тем же
  правилом, что и любой другой массив.

### Риски и зависимости

- **Структуры вне понижения q**: слой свёртки не видит полей (`ModelNode`).
  Граница названа и вынесена кандидатом.
- **`git checkout` рабочего файла посреди мутаций стирает правку** — мутации
  проверять временными копиями (урок повторился дважды за сессию).

## Разработка

### Задача

#### Что было

Понижение q-литерала смотрело на скалярный тип, печать массива у цели `rust`
знала только элемент-структуру, а тип приёмника у `sv` при записи в элемент
массива был `None`.

#### Что сделано

**`takt-lang/src/semantic/declaration/mod.rs`** — `lower_folded_fixed`
понижает агрегат поэлементно по типу элемента (рекурсивно).

**`takt-lang/src/generator/rust/rust_coerce.rs`** — ветвь массива обобщена:
элементы печатаются `coerce_to` по типу элемента для **любого** типа;
бит-вектор `[bit;N≤64]` исключён.

**`takt-lang/src/generator/sv/sv_stmt.rs`** — `target_type` для индексации
отдаёт тип элемента (тип базы даёт `sv_array::array_type_expr`).

**Сверка**: `aggregate_element_types_match_generated_c` — значения `whole`,
`code` и **представление** `gains[0] = 384`.

**Первая правка была не в том месте.** Понижение добавлялось в
`lower_fixed_var` (вывод типов) и **работало**, но результат перезаписывался
свёрткой инициализаторов: она берёт сырой АСД и подменяет значение (защита
`is_literal` агрегат не покрывает). Показал это отладочный прогон, а не
чтение.

#### Проверки

```sh
cargo test --test conformance aggregate_element_types
cargo test --test conformance   # 166
cargo test --test targets       # 391
cargo test -p takt-lang --lib   # 1106
scripts/probe.sh -n 2 qarr.takt; scripts/probe.sh -n 2 enumarr.takt
./scripts/precheck.sh
```

Мутации: «не понижать агрегат» — сверка красная («порождённый C не
компилируется»); «`sv` не берёт тип элемента» — проба даёт `verilator ОТВЕРГ`.

- **Правка сначала была не в том месте.** Понижение в `lower_fixed_var`

  что слой свёртки не видит полей структуры.
- Исправлений (`docs/fixes/`) не потребовалось.

- Элемент агрегата отвечает так же, как скаляр того же типа: понижение
  q-литерала идёт поэлементно, печать массива у `rust` — по типу элемента для
