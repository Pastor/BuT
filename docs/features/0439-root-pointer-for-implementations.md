# Фича: Указатель на корень нужен и моделям-реализациям состояния

- **Номер:** 0439
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2 (невалидный вывод при нулевом коде возврата: `cc` отвергает
  порождённый файл, а `taktc` рапортует об успехе)
- **Класс:** генерация
- **Связанные issue (анализ):** класс найден тестом [табличная форма для состояния-цепочки A + B](0438-table-form-chain.md); воспроизводится **формой по умолчанию**, то
  есть существовал до табличной формы

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32): «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог». Раздел

## Краткое описание

Указатель на корень (`main`) печатается функциям под-модели **по нужде** (фичи и 0419), и признак нужды считался по объявлениям: блоки, условия рёбер,
функции и **вложенные** модели. Модели, которыми **реализовано состояние**
(`= M`, `A | B`, `A + B`), в признак не входили — а их тикает та же функция и
передаёт им `main`. Модель-обёртка без собственных обращений к корню получала
сигнатуру без `main`, тогда как тело звало `Child_tick(&…, main)`: `cc` отвечал
«use of undeclared identifier 'main'» при **нулевом** коде возврата `taktc`.

> Фича зарегистрирована по находке при работе над 0438; далее проходит жизненный
> цикл по правилу 17.

## Документирование (правило 24)

**Не требуется:** язык не затронут, наблюдаемое поведение — тоже. Предмет —
сигнатура функции в порождённом C, то есть деталь реализации цели, которой в

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор, аналитик

### Context

Правило признака  сформулировано так: «указатель нужен функции, если
её тело обращается к состоянию модели **либо** зовёт функцию, которой он нужен».
Второе условие в коде было реализовано только для **вложенных** моделей
(`ModelNode::models`), а реализация состояния ссылается на модель, объявленную
где угодно в файле, — она в `models` не лежит.

Ошибка признака здесь **громкая** (так и записано в шапке `c_needs`): сказав
«не нужен» там, где тело упоминает `main`, получаем отказ `cc`. Громкой она
оказалась лишь для того, кто соберёт вывод: `taktc` возвращает ноль, а проверка
корпуса класса не покрывает — в корпусе носитель композиции либо сам корень,
либо имеет собственные порты.

### Considered Options

- **A. Печатать указатель всегда.** Отвергнут: это откат фич и 0419, 30
  заглушек `(void)main;` вернулись бы в корпус.
- **B. Считать признак по напечатанному тексту.** Отвергнут: сигнатура
  печатается раньше тела и в трёх местах (прототип, определение, вызов) — та же
  причина, по которой признак 0396 считается по семантике.
- **C. Дополнить обход детьми по вызову — моделями реализаций.** Принят: это
  ровно то же правило, что уже действует для вложенных моделей.

### Decision

`c_needs::implementation_children` собирает модели из дерева `Extend` состояния
(`Model`, `Parentless`, `Concatenation`, `Parallel`), и обе ветви признака
(`_tick` и `_init`) рекурсируют в них наравне с `models`. Разбор `Extend`
**исчерпывающий**: пропущенная форма означала бы «ребёнка не видно», то есть тот
самый отказ `cc` при нулевом коде возврата.

### Consequences

Вывод корпуса не изменился (там признак и так отвечал «нужен» по другим
причинам) — изменился вывод входов, которые прежде не собирались вовсе.

#### Acceptance criteria

- A1. Три формы реализации (`= M`, `A | B`, `A + B`) моделью без собственных
  обращений к корню дают вывод, который собирается `cc` флагами проверки.
- A2. Вывод корпуса не изменился (проверка детерминизма и снимки `book/`).

## Анализ

### Цель и контекст

Класс — «признак нужды не видит потребителя». Проверяемое условие: вывод
собирается чужим инструментом; код возврата `taktc` вердиктом не является
(правило 30).

### Замер (правило 30, 2026-08-31)

Модель-обёртка без собственных портов, реализованная моделью с портом:

| Форма реализации | `taktc` | `cc -Wall -Wextra -Werror` |
|---|---|---|
| `= M` (одиночная) | код 0 | **отказ**: use of undeclared identifier 'main' |
| `A \| B` (параллель) | код 0 | **отказ** |
| `A + B` (цепочка) | код 0 | **отказ** |

После правки все три собираются. Замер снят **формой по умолчанию** — класс к
табличной форме отношения не имеет.

### Зависимости фичи (правило 17/19)

Нет; правит признак фич.

### Требования и проверяемые условия

- R1. Признак `_tick` видит модели реализаций.
- R2. Признак `_init` видит их тоже (родитель зовёт `Child_init(…, main)` тем же
  правилом).
- R3. Разбор дерева `Extend` исчерпывающий.

### Критерии приёмки и способ проверки

A1, A2 — набор `root_pointer_implementations_tests` и полный `precheck.sh`
(проверки целей `c`/`c-hal`, детерминизм, снимки документа).

### Редакторский слой (правило 29)

Не затронут.

### Особенности по обратной функциональности

Ломающих изменений нет: сигнатура меняется только там, где вывод прежде не
собирался.

### Риски и зависимости

Риск обратной ошибки («нужен» там, где не нужен) — лишняя заглушка
`(void)main;`, то есть косметика; вывод корпуса при этом контролирует проверка
детерминизма и снимки документа.

### Выводы и дальнейшие шаги

Готово. Соседний вопрос, вынесенный кандидатом: признак `c_needs` не имеет

выборку.

## Итог (что сделано)

Признак нужды в указателе на корень  дополнен детьми по вызову —
моделями, которыми **реализовано состояние**. Прежде обёртка без собственных
обращений к корню порождала C, который `cc` отвергает («use of undeclared
identifier 'main'») при нулевом коде возврата `taktc`; замер показал класс на
всех трёх формах реализации (`= M`, `A | B`, `A + B`), и он воспроизводился
формой по умолчанию, то есть жил до табличной формы. Вывод корпуса не изменился.
Подробности — в разделах «Архитектура (ADR)» и «Анализ».
