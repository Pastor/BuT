# Фича: Присваивание агрегата — место записи выбирает общий носитель

- **Номер:** 0340
- **Статус:** ГОТОВО
- **Зависит от:** 0330, 0293, 0320 (закрыты; проставлено 2026-08-20)
- **Связанные issue (анализ):** найдено пробой «функция возвращает структуру»

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**: «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».

## Краткое описание

`body := {3, 4};` при `body: Point` не переводила **ни одна** цель, кроме
`rust`: `c` печатала форму, которой в C нет вовсе, `st` и `sv` адресовали
структуру как **массив**. Всё — при нулевом коде возврата `taktc`.

## Документирование

**Не требуется** — подтверждено: правится представление у трёх целей.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0340-aggregate-assign-place.md](0340-aggregate-assign-place.md)

### Контекст

Замер-20 на `body := {3, 4};` при `body: Point`:

| Потребитель | Ответ |
|---|---|
| эталон, `rust` | верно |
| **`c`, `c-hal`** | `model->body = {3, 4};` — `cc`: «expected expression» |
| **`st`, `st-at`** | `body[0] := 3;` — структура индексируется, `iec2c` отвергает (5 ошибок) |
| **`sv`, `sv-mmio`** | то же, verilator отвергает (3 сообщения) |

Всё — при **нулевом** коде возврата `taktc`.

Фича чинила тот же класс у `st` и `sv` **для массива** и утверждала в
комментарии, что поэлементная форма «совпадает с тем, что печатает цель `c`».
Замер это **опроверг**: цель `c` печатала агрегат как есть, и её вывод не
собирался ни для массива, ни для структуры. Утверждение о чужом коде
проверяется прогоном, а не чтением.

### Решение

Правило «куда писать элемент агрегата» вынесено в общий носитель
`generator/aggregate.rs`: массив — по индексу, структура — по **имени поля**, в
порядке **объявления** (агрегат позиционный, 0034).

Носитель принимает **поля структуры**, а не модель: цели хранят объявления
по-разному (`ModelNode` у `st` и `c`, снимок карты у `sv`), и он отвечает за
правило выбора формы, а не за поиск объявления.

Цель `c` получила разворот в печатнике **операторов** (`c_expr/aggregate.rs`):
из выражения поэлементная запись невыразима — нужны несколько операторов.

### Границы

- **Массив в C не присваивается** даже составным литералом, поэтому форма одна
  на оба случая — поэлементная.
- **Цель `rust` не тронута:** там агрегат печатается литералом структуры
  (`Point { x: 3, y: 4 }`) и массива — обе формы в языке есть.
- **Длину агрегата сверяет семантика** (`SE-123`), поэтому носитель
  берёт `take(count)` и не судит о несоответствии.

### Отвергнутые варианты

1. **Составной литерал `(Point){3, 4}` у цели `c`.** Работает для структуры и
   **не** работает для массива — две формы вместо одной.
2. **Копия правила в каждой цели.** Они уже разошлись однажды: `st` и `sv`
   печатали индекс для структуры.

### Последствия

- Вывод корпуса не изменился.
- Сверка значений заведена на цели `c`; контрольный вход — массив.

## Анализ

### Цель и контекст

Найдено пробой «функция возвращает структуру»: соседний вход показал, что
присваивание агрегата структуре не переводит **ни одна** цель, кроме `rust`.

### Зависимости фичи

- **Зависит от:** 0330 (поэлементная запись массива), 0293 (структуры в целях),
  0320 (длина агрегата). Закрыты.
- **Влияние на порядок разработки:** нет.

### Требования и проверяемые условия

- **R1.** `c`: поэлементно, `cc -Werror` принимает.
- **R2.** `st`: структура по имени поля, `iec2c` принимает.
- **R3.** `sv`: то же, линт чист.
- **R4.** Массив по-прежнему по индексу (контроль).
- **R5.** Значения совпадают с эталоном.
- **R6.** Вывод корпуса не изменился.

### Разбор

#### Почему носитель принимает поля, а не модель

У целей разное представление объявлений: `st` и `c` держат `ModelNode`, `sv` —
снимок карты уровней. Носитель, требующий `ModelNode`, вынудил бы `sv` таскать
дерево ради одного правила; носитель, принимающий поля, оставляет каждому его
способ поиска.

#### Что показал замер

Комментарий фичи утверждал о поведении **чужой** цели и был неверен. Это
класс («проза приписывает коду чужую роль»), и он ловится только прогоном.

### Риски

- **Структура без объявления в области видимости:** носитель возвращает
  индексную форму — прежнее поведение; ошибка при этом уже поймана семантикой.

## Итог (что сделано)

**Правило «куда писать элемент агрегата» стало общим носителем.**

- **Массив — по индексу, структура — по имени поля**, в порядке **объявления**:
  агрегат позиционный (0034), и сортировка развела бы значения по чужим полям.
- **Носитель принимает поля, а не модель:** цели хранят объявления по-разному
  (`ModelNode` у `st` и `c`, снимок карты у `sv`), и он отвечает за правило
  выбора формы, а не за поиск объявления.
- **Цель `c` получила разворот в печатнике операторов:** из выражения
  поэлементная запись невыразима — нужны несколько операторов.
- **Комментарий фичи был неверен.** Он утверждал, что поэлементная
  форма «совпадает с тем, что печатает цель `c`»; замер показал, что цель `c`
  печатала агрегат как есть и её вывод не собирался. Утверждение о **чужом**
  коде проверяется прогоном, а не чтением.
- **Массив в C не присваивается** даже составным литералом — оттого форма
  одна на оба случая.
- **Контрольный вход (массив) обязателен:** без него правка читалась бы как
  «агрегат печатается по имени поля всегда».
