### Context

Версия языка Lam живёт **только** в `README.md` (строка `**Версия языка: 0.3.0**`
в разделе «10. Расширение и версии»). В коде компилятора константы версии **нет**,
`lamc` версию **не печатает**. Рассинхрон между документацией и фактическим
поведением компилятора **ничем не ловится**.

Дефект — **живой на момент заведения фичи**: фича
[семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md) (закрыта 2026-07-22) подняла версию
языка `0.3.0 → 0.4.0` и зафиксировала это в `CHANGES.md`/`CLAUDE.md`, но
`README.md` остался на `0.3.0`. Это прошло через закрытие 0078 незамеченным именно
потому, что сверять было не с чем и нечем.

Обострено решением заказчика от 2026-07-15 (версия языка
**накапливается** по циклам, а не растёт с каждой фичей): исполнение решения
затруднено тем, что единого места версии в коде нет — пять фич пула независимо
заявляли подъём `0.2.0 → 0.3.0`, а сверить намерения было не с чем.

Прецедент проекта: **правило, которое нельзя проверить
командой, — не правило.** README как единственный носитель факта повторяет судьбу
доков, отстающих от кода.

### Decision Drivers

1. **Единый источник истины.** Версия языка должна иметь **одно** каноническое
   место в коде; документация обязана следовать за ним, а не наоборот.
2. **Машинная проверяемость.** Рассинхрон дока↔константа должен валить
   `precheck.sh`/CI, а не жить до следующего ручного замечания (как дефект).
3. **Минимальность и аддитивность.** Фича не меняет язык — только
   вводит константу и проверка. Ничего в поведении компилятора/симулятора и в
   порождаемом коде меняться не должно.
4. **Ограничение размера `lamc.rs`.** Файл `grammar/src/bin/lamc.rs` ровно на
   baseline размера (1993 строки, реестр `module-size-baseline.txt`) — расти он
   **не имеет права**. Любое решение с CLI-подкомандой упирается в это.

### Considered Options

#### Option A. Константа в коде + проверка грепает исходник, сверяя с README

`pub const LANGUAGE_VERSION: &str = "0.4.0";` в отдельном модуле
`grammar/src/version.rs` (реэкспорт из `lib.rs`). Проверка
`scripts/check-language-version.sh` извлекает значение константы из исходника и
каноническую строку `**Версия языка: X.Y.Z**` из `README.md`, сверяет; расхождение
→ красный `precheck.sh`.

**Pros:**
- Единый источник истины в коде (драйвер 1); README обязан следовать (проверка).
- Машинная проверяемость (драйвер 2) прецедентом ADR — грепом исходника,
  как `check-diagnostic-codes.sh` грепает `with_code`.
- `lamc.rs` **не растёт** (драйвер 4) — CLI не трогаем.
- Аддитивно (драйвер 3): новый модуль, новая проверка, правка одной строки README.

**Cons:**
- Проверка грепает строковый литерал исходника — привязан к форме объявления
  (`LANGUAGE_VERSION: &str = "…"`). Форма стабильна и покрыта юнит-тестом формата.
- `lamc version` пользователю по-прежнему недоступен (см. Option B) — уходит в
  бэклог-кандидат.

#### Option B. Константа + подкоманда `lamc version`, проверка сверяет вывод CLI с README

Как A, но версия отдаётся через `lamc version`, а проверка сверяет `lamc version` с
README (контракт — CLI, а не форма исходника).

**Pros:**
- CLI-контракт чище грепа исходника; `lamc version` полезен пользователю.

**Cons:**
- `lamc.rs` **обязан вырасти** (диспетч подкоманды) — прямое нарушение baseline
  размера (драйвер 4). Обходы (удалить строки-компенсаторы, вынести диспетч в
  библиотеку и всё равно добавить `if`-ветку) либо хрупки, либо всё равно растят
  файл.
- Проверка зависит от сборки `lamc` — медленнее и не «до тестов», как быстрые проверки.

#### Option C. Rust-тест сверяет `LANGUAGE_VERSION` с README вместо shell-проверки

Константа + `#[test]`, читающий `../README.md` и сверяющий.

**Pros:**
- Проверка на языке проекта, без нового shell-скрипта.

**Cons:**
- Тест крейта `grammar` запускается из каталога крейта; `README.md` — в корне
  workspace (`../README.md`) — путь хрупкий, ломается при разных запусках
  (`cargo test` из корня vs из крейта), в отличие от shell-проверки, который
  `precheck.sh` всегда зовёт из корня репозитория.
- Смешивает doc-инвариант с юнит-тестами; прецедент проекта для doc-инвариантов —
  именно shell-проверка в `precheck.sh` (размер модуля, реестр кодов, ссылки).

### Decision

Принимается **Option A**. Единственный источник истины — константа
`grammar::version::LANGUAGE_VERSION` (реэкспорт `grammar::LANGUAGE_VERSION`); проверка
`scripts/check-language-version.sh` в `precheck.sh` сверяет её с канонической
строкой `**Версия языка: X.Y.Z**` в `README.md`. Это единственный вариант, не
растящий `lamc.rs` (драйвер 4) и следующий прецеденту машинных doc-проверок проекта
(ADR, драйвер 2).

Живой рассинхрон 0078 (README `0.3.0`, факт `0.4.0`) устраняется в рамках этой
фичи — иначе проверка красный на текущем дереве: константа = `0.4.0`, каноническая
строка README правится `0.3.0 → 0.4.0`. Это **не** подъём версии языка:
константа лишь фиксирует уже действующую `0.4.0`.

Подкоманда `lamc version` (Option B) — полезна, но заблокирована baseline размера
`lamc.rs`; выносится в **кандидат** (бэклог `FEATURES.md`), берётся после появления
запаса в `lamc.rs` или его рефакторинга.

Проверка сверяет **только** каноническую строку `**Версия языка: X.Y.Z**` (текущая
версия). Исторические упоминания версий в README (заметки «`0.2.0 → 0.3.0`»,
«версия 0.3.0 накапливает», ссылки на фичи прошлых циклов) — **корректны в своём
контексте** и проверкой не трогаются: якорь узкий по замыслу.

### Consequences

#### Положительные

- Версия языка централизована в коде; рассинхрон дока↔факт ловится машиной
  (класс дефекта закрыт конструктивно).
- Исполнение (накопление версии) обретает опору: есть единственное
  место, куда пишется номер цикла, и проверка, стерегущий согласие с README.
- Публичная константа доступна тестам и будущим тулам (напр. будущему
  `lamc version`).

#### Отрицательные / Action items

- Проверка привязан к форме объявления константы — компенсируется юнит-тестом формата
  (`version::tests`) и узостью греп-паттерна.
- `lamc version` (Option B) не реализован — **кандидат** в `FEATURES.md`.
- README должен нести каноническую строку `**Версия языка: X.Y.Z**` ровно в одном
  экземпляре — проверка падает и при её отсутствии, и при нескольких (защита от
  расхождения якоря).

#### Acceptance criteria

1. `grammar::LANGUAGE_VERSION` существует, публичен, равен `"0.4.0"`; юнит-тест
   проверяет формат `x.y.z`.
2. `scripts/check-language-version.sh` возвращает 0, когда константа и
   каноническая строка README совпадают, и ненулевой код при расхождении,
   отсутствии или дубле канонической строки. Проверено пробой (искусственный
   рассинхрон → красный).
3. Проверка подключён в `precheck.sh` (и, следовательно, в CI по 0090) в блоке быстрых
   проверок (до долгих тестов).
4. `README.md` приведён к `0.4.0` (каноническая строка); `./scripts/precheck.sh`
   зелёный.
5. Вывод всех целей и симулятора байт-в-байт неизменен: фича не
   трогает генераторы. Версия языка **не** поднимается.

## Анализ

### Цель и контекст

Ввести **единственный источник истины** для версии языка Lam в коде
(`grammar::LANGUAGE_VERSION`) и **машинный проверка**, сверяющий эту константу с
канонической строкой версии в `README.md`. Закрывает класс дефекта, при котором
документация отстаёт от фактической версии, а сверить нечем (прецедент: фича
подняла язык до `0.4.0`, но README остался на `0.3.0` — не поймано при закрытии).

Опора на прецедент машинных doc-проверок проекта (ADR — размер модуля, ADR
— реестр кодов): *правило, которое нельзя проверить командой, — не правило*.
Обоснование выбора Option A (константа + shell-проверка грепом исходника) — в ADR.

### Зависимости фичи

- **Зависит от:** **нет.** Фича самодостаточна: затрагивает только крейт `grammar`
  (новый модуль `version.rs` + реэкспорт), `scripts/` (новая проверка + подключение в
  `precheck.sh`) и `README.md` (правка канонической строки). Ни контракта, ни
  схемы, ни инфраструктуры других незакрытых фич не задействует.
- **Влияние на порядок разработки:** завершение фичи не разблокирует напрямую
  других фич таблицы, но даёт опору своду (накопление версии) для **всех**
  будущих фич, меняющих язык: появляется единственное место записи номера цикла и
  проверка согласия с README. Порядок хвоста `FEATURES.md` не меняется.

### Требования и проверяемые условия

- **R1. Единственный источник в коде.** `pub const LANGUAGE_VERSION: &str` в
  `grammar/src/version.rs`, реэкспорт `grammar::LANGUAGE_VERSION`. Значение —
  фактическая версия языка `"0.4.0"` (после 0078).
- **R2. Формат константы.** Значение — SemVer-тройка `x.y.z` из десятичных
  компонент; охраняется юнит-тестом `version::tests`.
- **R3. Проверка синхронизации.** `scripts/check-language-version.sh` (POSIX `sh`, без
  внешних зависимостей — образец `check-diagnostic-codes.sh`) извлекает версию из
  константы и каноническую строку `**Версия языка: X.Y.Z**` из `README.md`,
  сравнивает. Возврат 0 при совпадении, ненулевой — при (а) расхождении,
  (б) отсутствии канонической строки, (в) более чем одной канонической строке.
- **R4. Подключение в конвейер.** Проверка вызывается в `precheck.sh` в блоке быстрых
  проверок (рядом с `check-module-size.sh`/`check-diagnostic-codes.sh`, **до**
  долгих тестов). CI получает его автоматически (0090: CI гоняет весь
  `precheck.sh`).
- **R5. Устранение живого рассинхрона.** Каноническая строка `README.md` приведена
  `0.3.0 → 0.4.0`; `precheck.sh` зелёный. Это не подъём версии —
  фиксация уже действующей `0.4.0`.
- **R6. Аддитивность.** Вывод всех целей (`c`/`c-hal`/`plantuml`/`st`/
  `st-at`/`rust`/`sv`/`sv-mmio`) и симулятора байт-в-байт неизменен; генераторы не
  трогаются. Версия языка **не** поднимается.

### Особенности по обратной функциональности

Полностью аддитивно: новый публичный элемент API
(`grammar::LANGUAGE_VERSION`) — минорный бамп крейта `grammar`; новая проверка; правка
одной строки документации. Существующий код, тесты, порождаемый вывод и версия
языка не затронуты. Крейт `grammar`: `0.9.0 → 0.10.0` (аддитивный публичный API,
SemVer minor; прецедент 0072 `0.7.0 → 0.8.0`). Крейт `simulation` не трогается.

### Риски и зависимости

- **Риск: проверка привязан к форме объявления константы** (греп строкового литерала).
  Снижение: форма стабильна, покрыта юнит-тестом формата; греп-паттерн узкий
  (`LANGUAGE_VERSION: &str = "…"`), как `check-diagnostic-codes.sh` грепает
  `with_code`.
- **Риск: якорь README неоднозначен** (несколько строк с версией). Снижение: проверка
  падает при ≠1 совпадении канонической строки `**Версия языка: X.Y.Z**`;
  исторические упоминания версий имеют иную форму и под якорь не подходят.
- **Зависимость: `lamc version` (Option B)** заблокирован baseline размера
  `lamc.rs` — вынесен в **кандидат** `FEATURES.md`, вне объёма 0085.
- **Tier:** **Tier 3** (инфраструктура/процесс; текущая боль — устаревшая строка
  README, будущая — незамеченный подъём версии). Живой рассинхрон 0078 придаёт
  фиче конкретную ценность «здесь и сейчас», но класс — процессная страховка, не
  дефект поведения компилятора.

## Разработка

### Задача

#### Что было

Версия языка жила **только** в `README.md` (`**Версия языка: 0.3.0**`). Константы
в коде не было, `lamc` версию не печатал, рассинхрон дока↔факт ничем не ловился.
**Живой дефект:** фича подняла язык `0.3.0 → 0.4.0` (`CHANGES.md`/`CLAUDE.md`),
но `README.md` остался на `0.3.0` — прошло незамеченным при закрытии 0078.

#### Что сделано

Реализована **Option A** ADR.

- **Константа (`grammar`).** Новый модуль `grammar/src/version.rs`:
  `pub const LANGUAGE_VERSION: &str = "0.4.0";` — единственный источник истины.
  Реэкспорт `grammar::LANGUAGE_VERSION` в `lib.rs`. Два юнит-теста: формат
  SemVer-тройки и наличие реэкспорта из корня крейта.
- **Проверка (`scripts`).** `scripts/check-language-version.sh` (POSIX `sh`, образец
  `check-diagnostic-codes.sh`): извлекает версию из литерала `version.rs` и
  каноническую строку `**Версия языка: X.Y.Z**` из `README.md`, сверяет. Три
  условия отказа: расхождение / нет якоря / дубль якоря. Подключён в `precheck.sh`
  в блоке быстрых проверок (после реестра кодов, до долгих тестов) — CI получает
  его автоматически (0090).
- **Устранение живого рассинхрона (`README`).** Каноническая строка приведена
  `0.3.0 → 0.4.0`; добавлены заметка о единственном источнике истины (проверка) и
  историческая врезка `0.3.0 → 0.4.0`. Это **не** подъём версии — фиксация уже действующей `0.4.0`.
- **Компенсация размера `lib.rs`.** Модуль-декларация + реэкспорт (+3 строки)
  нарушили бы храповик размера (`lib.rs` на baseline 1402). Ужат crate-doctest
  ровно на 3 строки (fmt-стабильно, doctest остаётся валидным) — `lib.rs` вновь
  1402, baseline не трогается. `lamc.rs` (тоже на baseline 1993) **не тронут** —
  CLI-подкоманда `version` вне объёма (Option B заблокирован размером; кандидат).

| Стек | Статус |
|---|---|
| `grammar` | ✅ константа + реэкспорт + юнит-тесты, компенсация размера `lib.rs` |
| `scripts` | ✅ новая проверка + подключение в `precheck.sh` |
| `README.md` | ✅ каноническая строка `0.4.0` + заметки |
| `simulation` | н/п — фича не затрагивает симулятор |
| генераторы целей | н/п — вывод байт-в-байт неизменен |
