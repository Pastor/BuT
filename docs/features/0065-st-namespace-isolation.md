## Краткое описание

Пространство имён `FUNCTION`/`FUNCTION_BLOCK` в IEC 61131-3 **плоское и общее со
стандартной библиотекой**, а генератор `st` печатает имена как есть. Три следствия
(все подтверждены проверкой `iec2c`):

1. **Одноимённые `fn` разных моделей столкнутся** — цель `c` префиксует именем
   модели (`Stacker_travel_time`), цель `st` — нет.
2. **Модель с именем `Concat`/`ABS`/`MIN`/`SEL`** даёт `invalid function block
   name`; имя корневой модели берётся **из имени файла**, поэтому ловушка
   срабатывает на `concat.lam` (поймано на фикстуре 0041-07, файл переименован).
3. **Капкан шире POU — бьёт и по обычным переменным.** Локальная переменная
   функции с именем `left` даёт «invalid located variable declaration» — `LEFT` в
   IEC стандартная **строковая** функция. Проверено: `left`/`LEFT`/`right`/`mid`
   отвергаются, `remaining`/`v` принимаются; идентификаторы IEC
   **регистронезависимы**, поэтому нижний регистр не спасает. Диагностика
   **обманчива** — говорит про «located variable» (`AT %…`), которых в объявлении
   нет вовсе, то есть по тексту ошибки причину не найти.

Оба класса `iec2c` ловит **громко** («duplicate»/«invalid name») — тихого
расхождения нет. Лечение общее: префиксовать имена уникальным именем модели, как в
цели `c`. Обойдено переименованием в примере (`left` → `remaining`).

В корпусе п. 3 был замаскирован тем, что до 0030 **ни одна** функция примеров не
имела локальных переменных.

Выявлено при закрытой [генератор генерации в Structured Text (IEC 61131-3)](0041-st-backend.md), расширено при
[исправление примера comprehensive.lam (недостижимый сценарий)](0030-comprehensive-example-fix.md).

> **Объединены два кандидата** («Имена POU цели `st` не изолированы» и его
> подпункт-уточнение про переменные): лечение у них одно — изоляция пространства
> имён цели (решение заказчика 2026-07-17).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0065-st-namespace-isolation.md); вскрыт [исправление](../fixes/0041-01-st-fn-dedup-silent.md) (**Tier 1**, молчаливо неверный вывод)

### Context

Пространство имён POU (`FUNCTION`/`FUNCTION_BLOCK`) в IEC 61131-3 **плоское и
общее со стандартной библиотекой**; идентификаторы **регистронезависимы**.
Генератор `st` печатает имена **как есть** (`st_func.rs:312`:
`FUNCTION {name} : {ret_ty}`), тогда как цель `c` префиксует именем модели
(`DupA_helper`).

Кандидат называл **два** следствия и утверждал про оба: «`iec2c` ловит **громко**
(«duplicate»/«invalid name»), **тихого расхождения нет** — поэтому кандидат, а не
дефект».

**Проработка проверила все заявки пробами. Главная — опровергнута.**

#### Проба 1 (опровергает кандидата): одноимённые `fn` склеиваются молча

Вход: две модели, у каждой своя `fn helper` с **разными** телами.

| Цель | Результат |
|---|---|
| **`c` (эталон)** | `DupA_helper` (`x + 1`) **и** `DupB_helper` (`x + 2`) |
| **`st`** | **одна** `FUNCTION helper` с телом **`helper := x + 1;`** — на обе модели |

**`iec2c` принял** (`rc = 0`). И не мог не принять: дубля в тексте **нет**.
Причина — `st_func.rs:275`, дедупликация по голому имени, с комментарием:

> «Одноимённые функции разных моделей столкнулись бы; столкновение поймает
> `iec2c` («duplicate»), то есть **громко, а не молча**.»

**Комментарий неверен.** Дедупликация именно и означает, что `iec2c` **не увидит**
столкновения. Модель `B` вместо `w = 3` получает `w = 2`, переход
`ref Done2: w = 3` **не срабатывает никогда** — автомат стоит **молча**.
Заведён **[исправление](../fixes/0041-01-st-fn-dedup-silent.md), Tier 1**.

Кандидат унаследовал ошибку **из комментария** — и из-за этого дефект Tier 1
числился «долгом Tier 3».

#### Проба 2 (подтверждает кандидата): имя модели против стандартной библиотеки

`concat.lam` → `FUNCTION_BLOCK Concat` →
`error: invalid function block name in function block declaration.` — **громко**.
Имя корневой модели берётся **из имени файла**, поэтому ловушка срабатывает на
`concat.lam`.

#### Проба 3 (подтверждает кандидата): имя переменной против стандартной библиотеки

Локальная `var left: u8` → `left : USINT;` →
`error: invalid located variable declaration.` +
`error: unexpected token after 'VAR' in located variable(s) declaration.`

Громко, но **диагностика обманчива**: говорит про «located variable» (`AT %…`),
которых в объявлении **нет вовсе**. По тексту ошибки причину не найти.

### Decision Drivers

1. **Тихо неверный вывод — худший класс** (Tier 1). Исправление обязан быть
   закрыт; всё остальное — вторично.
2. **Эталон уже решил задачу правильно.** Цель `c` префиксует POU именем модели.
   Расхождение целей — не свойство IEC, а недоделка `st`.
3. **Столкновение со стандартной библиотекой — не то же, что столкновение
   моделей.** Первое лечится префиксом, второе — нет: у корневой модели `Concat`
   префикс **её же имя**.
4. **Прецедент проекта — диагностика, а не молчаливое переименование.** Цель `sv`
   для того же класса завела `SV-012` (имя = ключевое слово) и `SV-007`
   (зарезервированные `clk`/`rst_n`).

### Considered Options

#### Option A. Префикс POU именем модели + диагностика на столкновение со стандартной библиотекой

Два разных лечения на две разные беды (драйвер 3):

1. **POU** (`FUNCTION`/`FUNCTION_BLOCK`) получают **уникальное имя модели**
   префиксом — как в цели `c`. Дедупликация по голому имени **исчезает вместе с
   причиной**: имена перестают совпадать → **исправление закрыт как следствие**.
2. **Любой идентификатор**, совпадающий (без учёта регистра) со стандартной
   функцией IEC или ключевым словом, → **диагностика `ST-014`**.

**Pros:**
- Закрывает **Tier 1** (драйвер 1) — и не заплатой, а устранением причины.
- Повторяет уже принятое и работающее решение эталона (драйвер 2).
- Диагностика вместо догадки — прецедент `sv` (драйвер 4); автор узнаёт правду в
  компиляторе Lam, а не по обманчивому «invalid located variable declaration».
- Лечит и `Concat` (проба 2), и `left` (проба 3) — одним правилом.

**Cons:**
- **Ломает переносимость** для моделей с «плохими» именами: `.lam`, валидный для
  `c`/`rust`/`sv`, перестанет собираться целью `st`. Смягчение: это **уже так** —
  сегодня такая модель просто отвергается `iec2c` с невнятным текстом; меняется
  лишь **кто и как** об этом говорит.
- Список стандартных функций IEC длинный (`ABS`, `MIN`, `MAX`, `SEL`, `LIMIT`,
  `CONCAT`, `LEFT`, `RIGHT`, `MID`, `LEN`, `FIND`, `INSERT`, `DELETE`, `REPLACE`…)
  и его надо вести. Смягчение: у `sv` уже ведётся такой же (`SV_KEYWORDS`).

#### Option B. Только префикс POU; столкновения со стандартной библиотекой оставить `iec2c`

**Pros:** меньше работы; Tier 1 всё равно закрыт.

**Cons:**
- Оставляет **обманчивую** диагностику (проба 3: «located variable», которых нет)
  — то есть пользователь остаётся с ошибкой, по тексту которой причину не найти.
- Не лечит `Concat` (проба 2).

#### Option C. Молчаливое переименование (mangling) всех идентификаторов

**Pros:** переносимость сохраняется полностью; автору ничего менять не надо.

**Cons:**
- **Нарушает драйвер 4** и прецедент `sv`: имя в порождённом ST перестаёт
  совпадать с именем в `.lam` — отладка на ПЛК (где инженер видит именно ST)
  становится головоломкой.
- Схема mangling сама может столкнуться (пользовательская модель с именем,
  совпавшим с результатом mangling).
- Скрывает от автора факт, который ему полезно знать.

#### Option D. Не делать (статус-кво)

**Pros:** ноль работы.

**Cons:** оставляет **Tier 1** (драйвер 1). Отвергается сразу.

### Decision

Принимается **Option A**.

**Нормативные правила:**

1. **POU префиксуются уникальным именем модели** — как в цели `c`
   (`DupA_helper`). Дедупликация по голому имени (`st_func.rs:275`)
   **удаляется**; вместе с ней исчезает
   [исправление](../fixes/0041-01-st-fn-dedup-silent.md).
   **Убрать дедупликацию, не префиксуя, нельзя:** тогда `iec2c` даст
   «duplicate», то есть тихий дефект станет громким отказом на **корректной**
   модели.
2. **`ST-014`** — ошибка: идентификатор (POU, переменная, параметр, поле)
   совпадает со стандартной функцией IEC либо ключевым словом. Сравнение —
   **без учёта регистра** (идентификаторы IEC регистронезависимы: `left`,
   `LEFT`, `Left` — одно и то же).
3. **Текст `ST-014` обязан называть причину**, которой нет в диагностике `iec2c`:
   «`left` — стандартная строковая функция IEC 61131-3; переименуйте». Сегодняшнее
   «invalid located variable declaration» указывает на `AT %…`, которых в
   объявлении нет.
4. **Проверка — на именах модели тоже** (проба 2: `concat.lam` → `FUNCTION_BLOCK
   Concat`). Имя корневой модели берётся из **имени файла**, поэтому `ST-014`
   обязана срабатывать и на нём.
5. **Комментарий `st_func.rs:275` исправляется вместе с кодом** — он утверждает
   неправду и переживёт правку, если его не тронуть (он уже ввёл в заблуждение
   автора кандидата).
6. Язык **не меняется** → версия не растёт (правило 22).

### Consequences

#### Положительные

- **Tier 1 закрыт**: одноимённые `fn` разных моделей больше не склеиваются.
- Цели `c` и `st` начинают именовать POU **одинаково** — расхождение эталона и
  генератора исчезает.
- Обманчивая диагностика `iec2c` заменяется внятной `ST-014`.

#### Отрицательные / Action items

- **A-1. Сверки для цели `st` Не существует.** Есть `conformance_{c,sv,rust}_tests`
  — `st` **нет**. То есть поведение ST не проверялось **никогда**, а проверка `iec2c`
  доказывает лишь компилируемость. Именно поэтому 0041-01 дожил.
  **Критерий закрытия исправления требует завести сверку** — это долг с фичи, и
  0065 его отдаёт. Сверка ST требует исполнять порождённый ST, то есть
  runtime — объём нетривиален; вынесен задачей и **может быть признан
  отдельной фичей**, если окажется несоизмерим.
- **A-2. Переносимость меняется в частном случае:** модель с именем `Concat`/`left`
  собиралась целями `c`/`rust`/`sv` и не собиралась `st` (`iec2c`); теперь не
  собирается `st` **внятно**. Правило 11 требует назвать — названо; это **не**
  регресс.
- **A-3. Список стандартных функций IEC надо вести.** Прецедент — `SV_KEYWORDS`.
  Неполный список = пропущенное столкновение, но оно **громко** ловится `iec2c`
  (кроме случая дублей, который правило 1 устраняет структурно).
- **A-4. Вывод корпуса изменится:** имена функций получат префикс. Это
  **ожидаемо**; дифф обязан быть объяснимым построчно (детерминизм — закрытая
  [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr)).

#### Acceptance criteria

1. **A1.** Две модели с одноимёнными `fn` дают в ST **две разные** функции с
   **разными** телами; `grep -c "FUNCTION .*helper"` → **2**.
2. **A2.** Модель `B` из пробы даёт `w = 3`; переход `Done2` **срабатывает**
   (сегодня — никогда).
3. **A3.** **Потактовая сверка `st`** на этой модели — зелёная (A-1).
4. **A4.** `concat.lam` → **`ST-014`** (внятно), а не `invalid function block
   name` от `iec2c`.
5. **A5.** `var left` → **`ST-014`** с указанием причины (стандартная строковая
   функция IEC), а не «invalid located variable declaration».
6. **A6.** Регистронезависимость: `left`, `LEFT`, `Left` → одинаково `ST-014`.
7. **A7.** Проверка `iec2c` по **всему** корпусу — зелёный; вывод целей, кроме `st`,
   **побайтово прежний**.
8. **A8.** Комментарий `st_func.rs:275` исправлен (правило 5).
9. **A9.** `examples/` перегенерирован; дифф `st` объяснён построчно (префиксы).

### Приоритет (Tier) — обоснование

**Tier 2** (кандидат утверждал Tier 3 — «не дефект»; проработка переоценила).

- Фича **закрывает Tier 1**-дефект: молчаливо неверный вывод, из-за которого
  автомат на ПЛК стоит.
- Против Tier 1 для самой фичи: дефект **условен** — бьёт только по моделям с
  одноимёнными `fn` в разных моделях, каких в корпусе нет.
- Против Tier 3: «изолировать имена» — не долг, когда один из его симптомов
  молча ломает поведение.

### Требования и проверяемые условия

- **R1. POU префиксуются именем модели** — как в цели `c`.
- **R2. Дедупликация по голому имени удаляется** вместе с причиной.
  Убрать её **не префиксуя** нельзя: `iec2c` даст «duplicate», то есть тихий
  дефект станет громким отказом на **корректной** модели.
- **R3. `ST-014`** — идентификатор совпал со стандартной функцией IEC либо
  ключевым словом.
- **R4. Сравнение без учёта регистра** (идентификаторы IEC регистронезависимы).
- **R5. Текст `ST-014` называет причину** — то, чего нет в диагностике `iec2c`.
- **R6. Проверка распространяется на имя модели** (берётся из имени файла).
- **R7. Комментарий `st_func.rs:275` исправлен** (он утверждает неправду).
- **R8. Прочие цели не задеты**; язык не меняется → версия не растёт.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Две одноимённые `fn` → **две** функции с разными телами | Фикстура + греп |
| A2 | Модель `B` даёт `w = 3`; переход срабатывает | Прогон |
| A3 | **Потактовая сверка `st`** — зелёная | Новая сверка (см. A-1 ADR) |
| A4 | `concat.lam` → `ST-014`, а не `invalid function block name` | Контрпример |
| A5 | `var left` → `ST-014` с причиной | Контрпример |
| A6 | `left`/`LEFT`/`Left` → одинаково | Контрпримеры |
| A7 | Проверка `iec2c` по корпусу зелёный; прочие цели побайтово прежние | `precheck.sh` + `git diff` |
| A8 | Комментарий исправлен | Ревью |
| A9 | Дифф `st` объяснён построчно | Ревью диффа |

### Особенности по обратной функциональности

**Вывод цели `st` изменится** (правило 11): имена POU получат префикс. Это
**ожидаемо** и объяснимо построчно (детерминизм — закрытая 0048). Прочие цели,
симулятор, LSP, форматтер — **не задеты** (A7).

**Изменение контракта, названное честно:** модель с именем `Concat` или
переменной `left` перестанет собираться целью `st` **внятно** (`ST-014`). Сегодня
она **уже** не собирается — `iec2c` отвергает её обманчивым текстом. То есть
меняется **кто и как** об этом говорит, а не факт. **Это не регресс.**

Язык не меняется → версия не растёт (правило 22).

### Риски и зависимости

- **R-1. Поведенческую правку нечем проверить.** **Сверки для цели `st` не
  существует** (`conformance_{c,sv,rust}_tests` есть, `st` — нет). Именно поэтому
  0041-01 дожил: проверка `iec2c` доказывает компилируемость, но **не верность**. Снижение: A3 — завести сверку. Она требует **исполнять**
  порождённый ST (runtime), объём нетривиален → задача; **может быть
  признана отдельной фичей**, если окажется несоизмерима.
- **R-2. Убрать дедупликацию, забыв префикс.** Дало бы «duplicate» от `iec2c` на
  корректной модели — громко, но неверно. Снижение: R1 и R2 — **одной** задачей.
- **R-3. Список стандартных функций IEC неполон.** Пропущенное имя → столкновение
  поймает `iec2c` (громко, но обманчиво). Снижение: прецедент `SV_KEYWORDS`;
  **структурный** случай (дубли) правилом 1 закрыт **независимо** от полноты
  списка — то есть худшее (тихое) не зависит от полноты.
- **R-4. Префикс сломает читаемость ST на ПЛК.** Инженер видит `Stacker_travel_time`
  вместо `travel_time`. Принято: ровно так уже делает эталон `c`; альтернатива
  (mangling) хуже — см. Option C ADR.

## Разработка

### Задача

#### Что было

`st_func.rs:312` печатает `FUNCTION {name}` **как есть**, а `st_func.rs:275`
дедуплицирует функции **по голому имени** с комментарием:

> «Одноимённые функции разных моделей столкнулись бы; столкновение поймает
> `iec2c` («duplicate»), то есть громко, а не молча.»

**Комментарий неверен** — проба доказала: эмитится **одна** функция (тело первой
модели), дубля в тексте нет, `iec2c` **принимает** (rc=0), а вторая модель **молча
считает не то** → автомат стоит.
[Исправление](../fixes/0041-01-st-fn-dedup-silent.md), **Tier 1**.

Эталон (цель `c`) делает правильно: `DupA_helper` (`x+1`) и `DupB_helper` (`x+2`).

#### Что сделано

1. **Префиксовать POU уникальным именем модели** — как в цели `c` (правило 1 ADR).
2. **Удалить дедупликацию** (`emitted: Vec<String>`) — она исчезает **вместе с
   причиной**: имена перестают совпадать.
   **Порядок важен: убрать дедупликацию, не префиксуя, нельзя** — тогда `iec2c`
   даст «duplicate», то есть тихий дефект станет **громким отказом на корректной
   модели**. Обе правки — **одной** задачей (правило 2 R-2 анализа).
3. **Исправить комментарий** `st_func.rs:275` (правило 5 ADR): он утверждает
   неправду и **переживёт правку кода**, если его не тронуть. Он уже ввёл в
   заблуждение автора кандидата — из-за него дефект Tier 1 числился «долгом
   Tier 3».

Статус по обратной функциональности (правило 11): вывод цели `st` **изменится**
(префиксы) — ожидаемо и объяснимо построчно (детерминизм 0048). Прочие цели,
симулятор, LSP, форматтер — не задеты.

#### Проверки

- **T1/A1:** две одноимённые `fn` → **две** функции с **разными** телами
  (`grep -c "FUNCTION .*helper"` → 2).
- **T2/A2:** модель `B` даёт `w = 3`; переход `Done2` **срабатывает** (сегодня —
  никогда).
- **T4:** имена POU у `c` и `st` согласованы.
- **T9/A7:** `iec2c` принимает весь корпус.
- **T10:** прочие цели побайтово прежние.
- **T11/A9:** дифф `st` — только префиксы.
- **T12/A8:** комментарий исправлен.
- **T13 (мутация):** вернуть дедупликацию — **T2/T3 падают**, а **проверка `iec2c`
  проходит**. Это и есть доказательство, что проверка контролем не является.

### Задача

#### Что было

Столкновение со стандартной библиотекой IEC ловит `iec2c` — **громко, но
обманчиво**. Пробы 2026-07-17:

| Вход | Диагностика `iec2c` |
|---|---|
| `concat.lam` → `FUNCTION_BLOCK Concat` | `error: invalid function block name in function block declaration.` |
| `var left: u8` | `error: invalid located variable declaration.` + `unexpected token after 'VAR' in located variable(s) declaration.` |

Второй текст **указывает не на то**: говорит про «located variable» (`AT %…`),
которых в объявлении **нет вовсе**. По тексту ошибки причину найти **невозможно**.

Причина обеих: идентификаторы IEC **регистронезависимы** и делят плоское
пространство со стандартной библиотекой (`CONCAT`, `LEFT`, `RIGHT`, `MID`,
`LIMIT`, `ABS`, `MIN`, `MAX`, `SEL`…; `step` — ключевое слово SFC).

#### Что сделано

**`ST-014`** (код свободен: заняты `ST-001`…`ST-013`) — ошибка: идентификатор
совпал со стандартной функцией IEC либо ключевым словом.

1. **Сравнение без учёта регистра** (правило 4 ADR): `left`, `LEFT`, `Left` —
   одно и то же.
2. **Область** (правило 2 ADR): POU, переменные, параметры, поля — **и имя
   модели** (правило 6: берётся из **имени файла**, поэтому `concat.lam`
   срабатывает).
3. **Текст называет причину** (правило 3 ADR): «`left` — стандартная строковая
   функция IEC 61131-3; переименуйте» — то, чего в диагностике `iec2c` **нет**.
4. **Список** — по образцу `SV_KEYWORDS` (`sv_module.rs:82`), прецедент цели `sv`
   (`SV-012`).

**Полнота списка не критична для худшего случая:** структурный дефект (дубли)
закрывает [изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md#разработка) **независимо** от списка; пропущенное
здесь имя поймает `iec2c` — громко, пусть и обманчиво. То есть список улучшает
диагностику, но не является единственной защитой.

Статус по обратной функциональности (правило 11): модель с именем `Concat`/`left`
перестанет собираться целью `st` **внятно**. Сегодня она **уже** не собирается
(`iec2c` отвергает) — меняется **кто и как** об этом говорит. **Не регресс.**

#### Проверки

- **T5/A4:** `concat.lam` → `ST-014`, а не `invalid function block name`.
- **T6/A5:** `var left` → `ST-014` **с причиной**.
- **T7/A6:** `left`/`LEFT`/`Left` → одинаково.
- **T8:** `ABS`, `MIN`, `SEL`, `LIMIT`, `step` → `ST-014`.
- **T9/A7:** проверка `iec2c` по корпусу зелёный (в корпусе таких имён нет — их уже
  переименовали при 0030: `left` → `remaining`).
- **T10:** прочие цели побайтово прежние.

### Задача

#### Что было

**Сверки для цели `st` не существует.** Есть `conformance_c_tests`,
`conformance_sv_tests`, `conformance_rust_tests` — `st` **нет**.

Следствие: поведение порождённого ST **никогда не проверялось**. Проверка `iec2c`
доказывает, что вывод **компилируется**, но **не** что он **верен** — и это не
теория: ровно так дожил [исправление](../fixes/0041-01-st-fn-dedup-silent.md)
(Tier 1), который `iec2c` **принял** (rc=0).

Правило проекта (уроки и 0050): **сверку заводить вместе с генератором**. Для
`st` это **долг с фичи**, и 0065 его отдаёт.

#### Что сделано

`simulation/tests/conformance_st_tests.rs` — потактовая сверка трассы симулятора
с трассой порождённого ST.

**Наблюдение берётся оттуда, откуда его берёт потребитель** (правило проекта,
`CLAUDE.md`): у `c` — поля структуры, у `sv` — иерархическая ссылка
`dut.<сигнал>`, у `rust` — выходные порты через HAL. Для `st` потребитель — ПЛК,
то есть **located-переменные / выходные порты**.

**Главная трудность — исполнить порождённый ST.** `iec2c` **транслирует** ST в
C (`POUS.c`/`POUS.h`), но runtime к нему не прилагается: нужен либо MatIEC-runtime,
либо собственный драйвер, вызывающий порождённую функцию такта из C. Второй путь
ближе к тому, что уже умеет `conformance_c_tests`.

**Объём может оказаться несоизмерим с 0065.** Если так — задача **выделяется в
отдельную фичу** (решение заказчика), а 0065 закрывается с A3, доказанным
минимальной сверкой на фикстуре дублей. Признать это честнее, чем растянуть 0065
на неопределённый срок: Tier 1 (0065-01) ждать не должен.

#### Спайк реализации (2026-07-18) — задел для отдельной фичи

Пробным драйвером установлено, что путь **осуществим**, но **несоизмерим** с
объёмом 0065 (см. решение ниже). Задел, снятый спайком, чтобы следующий не
проходил его заново:

1. **ABS `iec2c` доступен из C.** `iec2c` (без `-c`) кладёт рядом `POUS.h`/
   `POUS.c` плюс `LOCATED_VARIABLES.h`/`VARIABLES.csv`. Время выполнения-заголовки —
   в `~/.local/share/matiec/lib/C/` (`iec_std_lib.h`, `accessor.h`, `iec_types.h`).
   Каждая модель → `struct {Name}_data__`; такт = `{Name}_body__(&data)`;
   инициализация = `{Name}_init__(&data, retain)`. Чтение поля —
   `__GET_VAR(data.FIELD)` (раскрывается в `data.FIELD.value`), установка —
   `__SET_VAR(data.,FIELD,,значение)`. Вложенный экземпляр композиции — поле
   `data.A0` / `data.B1` (суффикс — порядковый номер).
2. **Драйвер собирается и запускается.** Харнесс `#include "iec_std_lib.h"` +
   определения `TIME __CURRENT_TIME; BOOL __DEBUG;` + `#include "POUS.h"` +
   `#include "POUS.c"`, затем цикл `{Root}_body__(&fb)` компилируется
   `cc -std=c99 -I lib/C` без ошибок (нужен `-w`: заголовки MatIEC шумят
   `-Wpointer-sign`/`-Wvarargs`). **Прямое подтверждение исправления:** в
   `POUS.c` эмитируются **две разные** функции `___DUPFNA_HELPER` (тело
   `X + 1`) и `___DUPFNB_HELPER` (тело `X + 2`) — склейки нет на уровне C.
3. **Капкан, из-за которого спайк не даёт готовой трассы: MatIEC вызывает
   вложенный FB без установки `EN`.** `DUPFN_body__` печатает
   `DUPFNA_body__(&data__->A0);`, а `DUPFNA_body__` открывается
   `if (!__GET_VAR(data__->EN)) return;`. `EN` инициализируется `FALSE` и нигде
   не поднимается, поэтому под-FB композиции **не исполняются** — трасса
   застревает на стартовом состоянии (`w = 0` на всех тактах). Драйвер обязан
   либо взводить `EN` каждого уровня явно (`__SET_VAR(fb.A0.,EN,,TRUE)` —
   рекурсивно по дереву экземпляров), либо это чинится в **генераторе**
   (эмитить `a0.EN := TRUE;` перед `a0()`), и тогда встаёт вопрос: **исполнится
   ли порождённая композиция на реальном ПЛК** без явного `EN`? Это отдельный
   разбор (возможно — смежный дефект), а не деталь сверки.

**Вывод спайка (пересмотрен):** первоначально спайк застрял на нулевой трассе и
казался объёмом отдельной фичи. Первопричина оказалась **одной строкой** —
ноль-инициализация структуры (`{Root}_data__ fb = {0};`): мусорный бит
`__IEC_FORCE_FLAG` на стеке блокировал `__SET_VAR`. `EN` руками взводить **не
нужно** — `init` ставит его в TRUE сам. После этого сверка сделана **в объёме
0065** (решение заказчика 2026-07-18 «продолжить сверку сейчас»).

#### Итог (сделано, 2026-07-18)

`simulation/tests/conformance_st_tests.rs` — потактовая (до установившегося
состояния) сверка порождённого ST с симулятором на фикстуре одноимённых `fn`
(`simulation/tests/data/eval/st_dup_fn.lam`). Путь исполнения ST:
`compile_to_st` → `iec2c` → `POUS.c/POUS.h` → C-драйвер (`{Root}_body__` за такт,
чтение полей экземпляров) → `cc` → запуск → разбор трассы.

- **A3 доказан поведенчески:** обе стороны дают `wa = 2`, `wb = 3`. До исправления
  модель `B` считала бы `wb = 2` (склейка с телом `A`).
- **T13 (мутация) проверен вручную:** возврат дедупликации по голому имени в
  `pou_name`/`emit_functions` даёт `wb = 2` → **сверка падает**, а `iec2c`
  компилирует ST без нареканий. То есть сверка ловит ровно то, чего проверка не видит.
- **Мягкая деградация:** нет `iec2c`/заголовков MatIEC/`cc` → тест-пропуск (как
  проверка ST в `precheck.sh`), а не красный.
- **Наблюдение — как у потребителя:** поля экземпляров FB (аналог `dut.<сигнал>`
  у `sv`); переменные `wa`/`wb` названы по-разному, т.к. в композиции симулятор
  адресует вложенную переменную по имени.

**Точки наблюдения зафиксированы для фикстуры** (`A0.WA`/`B1.WB` — имена
экземпляров MatIEC + поля в верхнем регистре). Обобщение на весь корпус (обход
дерева экземпляров, извлечение located-переменных, `st-at`) — **не в объёме**:
для A3 достаточно фикстуры дублей, и это записано как возможное расширение.

**Смежная находка спайка (не дефект генератора):** `EN`-семантика — деталь
времени выполнения MatIEC-в-C (`__INIT_VAR` ставит `EN := TRUE`, а `__SET_VAR` глушится
мусорным `FORCE`-битом неинициализированной памяти), а **не** свойство
порождённого ST. Драйвер обнуляет структуру — и композиция исполняется без правок
генератора. Отдельная фича по `EN` **не требуется**.

#### Проверки

- **T3/A3 — основная:** трасса ST = трасса симулятора на **каждом** такте на
  фикстуре с одноимёнными `fn` (модель `B` обязана дать `w = 3`).
- **T13 (мутация):** вернуть дедупликацию → **сверка падает**, а **проверка `iec2c`
  проходит**. Это и есть смысл задачи: доказать, что сверка ловит то, чего проверка
  не видит.
- Однопоточность: `-- --test-threads=1` (`CLAUDE.md`).
- `iec2c` собирается `scripts/ensure-iec2c.sh` (мягкий пропуск предкоммит не
  валит) — сверка обязана вести себя так же: **нет `iec2c` → пропуск**, а не
  красный тест.

### Тестовые данные и окружение

- **Фикстура T1–T3** — новая: две модели с одноимёнными `fn`. В корпусе такого
  **нет** (потому дефект и дожил — дыра **в покрытии**, а не в коде).
- **Контрпримеры T5–T8** — в `grammar/tests/data/semantic/invalid/`.
  `concat.lam` (T5): имя корневой модели берётся из **имени файла**, поэтому
  фикстуру надо именно **так и назвать**.
- **`iec2c`:** `~/.local/bin/iec2c -I ~/.local/share/matiec/lib -T <вывод> файл.st`
  — **`-I` обязателен** (без `lib/ieclib.txt` iec2c падает на любом входе).
- **Однопоточность:** `-- --test-threads=1` (`CLAUDE.md`).

### Долг, который отдаёт эта фича

**Сверки для цели `st` не существует** — есть `conformance_{c,sv,rust}_tests`,
`st` нет. То есть поведение ST **никогда** не проверялось, а проверка `iec2c`
доказывает лишь компилируемость. Это прямая причина, по которой
0041-01 дожил. T3 заводит сверку; она требует **исполнять** порождённый ST
(runtime) — объём нетривиален и **может быть признан отдельной фичей**.

## Итог проработки (2026-07-17)

**Ключевая заявка кандидата опровергнута пробой.** Кандидат утверждал: «Оба
случая `iec2c` ловит **громко**, **тихого расхождения нет** — поэтому кандидат, а
не дефект». Про случай 1 это **неправда**.

| # | Проба | Результат | Заявка |
|---|---|---|---|
| 1 | Две модели, у каждой `fn helper` с **разными** телами | **`st`: Одна** `FUNCTION helper` с телом первой (`x+1`); **`iec2c` Принял** (rc=0). Эталон `c`: `DupA_helper` **и** `DupB_helper` | **Опровергнута** |
| 2 | `concat.lam` | `invalid function block name` — громко | подтверждена |
| 3 | `var left: u8` | `invalid located variable declaration` — громко, но **обманчиво** | подтверждена |

**Механизм** — `st_func.rs:275`, дедупликация по голому имени с комментарием:
«столкновение поймает `iec2c` («duplicate»), то есть **громко, а не молча**».
**Комментарий неверен:** дедупликация именно и означает, что дубля в тексте **нет**
— ловить нечего. Модель `B` вместо `w = 3` получает `w = 2` → переход
`ref Done2: w = 3` **не срабатывает никогда** → автомат **молча стоит**.

Заведён **[исправление](../fixes/0041-01-st-fn-dedup-silent.md), Tier 1**.
**Кандидат унаследовал ошибку из комментария дословно** — из-за этого дефект
Tier 1 три месяца числился «долгом Tier 3». Урок: *формулировка кандидата —
гипотеза, а не факт, даже если списана из кода*.

**Принято** ([ADR](0065-st-namespace-isolation.md#архитектура-adr), Option A) — два лечения
на две **разные** беды: (1) **POU префиксуются именем модели**, как в `c` →
дедупликация исчезает вместе с причиной, исправление закрыт **как следствие**;
(2) **`ST-014`** (код свободен) — идентификатор совпал со стандартной функцией IEC
или ключевым словом; сравнение **без учёта регистра**; текст **называет причину**,
которой нет у `iec2c`. Отклонены: только префикс (оставляет обманчивую
диагностику), молчаливое переименование (имя в ST перестаёт совпадать с `.lam` —
отладка на ПЛК становится головоломкой; прецедент `sv` — диагностика), статус-кво.

**Долг, который отдаёт фича: сверки для цели `st` Не существует**
(`conformance_{c,sv,rust}_tests` есть, `st` — нет). Поведение ST не проверялось
**никогда** — ровно поэтому 0041-01 и дожил. Задача её заводит; если
объём окажется несоизмерим (нужен runtime для порождённого ST), она **выделяется в
отдельную фичу** — Tier 1 ждать не должен.

Язык не меняется → версия не растёт (правило 22).
