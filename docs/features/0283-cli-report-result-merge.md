## Краткое описание

**Печать результата компиляции в CLI живёт в двух почти одинаковых функциях.**
Замер при закрытии [предупреждения генераторов возвращаются вызывающему, а не печатаются из библиотеки](0168-generator-warnings-return.md)
(2026-08-16): после приведения целей к одному контракту `report_simple_result`
и `report_hal_result` принимают **один и тот же** тип и делают одно и то же,
различаясь лишь тем, что первая знает `--verbose` (печатает канонический путь
входа), а вторая — нет. Слияние меняет наблюдаемое поведение
`c-hal`/`st-at`/`sv-mmio` (у них появился бы verbose-вывод), поэтому 0168 его
сознательно не делала. Кандидат: свести к одной функции, решив, каким должен
быть `--verbose` у адрес-потребляющих целей.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по правилу 17.

### Context

После того как фича привела все цели к контракту
`Result<Vec<Diagnostic>, Diagnostic>`, печать результата в CLI осталась в
**двух** функциях — `report_simple_result` и `report_hal_result`. Тип у них
один, тело одно, а различие единственное: первая знает `--verbose`, вторая нет.

**Замер-20** (прогон инструмента):

```
$ taktc compile --verbose -t st    …/elevator_mini.takt -o out
Скомпилировано: /Volumes/…/examples/elevator_mini.takt → out (st)

$ taktc compile --verbose -t st-at …/elevator_mini.takt -o out
Скомпилировано: examples/elevator_mini.takt → out/ (st-at)
```

То есть `c-hal`, `st-at` и `sv-mmio` флаг **молча игнорировали**: пользователь
просит подробность, инструмент делает вид, что просьбы не было. Заодно виден
второй разнобой: в verbose-ветви путь выхода печатался **без** слэша, в
обычной — со слэшем.

`--verbose` в README не описан, контракта на форму строки нет; тестов,
завязанных на неё, в дереве не было.

### Decision Drivers

1. **Молчаливо проигнорированный флаг — дефект**, а не косметика: ответ
   инструмента не соответствует просьбе.
2. **Две функции об одном предмете расходятся** — записанный урок проекта
   (0084/0193/0195); здесь они уже разошлись.
3. **0168 не сделала слияния сознательно**, потому что оно меняет наблюдаемое
   поведение; решение об изменении принимается отдельно — то есть здесь.

### Considered Options

#### Option A. Оставить две функции, добавить `--verbose` во вторую

**Pros:** минимальная правка.
**Cons:** две копии одного тела остаются и разойдутся снова — уже разошлись
однажды.

#### Option B. Одна функция `report_result` на все цели

**Pros:** различий нет по построению; `--verbose` действует везде; форма строки
одна.
**Cons:** меняется наблюдаемый вывод трёх целей (появляется канонический путь
при `--verbose`) и verbose-вывод остальных (добавляется слэш).

#### Option C. Убрать `--verbose` из «простых» целей

**Pros:** единообразие тоже достигается.
**Cons:** изъятие работающей возможности ради симметрии; пользователю она
полезна.

### Decision

Принимается **Option B**: обе функции заменены на `report_result`, `--verbose`
действует у всех целей, путь выхода печатается со слэшем в обоих режимах (это
каталог).

Контроль — `takt-lang/tests/targets/cli_report_result_tests.rs`: пять проверок,
включая **контрпример** (без флага путь печатается как передан) и глушение
`--quiet` у обеих ветвей прежнего деления.

### Consequences

#### Положительные

- `--verbose` перестал быть флагом-обманкой для трёх целей.
- Форма строки результата одна и контролируется тестами.
- Копия тела исчезла — расходиться больше нечему.

#### Отрицательные / Action items

- **Наблюдаемое изменение:** при `--verbose` цели `c-hal`/`st-at`/`sv-mmio`
  печатают абсолютный путь входа, а verbose-вывод прочих целей получил слэш
  после пути выхода. Контракта на эту строку нет (README её не описывает), в
  дереве от неё никто не зависел.
- Цель `c` по-прежнему печатает своё сообщение (оно перечисляет пути поиска) —
  это осознанное исключение, названное в док-комментарии.

#### Acceptance criteria

1. `--verbose` даёт канонический путь у «простой» и у адресной цели.
2. **Контрпример:** без флага печатается путь как передан.
3. `--quiet` глушит результат у обеих ветвей.
4. Путь выхода печатается со слэшем в обоих режимах.
5. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Свести печать результата к одной функции, решив вопрос, оставленный фичей:
каким должен быть `--verbose` у адрес-потребляющих целей. ADR принял Option B —
одинаковым для всех.

### Замер (снят 2026-08-20, правило 30)

Кандидат подтверждён **прогоном инструмента**, и замер нашёл второй разнобой,
которого кандидат не называл.

| Цель | `--verbose` | Что печатается |
|---|---|---|
| `st` | учитывается | абсолютный путь входа, выход **без** слэша |
| `st-at` | **игнорируется** | путь как передан, выход со слэшем |

То есть различий было два: наличие verbose и форма пути выхода.

**Контроль совместимости:** `--verbose` в README не описан (греп по документу —
пусто), строка «Скомпилировано:» в тестах и скриптах не разбирается (греп по
`takt-lang`, `takt-sim`, `scripts` — только упоминания в комментариях). Значит
изменение наблюдаемого никого в дереве не ломает.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет (0168 и 0275, на которые опирается устройство, закрыты).
- **Влияние на порядок:** никого не разблокирует.

  сообщение с путями поиска).

## Разработка

### Задача

#### Что сделано

Обе функции заменены на одну — `report_result` в `takt-lang/src/compile_cli/mod.rs`.
Восемь мест вызова (по одному на цель) зовут её.

Различия, которые были между копиями, сняты:

| Что | Было | Стало |
|---|---|---|
| `--verbose` | учитывался только «простой» ветвью | учитывается всеми |
| путь выхода в verbose-режиме | без слэша | со слэшем, как в обычном |

Без изменений: печать ошибки и выход с кодом 1, `print_warnings` с реестром
файлов (границы фич и 0275 на месте), собственное сообщение цели `c`
(оно перечисляет пути поиска — названное исключение).

#### Контроль

`takt-lang/tests/targets/cli_report_result_tests.rs` — пять проверок:
`--verbose` у «простой» и у адресной цели, **контрпример** (без флага путь как
передан), глушение `--quiet` у обеих ветвей, форма пути выхода в обоих режимах.

Контрпример обязателен: без него «печатает канонический путь» проходило бы и
у реализации, печатающей его всегда.

#### Проверка

```sh

cargo test --test targets cli_warning_position_tests::   # границы 0228 целы
```
