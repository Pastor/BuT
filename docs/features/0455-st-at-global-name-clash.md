# Фича: Имя размещённого порта против имён POU у цели st-at

- **Номер:** 0455
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2 (вывод цели не транслируется `iec2c` при нулевом коде возврата
  `taktc` — прошивку для ПЛК из такой модели не собрать)
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат, заведённый фичей
  [формулы и инварианты в переборе](0454-matrix-formulas.md)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Адресованный порт цель `st-at` печатает в `VAR_GLOBAL` конфигурации, а рядом
стоят имена блоков, программы, ресурса и экземпляра. Пространство имён IEC
плоское и **регистронезависимое** — совпадение давало невалидный ST. Фича
заводит отказ `ST-024` с названной причиной.

> Фича заведена из блока кандидатов.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

Замер-31 (файл `probe.takt` → корневая модель `Probe`), семь имён
порта:

| Имя порта | Что оно занимает в выводе | `iec2c` |
|---|---|---|
| `probe` | `FUNCTION_BLOCK Probe` | **отвергает** |
| `probewrap` | `FUNCTION_BLOCK ProbeWrap` | **отвергает** |
| `probemain` | `PROGRAM ProbeMain` | **отвергает** |
| `res0` | `RESOURCE Res0` | **отвергает** |
| `inst0` | `PROGRAM Inst0 WITH …` | **отвергает** |
| `probeconfig` | `CONFIGURATION ProbeConfig` | принимает |
| `tick` | `TASK Tick` | принимает |

Контрольный вход: та же **локальная** переменная с именем `probe` принимается —
она живёт внутри блока.

Ответ `iec2c` обманчив («invalid global variable(s) declaration»), а код
возврата `taktc` — **нулевой**: класс виден только прогоном инструмента.

### Decision

Отказ `ST-024` при построении `VAR_GLOBAL`: имя порта сверяется **без учёта
регистра** со списком имён, которые цель печатает рядом. Список — из замера
(блоки, `<Root>Main`, `Res0`, `Inst0`), а не из стандарта: две записи, которые
`iec2c` принимает, в него не входят.

### Considered Options

- **A. Отказ `ST-024`** — принят: то же решение, что у `ST-023` (0378) —
  «отказ, а не переименование за автора».
- **B. Переименовать порт в выводе** — отвергнут: имя размещённой переменной
  видит инженер ПЛК, оно же стоит в выгружаемой карте адресов.
- **C. Расширить `ST-023`** — отвергнут: смысл иной (там имя **типа**), а код
  диагностики — это смысл.

### Consequences

Вывод корпуса не меняется: таких имён в `examples/` нет. Модель с совпадением
теперь отвергается **до** записи файла, а не после прогона `iec2c`.

#### Acceptance criteria

- A1. Каждое из пяти занятых имён даёт `ST-024`.
- A2. Имена, которые `iec2c` принимает (конфигурация, задача, обычное), и
  **локальная** переменная — не задеты.
- A3. Текст отказа называет причину и говорит, что модель валидна для прочих
  целей.

## Анализ

### Замер

Таблица выше. Дополнительно проверено: у цели `st` (без адресов) тот же порт
принимается — `VAR_GLOBAL` там нет вовсе, и класс принадлежит именно `st-at`.

### Зависимости фичи

[имя переменной, совпавшее с именем типа, у цели st](0378-st-name-type-clash.md) — `ST-023` и приём «отказ, а не
переименование»; [список зарезервированных имён IEC проверяется прогоном](0342-st-reserved-names.md) — список зарезервированных
имён IEC, проверяемый прогоном.

### Требования и проверяемые условия

- R1. A1…A3 выше.
- R2. Список занятых имён — из замера, и контрольные входы стоят рядом с
  отказами.

### Критерии приёмки и способ проверки

`st_global_name_clash_tests` (пять отказов + четыре контроля), полный
`precheck.sh`.

### Редакторский слой

**Не затронут:** язык не меняется.

### Особенности по обратной функциональности

Модель, которая прежде давала невалидный ST, теперь получает отказ с причиной.
Это ужесточение — но оно заменяет «файл на диске, который не транслируется».

### Риски и зависимости

Риск — ложный отказ на имени, которое `iec2c` на самом деле принимает; он снят
контрольными входами (`probeconfig`, `tick`, локальная переменная).

## Итог

Закрыт класс, найденный осью формул: он оказался не про формулы, а про имена —

разрастания.
