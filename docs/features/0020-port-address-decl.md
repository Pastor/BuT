# Фича: Адрес порта — размещение и потребление (карта адресов)

- **Статус:** ГОТОВО (2026-07-14)
- **Зависит от:** нет
- **Крейт:** `grammar` (версия языка 0.1.0 → 0.2.0, аддитивно)

## Краткое описание

Подсистема привязки портов к аппаратным адресам. Источники (по возрастанию
приоритета): инлайн `:=` (сахар) → оператор `address NAME = <expr>;` в модели →
внешняя `.ld`-подобная карта (`--address-map`). Все источники наполняют единый
`AddressMap: PortId → Address`, из которого генерируется C-таблица адресов и
принятый по умолчанию HAL. `-D`/инъекция define’ов, SVD-экспорт и ST `AT %` вынесены в
отдельные фичи/кандидаты.

## Декомпозиция (см. анализ)

- **0020-01** — `.lam`-грамматика + AST оператора `address`.
- **0020-02** — семантика `AddressMap` + приоритет + диагностики конфликта/висячей.
- **0020-03** — внешняя `.ld`-подобная карта (`--address-map`, наложение + warning).
- **0020-04** — полнота по достижимости (опора на `unused.rs`).
- **0020-05** — потребление в C: таблица адресов + принятый по умолчанию HAL (`*(volatile*)`).

## Риски

- Жёсткое ключевое слово `address` — коллизия с идентификаторами (grep + миграция).
- Новый парсер `.ld`-подобного формата (отдельный мини-язык).
- Семантика приоритета/полноты — двухпроходность; не сломать колбэк-HAL.

### Context

Адрес порта сегодня задаётся **инициализатором** в самом объявлении:

```lam
in  BTN: u8 := 0x200000;      // 0x200000 — аппаратный адрес порта
out LED: bit := 0x200004;
in  WAIT: bit := 0x44533932:33;  // адрес:бит
```

Грамматика (`grammar.lalrpop`): `("in"|"out"|"inout") name (":" Type)? (":=" Expression)? ";"`.
Выражение-адрес попадает в `VariableDefine::Port { initializer }`.

**Критическая находка (проверено в коде, 2026-07-14).** Числовой адрес **не
эмитится в генерируемый C вообще**. Порт компилируется в **enum-вариант**
(`ROOT_BTN`), а чтение/запись идут через **HAL-колбэки**
(`read_bit(port_enum, userdata)` — `generator/c/c_expr.rs:261`). Значение `expr`
хранится в `VariableNode::Port`, но C-генератор берёт лишь `name, ty, upper` и
адрес игнорирует. Единственная проверка — валидность бита в `0xADDR:bit`
(`validate.rs`). То есть маппинг enum→адрес сейчас живёт **вне языка**, в HAL,
который пишет пользователь; адрес в `.lam` — фактически метаданные.

**Следствие.** Задача состоит из **двух независимых решений**, которые
первая редакция ADR смешивала:

1. **Размещение** — где и каким синтаксисом записан адрес.
2. **Потребление** — что компилятор делает с адресом.

Пока (2) = «ничего», выбор синтаксиса в (1) — косметика. Поэтому решение
принимается по обеим осям сразу.

**Проблема (мотивация).** Объявление порта (имя, тип, направление) и его
аппаратный **адрес** — разные сущности; адрес зависит от платформы/ревизии. Их
слияние в одной строке мешает: (а) держать карту адресов отдельно от логики;
(б) переопределять адреса под разные платформы без правки объявлений (оверлеи).

#### Как адрес/привязку к железу задают другие языки (обзор)

| Семья | Пример | Размещение |
|---|---|---|
| Инлайн в объявлении | `in BTN: u8 := 0x200000;` (Lam); `#define BTN (*(volatile u8*)0x200000)` (C) | в объявлении |
| Отдельная клауза, тот же файл | `for Reg'Address use To_Address(16#200000#);` / аспект `with Address =>` (Ada) | рядом с объявлением |
| Выделенный локатор | `VAR btn AT %IX1.0 : BOOL; END_VAR` (IEC 61131-3 ST) | в объявлении, оператор `AT` |
| Внешний файл-описание | SVD (карта регистров) → `svd2rust`; device tree `.dts` + **оверлеи**; линкер `.ld` (`PROVIDE`, `SECTIONS`) | отдельный файл, читается тулчейном |
| Препроцессор / build-time | `-DBTN_ADDR=0x200000`, config-header (C/CMake) | вне исходника, подстановка при сборке |

Для промышленной автоматики и embedded (профиль Lam) индустрия сходится на двух
семьях: **выделенный локатор** (IEC `AT %…`) и **внешний файл-описание с
оверлеями** (SVD/DT/ld) — именно ради «адрес отдельно от логики, оверлеи под
платформы», что и есть мотивация 0020.

### Decision Drivers

1. **Разделение ответственностей** — объявление порта ≠ его адрес.
2. **Потребление адреса** — адрес должен стать реально используемым артефактом,
   а не мёртвыми метаданными.
3. **Платформенные оверлеи** — переопределять адреса под платформу/ревизию без
   правки модели.
4. **Обратная совместимость** — существующие `.lam` с инлайн-адресом
   работают без изменений.
5. **Простота грамматики/LR(1)** и **однозначность** — исключить
   противоречивое задание адреса.
6. **Переиспользование инфраструктуры** — по возможности не плодить парсеры.

### Considered Options (исходная редакция)

Первая редакция рассматривала только ось *размещения*:

- **Option A.** Отдельный оператор `address NAME = <expr>;` (аддитивно, инлайн —
  сахар). *Прецедент: Ada address clause.*
- **Option B.** Блок `address { BTN = 0x…; LED = 0x…; }`.
- **Option C.** Атрибут-постфикс `in BTN: u8 @ 0x200000;`.
- **Option D.** Статус-кво.

Эти варианты остаются валидными **внутри** оси размещения, но сами по себе не
отвечают на ось потребления и на оверлеи — поэтому решение расширено.

### Decision (пересмотр 2026-07-14)

Принимается **гибрид** на базе единого внутреннего слоя.

#### Ядро: `AddressMap`

Компилятор после семантики строит канонический слой
**`AddressMap: PortId → Address { value, bit? }`**. Всё остальное — либо
*источники*, наполняющие карту, либо *потребители*, читающие её. Это разъединяет
«где записан адрес» и «что с ним делают».

```
источники (размещение)                 AddressMap             потребители
──────────────────────                ────────────            ───────────
inline  in BTN:u8 := 0x…;  ─┐                            ┌─►  C: таблица + дефолтный HAL
address BTN = 0x…;         ─┼──►  PortId → Address ──────┼─►  ST/PLC: AT %IX…  (позже)
внешняя карта stm32.map    ─┤     (+ диагностики)        └─►  SVD-подобный экспорт (позже)
-D BTN_ADDR=0x…            ─┘
```

#### Источники и приоритет

Порядок разрешения (по возрастанию приоритета — **выигрывает верхний слой**):

1. **inline** `in BTN: u8 := 0x…;` — базовый слой (десугарится в неявную привязку);
2. **`address NAME = <expr>;`** — оператор в модели `.lam` (**новое, жёсткое
   ключевое слово `address`**);
3. **внешняя карта** — **отдельный `.ld`-подобный формат** (файл вида
   `NAME = 0xADDR;`), читается флагом `--address-map FILE`; платформенный наложение
   **главнее** модели.

Плюс **`-D` инъекция символов**: `--define BTN_ADDR=0x200000` вводит константу в
среду, которую могут использовать выражения адреса (`address BTN = BTN_ADDR;`).
Это не отдельный парсер, а подстановка в окружение констант.

```ebnf
@startebnf
(* .lam: инлайн-сахар и новый оператор *)
PortDecl    = ("in" | "out" | "inout"), name, [":", Type], [":=", address (* сахар *)], ";";
AddressDecl = "address", name, "=", Expression, ";";
(* внешняя карта .ld-подобная (отдельный формат, расширяемый позже) *)
AddressMapFile = { MapEntry | Comment };
MapEntry       = name, "=", address, ";";
@endebnf
```

#### Правила разрешения и диагностики

- **Двойное задание в одной области** (напр. inline `:=` **и** `address` для
  одного порта в модели) → **ошибка** (SE-код).
- **Кросс-уровневое перекрытие** (внешняя карта переопределяет модель) →
  **warning** (ожидаемое поведение наложения, но заметное).
- **Висячая привязка** — `address`/запись карты для несуществующего порта →
  **ошибка**.
- **Полнота карты** — адрес **обязателен** для портов, **достижимых
  кодогенерацией** (переиспользуем анализ достижимости из `semantic/unused.rs`);
  мёртвые/неиспользуемые порты **не** требуют адреса. Отсутствие адреса у
  достижимого порта при генерации кода → **ошибка** (по целевой платформе).

#### Потребители

- **C:** из `AddressMap` эмитим таблицу/`#define` и **принятую по умолчанию реализацию HAL**
  (`read_bit`/`write_bit` через `*(volatile*)addr`) — закрывает текущий пробел
  «адрес мёртв». Пользовательский HAL по-прежнему возможен (адрес не ломает
  существующий колбэк-интерфейс).
- **ST/PLC:** `address → AT %…` — реализуется вместе с будущим **ST-генератором**
  (кандидат в `FEATURES.md`).
- **SVD-подобный экспорт:** `lamc address-map --emit …` выгружает карту наружу
  (отдельная фича).

#### Что **не** выбрано и почему

- **Внешняя карта как ограниченный `.lam`-фрагмент** — отклонено: заказчик выбрал
  **отдельный `.ld`-подобный формат** (проще для платформенных инженеров,
  привычная модель линкер-скрипта; расширение формата — позже).
- **`address` как контекстное ключевое слово** — отклонено в пользу **жёсткого**
  ключевого слова (однозначность важнее; риск коллизии закрывается миграцией
  идентификаторов `address`, см. Action items).

### Consequences

#### Положительные

- Объявление порта и адрес разделяемы; карта выносится во внешний файл; оверлеи
  под платформы — без правки модели.
- Адрес перестаёт быть мёртвым: C-таблица/принятый по умолчанию HAL, задел под ST `AT %` и
  SVD-экспорт.
- Единый `AddressMap` разъединяет размещение и потребление — новые источники и
  потребители добавляются независимо.
- Обратная совместимость полная: инлайн-форма работает как раньше.

#### Отрицательные / Action items

- **Ключевое слово `address`** (жёсткое) — правка `lexer.rs` (KEYWORDS); риск для
  моделей с идентификатором `address`. → grep по `examples/`/фикстурам; при
  коллизии — миграция имён.
- **Новый парсер `.ld`-подобной карты** — отдельный мини-формат (не
  переиспользует LALRPOP-грамматику `.lam`); нужен свой лексер/парсер и
  диагностики путей/дублей.
- **Семантика:** новый проход построения `AddressMap` (сбор источников →
  разрешение приоритета → диагностики конфликта/висячей/полноты); опора на
  достижимость из `unused.rs`.
- **C-генератор:** новый режим эмиссии таблицы адресов и принятого по умолчанию HAL из
  `AddressMap`.
- **`-D`/инъекция define’ов** и **SVD-экспорт** — выносятся в **отдельные фичи**
  (кандидаты в `FEATURES.md`); **ST `AT %`** — в фичу «ST-генератор».
- Язык расширен (оператор `address`, семантика карты) → **повышение версии
  языка**; крейт `grammar` — минорный бамп по SemVer.

#### Пере-декомпозиция фичи из «малого синтаксиса» становится **подсистемой привязки к железу**. Ядро
(эта фича) — `AddressMap` + оператор `address` + внешняя `.ld`-карта + C-таблица/
принятый по умолчанию HAL + диагностики. `-D`, SVD-экспорт, ST `AT %` — отдельные
фичи/кандидаты. Детали — в анализе.

#### Acceptance criteria

1. `address NAME = <expr>;` парсится, привязывается к порту `NAME`; жёсткое
   ключевое слово `address`.
2. Внешняя `.ld`-подобная карта читается `--address-map`, переопределяет модель
   (наложение), даёт **warning** при перекрытии.
3. Инлайн-форма `:= <addr>` работает без изменений (регресс = 0).
4. Двойное задание в одной области → **ошибка**; висячая привязка → **ошибка**.
5. Порт, **достижимый** кодогенерацией и без адреса → **ошибка**; мёртвый порт
   без адреса — ОК.
6. C-генератор эмитит таблицу адресов и принятый по умолчанию HAL из `AddressMap`
   (`*(volatile*)addr`); поведение сходно с ручным HAL.
7. Нет новых LR(1)-конфликтов в `.lam`-грамматике.

## Анализ

### Цель и контекст

Дать возможность задавать аппаратный адрес порта отдельно от объявления **и**
сделать адрес реально потребляемым артефактом. По ADR (пересмотр) — гибрид:

- **Размещение** (по возрастанию приоритета): inline `:=` (сахар) → оператор
  `address NAME = <expr>;` в модели → внешняя `.ld`-подобная карта
  (`--address-map`); плюс `-D` инъекция символов.
- **Потребление:** C-таблица + принятый по умолчанию HAL (это ядро); ST `AT %` и
  SVD-экспорт — отдельные фичи.
- Связующее звено — `AddressMap: PortId → Address { value, bit? }`.

**Находка, определившая пересмотр:** адрес сейчас **не эмитится в C** (порт →
enum, read/write через HAL-колбэки; `generator/c/c_expr.rs:261`) — то есть до
[адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md) адрес был мёртвыми метаданными.

### Зависимости фичи

- **Зависит от:** нет. Затрагивает `grammar` (лексер, `.lam`-грамматика, новый
  парсер `.ld`-карты, семантика портов/`AddressMap`, C-генератор). Пересечения с
  0019 нет.
- **Разблокирует:** задел под кандидаты «ST-генератор» (`AT %`), «`-D`/define»,
  «SVD-экспорт» — они читают `AddressMap`.

### Требования и проверяемые условия

- **R1. Оператор `address`.** `address NAME = <expr>;` в модели привязывает адрес
  к порту `NAME`; `address` — **жёсткое** ключевое слово.
- **R2. Совместимость.** Инлайн-форма `in NAME: T := <addr>;` работает без
  изменений; существующие `.lam` не ломаются (регресс = 0).
- **R3. `AddressMap` и приоритет.** Компилятор строит `PortId → Address` из всех
  источников; приоритет: inline < `address` в модели < внешняя карта.
- **R4. Диагностика конфликта в одной области.** Адрес задан и inline, и через
  `address` для одного порта → **ошибка** (новый SE-код).
- **R5. Диагностика висячей привязки.** `address`/запись карты для
  несуществующего порта → **ошибка**.
- **R6. Внешняя `.ld`-подобная карта.** Отдельный формат `NAME = 0xADDR;` (+
  комментарии), читается `--address-map FILE`; переопределяет модель (наложение);
  перекрытие → **warning**.
- **R7. Полнота карты.** Адрес обязателен для портов, **достижимых
  кодогенерацией** (переиспользуем достижимость из `semantic/unused.rs`); мёртвый
  порт без адреса — ОК; отсутствие адреса у достижимого порта → **ошибка** (по
  цели).
- **R8. Потребление в C.** Из `AddressMap` генерируются таблица адресов и
  принятый по умолчанию HAL (`read_bit`/`write_bit` через `*(volatile*)addr`).
- **R9. Без новых LR(1)-конфликтов** в `.lam`-грамматике.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | `address NAME = expr;` парсится и привязывается | фикстура `valid/port_address_separate.lam` + тест |
| A2 | Регресс инлайн-формы = 0 | `cargo test --features lsp -- --test-threads=1` |
| A3 | Конфликт в одной области → ошибка | контрпример `invalid/port_address_conflict.lam` |
| A4 | Висячая привязка → ошибка | контрпример `invalid/port_address_dangling.lam` |
| A5 | Внешняя карта переопределяет модель + warning | фикстура карты `*.map` + тест разрешения приоритета |
| A6 | Достижимый порт без адреса → ошибка; мёртвый — ОК | пара фикстур (используемый/мёртвый порт) |
| A7 | C: таблица адресов + принятый по умолчанию HAL из карты | зонд вывода C, затем assertions против захвата |
| A8 | Нет LR(1)-конфликтов | `cargo build` без предупреждений |

### Особенности по обратной функциональности

Изменение **аддитивное** для `.lam`: инлайн-форма не отменяется; существующие
файлы валидны. Новое — оператор `address`, внешний формат карты, C-эмиссия
адресов. Регресс = 0 (R2/A2).

Язык расширяется (оператор + семантика карты) → **версия языка повышается**; крейт `grammar` — минорный бамп по SemVer.

### Риски и зависимости

- **Ключевое слово `address` (жёсткое)** — коллизия с идентификаторами в `.lam`.
  → grep по `examples/`/фикстурам; при коллизии — миграция имён.
- **Новый парсер `.ld`-карты** — отдельный мини-формат, свой лексер/диагностики
  (пути, дубли записей). Держать простым; расширение формата — позже.
- **Семантика приоритета/полноты** — двухпроходность: сначала собрать порты и все
  источники, затем разрешить приоритет и проверить достижимость.
- **C-эмиссия HAL** — не ломать существующий колбэк-интерфейс; принятый по умолчанию HAL —
  дополнение, а не замена.

### Декомпозиция разработки

- **0020-01** — `.lam`-грамматика + AST: оператор `address NAME = <expr>;`,
  ключевое слово в лексере, узел AST, фикстуры парсинга (R1, R9).
- **0020-02** — семантика: `AddressMap`, разрешение приоритета (inline < `address`),
  диагностики конфликта (R4) и висячей привязки (R5) (R3).
- **0020-03** — внешняя `.ld`-подобная карта: парсер формата, флаг
  `--address-map`, наложение + warning (R6).
- **0020-04** — полнота по достижимости (R7, опора на `unused.rs`).
- **0020-05** — потребление в C: таблица адресов + принятый по умолчанию HAL из `AddressMap`
  (R8).

(Декомпозиция ориентировочная; уточняется при реализации.)

### Вынесено в отдельные фичи/кандидаты

- **`-D`/инъекция define’ов** — символы в среде констант для выражений адреса.
- **SVD-подобный экспорт** — выгрузка `AddressMap` наружу.
- **ST `AT %`** — в рамках фичи «ST-генератор» (кандидат `FEATURES.md`).

## Разработка

### Задача

> **Статус:** ВЫПОЛНЕНО (лексер + грамматика + AST реализованы, LR(1) без
> конфликтов, тесты зелёные). Семантика (`AddressMap`, привязка, диагностики) —
> задача.

#### Что было

Адрес порта задавался только инлайн-инициализатором в объявлении
(`in BTN: u8 := 0x200000;`). Отдельного оператора задания адреса не было. В
лексере уже существовал терминал адресного литерала `address =>
Token::AddressLiteral(...)` (для формы `0xADDR:bit`) — это **другой** терминал,
не путать с ключевым словом.

#### План реализации (по шагам)

1. **Лексер (`parser/lexer.rs`).** Новый токен-ключевое слово `Token::Address`;
   запись `"address" => Token::Address` в `KEYWORDS`; `Display`. Жёсткое ключевое
   слово (решение ADR).
2. **Грамматика (`grammar.lalrpop`).** Терминал `"address" => Token::Address` в
   extern-мапе (сосуществует с bare-терминалом `address` = адресный литерал);
   правило `AddressDefine: "address" IdentifierOrError "=" Expression ";"`
   (связка `=`, как в определениях имён); вариант
   `ModelElement::Address`.
3. **AST (`parser/ast.rs`).** Структура `AddressDefine { loc, name:
   Option<Identifier>, value: Expression }` и вариант `ModelElement::Address(Box<…>)`.
4. **Исчерпываемость match.** `semantic/docs.rs::element_start` и
   `lsp.rs::symbols_from_model` — новые arm (`docs.rs` — `loc.start()`; LSP —
   no-op). `semantic/tree.rs::construct_model` — цепочка `if let …`, новый вариант
   игнорируется естественно (семантика в 0020-02). `lib.rs`-проходы — `_ => {}`.
5. **Тесты (сперва зонд, затем ассерты — CLAUDE.md).**

#### Что сделано (факт)

- **`parser/lexer.rs`:** вариант `Token::Address`, `Display => "address"`,
  `"address" => Token::Address` в `KEYWORDS`.
- **`grammar.lalrpop`:** `"address" => Token::Address` в extern-мапе;
  `AddressDefine` = `"address" IdentifierOrError "=" Expression ";"`;
  `AddressDefine => ModelElement::Address(Box::new(<>))` в `ModelElement`.
- **`parser/ast.rs`:** `AddressDefine` (derive `Debug, PartialEq, Eq, Clone` +
  условный serde) и `ModelElement::Address(Box<AddressDefine>)`.
- **`semantic/docs.rs`:** arm `Address(a) => Some(a.loc.start())`.
- **`lsp.rs`:** `Address(_)` в no-op-группе `symbols_from_model`.
- **Тесты:**
  - `lexer_tests.rs`: `address_keyword_produces_address_token`; `address`/`inout`
    добавлены в `is_keyword`-список; `address` — в фикстуру `keywords.lam`.
  - `parser_tests.rs`: `address_operator_parses_to_model_element_address`
    (имя + `Expression::Number(0x200000)`), `…_accepts_bit_addressed_literal`
    (`Expression::Address(_,0x200004,3)`), `…_coexists_with_port_declaration`.
  - `semantic_tests.rs`: `address_operator_is_accepted_and_ignored_by_semantics`
    (строится, адрес пока игнорируется).
  - Фикстура `tests/data/parser/valid/port_address.lam` (авто-подхват).

#### Заметки для 0020-02

- **Голый `0x…` → `Expression::Number`**, `0xADDR:bit` → `Expression::Address`;
  разрешение адреса должно принимать оба (число и адресный литерал).
- В `construct_model` оператор сейчас **игнорируется** — там появится сбор в
  `AddressMap` и приоритет источников (inline < `address` < внешняя карта).
- Диагностики (конфликт в одной области, висячая привязка, полнота по

### Задача

> **Статус:** ВЫПОЛНЕНО (захват привязок + диагностики конфликта/висячей
> привязки; тесты зелёные). Внешняя `.ld`-карта и приоритет-наложение — 0020-03;
> полнота по достижимости — 0020-04; потребление в C — 0020-05.

#### Что было

После 0020-01 оператор `address` парсился в `ModelElement::Address`, но
`construct_model` его **игнорировал** — привязка нигде не сохранялась, порт
оставался без адреса, диагностик не было.

#### Что сделано (факт)

- **`semantic/mod.rs`:** новый узел `AddressBindingNode { port, loc, value }` и
  поле `ModelNode::address_defs: Vec<AddressBindingNode>`. Поле добавлено в
  full-literal конструкторы (`ModelNode::new`, клон с переименованием);
  `..Default::default()`-сайты и `#[derive(Default)]` подхватывают пустой `Vec`
  автоматически. В `PartialEq for ModelNode` **не** включено (не часть
  идентичности модели, как `loc`/`type_locs`).
- **`semantic/tree.rs` (`construct_model_stage0`):** новый arm
  `ModelElement::Address(def)` — извлекает имя порта (`extract_name`) и сохраняет
  привязку в `address_defs` (значение — сырое `ExpressionNode::Unresolved`).
  Захват отделён от проверки: порт может объявляться **после** оператора.
- **`semantic/validate.rs`:** `check_port_addresses(model)` в конвейере
  `validate_model` (после `check_array_sizes`). Диагностики:
  - **SE-048** (R5) — `address` ссылается на имя, которого нет среди портов
    модели (висячая привязка).
  - **SE-049** (R4) — адрес задан одновременно inline (`:= <addr>`) и оператором
    `address`, **либо** несколькими операторами `address` для одного порта.

  «Наличие inline-адреса» = `VariableNode::Port.expr != ExpressionNode::None`.

#### Тесты

- `semantic_tests.rs`:
  - `address_operator_is_captured_in_address_defs` — привязка попадает в
    `address_defs` с именем порта.
  - `example_port_address_separate_is_valid` — фикстура
    `valid/port_address_separate.lam` (адрес отдельным оператором, 2 порта) —

  - `port_address_conflict_inline_and_operator_is_error` →

  - `port_address_duplicate_operator_is_error` (из строки) → SE-049.
  - `port_address_dangling_reference_is_error` →
    `invalid/port_address_dangling.lam` → SE-048.

#### Решения и границы

- **Приоритет inline < `address`** (из ADR) внутри одной модели **не** реализуется
  как «тихое переопределение»: по решению заказчика (R4) наличие обоих источников
  для одного порта — **ошибка**. Приоритет-наложение (внешняя карта поверх модели с
  warning) появляется в 0020-03, где источники в разных областях.
- **Консолидированный `AddressMap`** (PortId → разрешённый адрес) **не** строится:
  без внешней карты (0020-03) и потребителя (0020-05) он спекулятивен. Сохранён
  сырой субстрат `address_defs`; понижение выражения-адреса в конкретное значение.

#### Заметки для 0020-03/05

- Голый `0x…` → `Expression::Number`, `0xADDR:bit` → `Expression::Address` —
  понижение адреса должно принимать оба (см. `value: ExpressionNode::Unresolved`).
- Внешняя карта наполняет тот же слой; правило приоритета — наложение поверх

### Задача

> **Статус:** ВЫПОЛНЕНО (парсер формата + наложение-предупреждения + флаг
> `--address-map`; тесты зелёные). Понижение адреса в целевой код и
> консолидированный `AddressMap`.

#### Что было

После 0020-02 адрес порта задавался только внутри `.lam` (inline или оператором
`address`). Внешнего платформенного наложения не было.

#### Формат карты (отдельный `.ld`-подобный мини-язык)

Намеренно **не** фрагмент `.lam` (решение заказчика). Построчный формат:

```text
// комментарий до конца строки
BTN = 0x00200000;
LED = 0x00200004:3;   // адрес:бит
CNT = 42;             // допускается десятичное
```

EBNF: `Entry = Name "=" Address ";"`; `Address = (0x-hex | dec) [":" dec]`.

#### Что сделано (факт)

- **`grammar/src/address_map.rs`** (новый модуль):
  - `AddressMapEntry { name, addr, bit: Option<i64>, loc }`.
  - `parse_address_map(src, file_no) -> Result<Vec<AddressMapEntry>, Vec<Diagnostic>>`
    — свой сканер с байтовыми `Location`, комментарии `//`, устойчивость к
    ошибкам (восстановление до `;`, сообщаются все ошибки). Коды:
    **AM-001** (имя), **AM-002** (`=`), **AM-003** (адрес), **AM-004** (`;`),
    **AM-005** (битый литерал), **AM-006** (дубликат записи).
  - `address_map_overlay_warnings(model, &entries) -> Vec<Diagnostic>` — наложение
    на модель: **SE-050** (карта переопределяет адрес порта, заданный inline или
    оператором `address`), **SE-051** (запись для несуществующего порта).
- **`grammar/src/lib.rs`:** `pub mod address_map;` + реэкспорт
  `parse_address_map`, `address_map_overlay_warnings`, `AddressMapEntry`.
- **`grammar/src/bin/lamc.rs`:** флаг `--address-map <файл>` (`CompileOptions.
  address_map`); в main-потоке карта читается, разбирается (ошибки формата →
  выход с кодом), затем печатаются наложение-предупреждения. Справка и таблица
  флагов дополнены.

#### Тесты

- Юнит-тесты `address_map.rs`: hex/dec/`:bit`, пустая карта, AM-002/004/005/006,
  восстановление (все ошибки).
- `grammar/tests/address_map_tests.rs`: наложение inline→SE-050, оператор→SE-050,
  порт без адреса модели → без предупреждений, висячая запись → SE-051,
  смешанный случай.
- `lamc.rs`: разбор `--address-map`, отсутствие по умолчанию, ошибка без
  аргумента.

#### Решения и границы

- **Приоритет** (внешняя карта > модель) выражен как **предупреждение об оверлее**
  (SE-050) на этапе 0020-03; фактическое переопределение значения при генерации —
  0020-05 (там внешняя запись побеждает inline/оператор).
- **Область проверки** — `variables` **переданной** модели (корневой). Порты во
  вложенных моделях наложение пока не покрывает (флоские имена карты); при
  необходимости — расширить в 0020-05.
- Числовой адрес карты пока **не** доходит до C — только валидация и
  предупреждения (потребитель — 0020-05).

- `cargo test --features lsp -- --test-threads=1` — все зелёные (612 lib + наборы);

### Задача

> **Статус:** ВЫПОЛНЕНО (аналитическая проверка полноты + тесты). Подключение к
> потребителю адресов (C-таблица/HAL) и эскалация в ошибку.

#### Что было

После 0020-01…03 адрес можно задать тремя источниками, но не было проверки, что
**используемый** порт вообще имеет адрес.

#### Что сделано (факт)

- **`semantic/validate.rs`:** `check_port_address_completeness(model,
  external_ports) -> Vec<Diagnostic>`. Достижимость порта берётся из
  `unused::compute_usage(model).ports` (порт используется в условиях/блоках/
  функциях). Для **используемого** порта без адреса (ни inline, ни оператором
  `address`, ни во внешней карте `external_ports`) — предупреждение **SE-052**.
  **Мёртвые** порты без адреса не предупреждаются. Результат отсортирован по
  позиции (детерминизм); обход рекурсивный по вложенным моделям.
- **`lib.rs`:** публичная обёртка `port_address_completeness_warnings(model,
  external_ports: &[String])`.

#### Почему предупреждение, а не ошибка (и почему не в конвейере)

В текущей C-модели адрес порта **не эмитится** (порты идут через HAL-колбэки), и
примеры (`elevator.lam`, `elevator_mini.lam`) объявляют используемые порты **без**
адресов. Жёсткая ошибка в `validate_model`/`compile_to_c` сломала бы их. Поэтому
[адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md)-04 — **аналитическая** функция: она не вызывается конвейером по умолчанию.
Требование «по цели» (R7) материализуется в 0020-05, где включается
адрес-потребляющая генерация (C-таблица/HAL): там потребитель вызывает эту
проверку и трактует SE-052 как ошибку, передавая в `external_ports` имена портов
из внешней карты.

#### Тесты

`grammar/tests/port_address_completeness_tests.rs`:
- используемый порт без адреса → SE-052;
- мёртвый порт без адреса → без предупреждений;
- используемый порт с inline-адресом → тихо;
- используемый порт с оператором `address` → тихо;
- используемый порт, покрытый внешней картой (`external_ports`) → тихо.

#### Заметки для 0020-05

- Вызвать `port_address_completeness_warnings` в адрес-потребляющем C-режиме,
  передав имена портов из разобранной внешней карты; трактовать SE-052 как ошибку.
- Тогда же строится консолидированный `AddressMap` (inline < `address` < внешняя
  карта) с понижением выражения-адреса в число.

#### Проверки

- `cargo build --bin lamc` — успешно.
- `cargo test --features lsp -- --test-threads=1` — все зелёные;
  `cargo fmt --check` чист; новых clippy-предупреждений нет (базлайн 106).

### Задача

> **Статус:** ВЫПОЛНЕНО (резолв `AddressMap` + цель `c-hal` + эмиссия таблицы и
> принятого по умолчанию HAL; вывод компилируется `cc -std=c99 -Wall`; тесты зелёные).

#### Решения заказчика

- **Форма вывода:** таблица адресов + принятый по умолчанию HAL (Вариант 1), деградация 2→3 по
  осуществимости.
- **Проверка:** новая цель `-t c-hal`; цель `c` — байт-в-байт как прежде (регресс = 0).
- **Внешняя карта:** участвует в резолве `AddressMap` для `c-hal`.

#### Что сделано (факт)

##### Резолв `AddressMap` (`address_map.rs`)

- `resolve_addresses(model, external) -> AddressResolution`: приоритет
  **inline < `address` < внешняя карта**; понижение выражения-адреса в `(addr,
  bit)` (`lower_addr_expr`); источник-победитель (`AddressSource`).
- Диагностики: **SE-052** (used-порт без адреса → ошибка полноты), **SE-050**
  (наложение карты), **SE-051** (висячая запись). Конфликт inline+`address` уже
  исключён семантикой (SE-049).

##### Пламбинг режима `c-hal`

- `generator/mod.rs` `GenerateOptions`: поля `hal: bool` и
  `address_map: HashMap<String, ResolvedAddress>` (обновлены `new`/`Default`).
- `lib.rs` `compile_to_c_hal(filename, source, out, search_paths, external,
  options) -> Result<Vec<Diagnostic>, Diagnostic>`: разрешает адреса, при
  SE-052-ошибке возвращает `Err`, иначе включает `hal` + карту и генерирует C;
  возвращает предупреждения (SE-050/051).
- CLI: цель `-t c-hal`; `--address-map` протянут в резолв; справка дополнена.

##### Эмиссия C (`generator/c/c_header.rs`)

- В режиме `hal` перед `#endif` эмитится блок: тип `{Root}_PortBinding { uintptr_t
  addr; int8_t bit; uint8_t width; }`, таблицы `static const {Enum}__ADDR[]`
  (индексы — те же enum-варианты), принятые по умолчанию `read_*`/`write_*` через
  `*(volatile T*)addr` (ширина из `get_c_type`; бит `<0` = весь регистр), и
  `{Root}_bind_default_hal({Root} *m)` (связывает только присутствующие
  классы/направления).
- Для одиночной модели без под-моделей в режиме `hal` добавляется `typedef struct
  {Root} {Root};` — иначе прототипы `{Root}_init({Root} *)` невалидны в C. Режим
  `c` не затронут.

#### Проверки

- Сквозной прогон `lamc … -t c-hal --address-map`: наложение BTN→`0x40000000`
  (SE-050), inline `:bit`, оператор `address`, принятый по умолчанию HAL.
- **Вывод компилируется** `cc -std=c99 -Wall -c` без ошибок.
- Режим `c` — 0 HAL-артефактов (регресс = 0, подтверждено тестом и codegen-тестами).
- Тесты: `address_map_tests.rs` (резолвер — 6), `codegen_tests.rs` (c-hal — 4:
  эмиссия/регресс/SE-052/наложение), CLI-разбор `-t c-hal`.
- `cargo test --features lsp -- --test-threads=1` — все зелёные; fmt/clippy чисты.

#### Найденное попутно (вне 0020)

Базовый генератор `c` **не** эмитит `typedef struct {Root} {Root};` для одиночной
модели без под-моделей → её `.h` не компилируется как отдельный C (прототипы
`{Root}_init({Root} *)`). В `c-hal` исправлено локально; для цели `c` —
пред­существующий баг, оформить отдельно (кандидат в `FEATURES.md`).

#### Границы

- Ширина bit-порта в таблице информативна (`int`→4); принятые по умолчанию bit-функции всегда
  используют `uint8_t` + извлечение бита.
- Наложение/таблица покрывают порты корневой модели (и под-модели через
  `collect_ports_by_class`); резолв полноты — по достижимости из `unused.rs`.

## Итог (что сделано)

Все под-задачи…05 выполнены; фича закрыта. Реализовано:

- **Оператор `address Имя = <адрес>;`** — жёсткое ключевое слово `Token::Address`,
  правило `AddressDefine`, узел `ast::AddressDefine`, `ModelElement::Address`
  (0020-01). Инлайн-форма `in P: T := <addr>;` сохранена (регресс = 0).
- **Семантика привязки** — `ModelNode::address_defs`, захват в `construct_model`,
  `check_port_addresses` в `validate_model`: **SE-048** (висячая привязка),
  **SE-049** (конфликт inline + `address` / дубликат) (0020-02).
- **Внешняя `.ld`-подобная карта** — модуль `address_map.rs`: `parse_address_map`
  (коды AM-001…006), `address_map_overlay_warnings` (**SE-050** наложение, **SE-051**
  висячая запись), CLI `--address-map` (0020-03).
- **Полнота по достижимости** — `port_address_completeness_warnings` /
  `check_port_address_completeness` (опора на `unused.rs`): используемый порт без
  адреса → **SE-052** (0020-04).
- **Потребление в C — цель `-t c-hal`** — `resolve_addresses` (консолидированный
  `AddressMap`, приоритет inline < `address` < внешняя карта), `compile_to_c_hal`,
  эмиссия таблицы адресов + принятого по умолчанию HAL (`*(volatile T*)addr`) +
  `bind_default_hal`; SE-052 в этом режиме — ошибка. Цель `c` — байт-в-байт как
  прежде; `c-hal`-вывод компилируется `cc -std=c99 -Wall` (0020-05).

**Диагностики:** SE-048, SE-049, SE-050, SE-051, SE-052; AM-001…006.
**Версия языка:** 0.1.0 → 0.2.0 (аддитивно).
**Вынесено в кандидаты (`FEATURES.md`):** `-D`/инъекция define’ов, SVD-экспорт,
ST `AT %` (в рамках ST-генератора), исправление typedef корня для цели `c`.
