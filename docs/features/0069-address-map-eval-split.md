Было 587 строк, стало **1054** без тестов (1116 с ними) — вычислитель выражений
адреса добавил ~460. Лимит ~1000 (`CLAUDE.md`) превышен.

- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0069-address-map-eval-split.md); исполняет запись реестра долга [разделение переросших модулей (validate.rs, lsp.rs, c_expr.rs)](0027-module-size-split.md#архитектура-adr); отдаёт долг, предвиденный анализом [инъекция define'ов для адресов (--define)](0042-address-defines.md#архитектура-adr)

### Context

`grammar/src/address_map.rs` — **1116** строк с тестами, **1054** без. Лимит —
1000 (`CLAUDE.md`, храповик `scripts/check-module-size.sh`).

**Уточнение против кандидата: сборка не падает.** Кандидат писал «Лимит ~1000
(`CLAUDE.md`) превышен», из чего можно заключить, что храповик красный. Он
**зелёный**: файл **числится в реестре узаконенного долга** —
`scripts/module-size-baseline.txt:31` → `1116 grammar/src/address_map.rs`. Прогон:
«проверено файлов, записей долга 22, превышение 12049 строк» — отказа нет.

Так вышло по хронологии: **0042 закрылась раньше 0027** (`b5aacfb` → `0eac9ed`),
поэтому к моменту, когда 0027 замораживала базу, файл уже был 1116 и вошёл в
реестр **законно**, как унаследованный долг. Храповик назад **не проворачивали**.

Отсюда суть фичи: не «починить отказ», а **снять запись из реестра**. Правило: «файл оттуда **не имеет права расти**, а уложившийся в лимит обязан быть из
реестра **удалён**» — и скрипт это проверяет (правило 3: «Незакрытая запись — файл
уложился в лимит, а запись осталась»).

#### Замер: файл распадается на восемь частей, из них четыре — самостоятельные темы

| Часть | Строки | Размер |
|---|---|---|
| шапка + импорты | 1–35 | 35 |
| **парсер `.ld`-карты** (`Scanner`, `parse_address_map`, `parse_entry`, `parse_int`) | 36–305 | **270** |
| наложение/предупреждения карты | 307–348 | 42 |
| типы разрешения (`AddressSource`, `ResolvedAddress`, `AddressResolution`) | 350–392 | 43 |
| **среда define** (`AddressEnv`, `parse_defines`, `is_valid_symbol`) | 394–563 | **170** |
| диагностики выражения | 565–610 | 46 |
| **вычислитель** (`apply_binary`, `eval_ast_addr`, `eval_addr_expr`, `resolve_symbol`) | 611–878 | **268** |
| **разрешение адресов** (`resolve_addresses`, `resolve_model`) | 879–1054 | **176** |

**Оценка кандидата подтверждена:** вычислитель + `AddressEnv` = 268 + 170 = **438**
строк (кандидат оценивал «~460»); остаток 1054 − 438 = **616** → под лимитом.

**Анализ 0042 это предвидел** («при росте вычислитель выделяется в
`address_map/eval.rs`»), но оценивал прирост в **150–200** строк — фактический
**~460**. То есть предвидение было верным, а оценка — вдвое оптимистичной.

### Decision Drivers

1. **Правило проекта — «дели по логике», а не по числу строк.** `CLAUDE.md`: «Размер
   модуля — не больше ~1000 строк; **дели по логике**». Лимит — индикатор, а не
   цель.
2. **Прецедент 0027 задал форму.** Разделённые `semantic/validate/` (9 тем),
   `lsp/` (9), `generator/c/c_expr/` (7); «контракт держит `mod.rs` реэкспортом —
   пути импорта у потребителей прежние».
3. **Реестр долга — не разрешение.** Уложился — обязан выйти из реестра.
4. **Ноль изменений поведения.** Это перекладка; любой дифф вывода = дефект.

### Considered Options

#### Option A. Вынести ровно вычислитель + `AddressEnv` (буквальный объём кандидата)

**Pros:**
- Минимальная правка; остаток 616 строк — под лимитом; запись из реестра уходит.
- Ровно то, что планировал анализ 0042.

**Cons:**
- **Делит по лимиту, а не по логике** (драйвер 1): парсер `.ld`-формата (270
  строк) остаётся в одном файле с разрешением адресов, хотя это **разные** темы —
  один читает текст внешнего файла, другой ходит по модели.
- 616 строк — «пока влезло»: следующая фича по адресам
  ([экспорт карты адресов во внешний формат](0043-address-map-export.md#архитектура-adr) — экспорт карты,
  [ключ карты адресов — голое имя порта](0084-address-map-qualified-key.md) — ключ карты) снова упрётся.

#### Option B. Разделить по темам: `address_map/{mod,parse,env,eval,resolve}.rs`

| Модуль | Что | Строк |
|---|---|---|
| `parse.rs` | парсер `.ld`-карты + наложение | ~310 |
| `env.rs` | `AddressEnv`, `--define` | ~170 |
| `eval.rs` | вычислитель выражения адреса | ~270 |
| `resolve.rs` | `resolve_addresses`, типы разрешения | ~220 |
| `mod.rs` | реэкспорт + шапка | ~40 |

**Pros:**
- **Делит по логике** (драйвер 1); каждая тема самостоятельна и проверяема
  отдельно.
- **Повторяет форму 0027** (драйвер 2): каталог + `mod.rs`-реэкспорт → пути
  импорта у потребителей **не меняются**.
- Даёт запас: соседние фичи по адресам (0043, 0084) правят **свой** модуль.
- Готовит место для [исправления](../fixes/0020-01-port-bit-out-of-range.md)
  (бит вне диапазона): проверка бита — тема `parse`/`resolve`, и в
  тысячестрочном файле её было бы некуда положить.

**Cons:**
- Больше файлов; дифф шире.

#### Option C. Не делать (оставить запись в реестре)

**Pros:** ноль работы.

**Cons:** реестр перестаёт быть долгом и становится разрешением (драйвер 3) —
ровно то, против чего 0027 и заводила храповик.

### Decision

Принимается **Option B**.

Кандидат предлагал Option A, и она **достаточна для лимита** — но лимит здесь
следствие, а не причина. Правило проекта требует делить **по логике**, а замер
показывает **четыре** самостоятельные темы, из которых парсер внешнего формата
(270 строк) не имеет с разрешением адресов ничего общего. Option A оставила бы их
вместе и упёрлась бы в лимит на следующей же фиче по адресам.

**Нормативные правила:**

1. **Каталог `address_map/` + `mod.rs`-реэкспорт** — форма 0027; **пути импорта у
   потребителей не меняются**.
2. **Поведение неизменно.** Любое изменение вывода целей — **дефект**, а не
   «побочный эффект».
3. **Запись `1116 grammar/src/address_map.rs` удаляется** из
   `scripts/module-size-baseline.txt`. Заменять её записями на новые файлы
   **нельзя**: они обязаны укладываться в лимит.
4. **Приоритет источников адреса не трогается** (inline < `address` < карта) —
   контракт [адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md#архитектура-adr).
5. **Арифметика остаётся в одном месте.** `apply_binary` обслуживает **оба**
   матчера (сырой АСД у оператора `address` и понижённый `ExpressionNode` у
   inline). `CLAUDE.md` прямо предупреждает: «разъехавшись, они дали бы разный
   адрес для одного текста». Разделение по файлам **не должно** дать соблазн
   продублировать её.
6. Язык **не меняется** → версия не растёт (правило 22).

### Consequences

#### Положительные

- Долг **сокращается**: 22 записи → 21; превышение 12049 → ~10933 строк.
- Соседние фичи по адресам (0043, 0084) получают место.
- Форма повторяет три уже разделённых каталога — читателю не нужно учить новую.

#### Отрицательные / Action items

- **A-1. Дифф широкий, ценность невидима.** Перекладка не даёт пользователю
  ничего — она даёт **место**. Это осознанно: 0027 завела храповик именно потому,
  что правило «дели по логике» без машины **не работало** (`validate.rs` дорос до
  3654 строк).
- **A-2. `apply_binary` — единственная точка** (правило 5). Разделение файлов —
  типичный повод «а давайте у каждого будет свой хелпер»; здесь это дало бы **два
  разных адреса для одного текста**.
- **A-3. Оценка 0042 была вдвое оптимистичной** (150–200 против ~460). Записать в
  `CLAUDE.md`: *предвидение «при росте вынесем» не отменяет обязанности мерить —
  вынос не случился, потому что «ещё влезает»*.
- **A-4. Тесты переезжают вместе с темами.** Сегодня они в хвосте файла
  (1054→1116); после разделения каждый модуль несёт свои. Иначе `mod.rs` останется
  с тестами обо всём.

#### Acceptance criteria

1. **A1.** `grammar/src/address_map.rs` заменён каталогом `address_map/`; **все**
   файлы — **под лимитом** (1000).
2. **A2.** Запись `grammar/src/address_map.rs` **удалена** из
   `module-size-baseline.txt`; новых записей **не добавлено**.
3. **A3.** `./scripts/check-module-size.sh` — зелёный; долг 22 → **21** записи.
4. **A4.** **Пути импорта у потребителей не изменились** (реэкспорт из `mod.rs`) —
   `git diff` вне `address_map/` не содержит правок `use`.
5. **A5.** **Вывод всех целей побайтово прежний** (`c`/`c-hal`/`st`/`st-at`/`rust`/
   `sv`/`plantuml`) — опора на детерминизм закрытой
   [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr).
6. **A6.** `apply_binary` — **одна** функция на оба матчера (правило 5); греп:
   дублей нет.
7. **A7.** Приоритет источников адреса не изменился: тесты — зелёные.
8. **A8.** `./scripts/precheck.sh` — зелёный целиком.

### Риски и зависимости

- **R-1. Продублировать `apply_binary`** (главный). Разделение файлов — типичный
