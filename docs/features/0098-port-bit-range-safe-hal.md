## Краткое описание

Бит адреса порта (`0xADDR:бит`) не проверяется, а принятый по умолчанию HAL цели `c-hal`
читает **один байт** и сдвигает на `b.bit` → биты 8…31 читаются как **ноль**
(молча неверно), биты ≥ 32 дают **UB** (`int >> 33`). Воспроизводится на
`examples/extend_complex.lam` (бит 33). Дожило, потому что **`c-hal` не
компилируется ни одним проверкой**.

Решение (ADR, Option C): диапазон бита **[0, 63]** (`SE-060` вне его);
ширина доступа HAL — **минимальное слово, содержащее бит** (1/2/4/8 байт) →
UB исключён конструктивно; **проверка компиляции `c-hal`** в `precheck.sh`.

### Context

[Исправление](../fixes/0020-01-port-bit-out-of-range.md) (Tier 1) вскрыл, что
**бит адреса порта** (`0xADDR:бит`) не проверяется нигде, а принятый по умолчанию HAL цели
`c-hal` читает **всегда один байт** и сдвигает на `b.bit`:

```c
return ((*(volatile uint8_t*)b.addr) >> (b.bit < 0 ? 0 : b.bit)) & 1u;
```

Отсюда два класса дефекта (проба `cc -Wall` на `examples/extend_complex.lam`,
где есть `in WAIT: bit := 0x44533932:33`):

| Бит | Что происходит | Класс |
|---|---|---|
| 0…7 | верно | — |
| 8…31 | загружен **один байт**; после продвижения до `int` сдвиг даёт **всегда 0** | **молча неверно** |
| ≥ 32 | `int >> 33` — **undefined behavior** (C11 6.5.7p3) | **UB** |

Дожило потому, что **цель `c-hal` не компилируется ни одним проверкой**: в
`precheck.sh` она встречается только в проверке детерминизма (её вывод сверяют сам с
собой, но компилятору не подают). Класс — **дыра в покрытии, а не в коде**.

#### Открытый вопрос исправления

Исправление оставил заказчику вопрос: **что считать диапазоном бита?**

- Кандидат A — **разрядность типа порта** (для `bit` → 0).
- Кандидат B — **разрядность адресуемого слова** (но язык ширину слова **не
  выражает** — есть только адрес и бит).

### Decision Drivers

1. **Нет UB и нет молчаливо-неверного чтения** — прямая цель Tier-1 исправления.
2. **Не отвергать легитимную битовую упаковку.** `extend_complex.lam` кладёт три
   бит-порта (`:1`, `:2`, `:33`) в одно слово по разным смещениям — это и есть
   смысл бит-адресации. Правило, запрещающее смещение > 0, убивает всю фичу.
3. **Консервативность: лишний отказ честнее тихой порчи.** Правило проверяемо на
   АСД, без знания технологии.
4. **Аддитивность (правило 11):** цель `c` бит-адрес игнорирует (порты через
   HAL-колбэки) — её вывод меняться не должен; проверка живёт в
   адрес-потребляющем слое (`c-hal`/`st-at`).

### Considered Options

#### Option A. Диапазон = разрядность типа порта (`bit` → {0})

**Опровергнуто драйвером 2.** Тип `bit` шириной 1 → допустим только бит 0.
`extend_complex.lam` (биты 1, 2, 33) отвергается **целиком**, хотя биты 1 и 2
**корректны** (младший байт). Смещение бита относится к **слову**, а не к типу
порта, поэтому «ширина типа» — не та мера. Кандидат A из исправления **отклонён**:
он делает битовую упаковку невозможной.

#### Option B. Язык выражает ширину слова; диапазон = она

**Правильно, но вне объёма Tier-1 исправления.** Требует нового синтаксиса (`bit @
0xADDR[63:0]` или подобного), затрагивает парсер, семантику, карту адресов
(0084) и роль инициализатора (0070). Это **новая языковая возможность**, а не
устранение UB. Отложено к работам, выражающим ширину слова в языке.

#### Option C (принято). Диапазон = [0, 63]; ширина доступа HAL выводится из бита

**Диапазон бита — [0, 63].** `64` — предел, покрываемый стандартными
беззнаковыми словами C (`uint64_t`); слова шире в типовом MMIO нет. Бит `< 0` или
`≥ 64` → **ошибка `SE-060`** (в адрес-потребляющем слое).

**Ширина доступа принятого по умолчанию HAL — минимальное слово, содержащее бит:** бит 0…7 →
`uint8_t`, 8…15 → `uint16_t`, 16…31 → `uint32_t`, 32…63 → `uint64_t`. Сдвиг
всегда меньше ширины прочитанного типа → **UB исключён конструктивно**, а не
проверкой; «молча ноль» (8…31) исчезает вместе с ним.

**Pros:**
- Убирает **оба** класса дефекта (драйвер 1), доказано **исполнением** (не
  грепом): бит 33 читается `uint64_t`, `>> 33` определён.
- **Не отвергает упаковку** (драйвер 2): биты 1, 2, 33 `extend_complex` валидны;
  бит 33 обоснован — читается 64-битным словом (критерий 4 исправления закрыт
  **обоснованием**, не правкой примера).
- Консервативно и проверяемо на АСД (драйвер 3): «бит < 64?» — свойство числа.
- Аддитивно (драйвер 4): диагностика в `resolve_addresses` (слой `c-hal`/`st-at`);
  вывод цели `c` байт-в-байт прежний.

**Cons / осознанные ограничения:**
- **C-1. Ширина — per-port, а не per-word.** Три порта на одном адресе с битами
  1/2/33 получат ширины доступа 1/1/8 байт — доступ к одному регистру **разной
  ширины**. Каждый бит извлекается **корректно** (бит 1 — в младшем байте, бит 33
  — в 64-битном слове), но на реальном MMIO ширина шинного доступа значима.
  Унификация ширины по адресу требует группировки портов по адресу и упирается в
  плоский ключ карты ([ключ карты адресов — голое имя порта](0084-address-map-qualified-key.md)) —
  это Option B, а не Tier-1 исправление. Ограничение **задокументировано**.
- **C-2. Уточнение открытого вопроса при проработке.** Набросок «диапазон = ширина
  типа порта», озвученный при взятии исправления, **опровергнут** (Option A): он
  отвергает корпус. Резолюция уточнена до [0, 63] — это правомочие
  фичи-владельца (исправление прямо оставил вопрос владельцу).

### Decision

Принимается **Option C**.

**Нормативные правила:**

1. **`SE-060` — ошибка** на бит `< 0` или `≥ 64`, с локацией объявления порта.
   Живёт в `address_map/resolve.rs` (слой `c-hal`/`st-at`); цель `c` не задета.
2. **Ширина доступа принятого по умолчанию HAL к бит-порту — минимальное слово, содержащее
   бит** (1/2/4/8 байт). `read_bit`/`write_bit` выбирают тип чтения по `b.width`
   (`switch`, как у numeric-порта), маска — `(uint64_t)1u << s`.
3. **Диапазон [0, 63]** — предел `uint64_t`; шире слова цель не поддерживает.
4. **Проверка компиляции `c-hal`** заводится в `precheck.sh`: сегодня цель не
   компилируется вовсе (дыра, породившая дефект).
5. `extend_complex.lam` **не правится**: бит 33 обоснован правилом 2 (читается
   `uint64_t`).
6. Язык **не меняется** (проверка над существующим синтаксисом) → версия не
   растёт (правило 22).

### Consequences

#### Положительные

- UB и молчаливо-неверное чтение устранены **конструктивно** и доказаны
  исполнением.
- Цель `c-hal` впервые **компилируется** проверкой — закрыта дыра покрытия.
- Разблокирована [цель `sv-mmio`: адреса портов → регистровый файл на шине](0062-sv-mmio-target.md) (`sv-mmio`).

#### Отрицательные / Action items

- **A-1. Per-port ширина (C-1)** — не унифицирована по адресу; полная унификация
  за Option B (язык выражает ширину слова). Записать в `CLAUDE.md`.
- **A-2. Проверка компиляции — object-only** (`cc -c`/`-fsyntax-only`): `c-hal`-`.c`
  собирается автономно, но линковка требует внешних `extern fn` (напр.
  `has_flag` в `extend_complex`) и `main`. Компиляции-в-объект достаточно для
  критерия «c-hal компилируется»; линк-проверка потребовал бы драйверов на пример.
- **A-3. Значенческий тест — через `mmap(MAP_FIXED)`** (эмуляция MMIO на хосте):
  разыменование абсолютного адреса на хосте невозможно, поэтому C-драйвер
  отображает страницу по адресу порта и исполняет `read_bit`. При недоступности
  `mmap`/`cc` — скип (как `cc_available`).

#### Acceptance criteria

1. **A1.** Бит вне [0, 63] → `SE-060` (не тихое чтение нуля).
2. **A2.** Принятый по умолчанию HAL не содержит сдвига ≥ ширины прочитанного типа —
   проверено **тестом на значениях** (бит 33 читается `uint64_t`), а не грепом.
3. **A3.** `c-hal` **компилируется** проверкой `precheck.sh`.
4. **A4.** `extend_complex.lam` — бит 33 обоснован (правило 2), пример не правлен;
   вывод цели `c` байт-в-байт прежний.

## Анализ

### Зависимости

- **Нет фич-блокеров.** Опора — закрытые 0020 (объявление адреса), 0042
  (вычисление выражения адреса), 0043 (экспорт карты). Разблокирует
  [цель `sv-mmio`: адреса портов → регистровый файл на шине](0062-sv-mmio-target.md) (`sv-mmio`), которая и вскрыла дефект.
- **Смежно, не зависимость:** 0070 (роль инициализатора порта), 0084 (ключ карты
  адресов) — полное решение «язык выражает ширину слова» (Option B ADR) живёт там.

### Точки интеграции (замер по коду)

| Что | Где | Как |
|---|---|---|
| Финализированный бит | `address_map/resolve.rs::resolve_model` | после выбора источника-победителя, есть `loc`/`name`/`ty` → `SE-060` |
| Принятый по умолчанию HAL | `generator/c/c_header.rs::generate_hal` (→ вынесен в `c_hal.rs`) | ширина бит-порта, `read_bit`/`write_bit` |
| Проверка компиляции | `scripts/precheck.sh` | c-hal прежде только диффилась (детерминизм, стр. 145) |

### Ключевые решения анализа

1. **Диагностика — в адрес-потребляющем слое**, а не в `validate` (все цели):
   бит-адрес осмыслен только для `c-hal`/`st-at`, а цель `c` его игнорирует.
   Иначе `SE-060` ломала бы компиляцию `extend_complex` в цель `c`, где бит
   безвреден — нарушение аддитивности (правило 11).
2. **Ширина доступа — per-port из бита**, а не по типу порта. Разбор в ADR
   (Option A «ширина типа» отвергает битовую упаковку корпуса; Option B требует
   нового синтаксиса). Открытый вопрос исправления разрешён на [0, 63] (предел
   `uint64_t`).
3. **`extend_complex` не правится** — бит 33 обоснован (читается `uint64_t`),
   критерий 4 исправления закрыт обоснованием.
4. **Значенческий тест обязателен** (критерий 2 исправления — «на значениях, а не
   грепом»): компиляция UB не ловит (время выполнения). MMIO эмулируется `mmap(MAP_FIXED)`.

### Риски

- **Per-port ширина ≠ per-word** (C-1 ADR): три порта на одном адресе с битами
  1/2/33 → доступ 1/1/8 байт. Каждый бит извлекается корректно; унификация по
  адресу — за Option B. Задокументировано.
- **`mmap(MAP_FIXED)` платформозависим:** низкие адреса macOS отвергает (замер:
  0x10000000 → FAIL, 0x100000000000 → OK). Тестовый адрес — 16 ТБ; при неудаче —
  явный пропуск.

## Разработка

### Задача

#### Что было

Бит адреса порта не проверялся; принятый по умолчанию HAL цели `c-hal` читал **один байт** и
сдвигал на `b.bit`: бит 8…31 → молча ноль, бит ≥ 32 → UB (`int >> 33`). `c-hal`
не компилировалась ни одним проверкой.

#### Что сделано

1. **Диагностика `SE-060`** (`address_map/resolve.rs::resolve_model`): при
   финализированном бите вне `[0, 63]` — ошибка с локацией порта. В
   адрес-потребляющем слое (`c-hal`/`st-at`); цель `c` не задета (правило 4 ADR).
2. **Безопасный HAL** (`generator/c/c_hal.rs`, вынесен из `c_header.rs`): ширина
   доступа бит-порта — минимальное слово, содержащее бит (`word_bytes_for_bit`:
   1/2/4/8 байт), а не тип `bool`. `read_bit`/`write_bit` выбирают тип по
   `b.width` (`switch`), маска `(uint64_t)1u << s`. UB исключён конструктивно.
3. **Проверка компиляции `c-hal`** (`scripts/precheck.sh`): каждый пример
   генерируется в c-hal и компилируется `cc -c`. Примеры без адресов (SE-052) —
   пропуск.
4. **Вынос HAL в `c_hal.rs`**: `c_header.rs` упёрся в лимит размера модуля;
   удалён из `module-size-baseline.txt` (955 строк < 1000).

#### Проверки

- **A1:** `SE-060` на бите 64, валидность бита 63 — `hal_bit_range_tests::bit_in_range_ok_out_of_range_is_se060`.
- **A2 (значенческий):** бит 33 читается `uint64_t`, результат «1001» — `hal_bit_range_tests::hal_reads_wide_bit_without_ub` (mmap-эмуляция MMIO; скип при недоступности).
- **Границы слова:** `c_hal::tests::bit_word_width_by_bit_index`.
- **A3:** проверка компиляции c-hal в `precheck.sh` (7 примеров компилируются, `elevator_mini` — пропуск SE-052).
- **A4:** `extend_complex.lam` не правлен (бит 33 обоснован); вывод цели `c` байт-в-байт прежний.

Проверяется устранение **UB** и **молчаливо-неверного чтения** в принятом по умолчанию HAL
цели `c-hal`, а также диагностика бита вне диапазона. Критерий 2 исправления требует
проверки **на значениях**, а не грепом: компиляция UB не ловит.

- **Единую ширину доступа по адресу** (C-1 ADR: per-port, а не per-word) — за
  Option B (язык выражает ширину слова), вне объёма Tier-1 исправления.
- **Линковку c-hal в исполняемый файл** — extern fn/main требуют драйверов на
  пример; проверка компилирует в объект (критерий «c-hal компилируется»).

| Критерий | Проверка | Результат |

### Ключевые наблюдения

- **UB доказан устранённым исполнением, а не грепом.** Значенческий тест
  эмулирует MMIO через `mmap(MAP_FIXED)` по адресу порта (16 ТБ) и вызывает
  сгенерированный `read_bit`: при слове `1<<33` бит 33 = 1, бит 2 = 0; при
  `1<<2` — наоборот. Прежний код (`uint8_t >> 33`) равенства «1001» не даёт.
- **Замер платформы:** `mmap(MAP_FIXED)` macOS отвергает низкие адреса
  (0x10000000 → FAIL), но принимает высокие (0x100000000000 → OK) — отсюда выбор
  16-ТБ адреса; при неудаче тест печатает пропуск, а не падает.
- **Вынос HAL в `c_hal.rs`** снял `c_header.rs` с лимита размера (1334 → 955) и
  из реестра долга — долг модулей −1 (20 → 19 записей).

### Отклонения и ограничения

- **Per-port ширина ≠ per-word** (C-1 ADR): порты на одном адресе с разными
  битами получают разную ширину доступа. Каждый бит извлекается корректно;
  унификация — за Option B (язык выражает ширину слова).
- **Проверка — компиляция в объект**, не линковка (extern fn/main требуют драйверов).
- **Открытый вопрос исправления** разрешён на [0, 63] (уточнение: «ширина типа порта»
  отвергнута как несовместимая с битовой упаковкой).

## Итог (что сделано) — 2026-07-20

минимальное слово, содержащее бит. Реализовано:
