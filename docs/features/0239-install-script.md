## Краткое описание

Собрать релизные `taktc`, `takt-lsp` и `takt-sim` и поставить их в `bin`
префикса — одной командой, без запоминания трёх вызовов `cargo` с разными
манифестами и фичами.

## Что известно на входе

До фичи README предлагал два вызова:

```sh
cargo build --release --bin taktc
cargo install --path grammar --bin taktc
```

Обе строки **устарели**: крейт `grammar` переименован в `takt-lang` ещё фичей, то есть `cargo install --path grammar` не работает вовсе. Симулятор и
языковой сервер в разделе установки не упоминались; `takt-lsp` вдобавок
требует фичи `lsp`, без которой бинарника не существует, — и об этом знал
только раздел про редакторы.

Второе известное: сборка **в общий `target`** может идти часами. Замер фичи и повторный замер-17 (рабочий каталог — 110 ГБ, 629 590 файлов в
`debug/deps`): cargo обходит каталог перед каждой единицей компиляции. Скрипт,
который зависает на чужом мусоре, бесполезен.

## Документирование

**Не требуется** для языковых разделов: фича не меняет ни синтаксис, ни
семантику, ни поведение целей. Правку получил `README.md` — он по своду
описывает инструментарий и сборку.

## Анализ

### Цель и контекст

Заказчик просит одну команду вместо трёх вызовов `cargo` с разными манифестами
и фичами. Замер текущего состояния (2026-08-17):

| Что | Как сегодня | Оценка |
|---|---|---|
| `taktc` | `cargo build --release --bin taktc` + `cargo install --path grammar --bin taktc` (README) | вторая строка **не работает**: крейт `grammar` переименован в `takt-lang` фичей |
| `takt-sim` | в разделе установки **не упомянут** | инструмент есть, способа поставить нет |
| `takt-lsp` | `cargo install --path grammar --bin takt-lsp --features lsp` (раздел про редакторы) | тот же устаревший путь; без `--features lsp` бинарника не существует вовсе |

### Зависимости фичи

- **Зависит от:** `нет`.
- **Влияние на порядок разработки:** никого не блокирует и не разблокирует.
  Косвенно снижает риск для фичи (подкоманда `taktc version`): скрипт
  готов её показывать, как только она появится.

### Требования и проверяемые условия

- **R1. Одна команда.** `scripts/install.sh` собирает **релизные** `taktc`,
  `takt-sim`, `takt-lsp` и ставит их в `$PREFIX/bin`.
- **R2. Префикс настраивается** — флагом `--prefix` и переменной `TAKT_PREFIX`;
  умолчание `~/.local` (туда проект уже ставит `iec2c`).
- **R3. Языковой сервер отключаем** (`--no-lsp`): он нужен не всем, а его
  сборка тянет фичу `lsp`.
- **R4. Свой каталог сборки.** Умолчание — `target/install`, а не общий
  `target`; вызывающий волен назвать другой через `CARGO_TARGET_DIR`.
- **R5. Сухой прогон** (`--dry-run`) печатает, что было бы сделано, и **ничего
  не создаёт**.
- **R6. Проверка установленного** (`--check`) — код 1 и поимённый список
  недостающего.
- **R7. Отказ на неизвестном аргументе** (код 2), а не молчаливое игнорирование.
- **R8. Предупреждение о `PATH`**, если `$PREFIX/bin` в нём отсутствует.
- **R9. README актуален**: устаревший `cargo install --path grammar` заменён.

#### R4 отдельно: почему каталог сборки — свой

Замер-17: рабочий `target` этого репозитория — **110 ГБ**, 629 590
файлов в `debug/deps`. В таком каталоге `cargo test --all-features` не
завершился за 10 минут и был снят; полный `precheck.sh` в нём же, по замеру
фичи, шёл **более суток** там, где здоровая сборка занимает 42 с. Причина:
cargo обходит каталог перед каждой единицей компиляции.

Поэтому «состояние каталога сборки — свойство **инструмента**, а не дисциплина
автора» (формулировка 0234). Скрипт установки, зависающий на чужом мусоре,
своей задачи не решает.

Скрипт при этом **ничего не удаляет**: проверка чистит только собственный
`target/precheck`, и заводить второго уборщика фича не стала.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Справка и отказ на неизвестном флаге | `test-install.sh` (A1, A2) |
| A2 | Состав: три инструмента, три установки | `--dry-run` (A3) |
| A3 | `--no-lsp` убирает языковой сервер | `--dry-run` (A4) |
| A4 | Префикс уважается | `--dry-run --prefix` (A5) |
| A5 | `--build-only` не устанавливает | `--dry-run --build-only` (A6) |
| A6 | `--check` отвергает пустой префикс | `--check --prefix <пусто>` (A7) |
| A7 | Каталог сборки — `target/install` | `--dry-run` (A8) |
| A8 | Настоящая установка работает | ручной прогон в временный префикс: три бинарника на месте и исполняются |
| A9 | README не обещает несуществующего | чтение + проверка ссылок |

### Особенности по обратной совместимости

**Совместимость не затрагивается:** ни языка, ни библиотеки, ни формата вывода
фича не касается. Прежние вызовы `cargo build --release` продолжают работать —
скрипт их не заменяет, а избавляет от необходимости помнить.

### Риски и зависимости

- **R-1. Скрипт ставит поверх работающего бинарника.** Снижение: установка идёт
  `install -m 0755` (замена inode), а не записью поверх, — работающий процесс
  не портится.
- **R-2. Сборка в неожиданный каталог.** Снижение: скрипт **печатает** каталог
  сборки первой строкой; контроль A8 закрепляет умолчание.
- **R-3. Тест гоняет долгую релизную сборку и попадает в предкоммит.**
  Снижение: контроль настоящую сборку **не запускает** (проверяет то, что
  принадлежит скрипту), и в `precheck.sh` не добавляется: релизная сборка не
  входит в предкоммит по объёму.
- **R-4. `taktc --version` в проверке.** Такой команды нет (фича не
  закрыта), и вызов печатал бы ошибку при успешной установке. Снижение: признак
  свежести — размер и время файла.

## Разработка

### Задача

#### Что было

README предлагал:

```sh
cargo build --release --bin taktc
cargo install --path grammar --bin taktc
```

Вторая строка **не работает**: крейт `grammar` переименован в `takt-lang` ещё
фичей. Симулятор в разделе установки не упоминался вовсе, а языковой
сервер — только в разделе про редакторы и с тем же мёртвым путём. Вдобавок
`takt-lsp` без `--features lsp` не собирается: бинарника просто нет.

#### Что сделано

`scripts/install.sh` — одна команда на все три инструмента:

```sh
scripts/install.sh                     # → ~/.local/bin
scripts/install.sh --prefix /usr/local
scripts/install.sh --no-lsp --check --dry-run --build-only
```

Устройство:

- состав инструментов задан **одной таблицей** внутри скрипта (`имя | крейт |
  флаги`), и по ней идут и сборка, и установка, и `--check`: три списка
  разъехались бы;
- каталог сборки по умолчанию — **свой** `target/install` (урок:
  накопленный общий `target` растягивает минутную сборку на часы), переопределяем
  через `CARGO_TARGET_DIR`;
- установка идёт `install -m 0755` — замена inode, а не запись поверх:
  работающий бинарник не портится;
- скрипт **предупреждает**, если `$PREFIX/bin` не в `PATH`;
- `--dry-run` печатает команды и **ничего не создаёт**;
- неизвестный аргумент — отказ с кодом 2, а не молчаливое игнорирование.

**`taktc --version` скрипт не зовёт.** Такой команды у компилятора нет
(незакрытая фича), и вызов печатал бы «неизвестная команда» сразу после
успешной установки. Признак свежести — размер и время файла.

## Тест-план

### Область и цель

Проверяется то, что принадлежит **скрипту**: разбор аргументов, состав команд,
выбор каталога сборки, отказы и сообщения. Требования R1–R9 анализа.

**Настоящую релизную сборку контроль не запускает.** Она занимает минуты и
принадлежит cargo, а не скрипту; в предкоммит такой тест не добавляется. Сборка
проверяется **один раз вручную** при приёмке (T9).

Фича языка не меняет, поэтому примеров и контрпримеров на Takt
здесь нет.

### Что вскрылось попутно

**README обещал несуществующую команду.** `cargo install --path grammar` не
работает с фичи (переименование крейта), то есть **полтора десятка фич
подряд** документ предлагал читателю мёртвый путь установки. Найдено при
разборе входа, а не проверкой: проверка ссылок проверяет пути к файлам, а не
работоспособность команд в примерах. Кандидат заведён.

**Симулятор в разделе установки отсутствовал вовсе** — при том, что это один из
двух главных инструментов проекта.

смотрит только на пути к файлам; примеры вызовов инструментов устаревают молча —
что и произошло с `cargo install --path grammar`. Возможная мера — прогон
