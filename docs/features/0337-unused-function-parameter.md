## Краткое описание

`fn constant(v: u8) -> u8 { return 7; }` — законная запись, которую эталон
исполняет, а три цели порождали так, что вывод не проходит проверки проекта:
`unused parameter` у `c`, `unused variable` у `rust`, `UNUSEDSIGNAL` у `sv`.

## Документирование

**Не требуется** — подтверждено: правится представление у трёх целей.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0337-unused-function-parameter.md](0337-unused-function-parameter.md)

### Контекст

Замер-20 на `fn constant(v: u8) -> u8 { return 7; }`:

| Потребитель | Ответ |
|---|---|
| эталон, `st`, `st-at`, `plantuml` | исполняют / переводят чисто |
| **`c`, `c-hal`** | `cc -Werror`: unused parameter 'v' |
| **`rust`** | `rustc -D warnings`: unused variable: `v` |
| **`sv`, `sv-mmio`** | `UNUSEDSIGNAL` — проверка цели считает предупреждение ошибкой |

Фича закрыла этот класс **только для структурных** параметров (`main`,
`model`, `m`) цели `c` — тех, что эмитятся по протоколу вызова. Параметр,
объявленный **автором**, не гасил никто, хотя признак «параметр использован в
напечатанном тексте тела» уже существовал и работал.

### Решение

Один признак, три идиомы:

| Цель | Заглушка |
|---|---|
| `c` | `(void)v;` — тот же `c_params`, что у 0260 |
| `rust` | `let _ = v;` (`generator/rust/rust_unused.rs`) |
| `sv` | `logic _unused_v; _unused_v = &{1'b0, v};` (`generator/sv/sv_unused.rs`) |

Форма для `sv` выбрана **пробой обоих инструментов** (verilator и yosys,
2026-08-20) и не нова: тем же способом обёртка APB поглощает сигналы записи
(`_unused_write`).

**Имя параметра в сигнатуре не меняется.** Форма `_v` тоже гасит
предупреждение, но сигнатура порождённого модуля читается человеком: параметр,
названный автором `v`, обязан остаться `v`.

### Границы

- **`lint_off` запрещён правилом проекта** (0169): прагма гасит контроля, а не
  причину. В выбранной форме параметр честно используется, а константа `1'b0` в
  редукции даёт ноль — синтезатор выбрасывает логику сам (проверено yosys).
- **Признак смотрит на текст тела**, а не на семантику — как у 0260: это
  снимает транзитивность и не требует знать обо всех каналах использования.
- **Цель `st` не затронута:** `iec2c` о неиспользуемом параметре не говорит.

### Отвергнутые варианты

1. **Не эмитить параметр.** Вызов передаёт аргумент — сигнатура обязана его
   принять.
2. **`_v` в сигнатуре.** Меняет видимое имя.
3. **`#[allow(unused_variables)]` / `lint_off`.** Гасит контроля, а не причину.

### Последствия

- Вывод корпуса не изменился: функций с неиспользуемым параметром в
  `examples/` нет ни одной — потому все три проверки и молчали.

## Анализ

### Цель и контекст

Кандидат заведён замером — там неиспользуемый параметр всплыл как помеха
проверке. Отдельный замер показал, что целей три, а не одна.

### Зависимости фичи

- **Зависит от:** 0260 (признак и идиома у цели `c`), 0169 (приём поглощения у
  `sv`). Закрыты.
- **Влияние на порядок разработки:** снимает кандидата, заведённого 0336.

### Требования и проверяемые условия

- **R1.** `c`: `(void)v;`, `cc -Werror` молчит.
- **R2.** `rust`: `let _ = v;`, сборка под `-D warnings`.
- **R3.** `sv`: поглощение редукцией, `verilator -Wall` и `yosys` молчат.
- **R4.** Используемый параметр заглушки **не** получает.
- **R5.** Имя параметра в сигнатуре не изменилось.
- **R6.** Вывод корпуса не изменился.

### Разбор

#### Почему признак общий, а идиомы разные

Вопрос «пользуется ли тело параметром» один и решается одинаково — по
напечатанному тексту. Идиома же принадлежит целевому языку, и у каждого своя:
в C это приведение к `void`, в Rust — связывание с `_`, в SystemVerilog —
поглощение редукцией (объявлений «неиспользуемо» там нет вовсе).

#### Почему буфер

Чтобы задать вопрос напечатанному телу, тело надо сперва напечатать. У
`Printer` для этого уже есть `fork`, заведённый фичей ровно с этой целью —
и наследующий уровень отступа.

### Риски

- **Ложное «использован»** при совпадении имени с подстрокой: снято проверкой
  границ идентификатора (тот же урок, где `domain` содержит `main`).

### Почему тесты именно такие

Предмет — принимает ли вывод **целевой инструмент** под политикой проекта,
поэтому все три теста запускают настоящие `cc`, `rustc`, `verilator`.
Контрольная функция обязательна: без неё правило читалось бы как «заглушка
всегда», и лишняя строка ушла бы в вывод незамеченной.
