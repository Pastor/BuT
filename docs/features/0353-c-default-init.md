## Краткое описание

`<Root>_init` цели `c` ставит только поле `state`: переменная **без
инициализатора** не обнуляется вовсе и читается как **мусор стека**. Это
неопределённое поведение в прошивке — и молчаливое: код возврата `taktc`
нулевой, `cc -Wall -Wextra -Werror` тоже молчит (поле структуры, а не локальная
переменная).

**Замер-21** (`var n: u8;`, значение читается в теле):

| Потребитель | Умолчание |
|---|---|
| эталон | `0` |
| `st`, `st-at` | `0` — `VAR n : USINT;` инициализируется по стандарту IEC 61131-3 |
| `sv`, `sv-mmio` | `0` — `nodefault_n <= '0;` в ветви сброса |
| `rust` | `0` — `n: 0` в конструкторе (фича достроила это на структуры, `q`, `duration`) |
| **`c`, `c-hal`** | **мусор**: `Nodefault_init` ставит только `state` |

**Найдено прогоном харнесса, а не `probe.sh`:** тот сводит коды возврата, а
цель `c` возвращает ноль. Харнесс сверки 0352 прочитал **339** там, где эталон
даёт **3**.

**Корпус класс не покрывает:** у всех примеров `examples/` переменные несут
инициализатор, а штатные харнессы (`*_main.c`) объявляют модель без `= {0}` —
то есть дефект просто не проявляется.

**Граница фичи названа:** умолчание **перечисления** расходится и без неё —
эталон, `st` и `sv` дают `0` (значение, которого в наборе вариантов может не
быть вовсе: у `enum Mode { Idle = 5, Work = 7 }` нуля нет), а `rust` — **первый
вариант**. Выбор между ними меняет либо эталон, либо цель `rust`, то есть это
решение заказчика; фича приводит `c` к **большинству** (ноль) и выносит вопрос
кандидатом.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл
> по правилу 17.

## Документирование (правило 24)

**Не требуется** — язык не меняется: умолчание переменной уже определено
эталоном и тремя целями, фича приводит к нему восьмую. Наблюдаемое поведение
`.takt`-программы не меняется ни в одной законной записи; меняется вывод одной
цели, где сегодня он неопределён.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-21
- **Фича:** [../features/0353-c-default-init.md](0353-c-default-init.md)

### Контекст

`generate_model_init` (`generator/c/c_model_init.rs`) обходит переменные модели
и **пропускает** те, у кого инициализатора нет:

```rust
if let ExpressionNode::None = expr {
    continue;
}
```

Поэтому после `<Root>_init` поле структуры модели содержит то, что лежало в
памяти. Замер-21: эталон, `st`, `sv` и `rust` дают **ноль**, `c` и
`c-hal` — **мусор**; харнесс сверки прочитал 339 вместо 3.

Контракт `_init` при этом обещает обратное — README: «`_init` заполняет его
поэлементно», а ADR прямо называет целью «привести память в определённое
состояние до первого `_tick`, чтобы чтение полей между `_init` и `_tick`
перестало быть UB». То есть правило уже сформулировано, а исполнялось лишь для
переменных с инициализатором.

### Решение

**Переменная без инициализатора получает нулевое значение своего типа, и
печатается оно теми же путями, что и инициализатор.**

Ветвь `ExpressionNode::None` вместо `continue` печатает:

| Тип | Форма |
|---|---|
| скаляр (целое, `bit`, `bool`, `float`, `duration`, `q`, перечисление) | `model->x = 0;` |
| настоящий массив `[T;N]` | поэлементно, тем же `generate_array_init` |
| бит-вектор `N > 64` | по словам, тем же `generate_wide_bits_init` |
| структура | поле за полем, рекурсивно (структуру в C не присвоить) |

Знание «как выглядит нулевое значение» живёт **одним** носителем
(`c_model_init::zero_init`), а знание «куда писать» остаётся у существующих
печатников: массив и слова уже умеют раскладывать значение по элементам.

### Отвергнутые варианты

**А. Печатать `memset(model, 0, sizeof(*model));` в начале `_init`.** Короче, но
неверно: `_init` вызывается и как `reset`, а `memset` затёр бы указатели HAL
(`model->write_bit`, `model->userdata`), которые пользователь привязывает **до**
`_init` — это часть контракта цели с фичи. Вдобавок нулевой байтовый
образец не равен нулю для всякого типа (`float`, указатель) — для C это на
практике совпадает, но опираться на совпадение в порождаемом коде нельзя.

**Б. Обязать пользователя писать `Root m = {0};`.** Это перенос дефекта в
документацию: штатные харнессы корпуса так **не** делают, а язык обещает
умолчание — эталон и три цели его дают.

**В. Умолчание перечисления — первый вариант** (как у цели `rust`). По существу
разумнее нуля: у `enum Mode { Idle = 5, Work = 7 }` нуля в наборе нет. Но
эталон, `st` и `sv` дают **ноль**, и выбор в пользу первого варианта менял бы
их, а не цель `c`. Это решение заказчика; фича приводит `c` к большинству и
выносит вопрос кандидатом.

### Последствия

- Чтение поля между `_init` и `_tick` перестаёт быть UB **для всех**
  переменных, а не только для тех, у кого есть инициализатор.
- Вывод корпуса меняется только там, где переменная без инициализатора есть;
  сегодня в `examples/` таких нет, то есть снапшоты остаются прежними.
- Язык не меняется (правило 22): версия не поднимается.

### Замер (правило 30)

Снят 2026-08-21 **прогоном харнесса**, а не `probe.sh`: тот сводит коды
возврата, а цель `c` возвращает ноль. Сводка — в
[ADR](0353-c-default-init.md#архитектура-adr). Выводы, влияющие на объём:

1. **Расходятся две цели из восьми.** Эталон, `st`/`st-at` (стандарт IEC
   инициализирует `VAR` нулём), `sv`/`sv-mmio` (ветвь сброса) и `rust`
   (конструктор) дают ноль; `c` и `c-hal` — мусор стека.
2. **Форм записи в C четыре, не одна.** Скаляр присваивается, массив — нет
   (`array type is not assignable`), бит-вектор шире 64 бит — это массив
   **слов** (0078), структура присваивается только целиком из другой структуры.
   Общая ветвь покрыла бы лишь скаляр.
3. **Умолчание перечисления расходится и без фичи.** Эталон, `st`, `sv` дают
   `0` — значение, которого в наборе может не быть (`enum Mode { Idle = 5,
   Work = 7 }`), а `rust` даёт **первый вариант**. Выбор меняет либо эталон,
   либо цель `rust`; фича приводит `c` к большинству и выносит вопрос
   кандидатом.

### Объём правки

| Место | Что делается |
|---|---|
| `generator/c/c_zero_init.rs` | новый носитель: раскладка нулевого значения по типу |
| `generator/c/c_model_init.rs` | ветвь `ExpressionNode::None` печатает умолчание вместо `continue` |

**Проверка бит-вектора стоит раньше массива:** `[bit; 128]` есть
`TypeNode::Array(128, Bit)`, и общая ветвь напечатала бы 128 присваиваний по
несуществующим индексам — поле объявлено как `uint64_t[2]`.

**Неиспользуемая переменная в структуру не попадает** (штатный фильтр
`c_header::generate_model_header`), и обнулять её нельзя: поля нет, вывод не
скомпилировался бы. Фильтр стоит выше в том же цикле — правка его не задевает,
но контрольный тест на это обязателен.

### Зависимости (правило 17)

**Нет.** Используемые решения закрыты: 0033 (контракт `_init`), 0078
(бит-вектор), 0187 (порядок «HAL до `_init`»), 0293 (структуры у целей).

### Обратная совместимость (правило 11) и версия языка (правило 22)

**Язык не меняется, версия не поднимается.** Наблюдаемое поведение законной
`.takt`-программы не меняется ни в одной записи: умолчание уже определено
эталоном и тремя целями, фича приводит к нему восьмую. Меняется вывод цели `c`
там, где сегодня он **неопределён**.

### Редакторский слой (правило 29)

**Правок не требуется, ответ зафиксирован.** Ни лексика, ни синтаксис, ни
семантика, ни набор диагностик не затронуты — правится печать одной цели.

### Риски

- **Рост `_init` на моделях с большими массивами.** `var big: [u8; 1000];` без
  инициализатора даст тысячу присваиваний. Это цена явности; `memset` отвергнут
  в ADR (затёр бы указатели HAL). Класс не наблюдался: в корпусе таких
  объявлений нет.
- **Ложное обнуление неиспользуемой переменной** — ловится контрольным тестом
  и компиляцией корпуса.

## Разработка

### Задача

- **Фича:** [../features/0353-c-default-init.md](0353-c-default-init.md)
- **ADR:** [0353-c-default-init.md#архитектура-adr](0353-c-default-init.md#архитектура-adr)
- **Анализ:** [0353-c-default-init.md#анализ](0353-c-default-init.md#анализ)
- **Дата:** 2026-08-21

#### Что сделано

##### 1. Носитель нулевого значения (`generator/c/c_zero_init.rs`)

`emit_zero_init` раскладывает ноль по типу — потому что в C **не всё
присваивается**:

| Тип | Форма |
|---|---|
| скаляр (целое, `bit`, `bool`, `float`, `duration`, `q`, перечисление) | `model->x = 0;` |
| бит-вектор `N > 64` | по словам: `model->w[0] = 0; model->w[1] = 0;` |
| настоящий массив `[T;N]` | по элементам, рекурсивно |
| структура | по полям, рекурсивно |

##### 2. Ветвь `ExpressionNode::None` (`generator/c/c_model_init.rs`)

Прежде `continue`, теперь вызов носителя. Всё остальное в цикле — фильтр
неиспользуемых, ветви массива и слов для **авторского** инициализатора — не
тронуто.

#### Ловушки (проверено прогоном)

**Бит-вектор проверяется раньше массива.** `[bit; 128]` — это
`TypeNode::Array(128, Bit)`, а поле объявлено `uint64_t[2]`: общая ветвь
напечатала бы 128 присваиваний по несуществующим индексам. Порядок ветвей —
предмет отдельного теста.

**Неиспользуемую переменную обнулять нельзя:** штатный фильтр выбрасывает её
из структуры, и `model->spare = 0;` не скомпилировался бы. Фильтр стоит выше в
том же цикле; контрольный тест контролирует это.

**`memset` не годится** (ADR): `_init` служит и сбросом, а указатели HAL
привязываются **до** него (контракт 0187) — `memset` затёр бы их.

#### Границы

- **Умолчание перечисления — ноль**, как у эталона, `st` и `sv`; цель `rust`
  даёт **первый вариант**. Расхождение существует **до** этой фичи и меняет
  либо эталон, либо `rust` — вынесено кандидатом.
- Модель с большим массивом без инициализатора даст длинный `_init` (по
  присваиванию на элемент). Цена явности; в корпусе таких объявлений нет.

## Тест-план

- **Фича:** [../features/0353-c-default-init.md](0353-c-default-init.md)
- **Анализ:** [0353-c-default-init.md#анализ](0353-c-default-init.md#анализ)
- **Дата:** 2026-08-21

### Слои

| Слой | Что доказывает |
|---|---|
| 1. эмиссия | нужная форма для каждого из четырёх типов |
| 2. потактовая сверка | значение **верное**: трасса цели `c` = трасса эталона |

Второй слой обязателен: мусор стека компилируется и линтуется без единого
замечания — расхождение только в значениях.

### Примеры

| № | Вход | Ожидание |
|---|---|---|
| П1 | `var n: u8;` | `model->n = 0;` |
| П2 | `var a: [u8; 3];` | три присваивания по элементам |
| П3 | `var w: [bit; 128];` | **два** присваивания по словам, не 128 |
| П4 | `struct In { v: u8 } struct Out { i: In, n: u8 } var s: Out;` | `model->s.i.v = 0;` и `model->s.n = 0;` |

### Контрпримеры

| № | Вход | Ожидание | Что ловит |
|---|---|---|---|
| К1 | `var n: u8 := 7;` | `model->n = 7;`, нуля нет | подмену авторского значения умолчанием |
| К2 | неиспользуемая `var spare: u8;` | в выводе её нет вовсе | обнуление несуществующего поля — вывод не собрался бы |

### Потактовая сверка

| № | Вход | Ожидание |
|---|---|---|
| С1 | три формы (скаляр, элемент массива, поле структуры) без инициализаторов, значения растут по тактам | трасса эталона = трасса цели `c`: `[6, 12, 18, 24, 24]` |

Харнесс сверки **не обнуляет** модель (`ConformanceDefaultInit m;` без
`= {0}`): обнуление снаружи скрыло бы ровно тот дефект, который лечит фича.
Штатные харнессы корпуса поступают так же.

## Итог (что сделано)

**Чтение поля между `_init` и `_tick` перестало быть UB для всех переменных.**

- Ветвь `ExpressionNode::None` в `generate_model_init` вместо `continue`
  печатает ноль; раскладка по типу живёт носителем
  `generator/c/c_zero_init.rs`: скаляр — присваиванием, массив — по элементам,

- `memset` отвергнут: `_init` служит и сбросом, а указатели HAL
  привязываются **до** него (контракт 0187) — он затёр бы их.
- **Класс невидим инструментам:** мусор стека компилируется и линтуется без
  замечаний, код возврата `taktc` нулевой. Мутация «вернуть `continue`» упала
  **только** на потактовой сверке, дав `[428, 428, …]` вместо `[6, 12, 18,
