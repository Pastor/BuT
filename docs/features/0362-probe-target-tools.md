## Краткое описание

`scripts/probe.sh`  сводит **коды возврата `taktc`** по эталону и
восьми целям. Класс «`taktc` вернул ноль, а вывод отвергает **чужой**
инструмент» такой замер **не видит** — и это не рассуждение, а записанный
вывод фичи: «`probe.sh` этот класс не показывает — он сводит коды
возврата, а все три цели возвращали ноль; вердикт дал прогон целевых
инструментов».

Замер-21 (вход `nested.takt` — переменная `[[u8; 2]; 2]`, чтение
`grid[1][0]`):

| Потребитель | `probe.sh` | Прогон инструмента цели |
|---|---|---|
| эталон | `s = 3` | — |
| `c`, `c-hal` | ОТКАЗ `CC-015` | — (до инструмента не доходит) |
| **`st`, `st-at`** | **OK** | **`iec2c` ОТВЕРГ**: «Number of subscripts/indexes does not match … (array has 0 indexes)» |
| `rust` | OK | `rustc` и `clippy -D warnings` приняли |
| `sv`, `sv-mmio` | OK | `verilator --lint-only -Wall` принял |

То есть замер, снятый **по своду**, объявляет цель `st` исправной там,
где она кладёт на диск невалидный ST при нулевом коде возврата.

Предмет фичи — отдать машине ту часть проверки, которую сегодня делает
человек вручную: `probe.sh --tools` прогоняет по порождённому коду те же
инструменты, что и проверки предкоммита (`cc`, `iec2c` + `cc`, `rustc` +
`clippy-driver`, `verilator`), и печатает их вердикт рядом с кодом возврата
`taktc`.

### Context

свод свода требует снимать замер расхождения **прогоном**, и командой
для этого служит `scripts/probe.sh`. Скрипт проверяет пробу на три
ловушки и сводит в одну таблицу **коды возврата** эталона и восьми целей.

Кода возврата **недостаточно**, и это записано в живом контексте самой
фичей: «`probe.sh` этот класс не показывает — он сводит коды возврата, а
все три цели возвращали ноль; вердикт дал прогон целевых инструментов».
Класс — «`taktc` рапортует об успехе, а порождённый файл отвергает **чужой**
инструмент» — за последний месяц находили вручную фичи. Каждый раз человек делал одно и то
же: генерировал цель и звал `cc`/`iec2c`/`rustc`/`verilator` руками.

Замер-21 (вход: переменная `[[u8; 2]; 2]`, чтение `grid[1][0]`):

| Потребитель | `probe.sh` сегодня | Прогон инструмента цели |
|---|---|---|
| эталон | `s = 3` | — |
| `c`, `c-hal` | ОТКАЗ `CC-015` | до инструмента не доходит |
| **`st`, `st-at`** | **OK** | **`iec2c` ОТВЕРГ**: «Number of subscripts/indexes does not match» |
| `rust` | OK | `rustc` и `clippy -D warnings` приняли |
| `sv`, `sv-mmio` | OK | `verilator --lint-only -Wall` принял |

То есть по своду снятый замер объявляет цель `st` исправной там, где она
кладёт на диск невалидный ST при нулевом коде возврата.

### Decision Drivers

1. **Класс частый и дорогой.** Одиннадцать фич за месяц нашли его вручную;
   каждая тратила на это отдельный цикл проб.
2. **Цена прогона измерена и мала.** Замер-21 на пробе, где все цели
   транслируются: `cc` — 0.024 с, `iec2c` — 0.116 с, `cc` по `POUS.c` —
   0.073 с, `rustc` — 0.038 с, `clippy-driver` — 0.042 с, `verilator` —
   0.043 с, `yosys synth` — 0.088 с. Сам `probe.sh` идёт 0.073 с. То есть
   полный прогон инструментов добавляет доли секунды.
3. **Отсутствие инструмента — не «принято».** `iec2c`, `verilator`, `yosys`
   внешние; молчание при их отсутствии повторило бы класс, ради которого
   фича заводится.
4. **Флаги строгости обязаны совпадать с проверками.** Мягче проверки — замер
   объявит годным вывод, который предкоммит отвергнет; строже — замер даст
   ложную тревогу.

### Considered Options

#### Option A. Прогонять инструменты всегда (без флага)

**Pros:**
- Забыть нельзя: класс перестаёт зависеть от памяти снимающего замер.
- Цена измерена и мала (драйвер 2).

**Cons:**
- Проба на машине без `verilator`/`iec2c` даёт строки «пропуск», то есть
  вывод длиннее.
- Замер дорожает примерно вчетверо (0.07 с → ~0.4 с) — в относительных
  величинах много, в абсолютных незаметно.

#### Option B. Флаг `--tools`, по умолчанию выключено

**Pros:**
- Умолчание остаётся самым дешёвым.

**Cons:**
- **Флаг забудут** — ровно та забывчивость, ради которой фича заводится:
  одиннадцать фич знали про инструменты и всё равно снимали замер без них.
- Два режима одной команды: «замер» начинает означать разное.

#### Option C. Отдельный скрипт `scripts/probe-tools.sh`

**Pros:**
- `probe.sh` не растёт.

**Cons:**
- Два входа в один замер; второй не зовёт никто — а «инструмент, который никто
  не гоняет, неотличим от сломанного» (повод контроля:
  `run_simulations.sh` сломался в день фичи и не был замечен).

### Decision

Принимается **Option A**: `scripts/probe.sh` печатает раздел
**«инструменты целей»** всегда, прогоняя по порождённому коду те же
инструменты и с теми же флагами, что и проверки предкоммита:

| Цель | Инструмент | Команда |
|---|---|---|
| `c`, `c-hal` | `cc` | `cc -Wall -Wextra -Werror -c` |
| `st`, `st-at` | `iec2c`, затем `cc` | `iec2c -I <lib> -T <out>`, затем сборка `POUS.c` |
| `rust` | `rustc`, `clippy-driver` | `--edition 2021 --crate-type=lib -D warnings` через обёртку `#![no_std]` |
| `sv`, `sv-mmio` | `verilator`, `yosys` | `--lint-only -Wall`; `synth -top <модуль>` |
| `plantuml` | — | инструмента нет; строка так и говорит |

Три решения внутри:

1. **Второй шаг у цели `st` — сборка `POUS.c`.** Проверка предкоммита кончается
   на `iec2c`, а урок фичи гласит: форма, принятая разбором, не годна,
   пока не собран её вывод (`VAR_INPUT` с массивом `iec2c` разбирает, а
   порождённый C не компилируется). Проба идёт **дальше проверки** намеренно.
2. **Отсутствие инструмента печатается словом «пропуск»** и никогда не
   выглядит как «принял».
3. **Цель, у которой `taktc` отказал, инструмента не получает** — строка
   называет код отказа: инструменту нечего проверять.

### Consequences

#### Положительные

- Класс «нулевой код возврата при невалидном выводе» виден в том же замере,
  которым проверяется расхождение, — без второго ритуала.
- Проба у цели `st` строже проверки: ловится и то, что `iec2c` принимает, а `cc`
  не собирает.

#### Отрицательные / Action items

- Флаги инструментов теперь названы **в двух местах** — в проверках
  `scripts/precheck.sh` и в `scripts/probe.sh`. Носитель не сводится в один
  тривиально: проверки несут обвязку (корпус, списки транслируемых примеров,
  стабы, тестбенчи, `cmake`), и вынос её — отдельная работа. Расхождение
  контролируется: `scripts/test-probe.sh` требует, чтобы проба была **не мягче**
  проверки по ключевым флагам (`-Werror`, `-D warnings`, `-Wall`).
- Прогон удлиняется на доли секунды (драйвер 2).

#### Acceptance criteria

1. `scripts/probe.sh` печатает раздел «инструменты целей» с вердиктом по
   каждой из восьми целей.
2. На входе `[[u8; 2]; 2]` проба называет отказ `iec2c` у целей `st`/`st-at`,
   тогда как код возврата `taktc` нулевой.
3. Отсутствующий инструмент даёт строку «пропуск», отличимую от «принял».
4. `scripts/test-probe.sh` проверяет: (а) вердикт инструмента печатается,
   (б) невалидный вывод ловится, (в) годный вывод тревоги не даёт,
   (г) флаги строгости не мягче проверок предкоммита.

## Анализ

### Цель и контекст

`scripts/probe.sh` сводит коды возврата `taktc` и вердикт эталона. Класс
«код возврата нулевой, а вывод отвергает чужой инструмент» этим замером
**не измеряется** — вывод фичи, повторённый прогоном 2026-08-21 на входе
с переменной `[[u8; 2]; 2]`: цели `st`/`st-at` показаны как `OK`, а `iec2c` их
вывод отвергает.

Фича добавляет к пробе раздел «инструменты целей» — прогон `cc`, `iec2c` + `cc`,
`rustc` + `clippy-driver`, `verilator` + `yosys` по порождённому коду (решение
ADR — Option A, без флага).

### Зависимости фичи

- **Зависит от:** нет. Фича (сам `probe.sh` и его контроль) закрыта; проверки
  целей (0045, 0050, 0098, 0171, 0220) закрыты и служат образцом команд.
- **Влияние на порядок разработки:** ничего не разблокирует формально, но
  удешевляет замер каждой следующей фичи класса «цель порождает невалидный
  вывод» — а таких за месяц было одиннадцать.

### Требования и проверяемые условия

- **R1. Вердикт инструмента печатается по каждой цели.** Восемь строк; у
  `plantuml` инструмента нет, и строка это называет.
- **R2. Флаги совпадают с проверками предкоммита.** `cc -Wall -Wextra -Werror -c`,
  `rustc`/`clippy-driver --edition 2021 --crate-type=lib -D warnings` через
  обёртку `#![no_std]`, `verilator --lint-only -Wall`, `yosys … synth -top`.
  Мягче проверки — ложное «годен»; строже — ложная тревога.
- **R3. Цель `st` проверяется до конца цикла.** После `iec2c` собирается
  порождённый `POUS.c` (`cc -include POUS.h`): урок — форма, принятая
  разбором, не годна, пока не собран её вывод.
- **R4. Отсутствие инструмента отличимо от успеха.** `iec2c`, `verilator`,
  `yosys` внешние; строка «пропуск: нет …» и никогда «принял».
- **R5. Отказ `taktc` снимает шаг инструмента.** Инструменту нечего
  проверять; строка называет код отказа.
- **R6. Замер остаётся дешёвым.** Прогон инструментов добавляет доли секунды
  (замер ADR, драйвер 2); отдельного кэша не заводится.
- **R7. Контроль проверяет предмет, а не запуск.** `scripts/test-probe.sh`
  ловит невалидный вывод, не даёт ложной тревоги на годном и сверяет флаги
  строгости с `precheck.sh`.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Раздел «инструменты целей» есть в выводе пробы | прогон `scripts/probe.sh` на годной пробе |
| A2 | Вход `[[u8; 2]; 2]` даёт отказ `iec2c` у `st`/`st-at` при нулевом коде `taktc` | прогон пробы `nested.takt` |
| A3 | Годный вывод не даёт тревоги ни у одной цели | прогон пробы `structfn.takt` (структура в параметре функции) |
| A4 | Отсутствующий инструмент даёт «пропуск» | контроль: прогон с `PATH` без `verilator` |
| A5 | Флаги не мягче проверок | контроль: греп по `probe.sh` на `-Werror`, `-D warnings`, `-Wall` |
| A6 | Контроль стоит шагом предкоммита и зелён | `scripts/test-probe.sh`, затем `scripts/precheck.sh` |

### Особенности по обратной функциональности

- **Язык не затронут:** ни лексика, ни синтаксис, ни семантика, ни поведение
  целей. (редакторский слой) — **не применимо**, и это фиксируется
  здесь явно: LSP и плагины не задеваются, потому что фича не вводит ни узла
  АСД, ни токена, ни диагностики.
- **Прежний вывод пробы сохранён целиком**: разделы «проверка пробы»,
  «эталон», «цели» не меняются, новый раздел добавляется после них. Тем самым
  чтение старых замеров в карточках остаётся верным.

### Риски и зависимости

- **Два носителя флагов** (проверки и проба). Снижается контролем A5; полный
  вынос команд проверок в общий носитель — отдельная работа (проверки несут
  обвязку: корпус, списки транслируемых примеров, стабы, тестбенчи, `cmake`).
- **Заголовки MatIEC.** Шаг R3 требует `lib/C/iec_std_lib.h`, который кладёт
  `scripts/ensure-iec2c.sh` рядом с `ieclib.txt`. Их отсутствие — тот же
  случай R4 («пропуск»), а не отказ.
- **Имя верхнего модуля SV** берётся из имени файла `.sv` — так же, как в
  проверке предкоммита.

## Разработка

### Задача

#### Что было

`scripts/probe.sh` печатал три раздела: проверку пробы, вердикт эталона и
**коды возврата** `taktc` по восьми целям. Валидность порождённого файла не
проверял никто: цель, вернувшая ноль, показывалась как `OK` независимо от
того, принимает ли её вывод `cc`, `iec2c`, `rustc` или `verilator`.

#### Что сделано

**`scripts/probe.sh`** — новый раздел «инструменты целей» (после раздела
«цели»):

- вердикт трансляции запоминается в `$OUT/gen.<цель>` (пусто — вывод есть,
  иначе код отказа), и раздел его читает: у цели без вывода инструменту нечего
  проверять, строка называет код;
- `c`, `c-hal` → `cc -std=c11 -Wall -Wextra -Werror -c`;
- `st`, `st-at` → `iec2c -I <lib> -T <out>`, затем сборка порождённого C.
  Единицу трансляции выбирает помощник `iec_c_unit`: при наличии
  `<Имя>Config.c` (цель `st-at` — там CONFIGURATION с размещёнными
  переменными) собирается он, иначе `POUS.c` с `-include POUS.h`;
- `rust` → `rustc`, затем `clippy-driver`, оба
  `--edition 2021 --crate-type=lib -D warnings` через обёртку `#![no_std]` —
  как в проверке предкоммита;
- `sv`, `sv-mmio` → `verilator --lint-only -Wall --top-module <модуль>`,
  затем `yosys -q -p "read_verilog -sv …; synth -top …"`;
- `plantuml` → строка «инструмента нет (диаграмма)»;
- отсутствие внешнего арбитра → «пропуск: нет …».

**`scripts/test-probe.sh`** — пять новых проверок (7–11): раздел печатается;
годный вывод тревоги не даёт (контроль); отказ инструмента показан (заглушка
`cc`, отвергающая всё, — механизм проверяется без зависимости от живого
дефекта языка); отсутствие инструмента названо пропуском и не выдаётся за
успех (`IEC2C_PREFIX` в несуществующий путь); флаги строгости на месте;
цель без вывода отмечена кодом отказа.

**`README.md`** — раздел «Снятие замера расхождения» дополнен описанием
вердикта инструментов. **`docs/RULE.md`** — свод: прогон инструментов
внесён в список «что проверяет машина», названа граница «проба у цели `st`
идёт дальше проверки».

**Ложная тревога поймана контролем, а не чтением.** Первая редакция
собирала у обеих ST-целей `POUS.c` напрямую, и `st-at` давала
«call to undeclared function `__GET_GLOBAL_…`» **на любом входе** — включая
`examples/regulator.takt`, проходящий проверка. Контроль, кричащий всегда, замолкает
навсегда (урок исправления); причина — `POUS.c` цели `st-at` включается в
`<Имя>Config.c` после объявления глобальных размещённых переменных.

#### Проверки

```sh
scripts/test-probe.sh                       # сторож, 21 проверка
scripts/probe.sh -n 2 nested.takt           # A2: iec2c ОТВЕРГ у st/st-at
for f in examples/*.takt; do scripts/probe.sh -n 1 "$f"; done   # контроль: 0 тревог
```

Мутации контроля (все три пойманы): снять раздел «инструменты целей»; выдать
пропуск за «iec2c принял»; убрать `-Werror` из команды `cc`.

## Тест-план

### Область и цель

Проверяется инструмент снятия замера — `scripts/probe.sh` — и его контроль.
Язык не затрагивается, поэтому примеров и контрпримеров на Takt свод не
требует; вместо них — **пробы-входы**, на которых измеряется поведение самого
скрипта.

### Выводы и дальнейшие шаги

- **Ложную тревогу поймал контроль, а не чтение.** Первая редакция собирала
  `POUS.c` напрямую у обеих ST-целей, и `st-at` давала
  «call to undeclared function `__GET_GLOBAL_…`» **на любом входе**, включая
  проходящий проверка `examples/regulator.takt`. Причина — `POUS.c` цели `st-at`
  включается в `<Имя>Config.c` после объявления глобальных размещённых
  переменных; единицу трансляции теперь выбирает помощник `iec_c_unit`.
  Урок исправления подтверждён: контроль, кричащий всегда, замолкает навсегда.
- **Найден живой дефект — заводится отдельной фичей.** Цель `st` печатает
  многомерный массив объявлением IEC (`ARRAY [0..1, 0..1] OF USINT`), а
  индексирует его формой C (`grid[1][0]`), и `iec2c` вывод отвергает; цель `c`
  на том же входе отказывает `CC-015`, хотя `uint8_t grid[2][2]` в C
  представим. Класс вынесен кандидатом.
- Исправлений (`docs/fixes/`) не потребовалось.

## Итог (что сделано)

- `scripts/probe.sh` печатает раздел **«инструменты целей»**: порождённый код
  прогоняется `cc -Wall -Wextra -Werror`, `iec2c` (и сборкой порождённого им
  C), `rustc` + `clippy-driver -D warnings`, `verilator --lint-only -Wall` +
  `yosys synth` — теми же флагами, что у проверок предкоммита.
- **Класс, который замер не видел, назван замером же:** вход `[[u8; 2]; 2]`
  показывает цели `st`/`st-at` как `OK` в разделе «цели» и как «iec2c ОТВЕРГ»
  в разделе инструментов.
- **У цели `st` шага два** — намеренно строже проверки (урок: форма,
  принятая разбором, не годна, пока не собран её вывод). Единицу трансляции
  выбирает `iec_c_unit`: у `st-at` собирается `<Имя>Config.c`.
- **Ложную тревогу поймал контроль:** прямая сборка `POUS.c` у `st-at`
  давала «call to undeclared function `__GET_GLOBAL_…`» на **любом** входе,
  включая проходящий проверка `examples/regulator.takt`.
- Отсутствующий арбитр — «пропуск», никогда не «принял»; цель без вывода
  инструмента не получает и называет код отказа `taktc`.
- Контроль `scripts/test-probe.sh` вырос с 10 до 21 проверки; три мутации
  проверены. Контроль на корпусе — ноль ложных тревог на 11 примерах.
- Замер цены: полный прогон пробы — 0.9 с (прежде 0.07 с).
