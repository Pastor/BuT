# Фича: Именованное условие с вызовом функции

- **Номер:** 0503
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 3
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат `FEATURES.md` «именованное условие с вызовом функции непригодно у всех потребителей» (2026-09-02)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

`cond warm = hot() > 3;` не работает **ни у кого**: эталон обрывает прогон
`SIM-016`, семь целей отказывают пятью разными кодами. Причина не в печати:
именованные условия разрешаются на стадии 3, тела функций — на стадии 5, а
поиск функции отдаёт **снимок** её определения. Условие навсегда держит
неразрешённую копию. Фича перепривязывает такие вызовы после стадии 5.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

## Документирование

**Не требуется.** Язык не меняется: запись законна и сегодня — она просто не
работала. Новых диагностик нет; наоборот, снимаются пять разных отказов на
одном входе.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, аналитик, разработчик

### Context

Замер-02 (`scripts/probe.sh`), вход — `cond warm = hot() > 3;` при
`fn hot() -> u8 { return ticks + 1; }`:

| Потребитель | Ответ |
|---|---|
| эталон | `SIM-016` «неразрешённая функция не может быть вызвана» — прогон оборван |
| `c`, `c-hal` | `CC-018` |
| `st`, `st-at` | `ST-011` |
| `rust` | `RS-020` |
| `sv`, `sv-mmio` | `SV-002` |
| `plantuml` | печатает диаграмму (условий он не переводит) |

Перебор мест, где вызов стоит в условии (цель `c`, тот же `hot()`):

| Место | Ответ |
|---|---|
| условие ребра `ref Hot: hot() > 3;` | переводится |
| условие `if` в теле | переводится |
| охранная формула `: hot() < 200;` | переводится |
| `invariant Safe = hot() < 200;` | переводится |
| **именованное условие `cond warm = hot() > 3;`** | **не переводится** |

То есть сломано ровно одно место — и оно единственное, что разрешается **до**
функций.

### Decision Drivers

- Порядок стадий менять нельзя: тела функций (5) ссылаются на именованные
  условия (3), а условие — на функцию; круг разрывается только повторным
  проходом.
- Поиск функции отдаёт снимок (`search_func` клонирует значение из
  `ModelNode::functions`) — это устройство дерева, а не дефект вызова.
- Отказ у каждой цели свой: правило языка не должно выражаться пятью кодами.

### Considered Options

1. **Перепривязка вызовов после стадии 5** (принято). Проход обходит
   именованные условия и заменяет неразрешённое определение функции
   разрешённым — тем же, что вернёт `search_func` на этой стадии.
2. **Перенести разрешение условий после функций.** Отвергнуто: тела функций
   вправе ссылаться на именованное условие (`if warm { … }`), и обратный
   порядок сломал бы этот случай — круг остался бы, только с другой стороны.
3. **Сделать `ModelNode::functions` картой разделяемых ячеек.** Отвергнуто по
   объёму: правка задевает каждого потребителя `search_func`, а выигрыш —
   только этот класс.
4. **Честный отказ семантики «вызов в `cond` не поддержан».** Отвергнуто:
   запись законна по грамматике и работает во всех прочих местах условия;
   сужать язык ради удобства реализации не за что.

### Decision

После стадии 5 (тела функций) выполняется перепривязка: у каждого
именованного условия неразрешённое определение вызываемой функции заменяется
разрешённым. Проход идемпотентен и молчалив: имя, которого нет, оставляется как
есть — о нём говорят прежние проверки.

### Consequences

- `cond` с вызовом функции работает у эталона и у всех целей, переводящих
  условия.
- Пять разных отказов на одном входе исчезают.

#### Acceptance criteria

1. Проба: эталон исполняет, восемь целей переводят, инструменты проверки принимают.
2. Потактовая сверка эталон ↔ `c` на значении, вычисленном функцией из `cond`.
3. Контроль: неизвестное имя функции в `cond` по-прежнему отвергается.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

`semantic/condition/mod.rs::resolve_condition` для `ast::Condition::Function`
берёт определение через `ModelNode::search_func`, а тот **клонирует** значение
из карты функций. На стадии 3 в карте лежит `FunctionDefinitionNode::Unresolved`
(тело ещё не построено), и снимок этим и остаётся: `rebuild_condition` ветвь
`Function` копирует определение как есть.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | После стадии 5 именованное условие держит разрешённое определение функции |
| Т2 | Проход обходит вложенные модели и вложенные условия (`cond b = a;`) |
| Т3 | Имя, которого нет, проходом не трогается — судят прежние проверки |
| Т4 | Прочие места вызова в условии правкой не затронуты (контроль) |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh` по девяти потребителям, потактовая
сверка, набор целей, `precheck.sh`.

### Редакторский слой

**Не требуется:** ни лексика, ни синтаксис, ни набор диагностик не меняются.

### Особенности по обратной функциональности

Изменение только расширяет множество работающих программ.

### Риски и зависимости

- **Риск:** перепривязка встанет не на своё место в конвейере и не успеет к
  копиям условия. Снимается порядком: проход идёт сразу после стадии 5, то есть
  до стадии 4 (тела блоков) и стадии 6 (условия рёбер), которые копируют
  значение условия себе.

## Разработка

### Задача: проход перепривязки

Новый модуль `takt-lang/src/semantic/condition/relink.rs`. Обходит именованные
условия модели и **тела функций** (их копии условия уже построены стадией 5) и
заменяет неразрешённое определение вызываемой функции тем, что вернёт
`search_func` теперь. Вызывается из `stages/mod.rs` сразу после стадии 5 — до
стадий 4 и 6, которые копируют значение условия себе.

Карты условий и функций обходятся **в копии**, а не изымаются `mem::take`:
поиск функции читает ту же модель, и опустошённая карта отвечала бы «функции
нет». Первая редакция изымала — и перепривязка молча не срабатывала ровно там,
где условие лежит в теле функции. Мутация «изъятие вместо копии» оставлена в
отчёте: она воспроизводит этот промах.

## Тест-план

| Проверка | Ожидание |
|---|---|
| перебор восьми мест вызова в условии | все переводятся; провал — списком |
| копии условия: тело блока, тело функции, второе условие, под-модель | перепривязка доходит до каждой |
| потактовая сверка эталон ↔ `c` | `(2,1) (4,1) (4,2) (4,2)` с обеих сторон |
| контроль: неизвестное имя в `cond` | `SE-004` |
| проба по девяти потребителям | эталон исполняет, восемь целей переводят, инструменты принимают |

## Отчёт о тестировании

### Резюме

`./scripts/precheck.sh` — зелёный. Проба `cond warm = hot() > 3;`: эталон
исполняет, восемь целей переводят, `cc`, `iec2c`, `rustc`, `clippy`,
`verilator` и `yosys` вывод принимают. Прежде на том же входе было девять
отказов пятью кодами.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка — три мутации, каждая поймана:

| Мутация | Ответ набора |
|---|---|
| прохода нет (прежнее поведение) | перебор мест (списком из четырёх), под-модель, обе сверки |
| тела функций не обходятся | перебор: «именованное условие в теле функции» |
| карта изымается `mem::take`, а не копируется | то же — промах первой редакции |

Вторая и третья мутации дают **один** симптом, и это не совпадение: обе
означают, что перепривязка не дошла до копии условия внутри функции. Место
названо в тесте отдельной строкой именно поэтому.

### Найденные дефекты

Прогон вскрыл соседний класс, в объём не входящий (заведён кандидатом):
**функция, читающая состояние, вызванная из другой функции**, даёт невалидный
ST (`iec2c`: «Data type incompatibility … invoking function») и отказ `SV-002`.
Контрольный вход без именованных условий даёт то же самое — то есть класс
самостоятелен.

### Выводы и дальнейшие шаги

Записей о снятых отказах в целях не делается: коды `CC-018`, `ST-011`,
`RS-020`, `SV-002` остаются защитой в глубину — они достижимы другими входами.

## Итог (что сделано)

`cond` с вызовом функции работает у эталона и у всех целей. Причина была не в
печати: именованные условия строятся раньше функций, а поиск функции отдаёт
снимок определения — условие держало неразрешённую копию. Перепривязка после
стадии 5 доходит до всех копий условия: карты модели, вложенных условий, тел
функций и вложенных моделей.

Пять разных отказов на одном входе исчезли; неизвестное имя по-прежнему
отвергается `SE-004`.
