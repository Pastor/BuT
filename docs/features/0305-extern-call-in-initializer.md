### Context

Инициализатор объявления вычисляется **до первого такта**. Значение
`extern`-функции при компиляции неизвестно **по определению**: её тело живёт вне
программы.

**Замер-20** (`scripts/probe.sh`) на входе
`extern fn sensor() -> u8; var mirror: u8 := sensor();`:

| Потребитель | Ответ |
|---|---|
| эталон | `mirror = 0` — **молча** |
| `c`, `c-hal` | `CC-023` |
| `rust` | `RS-011` |
| `sv`, `sv-mmio` | `SV-002` |
| **`st`, `st-at`** | **код 0 и потерянный инициализатор** (`mirror : USINT;`) |
| `plantuml` | OK |

Худший ответ — `st`: прошивка получает необъявленное начальное значение, и об
этом не говорит никто.

Класс тот же, что у порта в инициализаторе  и ячейки по адресу
(0189): «чтение того, чего до первого такта нет».

### Decision Drivers

1. **Молчаливая потеря дороже отказа** — прошивка расходится с прогоном без
   единого слова.
2. **Общего поведения не существует:** у эталона внешней функции до первого
   такта нет, у `sv` ветвь сброса выражений не вычисляет. Нормировать нечем —
   значит запрет (тот же довод, что в ADR).
3. **Обход инициализаторов уже есть** — заводить второй значит развести их.

### Considered Options

#### Option A. Оставить как есть

**Cons:** цель `st` продолжает молча терять инициализатор.

#### Option B. Отвергать вызов `extern` в инициализаторе — `SE-084`

Проверка добавляется в **существующий** обход
(`validate/init_undefined_read.rs`) третьим случаем; код берётся уже
существующий — `SE-084` («функция не вычисляется при компиляции: `extern`…»),
чей смысл ровно этот.

**Pros:** девять потребителей отвечают одинаково; текст называет штатный путь
(вызов в теле).
**Cons:** запись, прежде принимавшаяся четырьмя потребителями (двумя — молча),
становится ошибкой.

#### Option C. Нормировать нулём у всех

**Cons:** ноль — это выдумка компилятора: автор писал вызов датчика, а получил
бы константу.

### Decision

Принимается **Option B**.

1. Третий случай в обходе `init_undefined_read` — `UndefinedRead::ExternCall`;
   код `SE-084`, текст называет функцию и штатный путь
   (`always { x := f(); }`).
2. **Форм внешней функции в ячейке две.** Инициализатор разрешается на
   стадии 2, а тела функций строятся на стадии 5 — поэтому в снимке лежит
   `FunctionDefinitionNode::Unresolved(FunctionDefine { external: true, … })`, а
   не `External`. Проверка только второй формы **не ловит ничего**: первая
   редакция так и делала, и проба молчала.
3. **Причина вердикта `InitialValueUnknown` стала защитной** (замер здесь же):
   единственный вход, который её давал, теперь отвергается семантикой. Ветвь
   оставлена и **названа** защитной — как `DomainNotEnumerable` в 0258; тест
   переписан так, чтобы проверять **причину недостижимости**, а не молчать о
   ней.

### Consequences

#### Положительные

- Один вход — один ответ у девяти потребителей.
- Молчаливая потеря инициализатора у `st`/`st-at` исчезла.
- Текст диагностики называет штатный путь.

#### Отрицательные / Action items

- **Ломающее изменение:** запись, которую `st` принимала (теряя смысл), а
  эталон исполнял нулём, теперь отвергается. В корпусе таких записей нет
  (предкоммит зелёный).
- Запрет узкий: прочие невычислимые формы (например, вызов встроенной функции
  отладки) остаются как есть — расширять его без замера нельзя (решение
  заказчика по Option D фичи).

#### Acceptance criteria

1. Вызов `extern` в инициализаторе даёт `SE-084` с именем функции и штатным
   путём.
2. Вложенный вызов (`sensor() + 1`) ловится тем же обходом.
3. **Контроль:** вызов локальной функции остаётся законным.
4. **Контроль:** вызов `extern` в теле остаётся законным.
5. Причина `InitialValueUnknown` названа защитной, тест проверяет недостижимость.
6. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Снять молчаливую потерю инициализатора у целей `st`/`st-at`. ADR принял
Option B: отказ `SE-084` в существующем обходе инициализаторов.

### Замер (снят 2026-08-20)

Кандидат («цели `st` и `st-at` молча теряют невычислимый инициализатор»)
подтверждён, но **форма другая**, чем он предполагал.

**Кандидат называл «вызов функции в инициализаторе» — и ошибался:** вызов
**локальной** функции вычисляется (`const_eval::call`), и `var x := seed();`
работает у всех. Молчаливую потерю даёт только **внешняя** функция:

| Потребитель | До | После |
|---|---|---|
| эталон | `mirror = 0` молча | `SE-084` |
| `c`, `c-hal` | `CC-023` | `SE-084` |
| `rust` | `RS-011` | `SE-084` |
| `sv`, `sv-mmio` | `SV-002` | `SE-084` |
| **`st`, `st-at`** | **код 0, `mirror : USINT;` без `:=`** | `SE-084` |
| `plantuml` | OK | `SE-084` |

**Контрольные входы** (оба остаются законными): вызов локальной функции в
инициализаторе и вызов `extern` **в теле** состояния.

**Находка при реализации:** в снимке ячейки внешняя функция лежит как
`FunctionDefinitionNode::Unresolved(FunctionDefine { external: true, … })`, а не
`External` — инициализатор разрешается на стадии 2, а тела функций строятся на
стадии 5. Первая редакция проверяла только `External` и **не ловила ничего**.

**Второе следствие:** причина вердикта верификации `InitialValueUnknown`
осталась без достижимых входов. Проверено на трёх кандидатах (локальная
функция, приведение, параметр) — ни один её не даёт.

### Зависимости фичи

- **Зависит от:** нет (0266, 0189, 0300 закрыты; используется их общий обход).
- **Влияние на порядок:** снимает кандидата блока 2.

### Требования и проверяемые условия

- **R1.** Вызов `extern` в инициализаторе — `SE-084` с именем функции и штатным
  путём.
- **R2.** Вложенный вызов ловится тем же обходом.
- **R3. Контроль:** локальная функция в инициализаторе законна.
- **R4. Контроль:** `extern` в теле законен.
- **R5.** Причина `InitialValueUnknown` названа **защитной**, а её тест
  проверяет недостижимость через `SE-084`, а не молчит.
- **R6.** Обход остаётся **один** на все правила инициализатора (0203).

### Особенности по обратной функциональности

**Ломающее изменение, и оно обосновано:** запись, которую `st` принимала
(теряя смысл), а эталон исполнял нулём, теперь отвергается. Общего поведения у
неё не существует (у эталона внешней функции до первого такта нет, у `sv`
ветвь сброса выражений не вычисляет) — значит любой «совместимый» выбор был бы
выдумкой компилятора. В корпусе таких записей нет: предкоммит зелёный.

**Версия языка не поднимается:** цикл 0.10.0 идёт, тег `v0.10.0` стоит (последующие фичи цикла вносят изменения в поднятую версию).

Приложение «Ошибки» описывает `SE-084` — текст кода не менялся.

### Риски и зависимости

- **Риск: запрет заденет законный вход.** **Снижение:** два контроля в контроле
  плюс зелёный корпус; запрет узкий — только внешняя функция.
- **Риск: `InitialValueUnknown` тихо умрёт.** **Снижение:** ветвь названа
  защитной в коде, а тест проверяет **причину** недостижимости и упадёт, если
  запрет ослабят.

## Разработка

### Задача

#### Что сделано

**`semantic/validate/init_undefined_read.rs`** — третий случай в **том же**
обходе, что `SE-099` (ячейка) и `SE-113` (порт):
`UndefinedRead::ExternCall(имя)` → `SE-084`. Текст называет функцию и штатный
путь: `always { x := f(); }`.

**Форм внешней функции в ячейке две.** Инициализатор разрешается на стадии
2, тела функций строятся на стадии 5 — поэтому в снимке лежит
`Unresolved(FunctionDefine { external: true, … })`, а не `External`. Первая
редакция проверяла только вторую форму и **не ловила ничего**; поймано пробой,
а не чтением.

**`verification/verify.rs`** — причина `InitialValueUnknown` помечена
**защитной**: единственный вход, который её давал, теперь отвергается
семантикой. Проверено на трёх кандидатах (локальная функция, приведение,
параметр) — ни один её не даёт.

**Тесты:**

- `takt-lang/tests/semantic/extern_initializer_tests.rs` — отказ, рекурсия по
  выражению и **два контроля** (локальная функция; `extern` в теле);
- `unsupported_reason_tests` — тест A4 переписан: он проверяет **причину
  недостижимости** (вход отвергается с `SE-084`), а не молчит о ней.

**`docs/diagnostics/README.md`** — у `SE-084` отмечено второе место эмиссии.

## Итог (что сделано)

**Молчаливая потеря инициализатора у целей `st`/`st-at` устранена.**

- **`SE-084` на вызов `extern`-функции в инициализаторе** — третий случай в
  **том же** обходе, что `SE-099` (ячейка) и `SE-113` (порт): правило одно —
  «инициализатор не читает того, чего до первого такта нет», — и обход обязан
  быть один. Текст называет функцию и штатный путь
  (`always { x := f(); }`).
- **Замер-20:** до правки один вход давал `mirror = 0` **молча** у
  эталона, `CC-023`/`RS-011`/`SV-002` у четырёх целей и **код 0 с потерянным
  инициализатором** у `st`/`st-at`. После — у всех `SE-084`.
- **Кандидат называл форму неверно:** «вызов функции» вычисляется, если
  функция **локальная** (`var x := seed();` работает у всех) — предмет только
  внешняя.
- **Форм внешней функции в ячейке две:** на стадии 2 лежит
  `Unresolved(FunctionDefine { external: true, … })`, а не `External`. Первая
  редакция проверяла только вторую и не ловила ничего.
- **Побочное следствие названо:** причина вердикта верификации
  `InitialValueUnknown` осталась без достижимых входов и помечена **защитной**
  (как `DomainNotEnumerable` в 0258); её тест переписан так, чтобы проверять
  **причину** недостижимости.

**Ломающее изменение** (обосновано в ADR): запись, которую `st` принимала,
теряя смысл, теперь отвергается; общего поведения у неё не существует. В
корпусе таких записей нет.
