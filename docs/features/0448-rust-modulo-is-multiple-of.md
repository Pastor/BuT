## Краткое описание

Цель `rust` печатала `x % k = 0` как `(x % k) == 0`, а `clippy` под
`-D warnings` — флагами проверки самой цели — отвечает `manual_is_multiple_of`.
Фича печатает такие сравнения методом: `x.is_multiple_of(k)`, а для `!= 0` —
`!x.is_multiple_of(k)`.

> Фича заведена из блока кандидатов.

## Документирование

**Не требуется:** язык не меняется, наблюдаемое поведение — тоже. Меняется
идиома печати у одной цели; таблицы соответствия форм в
[README](../../README.md) эта запись не касается.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31

### Context

Замер-31 (`clippy 0.1.97`), проба с четырьмя формами остатка:

| Запись в модели | Печать цели `rust` | `clippy -D warnings` |
|---|---|---|
| `n % 2 = 0` (`n: u8`) | `(self.n % 2) == 0` | **отказ**, `replace with: self.n.is_multiple_of(2)` |
| `n % 3 != 0` | `(self.n % 3) != 0` | **отказ**, `!self.n.is_multiple_of(3)` |
| `0 = n % 5` | `0 == (self.n % 5)` | **отказ** (та же запись для линтера) |
| `n % d = 0` (`d: u8`) | `((self.n as i32) % (self.d as i32)) == 0` | принято |
| `s % 2 = 0` (`s: i16`) | `(self.s % 2) == 0` | принято |

Проверка цели `rust` гоняет **только корпус**, а в корпусе записи `x % k = 0`
нет вовсе — потому класс и не был виден. Нашёлся он пробой при работе над
фичей.

### Decision

Печатать методом там, и только там, где замена **тождественна**:

1. тип левого операнда — **беззнаковое целое**: `is_multiple_of` в стабильном
   Rust есть только у беззнаковых, и `clippy` тем же ограничен;
2. делитель — **ненулевой литерал**: `x % 0` паникует, а `x.is_multiple_of(0)`
   возвращает `x == 0` — на переменном делителе замена меняла бы **поведение**;
3. вторая сторона — литеральный ноль, оператор `=` либо `!=`; стороны
   равноправны (`0 = x % k` — та же запись).

Правило живёт в печатнике сравнений (`rust_expr::comparison`) рядом с
существующим упрощением `bool_comparison` — прецедент той же природы: форма
меняется ради линтера цели, значение остаётся прежним.

### Considered Options

- **A. Печатать методом** — принято.
- **B. `#[allow(clippy::manual_is_multiple_of)]` в порождённом модуле** —
  отвергнуто: проект не глушит линтеры чужих инструментов (на котором
  стоит и запрет `lint_off` у цели `sv`). Заглушка спрятала бы и
  будущие настоящие случаи.
- **C. Обойти форму записи** (`x % k < 1`) — отвергнуто: запись, которую человек
  не пишет, ради обмана линтера.

### Consequences

Вывод корпуса **не меняется** (проверено прогоном: `examples/generated/rust`
байт в байт). Порождённый код требует `rustc ≥ 1.87` — версии, где
`is_multiple_of` стабилизирован; толчейн проекта `1.97.1`.

#### Acceptance criteria

- A1. `x % k = 0` и `x % k != 0` при беззнаковом `x` печатаются методом.
- A2. Переменный делитель и знаковый операнд правилу не подлежат.
- A3. `clippy -D warnings` принимает вывод.
- A4. Значения не меняются: потактовая сверка с эталоном.

## Анализ

### Цель и контекст

Предмет — идиома печати у цели `rust`. Проверяемое условие: линтер цели
принимает вывод, а значения не меняются.

### Замер

Таблица форм выше. Дополнительно: вывод корпуса при правке не изменился —
записи `x % k = 0` в `examples/` нет, что и объясняет молчание проверки.

### Зависимости фичи

Нет.

### Требования и проверяемые условия

- R1. A1…A4 выше.
- R2. Правило проверяет **узлы**, а не напечатанный текст: форма записи
  (скобки, порядок сторон) значения не имеет.

### Критерии приёмки и способ проверки

Потактовая сверка `conformance_modulo_tests` плюс прогон `clippy` в том же
наборе; мутации правила; полный `precheck.sh`.

### Редакторский слой

**Не затронут:** ни лексика, ни синтаксис, ни семантика не меняются.

### Особенности по обратной функциональности

Аддитивно: меняется печать одной формы у одной цели, вывод корпуса прежний.

### Риски и зависимости

Риск один — применить правило там, где замена меняет поведение (нулевой или
переменный делитель, знаковый операнд). Он снят условиями правила и мутациями:
«разрешить знаковый» роняет сборку драйвера, «потерять отрицание» — сверку.

## Разработка

`takt-lang/src/generator/rust/rust_modulo.rs` — правило (функция `multiple_of`)
и его обоснование; вызов — из `rust_expr::comparison`, до существующего
`bool_comparison`.

Отдельный модуль **не по вкусу**: `rust_expr.rs` уже стоял на 975 строках, и
правка упёрлась в лимит размера (`check-module-size.sh` — 1035 при 1000).
Новое вынесено, как того и требует правило.

## Итог

Ещё один случай, где вывод цели отвергался её же проверкой, а проверка этого не
показывал: корпус нужной записи не содержит. Правило узкое ровно настолько,
насколько тождественна замена, и обе границы (нулевой делитель, знаковый
операнд) закреплены контролем.
