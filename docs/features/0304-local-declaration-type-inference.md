# Фича: Локальное объявление в теле блока получает тип

- **Номер:** 0304
- **Статус:** ГОТОВО
- **Зависит от:** нет (проставлено на стадии анализа 2026-08-20)
- **Tier:** 1 — инструменты расходятся на одном входе, и один из них молчит
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат блока 2 `FEATURES.md` (замер при закрытии [wider_type(Integer, Array) берёт тип литерала и даёт ложную SE-089](0287-wider-type-array-literal.md), 2026-08-19), снят закрытием этой фичи

## Краткое описание

`var g := F + 1;`, написанное **внутри** `always { … }`, оставалось с типом
`Inference`: вывод типов шёл только по объявлениям верхнего уровня. Один вход
давал **три** разных ответа, и один из них был молчаливым.

## Документирование

**Не требуется.** Язык не меняется — исполняется то, что он уже обещает: вывод
типа из инициализатора. Раздел документа о переменных описывает вывод без
оговорки «только на верхнем уровне», то есть текст был верен, а инструменты —
нет.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-20
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича](0304-local-declaration-type-inference.md); [фича](0287-wider-type-array-literal.md) (где замер снят), [фича](0204-const-ref-type-inference.md) (вывод через ссылку — та же машинерия), [фича](0235-guard-formula-in-st-sv.md) (форму SV проверяют оба инструмента)

### Context

Вывод типов (`semantic::type_inference`) идёт по `model.variables` — таблице
объявлений **уровня модели**. Локальное объявление тела (`StatementNode::Variable`)
в неё не входит, и `var g := F + 1;` внутри `always { … }` оставался с
`TypeNode::Inference`.

**Замер-20** (`scripts/probe.sh`) — один вход, **три**
разных ответа:

| Потребитель | Ответ |
|---|---|
| эталон | `SIM-007` **в такте** |
| `c`, `c-hal` | `CC-015` |
| `st`, `st-at` | `ST-002` |
| `rust` | `RS-014` |
| **`sv`, `sv-mmio`** | **код 0 и невалидный модуль** |
| `plantuml` | OK |

Контрольный вход (то же объявление на **верхнем уровне**) переводится всеми —
значит предмет именно тело блока.

**Второй дефект, найденный контрольной пробой:** у цели `sv` локальные
переменные тел состояний **не объявлялись вовсе** — `hoist_locals` звался
только для тел функций. Это воспроизводится и на **явном** типе
(`var g: u8 := …`), то есть от вывода типов не зависит.

### Decision Drivers

1. **Молчаливый невалидный вывод — худший из ответов** (класс Tier 2): `taktc`
   рапортует об успехе, а отказ приходит от чужого инструмента.
2. **Язык уже обещает вывод типа** — документ не оговаривает «только на верхнем
   уровне»; неисполненное обещание и есть дефект.
3. **Правку надо делать там, где строится узел:** к моменту `type_inference`
   тела блоков ещё не построены.

### Considered Options

#### Option A. Отдельный проход по телам после построения

**Pros:** повторяет устройство `type_inference` (неподвижная точка).
**Cons:** второй обход всех тел ради случая, где инициализатор уже под рукой;
плюс порядок: тела строятся позже, и проход пришлось бы звать из нескольких
мест.

#### Option B. Вывод при понижении оператора

Тип берётся у `extract_type` сразу, как построен инициализатор.

**Pros:** одно место, никакого нового прохода; ссылки на объявления модели уже
разрешены (их типы известны).
**Cons:** цепочка локальных объявлений разрешается **в порядке текста** — но
именно так язык их и видит (правило: имя значит значение и ссылается
назад по тексту).

### Decision

Принимается **Option B**, и вместе с ним чинится найденное:

1. `semantic/statement/mod.rs`: при понижении `ast::Statement::Variable` тип
   `Inference` заменяется выведенным из инициализатора.
2. `generator/sv/sv_blocks.rs`: тела состояний и модели получают объявления
   локальных — `emit_hoisted_locals_auto` печатает `automatic logic …`.
   Форма проверена **обоими** инструментами: `verilator --lint-only -Wall` и
   `yosys -p synth` её принимают.
3. Заведена потактовая **сверка** значений (эталон против `c`) плюс проверка
   валидности вывода `sv` линтом.

### Consequences

#### Положительные

- Все девять потребителей отвечают одинаково на законной записи.
- Цель `sv` перестала печатать модуль со ссылкой на необъявленную переменную —
  в том числе на входах с **явным** типом, которые дефект задевал давно.

#### Отрицательные / Action items

- Вывод идёт по порядку текста: локальное объявление, ссылающееся на другое
  **ниже** по тексту, типа не получит. Это согласовано с правилом.
- Версия языка **не поднимается**: обещание языка не менялось — исполняется уже
  описанное (цикл 0.10.0 идёт, тег v0.10.0 стоит).

#### Acceptance criteria

1. Эталон исполняет локальное объявление; все восемь целей переводят.
2. Трассы эталона и цели `c` совпадают на **накапливающем** теле.
3. Вывод `sv` проходит `verilator --lint-only -Wall` и синтез `yosys`.
4. **Контроль:** явный тип у локальной переменной тоже даёт валидный SV.
5. Регрессия: `cargo test --all-features`, `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Убрать расхождение девяти потребителей на законной записи. ADR принял
Option B — вывод при понижении оператора.

### Замер (снят 2026-08-20)

Проба `scripts/probe.sh` на входе с `var g := F + 1;` внутри `always`:

| Потребитель | До | После |
|---|---|---|
| эталон | `SIM-007` в такте | исполняет (`probe=12`) |
| `c`, `c-hal` | `CC-015` | OK |
| `st`, `st-at` | `ST-002` | OK |

**Контрольный вход** (то же объявление на верхнем уровне) работал всегда —
значит предмет именно тело блока, а не форма выражения.

**Вторая контрольная проба нашла отдельный дефект:** у цели `sv` локальные
переменные тел не объявлялись **и при явном типе** (`var g: u8 := F + 1;` →
`Can't find definition of variable`). То есть дефекта было два, и второй
кандидат не называл.

- **Влияние на порядок:** снимает кандидата блока 2.

- **R3.** Цель `sv` объявляет локальные переменные тел состояний и модели.

- **R5.** Значения совпадают: потактовая сверка эталона и цели `c` на
  накапливающем теле.
- **R6. Контроль:** явный тип тоже даёт валидный SV.
- **R7.** Регрессия: корпус, снапшоты, предкоммит.

**Совместимость улучшается:** запись, которая прежде отвергалась (или давала
невалидный вывод), теперь переводится. Обратной поломки нет — ни один
работавший вход не меняет поведения (корпус и снапшоты не изменились).

**Версия языка не поднимается:** язык не менялся — исполняется уже описанное
поведение. Цикл 0.10.0 идёт, тег `v0.10.0` стоит (последующие фичи
цикла вносят изменения в поднятую версию).

### Редакторский слой

**Не требуется.** Ни лексика, ни синтаксис, ни диагностики не менялись: правка
внутри вывода типов и печатника `sv`. Новых кодов нет.

### Документирование

**Не требуется.** Документ описывает вывод типа без оговорки «только на верхнем
уровне» — текст был верен, а инструменты нет.

### Риски и зависимости

- **Риск: вывод «не туда» на сложном инициализаторе.** **Снижение:** зовётся та
  же `extract_type`, что и для верхнего уровня; разойтись двум путям не по чему.
- **Риск: `automatic` в SV изменит семантику.** **Снижение:** форма проверена
  обоими инструментами; переменная живёт внутри одного вычисления, регистровой
  пары у неё нет (это записано в печатнике).
- **Риск: сверка мерит не то.** **Реализовался:** первая редакция фикстуры не
  имела перехода, состояние уходило в `END`, и накопление не
  наблюдалось. Поймано самой сверкой; добавлен самопереход.

## Разработка

### Задача

#### Что сделано

**1. `semantic/statement/mod.rs`** — при понижении `ast::Statement::Variable`
тип `TypeNode::Inference` заменяется выведенным из инициализатора
(`type_inference::extract_type`).

Выводить надо **здесь**, а не общим проходом: локальное объявление живёт в
теле блока, а не в таблице модели, и к моменту `type_inference` тела ещё не
построены.

**2. `generator/sv/sv_blocks.rs` + `sv_stmt.rs`** — тела состояний и модели
получают объявления локальных переменных: новый `emit_hoisted_locals_auto`
печатает `automatic logic …` перед операторами.

Это **отдельный дефект**, не зависевший от первого: `hoist_locals` звался
только для тел функций, и цель печатала `g = (F + 1);` без объявления — при
**нулевом** коде возврата. Воспроизводится и на явном типе.

`automatic` обязателен: тело печатается внутри ветви `unique case` в
`always_comb`, где обычное объявление было бы статической переменной. Форма
проверена **обоими** инструментами (`verilator --lint-only -Wall` и
`yosys -p synth`).

**3. Сверка** `takt-sim/tests/conformance/conformance_local_decl_tests.rs`:
потактовые трассы эталона и цели `c` на **накапливающем** теле (`sum := sum + g`)
плюс проверка валидности вывода `sv` линтом.

#### Проверка

```sh
sh scripts/probe.sh -n 2 <модель с локальным объявлением>
cargo test --test conformance conformance_local_decl_tests::
```

## Итог (что сделано)

**Одна запись — один ответ у всех девяти потребителей.**

- **Тип локального объявления выводится** из инициализатора при понижении
  оператора (`semantic/statement/mod.rs`). Общим проходом это сделать нельзя:
  локальное объявление живёт в теле блока, а не в таблице модели, и к моменту
  `type_inference` тела ещё не построены.
- **Цель `sv` перестала печатать невалидный модуль.** Второй дефект,
  **не зависевший** от первого: локальные переменные тел состояний не
  объявлялись вовсе (`hoist_locals` звался только для функций) — воспроизводится
  и на **явном** типе. Объявление печатается как `automatic logic …` в ветви
  `unique case`; форма проверена **обоими** инструментами (verilator и yosys).
- **Сверка** `takt-sim/tests/conformance/conformance_local_decl_tests.rs`:
  потактовая трасса эталона против цели `c` на **накапливающем** теле плюс
  проверка валидности вывода `sv` линтом.

**Замер-20** (`scripts/probe.sh`): эталон — `SIM-007` в
такте; `c`/`c-hal` — `CC-015`; `st`/`st-at` — `ST-002`; `rust` — `RS-014`;
**`sv`/`sv-mmio` — код 0 и невалидный модуль**. После правки все восемь целей

**Первая редакция фикстуры мерила не то:** состояние без переходов уходит в
