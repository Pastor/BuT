# Фича: Переопределение типа не проверяется: встроенный тип можно затенить молча

- **Номер:** 0243
- **Статус:** ГОТОВО
- **Зависит от:** не проставлено — проставит аналитик на стадии анализа (правило 17)

## Краткое описание

Объявление типа (`type`, `struct`, `enum`) **не проверяется** ни на совпадение
со встроенным типом языка, ни на повторное объявление того же имени. Автор
вправе написать `type u8 = i64;` — и с этого места `u8` в файле означает
64-битное знаковое целое, а встроенный `u8` становится недостижим. Ни одна
диагностика при этом не выдаётся.

**Класс:** семантика (правило языка о пространстве имён типов).

## Что известно на входе

**Замер (2026-08-17, `taktc` коммита `9c9eb5bc`).** Все формы приняты молча,
компилятор рапортует об успехе:

| Проба | Результат | Что в порождённом C |
|---|---|---|
| `type u8 = i64;` + `var x: u8 := 200;` | принято | `int64_t x;` — встроенный `u8` подменён |
| `struct u8 { a: u16, b: u16 }` + `var v: u8 := {1, 2};` | принято | `typedef struct u8 { … } u8;`, поле `u8 v;` |
| `enum u8 { Off, On }` | принято | перечисление с именем встроенного типа |
| `type Level = u8; type Level = i64;` | принято | `int64_t x;` — **побеждает последнее** объявление |
| `struct S { a: u8 } struct S { b: u16 }` | принято, но затем `SE-061` | «структура 'S' не содержит поля 'a'» — диагностика **о следствии**, не о причине |

Симулятор ведёт себя так же (проба `type u8 = i64` исполняется, `x = 201`), то
есть эталон и цели согласованы — расхождения потребителей здесь нет. Дефект в
**языке**: правило «имя типа занято» не сформулировано и не проверяется.

**Последняя строка таблицы — главная.** Дубль пользовательской структуры уже
сегодня заканчивается ошибкой, но ошибка приходит **не по адресу**: автор ищет
опечатку в имени поля, тогда как причина — второе объявление, затёршее первое.
Это тот же класс, что 0204 (диагностика о следствии) и 0157.

**Соседи по языку проверяются.** Дубль **модели** отвергается («Модель с
именем '…' уже объявлена», `semantic/tree.rs`), коллизия имени условия и
переменной — `SE-054`, повторное объявление функции — тоже отказ. Не проверяются
ровно **типы**: `TypeDefine`, `StructDefine`, `EnumDefine` кладутся в `types`
без вопросов, а `builtin_type_by_name` (`semantic/type_node.rs`) спрашивается
**после** пользовательской таблицы — отсюда затенение.

**Имя типа — не ключевое слово, и это осознанно** (фича
[мёртвая лексика: слова и терминалы, которых грамматика не знает](./0201-dead-lexemes.md)): `bit`, `bool`, `u8`, `q` в `KEYWORDS` не
значатся, типы в грамматике суть `Type: Alias(Identifier)`, поэтому
`var bit: u8 := 1;` законен. Значит запрет обязан жить в **семантике**, а не в
лексере: сделать имена типов ключевыми словами — значит запретить и законные
имена переменных (класс решения, где правило языка перенесли из
квантификатора грамматики в семантику).

**Что предстоит решить (предмет ADR).**

1. **Затенение встроенного** — ошибка всегда либо предупреждение? Заказчик
   назвал ошибку; проверить, не опирается ли на затенение какой-нибудь приём в
   корпусе (замер обязателен: в `examples/` и фикстурах поискать имена типов,
   совпадающие со встроенными).
2. **Повторное объявление типа** — отдельный код с **двумя** позициями («здесь»
   и «уже объявлен здесь»), по образцу `name_collisions.rs` фичи, где обе
   позиции признаны обязательными.
3. **Область действия правила** — файл, модель или всё дерево с импортами?
   Импорт переносит типы к импортёру, поэтому столкновение
   возможно и через `import`; решение обязано это покрыть.
4. **Коды** — свободные в реестре после `SE-106`; тексты и раздел приложения
   документа (правила 25, 26).
5. **Форма имени** — `q(m, n)` и `[T;N]` именами не являются; список запретных
   имён обязан браться у **одного** носителя (`builtin_type_by_name`), а не
   переписываться в проверке.

### Context

Объявление типа (`type`, `struct`, `enum`) не проверяется ни на совпадение со
встроенным типом языка, ни на повторное объявление того же имени.

#### Замеры (2026-08-17, `taktc` коммита `9c9eb5bc`)

**Все формы принимаются молча, компилятор рапортует об успехе:**

| Проба | Результат | Что получается |
|---|---|---|
| `type u8 = i64;` + `var x: u8 := 200;` | принято | `int64_t x;` — встроенный `u8` подменён и недостижим |
| `struct u8 { a: u16, b: u16 }` | принято | `typedef struct u8 { … } u8;` |
| `enum u8 { Off, On }` | принято | перечисление с именем встроенного типа |
| `type Level = u8; type Level = i64;` | принято | побеждает **последнее** объявление |
| `struct S { a: u8 }` дважды | принято, затем `SE-061` | «структура 'S' не содержит поля 'a'» — **о следствии**, не о причине |

Эталон и цели согласованы между собой (проба `type u8 = i64` исполняется, даёт
`x = 201`), то есть расхождения потребителей нет — пробел в **языке**.

**Соседи по языку проверяются:** дубль модели отвергается («Модель с именем
'…' уже объявлена»), коллизия имени условия с переменной — `SE-054`, повторная
функция — отказ. Не проверяются ровно типы: `TypeDefine`/`StructDefine`/
`EnumDefine` кладутся в `types` без вопросов, а `builtin_type_by_name`
(`semantic/type_node.rs`) спрашивается **после** пользовательской таблицы —
отсюда затенение.

#### Решающий замер: цена запрета

В корпусе `examples/` — **ни одного** объявления, затеняющего встроенный тип.
В фикстурах — **25 файлов**, и почти все несут наследие эпохи до встроенных
целых: `type u8 = [bit;8];`. Отдельный случай —
`takt-lang/tests/data/include/std.takt` («стандартная библиотека типов BuT» —
старое имя проекта), объявляющая `u8`, `u16`, `u32`, `u64`, `u128`, `bool`.

**Проверено пробами: затенённый и встроенный типы дают тождественный
результат.**

| Проба | Встроенный `u8` | `type u8 = [bit;8]` |
|---|---|---|
| Представление в C | `uint8_t flags;` | `uint8_t flags;` |
| Битовый доступ `flags.0` | `((model->flags >> 0) & 1u)` | то же |
| Арифметика `200 + 100` (симулятор) | `44` (обёртка `mod 256`) | `44` |
| Цели `st` / `rust` / `sv` | — | вывод совпадает (отличия только в имени модели) |
| `type bool = bit;` в цели `rust` | `f: bool` | `f: bool` |

Причина совпадения: `[bit;N]` при N ≤ 64 — **упакованный скаляр**
([семантика `[bit;N]` расходится втрое](0078-bit-array-semantics.md#архитектура-adr)), то есть то же представление, что у
целого. Следовательно **чистка фикстур безопасна**: удаление затеняющих строк
поведения не меняет. `u128` встроенным **не является** (`builtin_type_by_name`
знает `u8`…`u64`, `i8`…`i64`), поэтому `type u128 = [bit; 128];` остаётся
законным и под запрет не попадает.

### Decision Drivers

1. **Заказчик назвал требование прямо:** «должна быть ошибка, что тип с таким
   именем уже определён — или где определён, или что он встроенный».
2. **Диагностика обязана указывать на причину, а не на следствие.** Сегодня
   дубль структуры проявляется как `SE-061` про отсутствующее поле — автор ищет
   опечатку там, где её нет.
3. **Правило языка — предмет семантики, а не лексера.** Имена типов намеренно не
   ключевые слова ([мёртвая лексика: слова и терминалы, которых грамматика не знает](0201-dead-lexemes.md#архитектура-adr)): `var bit: u8 := 1;` законен.
   Запрет через `KEYWORDS` отнял бы и законные имена переменных — тот же выбор,
   что сделала [семантика перечисления без вариантов](0172-empty-enum-semantics.md#архитектура-adr).
4. **Один носитель списка встроенных имён.** Список обязан спрашиваться у
   `builtin_type_by_name`, а не переписываться в проверке.

### Considered Options

#### Option A. Ошибка на обе формы: затенение встроенного и повторное объявление

Два кода: **`SE-107`** («имя типа занято встроенным типом языка») и
**`SE-108`** («тип с таким именем уже объявлен») — второй с **двумя** позициями,
как `name_collisions.rs` фичи.

**Pros:**
- Отвечает требованию заказчика буквально.
- Убирает молчаливую подмену смысла типа и диагностику о следствии.
- Цена измерена и мала: корпус чист, фикстуры чистятся без изменения поведения.

**Cons:**
- Ломает 25 фикстур — их надо править в рамках фичи.
- `std.takt` теряет пять объявлений из семи; файл остаётся осмысленным
  (`u128`, вспомогательные модели), но его роль «стандартной библиотеки типов»
  становится исторической.

#### Option B. Предупреждение вместо ошибки

**Pros:** ничего не ломает сразу.

**Cons:**
- Требование заказчика — ошибка. Предупреждение оставляет молчаливую подмену
  смысла работающей: `type u8 = i64;` продолжит менять значение `u8` во всём
  файле.
- Проект уже знает цену «предупреждения вместо отказа»: 0232 показала, что
  недоставленное предупреждение неотличимо от отсутствующего.

#### Option C. Запрет только затенения встроенных; дубли оставить как есть

**Pros:** правка вдвое меньше.

**Cons:** дубль пользовательского типа — ровно тот случай, где сегодня
диагностика **обманывает** (`SE-061` о поле вместо причины). Оставить его —
значит закрыть меньшую половину задачи.

### Decision

**Принято решением заказчика 2026-08-17: Option A**, оба кода сразу:

1. **`SE-107`** — объявление типа (`type`/`struct`/`enum`) с именем встроенного
   типа. Текст называет **имя** и то, что оно принадлежит языку.
2. **`SE-108`** — повторное объявление типа в одной области видимости. Текст
   несёт **две** позиции: где объявлен повторно и где объявлен впервые.
3. **Область действия** — таблица типов модели с учётом импорта: `import`
   переносит типы к импортёру, поэтому столкновение возможно и
   через него. Импортированное объявление, столкнувшееся с локальным, обязано
   давать `SE-108` с позицией **в файле-источнике** — иначе автор не найдёт
   вторую половину.
4. **Фикстуры чистятся в той же фиче**: 25 файлов, поведение не меняется
   (доказано пробами). `type u128 = [bit; 128];` сохраняется — `u128` не
   встроен.

### Consequences

#### Положительные

- `type u8 = i64;` перестаёт молча менять смысл языка внутри файла.
- Дубль типа диагностируется по причине, а не по следствию.
- Список встроенных имён остаётся у единственного носителя.

#### Отрицательные / Action items

- 25 фикстур и `std.takt` требуют правки; каждая проверяется прогоном, а не
  чтением.
- Документ `book/`: раздел о типах пополняется правилом, врезка «Частые ошибки»
  — кодами, приложение «Ошибки и предупреждения» — описанием (правила 24–26).
- **`std.takt` после чистки перестаёт быть «библиотекой типов»** — стоит
  решить, оставить ли файл вовсе (в нём есть вспомогательные модели) или
  переименовать его роль. Предлагается оставить и снабдить пояснением.

#### Acceptance criteria

1. `type u8 = …`, `struct u8 {…}`, `enum u8 {…}` отвергаются `SE-107` с позицией
   объявления.
2. Повторное объявление типа отвергается `SE-108` с **двумя** позициями.
3. `SE-061` про несуществующее поле больше не возникает на входе с дублем
   структуры (проверяется тем же входом, что в замере).
4. Корпус и фикстуры зелены; поведение фикстур после чистки не изменилось
   (сверка трасс до/после).
5. Коды описаны в реестре и в приложении документа.

## Анализ

### Цель и контекст

Объявление типа не проверялось ни на совпадение со встроенным именем, ни на
повтор: `type u8 = i64;` молча подменял встроенный тип во всём файле, а дубль
структуры проявлялся посторонней `SE-061` про несуществующее поле. ADR принял
**Option A** — ошибка на обе формы, два кода.

### Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Правка локальна для семантики; грамматика, цели и
  симулятор не затрагиваются.
- **Влияние на порядок разработки:** ничего не блокирует и не разблокирует.

### Требования и проверяемые условия

- **R1. Одна воронка на три формы.** `type`, `struct`, `enum` занимают имя через
  единственную функцию; список встроенных имён берётся у `builtin_type_by_name`.
- **R2. `SE-107` — имя занято языком.** Позиция указывает на **имя** в
  объявлении, текст называет имя и причину.
- **R3. `SE-108` — имя уже занято.** Две позиции: где повторно и где впервые.
- **R4. Импорт закрыт с обеих сторон.** `import` до локального объявления —
  ловится воронкой (позиции библиотеки перенесены); `import` после — ловится в
  `adopt.rs`, иначе `extend` молча заменил бы локальный тип библиотечным.
- **R5. Заметка честна о файле.** Координата печатается, только если заметка
  указывает в тот же файл; иначе текст называет источник, а координата
  опускается — чужая строка под своим путём обманывает.
- **R6. `u128` остаётся законным** — встроенным он не является.
- **R7. Фикстуры чистятся без изменения поведения** (доказано пробами ADR).
- **R8. Документ обновлён** (правило 24): раздел о типах, врезка «Частые
  ошибки», приложение «Ошибки и предупреждения».

|---|---|---|
| A1 | Три формы затенения отвергаются `SE-107` | контроль `type_redefinition_tests` |
| A2 | Дубли отвергаются `SE-108` с заметкой | тот же контроль |
| A3 | Прежняя `SE-061` на дубле структуры больше не приходит | тот же вход, что в замере |
| A4 | Импорт закрыт в обе стороны | проба `lib.takt` + `app.takt` |

### Особенности по обратной функциональности

**Совместимость ломается намеренно и обоснованно** (правило 11): запись
`type u8 = …` перестаёт компилироваться. Обоснование — она молча меняла смысл
языка внутри файла, а её единственное применение в проекте (25 фикстур,
`std.takt`) было наследием эпохи до встроенных целых. Пробы ADR показали
тождественность `[bit;8]` и `u8` во всех целях и в эталоне, поэтому чистка
безопасна. Автору, у которого такая запись есть, `SE-107` называет способ
починки — выбрать свободное имя.

**Редакторский слой (правило 29): правки не требуется.** Новых токенов, узлов
АСД и форм объявления нет; диагностики доезжают до LSP общей точкой
`collect_compile_diagnostics`.

### Риски и зависимости

- **Риск: фикстура теряет предмет при чистке.** Часть фикстур существует ради
  проверки псевдонимов — им нужно **переименование**, а не удаление. Снижение:
  каждая правка проверяется прогоном, а не чтением (класс уже проявился:
  `type_aliases.takt`, `type_alias_inference.takt`, `hover_big`).
- **Риск: заметка из чужого файла врёт координатой.** Снят R5.

## Разработка

### Задача

#### Что было

`ModelElement::Type`/`Enum`/`Struct` клали имя в `types`/`type_locs` без
вопросов. Следствия — в замерах ADR: затенение встроенного типа и молчаливое
затирание первого объявления вторым.

#### Что сделано

**Воронка `takt-lang/src/semantic/type_registry.rs`.** `claim_type_name` судит
имя: `SE-107`, если оно принадлежит языку (список — у `builtin_type_by_name`,
своей копии нет), `SE-108`, если уже занято (с позицией первого объявления
заметкой). Туда же переехала регистрация псевдонима (`declare_alias`): занятие
имени и запись типа — одно действие, разнесённые по файлам они разъезжаются.

**Три места вызова** — ветви `Type`, `Enum`, `Struct` в `tree.rs`. Имя
занимается **до** построения узла и до разбора полей: иначе объявление успевало
затереть чужую запись.

**Импорт (`import/adopt.rs`).** Переносятся `type_locs` (без них у `SE-108` не
было бы второй позиции) и проверяется столкновение, когда `import` идёт **после**
локального объявления — прежде `extend` молча заменял локальный тип
библиотечным. Обратный порядок ловит сама воронка.

**Печать заметок (`diagnostics/position.rs`).** Заметка получила координату:
прежде «первое объявление — здесь» не отвечало на вопрос «где». Если заметка
указывает в **другой** файл (столкновение через `import`), координата
опускается, а текст называет источник: чужая строка под своим путём — обман.
Модуль заведён по правилу размера — родитель был сверх лимита.

**Чистка корпуса фикстур: 25 файлов.** Не механическая: часть фикстур
существует **ради** проверки псевдонимов, и удаление лишило бы их предмета —
там типы **переименованы** (`u8` → `Byte`, `u16` → `Word`, `u32` → `DWord`), а
тесты подтянуты. Отдельный случай — `hover_big`, где позиция задана арифметикой
по номерам строк: удаление строки сдвинуло координату. `std.takt` потеряла пять
объявлений из семи; `u128` остался законным.

**Документ** (правило 24): раздел «Типы» получил правило с примерами и два кода
во врезке «Частые ошибки», приложение — разборы обоих кодов. Проверка глифов
поймал `⚠️` в приложении — заменено врезкой, как принято в документе.

### Выводы и дальнейшие шаги

1. **Замер ADR решил судьбу фичи.** Запрет ломал 25 фикстур, и цена зависела от
   того, эквивалентны ли `[bit;8]` и встроенный `u8`. Пробы показали
   тождественность во всех целях и в эталоне — чистка оказалась безопасной, а
   решение принято на факте, а не на осторожности.
2. **Чистка не была механической.** Часть фикстур проверяет **сами псевдонимы**;
   там понадобилось переименование, иначе тест остался бы без предмета. Один
   тест (`hover_big`) задаёт позицию арифметикой по номерам строк — удаление
   строки сдвинуло координату. Оба класса найдены прогоном, а не чтением.
3. **Побочное улучшение:** заметки диагностик получили координату — это касается
   всех диагностик с заметками, а не только новых.
4. **Проверки сработали как задумано:** размер модулей заставил вынести печать
   позиций в отдельный модуль, а `-D missing-docs` поймал разорванный
   док-комментарий.
5. **Исправлений (`docs/fixes/`) не потребовалось.**

## Итог (что сделано)

**Имя типа занимается один раз** (версия языка `0.10.0`). Объявление `type`,
`struct` и `enum` проходит через единственную воронку
`semantic/type_registry.rs`:

- **`SE-107`** — имя принадлежит встроенному типу языка. Список берётся у
  `builtin_type_by_name`, своей копии нет, поэтому `u128` остаётся законным.
- **`SE-108`** — имя уже занято: две позиции, «где повторно» и «где впервые».
  Этот же код закрывает столкновение через `import` — в обе стороны, потому что
  `adopt.rs` теперь переносит `type_locs` и проверяет занятость до `extend`.

Прежде обе формы принимались молча: `type u8 = i64;` подменял встроенный тип во
всём файле (цель `c` печатала `int64_t`), а дубль структуры проявлялся
посторонней `SE-061` про несуществующее поле — диагностикой **о следствии**.

**Побочное улучшение:** заметки диагностик получили координату (`примечание:
1:6: …`) — это касается всех диагностик с заметками. Если заметка указывает в
другой файл, координата опускается, а текст называет источник: чужая строка под
своим путём обманывает.

**Чистка корпуса — 25 фикстур**, и она оказалась не механической: часть файлов
проверяет **сами псевдонимы**, там типы переименованы (`u8` → `Byte`), а не
удалены; один тест задавал позицию арифметикой по номерам строк и потребовал
правки координаты. Безопасность чистки доказана пробами ADR: `[bit;8]` и
встроенный `u8` дают тождественный результат во всех целях и в эталоне.

Контроль — `takt-lang/tests/semantic/type_redefinition_tests.rs` (9 проверок:
три формы затенения, позиция на имени, контр-пример `u128`, дубли внутри вида и
между видами, и тот самый вход, что раньше давал обманчивую `SE-061`).
