# Фича: Индексация параметра-массива внутри функции

- **Номер:** 0346
- **Статус:** ГОТОВО
- **Зависит от:** 0210 (закрыта; проставлено 2026-08-20)
- **Связанные issue (анализ):** найдено пробой «константа-структура, разряд
  элемента массива, массив в параметре»

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32): «Архитектура (ADR)»,
«Анализ», «Разработка», «Тест-план», «Отчёт о тестировании», «Итог».
Отдельным артефактом остаются только исправления —

## Краткое описание

`fn first(a: [u8;2]) -> u8 { return a[0]; }` давал `SE-003` «Переменная 'a' не
найдена»: параметр был виден всюду, **кроме индексации**. Отказ приходил из
семантики — то есть язык принимал объявление, которое не работало.

## Документирование (правило 24)

**Не требуется** — подтверждено: правится разрешение имени, а не правило языка;
массив в параметре документ уже описывает.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0346-array-param-index.md](0346-array-param-index.md)

### Контекст

Замер-20, снятие причин по одной:

| Вход | Ответ |
|---|---|
| `fn f(a: [u8;2]) -> u8 { return a[0]; }` | **`SE-003`** «Переменная 'a' не найдена» |
| `fn f(a: [u8;2]) -> u8 { var x: u8 := 0; x := a[0]; return x; }` | **`SE-003`** |
| `fn f(a: [u8;2]) -> u8 { return 1; }` | работает |
| `fn f() -> u8 { var a: [u8;2] := {7, 1}; return a[0]; }` | работает |

То есть отказ давала **пара** «параметр + индексация»: ветвь
`ast::Expression::ArraySubscript` в `semantic/expression/mod.rs` спрашивала
только `model.search_var(...)` и в список параметров не заглядывала. Параметр
был виден всюду, кроме индексации.

Отказ приходил из **семантики**, то есть одинаково у эталона и всех восьми
целей: язык принимал объявление `fn f(a: [u8;2])`, которое не работало.

Тот же список параметров не передавался и в разбор **индекса**: рекурсивный
вызов шёл с `vec![]`, поэтому `a[i]`, где `i` — параметр, ломался по той же
причине.

### Решение

Имя ищется сперва среди параметров (`param_variable`), затем в таблице модели —
тот же приоритет, что в ветви разрешения идентификатора. Параметры передаются
и в разбор индекса. Срез (`ArraySlice`) получил ту же правку: это та же
позиция.

### Границы

- **Узел параметра синтетический** (`Location::Implicit`), как и в ветви
  разрешения имени: список параметров плоский, позиции объявления у него нет.
- **Контроли обязательны:** неизвестное имя по-прежнему `SE-003`, а
  индексация не массива — `SE-030`; иначе правка читалась бы как
  «индексация принимает любое имя».

### Отвергнутые варианты

1. **Класть параметры в таблицу модели.** Они не принадлежат модели и затенили
   бы одноимённые переменные вне функции.

### Последствия

- Массив в параметре функции стал работоспособен у эталона и всех целей.
- Замер попутно нашёл два соседних класса (константа-структура у `rust`/`sv`,
  передача массива аргументом у `st`) — вынесены кандидатами.

## Анализ

### Цель и контекст

Найдено пробой «константа-структура, разряд элемента массива, массив в
параметре»: отказ пришёл раньше всех трёх предметов — на самой индексации
параметра.

### Зависимости фичи (правило 17/19)

- **Зависит от:** 0210 (индекс — произвольное выражение). Закрыта.
- **Влияние на порядок разработки:** заводит двух кандидатов, найденных тем же
  замером.

### Требования и проверяемые условия

- **R1.** `a[0]` при параметре-массиве разрешается.
- **R2.** `a[i]` при параметре-индексе разрешается.
- **R3.** Неизвестное имя по-прежнему `SE-003`.
- **R4.** Индексация не массива по-прежнему `SE-030`.
- **R5.** Значения совпадают с эталоном.

### Разбор

#### Почему дефект дожил

Массив в параметре объявлять **можно**, и без индексации функция строилась;
фича занималась передачей массива под-модели через `VAR_IN_OUT`, а не
чтением его внутри функции. Корпус класс не покрывает: там массивы читаются в
телах состояний, а не в параметрах функций.

#### Что показала проба

Отказ маскировал сразу три соседних вопроса того же файла. Снятие причин по
одной (правило 30) отделило предмет от попутчиков — и они стали кандидатами с
готовым замером.

### Риски

- **Затенение.** Параметр имеет приоритет над переменной модели — тот же
  порядок, что в разрешении идентификатора; иное поведение было бы
  непоследовательным.

### Почему тесты именно такие

Отказ был **семантическим** — значит расхождения между потребителями не
существовало, и сверка нужна не для сравнения целей, а чтобы доказать, что
исправленное поведение верно (`first` даёт 7, `at_index` — 9).

Имя `at` для функции брать нельзя: это ключевое слово языка (адрес порта), и
отказ пришёл бы от парсера — первая редакция теста так и упала.

**Параметр стал виден и при индексации.**

- **Ветвь `ArraySubscript` спрашивала только таблицу модели** и в список
  параметров не заглядывала. Теперь имя ищется сперва среди параметров — тот же

  (рекурсивный вызов шёл с `vec![]`), поэтому `a[i]` с параметром-индексом
  ломался по той же причине. Срез получил ту же правку.
- **Отказ был семантическим**, то есть общим для эталона и всех восьми
  целей: расхождения не было, ломался **язык**.
- **Контроли обязательны:** неизвестное имя по-прежнему `SE-003`, индексация
  не массива — `SE-030`.
- **Проба маскировала три вопроса сразу:** отказ приходил раньше остальных
  предметов файла; снятие причин по одной (правило 30) отделило предмет от
  попутчиков, и те стали кандидатами с готовым замером.
