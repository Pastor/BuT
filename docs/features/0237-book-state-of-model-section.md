## Что известно на входе

**Класс:** документ (Tier 4).

Найдено при документировании [validate не обходит формулы: неизвестное имя в Guard молчит](0203-validate-formulas-traversal.md)
(2026-08-15): поиск `S(` по `book/src` даёт **одно** вхождение — саму отсылку.
Проверка ссылок этого не ловит: ссылка внутритекстовая («см. раздел …»), а не
Markdown-ссылка на файл, и проверять её нечем, кроме глаз.

Объём: описать в разделе о композиции проверку состояния под-модели — обе
равносильные записи (`S(Модель) = Состояние` и краткая `Модель = Состояние`,
узаконенная решением заказчика 2026-08-15), область видимости имени состояния
(оно принадлежит **указанной** модели) и пример, прогоняемый проверкой.

### Context

Раздел «Выражения и условия» отсылает за описанием проверки состояния
под-модели к разделу «Импорты и композиция моделей»:

> …проверка состояния под-модели (`S(Модель)` — см. раздел «Импорты и
> композиция моделей»).

Раздел-адресат о ней **не говорит ничего**: поиск `S(` по `book/src` даёт одно
вхождение — саму отсылку. Ссылка висячая.

Проверка ссылок этого не ловит по устройству: ссылка внутритекстовая («см.
раздел …»), а не ссылка на файл. Класс держится сводом и ревью.

**Что мешало описать раньше.** До [симулятор исполняет S(Модель) — проверку состояния под-модели](0245-sim-state-of-model.md)
конструкцию не исполнял эталон (`SIM-013`), а свод(д) требует, чтобы
пример раздела проверялся **компиляцией и симуляцией**; проверка примеров (0133)
прогоняет каждый `.takt` документа симулятором. Пример с `S(Модель)` уронил бы
проверка. Теперь эталон её исполняет, и препятствие снято.

### Decision Drivers

1. **Ссылка обязана вести к описанию.** Читатель, отправленный за деталями,
   должен их найти — иначе документ обещает то, чего не содержит.
2. **Место описания — там, куда ведёт ссылка.** Проверка состояния осмысленна
   только при композиции: одна модель спрашивает о другой. Это предмет раздела
   «Импорты и композиция моделей», а не «Выражений».
3. **свод.** Пример обязан быть функциональным, из практики, с разбором и
   выносками, и проверяться компиляцией **и** симуляцией.
4. **свод.** Описывается **язык**: где запись законна, что она значит и
   какому состоянию принадлежит имя справа. Деталей реализации инструментов в
   языковом разделе нет.

### Considered Options

#### Option A. Подраздел в «Импорты и композиция моделей» + ссылка из «Выражений»

Новый подраздел после «Композиции моделей», с примером и разбором; в
«Выражениях» краткое упоминание заменяется ссылкой на метку подраздела.

**Pros:**
- ссылка ведёт туда, где предмет раскрыт целиком, — вместе с композицией,
  без которой конструкция бессмысленна;
- пример раздела уже есть контекст (модели, `|`, общие переменные);
- свод соблюдено: подробности не раздувают «Выражения».

**Cons:**
- раздел «Импорты» растёт (он и так один из крупных).

#### Option B. Описать в «Выражениях», убрав отсылку

**Pros:**
- предмет — вид условия, а условия описывает этот раздел;
- ссылка исчезает вовсе.

**Cons:**
- запись без композиции не имеет смысла, а композиция описана **в другом
  разделе** — читателю пришлось бы прыгать туда за понятием «под-модель»;
- «Выражения» — раздел о формах записи; примеры с двумя моделями и трассой там
  чужеродны.

#### Option C. Отдельный раздел «Взаимодействие моделей»

**Pros:**
- предмет виден в оглавлении.

**Cons:**
- свод: новый раздел — **отдельная фича** со своим циклом; для одной
  конструкции это несоразмерно;
- предмет распадается: композиция в одном разделе, наблюдение за ней — в другом.

### Decision

Принимается **Option A**.

Состав правки:

1. Подраздел **«Проверка состояния под-модели»** в
   `book/src/09-imports/index.typ` после «Композиции моделей»: обе равносильные
   записи, область видимости имени состояния (оно принадлежит **указанной**
   модели), места употребления (ребро `ref`, `cond`, формула/`invariant`) и
   граница — в теле блока запись незаконна.
2. **Пример** по своду: узнаваемая пара «пресс + подающий конвейер»,
   вводный бриф, числовые выноски в комментариях, разбор по ходу рассказа,
   прогон симулятором со сценарием.
3. В «Выражениях» — ссылка на метку подраздела вместо слов «см. раздел».
4. Блок «Частые ошибки» раздела дополняется кодами `SE-033` (состояние не
   найдено в указанной модели) и `SIM-036` (модель в прогоне не запущена).

### Consequences

#### Положительные

- Висячая ссылка снята; конструкция описана там, где читатель её ищет.
- Пример прогоняется проверкой — описание проверяется машиной, а не только
  ревью.

#### Отрицательные / Action items

1. Раздел «Импорты и композиция моделей» растёт примерно на страницу.
2. Пример добавляет два файла (`.takt` + сценарий) в корпус документа: проверка
   примеров станет прогонять на один пример больше.
3. Ограничение целей (`rust`/`st`/`sv` конструкцию не переводят) в языковом
   разделе **не упоминается** — свод; оно вынесено кандидатом в
   `FEATURES.md` фичей.

#### Acceptance criteria

1. В разделе «Импорты и композиция моделей» есть подраздел о проверке
   состояния под-модели с меткой, обе формы записи описаны.
2. Ссылка из «Выражений» ведёт на эту метку (сборка Typst падает на неизвестной
   метке — проверка автоматическая).
3. Пример компилируется целью `c` и прогоняется симулятором со сценарием,
   поведение соответствует брифу; проверка примеров документа зелёный.
4. Блок «Частые ошибки» раздела дополнен `SE-033` и `SIM-036`.
5. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Снять висячую ссылку: раздел «Выражения и условия» отсылает за описанием
`S(Модель)` к разделу «Импорты и композиция моделей», а тот о проверке
состояния под-модели не говорит. Решение — подраздел в разделе-адресате с
примером по своду (ADR, Option A).

Фича **документная**: язык не меняется, описывается уже существующее и (с
[симулятор исполняет S(Модель) — проверку состояния под-модели](0245-sim-state-of-model.md)) исполняемое эталоном поведение.

### Зависимости фичи

- **Зависит от:** [симулятор исполняет S(Модель) — проверку состояния под-модели](0245-sim-state-of-model.md) — **закрыта**
  2026-08-17. Обоснование: свод(д) требует, чтобы пример раздела
  проверялся симуляцией, а проверка примеров (0133) прогоняет каждый `.takt`
  документа; до 0245 эталон отвечал на конструкцию `SIM-013`, и пример уронил
  бы проверка.
- **Влияние на порядок разработки:** фича никого не блокирует. Соседняя
  документная [раздел документа о переменных не отражает свёртку инициализатора](0222-book-variables-const-fold.md) (раздел о
  переменных и свёртка инициализатора) от неё не зависит.

### Требования и проверяемые условия

- **R1. Ссылка ведёт к описанию.** В разделе «Импорты и композиция моделей»
  есть подраздел о проверке состояния под-модели, помеченный меткой; ссылка из
  «Выражений» ведёт на неё.
- **R2. Описан язык, а не инструменты.** Указаны: обе равносильные
  записи, смысл, **чьё** имя стоит справа (состояние указанной модели, а не той,
  где записано условие), места употребления (ребро `ref`, `cond`,
  формула/`invariant`) и граница — тело блока такой записи не принимает.
- **R3. Пример по своду.** Узнаваемое устройство из практики, вводный
  бриф, числовые выноски `(1)`, `(2)` в комментариях, связный разбор по ходу
  рассказа, физика — с датчиков и приводов, а не счётом тактов.
- **R4. Пример проверен компиляцией И симуляцией (правило «Пример раздела: функциональный, из практики, с разбором-выносками»).** Компилируется
  целью `c`; прогон со сценарием даёт поведение, обещанное брифом.
- **R5. Блок «Частые ошибки» дополнен.** `SE-033` — состояние не
  найдено в указанной модели; `SIM-036` — модель в прогоне не запущена. Формат
  строки: сначала код, затем описание.
- **R6. Проверки документа зелёные.** Символы (0146), лексика (0160), примеры
  (0133), сборка Typst (0240).

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Подраздел с меткой существует, ссылка ведёт на него | `typst compile` (неизвестная метка — ошибка) + чтение |
| A2 | Обе формы записи и область видимости описаны | ревью текста против поведения |
| A3 | Пример компилируется целью `c` | шаг проверки примеров `precheck.sh` |
| A4 | Пример осмыслен: поведение отвечает брифу | прогон `takt-sim` со сценарием, сверка трассы вручную |
| A5 | «Частые ошибки» дополнены | чтение раздела |
| A6 | Предкоммит зелёный | `./scripts/precheck.sh` |

### Особенности по обратной функциональности

Правка **аддитивна**: добавляются подраздел, пример и сценарий; существующий
текст меняется в одном месте — упоминание в «Выражениях» получает ссылку на
метку вместо слов «см. раздел». Ни структура документа (состав `main.typ`), ни
нумерация разделов не меняются.

Версия языка **не растёт**: язык не изменён. Версии крейтов — тоже.

### Риски и зависимости

- **Пример может оказаться «компилируется, но бессвязен»** — класс, названный
  сводом(д). Снижение: сценарий и ручная сверка трассы с брифом; числа
  разбора берутся из прогона, а не придумываются.
- **свод(е): такт — не единица физической величины.** В примере положение
  и готовность приходят **входными портами** (датчики), команды идут выходными
  (приводы); тактами меряется только выдержка, и она записывается литералом
  длительности.
- **свод против соблазна упомянуть ограничения целей.** Того, что
  `rust`/`st`/`sv` конструкцию не переводят, в языковом разделе быть не должно;
  запись об этом живёт кандидатом в `FEATURES.md` (внесён фичей).
- **свод: не требуется:** язык не меняется, редакторский слой не
  затронут.

## Разработка

### Задача

#### Что было

Раздел «Выражения и условия» отсылал за описанием `S(Модель)` к разделу
«Импорты и композиция моделей» словами «см. раздел …», а тот о проверке
состояния под-модели не говорил ничего: поиск `S(` по `book/src` давал одно
вхождение — саму отсылку.

#### Что сделано

**Подраздел «Проверка состояния под-модели»** в `book/src/09-imports/index.typ`
(после «Композиции моделей», метка `<проверка-состояния-под-модели>`):

- обе равносильные записи — `S(Модель) = Состояние` и `Модель = Состояние`, а
  также отрицание;
- **чьё** имя стоит справа: состояние **указанной** модели, даже если у
  наблюдателя есть одноимённое; отсутствующее — `SE-033`;
- места употребления: ребро `ref`, именованное `cond`, инвариант, составное
  условие; **граница** — в теле блока запись незаконна;
- момент наблюдения: переход соседа виден **на том же такте**.

**Пример по своду** — линия штамповки (`examples/press_line.takt` +
сценарий `examples/press-sim.json`): пресс с выдержкой под давлением и
подающий конвейер, который стоит, пока ползун опущен. Вводный бриф, две
числовые выноски в комментариях кода ((1) — полная запись, (2) — краткая с
отрицанием), связный разбор по ходу рассказа, трасса прогона с числами.
Физика приходит датчиком (`part_ready`) и уходит приводами (`ram`, `belt`);
тактами меряется только выдержка, и та задана литералом длительности при
объявленном `clock` (правило «Пример раздела: функциональный, из практики, с разбором-выносками»). Счётчик `fed` считает **события** — входы
в `Feeding`.

**Ссылка из «Выражений»** заменена на `#link(<проверка-состояния-под-модели>)`
— теперь она ведёт к описанию, а не к разделу вообще.

**Блок «Частые ошибки»** раздела дополнен `SE-033` и `SIM-036` (формат «сначала код, затем описание»).

#### Проверки

```sh
cargo run --bin taktc -- compile -t c book/src/09-imports/examples/press_line.takt \
  -o /tmp/press --tick-hz=1000          # компилируется
cargo run --bin takt-sim -- book/src/09-imports/examples/press_line.takt \
  -s book/src/09-imports/examples/press-sim.json   # осмысленное поведение
make -C book pdf                        # сборка, метка ссылки разрешается
./scripts/check-book-glyphs.py          # 60 файлов, символов вне шрифта нет
./scripts/check-book-keywords.py        # лексика и подсветка сверены
```

Трасса прогона (сокращённо) — она же приведена в разделе:

```text
Шаг  1:  [Idle, Feeding]      part_ready=0  belt=1  ram=0  fed=1
Шаг  2:  [Pressing, Holding]  part_ready=1  belt=0  ram=1  fed=1
…
Шаг 22:  [Idle, Feeding]      part_ready=0  belt=1  ram=0  fed=2
```

Поведение отвечает брифу: пресс уходит в работу на втором такте, лента
останавливается **тем же тактом**, через 20 тактов выдержки ползун поднимается
и подача возобновляется (`fed` = 2).

Заголовок примера назван «Пример: линия штамповки», а не «Пример»: в разделе
уже есть общий блок «Пример», и два одинаковых заголовка в одном
разделе читались бы как ошибка вёрстки.

## Тест-план

### Область и цель

Фича документная: язык не меняется. Проверяется, что описание **верно**
(соответствует поведению инструментов), **полно** в объёме ADR и **проверяемо
машиной** — пример компилируется и прогоняется, ссылка разрешается сборкой.

#### T7 — трасса прогона

```text
Шаг  1:  [Idle, Feeding]      part_ready=0  belt=1  ram=0  fed=1
Шаг  2:  [Pressing, Holding]  part_ready=1  belt=0  ram=1  fed=1
Шаг  3:  [Pressing, Holding]  part_ready=0  belt=0  ram=1  fed=1
…
Шаг 21:  [Pressing, Holding]  part_ready=0  belt=0  ram=1  fed=1
Шаг 22:  [Idle, Feeding]      part_ready=0  belt=1  ram=0  fed=2
Шаг 23:  [Idle, Feeding]      part_ready=0  belt=1  ram=0  fed=2
```

Бриф обещает: конвейер подаёт, пока ползун поднят, и останавливается, когда
пресс пошёл. Трасса это показывает — лента встала **тем же тактом**, которым
пресс перешёл в `Pressing` (шаг 2), и пошла снова, когда выдержка `20ms`
(20 тактов при `clock 1kHz`) истекла (шаг 22), увеличив счётчик поданных
заготовок до двух.

### Примеры и контрпримеры

свод применяется по существу: язык не меняется, но раздел описывает
языковую конструкцию, поэтому её границы названы и в тексте, и тестами
[симулятор исполняет S(Модель) — проверку состояния под-модели](0245-sim-state-of-model.md):

| Запись | Ответ | Где сказано |
|---|---|---|
| `ref Feeding: S(Press) = Idle;` | законна | пример раздела, выноска (1) |
| `ref Holding: Press != Idle;` | законна | пример раздела, выноска (2) |
| `cond ready = S(Press) = Idle;` | законна | подраздел, врезка о местах употребления |
| `invariant sane = S(Press) = Idle \| S(Press) = Pressing;` | законна | там же |
| `always { if S(Press) = Idle { … } }` | **незаконна** | подраздел: «в теле блока такая запись незаконна» |
| `S(Press) = Broken` | `SE-033` | подраздел + «Частые ошибки» |

## Итог (что сделано)

Висячая ссылка снята: в разделе [«Импорты и композиция моделей»](../../book/src/09-imports/index.typ)
появился подраздел **«Проверка состояния под-модели»**, а отсылка из раздела
«Выражения» ведёт теперь на его метку (у Typst неизвестная метка — ошибка
сборки, то есть ссылка проверяется машиной).

Описаны: обе равносильные записи (`S(Модель) = Состояние` и `Модель =
Состояние`) с отрицанием; принадлежность имени справа — состоянию **указанной**
модели (`SE-033`, если такого нет); места употребления — ребро `ref`, `cond`,
инвариант, составное условие; **граница** — в теле блока запись незаконна;
момент наблюдения — тот же такт, что и переход соседа.

Пример по своду — **линия штамповки** (`examples/press_line.takt` +
сценарий `press-sim.json`): пресс с выдержкой под давлением и подающий
конвейер, стоящий, пока ползун опущен. Пример компилируется целью `c` и
прогоняется симулятором в проверке документа (0133); трасса подтверждает бриф.
Блок «Частые ошибки» дополнен `SE-033` и `SIM-036`.

Фича стала возможна только после [симулятор исполняет S(Модель) — проверку состояния под-модели](0245-sim-state-of-model.md): до неё
эталон конструкцию не исполнял (`SIM-013`), и пример уронил бы проверка примеров.

Детали — в [отчёте](0237-book-state-of-model-section.md#отчёт-о-тестировании) и
[задаче](0237-book-state-of-model-section.md#разработка).
