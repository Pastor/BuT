## Краткое описание

**Структура без полей принимается языком и даёт невалидный по стандарту C.**
Замер при закрытии [семантика перечисления без вариантов](0172-empty-enum-semantics.md)
(2026-08-16): правило `StructDefine` использует `Comma<StructField>` («ноль
или более»), поэтому `struct S { }` компилируется, а цель `c` печатает
`typedef struct S { } S;` — пустая структура есть **расширение GNU** (C11
6.7.2.1 требует непустой список объявлений). Проверка проекта (`-Wall -Werror`)
это **пропускает**; `cc -pedantic` отвергает (`-Wgnu-empty-struct`). Класс
тот же, что у пустого перечисления («агрегатное объявление без элементов»), но
устройство отказа иное: у структуры сегодня отвечает **чужой инструмент** и
только под флагом, которого в проверке нет. Кандидат: принять решение языка —
запрет (`SE-…` на объявлении, симметрично `SE-105`) либо законная пустая
запись с ответом от всех целей. Прежде чем решать, замерить остальные цели:
`st`/`rust`/`sv` на пустой структуре не проверялись.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по правилу 17.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-18
- **Authors:** Архитектор + аналитик + разработчик
- **Related issues:** [Фича](0284-empty-struct-semantics.md); прямой образец — [ADR](0172-empty-enum-semantics.md#архитектура-adr) (`SE-105`, перечисление без вариантов)

### Context

Правило `StructDefine` использует `Comma<StructField>` («ноль или более»),
поэтому `struct S { }` язык принимает. Карточка сообщала, что цель `c` печатает
расширение GNU, и просила **перед решением замерить остальные цели**.

**Замер-18** на `struct Empty { }` с используемой переменной:

| Потребитель | Что происходило |
|---|---|
| эталон | исполняет: переменная получает `Empty{}` |
| `c`, `c-hal` | `typedef struct Empty { } Empty;` — компилируется, но `cc -std=c11 -pedantic` даёт `warning: empty struct is a GNU extension [-Wgnu-empty-struct]` (C11 6.7.2.1 требует непустой список объявлений) |
| `st`, `st-at` | `Empty : STRUCT END_STRUCT;` — **`iec2c` отвергает**: `error: no structure element declared in structure type declaration` |
| `rust` | отказ `RS-014` «значение по умолчанию для типа 'Empty' не строится» |
| `sv`, `sv-mmio` | `empty_t used_e;` — ссылка на **необъявленный** тип; `verilator`: `Can't find typedef/interface: 'empty_t'` |

**Контрольный замер отделил причину от следствия.** Непустая структура
`struct Pt { a: u8, b: u8 }` проходит и `cc -std=c11 -pedantic`, и `iec2c`
(POUS.c порождён, ошибок нет). Значит ломается **пустота**, а не структурный тип.

**Но тот же контроль сузил объём фичи.** Отказ `RS-014` и висячий тип у `sv`
воспроизводятся и на **непустой** структуре: эти две цели не переводят
структуры **вовсе**. К пустоте они отношения не имеют — это соседний класс
(кандидат «структуры не транслируются целями `st` и `rust` дальше объявления»,
который замер расширяет на `sv`).

**Проверка проекта класс не видел по устройству:** он гоняет `cc` **без**
`-pedantic` (там пустая структура законна как расширение), проверка `st` пропускает
файл через `iec2c` только для корпуса, а пустых структур в `examples/` нет ни
одной.

### Decision Drivers

1. **Решение уже принято — для перечисления.** ADR постановил: у
   перечисления обязан быть хотя бы один вариант, и говорит это **семантика**,
   на объявлении. Структура — та же форма («агрегатное объявление без
   элементов»), и разное отношение к ней есть дефект правила.
2. **Отвечает чужой инструмент, и только под флагом.** Сегодня о пустой
   структуре говорит `cc -pedantic` (которого в проверке нет) и `iec2c` — на
   **порождённом** файле, то есть автор узнаёт о своей ошибке из чужого
   сообщения о чужом языке.
3. **Пустая структура ничего не выражает.** Значения у неё одно, полей нет,
   прочитать нечего: запрет не отнимает выразительности.
4. **Квантификатор грамматики — не место для правила языка**: смена
   `Comma` на `CommaOne` изменила бы язык молча, а текст отказа стал бы
   внутренностью LR-разбора.

### Considered Options

#### Option A. Оставить как есть

**Pros:** ноль правок.

**Cons:** порождённый ST **не компилируется**, а C держится на расширении
компилятора. Автор узнаёт об этом от чужого инструмента или не узнаёт вовсе.

#### Option B. Сузить грамматику до `CommaOne<StructField>`

**Pros:** одна строка.

**Cons:** правило языка становится свойством квантификатора, а сообщение —
`SY-002` «нераспознанный токен `}`». Ровно то устройство, которое ADR
признал негодным и заменил.

#### Option C. Оставить запись законной и научить цели её переводить

**Pros:** язык не сужается.

**Cons:** переводить нечего: в C стандартного представления пустой структуры
нет, в ST — тоже. Пришлось бы подставлять фиктивное поле, то есть печатать не
то, что написал автор.

#### Option D. Отказ семантики — `SE-115` на объявлении

**Pros:**
- Ответ одинаков у всех девяти потребителей и приходит **до** генерации.
- Симметрия с `SE-105`: одна форма — одно устройство отказа.
- Текст называет требование и выход, а не пересказывает чужую ошибку.

**Cons:**
- Формально ломающее. Замер: в `examples/` и фикстурах пустых структур нет
  ни одной, ни один тест такую запись не закреплял — предкоммит зелёный без
  правок корпуса.

### Decision

Принимается **Option D**.

1. Структура без полей — ошибка **`SE-115`**, на **объявлении**, накопительно
   (правило: две пустые структуры — две диагностики).
2. Проверка живёт в `semantic/validate/structs.rs`, рядом с прочими правилами о
   структурах.
3. Грамматика **не трогается**: `Comma<StructField>` остаётся, правило языка
   выражает семантика.
4. Коды `SE-105` и `SE-115` остаются **разными**: форма одна, причины разные —
   у перечисления выбирать нечего, у структуры вывод не принимают чужие
   инструменты. Подмена размыла бы обе.

### Consequences

#### Положительные

- Порождённый ST перестал быть невалидным на этом классе; C перестал зависеть
  от расширения компилятора.
- Автор получает сообщение на **своём** языке и на своей строке.
- Правило про агрегаты стало симметричным.

#### Отрицательные / Action items

- Запись, которую язык принимал, стала ошибкой. Выход назван в тексте.
- **Цели `rust` и `sv` не переводят структуры вовсе** — этой фичей не
  затронуто и ею не лечится: класс шире и вынесен кандидатом (замер расширил
  его на `sv`, где вывод ссылается на необъявленный тип).

#### Acceptance criteria

1. `struct S { }` даёт `SE-115` на объявлении, с названным выходом (A1).
2. Две пустые структуры дают две диагностики (A2).
3. Непустая структура остаётся законной (A3).
4. Пустое перечисление по-прежнему судит `SE-105` (A4).
5. `./scripts/precheck.sh` зелён без правок корпуса (A5).

## Анализ

### Цель и контекст

`struct S { }` язык принимал, а вывод не принимали чужие инструменты. Фича
отвергает форму диагностикой `SE-115` — тем же устройством, каким `SE-105`  отвергает перечисление без вариантов.

### Зависимости фичи (правило 17/19)

- **Зависит от:** нет. Образец [семантика перечисления без вариантов](0172-empty-enum-semantics.md)
  закрыт.
- **Влияние на порядок разработки:** никого не разблокирует. Замер расширил
  соседний кандидат («структуры не транслируются целями `st` и `rust` дальше
  объявления») на цель `sv`.

### Замер (карточка прямо требовала его перед решением)

Карточка знала о цели `c` и просила «замерить остальные цели: `st`/`rust`/`sv`
на пустой структуре не проверялись». Прогон 2026-08-18:

| Потребитель | Что происходило |
|---|---|
| эталон | исполняет: `e = Empty{}` |
| `c`, `c-hal` | `typedef struct Empty { } Empty;`; `cc -std=c11 -pedantic` → `warning: empty struct is a GNU extension` |
| `st`, `st-at` | `Empty : STRUCT END_STRUCT;`; `iec2c` → `error: no structure element declared in structure type declaration` |
| `rust` | отказ `RS-014` |
| `sv`, `sv-mmio` | `empty_t used_e;` при отсутствующем `typedef`; `verilator` → `Can't find typedef/interface` |

#### Контроль отделил причину — и сузил объём

**Непустая** структура `struct Pt { a: u8, b: u8 }`:

- `cc -std=c11 -pedantic` — принимает без замечаний;
- `iec2c` — принимает (POUS.c порождён, ошибок нет);
- `rust` — **тот же** `RS-014`;
- `sv` — **та же** висячая ссылка (`pt_t`), `verilator` отвергает.

То есть к **пустоте** относятся только `c` (расширение GNU) и `st`
(невалидный ST). Цели `rust` и `sv` не переводят структуры **вовсе** — это
соседний класс, и фича его не лечит.

**Первая проба не воспроизвела дефект у `rust` и `sv` вовсе:** переменная
была неиспользуемой, и штатный фильтр выбросил её из вывода. Тот же капкан, что
в фиче, — проба обязана использовать объявленное.

**Вторая проба дала ложный `redefinition of 'Pair'`** в C: файл назывался
`pair.takt`, корневая модель получила имя `Pair` из имени файла и столкнулась
со `struct Pair` (известный класс). К предмету отношения не имеет —
переименование структуры замер очистило.

### Риски и зависимости

- **Риск: подменить `SE-105`.** Снят отдельным тестом-границей: перечисление

- **Риск: «исполнить» правило запретом структур вообще.** Снят контрольным

- **Граница: цели `rust` и `sv` не переводят структуры вовсе** — не лечится
  этой фичей, вынесено кандидатом (замер расширил его на `sv`).

## Разработка

### Задача

#### Что было

`struct S { }` принималось языком. Цель `c` печатала расширение GNU, порождённый
ST отвергал `iec2c`, а эталон исполнял запись как ни в чём не бывало. О беде
автор узнавал от чужого инструмента — и только если запускал его с флагом,
которого в проверке проекта нет.

#### Что сделано

**1. Проверка `validate_empty_structs`** (`semantic/validate/structs.rs`) —
`SE-115` на **объявлении**, накопительно. Подключена в
`validate_model_all` рядом с `validate_empty_enums`.

**2. Грамматика не тронута.** `Comma<StructField>` («ноль или более») остаётся:
правило языка не должно быть свойством квантификатора, а текст отказа —
внутренностью LR-разбора. Это прямой урок, где такое устройство признали
негодным и заменили.

**3. Коды разные, форма одна.** `SE-105` (перечисление) и `SE-115` (структура) —
«агрегат без элементов», но причины разные: у перечисления выбирать нечего, у
структуры вывод не принимают чужие инструменты. Граница закреплена тестом.

**4. Документ.** Реестр диагностик, приложение «Ошибки и предупреждения»
(раздел `SE-115` с примером и выходом), языковой раздел «Типы» — правило
текстом в подразделе о структурах плюс строка в «Частые ошибки» (правило 26).

#### Проверки

```sh
cargo test --all-features                       # 3204 теста, 0 провалов
cargo run --bin takt-sim -- empty.takt -n 1     # SE-115 у эталона
cc -std=c11 -pedantic -c порождённый.c          # прежде: -Wgnu-empty-struct
iec2c -I … порождённый.st                       # прежде: no structure element declared
./scripts/precheck.sh
```

Соответствие условиям анализа: R1 — A1, R2 — A2, R3 — A3, R4 — A4, R5 — A5.

**Первый прогон предкоммита был красным** — `clippy` отверг `line as usize`
в моём же тесте (`unnecessary_cast` под `-D warnings`). Правка однострочная;
записано здесь потому, что проверка сработал ровно так, как задуман: тесты идут под
теми же линтами, что и код.

**Корпус правок не потребовал:** пустых структур нет ни в `examples/`, ни в
фикстурах, и ни один тест такую запись не закреплял.

Версия крейта `takt-lang`: `0.42.0` → `0.43.0`. Версия языка **не растёт** —
цикл `0.10.0` открыт фичей (правило 22, накопление).

## Тест-план

### Область и цель

Фича **меняет язык** (множество принимаемых программ сужается), поэтому правило
16 применяется:

- **Контрпример:** `struct Empty { }` — отвергается `SE-115`;
- **Пример:** `struct Point { x: u16, y: u16 }` — законен и переводится всеми
  целями, которые вообще переводят структуры.

Оба вошли в документ: языковой раздел «Типы» (подраздел о структурах) и
приложение «Ошибки и предупреждения».

**Контрольная проверка обязательна и по существу.** Без неё правило можно
было бы «исполнить», запретив структуры вовсе; кроме того, именно контроль

### Выводы и дальнейшие шаги

1. **Карточка требовала замерить остальные цели перед решением — и это себя
   оправдало.** Замер показал, что `RS-014` у `rust` и висячая ссылка на
   необъявленный тип у `sv` **не про пустоту**: они воспроизводятся и на
   непустой структуре. Без контроля фича приписала бы себе чужой класс и
   «починила» бы его запретом, которого он не лечит.
2. **Две пробы из трёх были негодными — снова.** Первая не воспроизвела дефект
   у `rust` и `sv` вовсе: переменная была неиспользуемой, и штатный фильтр
   выбросил её из вывода (тот же капкан, что в 0300). Вторая дала ложный
   `redefinition of 'Pair'` в C: файл назывался `pair.takt`, и корневая модель
   столкнулась со `struct Pair` (известный класс).
3. **Предкоммит покраснел на моём же тесте** — `clippy` отверг `line as usize`
   (`unnecessary_cast` под `-D warnings`). Правка однострочная; отмечено
   потому, что проверка сработал ровно как задуман: тесты идут под теми же линтами,
   что и код.
4. **Исправлений не требуется.** Дефектов, заводящих `docs/fixes/0284-YY-*`,
   не найдено.
5. **Кандидат актуализирован** (правило 28): запись «структуры не транслируются
   целями `st` и `rust` дальше объявления» расширена на цель **`sv`** — она
   печатает ссылку на необъявленный тип (`verilator`: `Can't find typedef`), и
   это воспроизводится на **любой** структуре, а не только на пустой.

## Итог (что сделано)

Структура без полей отвергается диагностикой **`SE-115`** — на объявлении,
накопительно, тем же устройством, каким `SE-105`  отвергает
перечисление без вариантов. Грамматика **не тронута**: `Comma<StructField>`
остаётся, правило языка выражает семантика — прямой урок.

**Карточка требовала замерить остальные цели перед решением, и это себя
оправдало.** Замер: цель `c` печатала расширение GNU (`cc -std=c11 -pedantic`
→ `-Wgnu-empty-struct`), порождённый ST **отвергал `iec2c`** («no structure
element declared in structure type declaration»), а эталон исполнял запись.

**Контроль отделил причину и сузил объём фичи.** Отказ `RS-014` у `rust` и
ссылка на необъявленный тип у `sv` (`verilator`: `Can't find typedef`)
воспроизводятся и на **непустой** структуре: эти цели не переводят структуры
**вовсе**. К пустоте они отношения не имеют — без контроля фича приписала бы
себе чужой класс и «починила» бы его запретом, который его не лечит.

**Проверка проекта класс не видел по устройству:** он гоняет `cc` **без**
`-pedantic` (там пустая структура законна как расширение), а пустых структур
нет ни в `examples/`, ни в фикстурах.

**Две пробы из трёх были негодными.** Первая не воспроизвела дефект у
`rust`/`sv` вовсе — переменная была неиспользуемой, и её выбросил штатный
фильтр (тот же капкан, что в 0300). Вторая дала ложный `redefinition of 'Pair'`:
файл назывался `pair.takt`, корневая модель получила имя из имени файла и
столкнулась со `struct Pair`.

Версия крейта `takt-lang`: `0.42.0` → `0.43.0`. Версия языка **не растёт**:
цикл `0.10.0` открыт фичей (правило 22, накопление).
