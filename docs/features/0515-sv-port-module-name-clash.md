# Фича: Цель `sv` — имя порта против имени модуля

- **Номер:** 0515
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `sv`: имя порта, совпадающее с именем модуля, даёт `VARHIDDEN`» (заведён при закрытии [проверка примеров `book/` под инструментами целей](0513-book-targets-gate.md))

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Имя порта, совпадающее с именем модуля, отвергается диагностикой **`SV-020`**.
Прежде цель печатала такой модуль, а `verilator` под `-Wall` отвечал
`VARHIDDEN` («Declaration of signal hides declaration in upper scope») — проверка
цели считает предупреждение ошибкой, и всё это при **нулевом** коде возврата
`taktc`. Совпадение возникает само собой: имя модуля цель строит из имени
модели, а у корневой — из имени **файла**, поэтому `out probe: u8`
в файле `probe.takt` его и прячет.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> своду.

## Документирование

**Затронуто.** Приложение «Ошибки и предупреждения» — запись `SV-020` в сводной
таблице кодов цели SV. Язык не меняется: отказ принадлежит цели,
модель остаётся валидной для `c`, `c-hal`, `st`, `rust`, `plantuml`; версия
языка не поднимается (прецедент — `ST-024`).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh`; модель в файле `probe.takt` с портом
`out probe: u8`):

| Потребитель | Ответ |
|---|---|
| эталон, `c`, `c-hal`, `st`, `rust`, `plantuml` | исполняют / переводят, инструменты принимают |
| `sv`, `sv-mmio` | **`verilator`: `VARHIDDEN`** |
| `st-at` | `ST-024` — тот же класс, закрытый фичей |

Границы измерены отдельным прогоном: `verilator` **принимает** порт с именем
типа (`typedef`), порт рядом с одноимённой функцией и переменную модели с
именем модуля — отказ на них был бы ложным. Прочие
служебные имена цели (`clk`, `en`, `is_done`, `state`) уже отвергает `SV-007`.

Класс найден пробой **контроля** проверки, а не корпусом: в `examples/` и
`book/` имя порта нигде не совпадает с именем файла.

### Decision Drivers

- Прецедент рядом и решён так же: `ST-024` (0455) — имя размещённого порта
  против имён POU; тот же вход даёт его и сегодня.
- Переименовать за автора нельзя: имя порта — контракт для того, кто подключает
  модуль, и оно обязано совпадать со спецификацией автоматики (решение ADR).

### Considered Options

1. **Отказ цели `SV-020` с названной причиной** (принято).
2. **Переименовать порт в выводе.** Отвергнуто: имя порта видит интегратор.
3. **Переименовать модуль.** Отвергнуто по той же причине: имя модуля —
   контракт инстанцирования.
4. **Расширить `SV-007`.** Отвергнуто: там список известных заранее имён, а имя
   модуля вычисляется позже — из имени модели либо файла; и текст `SV-007`
   перечисляет служебные сигналы, к которым этот случай не относится.

### Decision

`sv_module::check_module_name_clash` сверяет имя каждого **используемого** порта
модели с именем модуля и отвечает `SV-020`.

### Consequences

- Отказ приходит до генерации, с позицией порта и указанием, что прочие цели
  модель переводят.
- Режим `sv-mmio` покрыт тем же: адресованный порт портом модуля не становится,
  но объявляется сигналом — `VARHIDDEN` приходит на него.
- Неиспользуемый порт отказа не даёт: до вывода он не доезжает.

#### Acceptance criteria

1. Совпадение → `SV-020` с позицией; прочие цели переводят.
2. Режим `sv-mmio` — тот же отказ.
3. Контроль: различные имена, неиспользуемый порт, имя типа и имя функции —
   переводятся.
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Проверка имён у цели — `check_sv_name` (списки `RESERVED_NAMES` и
`SV_KEYWORDS`). Имя модуля в них попасть не может: оно строится позже, в
`generator::sv::generate`, из `root_name`. Отсюда отдельная проверка, вызываемая
там, где имя уже известно.

### Замер

Таблицы — в разделе «Архитектура (ADR) → Context». Замер шире кандидата на один
режим (`sv-mmio`, где сигнал объявляется вне списка портов) и уже — на три
формы, которые инструмент принимает.

### Зависимости фичи

Зависимостей нет.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | Имя порта = имя модуля → `SV-020` с позицией |
| Т2 | То же в режиме `sv-mmio` |
| Т3 | Неиспользуемый порт отказа не даёт |
| Т4 | Имя типа и имя функции не трогаются |
| Т5 | Текст отказа называет цели, где модель валидна |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh`, набор
`targets/sv_module_name_clash_tests.rs` (6 тестов), фикстура корпуса
`tests/data/svclash0515/probe.takt`, `precheck.sh`.

### Редакторский слой

**Не требуется:** лексика и синтаксис не затронуты; диагностика принадлежит
цели и доезжает до редактора обычным путём (её возвращает компиляция).

### Особенности по обратной функциональности

Модель с таким именем порта теперь получает отказ цели `sv` вместо вывода,
который отвергает `verilator`. Это сужение принимаемого целью множества —
намеренное: прежний вывод всё равно не проходил проверка цели.

### Риски и зависимости

- **Риск:** ложный отказ на имени, которое инструмент принимает. Снят вторым
  прогоном (три формы исключены) и контрольными тестами.

## Разработка

### Задача: проверка и диагностика

`takt-lang/src/generator/sv/sv_module.rs` — `sv020` и
`check_module_name_clash`; вызов — в `generator::sv::generate` сразу после
вычисления имени модуля. Проверяются порты модели (а не список портов модуля),
с фильтром использования.

### Задача: контроля и корпус

Набор `sv_module_name_clash_tests.rs` (6 тестов, включая оба режима и три
контроля) и фикстура `tests/data/svclash0515/probe.takt` — вход, дающий код в
корпусе.

Фикстура сняла ещё и **протухшую** запись реестра недостижимых кодов:
`ST-024` теперь достижим корпусом (тот же вход даёт его у цели `st-at`).

## Отчёт о тестировании

### Резюме

`./scripts/precheck.sh` — зелёный. Проба: `sv` и `sv-mmio` отвечают `SV-020`,
шесть прочих потребителей переводят и их инструменты принимают.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка: снятие фильтра использования
ловится тестом `unused_port_is_not_refused`, а расширение правила на имена
типов и функций — тестом `type_and_function_names_are_left_alone`.

### Найденные дефекты

Дефектов правки нет. Побочный результат — снята протухшая запись долга покрытия
(`ST-024`).

### Выводы и дальнейшие шаги

Класс, найденный контролем проверки, закрыт; вход на него теперь есть в
корпусе, то есть его видят проверки целей.

## Итог (что сделано)

Заведена диагностика `SV-020`: имя порта, совпадающее с именем модуля, цель
`sv` (и `sv-mmio`) отвергает с названной причиной. Прежде она печатала модуль,
который `verilator` встречает `VARHIDDEN`, — то есть вывод не проходил проверка
самой цели при нулевом коде возврата `taktc`.

Границы правила замерены прогоном: имя типа, имя функции и переменная модели
конфликта не дают, и отказ на них был бы ложным.
