# Фича: Цель `st` — разделяемые переменные передаются транзитивно

- **Номер:** 0505
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «функция, читающая состояние, вызванная из другой функции» (2026-09-02)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

В IEC 61131-3 `FUNCTION` **чистая**: переменных вызывающего блока она не видит,
и цель `st` передаёт ей нужные через `VAR_IN_OUT` (0030). Список считается по
**собственному** телу функции — и обрывается на первом же вложенном вызове:
`outer`, зовущая `hot()`, которая читает `ticks`, печатает `hot(ticks)`, не
объявив `ticks` у себя. `iec2c` отвечает «Variable not declared in this scope»
при **нулевом** коде возврата `taktc`. Признак делается транзитивным.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Документирование (правило 24)

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, разработчик

### Context

Замер-02 (`scripts/probe.sh`). Вход: `fn hot() -> u8 { return ticks + 1; }`
и `fn outer(k: u8) -> u8 { return k + hot(); }`.

| Потребитель | Ответ |
|---|---|
| эталон, `c`, `c-hal`, `rust`, `sv`, `sv-mmio`, `plantuml` | исполняют / переводят, инструменты принимают |
| `st`, `st-at` | `iec2c`: «Data type incompatibility … invoking function», «Variable not declared in this scope» |

Порождённое: `FUNCTION …_hot : USINT VAR_IN_OUT ticks : USINT; END_VAR`, а в
`…_outer` — вызов `…_hot(ticks)` при отсутствии `ticks` в её объявлениях.

Контроль, отделивший класс от соседа: **первая** редакция пробы держала
досрочный возврат в `outer`, и `sv` отказывала `SV-002` — по своей, названной и
задокументированной причине (возврат печатается присваиванием имени функции).
С одним возвратом `sv` вход принимает: класс принадлежит **только** цели `st`.

### Decision Drivers

- Признак «что функции нужно от состояния» у целей `c` и `rust` уже
  **транзитивен** (`rust_needs::function_needs` с множеством посещённых), и
  ровно этого требует `Touch::Transitive` в переборе 0449.
- Список — единый источник истины для объявления и для аргументов вызова
  (комментарий `state_params`): расширять надо его, а не печать.

### Considered Options

1. **Сделать `state_params` транзитивным** (принято): к собственному
   употреблению добавляется употребление всех вызываемых функций, обход — с
   множеством посещённых (граф вызовов ацикличен, `SE-053`).
2. **Отказ цели «функция зовёт функцию с состоянием».** Отвергнуто: запись
   законна, семь потребителей её переводят, а обход (передать значение
   параметром) автор писать не обязан.
3. **Встраивать такие функции.** Отвергнуто: подстановка — отдельный механизм
   (0444) с собственными границами, и делать её обязательной ради ST значило бы
   менять вывод там, где он верен.

### Decision

`state_params` цели `st` считается **транзитивно**: функция объявляет
`VAR_IN_OUT` для переменных и портов, которые читает её тело **и тела всех
функций, которые она зовёт**.

### Consequences

- Функция, зовущая функцию с состоянием, переводится, и `iec2c` вывод
  принимает.
- Список параметров у таких функций растёт — это плата за чистоту `FUNCTION` в
  IEC, и она видна в выводе.

#### Acceptance criteria

1. Проба: `iec2c` принимает вывод `st` и `st-at`.
2. Цепочка длиннее одного шага (`a` → `b` → `c`) тоже переводится.
3. Контроль: функция без обращения к состоянию параметров не получает.
4. Потактовая сверка эталон ↔ `st`.
5. `./scripts/precheck.sh` зелёный.

## Разработка

### Задача: транзитивный список `VAR_IN_OUT`

`takt-lang/src/generator/st/st_func.rs`: `state_params` считается рекурсивно —
к собственному употреблению добавляются нужды всех вызываемых функций. Имена
вызванных берутся у того же обхода (`UsageSet::functions`), множество
посещённых защищает от цикла (сам цикл запрещает `SE-053`). Порядок списка
остаётся алфавитным: он — единый источник истины для объявления и для
аргументов вызова.

### Задача: списки параметров вынесены в свой модуль

Правка перевела `st_func.rs` за предел размера (1005 строк при ~1000). Три
списка, из которых складывается заголовок POU (`params_of`, `state_params`,
`const_params`), вынесены в `st_params.rs` — граница по ответственности: там
печать функций и вызовов, здесь — что функция берёт у модели. Контракт держит
реэкспорт, пути потребителей не менялись (правило 11).

## Тест-план

| Проверка | Ожидание |
|---|---|
| `outer` зовёт `hot`, читающую переменную модели | `VAR_IN_OUT` вызывающей содержит переменную, аргумент вызова — её же |
| цепочка `outer` → `mid` → `hot` | переменная доходит до обоих уровней, своя переменная `outer` не теряется |

| потактовая сверка эталон ↔ `st` | `9 15 21` с обеих сторон |
| контроль: обе функции чистые | секции `VAR_IN_OUT` нет ни у одной |
| размер модулей после правки | предел ~1000 строк не превышен |

## Отчёт о тестировании (правило 20)

### Резюме

`./scripts/precheck.sh` — зелёный. Проба по девяти потребителям: эталон
исполняет, восемь целей переводят, инструменты проверки принимают.

### Фактические результаты по проверкам

Все проверки пройдены. Мутационная проверка — обе мутации пойманы:

| Мутация | Ответ набора |
|---|---|
| транзитивности нет (прежнее поведение) | три теста набора, включая прогон `iec2c` |
| наследование на один шаг | цепочка из трёх: `Probe_outer` не объявляет `ticks` |

Вторая мутация — причина, по которой в наборе есть цепочка длиной три: на
двух функциях «один шаг» и «транзитивно» неразличимы.

### Найденные дефекты

Дефектов правки нет. Замер кандидата оказался **неточен** в части цели `sv`:
приписанный ему отказ `SV-002` давала не цепочка вызовов, а **досрочный
возврат** в пробе — по своей задокументированной причине. С одним возвратом
`sv` вход принимает; класс принадлежит только цели `st`. Это второй случай
подряд, когда текст кандидата уточняется прогоном (правило 30).

### Выводы и дальнейшие шаги

Корпус такой формы не содержит — снимки `examples/generated/` не изменились.

## Итог (что сделано)

Цель `st` считает список разделяемых переменных **транзитивно**: функция
объявляет `VAR_IN_OUT` для того, что читает её тело и тела всех функций,
которые она зовёт. Прежде список обрывался на первом вложенном вызове, и
`iec2c` отвечал «Variable not declared in this scope» при нулевом коде возврата
`taktc`.

Класс принадлежит только цели `st`: приписанный кандидатом отказ `sv` оказался
её собственной границей (досрочный возврат), и это проверено контрольным
входом.
