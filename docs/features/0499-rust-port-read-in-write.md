# Фича: Цель `rust` — чтение порта в аргументе записи порта

- **Номер:** 0499
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 1
- **Класс:** невалидный вывод цели
- **Связанные issue (анализ):** перебор «порты × позиции значения» 2026-09-02

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Запись в выходной порт, чьё значение читает входной порт, давала у цели `rust`
невалидный файл при **нулевом** коде возврата `taktc`: методы HAL-трейта берут
`&mut self`, и `hal.write_u8(p, hal.read_u8(q))` — два изменяемых заимствования
разом (`E0499`). Значение поднимается во временную.

## Замер (правило 30)

Дата: 2026-09-02. Инструмент: `scripts/probe.sh`. Вход — простейший:
`echo := raw + ticks;` при `in raw: u8`, `out echo: u8`.

| Потребитель | Ответ |
|---|---|
| эталон, `c`, `c-hal`, `st`, `st-at`, `sv`, `sv-mmio`, `plantuml` | исполняют / переводят |
| `rust` | `rustc`: `E0499 cannot borrow *hal as mutable more than once` |

**Почему проверка цели молчал.** Он гоняет корпус, а в `examples/` нет ни одной
записи в порт, чьё значение читает порт: `grep` по `examples/generated/rust/*.rs`
даёт ноль совпадений при 19 вызовах `write_*`. Форма при этом самая обычная —
«эхо входа на выход»; корпус пишет в порт константы и переменные модели.

**А в документе класс был.** Проверка снимков `book/` показал, что пример
`book/src/18-showcase/examples/lift.takt` содержит ровно эту запись
(`display := at_floor;` — «индикатор следует за датчиком»), и приложение
«Порождённый код примера» печатало читателю Rust, который не собирается.
Примеры `book/` проверяются компиляцией и симуляцией, но инструментами целей —
нет; отсюда кандидат в `FEATURES.md`.

### Граница класса — тоже замер

Проба на голом Rust: из трёх сочетаний заимствований запрещено **одно**.

| Форма | `rustc` |
|---|---|
| `hal.write_u8(p, hal.read_u8(q))` | `E0499` |
| `hal.read_u8(a) + hal.read_u8(b)` | принимает |
| `f(hal.read_u8(a), hal)` | принимает |

Два последних разводит two-phase borrow, и поднимать там нечего. Отсюда узость
правила: подъём печатается **по нужде**, только у записи в порт.

## Архитектура (ADR)

Правка живёт у **цели**, а не в семантике: прочие семь потребителей ту же
запись переводят, и подъём во временную — идиома Rust (как `local_stub` 0376
или разыменование 0494), а не свойство языка. Этим случай отличается от 0400,
0431 и 0493, где временную заводит семантика для нескольких целей сразу.

Форма — блочное выражение `{ let takt_value = …; hal.write_u8(…, takt_value) }`.
Присваивание печатает **один** носитель (`rust_assign::assign`), и блок работает
в любом его контексте: отдельной правки печатника операторов не нужно, а значит
не возникает второго места, которое обязано согласиться.

Признак берётся у **напечатанного** текста — «есть ли в значении обращение к
получателю HAL». Обход дерева значил бы перечисление форм (условие,
арифметика, аргумент вызова, приведение), а печатнику важно ровно одно.

### Отвергнуто

- **Поднимать всегда.** Проще, но лишняя временная — шум в выводе, который
  читают люди, и расхождение снимков `examples/`.
- **Сделать `read_*` методом `&self`.** Убрало бы конфликт, но лжёт о железе:
  чтение регистра бывает с побочным эффектом (очистка флага по чтению).

## Анализ

Затронут один носитель — `rust_expr::write_port`. Второй путь печати записи
(начальное значение порта, `rust_port_init`) правки не требует: инициализатор
порта не читает портов вовсе — это запрещает `SE-113`.

## Тест-план

| Проверка | Ожидание |
|---|---|
| `rustc` и `clippy` под `-D warnings` | принимают вывод |
| формы `write_u8` и `write_bit` | значение поднято, внутри вызова чтения нет |
| значение без чтения порта | подъёма нет |
| потактовая сверка эталон ↔ `rust` | `(21, 1, 3)` с обеих сторон |

## Отчёт о тестировании

Мутационная проверка — обе мутации пойманы:

| Мутация | Ответ набора |
|---|---|
| подъёма нет (прежнее поведение) | `rustc` отверг вывод; текстовый контроль упал |
| подъём всегда | контроль «по нужде» упал |

Мутация «подъёма нет» роняет и **сверку**: драйвер не собирается с тем же
`E0499`, что был в замере, — то есть набор воспроизводит исходный класс, а не
проверяет форму текста.

Фикстура сверки берёт **двунаправленный** порт: значение, записанное моделью,
читают обе стороны, и сценарий входов не нужен. С входным портом обе стороны
читали бы нули, и `o_sum` не отличался бы от контрольного `o_plain`.

`./scripts/precheck.sh` — зелёный.

## Итог

Цель `rust` печатает валидный файл для записи в порт, чьё значение читает порт.
Граница правила измерена: два прочих сочетания заимствований законны, и подъём
там не печатается.
