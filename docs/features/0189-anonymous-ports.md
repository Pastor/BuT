## Краткое описание (как понято требование)

Вводится **анонимный порт** — обращение к ячейке по адресу **без объявления
имени**, прямо в выражении. Префикс `#` относится **только** к этой форме:
объявление порта остаётся таким, каким его задаёт
[пересмотр задания адресов и доступа к портам](0187-port-io-redesign.md), и в этой фиче **не меняется**.

### Обращение по анонимному адресу (без объявления)

Адрес пишется в выражении литералом с префиксом `#`, к нему применимы уже
существующие операции языка:

```takt
#0x000346619.4                  // 4-й бит по адресу 0x346619 (битовый доступ)
#0x000346619:0 as u64           // ячейка по адресу как 64-разрядное целое
#0x000346619:0 as u64 := 67     // запись 67 по адресу как u64
```

- `.4` — **битовый доступ** к анонимному порту (тот же оператор, что `x.0`);
- `:0` — часть **адресного литерала** (позиция бита), как в `0xADDR:бит`;
- `as u64` — приведение, задающее **ширину доступа** к ячейке;
- присваивание `:= 67` — **запись** по адресу.

**Направление у анонимного порта не объявлено**, поэтому его использование
**для записи всегда даёт предупреждение** — компилятор не может проверить, что
запись по этому адресу законна.

### Анонимное обращение — операнд, а не оператор

Само по себе обращение обособленно стоять **не может**: чтение ячейки, значение
которой никуда не идёт, эффекта не имеет. Такая запись — **синтаксическая**
ошибка (её даёт парсер, а не семантика):

```takt
#0x000346619.4;                        // ОШИБКА: обособленное обращение
```

Законно оно там, где значение **потребляется** — в условии, в правой части, в
аргументе:

```takt
if #0x000346619.4 && b = 4 { … }       // корректно: значение потребляет условие
x := #0x000346619:0 as u64;            // корректно: значение потребляет присваивание
```

…и там, где обращение само является **целью записи** (эффект есть):

```takt
#0x000346619:0 as u64 := 67;           // корректно: запись (с предупреждением)
```

### Объявление порта — по 0187, без изменений

Размещение именованного порта задаётся ключевым словом `at`, а `:=` означает
начальное значение (решение заказчика 2026-07-31, [ADR](0187-port-io-redesign.md#архитектура-adr)).
Фича этой формы **не касается** — примеры записываются так:

```takt
out X: bit at 0x000346619:7;        // выход, бит 7 по адресу
out Y: u32 at 0x000346619:0;        // выход, бит 0, тип u32
in  P: bit at 0x000346619:8;        // вход, бит 8
out H: u16 at 0x000346619 := 89;    // выход, тип u16, начальное значение 89
```

То есть `#` и `at` **не конкурируют**: `at` размещает **именованный** порт,
`#` адресует ячейку, у которой имени нет вовсе.

## Решения стадии 2 (ADR принят 2026-08-01)

Все семь развилок закрыты решением заказчика — подробности и цена вариантов в
[ADR](0189-anonymous-ports.md#архитектура-adr), раздел `Decision`:

| Ось | Решение |
|---|---|
| смысл `:B` / `as T` | `:B` — начало поля, `as T` — его разрядность; `#A` без ширины — ошибка |
| формы бита | `.B` (один бит) и `:B as T` (поле) законны обе |
| запись | предупреждение `SE-096`, текст называет способ снять |
| цели | `c-hal`, `st-at`, `sv-mmio` — поддерживают; `c`, `rust`, `st`, `sv` — отказ с причиной |
| симулятор | синтетический порт с именем из адреса |
| обособленное выражение | оператором остаются присваивание и вызов; прочее — `SY-007` |
| голый адресный литерал | вне позиции адреса запрещён (закрывает Tier-1-находку Ф2) |

## Открытые вопросы регистрации (закрыты стадией 2)

Ниже — исходный список вопросов, с которыми фича заводилась; каждый решён ADR:

1. **Тип и ширина доступа анонимного порта.** `as u64` задаёт ширину; что
   означает `#ADDR` без `as` и без бита — ошибка или умолчание?
2. **Разрешение бита:** `#ADDR:бит` (адресный литерал) и `#ADDR.бит` (битовый
   доступ) дают одно и то же значение разными путями — нужно решить, обе ли
   формы законны и как они соотносятся.
3. **Взаимодействие с картой адресов** (`--address-map`, оператор `address`):
   анонимный порт имени не имеет, значит переопределить его извне нечем — это
   осознанное ограничение или дыра в переносимости?
4. **Поведение целей.** Анонимный доступ естественен для `c-hal` (`*(volatile
   T*)addr`), но у `c` доступ идёт через HAL-колбэки по перечислению портов, у
   `st-at` — через located-переменные, у `sv` адресов нет вовсе. Требуется
   решить, какие цели фичу поддерживают, а какие отказывают диагностикой.
5. **Симулятор**: чем является анонимный адрес в прогоне — ячейкой модели
   памяти, портом со сгенерированным именем или отказом.
6. **Код предупреждения** на запись без направления и его текст.
7. **Как грамматика различает позиции.** Требование — отказ **синтаксический**:
   обособленное обращение недопустимо, а обращение-операнд и обращение-цель
   записи допустимы. Значит анонимный доступ входит в правило выражения, но
   оператор-выражение из него одного не выводится; форму правила предстоит
   выбрать так, чтобы отказ давал парсер, а не проверка после разбора.

### Context

Заказчик просит форму обращения к ячейке **по адресу, без объявления имени**:

```takt
#0x000346619.4                  // 4-й бит по адресу
#0x000346619:0 as u64           // ячейка как 64-разрядное целое
#0x000346619:0 as u64 := 67     // запись
```

Именованный порт эту задачу решает не всегда: регистр, к которому обращаются
один раз (разблокировка периферии, чтение идентификатора чипа, взвод контрольного
таймера), требует объявления, имени и — при `--address-map` — записи в карте.
Форма `#` убирает посредника.

#### Что уже есть в языке (пробы 2026-08-01, `taktc` ветки v2)

**Ф1. Адресный литерал уже является выражением.** Токен `AddressLiteral`
(`0xNNNN:бит`, `parser/lexer.rs`) входит в атом выражения (`Precedence1Full`,
`Precedence1NoBrace` в `grammar.lalrpop`) и порождает узел
`ast::Expression::Address(loc, addr, bit)` → `ExpressionNode::Address(addr, bit)`.
То есть **половина синтаксиса 0189 в языке уже разобрана** — не хватает префикса
`#` и семантики доступа.

**Ф2. И это — молчаливое расхождение эталона и цели `c` (Tier 1).** Проба
(вход из десяти строк, `var x: u8 := 0; always { x := 0x105:0; }`):

| Потребитель | Что делает с `x := 0x105:0;` |
|---|---|
| симулятор | присваивает **число 0x105 = 261**, бит игнорирует (`takt-sim/src/expression.rs`: `Address(addr, _bit) => Value::Number(addr)`); трасса `x=5` для `u8` |
| цель `c` | **оператор исчезает целиком** — в порождённом `.c` присваивания нет вовсе, `taktc` рапортует успех |
| цель `c-hal` | то же |
| цель `rust` | отказ `RS-011` («цель rust карту адресов не потребляет») |
| цель `st` | отказ `ST-011` |
| цель `sv` | отказ `SV-002` |

То же с приведением: `x := 0x105:0 as u64;` — симулятор `x=261`, цель `c` теряет
оператор. Класс — тот же, что у [семантическое разрешение тел вложенных операторов](0155-semantic-nested-statement-resolution.md): невыразимый
узел печатается **пустотой**, а не диагностикой.

**Ф3. В условиях адресного литерала нет вовсе.** `ref Done: 0x105:0 = 1;` →
`SY-002` (грамматика `Condition` этот атом не содержит). То есть форма
`if #0x346619.4 && b = 4 { … }` из требования сегодня недостижима **дважды**:
нет `#` и нет адресного атома в грамматике условий.

**Ф4. Обособленное выражение язык принимает — и это уже даёт дефект.** Требование
[анонимные порты](0189-anonymous-ports.md) гласит: обособленное обращение `#0x346619.4;` обязано быть **синтаксической**
ошибкой. Но сегодня обособленным может стоять **любое** выражение: проба
`always { x + 1; }` компилируется, цель `c` печатает `model->x + 1;`, а проверка
`cc -Wall -Werror`  отвергает вывод: `error: expression result unused
[-Werror,-Wunused-value]`. То есть отказ приходит **от чужого инструмента на
порождённом файле**, а не от компилятора Takt на исходнике.

**Ф5. Битовый доступ `.N` существует** (`Expression::BitAccess`) и печатается
целью `c` как `((model->y >> 1) & 1u)`.

**Ф6. Механика доступа по адресу есть у трёх целей из семи.**

| Цель | Механика | Нужно ли имя порта |
|---|---|---|
| `c-hal` | таблица `{uintptr_t addr; int8_t bit; uint8_t width;}`, доступ `*(volatile uintN_t*)b.addr`, ширина по слову (`word_bytes_for_bit`, 0098) | **нет** — имя лишь индексирует таблицу |
| `st-at` | локация IEC `AT %IX256.0` у **глобальной переменной**, блоки видят её через `VAR_EXTERNAL` | **да** — локация принадлежит объявлению с именем |
| `sv-mmio` | срез регистрового файла `reg_*[bit +: width]`; направление принадлежит **биту**, а не слову | **да** — имя даёт сигнал |
| `c` | колбэки `(*ptr->read_numeric)(ПОРТ, …)` по перечислению портов | **да** — нужен перечислитель |
| `rust` | метод HAL-трейта по варианту `Port::Имя` | **да** |
| `st` | порт = `VAR_INPUT`/`VAR_OUTPUT` блока | **да** |
| `sv` | вывод модуля; адресов нет вовсе | адрес неприменим |

**Ф7. Токен `#` в лексере уже есть** (`Token::Sharp`, `parser/lexer.rs`), в
грамматике **не используется**, в `lsp/semantic_tokens.rs` разобран. То есть
префикс не требует нового токена — только правила.

**Ф8. Контракт доступа зафиксирован 0187 (ось 4B).** Таблица «чтение —
выражение, запись — оператор» и контроль
`takt-lang/tests/semantic/port_access_contract_tests.rs`. Анонимный доступ обязан войти в
**ту же** таблицу, иначе контракт получает исключение, о котором новая цель не
узнает.

### Практика других языков

| Язык / среда | Как адресуется ячейка без имени | Ширина доступа | Направление | Чем полезно нам |
|---|---|---|---|---|
| **C (CMSIS-стиль)** | `*(volatile uint32_t*)0x40000000` — выражение, тип задаётся приведением | **типом приведения**, обязательно | не выражается | ширина обязана быть явной: «просто адрес» типа не имеет |
| **Zig** | `@as(*volatile u32, @ptrFromInt(0x4000_0000)).*` | типом указателя | не выражается | то же, но приведение проверяемое |
| **Rust (`core::ptr`)** | `read_volatile(0x4000_0000 as *mut u32)` | типом указателя | не выражается; `unsafe` обязателен | доступ по «сырому» адресу — **помеченная опасность**, а не обычная операция |
| **Ada** | `for X'Address use To_Address(16#4000_0000#)` — только через **объявление** | типом объекта | `pragma Volatile` | безымянного доступа нет by design: адрес всегда получает имя и тип |
| **IEC 61131-3 (ST)** | `%QX0.0` — **прямая переменная**, может стоять прямо в выражении (`IF %IX0.1 THEN`) | буквой локации (`X`/`B`/`W`/`D`/`L`) | классом (`%I`/`%Q`/`%M`) | ближайший прецедент: анонимное обращение **есть**, и оно несёт и ширину, и направление |
| **SystemVerilog** | адресов нет; регистровый файл — срез `reg[bit +: width]` | шириной среза | направление у бита | наш `sv-mmio` уже так устроен |
| **Ассемблеры МК** | `MOV A, 0x35` — адрес есть, типа нет | инструкцией | нет | пример того, чего избегать: смысл кодируется вне выражения |

Два вывода, важных для выбора:

1. **Везде, где безымянный доступ есть, ширина задаётся явно** — приведением
   (C, Zig, Rust) или буквой локации (IEC). Ни один язык не выводит её из
   контекста присваивания.
2. **Direct-переменные IEC — единственный прецедент, где безымянное обращение
   несёт направление** (`%I` читают, `%Q` пишут). В C/Zig/Rust направления нет,
   ответственность на авторе; Rust дополнительно требует `unsafe`.

### Оси и варианты

#### Ось 1 — что означает `#АДРЕС` и как задаётся ширина доступа

Требование заказчика содержит три формы: `#A.4` (бит), `#A:0 as u64` (слово),
`#A:0 as u64 := 67` (запись). Прочтение `:0` неоднозначно, и от него зависит всё
остальное.

- **1A. `:B` — начальный бит поля, `as T` — его ширина** (`#A:B as T` ≡ срез
  `[B +: разрядность T]`; `#A.B` ≡ один бит `B`; `#A as T` ≡ `#A:0 as T`).
  *Плюсы:* согласуется с обеими существующими реализациями доступа по адресу —
  `{addr, bit, width}` у `c-hal` и `reg[bit +: width]` у `sv-mmio` (Ф6);
  объясняет пример заказчика `#A:0 as u64` (поле шириной 64 с бита 0) без
  противоречия «бит 0 при 64 разрядах». *Минусы:* два способа сказать «один бит»
  (`#A:4 as bit` и `#A.4`) — нужен ответ, законны ли оба (ось 2).
- **1B. `:B` — только позиция бита, `as T` — приведение значения, а не ширина
  доступа.** Тогда `#A:0 as u64` означает «бит 0, приведённый к `u64`», то есть
  0 или 1. *Плюсы:* `:B` значит ровно то же, что в объявлении порта. *Минусы:*
  выразить «прочитать 64-разрядное слово» становится нечем — то есть пример
  заказчика теряет заявленный смысл.
- **1C. Ширина только приведением, `:B` в анонимной форме запрещён** (`#A as u32`
  — слово, `#A.4` — бит). *Плюсы:* один способ на смысл, форма ближе всего к
  C/Zig/Rust. *Минусы:* поле шириной меньше слова со смещением (`[3 +: 4]`) не
  выразимо, хотя `sv-mmio` это умеет — язык окажется беднее собственной цели.
- **1D. `#A` без `as` и без бита законно, тип берётся из контекста** (тип
  приёмника присваивания либо второго операнда). *Плюсы:* короче. *Минусы:*
  против практики **всех** рассмотренных языков; в позиции без типа (`x := #A + 1`)
  ширина доступа к MMIO становится догадкой — ровно тот класс, который проект
  запретил в 0029 (`CC-016` вместо `_ => 4`).

Независимо от выбора требуется решить, **что такое `#A` вовсе без `as` и без
бита**: ошибка (называющая, чего не хватает) или умолчание. Предложение —
ошибка, по выводу 1 из практики языков.

#### Ось 2 — две формы бита: `#A:4` и `#A.4`

- **2A. `.B` — единственная форма одного бита; `:B` означает начало поля** (пара
  к 1A). Разные написания — разный смысл, дублирования нет.
- **2B. Обе формы законны и эквивалентны** (`#A:4` ≡ `#A.4`). *Минусы:* два
  написания одного смысла — форматтеру придётся выбирать канон, а документу
  объяснять разницу, которой нет.
- **2C. `.B` у анонимного обращения запрещён** (только `:B`). *Минусы:* ломает
  ожидание «`.N` — это бит», уже существующее в языке (Ф5), и расходится с
  требованием заказчика, где написано `#0x000346619.4`.

#### Ось 3 — направление и предупреждение о записи

Требование: «использование для записи **всегда даёт предупреждение**».

- **3A. Предупреждение на запись, чтение — молча.** Новый код `SE-096`.
  *Плюсы:* буква требования; чтение по чужому адресу безопаснее записи.
  *Минусы:* предупреждение, которое нечем погасить, в большом проекте становится
  шумом и его глушат целиком.
- **3B. Предупреждение на запись + названный способ его снять** — объявить
  именованный порт с тем же адресом (тогда направление объявлено и проверяемо).
  Новой сущности не требуется: способ уже есть, его надо назвать в тексте
  диагностики и в документе. *Минусы:* нет.
- **3C. Предупреждение и на чтение.** *Плюсы:* чтение MMIO тоже бывает с
  побочным эффектом (регистры, очищаемые чтением). *Минусы:* против требования.

#### Ось 4 — какие цели поддерживают анонимный доступ

Ключевой факт — Ф6: имени не требует **только** `c-hal`.

- **4A. Поддерживают `c-hal`, `st-at`, `sv-mmio`; остальные — называющий отказ.**
  У `st-at` и `sv-mmio` ячейке синтезируется имя (`__at_0x346619_4`), у
  `c`/`rust`/`st`/`sv` — отказ с причиной («доступ по адресу требует цели с
  картой памяти»). *Плюсы:* каждая цель делает то, что умеет; отказ громкий.
  *Минусы:* модель с `#` перестаёт быть переносимой между профилями — но она на
  это и не претендует.
- **4B. Плюс прямой доступ в `c` и `rust`** (`*(volatile uint32_t*)0x…`,
  `read_volatile`). *Плюсы:* переносимость шире. *Минусы:* ломает главный принцип
  цели `c` — «порты идут через HAL, адресов цель не знает»: прошивка,
  собранная под `c`, начнёт обращаться к железу мимо HAL пользователя.
- **4C. Только `c-hal`;** `st-at` и `sv-mmio` отказывают. *Плюсы:* минимальный
  объём, ни одного синтезированного имени. *Минусы:* `sv-mmio` умеет ровно это
  (срез регистра) — отказ был бы искусственным.

Любой вариант обязан дать **сверку с эталоном** (ось 5): цель, исполняющая
доступ иначе, чем симулятор,, уже стоивший проекту двух
дефектов.

#### Ось 5 — чем является анонимный адрес в симуляторе

- **5A. Ячейка модели памяти** (разреженная карта `адрес → слово`, начальное
  содержимое — ноль, сценарий может задать значение). *Плюсы:* перекрытие полей
  разной ширины по одному адресу моделируется верно. *Минусы:* новая сущность в
  симуляторе и новый раздел формата сценария.
- **5B. Синтетический порт с именем из адреса** (`#0x346619.4` → порт
  `__at_0x346619_4`; дальше — существующий механизм портов и сценариев).
  *Плюсы:* переиспользует всё готовое (значения портов, сценарии 0132) и
  совпадает с тем, что `st-at`/`sv-mmio` вынуждены сделать в кодогене.
  *Минусы:* два обращения к одной ячейке **разной ширины** станут разными
  портами — перекрытие полей не моделируется.
- **5C. Отказ `SIM-0NN`** — модель с `#` эталоном не исполняется. *Минусы:*
  модель становится непроверяемой (тупик `extern fn`, кандидат 0186-01), а
  примеры документа с `#` невозможны — проверка `book/` их не примет.

#### Ось 6 — грамматика: как сделать отказ обособленного обращения синтаксическим

Требование: `#0x346619.4;` — ошибка **парсера**. Факт Ф4: сегодня обособленным
законно стоит любое выражение, и порождённый C ловится `-Wunused-value`.

- **6A. Оператором-выражением остаются только формы с эффектом** — присваивание
  и вызов функции; всё прочее (включая `#…;` и `x + 1;`) — новый `SY-006`.
  *Плюсы:* закрывает требование 0189 и подтверждённый дефект Ф4 **одним**
  правилом; прецедент внутри проекта — [присваивание отвергается семантикой, а должно — грамматикой](../fixes/0187-01-assignment-is-statement-in-grammar.md) (позиция
  присваивания переведена в грамматику по требованию заказчика). *Минусы:*
  ломающее изменение для моделей, где обособленное выражение стоит (в корпусе
  таких нет — полная проверка выносится в анализ).
- **6B. Точечно: обособленным не может стоять только анонимное обращение.**
  *Плюсы:* минимальная правка, буква требования соблюдена. *Минусы:* дефект Ф4
  остаётся; язык получает правило-исключение вместо правила.
- **6C. Отказ семантический** (`SE-0NN` на выражение без эффекта). *Плюсы:*
  текст диагностики точнее. *Минусы:* против прямого требования заказчика («её
  даёт парсер, а не семантика»).

#### Ось 7 — судьба голого адресного литерала в выражении (находка Ф2)

Ось заведена **пробой**, а не требованием: она объясняет, почему форма `#` вообще
нужна, и обязана решаться вместе с ней — иначе в языке останутся две записи
одного смысла, из которых одна молча неверна.

- **7A. Голый `0xNNN:B` вне позиции адреса — синтаксическая ошибка.** Адресный
  литерал остаётся атомом только там, где его ждут (`at`, `address`, карта), а в
  выражении ячейка адресуется **только** через `#`. *Плюсы:* устраняет Ф2
  конструктивно; `#` получает смысл «здесь начинается доступ к памяти», видимый
  и человеку, и подсветке. *Минусы:* правка затрагивает существующий атом —
  требуется проверка корпуса и фикстур (беглая проба: в `examples/` голых
  адресных литералов в выражениях нет).
- **7B. Голый литерал остаётся числом-адресом** (как сегодня в симуляторе), шесть
  целей приводятся к этому поведению. *Минусы:* закрепляется форма, у которой нет
  применения.
- **7C. Не трогать.** *Минусы:* Tier 1 живёт дальше, а рядом появляется `#` с тем
  же написанием и другим смыслом.

### Предварительная рекомендация (не решение)

Связка **1A + 2A + 3B + 4A + 5B + 6A + 7A**:

- `#A:B as T` — поле шириной `T` с бита `B`; `#A.B` — один бит; `#A as T` —
  слово; `#A` без ширины — ошибка. Это ровно та тройка `{addr, bit, width}`,
  которой уже оперируют `c-hal` и `sv-mmio`;
- запись даёт предупреждение, текст которого называет способ его снять
  (объявить именованный порт);
- цели `c-hal`, `st-at`, `sv-mmio` поддерживают, прочие отказывают с причиной;
- симулятор моделирует ячейку синтетическим портом — сверка потактовая;
- обособленным оператором остаются только присваивание и вызов;
- голый адресный литерал в выражении становится синтаксической ошибкой.

**Цена связки:** новая форма выражения (лексер не трогается — `#` уже есть,
Ф7), правки грамматики выражений **и условий** (Ф3), новый узел АСД со всеми
обязанностями сопровождения (форматтер, `semantic/usages/walk.rs`,
`lsp/symbols.rs`, `semantic_tokens.rs` — свод), доступ в трёх целях,
модель доступа в симуляторе, подъём версии языка (`0.8.0` не
выпущена, изменения накапливаются в неё), разделы `book/` 05 и 08 плюс
приложение диагностик.

**Ломающая часть** — оси 6A и 7A: они отвергают тексты, которые сегодня
принимаются. по своду это требует явного решения заказчика; ценой
бездействия является подтверждённый пробой дефект (Ф2 — молчаливое расхождение
эталона и цели `c`, Ф4 — отказ чужого инструмента на порождённом файле).

### Вопросы заказчику

| # | Вопрос | Варианты |
|---|---|---|
| 1 | что означают `:B` и `as T` в анонимном обращении | 1A (начало поля + ширина) / 1B (позиция бита + приведение) / 1C (только `as`) / 1D (вывод из контекста) |
| 2 | законны ли обе формы бита (`#A:4`, `#A.4`) | 2A (разный смысл) / 2B (эквивалентны) / 2C (только `:B`) |
| 3 | предупреждение о записи | 3A (только запись) / 3B (+ названный способ снять) / 3C (и чтение тоже) |
| 4 | какие цели поддерживают | 4A (`c-hal`, `st-at`, `sv-mmio`) / 4B (все, включая `c`/`rust`) / 4C (только `c-hal`) |
| 5 | симулятор | 5A (модель памяти) / 5B (синтетический порт) / 5C (отказ) |
| 6 | обособленное выражение-оператор | 6A (запретить все без эффекта) / 6B (только `#`) / 6C (семантикой) |
| 7 | голый адресный литерал в выражении (находка Ф2) | 7A (запретить) / 7B (узаконить числом) / 7C (не трогать) |

### Decision

**Решение заказчика 2026-08-01** по всем семи осям:

| # | Ось | Решение |
|---|---|---|
| 1 | смысл `:B` и `as T` | **1A** — `:B` начало поля, `as T` его разрядность; `#A` без ширины — ошибка |
| 2 | две формы бита | **2A** — `.B` (один бит) и `:B as T` (поле) законны обе, смысл разный |
| 3 | предупреждение о записи | **3B** — предупреждение на запись, текст называет способ снять (объявить порт) |
| 4 | цели | **4A** — `c-hal`, `st-at`, `sv-mmio` поддерживают; `c`, `rust`, `st`, `sv` отказывают с причиной |
| 5 | симулятор | **5B** — синтетический порт с именем из адреса |
| 6 | обособленное выражение | **6A** — оператором остаются только присваивание и вызов; прочее — `SY-006` |
| 7 | голый адресный литерал в выражении | **7A** — вне позиции адреса запрещён |

**Что это означает практически.**

```takt
// чтение
x := #0x346619:0 as u64;          // 64 разряда с бита 0
b := #0x346619.4;                 // один бит
y := #0x346619:3 as u8;           // поле [3 +: 8]
if #0x346619.4 && b = 4 { … }     // операнд условия

// запись — оператор, предупреждение SE-096 (направление не объявлено)
#0x346619:0 as u64 := 67;

// незаконно
#0x346619;                        // SY-006: выражение без эффекта
x := #0x346619;                   // ширина не задана
x := 0x346619:0;                  // голый адресный литерал вне позиции адреса
```

Три следствия, которые нельзя потерять при реализации:

- **Тройка `{addr, bit, width}` — единая для языка и целей.** Она уже есть у
  `c-hal` (таблица привязок) и `sv-mmio` (срез `[bit +: width]`); анонимное
  обращение обязано порождать **ту же** тройку, а не собственную.
- **Оси 6A и 7A ломающие** — отвергают тексты, которые сегодня принимаются.
  Заказчик выбрал их, зная цену; переходного периода нет (прецедент 0187).
  Ось 6A шире буквы требования сознательно: одно правило закрывает и запрос
  («обособленное обращение — ошибка парсера»), и подтверждённый дефект Ф4.
- **Ось 5B не моделирует перекрытие полей** разной ширины по одному адресу
  (`#A as u8` и `#A as u32` — разные синтетические порты). Это осознанное
  ограничение эталона; оно **обязано** попасть в документ и в отчёт, иначе
  станет молчаливым расхождением с `c-hal`, который читает настоящую память.

### Consequences

Уже сейчас можно утверждать:

- **Фича меняет язык** → версия `0.8.0` (не выпущена) принимает изменения без
  подъёма номера; при выпуске это ломающее изменение, если приняты
  6A/7A.
- **Новый узел АСД тянет четыре обязанности сопровождения:** печать в `format/`
  (иначе `format_source` начнёт отказывать), обход `semantic/usages/walk.rs`
  (сборка валится сама), `lsp/symbols.rs` + `semantic_tokens.rs`,
  вычислитель симулятора `eval/` под `deny(wildcard_enum_match_arm)`.
- **Сверку заводить вместе с доступом**, а не после: проверка цели доказывает, что
  вывод компилируется, но не что он верен (уроки и 0050).

## Анализ

### Цель и контекст

[ADR](0189-anonymous-ports.md#архитектура-adr) принят решением заказчика 2026-08-01
по семи осям: `#A:B as T` — поле разрядности `T` с бита `B` (1A), формы `.B` и
`:B as T` законны обе с разным смыслом (2A), запись даёт предупреждение с
названным способом снять (3B), поддерживают `c-hal`/`st-at`/`sv-mmio` (4A),
симулятор моделирует ячейку синтетическим портом (5B), обособленным оператором
остаются только присваивание и вызов (6A), голый адресный литерал вне позиции
адреса запрещён (7A).

Анализ переводит это в точки кода, задачи, замеры и риски.

### Зависимости фичи

- **Зависит от:** нет. [пересмотр задания адресов и доступа к портам](0187-port-io-redesign.md) закрыта
  2026-08-01; принятая ею модель (`at` размещает, `:=` — начальное значение,
  доступ нормирован таблицей) — вход этой фичи, а не ожидание.
- **Влияние на порядок разработки:** фича не разблокирует ничего — ни одна
  незакрытая фича на 0189 не ссылается. Порядок таблицы `FEATURES.md` не
  меняется: 0189 стоит первой как единственная проработанная до `АНАЛИЗ`.
- **Смежно:**
  - [адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md) — три источника адреса.
    Анонимное обращение **четвёртым источником не является**: у ячейки нет
    имени, значит ни оператор `address`, ни `--address-map` её не адресуют.
    Приоритет источников не трогается.
  - [проверка диапазона бита адреса порта и безопасный принятый по умолчанию HAL](0098-port-bit-range-safe-hal.md) — предел бита `[0, 63]`
    и ширина доступа по слову; анонимное обращение подчиняется тем же правилам,
    иначе `c-hal` получит два разных закона для одной ячейки.
  - [пересмотр задания адресов и доступа к портам](0187-port-io-redesign.md) — таблица доступа и её контроль
    `takt-lang/tests/semantic/port_access_contract_tests.rs`: анонимный доступ входит в
    **ту же** таблицу.

### Что подтверждено пробами и чтением кода (2026-08-01)

1. **Токен `#` уже есть** (`Token::Sharp`, `parser/lexer.rs`), в грамматике не
   используется, в `lsp/semantic_tokens.rs` разобран. Нового токена не нужно.
2. **Адресный литерал уже атом выражения** (`Precedence1Full`,
   `Precedence1NoBrace`) и даёт `ExpressionNode::Address(addr, bit)`. В грамматике
   **условий** его нет (проба: `ref Done: 0x105:0 = 1;` → `SY-002`).
3. **Голый адресный литерал в теле — молчаливое расхождение (Tier 1).** Проба:
   `always { x := 0x105:0; }` — симулятор `x = 5` (адрес как число, обёртка
   `u8`), цель `c` **теряет оператор целиком**, `rust`/`st`/`sv` отказывают
   (`RS-011`/`ST-011`/`SV-002`). Ось 7A устраняет причину.
4. **Обособленное выражение принимается языком.** Проба: `always { x + 1; }`
   компилируется, цель `c` печатает `model->x + 1;`, а проверка `cc -Wall -Werror`
   отвергает вывод (`error: expression result unused [-Wunused-value]`). Ось 6A
   устраняет причину.
5. **`if` в теле разбирается через `Expression`** (`grammar.lalrpop`,
   `OpenStatement`/`ClosedStatement`), а не через `Condition`. Значит требование
   заказчика `if #0x346619.4 && b = 4 { … }` покрывается атомом **выражения**;
   грамматика **условий** нужна отдельно — для рёбер `ref` и именованных `cond`.
6. **В грамматике условий нет `as`** (факт фичи: «`*`, `/` и `as` там
   отсутствуют»). Следствие: в условии выразима только **битовая** форма
   `#A.B`; словная требует приведения и потому в условии незаконна.
7. **Механику доступа по адресу имеют три цели** — `c-hal` (таблица
   `{addr, bit, width}` + `*(volatile uintN_t*)`), `st-at` (локация `%IX256.0` у
   **именованной** глобальной), `sv-mmio` (срез `reg[bit +: width]`). Имени не
   требует только `c-hal`.
8. **Прецедент точной диагностики парсера есть**: `parse_entry.rs`
   перехватывает `ParseError::UnrecognizedToken` по токену `:=` и печатает
   `SY-006` — правило языка вместо механики разбора.
9. **Свободные коды:** `SE-096`, `SE-097`, `SE-098`; `SY-007`, `SY-008` (занято
   до `SE-095` и `SY-006`; `SE-091` — `RETIRED`).

#### Замер цены ломающих осей (2026-08-01)

| Ось | Что отвергается | Найдено в проекте |
|---|---|---|
| 7A | голый `0xNNN:B` в выражении | **0** в `.takt` (корпус, `book/`, все фикстуры). 16 совпадений в `.rs` — это **карты адресов** (`.ld`-формат) и доктест `parse_address_literal`, к выражениям отношения не имеют |
| 6A | обособленное выражение-оператор | **0** в `.takt`: все 21 совпадение эвристики — поля структур, `break;`, `return;` |

Замер по `.takt` полон, по `.rs` — нет: фикстуры живут строками внутри тестов,
и часть из них разбирает именно эти формы (`parser_tests.rs:378`,
`parser_tests/part2.rs:935` проверяют разбор адресного литерала **как
выражения**). Их правка — часть задачи; полный список даст прогон, а не
греп.

### Форма и её разбор

#### Синтаксис (принят ADR)

```
AnonAddress ::= '#' AddressLiteral      // #0x346619:3 — начало поля бит 3
              | '#' HexNumber           // #0x346619   — начало поля бит 0
Ширина      ::= 'as' Type               // обязательна, кроме битовой формы
Бит         ::= '.' Number              // #0x346619.4 — один бит
```

#### Как это ложится на существующие узлы

Обращение **не** поглощает `as` и `.N` в свой узел: оба оператора в языке уже
есть (`Expression::Cast`, `Expression::BitAccess`), у них свои приоритеты
(`Chain7` и постфикс), и дублировать их разбор внутри нового атома значило бы
завести вторую грамматику приведения. Поэтому:

| Запись | Дерево АСД | Узел семантики |
|---|---|---|
| `#0x346619:0 as u64` | `Cast(AnonAddress(0x346619, 0), u64)` | `AnonPort { addr, bit: 0, width: 64 }` |
| `#0x346619.4` | `BitAccess(AnonAddress(0x346619, 0), 4)` | `AnonPort { addr, bit: 4, width: 1 }` |
| `#0x346619:3 as u8` | `Cast(AnonAddress(0x346619, 3), u8)` | `AnonPort { addr, bit: 3, width: 8 }` |
| `#0x346619` | `AnonAddress(0x346619, 0)` | **`SE-097`** — ширина не задана |

**Канонизация — в одной воронке.** Свёртку `Cast`/`BitAccess` над `AnonAddress`
в тройку делает **одно** место семантики (образец — `canonicalize_state_of`
фичи, где скобки паттерна снимаются в единственной воронке
`resolve_condition`). Обёртки `Parenthesis` снимаются **только** у операнда
анонимного обращения: глобально их снимать нельзя — генераторы печатают их как
группировку.

**Ширину задаёт ближайшее приведение.** `#A as u32 as u8` — доступ шириной 32
с последующим сужением значения до `u8`, а не доступ шириной 8: приведение,
стоящее непосредственно над обращением, задаёт **ширину доступа к памяти**, все
последующие — обычные операции над прочитанным значением. Иначе ширина
обращения к MMIO зависела бы от хвоста выражения.

### Требования и проверяемые условия

#### Форма и разбор

- **R1.** `#0x346619:0 as u64`, `#0x346619.4`, `#0x346619 as u32` разбираются в
  позиции **выражения** (тело блока, тело функции, `if`, аргумент вызова,
  инициализатор).
- **R2.** `#0x346619.4` разбирается в позиции **условия** (ребро `ref`,
  именованный `cond`, `invariant`). Словная форма в условии незаконна и даёт
  **называющую** диагностику (в грамматике условий нет `as` — факт 6), а не
  `SY-002` про неведомый токен.
- **R3.** Позиции узла сохранены: диагностика указывает на само обращение, а не
  на начало оператора.
- **R4.** Форматтер печатает обращение обратно байт-в-байт, сохраняя выбор формы
  (`.4` против `:4 as bit`): синонимы не канонизируются, как `while`/`loop`.
- **R5.** Предел глубины разбора (`MAX_PARSE_DEPTH`, 0156) считает новый узел, а
  отвергнутое дерево утилизируется итеративно (`parser/depth/dismantle.rs`).

#### Семантика

- **R6.** Узел семантики несёт **тройку** `{addr, bit, width}` — ту же, которой
  оперируют `c-hal` и `sv-mmio`.
- **R7.** Ширина не задана (`#A` без `as` и без `.B`) → **`SE-097`**,
  называющая, чего не хватает.
- **R8.** Запись по анонимному адресу → предупреждение **`SE-096`**, текст
  которого **называет способ снять**: объявить именованный порт с тем же
  адресом (решение 3B). Чтение — молча.
- **R9.** Бит вне `[0, 63]` либо `bit + width > 64` → **`SE-098`**. Пределы те
  же, что у именованного порта (0098): два закона для одной ячейки недопустимы.
- **R10.** Тип выражения — тип ширины (`as T` → `T`; `.B` → `bit`), а не
  `Unsupported`: иначе проверки типов обойдут обращение молча.

#### Ломающие правила (оси 6A и 7A)

- **R11.** Обособленным оператором остаются **присваивание** и **вызов
  функции**; `x + 1;`, `#A.4;`, `A;` → **`SY-007`** от **парсера**, с текстом о
  правиле языка, а не о механике разбора (прецедент `SY-006`).
- **R12.** Голый адресный литерал вне позиции адреса (`x := 0x105:0;`) →
  **`SY-008`**, текст которого называет замену (`#0x105:0 as ТИП`). Позиции
  `at`, `address` и внешняя карта не затронуты.
- **R13.** Миграция фикстур выполнена в этой же фиче; `precheck.sh` зелёный.

#### Потребители

- **R14. Симулятор** исполняет обращение как синтетический порт
  (имя строится из адреса, бита и ширины): значение читается и пишется,
  наблюдаемо в трассе, задаётся сценарием по имени (механизм 0132).
- **R15. `c-hal`** порождает доступ `*(volatile uintN_t*)0xADDR` со сдвигом и
  маской по `{bit, width}` — той же формы, что принятый по умолчанию HAL именованного порта.
- **R16. `st-at`** порождает размещённую переменную с синтезированным именем;
  `iec2c` вывод принимает.
- **R17. `sv-mmio`** порождает срез регистрового файла `[bit +: width]`; чтение
  — вход регистрового файла, запись — выход (направление принадлежит биту,
  свод ADR). Оба инструмента (`verilator`, `yosys`) вывод принимают.
- **R18. `c`, `rust`, `st`, `sv`** отказывают **с причиной** («доступ по адресу
  требует цели с картой памяти: `c-hal`, `st-at`, `sv-mmio`»), а не теряют
  оператор молча.
- **R19. Сверка потактовая:** симулятор ≡ `c-hal` на модели с чтением и записью
  анонимной ячейки. Проверка цели доказывает компилируемость, но не верность.
- **R20.** Таблица контракта доступа 0187 расширена строкой анонимного
  обращения, контроль падает при отклонении.

#### Общее

- **R21.** Версия языка: `0.8.0` не выпущена — изменения накапливаются в неё, подъёма нет.
- **R22.** Редакторский слой — см. раздел ниже; ответ «не нужно»
  фиксируется наравне с правкой.
- **R23.** Документ `book/`: разделы 05 (выражения) и 08 (порты и адреса) плюс
  приложение «Ошибки и предупреждения» (`SE-096`…`SE-098`, `SY-007`, `SY-008`).

### Особенности по обратной совместимости

- **Ломающих изменений два**, оба приняты заказчиком осознанно:
  - обособленное выражение-оператор перестаёт быть законным (`SY-007`);
  - голый адресный литерал в выражении перестаёт быть законным (`SY-008`).
- **Цена в проекте близка к нулю** (замер выше): в `.takt` нет ни одного случая
  ни того, ни другого; правки требуют лишь строковые фикстуры тестов парсера,
  сознательно проверяющие отменяемые формы.
- **Цена у пользователя** ненулевая, но обе отменяемые формы сегодня либо молча
  неверны (адресный литерал: расхождение эталона и цели `c`), либо отвергаются
  инструментом цели на порождённом файле (обособленное выражение:
  `-Wunused-value`). Отменяется то, что и так не работало.
- **Переходного периода нет** — прецедент 0187, решение заказчика.
- **Приоритет источников адреса (0020) не трогается**: анонимное обращение
  четвёртым источником не является.
- **Версия языка** не поднимается: `0.8.0` не выпущена.

### Риски

- **Риск: две грамматики (выражения и условия) разъедутся.** Атом `#` вводится в
  обе; забыть вторую легко, а проявится это как `SY-002` на законном ребре.
  Снижение — критерий A2 и фикстура с ребром `ref Next: #0x100.0;`.
- **Риск: свёртка `Cast`/`BitAccess` окажется в двух местах.** Уроки
  («арифметика — в одном месте») и 0074 («канонизация — в единой воронке»):
  свёртка пишется один раз, оба потребителя (выражения и условия) зовут её.
- **Риск: ширина доступа станет догадкой.** Класс (`_ => 4`): если
  приведение не найдено, обязан быть **отказ** `SE-097`, а не умолчание.
- **Риск: `SE-098` разойдётся с `SE-060`.** Предел бита у именованного порта
  считает слой адресов, у анонимного — семантика. Значение предела и правило
  ширины слова обязаны браться из **общего** места, иначе один и тот же адрес
  получит два закона.
- **Риск: цель `c` потеряет оператор молча** — ровно тот дефект, который фича
  устраняет. Отказ обязан быть **возвращён вызывающему**, а не проглочен
  печатником; критерий A13 проверяет наличие диагностики, а не
  отсутствие вывода.
- **Риск: 5B скроет перекрытие полей.** Симулятор моделирует `#A as u8` и
  `#A as u32` как **разные** порты, `c-hal` читает одну и ту же память. Это
  осознанное ограничение (ADR, раздел Decision) — оно обязано попасть в документ
  и в отчёт, иначе станет молчаливым расхождением.
- **Риск: `SY-007` заденет законную форму.** Вызов функции, возвращающей
  значение (`beep();` при `fn beep() -> u8`), обязан остаться законным: эффект у
  него есть. Проверяется отдельной фикстурой.

## Тест-план

### Область и цель

Проверяется форма `#АДРЕС` целиком: разбор (выражения и условия), свёртка в
тройку `{адрес, бит, ширина}`, диагностики (`SE-096`…`SE-099`, `SY-007`,
`SY-008`), поведение семи целей и эталона, а также **совпадение** трасс эталона
и цели `c-hal`.

свод: фича меняет синтаксис и семантику, поэтому в плане обязательны
примеры **и контрпримеры** — они ниже в каждой строке таблицы (вход, который
обязан приниматься, и вход, который обязан отвергаться).

Главный предмет проверки — не «компилируется», а **не расходится**: пробы
стадии 2 показали, что цель `c` теряла оператор молча при рапорте об успехе.
Поэтому у каждой цели проверяется **наличие диагностики**, а у пары

### Выводы и дальнейшие шаги

**Фича закрыла два подтверждённых дефекта Tier 1**, вскрытых её собственными
пробами на стадии архитектуры:

1. **Голый адресный литерал в выражении** (`x := 0x105:0;`): симулятор
   присваивал адрес числом (`x = 5`), цель `c` **теряла оператор целиком** при
   рапорте об успехе, три цели отказывали. Устранено осью 7 — форма отвергается
   разбором с называющей диагностикой.
2. **Цель `c` глотала любую ошибку печати оператора** (`Err(_) => {}` в
   `c_expr/stmt.rs`). Пропуск задумывался для встроенных `debug`/`S`, а работал
   для всего: невыразимый узел исчезал из вывода. Теперь пропускается только
   вызов встроенной функции, остальное доезжает до автора (класс исправления).

**Исправлений (`docs/fixes/`) не потребовалось:** все расхождения найдены до
закрытия и устранены в самих задачах.

**Записано кандидатами в `FEATURES.md`** (не втянуто в объём):

- сверки через `mmap` стоят ~90 с каждая, и таких контрольных тестов теперь два;
- цель `sv-mmio` на модели **без** входных битов оставляет `reg_wdata`/`reg_wen`
  неиспользуемыми (`verilator` предупреждает, но принимает) — свойство цели,
  существовавшее и до фичи (проверено на `examples/regulator.takt`).

## Итог (что сделано)

В язык введено **обращение к ячейке по адресу без имени** — `#АДРЕС`. Форма
собирается из трёх узлов, которые в языке уже были (`#адрес`, `as ТИП`, `.N`),
и сворачивается семантикой в тройку `{адрес, бит, тип}` — **ту же**, которой
уже оперируют принятый по умолчанию HAL цели `c-hal` (`{addr, bit, width}`) и регистровый
файл цели `sv-mmio` (`reg[bit +: width]`).

| Ось решения | Итог |
|---|---|
| 1 (смысл `:B` / `as T`) | `#A:B as T` — поле разрядности `T` с бита `B`; `#A` без ширины — `SE-097` |
| 2 (формы бита) | `.B` и `:B as bit` законны обе, смысл разный |
| 3 (запись) | предупреждение `SE-096`, текст называет способ снять |
| 4 (цели) | `c-hal`, `st-at`, `sv-mmio` — доступ; `c`, `rust`, `st`, `sv` — отказ с причиной (`CC-021`, `ST-018`, `SV-017`) |
| 5 (эталон) | синтетический порт: значение видно в трассе, сверка потактовая |
| 6 (оператор) | оператором остаются присваивание и вызов; прочее — `SY-007` |
| 7 (голый литерал) | вне позиции размещения — `SY-008` |

**Фича попутно устранила два подтверждённых дефекта Tier 1**, вскрытых пробами
стадии 2 (оба — «молча неверный продукт»):

1. **Голый адресный литерал** в теле (`x := 0x105:0;`) принимался языком:
   симулятор присваивал адрес числом, а цель `c` **теряла оператор целиком**
   при рапорте об успехе. Устранено осью 7 — форма отвергается разбором.
2. **Цель `c` глотала любую ошибку печати оператора** (`Err(_) => {}`): пропуск
   задумывался для встроенных `debug`/`S`, а работал для всего. Теперь
   пропускается только вызов встроенной функции, прочее доезжает до автора
   диагностикой (класс исправления).

**Ограничение, зафиксированное сознательно:** эталон различает ячейки по
тройке, поэтому `#A as u8` и `#A as u32` для него — **разные** ячейки, тогда
как на плате это одна память. Записано в документе, в `CLAUDE.md` и пришпилено
тестом `takt-sim/src/anon_cell.rs::different_widths_are_different_cells`.

Детали проверок — в [отчёте](0189-anonymous-ports.md#отчёт-о-тестировании); решения и цена
вариантов — в [ADR](0189-anonymous-ports.md#архитектура-adr).
