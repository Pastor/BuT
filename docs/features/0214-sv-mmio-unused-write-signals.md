### Context

Цель `sv-mmio` печатает регистровый интерфейс из четырёх сигналов: `reg_addr`,
`reg_wdata`, `reg_wen`, `reg_rdata`. На модели, у которой нет **входных** портов,
писать шине некуда — и два сигнала записи остаются неподключёнными.

#### Замеры (2026-08-17, verilator 5.050, `--lint-only -Wall`)

| Модель | Порты | Регистровый интерфейс | `UNUSEDSIGNAL` |
|---|---|---|---|
| проба `no_ports` (портов нет вовсе) | — | **не эмитится вовсе** | 0 |
| проба `only_in` (только `in cmd`) | входной | все четыре сигнала | 0 |
| `examples/regulator.takt` (только `out ready`) | выходной | все четыре сигнала | **2**: `reg_wdata`, `reg_wen` |
| `examples/stacker.takt` (входные и выходные) | оба | все четыре сигнала | 0 |

**Замер кандидата уточнён:** предупреждений **два**, а не четыре. Свойство
действительно старше фичи и к анонимным ячейкам не сводится.

**Решающее наблюдение — правило уже существует, но действует наполовину.**
Модель без единого порта регистрового интерфейса **не получает**: цель уже умеет
не печатать то, чему нет соответствия в модели. Не хватает лишь различения по
**направлению**: сигналы записи нужны, когда есть хотя бы один входной регистр,
а не когда есть хоть какой-нибудь.

**Почему проверка молчит.** Список `SV_MMIO_TRANSLATABLE` состоит из одного примера
— `stacker`, у которого входные порты есть. Модель без входных битов в проверка не
попадает, поэтому предупреждения никто не видит. При этом
`verilator --lint-only -Wall` завершается с **ненулевым** кодом
(`%Error: Exiting due to 2 warning(s)`): попади такая модель в проверка — он бы упал.

**APB-обёртка (0169) наследует ту же беду:** пара «ядро + обёртка» на
`regulator` даёт те же два предупреждения, и приходят они от ядра.

### Decision Drivers

1. **Интерфейс должен отражать модель.** Сигнал, которому в модели ничего не
   соответствует, — либо лишний, либо признак незаконченной трактовки.
2. **Правило уже принято на соседнем случае** (нет портов → нет интерфейса);
   решение должно его продолжить, а не завести второе.
3. **Проверка обязан ловить это сам.** Сегодня класс невидим, потому что в списке
   `sv-mmio` один пример с «удобным» составом портов.
4. **Ни одного молчаливого драйвера.** Любое решение, где шина и автомат пишут
   один разряд, требует явного арбитража — иначе синтез даст неопределённость.

### Considered Options

#### Option A. Эмитить сигналы записи только при наличии входных регистров

`reg_wdata`/`reg_wen` печатаются, если у модели есть хотя бы один входной порт с
адресом; `reg_addr`/`reg_rdata` — как сейчас, при наличии любого регистра.

**Pros:**
- Продолжает уже принятое правило «интерфейс отражает модель».
- Снимает предупреждения без единой заглушки.
- Модуль только для чтения получает честный интерфейс — по нему видно, что
  запись не предусмотрена.

**Cons:**
- Форма интерфейса становится зависимой от состава портов — потребитель ядра
  (в том числе APB-обёртка) обязан это учитывать. Обёртка APB принимает
  `pwdata`/`pwrite` по спецификации шины; при ядре без записи они станут
  неиспользованными **в обёртке**, и её придётся честно закрыть — либо
  игнорировать запись с явным комментарием, либо не эмитить адаптер записи.

#### Option B. Позволить шине писать в выходные регистры (арбитраж)

**Pros:** интерфейс постоянен, запись работает всегда.

**Cons:**
- **Два драйвера одного разряда:** автомат и шина. Требуется арбитраж в
  `always_ff` и решение «кто главнее» — то есть **изменение семантики цели**:
  значение выходного порта перестаёт быть функцией модели.
- Противоречит смыслу `out` в языке: выход — то, что вычисляет автомат.

#### Option C. Заглушить предупреждение `/* verilator lint_off UNUSEDSIGNAL */`

**Pros:** одна строка.

**Cons:** прячет симптом, оставляя причину. Проект уже знает цену такого хода:
проверка, которому заглушили голос, перестаёт быть свидетелем.

#### Option D. Ничего не менять

**Pros:** ноль риска.
**Cons:** порождённый модуль несёт сигналы в никуда; попадание такой модели в
проверка уронит его с сообщением, объясняющим следствие, а не причину.

### Decision

**Принято решением заказчика 2026-08-17: Option A.**

1. `reg_wdata`/`reg_wen` эмитятся тогда и только тогда, когда есть хотя бы один
   **записываемый шиной** регистр (входной порт с адресом).
2. **APB-обёртка приводится в соответствие** тем же признаком: при ядре без
   записи её сигналы записи либо не подключаются к ядру с явным пояснением,
   либо не эмитятся — что именно, решает проба линтом (оба варианта обязаны
   пройти `--lint-only -Wall` и синтез).
3. **Проверка пополняется моделью без входных битов.** Сегодня список
   `SV_MMIO_TRANSLATABLE` — один `stacker`; без второго примера класс останется
   невидимым. Кандидат — `regulator` (все порты `out`), он уже в корпусе.

### Consequences

#### Положительные

- Порождённый модуль перестаёт нести сигналы, которым в модели ничего не
  соответствует.
- Проверка начинает видеть класс: `verilator -Wall` на модели только для чтения
  падал бы, а теперь проверяется постоянно.

#### Отрицательные / Action items

- Форма интерфейса ядра зависит от состава портов — это надо **назвать** в
  README (раздел о цели `sv-mmio`), иначе интегратор шины столкнётся с этим на
  плате, а не в документе.
- Обёртка APB требует парной правки и собственной пробы линтом и синтезом.
- Тестбенч APB (0169) написан руками и обращается к записи; для ядра без
  записи нужен либо отдельный тестбенч, либо явное исключение с причиной.

#### Acceptance criteria

1. `regulator` целью `sv-mmio` даёт **0** `UNUSEDSIGNAL` под `--lint-only -Wall`.
2. `stacker` (входные порты есть) сохраняет прежний интерфейс — вывод не изменился.
3. Пара «ядро + APB-обёртка» на модели без записи проходит линт и синтез.
4. `SV_MMIO_TRANSLATABLE` содержит модель без входных битов, и проверка зелёный.
5. Форма интерфейса описана в README.

## Анализ

### Цель и контекст

На модели без входных портов цель `sv-mmio` печатала `reg_wdata`/`reg_wen`,
которым в модели ничего не соответствует: `verilator --lint-only -Wall` отвечал
двумя `UNUSEDSIGNAL` и **ненулевым** кодом возврата. ADR принял **Option A** —
сигналы записи эмитятся только при наличии записываемого шиной регистра.

### Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Правка локальна для цели `sv-mmio` и её адаптера шины.
- **Влияние на порядок разработки:** ничего не блокирует.

### Требования и проверяемые условия

- **R1. Признак — один.** «Есть ли что писать шиной» вычисляет единственный
  предикат `Mmio::has_writable`; своей копии условия у потребителей быть не
  должно.
- **R2. Ядро без записи не объявляет `reg_wdata`/`reg_wen`.**
- **R3. Ядро с входным портом не изменилось** — вывод байт-в-байт прежний.
- **R4. Адаптер APB следует за ядром:** не подключает несуществующие выводы, а
  сигналы записи протокола честно поглощает (их состав задан шиной, а не
  моделью, поэтому из интерфейса обёртки они не исчезают).
- **R5. Цикл записи по шине завершается штатно** (`pready = 1`, `pslverr = 0`) и
  значение выходного регистра не меняет.
- **R6. Проверка видит класс:** в `SV_MMIO_TRANSLATABLE` есть модель без входных
  битов, у неё парный тестбенч APB.
- **R7. Каждый потребитель интерфейса спрашивает, а не помнит.** Потребителей
  **три**, а не два: ядро, адаптер APB и **потактовая сверка**
  `conformance_sv_mmio_tests`, которая строит тестбенч кодом. Третьего ADR не
  назвал — его нашёл прогон (`PINNOTFOUND`).

### Особенности по обратной функциональности

**Форма интерфейса ядра становится зависимой от состава портов** — это
наблюдаемое изменение для интегратора шины. Обоснование (правило 11): прежний
интерфейс обещал запись, которой нет, и оставлял входы висеть; инструмент
сообщал об этом ошибкой. Модели **с** входными портами не затронуты вовсе
(вывод байт-в-байт прежний), поэтому изменение касается лишь тех случаев, где
прежний вывод и так не проходил `-Wall`.

**Редакторский слой (правило 29): не затронут** — язык не меняется.

### Риски и зависимости

- **Риск: потребитель, который помнит интерфейс, а не спрашивает.** Реализовался
  дважды (адаптер APB — предвиден ADR; сверка — нет). Снижение: R7 и прогон
  каждого потребителя, а не чтение.
- **Риск: тестбенч, проверяющий не то.** Первая редакция
  `regulator_apb_tb.sv` пыталась записать в выходной регистр **до** завершения
  автомата — и падала, потому что значение менял сам автомат за три такта цикла
  APB. Порядок проверок переставлен, причина записана в шапке тестбенча.

## Разработка

### Задача

#### Что было

`emit_reg_iface_lines` печатала все четыре сигнала регистрового интерфейса, если
у модели есть хоть один адресованный порт. На модели без **входных** портов
`reg_wdata`/`reg_wen` оставались неподключёнными: `verilator --lint-only -Wall`
— два `UNUSEDSIGNAL` и ненулевой код возврата.

#### Что сделано

**`takt-lang/src/generator/sv/sv_mmio.rs`:** заведён предикат
`Mmio::has_writable` — есть ли регистр, который пишет шина. Сигналы записи
эмитятся только при нём. Правило не новое, а достроенное: при
`Mmio::is_empty` интерфейс не эмитился и раньше — не хватало различения по
**направлению**.

**`takt-lang/src/generator/sv/sv_apb.rs`:** адаптер следует за ядром — не
объявляет внутренних проводов записи, не подключает `.reg_wdata`/`.reg_wen` и
честно поглощает сигналы записи протокола
(`wire _unused_write = &{1'b0, pwdata, pwrite, psel, penable};`). Без этого
verilator отвечал `PINNOTFOUND`: пара «ядро + обёртка» не собиралась вовсе.
Состав интерфейса самой обёртки не меняется — он задан шиной APB, а не моделью.

**`takt-sim/tests/conformance/conformance_sv_mmio_tests.rs`:** сверка строит
тестбенч кодом и подключала сигналы записи безусловно. Теперь читает
порождённый модуль и подключает то, что он объявил. Это **третий**
потребитель интерфейса — ADR назвал два.

**Проверка:** `SV_MMIO_TRANSLATABLE="stacker regulator"`. Прежде список состоял из
одного примера со входными портами, поэтому класс был невидим.

**Тестбенч `examples/generated/sv-mmio/tb/regulator_apb_tb.sv`** (рукописный,
как принято для APB): чтение выходного регистра до и после завершения автомата,
цикл записи по нему и проверка, что значение не изменилось, чтение адреса без
порта. Первая редакция падала: `regulator` сходится за считанные такты, и
попытка записи **до** завершения ничего не доказывала — значение менял сам
автомат. Порядок проверок переставлен, причина записана в шапке.

**README:** раздел о цели `sv-mmio` дополнен — состав интерфейса зависит от
модели, адаптер следует за ядром, цикл записи завершается штатно.

## Тест-план

### Область и цель

Проверяется **состав** порождённого интерфейса и то, что все его потребители
следуют за ним. Линт и синтез состава не различают: модуль с лишним входом
валиден (урок ADR), поэтому форма проверяется текстом, а поведение —
тестбенчем с настоящими циклами APB.

### Проверки (условие → ожидаемый результат)

| # | Проверка | Предусловие | Ожидаемый результат | Ссылка на R/A |
|---|---|---|---|---|
| T1 | Ядро без входных портов | все порты `out` | нет `reg_wdata`/`reg_wen`, `reg_rdata` на месте | R2 / A5 |
| T2 | Ядро с входным портом | есть `in` | все четыре сигнала | R3 / A5 |

## Отчёт о тестировании

### Резюме

**Пройдено; фича готова к закрытию (`ГОТОВО`).** Ядро без записываемых
регистров больше не объявляет `reg_wdata`/`reg_wen`; `regulator` даёт **0**

### Выводы и дальнейшие шаги

1. **Потребителей интерфейса оказалось три, а не два.** ADR назвал ядро и
   адаптер APB; третьим был **потактовая сверка**, строящая тестбенч кодом —
   она подключала сигналы записи безусловно и отвечала `PINNOTFOUND`. Нашёл её
   прогон, а не чтение. Урок общий: интерфейс, зависящий от модели, обязывает
   каждого потребителя **спрашивать**, а не помнить.
2. **Тестбенч поймал деталь, которую не видно в коде.** Первая редакция
   проверяла запись в выходной регистр **до** завершения автомата и падала:
   `regulator` сходится за считанные такты, и значение менял сам автомат за три
   такта цикла APB. Порядок проверок переставлен; причина записана в шапке
   тестбенча, чтобы следующий автор не «починил» его обратно.
3. **Замер кандидата уточнён:** предупреждений было **два**, а не четыре.
4. **Класс был невидим проверке** ровно потому, что список `sv-mmio` состоял из
   одного примера с удобным составом портов. Теперь их два.
5. **Исправлений (`docs/fixes/`) не потребовалось.**

## Итог (что сделано)

**Регистровый интерфейс отражает состав портов модели.** Сигналы записи
(`reg_wdata`, `reg_wen`) эмитятся только при наличии записываемого шиной
регистра — предикат `Mmio::has_writable`. Правило не новое, а достроенное:
интерфейс уже не эмитился вовсе при отсутствии адресованных портов, не хватало
различения по **направлению**.

| Что | До | После |
|---|---|---|
| `regulator` целью `sv-mmio` под `verilator -Wall` | **2** `UNUSEDSIGNAL`, ненулевой код возврата | **0** |
| Пара «ядро + APB» на `regulator` | `PINNOTFOUND` ×2 | линт и синтез проходят |
| `stacker` (ядро и адаптер) | — | байт-в-байт прежний |

**Потребителей интерфейса оказалось три, а не два.** ADR назвал ядро и
адаптер APB; третьим был **потактовая сверка** `conformance_sv_mmio_tests`,
строящая тестбенч кодом, — её нашёл прогон, а не чтение. Все трое теперь
спрашивают у ядра, что оно объявило.

**Проверка пополнен `regulator`**: прежде `SV_MMIO_TRANSLATABLE` состоял из
одного `stacker` со входными портами, и класс был невидим. Рукописный тестбенч
`regulator_apb_tb.sv` доказывает главное: цикл записи по выходному регистру
завершается штатно, а значение остаётся тем, что вычислил автомат.
