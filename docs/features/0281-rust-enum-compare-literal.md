## Краткое описание

**Цель `rust` порождает невалидный код на сравнении перечислимой переменной с
числом.** Замер при закрытии
[цель `c`: использовать объявленные константы перечисления](0167-c-enum-constants-usage.md) (2026-08-16): вход
`enum Command { Stop = 0, Go = 1 } … ref Run: c = 1;` даёт
`if self.c == 1 {`, и `rustc` отвергает это `E0308` («expected `Command`,
found integer») — присваивание при этом печатается верно (`self.c =
Command::Go`), то есть цель восстанавливает вариант **только** в одном из двух
мест. Проверка цели гоняет **только корпус**, а в корпусе такого сравнения нет —
ровно класс дефектов, доживших по той же причине. Цели `sv`
и `st` ту же запись переводят валидно (`== 1` там законно), так что предмет —
именно `rust`. Кандидат: восстанавливать вариант и в сравнении (место —
`rust_expr`/печатник условий), контроль — фикстурой, а не корпусом.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

### Context

В Takt вариант перечисления — число, и `ref Done: c = 1;` — естественная
запись. В Rust у `enum` числового представления в выражении нет.

**Замер-19** (`rustc --edition 2021` и `clippy-driver -D warnings` по
порождённому модулю; проба признана годной, снята `scripts/probe.sh`):

| Место | Печаталось | Ответ инструмента |
|---|---|---|
| присваивание `c := Go;` | `self.c = Command::Go;` | верно |
| сравнение `ref Done: c = 1;` | `if self.c == 1 {` | **`E0308`**: expected `Command`, found integer |
| **контроль** `ref Done: c = Go;` | `if self.c == Command::Go {` | верно |

Цель восстанавливала вариант **только в одном из двух** мест. Соседние цели
(`c`, `st`, `sv`) ту же запись переводят валидно — предмет именно в `rust`.

**Ровно тот класс, что и исправление**: там присваивание коэрцию `bit → bool`
делало, а сравнение — нет; здесь присваивание восстанавливает вариант, а
сравнение — нет. Два пути одной идеи расходятся молча.

**Проверка цели этого не видит по устройству:** он гоняет только корпус, а
сравнения перечисления с числом там нет ни одного.

### Decision Drivers

1. **Невалидный вывод при рапорте об успехе** — худший исход: `taktc`
   возвращает ноль, отказ приходит от чужого компилятора.
2. **Правило восстановления варианта обязано быть одно.** Два места (присваивание
   и сравнение) уже разъехались; третья копия разъедется снова.
3. **Догадка недопустима.** Значение вне набора вариантов представить нечем —
   отказ честнее подстановки «первого попавшегося».

### Considered Options

#### Option A. Оставить как есть

**Cons:** порождённый модуль не компилируется; узнаёт об этом сборка прошивки.

#### Option B. Печатать `as` числовое приведение (`self.c as u8 == 1`)

**Pros:** механически просто.

**Cons:** вводит в вывод числовую природу перечисления, которой в Rust у него
нет; `clippy` ругается на лишние приведения, а читаемость падает. И расходится
с тем, как ту же величину печатает присваивание.

#### Option C. Восстанавливать вариант — общей функцией с присваиванием

**Pros:**
- вывод валиден и читаем (`self.c == Command::Go`);
- присваивание и сравнение печатают **одно и то же** имя, потому что зовут одну
  функцию;
- значение вне набора вариантов даёт честный отказ.

**Cons:** ветвь печатника условий приходится заводить отдельно (как для
`bit`/`bool` в 0148-01) — но это ровно та же форма и то же место.

### Decision

Принимается **Option C**. Имя варианта строит
`rust_expr::enum_variant_literal(enum_name, value, scope)` — единственный
носитель; его зовут `coerce_to` (присваивание) и новая ветвь `enum_comparison`
печатника условий. Литерал распознаётся с обеих сторон (`c = 1` и `1 = c`),
формы `==` и `!=` обрабатываются одинаково.

### Consequences

#### Положительные

- Порождённый модуль компилируется и проходит `clippy -D warnings`.
- Присваивание и сравнение согласованы по построению, а не по дисциплине.

#### Отрицательные / Action items

- Форма вывода цели `rust` меняется для этой записи; корпус её не содержит,
  снимки не двигаются.
- Сравнение с именем варианта (`c = Go`) идёт другим узлом
  (`ConditionNode::EnumVariant`) и в новую ветвь не попадает — это названная
  граница, закреплённая контрольным тестом.

#### Acceptance criteria

1. `ref Done: c = 1;` печатается `self.c == Command::Go` (A1).
2. `!=` и обратный порядок операндов работают так же (A2).
3. Контроль: сравнение с именем варианта не изменилось (A3).
4. Порождённый модуль принимается `rustc` и `clippy -D warnings` (A4).
5. Значение вне набора вариантов даёт отказ с причиной (A5).
6. `./scripts/precheck.sh` зелён (A6).

восстанавливала при **сравнении**: `ref Done: c = 1;` давало `self.c == 1` и
`E0308` от `rustc` при нулевом коде возврата `taktc`. Фича сводит оба места к

## Разработка

### Задача

#### Что было

Восстановление варианта по числу жило **внутри** `coerce_to`
(`rust_expr.rs`) — то есть было доступно только присваиванию. Печатник условий
о нём не знал и печатал `self.c == 1`; `rustc` отвечал `E0308` при нулевом коде
возврата `taktc`.

#### Что сделано

1. Тело восстановления вынесено из `coerce_to` в функцию
   `rust_expr::enum_variant_literal(enum_name, value, scope)` — **единственный**
   носитель правила. `coerce_to` теперь её зовёт.
2. В печатник условий (`rust_cond.rs`) добавлена ветвь `enum_comparison` —
   по образцу `boolean_comparison` (тот же класс дефекта):
   литерал ищется с обеих сторон, формы `==` и `!=` обрабатываются одинаково,
   тип операнда берётся у `condition_type`.

**Носитель обязан быть один.** Дефект и состоял в том, что знание жило в
одном месте из двух; третья копия разъехалась бы так же молча.

**Значение вне набора вариантов** отвергается с причиной — эта ветвь
существовала и раньше, теперь она обслуживает и сравнение.

#### Проверки

```sh
cargo test --test targets rust_enum_compare   # 6 тестов, включая настоящий clippy-driver
cargo test --all-features                     # 3251 тест
./scripts/precheck.sh                         # полный гейт
```

Попутно исправлен инструмент замера: `scripts/probe.sh` падал на любой пробе
с объявленным типом — исправление [`probe.sh` падал на пробе с объявленным типом](../fixes/0301-02-probe-type-declaration.md).
Без этого замер по своду снять было нельзя.

## Итог (что сделано)

**Сравнение перечислимой переменной с числом печатается вариантом.** Цель
восстанавливала вариант при **присваивании** и не восстанавливала при
**сравнении**: `ref Done: c = 1;` давало `self.c == 1`, и `rustc` отвечал
`E0308` при нулевом коде возврата `taktc`. Ровно тот класс, что и исправление
[сравнение `bit` с литералом даёт некомпилируемый Rust](../fixes/0148-01-rust-bit-compare.md), — два пути одной идеи
разошлись молча.

**Сделано:** восстановление варианта вынесено из `coerce_to` в
`rust_expr::enum_variant_literal` — единственный носитель; печатник условий
получил ветвь `enum_comparison` по образцу `boolean_comparison`. Литерал
распознаётся с обеих сторон, `==` и `!=` — одинаково, значение вне набора
вариантов даёт честный отказ.

**Контроль** — `takt-lang/tests/targets/rust_enum_compare_tests.rs`: шесть
тестов, включая контроль (сравнение с именем варианта) и прогон настоящего
`clippy-driver -D warnings`. Проверка цели класс не видел: он гоняет только
корпус, где такого сравнения нет.

**Попутно исправлен инструмент замера** — исправление
[`probe.sh` падал на пробе с объявленным типом](../fixes/0301-02-probe-type-declaration.md): `scripts/probe.sh` падал
под `set -eu` на **любой** пробе с объявленным типом (форма `[ … ] && printf` в
теле цикла отдавала статус 1, когда совпадения нет). Без этого замер по своду снять было нельзя; в контроль добавлена недостающая отрицательная ветвь,
мутация её валит.

**Версия языка не поднята** (форма вывода цели, не язык); крейт `takt-lang`:
`0.46.1` → `0.46.2`.
