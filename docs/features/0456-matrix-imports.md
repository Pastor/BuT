# Фича: Импорты и подключаемые модели в переборе

- **Номер:** 0456
- **Статус:** ГОТОВО
- **Зависит от:** [формулы и инварианты в переборе](0454-matrix-formulas.md)
- **Tier:** 2 (перебор нашёл вход, на котором вывод целей `c` и `st` не
  собирается: определение и вызов печатались с разными префиксами)
- **Класс:** генерация
- **Связанные issue (анализ):** по запросу заказчика 2026-08-31 («добавь в
  перебор импорты и подключаемые модели»)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Матрица перебора работала на **одном** файле и потому не касалась импорта. Фича
учит генератор отдавать набор файлов и добавляет шесть видов: вызов функции из
подключённого файла (полным и выборочным импортом), тип, модель-реализацию,
попытку взять вложенную модель полным импортом и **транзитивный** импорт.
Последний вскрыл дефект.

## Документирование (правило 24)

**Не требуется:** язык не меняется. Чинится вывод двух целей.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

Импортированное объявление становится объявлением **импортёра** (правило
[общие переменные библиотечного файла в импортёре](0184-imported-shared-variables.md)): цель `c` строит из владельца имя
функции (`Probe_base_value`). Перепривязка делалась для самой функции, но
**не** для ячеек вызовов в телах перенесённых функций — а при транзитивном
импорте (`probe` → `mid` → `base`) такие вызовы есть.

### Замер (правило 30, 2026-08-31)

```text
probe.c:17:12: error: call to undeclared function 'ProbeMid_base_value'
   note: did you mean 'Probe_base_value'?
```

Определение — `Probe_base_value`, вызов — `ProbeMid_base_value`. Код возврата
`taktc` **нулевой**. У цели `st` — то же (`ProbeMid_base_value(0)`); у `rust` и
`sv` имена не квалифицируются владельцем, и класс их не задел.

### Decision

1. **Ячейка вызова перепривязывается наравне с объявлением**
   (`adopt_function_cell`): ячейка **заменяется**, а не правится на месте —
   `Rc` разделяется с другими употреблениями.
2. **Тела перенесённых функций обходятся отдельно.** К моменту обхода
   поддерева библиотеки функции из неё уже изъяты (`functions.clear()`), и
   обход их не видел — отсюда и жил дефект.
3. **Локальные имена функции при усыновлении пропускаются** — параметры **и**
   объявления тела. Их ячейки созданы при разрешении в контексте библиотеки и
   выглядят её объявлениями; без списка обход докладывал о них как о
   «неимпортированных объявлениях» (`SE-074`) и требовал импортировать то,
   чего библиотека не объявляет. Список собирает общий носитель
   `semantic::fresh::collect_locals`.

Границу пришлось уточнять **дважды**: сперва обход задел параметры (поймал
перебор), затем локальные тела (поймал существующий тест
`whole_file_import_does_not_demand_local_names` — тот самый класс, ради
которого он и заведён).

### Consequences

Вывод корпуса не меняется. Перебор — 230 случаев на цель, 28.5 с.

#### Acceptance criteria

- A1. Шесть видов импорта × формы реализации: инструменты целей принимают
      вывод либо цель отказывает **ожидаемым** кодом.
- A2. Транзитивный импорт собирается у `c` и `st`.
- A3. Мутация «не обходить тела перенесённых функций» роняет перебор.

## Анализ

### Формы и их поведение (замер-31)

| Вид | Итог |
|---|---|
| `import "helper.takt";` + вызов функции | переводят все |
| `import { twice } from "…";` | переводят все |
| тип из подключённого файла | переводят все |
| `import { Engine } from "…";` + `= Engine` | переводят все |
| `import "helper.takt";` + `= Helper` (вложенная модель) | **`SE-106`** у всех — полный импорт вносит только контейнер файла; отказ несёт подсказку «подключите выборочно» |
| транзитивный импорт | **дефект** у `c` и `st` (см. выше) |

Имя библиотеки в пробе — `helper.takt`, а модель внутри названа `Engine`:
имя файла становится именем контейнера, и совпадение имён скрыло бы разницу
между «контейнер» и «вложенная модель».

### Зависимости фичи (правило 17/19)

### Требования и проверяемые условия

- R1. A1…A3 выше.
- R2. Файлы библиотек кладутся **рядом** с пробой: путей поиска задавать не
  нужно.

### Критерии приёмки и способ проверки

`target_matrix_tests` (8 целей × 230 случаев), `root_pointer_matrix_tests`,
мутация, полный `precheck.sh` (в нём 268 потактовых сверок).

### Редакторский слой (правило 29)

**Не затронут.**

### Особенности по обратной функциональности

Модель с транзитивным импортом прежде давала невалидный вывод у двух целей;
теперь собирается. Прочее не менялось — корпус байт в байт.

### Риски и зависимости

Риск — усыновление задевает лишнее (что и случилось с параметрами). Снят
контрольными видами: пять форм импорта, которые обязаны переводиться, стоят в
той же матрице рядом с транзитивным.

## Разработка

  функций, список имён параметров в контексте усыновления;
- `takt-lang/tests/targets/matrix_probes.rs` — `ProbeFile`/`library_files`:
  проба стала набором файлов;
- оба контроля матрицы кладут библиотеки рядом с пробой.

## Итог

Перебор впервые вышел за пределы одного файла — и сразу нашёл класс, который
жил ровно там, куда не заглядывал ни один тест: определение функции
усыновлялось импортёром, а вызов внутри перенесённого тела оставался при
прежнем владельце. Попутно выяснилось, что усыновление принимает параметр
функции за объявление библиотеки, — обе правки закрыты одним обходом.
