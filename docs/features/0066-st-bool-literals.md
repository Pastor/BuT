# Фича: Булевы литералы в телах цели `st` печатаются числом

- **Номер:** 0066
- **Статус:** ГОТОВО (см. «Итог (что сделано)» ниже)
- **Зависит от:** **нет** (проверено аналитиком 2026-07-17 — см. [анализ](0066-st-bool-literals.md#анализ)). Опоры **закрыты**: [генератор генерации в Structured Text (IEC 61131-3)](0041-st-backend.md), [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md). **Очерёдность: после [изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md)** — она заводит потактовую сверку `st` ([изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md#разработка)), которой сегодня **нет вовсе**; до неё «поведение не изменилось» доказывается только проверкой и ревью диффа.
- **Приоритет / Tier:** **Tier 3** — компилируемость **не страдает** (проба: `iec2c` принимает и `0`, и `FALSE`), поведение верно. Страдает читаемость вывода — на цели, чей вывод **читают люди** (ПЛК отлаживают по тексту ST).
- **Крейт:** `grammar` (`generator/st/`: `st_expr.rs`, `st_stmt.rs`)
- **Связанные issue (анализ):** новая фича (перевод кандидата из `FEATURES.md`)

## Краткое описание

Тела цели `st` печатают `cmd_fork := 0;` вместо `cmd_fork := FALSE;`. MatIEC
принимает `0`/`1` для `BOOL` (проверено пробой — **вопреки ожиданию плана
0041-04**), поэтому это не дефект компилируемости.

Беда в другом: **объявления** тот же генератор печатает канонично
(`flag : BOOL := TRUE;`), то есть вывод **сам с собой не согласован**.

Лечение: печатник выражений должен знать **целевой тип присваивания** — сейчас он
его не получает (`st_expr::print_expression` типа назначения не видит).

Выявлено при закрытой [генератор генерации в Structured Text (IEC 61131-3)](0041-st-backend.md).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0066-st-bool-literals.md); повторяет приём целей [генератор генерации в SystemVerilog](0045-sv-backend.md#архитектура-adr) и [генератор генерации в Rust](0050-rust-backend.md#архитектура-adr) (`coerce_to` по целевому типу)

### Context

Кандидат заявлял: тела цели `st` печатают `cmd_fork := 0;` вместо
`cmd_fork := FALSE;`, тогда как **объявления** тот же генератор печатает канонично
(`busy : BOOL := FALSE;`) — «вывод сам с собой не согласован». Причина:
`st_expr::print_expression(expr, model)` **целевого типа не видит**.

**Всё подтверждено пробами. И найдено следствие крупнее заявленного.**

#### Проба 1: заявка кандидата верна дословно

`examples/generated/st/stacker.st`: тела — `cmd_fork := 0;` (строки 168, 172),
`cmd_fork := 1;` (177); объявления — `busy : BOOL := FALSE;` (409). Сигнатура
`print_expression(expr: &ExpressionNode, model: &ModelNode)` — **целевого типа
нет**.

#### Проба 2: MatIEC принимает `0`/`1` намеренно, а не по недосмотру

| Вход (для `b : BOOL`) | `iec2c` |
|---|---|
| `b := FALSE;` | принял |
| `b := 0;` | **принял** |
| `b := 1;` | **принял** |
| `b := 2;` | **ОТВЕРГ**: `Incompatible data types for ':=' operation.` |
| `IF b = 1 THEN …` | принял |

То есть `0`/`1` для `BOOL` — **поддержаны намеренно** (иначе `2` прошло бы тоже).
**Это не дефект компилируемости** — кандидат прав.

#### Проба 3 (крупнее заявки): та же причина теряет имя варианта перечисления

| Цель | Присваивание `command := Stop` | Константы перечисления эмитятся? |
|---|---|---|
| **`rust`** | `(*command) = Command::Stop;` | да |
| **`sv`** | `elevator_mini_command_next = COMMAND_STOP;` | да |
| **`st`** | **`command := 2;`** | **ДА** — `Command_Stop : USINT := 2;` рядом |
| `c` | `main->command = 2;` | **нет** (греп по `.h` пуст) |

**Цель `st` — единственная, чей вывод противоречит сам себе:** она **объявляет**
константы `Command_Up`/`Command_Down`/`Command_Stop` и тут же **их не
использует**. У `c` вывод хотя бы внутренне согласован (восстанавливать нечем —
констант нет; это отдельная находка, вынесена кандидатом).

**Следствие для `enum` тяжелее, чем для `BOOL`.** `cmd_fork := 0` при
`cmd_fork : BOOL` читается: булев ноль очевиден. А `command := 2` **не читается
вовсе** — чтобы узнать, что это `Stop`, надо листать таблицу констант. Отладка на
ПЛК ведётся **по тексту ST**, и это прямая потеря.

### Decision Drivers

1. **Вывод обязан быть согласован сам с собой.** Объявлять `Command_Stop` и
   печатать `2` — значит выдавать читателю загадку, ответ на которую компилятор
   знал.
2. **Приём уже принят и работает в двух целях.** `rust` и `sv` восстанавливают
   вариант по целевому типу (`coerce_to`) — «в трёх местах: присваивание, сброс
   переменной, блок `enter`».
3. **Не расширять сигнатуры без нужды.** `print_expression` зовётся отовсюду;
   протаскивать целевой тип через все узлы — цена, несоизмеримая с задачей.
4. **Компилируемость не страдает ни в одном варианте** (проба 2) → это работа над
   **качеством**, и рисковать поведением ради неё нельзя.

### Considered Options

#### Option A. `coerce_to(ty, expr)` в трёх местах — как в `rust` и `sv`

Не менять `print_expression`. Завести `coerce_to` (целевой тип + узел → текст) и
звать **на присваивании, сбросе переменной и в блоке `enter`** — ровно там же, где
это делают две другие цели.

**Pros:**
- **Повторяет уже принятое и проверенное решение** (драйвер 2) — не изобретение, а
  выравнивание третьей цели по двум.
- Точка решения **одна и узкая**; `print_expression` не трогается (драйвер 3).
- Лечит **оба** симптома (`BOOL` и `enum`) одним механизмом.
- Легко доказать неизменность поведения: меняется **текст литерала**, а не
  вычисление (драйвер 4).

**Cons:**
- Три места надо не забыть; забудешь одно — вывод снова несогласован (**в этом
  месте**). Смягчение: контроль на каждое (T4–T6).

#### Option B. Протащить целевой тип в `print_expression`

**Pros:** литерал знает тип **везде**, не только в трёх местах.

**Cons:**
- Меняет сигнатуру, зовущуюся из всех узлов (драйвер 3) — цена несоизмерима.
- Расходится с `rust`/`sv` (драйвер 2): третья цель получила бы **свой**
  механизм для той же задачи — ровно то, за что 0060 вынуждена сводить четыре
  копии расчёта перечисления в одну.

#### Option C. Чинить только `BOOL` (буквальный объём кандидата)

**Pros:** минимальная правка.

**Cons:**
- Оставляет **более тяжёлый** симптом (`command := 2` нечитаемо, драйвер 1) при
  том, что причина и лечение — **те же**. Пришлось бы протаскивать целевой тип
  дважды.

#### Option D. Не делать

**Pros:** ноль работы; компилируемость не страдает (проба 2).

**Cons:** вывод остаётся противоречащим сам себе (драйвер 1); `st` остаётся
единственной целью, объявляющей константы и не использующей их.

### Decision

Принимается **Option A**, с **расширенным против кандидата объёмом**: лечатся
**оба** симптома — `BOOL` **и** перечисления.

Расширение обосновано пробой 3: причина одна (`print_expression` не видит целевого
типа), лечение одно (`coerce_to`), а половина, которой не было в кандидате
(`enum`), — **более ценная**: `command := 2` нечитаемо, тогда как `cmd_fork := 0`
всего лишь неканонично.

**Нормативные правила:**

1. `coerce_to(ty, expr)` — **единственная** точка решения; `print_expression`
   **не меняется**.
2. Зовётся в **трёх** местах — присваивание, сброс переменной, блок `enter` —
   **тех же**, что у `rust` и `sv`.
3. `TypeNode::Bool` + `Number(0|1)` → `FALSE`/`TRUE`.
4. `TypeNode::Enum` + `Number(n)` → **имя константы** (`Command_Stop`), если
   вариант с таким значением есть; иначе — число (модель вправе присвоить
   произвольное число перечислимой переменной; догадываться нельзя).
5. **Поведение не меняется** — меняется только **текст литерала**.
6. Язык **не меняется** → версия не растёт (правило 22).

### Consequences

#### Положительные

- Вывод `st` перестаёт противоречить сам себе; объявленные константы наконец
  используются.
- Отладка на ПЛК (по тексту ST) перестаёт требовать сверки с таблицей констант.
- Три цели из четырёх начинают восстанавливать вариант **одинаковым** приёмом.

#### Отрицательные / Action items

- **A-1. Вывод `st` изменится** — `cmd_fork := 0` → `FALSE`, `command := 2` →
  `Command_Stop`. Дифф **ожидаем** и обязан быть объяснимым построчно (детерминизм
  — закрытая [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr)). Правило 11 не нарушено:
  наружный контракт (поведение, порты, адреса) неизменен.
- **A-2. Сверки для `st` не существует** — то есть «поведение не изменилось»
  (правило 5) доказывать нечем, кроме проверки `iec2c` и ревью диффа. Это долг фичи; его отдаёт [изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md#разработка).
  **0066 разумно вести после 0065**: тогда правка получит поведенческого
  контроля. Формально не зависимость — риск низкий (меняется текст литерала, не
  вычисление).
- **A-3. Правило 4 — не догадываться.** Если значения-варианта нет, печатать
  число: перечислимой переменной можно присвоить произвольное число, и подменять
  его именем «похожего» варианта — тихая ложь.
- **A-4. Цель `c` не эмитит констант перечисления вовсе** (проба 3) — поэтому там
  `main->command = 2` безальтернативно. Вынесено **кандидатом**; в объём 0066 не
  входит (другая цель, другой объём).

#### Acceptance criteria

1. **A1.** `cmd_fork := 0;` → **`cmd_fork := FALSE;`**; `:= 1` → `TRUE`.
2. **A2.** `command := 2;` → **`command := Command_Stop;`** (константа объявлена
   тут же — `Command_Stop : USINT := 2;`).
3. **A3.** Все **три** места (присваивание, сброс, `enter`) — покрыты.
4. **A4.** Значение без варианта → печатается **числом** (правило 4).
5. **A5.** Проверка `iec2c` по **всему** корпусу — зелёный.
6. **A6.** Вывод целей `c`/`c-hal`/`rust`/`sv`/`plantuml` — **побайтово прежний**.
7. **A7.** Дифф `st` объяснён построчно: **только** литералы.
8. **A8.** Язык не изменился; версия не поднята.

## Анализ

### Цель и контекст

Кандидат: тела `st` печатают `cmd_fork := 0;` вместо `FALSE`, тогда как
объявления — канонично (`busy : BOOL := FALSE;`); вывод сам с собой не
согласован. Причина названа верно: `print_expression` целевого типа не видит.

**Проработка заявку подтвердила и нашла следствие крупнее.** ADR принял
**Option A** с **расширенным объёмом**: лечатся `BOOL` **и** перечисления.

### Замер (пробы 2026-07-17)

**1. Заявка кандидата — верна дословно.** `stacker.st`: тела — `cmd_fork := 0;`
(168, 172), `cmd_fork := 1;` (177); объявления — `busy : BOOL := FALSE;` (409).
`print_expression(expr, model)` — целевого типа нет.

**2. MatIEC принимает `0`/`1` намеренно:** `b := FALSE` ✔, `b := 0` ✔, `b := 1` ✔,
**`b := 2` ✘** (`Incompatible data types for ':=' operation`), `IF b = 1` ✔.
Отвергая `2`, но принимая `0`/`1`, MatIEC поддерживает булев ноль/единицу
**сознательно**. **Компилируемость не страдает** — кандидат прав.

**3. Крупнее заявки — теряется имя варианта перечисления:**

| Цель | `command := Stop` | Константы эмитятся? |
|---|---|---|
| `rust` | `(*command) = Command::Stop;` | да |
| `sv` | `elevator_mini_command_next = COMMAND_STOP;` | да |
| **`st`** | **`command := 2;`** | **ДА** — `Command_Stop : USINT := 2;` рядом |
| `c` | `main->command = 2;` | **нет** (греп по `.h` пуст) |

**`st` — единственная цель, чей вывод противоречит сам себе:** объявляет
константы и не использует их. У `c` вывод внутренне согласован (восстанавливать
нечем) — это **другая** находка, вынесена кандидатом.

**`enum` тяжелее `BOOL`:** `cmd_fork := 0` при `BOOL` читается; `command := 2`
**не читается вовсе**. Отладка на ПЛК идёт **по тексту ST**.

### Зависимости фичи (правило 17/19)

- **Зависит от:** **нет**. Опоры **закрыты**: [генератор генерации в Structured Text (IEC 61131-3)](0041-st-backend.md),
  [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md) (дифф читаем).
- **Очерёдность: после [изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md).**
  Формально не зависимость (файлы разные: 0065 — `st_func.rs`/имена, 0066 —
  `st_expr.rs`/`st_stmt.rs`), но 0065 заводит **потактовую сверку `st`**
  ([изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md#разработка)), которой сегодня **нет
  вовсе**. После неё у 0066 появляется поведенческий контроль; до неё «поведение не
  изменилось» доказывается только проверкой и ревью диффа.
- **Пересечения:** [расчёт ширины перечисления — вынести в общий слой](0060-enum-width-shared-layer.md) правит
  `st_type.rs` — не конфликтует.
- **Влияние на порядок:** никого не блокирует.

### Приоритет (Tier) — обоснование

**Tier 3.**

- **Компилируемость не страдает** (проба 2) — дефекта нет.
- Поведение верно; страдает **читаемость вывода**, то есть эксплуатация.
- Против Tier 2: ничего не сломано, обхода не требуется.
- Но и не «косметика»: `command := 2` — потеря информации, которой компилятор
  располагал, на цели, чей вывод **читают люди** (ПЛК отлаживают по ST).

### Требования и проверяемые условия

- **R1. `coerce_to(ty, expr)` — единственная точка решения**; `print_expression`
  **не меняется**.
- **R2. Три места** — присваивание, сброс переменной, блок `enter` — **те же**,
  что у `rust`/`sv`.
- **R3. `Bool` + `Number(0|1)`** → `FALSE`/`TRUE`.
- **R4. `Enum` + `Number(n)`** → имя константы, **если вариант с таким значением
  есть**; иначе — число.
- **R5. Поведение не меняется** — меняется только текст литерала.
- **R6. Прочие цели не задеты**; язык не меняется → версия не растёт.

### Особенности по обратной функциональности

**Наружный контракт не меняется** (правило 11): поведение, порты, адреса,
публичный интерфейс POU — прежние. Меняется **текст литералов** в телах.

**Вывод `st` изменится** — это ожидаемо и объяснимо построчно (детерминизм —
закрытая 0048). Прочие цели, симулятор, LSP, форматтер — **не задеты** (A6).
Язык не меняется → версия не растёт (правило 22).

### Риски и зависимости

- **R-1. Доказывать неизменность поведения нечем.** **Сверки для `st` не
  существует** — проверка `iec2c` доказывает лишь компилируемость,
  а ровно на этой цели уже дожил Tier 1
  ([цель `st` молча склеивает одноимённые `fn` разных моделей](../fixes/0041-01-st-fn-dedup-silent.md)). Снижение: вести **после**
  0065-03; риск сам по себе низкий — меняется текст литерала, не вычисление.
- **R-2. Забыть одно из трёх мест.** Тогда вывод останется несогласованным
  **точечно** — то есть дефект замаскируется. Снижение: R2 + контроль на каждое
  место (A3).
- **R-3. Догадаться там, где нельзя.** Перечислимой переменной можно присвоить
  произвольное число; подменять его именем «похожего» варианта — тихая ложь.
  Снижение: R4 — нет варианта, печатаем число; контроль A4.
- **R-4. Соблазн протащить тип в `print_expression`** (Option B). Дал бы третьей
  цели **свой** механизм для задачи, уже решённой в двух других, — ровно то, за
  что 0060 вынуждена сводить четыре копии расчёта перечисления в одну.

### Побочная находка проработки (вне объёма, заведена кандидатом)

**Цель `c` не эмитит констант перечисления вовсе** (греп по порождённому `.h` —
пусто), поэтому `main->command = 2` там безальтернативно: восстанавливать нечем.
В отличие от `st`, вывод `c` внутренне **согласован** — он просто беднее. Смежно
с [эталонный `SRC` в `lib.rs` порождает C с 11 ошибками `cc`](0075-lib-src-reference-model.md) и
[дефекты генератора C по структурам](0080-c-struct-defects.md).

## Разработка

### Задача

#### Что было

`st_expr::print_expression(expr, model)` **целевого типа не видит**, поэтому тела
печатают литерал как есть:

| Что | Тело `st` | Объявление `st` | `rust` | `sv` |
|---|---|---|---|---|
| `BOOL` | `cmd_fork := 0;` | `busy : BOOL := FALSE;` | — | — |
| `enum` | **`command := 2;`** | `Command_Stop : USINT := 2;` | `Command::Stop` | `COMMAND_STOP` |

**Цель `st` — единственная, чей вывод противоречит сам себе:** объявляет константы
и тут же их не использует. (У `c` восстанавливать нечем — констант она не эмитит
вовсе; это отдельный кандидат.)

#### Что сделано

Завести **`coerce_to(ty, expr)`** — по образцу целей `rust` и `sv`, где приём уже
принят и работает:

1. **`print_expression` Не меняется** (правило 1 ADR): она зовётся из всех узлов,
   и протаскивать целевой тип через каждый — цена, несоизмеримая с задачей.
2. **Звать в трёх местах** — присваивание, сброс переменной, блок `enter` —
   **тех же**, что у `rust`/`sv` (правило 2).
3. `Bool` + `Number(0|1)` → `FALSE`/`TRUE` (правило 3).
4. `Enum` + `Number(n)` → **имя константы** (`Command_Stop`), **если вариант с
   таким значением есть**; иначе — **число** (правило 4).
   **Догадываться нельзя:** перечислимой переменной можно присвоить произвольное
   число, и подменять его именем «похожего» варианта — **тихая ложь**.
5. **Поведение не меняется** — меняется только текст литерала.

#### Проверки

- **T1/T2/A1:** `:= 0`/`:= 1` для `BOOL` → `FALSE`/`TRUE`.
- **T3/A2:** `command := 2` → `command := Command_Stop`.
- **T4/A4 + T13 (мутация):** значение без варианта → число; «подбор ближайшего»
  обязан валить T4.
- **T5–T7/A3:** покрыты **все три** места; забытое место замаскирует дефект
  точечно.
- **T12:** сигнатура `print_expression` прежняя.
- **T8/A5:** проверка `iec2c` зелёный. Он был зелёным и **до** правки (`b := 0`
  принимается) — **контролем не является**.
- **T9/A7:** поведение прежнее. **Сверки для `st` не существует** — её заводит
  [изоляция пространства имён цели `st` (POU и переменные)](0065-st-namespace-isolation.md#разработка); **вести 0066 после 0065**.
- **T10/A6:** прочие цели побайтово прежние.
- **T11:** дифф `st` — только литералы.

Проверяется **текст литералов** в телах цели `st`. Язык не меняется →
примеров/контрпримеров синтаксиса правило 16 не требует.

**неизменность поведения** (T9).

## Итог проработки (2026-07-17)

**Заявка кандидата подтверждена дословно** — и найдено следствие **крупнее
заявленного**, из-за чего объём расширен.

**1. Заявка верна.** `stacker.st`: тела — `cmd_fork := 0;` (168, 172),
`cmd_fork := 1;` (177); объявления — `busy : BOOL := FALSE;` (409).
`print_expression(expr, model)` — целевого типа **нет**.

**2. MatIEC принимает `0`/`1` намеренно, а не по недосмотру:**

| Вход (`b : BOOL`) | `iec2c` |
|---|---|
| `b := FALSE` / `b := 0` / `b := 1` | **принял** |
| **`b := 2`** | **ОТВЕРГ**: `Incompatible data types for ':=' operation` |

Отвергая `2`, но принимая `0`/`1`, MatIEC поддерживает булев ноль/единицу
**сознательно**. Компилируемость **не страдает** — кандидат прав.

**3. Та же причина теряет имя варианта перечисления — и это тяжелее:**

| Цель | `command := Stop` | Константы эмитятся? |
|---|---|---|
| `rust` | `(*command) = Command::Stop;` | да |
| `sv` | `elevator_mini_command_next = COMMAND_STOP;` | да |
| **`st`** | **`command := 2;`** | **ДА** — `Command_Stop : USINT := 2;` **рядом** |
| `c` | `main->command = 2;` | **нет** (греп пуст) |

**`st` — единственная цель, чей вывод противоречит сам себе:** объявляет
константы и тут же их не использует. `cmd_fork := 0` при `BOOL` **читается**;
`command := 2` **не читается вовсе** — чтобы узнать, что это `Stop`, надо листать
таблицу констант. Отладка на ПЛК ведётся **по тексту ST**.

**Принято** ([ADR](0066-st-bool-literals.md#архитектура-adr), Option A) с **расширенным
объёмом**: `coerce_to(ty, expr)` — по образцу целей `rust` и `sv`, где приём уже
принят; зовётся в **трёх** местах (присваивание, сброс, `enter`) — **тех же**;
`print_expression` **не меняется**. Лечатся **оба** симптома: `BOOL` → `FALSE`/
`TRUE`, `enum` → имя константы. Расширение обосновано тем, что причина одна,
лечение одно, а половина, которой не было в кандидате, — **более ценная**.
Отклонены: протаскивание типа в `print_expression` (дало бы третьей цели **свой**
механизм для задачи, решённой в двух других — ровно то, за что 0060 сводит четыре
копии в одну), только `BOOL`, статус-кво.

**Правило «не догадываться»:** значение без соответствующего варианта
печатается **числом** — перечислимой переменной можно присвоить произвольное
число, и подменять его именем «похожего» варианта было бы **тихой ложью**.

**Побочная находка (кандидат):** цель `c` **не эмитит констант перечисления
вовсе**, поэтому `main->command = 2` там безальтернативно; её вывод, в отличие от
`st`, внутренне **согласован** — просто беднее.

Язык не меняется → версия не растёт (правило 22).

## Итог (что сделано)

**Закрыта** (`ГОТОВО`, 2026-07-18). Тела цели `st` печатают литералы `BOOL` и
перечислений **по целевому типу** — вывод перестал противоречить сам себе.

- **Крейт `grammar`** (`generator/st/`): в `st_expr.rs` добавлен
  `coerce_to(value, target, model)` (по образцу целей `rust`/`sv`): `BOOL`/`bit` +
  `0`/`1` → `FALSE`/`TRUE`; перечисление + число → **имя константы**
  (`Command_Stop`, совпадает с объявлением `st_decl::enum_constants`); значение без
  варианта → **число** (правило 4 — не догадываться). `print_expression`
  **не менялась** (правило 1 ADR). Вызывается в `st_stmt.rs` в двух узлах,
  покрывающих **три места** ADR: `Assign` в `StatementNode::Expression` (тела,
  включая `enter`/`exit`/`always` — они идут через тот же `print_statement`) и
  инициализатор локального объявления.
- **Дифф `st` — только литералы (A7):** `cmd_fork := 0` → `FALSE`,
  `command := 2` → `Command_Stop`; `state := 2` (синтетический регистр, не Lam-enum)
  **остался числом**. Прочие цели (`c`/`c-hal`/`rust`/`sv`/`plantuml`) — побайтово
  прежние (A6).
- **Проверки и сверка:** `iec2c` принимает весь корпус (A5); потактовая
  `conformance_st_tests` (заведена 0065) вердикта **не изменила** — правка меняет
  текст литерала, не вычисление. Тесты: `coerce_to` — 3 юнит-теста в `st_stmt.rs`
  (bool → FALSE/TRUE, enum → имя, T13: значение без варианта → число). 1988 тестов
  зелёные, clippy/fmt чисты.

Объём **расширен против кандидата** (решение ADR): лечится не только `BOOL`, но и
перечисления — причина одна, лечение одно, а `command := 2` нечитаемо, тогда как
`cmd_fork := 0` лишь неканонично. Язык не менялся → версия не росла (правило 22).
