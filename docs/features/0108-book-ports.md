## Краткое описание

Описывает **порты и адреса**: направления `in`/`out`/`inout`; объявление адреса и карту адресов; бит адреса (`0xADDR:бит`); связь портов с окружением и целями `c-hal`/`st-at`/`sv-mmio`.

## Итог (что сделано)

Наполнен раздел `book/src/08-ports-addresses/index.typ` описанием языка (свод —
язык не меняется, Tier 3; ADR/анализ не требовались):

- **Направления** `in`/`out`/`inout` (вход только читается, выход только пишется,
  двунаправленный — и то и другое); порт используется как переменная с учётом
  направления.
- **Адрес порта** — три способа: **инлайн** (`:= 0xADDR`), **оператор** `address
  Имя = 0xADDR;`, **внешняя карта** (`--address-map`, формат близкий к `.ld`).
  Приоритет: инлайн < оператор < внешняя карта.
- **Бит адреса** `0xADDR:бит` — диапазон [0, 63]; битовые порты делят один адрес.
- **Связь с целями**: адрес потребляют `c-hal`/`st-at`/`sv-mmio`; цель `c`
  обращается к портам через HAL-колбэки и адрес не использует. Выгрузка
  разрешённой карты — `taktc address-map --emit map|json`.
- **Частые ошибки**: `SE-048`, `SE-049`, `SE-052`, `SE-060`.
- Пример `book/src/08-ports-addresses/examples/ports.takt` — панель управления
  вентилятором: три способа задания адреса, два битовых порта на одном регистре
  (`fan` бит 0, `alarm` бит 5). **Компилируется** `taktc` (цели `c` и `c-hal`,
  EXIT 0, без предупреждений) и **проверен симуляцией** (правило «Пример раздела: функциональный, из практики, с разбором-выносками»): кнопка →
  `On`/`fan=1`, перегрев (temp 90 ≥ MAX_T 80) → `alarm=1`, отпускание кнопки →
  `Off`/всё сброшено. Карта адресов выгружается `address-map --emit map`.

**Живая проверка:** пример компилируется и симулируется; `./scripts/precheck.sh`
зелёный. Язык не менялся → версия языка та же.
