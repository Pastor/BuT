## Краткое описание

**Сборка документа переписывает committed SVG при смене версии graphviz.**
Замечено при работе над [левая часть присваивания — вызов функции: семантика принимает, цель c печатает невалидный C](0249-assign-to-call-place.md)
(2026-08-18): `make -C book build` перезаписал три файла
`book/src/18-showcase/images/*.svg`, изменив в них только строку
`Generated by graphviz version 15.1.0 → 15.1.1`. Сборка входит в предкоммит, то есть любой прогон на машине с другой версией graphviz пачкает
рабочее дерево посторонним диффом. Кандидат: не хранить порождённые SVG в
репозитории либо вычищать из них строку версии.

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по правилу 17.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-20
- **Authors:** Архитектор + Аналитик
- **Related issues:** [Фича](0265-book-svg-graphviz-version.md); [фича](0240-book-typst.md) (сборка документа — шаг предкоммита), [фича](0301-probe-checklist.md) (каталог бинарников — один носитель), [фича](0251-cargo-target-dir.md) (сборка переехала в `target/precheck`)

### Context

`book/scripts/render_verify_graphs.sh` порождает три SVG раздела «Практический
пример», и они **хранятся в репозитории**. `dot` вписывает в вывод свою версию:

```
<!-- Generated by graphviz version 15.1.0 (20260618.0150) -->
```

Замер (2026-08-18, при работе над 0249): `make -C book build` переписал три
файла, изменив в них ровно эту строку (`15.1.0 → 15.1.1`). Сборка документа
входит в предкоммит — значит любой прогон на машине с другим `graphviz` пачкает
рабочее дерево посторонним диффом.

**Вторая беда, найденная здесь же (кандидат блока 2):** скрипт искал
компилятор в `$ROOT/target/debug/taktc`, тогда как сборка идёт в
`target/precheck`. Регенерация молча не запускалась — печаталось
«регенерация не удалась, использую закоммиченные SVG», а **код возврата
оставался нулевым**. След этой поломки лежал в репозитории: файл
`lift-kripke.dot` был **пуст** (перенаправление создало его до неудачного
вызова).

### Decision Drivers

1. **Проверка не вправе пачкать дерево.** Предкоммит, оставляющий `git status`
   грязным, приучает игнорировать его вывод.
2. **Версия инструмента — не содержание диаграммы.** Она не влияет ни на
   картинку, ни на документ.
3. **Молчаливая неудача хуже отказа:** «использую закоммиченные SVG» с кодом 0
   — это отчёт об успехе там, где работа не сделана.

### Considered Options

#### Option A. Не хранить SVG в репозитории

**Pros:** расхождению неоткуда взяться.
**Cons:** сборка документа станет требовать `graphviz` и шрифт ГОСТ у каждого,
кто собирает PDF, — против принципа 0240 («внешний инструмент один»).

#### Option B. Вычищать строку версии при генерации

**Pros:** SVG остаются в репозитории и стабильны; сборка документа по-прежнему
требует только `typst`.
**Cons:** в файле остаётся комментарий-заглушка вместо версии — но она и не
нужна.

#### Option C. Приводить SVG к каноническому виду отдельным скриптом

**Cons:** второй инструмент о том же предмете; расхождение с генератором —
вопрос времени.

### Decision

Принимается **Option B**, и вместе с ним чинится найденное:

1. `render_verify_graphs.sh` вычищает строку версии (`sed` после `flatten`),
   заменяя её стабильным комментарием.
2. Каталог бинарников берётся у **единственного носителя**
   `scripts/target-dir.sh`  — своей копии пути в скрипте больше нет.
3. Предкоммит проверяет **committed** файлы: в `book/src/*/images/*.svg` нет
   строки `graphviz version`, а `.dot`-исходники **непусты** (пустой файл — след
   молча не работавшей регенерации).
4. Комментарий в предкоммите исправлен: он объяснял выбор цели `pdf` вместо
   `build` в том числе «переписыванием SVG» — эта причина снята.

### Consequences

#### Положительные

- Прогон на машине с другим `graphviz` дерево не пачкает.
- Регенерация диаграмм снова работает; пустой `lift-kripke.dot` наполнен.
- Молчаливая неудача теперь ловится проверкой — по пустому исходнику.

#### Отрицательные / Action items

- Регенерация по-прежнему требует `graphviz` и шрифт ГОСТ — но она **не** входит
  в предкоммит (цель `pdf`, а не `build`).
- В SVG вместо версии стоит комментарий-заглушка: при отладке `dot` версию
  придётся смотреть иначе.

#### Acceptance criteria

1. Перегенерированные SVG не содержат `graphviz version`.
2. Повторный прогон скрипта дерева не меняет.
3. Скрипт берёт каталог бинарников у `target-dir.sh`.
4. Предкоммит ловит committed SVG с версией и пустой `.dot`.
5. `./scripts/precheck.sh` — код 0.

## Анализ

### Цель и контекст

Сделать так, чтобы прогон предкоммита не пачкал дерево. ADR принял Option B:
вычищать версию при генерации.

### Замер (снят 2026-08-20, правило 30)

Кандидат подтверждён: `dot` вписывает в SVG строку
`<!-- Generated by graphviz version 15.1.0 (20260618.0150) -->`, и при смене
версии она даёт дифф в трёх файлах.

**Находка сверх кандидата — молчаливая поломка регенерации.** Скрипт искал
`taktc` в `$ROOT/target/debug`, а сборка идёт в `target/precheck`:

```
book/scripts/render_verify_graphs.sh: line 33: …/target/debug/taktc: No such file or directory
  ⚠ регенерация не удалась — использую закоммиченные SVG.
```

**Код возврата при этом нулевой.** След поломки лежал в репозитории: файл
`book/src/18-showcase/images/lift-kripke.dot` был **пуст** — перенаправление
создало его до неудачного вызова, и пустышка попала в коммит.

Это ровно класс фичи («каталог бинарников — один носитель»), и запись о
нём висела кандидатом блока 2 `FEATURES.md`; она снимается закрытием 0265
(правило 28).

### Зависимости фичи (правило 17/19)

- **Влияние на порядок:** снимает кандидата про третью копию знания о каталоге.

### Требования и проверяемые условия

- **R1.** Порождённые SVG не содержат `graphviz version`.
- **R2.** Повторная регенерация дерева не меняет.

  регенерации.
- **R6.** Комментарий предкоммита о выборе цели `pdf` приведён к правде.

### Риски и зависимости

- **Риск: смена `dot` изменит геометрию, а не только версию.** **Снижение:**
  тогда дифф будет содержательным, и его увидит человек; проверка ловит именно
  **служебную** строку, которая содержания не несёт.
- **Риск: регенерация снова сломается молча.** **Снижение:** пустой `.dot`
  теперь роняет предкоммит — то есть след поломки стал сигналом.

## Разработка

### Задача

#### Что сделано

**`book/scripts/render_verify_graphs.sh`:**

1. строка версии graphviz вычищается сразу при генерации —
   `sed 's/^<!-- Generated by graphviz version .*$/…(версия вычищена: фича 0265)…/'`
   после `svg_flatten_text.py`;
2. путь к `taktc` берётся у **единственного носителя**
   `scripts/target-dir.sh`. Прежняя копия (`target/debug`)
   сломалась в день фичи и приводила к молчаливой неудаче с нулевым кодом
   возврата.

**`scripts/precheck.sh`:**

- после сборки документа проверяются **committed** файлы: в
  `book/src/*/images/*.svg` нет строки `graphviz version`, а `.dot`-исходники
  непусты;
- комментарий о выборе цели `pdf` вместо `build` исправлен: причина
  «регенерация переписывает SVG» снята этой фичей, осталась настоящая — шрифт
  ГОСТ и собранный `taktc` есть не у всех.

**Пустышка наполнена:** `lift-kripke.dot` лежал в репозитории **пустым** — след
той самой молчаливой поломки.

#### Проверка

```sh
book/scripts/render_verify_graphs.sh   # дважды: дерево не меняется
grep -rn 'graphviz version' book/src/*/images/*.svg   # пусто
```

## Итог (что сделано)

  печаталось «использую закоммиченные SVG» при **нулевом** коде возврата. След

  единственного носителя `scripts/target-dir.sh`, и одноимённый

- **Предкоммит проверяет committed файлы:** в SVG нет строки версии, а
