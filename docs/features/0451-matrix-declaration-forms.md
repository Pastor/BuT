# Фича: Формы объявлений в переборе — массивы, структуры, перечисления

- **Номер:** 0451
- **Статус:** ГОТОВО
- **Зависит от:** [сплошной перебор форм по всем целям](0450-target-matrix-sweep.md)
- **Tier:** 1 (перебор нашёл **молчаливое расхождение с эталоном**: начальное
  значение составного порта терялось, а вывод при этом валиден у всех целей)
- **Класс:** генерация
- **Связанные issue (анализ):** по запросу заказчика 2026-08-31 («добавь в
  перебор формы объявлений — массивы, структуры, перечисления»)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Матрица перебора ([сплошной контроль признака нужды в указателе на корень](0449-c-needs-matrix-guard.md),
[сплошной перебор форм по всем целям](0450-target-matrix-sweep.md)) знала одну форму объявления — скаляр `u8`.
Фича добавляет третью ось: **массив, структура, перечисление** — и чинит два
дефекта, которые эта ось вскрыла.

## Документирование

**Не требуется:** язык не меняется. Чинится поведение порождённого кода —
оно приводится к тому, что уже описано (начальное значение порта).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-08-31
- **Authors:** архитектор

### Context

Тип объявления меняет и путь печати, и границы целей: массив и структура в
порту **разворачиваются по листам**, перечисление в порту не
размещают `rust` и `st-at`, а инициализатор массива значением другой переменной
не выражает `c`. Матрица со скаляром всего этого не касалась.

### Decision

1. Ось `Kind` в общем генераторе матрицы (`matrix_probes`): `Scalar`, `Array`,
   `Struct`, `Enum`. Перебирается она **только у тех видов обращения**, которые
   касаются объявленного значения (`varies_by_kind`) — у `none`,
   `clock_after` и `extern_call` объявленного значения нет, и четыре
   одинаковых прогона были бы просто платой за время. Итог: 100 случаев вместо
   40.
2. Таблица законных границ расширена и стала общей для обоих контрольных тестов: набор
   0449 спрашивает её же, а не дублирует.
3. Два найденных дефекта чинятся здесь (см. «Анализ»).

### Consequences

Вывод корпуса не меняется. Перебор по восьми целям стоит 12.9 с (было 5.9 с).

#### Acceptance criteria

- A1. 100 случаев × 8 целей: инструмент цели принимает вывод либо цель
  отказывает **названным** кодом.
- A2. Начальное значение составного порта доезжает до прошивки и совпадает с
  эталоном (потактовая сверка).
- A3. Мутация «не раздавать значение листьям» роняет сверку.

## Анализ

### Замер

Перебор с новой осью дал два дефекта.

**1. Начальное значение составного порта терялось молча.** Разворот порта по
листам (`condition::port_split`) ставил листу `init: ExpressionNode::None`:

| | эталон | цель `c` (и `rust`, `st`, `sv`) |
|---|---|---|
| `out bus: [u8;3] := {4, 5, 6}` | `bus = [4,5,6]` | **ни одной записи** |
| `out pair: Pair := {7, 8}` | `pair = {lo=7, hi=8}` | **ни одной записи** |

Вывод при этом валиден: `cc` его принимает, код возврата `taktc` нулевой.
Класс невидим проверкам целиком — он ловится **только** сверкой значений.

**2. Вариант перечисления не вычислялся в инициализаторе порта.**
`out mode: Mode := Work;` → `SE-094` «имя 'Work' в области видимости не
объявлено», хотя `var m: Mode := Work;` законно: константный вычислитель
(`const_eval::resolve_name`) знал только константы и не спрашивал перечисления.

### Что сделано

- `semantic/condition/port_split.rs` — лист получает **свою часть** агрегата:
  у `Leaf` появился путь **позиций** (индекс элемента, номер поля в порядке
  объявления), и `leaf_initializer` берёт по нему часть
  значения. Позиции ведутся параллельно пути намеренно: по самому пути позицию
  поля не восстановить — тип структуры лежит в модели.
- `semantic/const_eval/mod.rs` — `resolve_name` спрашивает вариант
  перечисления **после** переменных (объявленная переменная затеняет
  одноимённый вариант — тот же порядок, что у разрешения выражений).

молча** — теперь оно совпадает с эталоном.

## Итог

Третья ось окупилась сразу: она нашла класс, невидимый ни одному инструменту
целей, — начальное значение составного порта пропадало по дороге, и «валидный
вывод» означал прошивку, которая стартует с нулями там, где модель обещает
значения. Второй дефект (вариант перечисления в инициализаторе порта) снял
запрет, которого в языке нет.
