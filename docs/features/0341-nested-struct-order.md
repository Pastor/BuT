# Фича: Вложенная структура — порядок объявления и тип поля

- **Номер:** 0341
- **Статус:** ГОТОВО
- **Зависит от:** 0293, 0340 (закрыты; проставлено 2026-08-20)
- **Связанные issue (анализ):** найдено пробой «вложенная структура и массив
  структур»

## Краткое описание

`struct Line { a: Point, b: Point }` не переводила **ни одна** цель: три
печатали структуры по алфавиту (а `Line` стоит раньше `Point`), четвёртая
считала доступ к полю логическим. Всё — при нулевом коде возврата `taktc`.

## Документирование

**Не требуется** — подтверждено: правится представление у четырёх целей.

## Архитектура (ADR)

- **Статус:** Accepted
- **Дата:** 2026-08-20
- **Фича:** [../features/0341-nested-struct-order.md](0341-nested-struct-order.md)

### Контекст

Замер-20 на `struct Point { x: u8, y: u8 }` и
`struct Line { a: Point, b: Point }`:

| Потребитель | Ответ |
|---|---|
| эталон | верно |
| **`c`, `c-hal`** | `cc`: «unknown type name 'Point'» |
| **`st`, `st-at`** | `iec2c`: «invalid specification in structure element declaration» ×2 |
| **`sv`, `sv-mmio`** | verilator: «Reference to 'point_t' before declaration» ×2 |
| **`rust`** | `RS-011`: «значение 7 не представимо в bool» |

Всё — при **нулевом** коде возврата `taktc`.

Причин две.

1. **Порядок объявления.** Структуры хранятся в `BTreeMap` и печатались **по
   алфавиту**; `Line` стоит раньше `Point`, а вмещающая структура обязана быть
   объявлена **после** вложенной — одинаково в C, IEC 61131-3 и SystemVerilog.
2. **Тип поля у цели `rust`.** `expression_type` считал **любой** доступ через
   точку логическим, не различая разряд `x.7` и поле `s.field`.

### Решение

- Порядок вынесен в общий носитель `generator/struct_order.rs`: обход в
  глубину по полям-структурам, зависимость печатается первой. Порядок
  детерминирован: обход идёт по алфавитному `BTreeMap`, а
  зависимости лишь поднимаются выше.
- Алфавитная сортировка **на выходе** у цели `st` снята: она разрушала
  собранный порядок.
- У цели `rust` `expression_type` различает `Member::Number` (разряд → `Bool`)
  и `Member::Identifier` (поле → `None`, тип неизвестен). `None` честнее
  выдумки: объявление структуры лежит в модели, а сюда она не передаётся, и
  приведение просто не применяется.

### Границы

- **Цикл структур** (`A` содержит `B`, `B` содержит `A`) бессмыслен — размер
  бесконечен, — но носитель его переживает: участник печатается один раз.
  Диагностика цикла — вопрос семантики, а не печати; вынесено кандидатом.
- **Тип поля у `rust` не восстанавливается**, а объявляется неизвестным: этого
  довольно, чтобы печать пошла обычным путём.

### Отвергнутые варианты

1. **Сортировать структуры в каждой цели.** Три копии правила разошлись бы —
   ровно это уже случилось с местом записи агрегата (0340).
2. **Передавать модель в `expression_type`.** Сигнатуру зовут из 30 мест;
   `None` решает задачу без этой правки.

### Последствия

- Вывод корпуса не изменился (вложенных структур в `examples/` нет).
- Тест `struct_member_access_is_refused_loudly` (0148) **закреплял дефект** —
  утверждал, что поля структур цель `rust` не переводит, хотя переводит с 0293.
  Переписан.

## Анализ

### Цель и контекст

Найдено пробой «вложенная структура и массив структур» — соседним входом после
фичи.

### Зависимости фичи

- **Зависит от:** 0293 (структуры в целях), 0340 (общий носитель для агрегата —
  образец). Закрыты.
- **Влияние на порядок разработки:** заводит кандидата (диагностика цикла
  структур) и кандидата о неполноте списка зарезервированных имён IEC,
  найденного попутно.

### Требования и проверяемые условия

- **R1.** `c`, `st`, `sv`: зависимость объявлена раньше вмещающей.
- **R2.** Вывод принимается `cc -Werror`, `iec2c`, `verilator -Wall`.
- **R3.** `rust`: поле структуры печатается доступом, вывод собирается.
- **R4.** Разряд `x.7` остаётся логическим (контроль).
- **R5.** Вывод корпуса не изменился.

### Разбор

#### Ловушка замера

Первая проба назвала переменную `ln`, и `iec2c` отвергал файл **по другой
причине**: `LN` — стандартная функция IEC (натуральный логарифм). Посторонняя
причина держалась до тех пор, пока её не сняли переименованием.
Попутно выяснилось, что список зарезервированных имён цели `st` **неполон** —
это вынесено кандидатом с готовым замером.

#### Почему `None`, а не тип поля

`expression_type` не получает модель, а объявление структуры лежит там. Ответ
«тип неизвестен» приводит к печати обычным путём — то есть к верному выводу.

### Риски

- **Порядок стал зависеть от обхода.** Детерминированность держит `BTreeMap`;
  контролем стоит проверка двух прогонов.

### Почему тесты именно такие

Порядок проверяется **позицией в тексте** (что раньше — `Point` или `Line`), а
валидность — прогоном настоящих инструментов: линт видит порядок, а тест
позиций объясняет, **почему** он такой.

### Что показал прогон

1. **Одна запись — два разных корня.** Три цели ошибались порядком, четвёртая
   типом; общего лечения не существовало, и объединяет их только вход.
2. **Проба солгала дважды.** Сперва имя `ln` дало посторонний отказ `iec2c`,
   затем ложный `RS-011` цели `rust` выглядел как «структуры не поддержаны».
   Оба раза спасло снятие причин по одной.
3. **Тест закреплял дефект второй раз за сессию** (первый): текст
   теста утверждал невозможность того, что уже работало.

## Итог (что сделано)

**Порядок объявления стал общим носителем; доступ к полю перестал быть bool.**

- **Правило одно на три цели:** вложенная структура объявляется раньше
  вмещающей. Носитель `generator/struct_order.rs`, обход в глубину, порядок
  детерминирован (обход по `BTreeMap`).
- **Алфавитная сортировка на выходе у `st` снята:** она разрушала собранный
  порядок.
- **У цели `rust` `expression_type` различает разряд и поле:** `x.7` → `Bool`,
  `s.field` → `None` (тип неизвестен, приведение не применяется). Прежде обе
  формы давали `bool`, и `seg.a.x := 7;` отвергался как «значение 7 не
  представимо в bool».
- **Тест закреплял дефект:** он утверждал, что поля структур цель `rust`
  не переводит, — а она переводит с фичи; отказ приходил от неверного типа.
  Переписан.
- **Ловушка замера:** первая проба назвала переменную `ln`, и `iec2c`
  отвергал файл **по другой причине** — `LN` есть стандартная функция IEC.
  Посторонняя причина снята переименованием, а попутно выяснилось,
  что список зарезервированных имён цели `st` **неполон** — вынесено кандидатом
  с готовым замером.
- **Цикл структур** носитель переживает (печатает участника один раз), но не
  диагностирует: это вопрос семантики — вынесено кандидатом.
