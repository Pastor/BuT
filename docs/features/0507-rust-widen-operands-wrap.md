# Фича: Цель `rust` — операнды расширяемой арифметики: приведение по нужде и обёртка

- **Номер:** 0507
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 1
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «примеры `book/` не проверяются инструментами целей» (замер-03 — класс найден его прогоном)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Арифметика, чьи операнды шире или уже приёмника, печатается целью `rust` через
общий печатник арифметики: операнды несут узел приведения, а операцию печатает
тот, кто знает правило переполнения. Прежде ветвь «арифметика в типе приёмника»
(0360) печатала операцию **сама** и теряла разом два правила — обёртку правила (`wrapping_add` вырождался в `+`: отладочная сборка прошивки **паникует**
там, где эталон переносит) и «приведение по нужде» (операнд, уже имеющий тип
приёмника, получал `x as u16` при `x: u16` — `clippy::unnecessary_cast`, то есть
отказ проверки самой цели). Код возврата `taktc` в обоих случаях **нулевой**.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Документирование (правило 24)

**Не требуется.** Язык не меняется: та же запись принимается и исполняется как
прежде, речь о форме порождённого Rust. Диагностик не заводится. Правило

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh`, вход `total := total + step;` при
`total: u16`, `step: u8`):

| Потребитель | Ответ |
|---|---|
| эталон | `3, 6, 9` — считает |
| `c`, `sv`, `sv-mmio`, `plantuml` | инструменты принимают |
| `rust` | `rustc` принял, **`clippy` ОТВЕРГ**: `casting to the same type is unnecessary (u16 -> u16)` |
| `st` | `ST-014` (отказ цели, к предмету отношения не имеет) |

Порождённое было: `self.total = (self.total as u16) + (self.step as u16);`.

Второй слой вскрылся сразу за первым: сняв лишнее приведение, получаем
`self.total = self.total + (self.step as u16);` — то есть `+` вместо
`wrapping_add`. Контроль: та же запись при **одинаковых** типах операндов
печатается `self.total.wrapping_add(self.step)`. Значит правило теряла
именно ветвь приёмника, и теряла **молча**: `65400 + 200` при `u16` эталон
переносит в `64`, а отладочная сборка прошивки падает
(`attempt to add with overflow`).

Класс найден прогоном инструментов целей по примерам `book/` (кандидат):
`book/src/04-models-states/examples/feeder.takt` — обычное накопление
`total := total + portion;` — печатал Rust, который отвергает `clippy`.

### Decision Drivers

- Правило переполнения (0127) и правило «приведение по нужде» (0263, 0361,
  0374, 0495) уже имеют **носителей**; ветвь приёмника обходила обоих, то есть
  дефект был в дублировании печати, а не в самих правилах.
- Ошибка громкая для чужого инструмента и **немая** для `taktc`: проверка цели
  корпуса её не видит — в `examples/` нет накопления с расширением.

### Considered Options

1. **Приведение выражать узлом, операцию отдать общему печатнику** (принято).
   Ветвь строит тот же арифметический узел с операндами `Cast(операнд, тип
   приёмника)` и печатает его обычным путём: обёртку ставит `wrapping_or_plain`,
   лишнее приведение снимает `rust_type::same_printed_type`. Новых знаний не
   заводится ни одного.
2. **Оставить строковую печать, добавив в неё оба правила.** Отвергнуто: это
   третья копия правила переполнения и вторая — правила «по нужде»; расхождение
   копий и есть исходный дефект.
3. **Печатать приведение только нуждающемуся операнду, операцию — как прежде.**
   Отвергнуто: чинит `clippy`, но оставляет потерю обёртки — то есть
   расхождение значений с эталоном, худший из двух слоёв.

### Decision

Ветвь «арифметика в типе приёмника» (`rust_coerce::coerce_to`) не печатает
операцию: она строит тот же узел с приведёнными операндами и передаёт его
`print_expression`.

### Consequences

- Беззнаковое накопление с расширением переносится так же, как у эталона.
- Лишнего `as` в выводе нет — `clippy -D warnings` принимает.
- Знаковый приёмник обёртки не получает (`(s as i16) + (u as i16)`) — правило сохранено в обе стороны.
- Снимки `examples/generated/` не меняются: корпус этой формы не содержит, чем
  и объясняется молчание проверки цели.

#### Acceptance criteria

1. Проба `scripts/probe.sh`: `rustc` и `clippy` принимают вывод.
2. Потактовая сверка эталон ↔ `rust` на входе с **переполнением**.
3. Контроль: знаковая арифметика печатается без обёртки; операнды одного типа
   приведений не получают (набор 0360 не изменил ожиданий по `st`, `sv`, `c`).
4. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

`coerce_to` — место, где известен тип приёмника (0335). Ветвь арифметики
заведена фичей: она приводит **операнды**, а не результат, иначе счёт шёл
бы в узком типе. Печать операции она делала строкой `({l} {op} {r})`, минуя
`wrapping_or_plain` — и комментарий рядом утверждал обратное («обёртку ставит
печатник арифметики»), то есть обещание кода разошлось с кодом.

### Замер (правило 30, 2026-09-03)

Таблица — в разделе «Архитектура (ADR) → Context». Пробы:
`scratchpad/probe0507.takt` (накопление `u16 += u8`), входы набора 0360
(`u8 + u8 → u16`, `i8 + u8 → i16`, контроль одинаковых типов).

Соседние классы, найденные тем же прогоном примеров `book/` и в объём **не**
входящие (заведены кандидатами):

- `rust`: сравнение поля с вариантом перечисления даёт `E0308`/`E0433`
  (`cache`, `dual_core`, `machine`, `pipeline`);
- `rust`: пустая ветвь `else` — `clippy::needless_else`;
- `st`: пустая ветвь `ELSE`, объявление переменной и условие `IF` отвергаются
  `iec2c` на тех же четырёх примерах, а `functions.takt` роняет `iec2c`
  на `VAR_INPUT`.

### Зависимости фичи (правило 17/19)

Зависимостей нет: правка внутри одной ветви печатника цели `rust`.

### Требования и проверяемые условия

| № | Требование |
|---|---|
| Т1 | Операнд, уже имеющий тип приёмника, приведения не получает |

| Т5 | Цели `c`, `st`, `sv` не затронуты; снимки корпуса не меняются |

### Критерии приёмки и способ проверки

Критерии — в ADR. Способ: `scripts/probe.sh`, набор форм

`takt-sim/tests/conformance/conformance_rust_widen_wrap_tests.rs`,
`precheck.sh`.

### Редакторский слой (правило 29)

**Не требуется:** лексика, синтаксис и диагностики не затронуты — меняется
только форма порождённого Rust.

### Особенности по обратной функциональности

Обратная совместимость полная: правка касается вывода, который либо не
принимался проверкой цели, либо расходился с эталоном значением.

### Риски и зависимости

- **Риск:** узел `Cast` над операндом изменит печать там, где приведение
  масштабирующее (`q(m, n)`). Снят охраной ветви: она срабатывает только когда
  оба операнда и приёмник — целые (`operands_need_cast`).

## Разработка

### Задача: операцию печатает печатник арифметики

#### Что было

`rust_coerce.rs`, ветвь `(Integer, Add|Subtract|Multiply|Divide|Modulo)`:
операция печаталась строкой, оба операнда получали `as <тип приёмника>`
безусловно.

#### Что сделано

Ветвь строит тот же узел с операндами `Cast(операнд, приёмник)`
(`cast_operands`) и зовёт `print_expression`. Обёртку ставит
`wrapping_or_plain`, лишнее приведение снимает `same_printed_type` — оба
носителя уже существовали.

#### Проверки

`mixed_arith_tests` (8 тестов), сверка `conformance_rust_widen_wrap_tests`,
проба `probe.sh`.

### Задача: контроля предмета

- `takt-lang/tests/targets/mixed_arith_tests.rs` — вход `KEEP` (левый операнд
  уже типа приёмника) и три проверки: приведение по нужде, обёртка у
  беззнакового, её отсутствие у знакового. Ожидание прежнего теста
  `widening_casts_operands` **исправлено**: оно закрепляло дефектную форму
  (`as u16) + (`).
- `takt-sim/tests/data/eval/conformance_widen_wrap.takt` + набор
  `conformance_rust_widen_wrap_tests.rs` — сверка значений на переполнении;
  драйвер собирается **без** `-O`, где проверки переполнения включены.

## Тест-план

| Проверка | Ожидание |
|---|---|
| `total: u16 += step: u8` | `self.total.wrapping_add(self.step as u16)` |
| лишнее приведение | в выводе нет `self.total as u16` |
| `u8 + u8 → u16` | `(self.a as u16).wrapping_add(self.b as u16)` |
| `i8 + u8 → i16` | `(self.s as i16) + (self.u as i16)` — без обёртки |
| операнды одного типа с приёмником | вывод прежний (контрпример 0360) |
| `clippy -D warnings` на трёх входах | принимает |
| потактовая сверка эталон ↔ `rust` | `65200, 65400, 64, 264` |
| цели `c`, `st`, `sv` | ожидания набора 0360 неизменны |
| пример `book/…/feeder.takt` | `rustc` и `clippy` принимают |

## Отчёт о тестировании (правило 20)

### Резюме

`./scripts/precheck.sh` — зелёный. Проба: восемь целей отвечают как прежде,
`clippy` принял вывод `rust`. Снимки `examples/generated/` не изменились.

### Фактические результаты по проверкам

Все проверки пройдены. Пример `book/src/04-models-states/examples/feeder.takt`,
на котором класс найден, теперь печатает
`shared.total.wrapping_add(self.portion as u16)` — `rustc` и `clippy` его
принимают.

Мутационная проверка:

| Мутация | Ответ набора |
|---|---|
| прежняя строковая печать `({l} as T {op} {r} as T)` | сверка падает **предметом** («attempt to add with overflow»), плюс 5 тестов формы |
| приведение обоим операндам при сохранённой обёртке | `operand_of_receiver_type_keeps_no_cast` и прогон `clippy` |

Первая мутация показывает, зачем сверка идёт на **переполнении**: на разгоне
(без переноса) обе формы дают одинаковые числа, и дефект был бы невидим.

### Найденные дефекты

Дефектов правки нет. Прогон примеров `book/` инструментами целей вскрыл соседние
классы (перечислены в разделе «Анализ → Замер») — заведены кандидатами.

### Выводы и дальнейшие шаги

Ветвь приёмника перестала быть третьим местом, где живёт правило переполнения.
Кандидат «примеры `book/` не проверяются инструментами целей» **актуализирован**:
замер-03 назвал поимённо, какие примеры и каким инструментом
отвергаются.

## Итог (что сделано)

Ветвь «арифметика в типе приёмника» цели `rust` больше не печатает операцию
сама: операнды несут узел приведения, а печать идёт общим путём. Тем самым
восстановлены два правила, которые ветвь обходила, — обёртка беззнакового
переполнения (эталон переносит, прошивка паниковала) и «приведение по нужде»
(лишнее `as` отвергал `clippy -D warnings`, то есть проверка самой цели).

Контроля: набор форм 0360 (его ожидание, закреплявшее дефектную форму,
исправлено) и новая потактовая сверка на входе с переполнением.
