# Фича: `SE-132` — прерывание вне цикла

- **Номер:** 0530
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 1
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат «`break` вне цикла: эталон и цель `c`
  расходятся молча» (заведён фичей [разборы диагностик прогона в справочнике](0529-book-sim-diagnostics.md), снят
  этой)

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32).

## Краткое описание

`break` и `continue` вне цикла компилятор принимал молча, и дальше потребители
расходились: эталон прерывал тело и **проверял переходы**, а цель `c` печатала
`break;` внутри ветви `case` — управление выходило из `switch` мимо присваивания
состояния, и автомат не уходил из состояния никогда. Запись отвергается новой
диагностикой `SE-132`. Версия языка поднята до **0.17.0**.

## Документирование (правило 24)

Язык меняется: сужается множество принимаемых программ. Раздел «Управляющие
конструкции» говорит, что вне цикла запись отвергается, и называет код; в
приложении заведён разбор `SE-132`. Разбор `SIM-024` снят: его вход теперь
отсекает семантика, и код остаётся защитной ветвью эталона.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** аналитик, разработчик

### Context

Замер-03  на записи

```takt
start Run {
    always { x := x + 1; break; }
    ref Next: x >= 1;
}
```

| Потребитель | Что делает |
|---|---|
| компилятор | принимает, код возврата нулевой, диагностики нет |
| эталон | прерывает тело и проверяет переходы: на первом шаге уже в `Next` |
| цель `c` | `break;` внутри `case` → выход из `switch` мимо `model->state = …`: автомат остаётся в `Run` **навсегда** |

Это Tier 1 по шкале проекта: инструменты расходятся молча, и увидеть разницу
можно только потактовой сверкой — которой на этой записи не было, потому что
запись считалась бессмысленной, а не ошибочной.

### Considered Options

1. **Задать поведение** («прервать тело блока») и сверить потактово.
   Отвергнуто: это новая конструкция управления, которую обязаны одинаково
   исполнить восемь целей, а в C для неё нужен не `break`, а флаг или `goto`.
   Язык такого не обещает.
2. **Чинить печать цели `c`** (например, `goto` в конец ветви). Отвергнуто:
   лечит симптом у одной цели, оставляя запись без смысла у остальных.
3. **Отвергать семантикой** (принято): документ уже обещал ошибку, а эталон
   давал `SIM-024` внутри функции — проверка просто стояла не там.

### Decision

Признак «внутри цикла» ведёт потоковый счётчик
(`takt-lang/src/semantic/loop_context.rs`), страж которого живёт ровно на
построении тела `loop`/`while`/`for`. Прерывание без стража — отказ `SE-132` с
позицией из АСД.

### Consequences

Обратная совместимость: программа с `break` вне цикла перестаёт приниматься.
Обоснование (правило 11) — она не имела определённого смысла: два потребителя
исполняли её по-разному, и любой выбор поведения сломал бы один из них. В
корпусе и примерах таких записей не было (прогон предкоммита).

#### Acceptance criteria

- `break`/`continue` вне цикла отвергаются с позицией;
- внутри цикла на любой глубине — принимаются;
- версия языка поднята, три источника согласованы.

## Анализ

### Замер (правило 30, 2026-09-03)

Прогон до правки: `taktc compile -t c` — успех; эталон — переход в `Next` на
первом шаге; порождённый C — `break;` перед `if (model->x >= 1) { model->state
= BR2_NEXT; }`, то есть присваивание недостижимо.

После правки: `model.takt:4:26: [SE-132] 'break' вне цикла…`; запись внутри
цикла (в том числе внутри `if` внутри `for`) принимается.

### Требования и проверяемые условия

- П1: `break` в теле блока состояния отвергается;
- П2: `continue` в теле функции отвергается;
- П3: `break` внутри `loop` принимается;
- П4: `continue` внутри `if` внутри `for` принимается;
- П5: после закрытия цикла признак снят (страж не «залипает»);
- П6: версия языка поднята и помечена тегом.

### Редакторский слой (правило 29)

**Не требуется:** лексика и синтаксис не менялись — `break`/`continue` те же
токены и те же правила грамматики. Изменилась семантика (новый отказ), и она
доезжает до редактора обычным путём: LSP берёт диагностики того же построения
дерева.

### Особенности по обратной функциональности

Множество принимаемых программ **сужается** — см. «Consequences». Версия языка
поднята до 0.17.0 (правило 22), тег ставится на коммит подъёма.

### Риски и зависимости

Риск: страж потоковый, и «залипший» счётчик сделал бы отказ невозможным. Снят
проверкой П5 и разрушением стража по `Drop` — ранний возврат по `?` счётчик не
оставляет поднятым.

## Разработка

### Задача — признак и отказ

#### Что сделано
`semantic/loop_context.rs`: потоковый счётчик, страж `LoopGuard`, конструктор
отказа `SE-132` (текст называет **слово автора** — `break` либо `continue`).
`semantic/statement/mod.rs`: страж на построении тел `loop` и `for`, проверка в
ветвях прерывания.

### Задача — тесты

#### Что сделано
`takt-lang/tests/semantic/loop_control_tests.rs` — пять проверок (B1…B5),
включая контроль «после цикла признак снят» и два контроля законных записей.
Поправлены два прежних теста, строивших `continue` вне цикла как заглушку.

### Задача — документ и реестр

#### Что сделано
Реестр диагностик (`SE-132` с замером в описании), сводная таблица и разбор в
приложении, глава «Управляющие конструкции» (обещание кода приведено к факту:
было `SIM-024`), снятие разбора `SIM-024`. Версия языка 0.16.0 → 0.17.0 в трёх
источниках.

### Найденные дефекты
Предмет фичи и есть дефект. Побочно: разбор `SIM-024` в приложении перестал

### Выводы и дальнейшие шаги
Класс закрыт отказом, а не поведением. Аналогичные «принимается молча, а
потребители расходятся» записи стоит искать тем же приёмом: сверкой эталона с
целью на конструкции, которую никто не считал осмысленной.

## Итог (что сделано)

`break` и `continue` вне цикла отвергаются диагностикой `SE-132` с позицией:
прежде запись принималась молча, эталон прерывал тело и проверял переходы, а
цель `c` теряла присваивание состояния — автомат не уходил из состояния никогда.
Признак ведёт потоковый страж на построении тел циклов; пять тестов держат обе
стороны правила. Версия языка поднята до 0.17.0.
