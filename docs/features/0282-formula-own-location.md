## Краткое описание

**У формулы нет собственной позиции, поэтому два `invariant` неразличимы в
диагностике.** Замер при закрытии
[предупреждения генераторов возвращаются вызывающему, а не печатаются из библиотеки](0168-generator-warnings-return.md) (2026-08-16): реестр
мест объявления формул (`semantic/formula/sites.rs`) кладёт в `FormulaSite::loc`
позицию **вместилища** — модели либо состояния, — а не самой формулы, потому
что у `Formula` позиции в дереве нет вовсе. Наблюдаемо: файл с двумя
`invariant` даёт две диагностики `ST-022` с **одинаковой** координатой (`1:1`
обе), и автор не знает, о какой из формул речь. Док-строка поля обещала
«позицию объявления» — утверждение было неверным и исправлено при 0168, но
**причина осталась**. Смежно: дедупликация `diagnostics::normalize`
сравнивает `(loc, код, текст)`, то есть при первой же попытке пропустить
целевые предупреждения через неё две одинаковые записи схлопнутся в одну —
ровно та потеря, от которой фича контролировала счётом. Кандидат: завести у
формулы собственный `loc` (место — построение `Formula` из АСД).

> Фича заведена **из бэклога кандидатов пакетным переводом** (решение заказчика
> 2026-08-18: «перевести всех кандидатов в фичи без проработки, решить, делать
> или нет, позже»). Стадии 2 и 3 **не пройдены**: приоритет, зависимости и
> объём не оценивались. Далее — жизненный цикл по своду.

### Context

Реестр мест объявления формул (`semantic/formula/sites.rs`) клал в
`FormulaSite::loc` позицию **вместилища** — модели либо состояния, — потому что
своей позиции у `Formula` в дереве не было вовсе.

**Замер-19** (`taktc compile -t st` на файле с двумя `invariant`):

```
model.takt:1:1: Предупреждение [ST-022]: …
model.takt:1:1: Предупреждение [ST-022]: …
```

Две записи с **одинаковой** координатой: автор не знает, о какой из формул речь.

**Смежная опасность, и она серьёзнее неудобства.** Дедупликация
`diagnostics::normalize` сравнивает `(позиция, код, текст)`. Пока координата у
обеих формул одна, два предупреждения с одинаковым текстом схлопываются в одно —
ровно та потеря, от которой фича контролировала **счётом**. То есть отсутствие
позиции было не только неинформативностью, но и заряженной ловушкой.

Док-строка поля прежде обещала «позицию объявления»; при 0168 обещание
исправили на честное описание, но **причина осталась**.

### Decision Drivers

1. **Диагностика обязана различать элементы**, о которых говорит.
2. **Дедупликация по позиции** делает совпадение координат потерей записи, а не
   косметикой.
3. **Позиция есть в АСД** — у `invariant` и у встроенной формулы; теряется она
   на построении семантического узла.

### Considered Options

#### Option A. Оставить позицию вместилища

**Cons:** две формулы неразличимы; `normalize` схлопывает одинаковые тексты.

#### Option B. Различать формулы по тексту диагностики

**Cons:** лечит симптом: координата остаётся ложной, а `normalize` по-прежнему
сравнивает позиции. И текст диагностики цели — не место для идентификаторов.

#### Option C. Завести у формулы собственную позицию

**Pros:**
- координата указывает на строку объявления формулы;
- дедупликация перестаёт быть ловушкой;
- реестр мест продолжает работать: позиция вместилища остаётся **запасным
  ходом** для формул, построенных вне разбора.

**Cons:** меняется вариант `Formula::Guard` — 19 мест в двух крейтах; правка
механическая, каждое указывает компилятор.

### Decision

Принимается **Option C**: `Formula::Guard(ConditionNode, Option<String>,
Location)`.

1. Позиция берётся у АСД при построении: у `invariant` — позиция объявления, у
   встроенной формулы — позиция аннотации.
2. Реестр мест предпочитает **свою** позицию формулы; позиция вместилища
   остаётся запасным ходом (`condition_to_formula` строит формулу без исходного
   текста — у неё позиции нет).
3. `PartialEq for Formula` позицию **игнорирует** — по тому же доводу, что и
   `PartialEq for Extend` (0056): иначе две записи одной формулы стали бы
   разными узлами.

### Consequences

#### Положительные

- Два `invariant` дают два предупреждения с разными координатами.
- `normalize` больше не схлопывает их в одно.

#### Отрицательные / Action items

- **`Formula::LTL` позиции не получила:** у неё своя строгость (`SE-056` —
  предупреждение) и свой потребитель — верификатор, который координату не
  печатает. Граница названа; понадобится — вводится тем же приёмом.
- Вариант перечисления стал трёхместным: новый потребитель обязан его разобрать
  (компилятор скажет).

#### Acceptance criteria

1. Два `invariant` дают координаты своих строк (A1).
2. Встроенная формула состояния несёт свою позицию (A2).
3. Две диагностики с одинаковым текстом переживают `normalize` (A3).
4. Формула, построенная вне разбора, берёт позицию вместилища (A4, контроль).
5. `./scripts/precheck.sh` зелён (A5).

## Разработка

### Задача

#### Что было

`Formula::Guard(условие, имя)` позиции не имел. Реестр мест
(`semantic/formula/sites.rs`) клал в `FormulaSite::loc` координату **вместилища**
— модели либо состояния. Два `invariant` давали два `ST-022` с одинаковой
координатой `1:1`.

#### Что сделано

1. **Третье поле — позиция:** `Formula::Guard(ConditionNode, Option<String>,
   Location)`. Берётся у АСД при построении дерева: у `invariant` — позиция
   объявления, у встроенной формулы — позиция аннотации.
2. **Реестр мест предпочитает свою позицию**; координата вместилища осталась
   запасным ходом — `condition_to_formula` строит формулу без исходного текста.
3. **`PartialEq` позицию игнорирует** — довод 0056: иначе две записи одной
   формулы стали бы разными узлами.

Правка затронула 19 мест в двух крейтах; каждое указал компилятор (`E0023`).

**Дедупликация была заряженной ловушкой:** `diagnostics::normalize` сравнивает
`(позиция, код, текст)`, и при одинаковой координате два предупреждения с
одинаковым текстом схлопывались бы в одно — ровно та потеря, от которой 0235
контролировала счётом. Теперь это проверяется прямо (тест T3).

## Итог (что сделано)

**У формулы есть собственная позиция.** Прежде её не было, и реестр мест
(`semantic/formula/sites.rs`) подставлял координату **вместилища**: два
`invariant` давали два предупреждения `ST-022` с одинаковой координатой `1:1` —

которой [цели st и sv теряют охранную формулу](0235-guard-formula-in-st-sv.md) контролировала **счётом**, то
есть косвенно. Теперь проверка прямая (тест прогоняет `normalize`).

**Сделано:** `Formula::Guard(ConditionNode, Option<String>, Location)`; позиция
берётся у АСД при построении — у `invariant` позиция объявления, у встроенной

иначе две записи одной формулы стали бы разными узлами.
