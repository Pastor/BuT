## Итог (что сделано)

Наполнен раздел `book/src/12-verification/index.typ` описанием языка (правило 24 —
язык не меняется, Tier 3; ADR/анализ не требовались). Раздел **языковой** —
описывает конструкции и семантику, без команд/вывода инструмента и графов (те — в
прикладных разделах 16/17, исключение правила 24):

- **Инварианты** `invariant Name = cond;` — свойство безопасности, проверяется на
  каждом такте.
- **Темпоральные свойства (LTL)** `: [LTL] φ;` — операторы `G`/`F`/`X`/`U`, атомы
  (имя состояния / предикат), комбинирование логикой; `G (S -> F T)` = живость.
- **Область формулы** — уровня модели (от старта) vs в теле состояния
  (`: [LTL] φ;` в `S` = `G (S -> φ)`).
- **Что означает результат** — проверка над управляющим графом: «держится»
  надёжно, «нарушено» может быть ложным по данным (без деталей механизма).
- **Частые ошибки** (правило 26): `SE-055` (LTL проверяет verify, не compile),
  `SE-056` (неизвестный атом).
- Пример `airlock.takt` — шлюз-тамбур с инвариантом `Interlock` (двери не открыты
  разом, держится по построению). **Компилируется** (0 предупреждений) и **проверен
  симуляцией** (правило 27д): цикл `Sealed→OuterOpen→Transfer→InnerOpen→Sealed`,
  инвариант держится. `: [LTL]` показан сниппетом в прозе (в компилируемой модели
  его нет — иначе `compile` даёт информационный `SE-055`).

**Живая проверка:** пример компилируется и симулируется; `./scripts/precheck.sh`
зелёный; сборка PDF (`make -C book build`) чистая. Язык не менялся → версия языка
та же.
