# Фича: Цель `c`: двунаправленный порт даёт дубль перечислителя

- **Номер:** 0421
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** новая фича (найдена пробой 2026-08-23)

## Стадии жизненного цикла

Все стадии — разделы этой карточки.

## Краткое описание

Двунаправленный порт (`inout`) попадает в **оба** перечисления цели `c` —
входных и выходных портов, — а перечислители в C делят одну область видимости.
Имена совпадали, и вывод не компилировался при нулевом коде возврата `taktc`.

## Документирование

Не требуется: язык не меняется, `inout` был законен и прежде.

- **Status:** Accepted
- **Date:** 2026-08-23

### Context

**Замер-23** (`scripts/probe.sh` на `inout line: u8 at 0x200;` с
чтением и записью в теле):

| Потребитель | Ответ |
|---|---|
| эталон | исполняет: `line` = 1, 3, 6 |
| `st`, `st-at`, `rust`, `plantuml` | переводят, инструменты принимают |
| `sv`, `sv-mmio` | `SV-006` — двунаправленного порта у цели нет |
| **`c`, `c-hal`** | **код возврата 0**, `cc` отвергает: `redefinition of enumerator 'INOUT_PORT_PORT_LINE'` |

Заголовок содержал:

```c
typedef enum { INOUT_PORT_PORT_LINE = 0, } InoutPort_In_NumericPort;
typedef enum { INOUT_PORT_PORT_LINE = 0, INOUT_PORT_PORT_PROBE = 1, } InoutPort_Out_NumericPort;
```

Корпус класс не покрывает: `inout` встречается только в
`examples/language/declarations.takt`, а проверки целей смотрят **верхний
уровень** (0403) — примеры языка туда не входят.

### Decision Drivers

- Имена портов **видны пользователю** (сигнатура HAL-колбэка): смена формы у
  однонаправленных портов была бы ломающей без нужды.
- Ошибка громкая (`cc` отвергает), но приходит от **чужого** инструмента при
  рапорте об успехе.

### Considered Options

1. **Сегмент стороны у всех портов** (`_IN`/`_OUT`). Отвергнут: ломает имена
   колбэков у всех существующих моделей ради одного случая.
2. **Сегмент только у двунаправленного порта** (принято): у однонаправленных
   имя прежнее, вывод корпуса не меняется.
3. **Отказ цели на `inout`.** Отвергнут: запись исполняют эталон и четыре
   цели, а выразить её в C можно — мешало только имя.

### Decision

Принят вариант 2: `port_enum_variant` принимает **объявленное** направление и
**сторону** перечисления; сегмент `_IN`/`_OUT` печатается, только когда порт
объявлен `inout`.

Объявленное направление едет вместе с портом в карте `collect_ports_by_class`
(тип `PortEntry`), поэтому перечисления и таблицы HAL строят то же имя, что и
печать обращения в теле.

### Consequences

- `c` и `c-hal` переводят двунаправленный порт; `cc` вывод принимает.
- Вывод корпуса **не изменился**.
- `sv`/`sv-mmio` по-прежнему отказывают `SV-006` — названная граница цели.

#### Acceptance criteria

Значения порта совпадают с эталоном потактово; имена перечислителей
различаются; у однонаправленного порта имя прежнее.

## Разработка

### Задача

#### Что было

`port_enum_variant(model, port)` строил имя без учёта направления; карта
`collect_ports_by_class` направление не несла.

#### Что сделано

- `c_names.rs` — сигнатура с объявленным направлением и стороной.
- `c_header.rs` — `PortEntry` несёт объявленное направление; перечисления
  печатаются с ним.
- `c_hal.rs` — таблицы адресов строят то же имя.
- `c_expr/{resolve,expr,condition}.rs`, `c_model_init.rs` — семь точек печати
  передают сторону по роли (чтение — `In`, запись — `Out`).

#### Проверки

Проба восьми целей, потактовая сверка, проверка имён, мутация, предкоммит.

### Найденные дефекты

### Выводы и дальнейшие шаги

третьего состояния), и это отдельная работа — вынесено кандидатом.

## Итог (что сделано)

`inout`-порт попадал в **оба** перечисления цели `c` под одним именем, и `cc`
отвергал вывод (`redefinition of enumerator`) при нулевом коде возврата
`taktc`. Имя перечислителя теперь строится с учётом **объявленного**
направления и **стороны** перечисления.

**Сегмент печатается только двунаправленному порту:** имена портов видны
пользователю в сигнатуре HAL-колбэка, и смена формы у однонаправленных была бы
ломающей без нужды. На это стоит контрольный тест.

**Класс найден пробой наугад:** `inout` в языке с начала, но ни один пример
верхнего уровня его не использует, а проверки целей смотрят только их (0403).

Контроль — потактовая сверка через **один регистр** подставного железа (чтение и
запись идут по одному адресу, как на плате) плюс проверка имён; мутация
проверена.
