### Context

У закрытых 0022/0023 остались два непокрытых пункта:

1. **CT3** — юнит-тест: произвольный **неалфавитный** символ (вне операторов/
   пунктуации языка) должен давать `BAD_CHARACTER`. Проверка по коду:
   `LamLexer.scanOperatorOrPunct` имеет ветку `else -> TokenType.BAD_CHARACTER` —
   поведение уже реализовано, но **контроля-теста нет** (есть лишь CT1 на `==`).
2. **Визуальная `runIde`-проверка** — цвета/подсветка в живой IDE. Требует GUI;
   в headless-окружении и CI невоспроизводима (`runIde` поднимает оконную IDE).

Прежнее утверждение «плагин нельзя собрать в CI» **опровергнуто** (уточнение
[действие Reformat Code в плагине IntelliJ](0039-intellij-reformat.md)): `buildPlugin`/`test --offline` проходят headless. GUI требует **только**
`runIde`, то есть остаток — именно **визуальный показ**, а не сборка/тесты.

### Decision Drivers

1. **Автоматизируемое — автоматизировать.** CT3 — чистый юнит-тест лексера,
   ему место в `LamLexerTest` (контроль против регресса ветки `BAD_CHARACTER`).
2. **Визуальное — признать остатком, а не имитировать.** Подсветку цветом в живой
   IDE headless-тест не проверит; выдумывать суррогат хуже, чем честно отметить
   визуальный пункт (прецедент A11 у 0022/0023/0038).
3. **Не блокировать закрытие визуальным пунктом.** Иначе фича «остаточных
   проверок» повиснет навсегда — GUI в CI/сессии нет по определению.

### Considered Options

#### Option A. Реализовать CT3 автотестом, `runIde` — визуальный остаток (принята)

**Pros:** покрывает автоматизируемую часть контролем; честно фиксирует визуальный
остаток; фича закрывается.

**Cons:** визуальный пункт остаётся непроверенным машиной (неизбежно без GUI).

#### Option B. Ждать GUI-окружения и закрыть всё разом

**Pros:** формально полное покрытие.

**Cons:** фича висит бессрочно; автоматизируемый CT3 не доезжает до контроля.

#### Option C. Суррогат визуальной проверки (сравнение атрибутов цветов в тесте)

**Pros:** видимость «автоматизации».

**Cons:** проверяет не то (маппинг ключ→атрибут уже покрыт
`LamSyntaxHighlighterTest`; сам **показ** цветом — вне досягаемости headless);
ложное чувство покрытия.

### Decision

Принимается **Option A**: CT3 добавляется юнит-тестом
`LamLexerTest.testArbitraryNonAlphaIsBadCharacter` (символы `@ $ \` \\ №` →
`BAD_CHARACTER`, ровно один токен на символ, покрытие всего ввода). Визуальная
`runIde`-проверка признаётся **визуальным остатком** (как A11 0022/0023/0038):
не блокирует закрытие, отмечается в отчёте. Язык/архитектура не меняются — ADR
фиксирует лишь объём и разрешение развилки «автоматизировать vs признать
остатком».

### Consequences

#### Положительные

- Ветка `BAD_CHARACTER` лексера получает контроль-тест (регресс поймается).
- Остаточные пункты 0022/0023 разрешены явно: один — тестом, другой — как
  признанный визуальный остаток.

#### Отрицательные / Action items

- Визуальный показ цветом остаётся на ручную проверку в `runIde` (GUI) — это
  постоянное свойство плагинных фич, не долг конкретной фичи.

#### Acceptance criteria

1. `LamLexerTest.testArbitraryNonAlphaIsBadCharacter` зелёный; `./gradlew
   --offline test` зелёный без правки прочих ожиданий.
2. В отчёте зафиксирован визуальный остаток `runIde` (не блокирует закрытие).

- **R2 (визуальный остаток).** `runIde`-показ цветом — не автоматизируется

### Особенности по обратной функциональности

Только плагин IntelliJ, только добавление теста — поведение неизменно (ветка
`BAD_CHARACTER` существовала). `grammar`/`simulation` — н/п.

### Риски и зависимости

- Символ, ошибочно классифицируемый как оператор (напр. `#`, `?`, `!` — они **в**
  списке операторов) — выбраны заведомо не-операторы (`@ $ \` \\ №`), проверено по
  `scanOperatorOrPunct`.
- `№` (U+2116) — категория Symbol, не Letter (`isLetter` = false) → идёт в
  `else`-ветку; кириллические **буквы** остались бы идентификаторами (не в наборе).

## Разработка

### Задача

#### Что было

Ветка `LamLexer.scanOperatorOrPunct` `else -> TokenType.BAD_CHARACTER` покрывала
любой неизвестный символ, но **контроля-теста не было** (CT1 проверял лишь `==`).

#### Что сделано

Добавлен юнит-тест `LamLexerTest.testArbitraryNonAlphaIsBadCharacter`: для набора
`@ $ \` \\ №` лексер даёт **ровно один** `BAD_CHARACTER`-токен на символ с текстом
= сам символ. Символы выбраны заведомо вне списка операторов/пунктуации языка
(`+ - * / % ! | & ^ ~ ? #` и скобки/пунктуация — это не `BAD_CHARACTER`).

Только тест — **production-код не менялся** (поведение уже было). Стеки
`grammar`/`simulation` — н/п.

#### Проверки

`cd extensions/intellij-lam && ./gradlew --offline test` — зелёный; новый тест
проходит, регресс 0022/0023 без правки ожиданий.
