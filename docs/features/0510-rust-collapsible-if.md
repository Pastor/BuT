# Фича: Цель `rust` — вложенный `if` сливается с внешним

- **Номер:** 0510
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2
- **Класс:** генерация
- **Связанные issue (анализ):** кандидат `FEATURES.md` «цель `rust`: `clippy::collapsible_if` на вложенном `if`» (заведён при закрытии [цели `rust` и `st` — пустая ветвь `match`](0509-empty-match-arm.md))

## Стадии жизненного цикла (правило 17)

Все стадии — **разделы этой карточки** (правило 32). Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Вложенный `if`, составляющий всё тело внешнего, печатается целью `rust`
конъюнкцией: `if a { if b { X } }` → `if (a) && (b) { X }`. Прежде вывод
отвергал `clippy` под `-D warnings` («this `if` statement can be collapsed») —
теми же флагами, что стоят в проверке самой цели, при **нулевом** коде возврата
`taktc`. То же правило применено к **последней** ветви `match`, и только к ней:
у любой другой слияние пропустило бы управление дальше по цепочке, то есть
поменяло бы автомат.

> Фича зарегистрирована из бэклога кандидатов; далее проходит жизненный цикл по
> правилу 17.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-03
- **Authors:** архитектор, разработчик

### Context

Замер-03 (`scripts/probe.sh` + прогон `clippy-driver` флагами проверки):

| Форма | Ответ инструментов |
|---|---|
| `if a { if b { X } }` | `rustc` принял, **`clippy` ОТВЕРГ** («can be collapsed») |
| последняя ветвь `match` = один `if` | то же |
| `if a { if b { X } } else { Y }` | принимают |
| `if a { if b { X } else { Y } }` | принимают |
| `if a { Z; if b { X } }` | принимают |
| ветвь `match` перед непустой `_` | принимают |

Прочие семь целей запись переводят, инструменты принимают.

Класс найден на примерах `book/` раздела «Процессор» и был **скрыт** за пустой
ветвью `else` (0509): линт сообщает о первой ошибке, и `needless_else` шёл
раньше.

### Decision Drivers

- Условие в Takt побочных эффектов не имеет (присваивание — оператор, 0187),
  поэтому конъюнкция вычисляет то же самое, а `&&` ленив, как и вложенный `if`.
- Границы линта измерены: три соседние формы `clippy` принимает — менять их
  значило бы менять вывод без повода (и снимки корпуса).
- У ветви `match` слияние законно **не всегда**: это вопрос автомата, а не
  формы.

### Considered Options

1. **Слить условия в конъюнкцию, у ветви `match` — только у последней**
   (принято).
2. **`#[allow(clippy::collapsible_if)]` в шапке модуля.** Отвергнуто политикой
   цели (0050): глушить линт в порождаемом коде нельзя — контроль должен остаться
   живым.
3. **Слить в семантике общим проходом.** Отвергнуто: у остальных семи целей
   проблемы нет, а вывод `c`/`st`/`sv` изменился бы без повода.
4. **Сливать ветвь `match` всегда.** Отвергнуто: при истинном образце и ложном
   внутреннем условии управление ушло бы в следующую ветвь — валидный вывод и
   другой автомат (мутация поймана сверкой).

### Decision

Печатник операторов цели `rust` раскручивает цепочку `if` без `else`, чьё тело —
единственный `if` без `else`, и печатает конъюнкцию условий. У `match` слияние
применяется к последней печатаемой ветви и только когда `_`-ветви в выводе нет.

### Consequences

- Все примеры `book/`, переводимые целью `rust`, принимаются `clippy`.
- Снимки `examples/generated/rust` не изменились: в корпусе такой формы нет.
- Одно условие печатается как прежде (`unwrap_outer`), слитые — со скобками
  подвыражений.

#### Acceptance criteria

1. Проба: `clippy` принимает обе формы предмета.
2. Контроль: три соседние формы печатаются как прежде.
3. Контроль: ветвь `match` перед `_` не сливается — контролирует потактовая сверка.
4. `./scripts/precheck.sh` зелёный.

## Разработка

### Задача: раскрутка цепочки у оператора

`rust_stmt.rs`: `unwrap_if_chain` (тело — один `if` без `else`) и
`collapse_nested_if` (то же для внешнего `if` без `else`). Одно условие
печатается прежней формой — иначе поехали бы снимки корпуса.

### Задача: слияние у последней ветви `match`

`_`-ветвь печатается в буфер до цепочки: знать, будет ли `else`, нужно раньше.
Слияние применяется к последней ветви с образцами и только при пустой `_`;
несколько образцов оборачиваются скобками перед `&&`.

### Задача: печать `match` вынесена в свой модуль

Правка перевела `rust_stmt.rs` за предел размера (1069 строк при ~1000). Печать
`match` вынесена в `rust_match.rs` — граница по ответственности: этот модуль
знает про пустую ветвь (0509), про слияние вложенного `if` (0510) и про порядок
ветвей, тогда как `rust_stmt` печатает операторы вообще. После выноса —
904 и 191 строка.

### Задача: контроля

Набор форм (5 тестов, включая прогон `clippy-driver`) и потактовая сверка,
ловящая слияние ветви перед `_`.

## Итог (что сделано)

Вложенный `if`, составляющий всё тело внешнего, печатается конъюнкцией; то же
сделано для последней ветви `match`. Прежде вывод отвергал `clippy -D warnings`
— проверка самой цели — при нулевом коде возврата `taktc`.

Границы правила измерены прогоном линта: три соседние формы он принимает, и они
не трогаются. У ветви `match` слияние ограничено последней ветвью при пустой
`_`: иначе оно пропускало бы управление дальше по цепочке — валидный вывод и
другой автомат, что и ловит новая потактовая сверка.
