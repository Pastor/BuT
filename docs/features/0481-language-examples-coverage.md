# Фича: Примеры языка показывают конструкции выражений

- **Статус:** ГОТОВО
- **Зависит от:** нет

- **Связанные issue (анализ):** проверка покрытия по запросу заказчика 2026-09-02

## Краткое описание

Подкаталог `examples/language/` — примеры, показывающие **конструкции языка**.
Шесть форм в позиции **выражения** там не показаны и живут только в прикладных
примерах верхнего уровня: `&&`, `||`, `<=`, `>=`, скобки и инлайн-формула
состояния. Проверка покрытия этого не видит — он считает область `examples/`
целиком. Фича доводит примеры языка до полноты и закрепляет это проверкой.

> Фича зарегистрирована по запросу заказчика (проверка покрытия 2026-09-02);
> далее проходит жизненный цикл по правилу 17.

## Документирование (правило 24)

**Не требуется.** Фича не меняет язык: ни синтаксиса, ни семантики, ни
поведения целей, ни диагностик. Она добавляет **примеры** в исполняемый корпус
и контроля к ним. Формы, о которых идёт речь, документ уже описывает — раздел
«Выражения» (приоритеты операторов, логические `&&`/`||`) и раздел
«Верификация» (инлайн-формула).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-02
- **Authors:** архитектор, аналитик

### Context

Замер-02 (прогон контроля покрытия и разовые замеры тем же
`takt_lang::parser::coverage`):

| Область | Покрыто конструкций |
|---|---|
| `examples/` целиком | 153 из 157 достижимых (остальные четыре — записи `never`) |
| `examples/language/` | **147** |
| верхний уровень `examples/*.takt` | **82** |

Шесть форм показаны только прикладными примерами верхнего уровня:
`Expression::And`, `Expression::Or`, `Expression::LessEqual`,
`Expression::MoreEqual`, `Expression::Parenthesis`, `StateElement::InlineFormula`.

Тонкость, из-за которой пробел не виден глазами: в примерах языка есть и
`>=`, и `<=`, и скобки — но **в условиях** (`ref Steady: raw >= Ceiling;`).
Это узлы `Condition::*`, а `Expression::*` — другие: язык разделяет их
намеренно (инвариант «`Condition` и `Expression` не унифицировать»). Логических
`&&`/`||` условная грамматика не принимает вовсе.

**Второй замер важнее первого.** Проверки целей предкоммита гоняют
`examples/*.takt` — **только верхний уровень** (`for takt_file in
examples/*.takt`, glob не рекурсивен). Покрытие же считается по всему
`examples/` рекурсивно. Значит **71** конструкция (LTL-выражения, формулы,
`every`, `invariant`, `break`/`continue`, `assembly`, импорт с определениями и
другие) показана только в `examples/language/` и **ни одной целью не
компилируется** — тогда как заголовок контроля обещает: «конструкции, которой
здесь нет, проверки предкоммита не видят».

### Decision

1. **Дополнить `examples/language/`** шестью формами: пять — в
   `expressions.takt` (позиция выражения, не условия), инлайн-формула — в
   `properties.takt`.
2. **Закрепить проверкой:** в список областей контроля покрытия добавляется третья
   — `language` (каталог `examples/language`). Долга у неё после правки не
   будет: 147 + 6 = 153, столько же, сколько у `examples/` целиком.

Область `examples` **сохраняется**: она отвечает на другой вопрос — «есть ли
конструкция в исполняемом корпусе вообще». Заменять её подкаталогом нельзя:
71 конструкция живёт только там, и замена молча ослабила бы требование.

### Consequences

- Примеры языка показывают все конструкции, которые может показать корпус.
- Регресс закрыт ратчетом: новая конструкция обязана попасть и в `language/`.
- **Названная граница:** примеры языка по-прежнему не компилируются целями и не
  симулируются — проверки предкоммита их не видят. Это соседний класс, он вынесен
  кандидатом (проверка для `examples/language/` по образцу проверки примеров `book/`).

#### Acceptance criteria

1. Контроль покрытия зелен с тремя областями и **без** новых записей долга.
2. `taktc fmt --check examples/` зелен (канон примеров).
3. Добавленные формы разбираются и семантически законны.
4. `./scripts/precheck.sh` зелёный.

## Разработка

### Задача — шесть форм в примерах языка

`examples/language/expressions.takt` — блок `always` состояния `Compute`
дополнен четырьмя строками в позиции **выражения**: `ready := a <= b;`,
`ready := a >= b;`, `ready := (a <= b) && (b >= 1);`,
`ready := (a > b) || (b = 5);`. Скобки и обе логические связки покрываются
этими же строками. Комментарий рядом называет причину, по которой формы
понадобились отдельно от условий: те же знаки на ребре дают узлы
`Condition::*`, а связок `&&`/`||` условная грамматика не принимает вовсе.

`examples/language/properties.takt` — состояние `Fill` получило безымянную
охранную формулу **элементом состояния**: `: [Guard] level <= 250;`. Прежде
формулы примера стояли элементами модели и оператором внутри `always` — это
`ModelElement::InlineFormula` и `Statement::InlineFormula`, третий разбор
показан не был.

Прикладные примеры верхнего уровня не тронуты (требование 3 анализа).

### Задача — третья область контроля покрытия

`takt-lang/tests/syntax/language_coverage_tests.rs`: массив `AREAS` вырос до
трёх записей — добавлена `("language", "examples/language")`. Ратчет, реестр
долга и все семь проверок проверки работают по областям, поэтому правка ограничена
одной константой и её комментарием, который называет роль каждой области.

Записей долга у новой области нет: после задачи она покрывает 153
конструкции — столько же, сколько `examples/` целиком (остальные четыре из 157
достижимых лежат в области `never`).

| Условие проверки | Как проверяется | Ожидаемый результат |
|---|---|---|
| `T1` Замер воспроизводится | прогон контроля с добавленной областью **до** правки примеров | падение списком ровно из шести форм, названных анализом |
| `T2` Полнота области `language` | `cargo test --test syntax language_coverage` | семь проверок зелены, новых записей долга нет |

| `T4` Формы законны | компиляция дополненных примеров подходящей целью | отказов, связанных с добавленными строками, нет |

`T1` — не формальность: без него зелёный `T2` доказывал бы лишь то, что
проверка не падает, а не то, что он контролирует предмет. Контроль обратной стороны
даёт `T3`: область, посчитанная по ошибочному каталогу, дала бы другое число.

`T4` берёт **подходящую** цель: `expressions.takt` содержит обращение к
ячейке `#0x300.0` (цель `c` отказывает `CC-018` — это её граница, а не дефект
правки), `properties.takt` объявляет `clock 100Hz` и требует `--tick-hz=100`.

### Примеры и контрпримеры (правило 16)

Фича языка не меняет, поэтому контрпримеров-диагностик у неё нет. Роль
контрольного входа играет `T1`: тот же проверка на **недополненных** примерах
называет ровно те шесть форм — то есть новая область меряет предмет, а не
проходит молча. Обратную сторону закрывает `T3`: область, посчитанная по
чужому каталогу, дала бы число, отличное от `examples`.

### Редакторский слой (правило 29)

**Не затронут:** ни лексика, ни синтаксис, ни семантика не изменены — новых
токенов, узлов АСД и диагностик нет. Изменение состоит из строк на уже
существующих конструкциях и одной константы теста.

### Найденные дефекты

Дефектов правки нет. Прогон `T4` вскрыл **соседний** класс, существующий и до
неё: блок формул внешнего анализатора в теле (`formula { … }`) не проходит
понижение, и четыре цели отвечают воронкой недостижимости — `c` даёт `CC-023`
(«узел не прошёл семантическое понижение»), `st` — `ST-011`, `rust` — `RS-011`,
`sv` — `SV-002`, тогда как узел законен, а предмет отказа — «обязательство для
внешнего анализатора цель не переводит». Замер снят пробой 2026-09-02
(`scripts/probe.sh -n 2`): эталон исполняет, `plantuml` принимает, целей с
выводом нет. Класс в объём 0481 не входит (примеры языка проверками целей не
гоняются) и вынесен **кандидатом** в `FEATURES.md`.

### Вердикт

**Готово.** Все шесть условий тест-плана выполнены, регресс проекта зелёный.
