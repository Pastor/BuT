# Фича: Общие переменные корня → структура `Shared` вместо параметров по одной

- **Номер:** 0059
- **Статус:** ГОТОВО (см. «Итог (что сделано)» ниже)
- **Зависит от:** **нет** (проверено аналитиком 2026-07-17 — см. [анализ](0059-rust-shared-struct.md#анализ), раздел «Зависимости фичи»). Опора — **закрытая** [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md) (детерминизм: иначе дифф корпуса нечитаем). С [цель `rust`: хвостовой `if/else` с `return` даёт `needless_return`](0058-rust-tail-return-if-else.md) не пересекается (та правит `rust_func.rs`/`rust_stmt.rs`, эта — `rust_model.rs`).

- **Крейт:** `grammar` (генератор `generator/rust/`: `rust_model.rs`, `rust_needs.rs`)

## Краткое описание

Цель `rust` передаёт общие переменные корня под-модели **по одной**
(`rust_needs::FnNeeds`, корневые переменные идут `&mut`-параметрами). У
`MovementController` (`stacker.lam`) их девять, поэтому такт получает 10
параметров и упирается в порог `clippy::too_many_arguments` (7). Арность диктует
**модель**, а не стиль, поэтому линт сегодня заглушён точечно на самом методе.
Системное лечение — свернуть общие переменные в структуру `Shared` и передавать
`&mut Shared`.

Вскрыто закрытой [генератор генерации в Rust](0050-rust-backend.md).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Лид разработки
- **Related issues:** [Фича](0059-rust-shared-struct.md); исполняет политику линтов [ADR](0050-rust-backend.md#архитектура-adr) (вариант (а)) там, где она сегодня **нарушена**

### Context

Цель `-t rust` передаёт под-модели переменные родительской модели **по одной**,
`&mut`-параметрами. Так решено в [ADR](0050-rust-backend.md#архитектура-adr) осознанно:
указатель на корень (`self.cabin.tick(&mut self)`) даёт **двойное заимствование**
(E0499), поэтому «как в C» (`Model *model`) сделать нельзя, и переменные пошли
параметрами — «как `VAR_IN_OUT` у ST».

Следствие — арность. Порог `clippy::too_many_arguments` — **7**, и `self` в него
**входит**. При превышении генератор **эмитит заглушку линта**:

```rust
// rust_model.rs:918
if 1 + shared.len() + usize::from(needs_hal_param) > 7 {
    p.ident("#[allow(clippy::too_many_arguments)]").nl();
}
```

**Замер по корпусу (2026-07-17, чтение порождённых `.rs`):**

| Под-модель | `shared` | Параметров (со `self` и `hal`) | Заглушка |
|---|---|---|---|
| `Stacker::CommandReceiver` | 6 | 8 | **да** |
| `Stacker::MovementController` | **8** | **10** | **да** |
| `Stacker::LiftController` | 3 | 5 | нет |
| `Elevator::Engine` | 3 | 5 | нет |
| `ElevatorMini::*` | 1–3 | 3–5 | нет |
| `ExtendComplex::*` | 0–2 | 1–4 | нет |
| `Comprehensive::*` | 0 | 2 | нет |

То есть заглушка сегодня стоит **у двух под-моделей одного примера**, а
`rust_model.rs:920` — **единственное место во всём генераторе, которое эмитит
`#[allow]` в порождаемый код**. Это и есть суть проблемы: **единственное
исключение из принятой политики (а)** ADR («не эмитить то, на что линт
ругается, вместо `#[allow]`; контроль должен остаться живым»).

**Уточнение факта, записанного в кандидате и в самом коде.** И кандидат («у
`MovementController` их девять»), и комментарий генератора (`rust_model.rs:911`:
«`MovementController` разделяет с корнем девять переменных») **ошибаются на
единицу**. Замер: в `stacker.lam` **девять** переменных корня
(`tgt_stack`, `tgt_row`, `tgt_section`, `tgt_type`, `busy`, `eta`,
`lift_request`, `lift_op`, `lift_done`), а `MovementController` разделяет
**восемь** — все, кроме `eta`. Девять — это размер **корня**, а не нужд
под-модели. Заявка кандидата «такт получает 10 параметров» при этом **верна**
(`self` + `hal` + 8). Отсюда важное для решения наблюдение: **`shared` считается
по каждой под-модели отдельно** (минимум по нуждам), а не «все переменные корня».

### Decision Drivers

1. **Политика (а) не должна иметь исключений.** ADR выбрал «не эмитить то, на
   что линт ругается» и прямо запретил глушить контрольных тестов (прецедент: `pub enum`
   глушит `dead_code` видимостью — «не делать»). Одно исключение делает политику
   договорной.
2. **Арность диктует модель, а не стиль.** Это верно — и потому лечить нужно
   **форму передачи**, а не линт: сама по себе заглушка не становится честнее от
   того, что арность обоснована.
3. **Масштабируемость.** 8 общих переменных дают 10 параметров; 20 дали бы 22.
   Предела нет — растёт вместе с моделью пользователя.
4. **Не потерять то, что今 работает.** `no_std`, отсутствие `unsafe`, потактовая
   сверка и контракт 0033 обязаны остаться в силе; заимствования не должны дать
   E0499 (ровно та причина, по которой 0050 не передала указатель на корень).

### Considered Options

#### Option A. Одна структура `Shared` на композирующую модель; поле корня; `&mut Shared` параметром

`Shared` = **объединение нужд под-моделей** (не «все переменные корня»: переменная,
которой не нужен никто, общей не является и остаётся прямым полем).

```rust
struct Shared { busy: bool, eta: u8, lift_done: bool, /* … */ }

pub struct Stacker<H: Hal> { shared: Shared, state: StackerState, /* … */ hal: H }

impl Stacker<H> {
    pub fn tick(&mut self) {
        self.movement.tick(&mut self.hal, &mut self.shared);   // ← поля НЕПЕРЕСЕКАЮЩИЕСЯ
    }
}
```

**Pros:**
- Заглушка исчезает **по построению**: параметров всегда `self` + `hal` +
  `&mut Shared` = 3 ≤ 7 (драйверы 1, 3).
- **Двойного заимствования нет** (драйвер 4): `&mut self.hal` и `&mut self.shared`
  — раздельные поля, а не `&mut self`; именно это отличает `Shared` от
  отвергнутого 0050 указателя на корень.
- Ближе к эталону: у цели `c` под-модель получает `Model *model` — то же самое,
  минус заимствования.
- Одна форма вывода — один путь кода.

**Cons:**
- **Теряется минимальность интерфейса:** сегодня сигнатура показывает, какие
  именно переменные читает под-модель (`LiftController` — ровно три); с `Shared`
  каждая под-модель видит всё объединение.
- Корпус меняется шире дефекта: правятся **все** композиции, а не только две
  под-модели `stacker`.

#### Option B. Структура ссылок на под-модель (`MovementControllerShared<'a>`)

**Pros:**
- Минимальность сохраняется: у каждой под-модели своя структура ровно из её нужд.
- Заглушка исчезает.

**Cons:**
- **Тип на каждую под-модель** + время жизни; объём вывода растёт.
- Место вызова становится **многословнее сегодняшнего**
  (`&mut MovementControllerShared { busy: &mut self.busy, … }`), то есть проблема
  «девять имён в строке» переезжает из сигнатуры в вызов, а не решается.

#### Option C. Оставить как есть (точечная заглушка)

**Pros:**
- Ноль правок; арность действительно диктуется моделью (драйвер 2 — верен).

**Cons:**
- **Нарушает политику (а)** и оставляет её единственное исключение (драйвер 1).
- Не масштабируется (драйвер 3).
- Заглушка на методе скрывает и **будущие** срабатывания линта на нём.

#### Option D. `Shared` только там, где порог превышен

**Pros:**
- Минимальный дифф корпуса: меняются ровно две под-модели `stacker`.

**Cons:**
- **Форму вывода начинает определять порог линта** — две формы одного и того же,
  два пути кода, две поверхности дефектов.
- Порог clippy — величина внешняя и может измениться; вывод генератора не должен
  от неё зависеть.

### Decision

Принимается **Option A**.

Она устраняет **единственное исключение** из политики (а) по построению, а не
заглушкой, и снимает потолок роста (драйвер 3). Ключ к ней — наблюдение, которого
не было у 0050: **двойное заимствование даёт `&mut self`, а не «структура»**;
`&mut self.hal` + `&mut self.shared` — непересекающиеся поля, и E0499 не возникает.
То есть довод, по которому 0050 отвергла «указатель на корень», к `Shared` **не
применим**.

Option D отклонена как порождающая две формы вывода ради экономии диффа: дифф —
одноразовая цена, две формы — постоянная. Option B сохраняет минимальность, но
переносит многословность в место вызова и множит типы. Option C оставляет политику
с исключением.

**Нормативные правила:**

1. `Shared` эмитится **только** у модели, у которой есть под-модели, нуждающиеся
   хотя бы в одной её переменной. Нет нужд — нет типа (иначе `dead_code`).
2. `Shared` = **объединение** нужд под-моделей. Переменная модели, не нужная ни
   одной под-модели, в `Shared` **не входит** и остаётся прямым полем: иначе имя
   типа лгало бы.
3. `Shared` **приватна** (как перечисления состояний): публичность заглушила бы
   `dead_code`-контроля видимостью — прямой запрет ADR.
4. Уровни вложенности: правило 1 применяется **к каждой** композирующей модели
   независимо — у промежуточной модели свой `Shared` (в корпусе такой случай есть:
   `extend_complex`).
5. `hal` в `Shared` **не входит** — он остаётся отдельным параметром и **последним**
   (инвариант: иначе `f(&mut hal, hal.read_u8(…))` даёт E0499).

**Язык не меняется** → версия языка не растёт (правило 22).

### Consequences

#### Положительные

- `#[allow]` в порождаемом коде **исчезает полностью**; политика (а) становится
  безысключительной, а `rust_model.rs:920` — удаляется.
- Арность такта перестаёт зависеть от размера модели (драйвер 3).
- Форма вывода одна.

#### Отрицательные / Action items

- **A-1. Минимальность интерфейса теряется** — осознанная цена. Сегодня сигнатура
  `LiftController::tick(…, lift_done, lift_op, lift_request)` документирует
  связность; с `Shared` она видна только в `rust_needs`. Смягчение: `Shared`
  строится **по объединению нужд** (правило 2), а не «все переменные корня», то
  есть связность модели по-прежнему ограничивает содержимое типа.
- **A-2. Дифф корпуса будет широким** — меняются `stacker`, `elevator`,
  `elevator_mini`, `extend_complex` (у `comprehensive` общих переменных нет).
  Это **не** нарушение правила 11: наружный контракт (публичный API, порты, HAL,
  поведение) неизменен, меняется внутренняя форма. Дифф **осмыслен и проверяем**
  благодаря детерминизму (закрытая [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr)).
- **A-3. Исправить неверный комментарий генератора.** `rust_model.rs:911` утверждает,
  что `MovementController` разделяет с корнем **девять** переменных; замер —
  **восемь** (девять — размер корня). Комментарий переживёт правку кода, поэтому
  чинится вместе с ней.
- **A-4. Проверить сверку, а не только проверка.** `Shared` меняет **способ доступа** к
  переменным (`busy` → `shared.busy`), то есть ровно тот класс, где ошибка тихая
  (урок: `always_comb` читал регистр вместо `_next`, и **оба** проверки приняли).
  Обязателен прогон `conformance_rust_tests`.

#### Acceptance criteria

1. **A1.** `grep -rn "allow(clippy::too_many_arguments)" examples/generated/rust/`
   — **пусто**; `rust_model.rs:920` (эмиссия заглушки) удалена.
2. **A2.** `grep -rn "p.ident(\"#\[allow" grammar/src/generator/rust/` — **пусто**:
   генератор не эмитит заглушек линтов вовсе (политика (а) без исключений).
3. **A3.** Проверка цели `rust` (rustc + clippy `-D warnings`) зелёный на **всём**
   корпусе.
4. **A4.** `conformance_rust_tests` — вердикты **не изменились** (A-4).
5. **A5.** Такт под-модели имеет ровно `self` + `hal?` + `&mut Shared?` — не более
   трёх параметров, независимо от числа общих переменных.
6. **A6.** Модель **без** общих переменных (`comprehensive`) типа `Shared` **не
   получает** (правило 1): `grep "struct Shared" comprehensive.rs` — пусто.
7. **A7.** Переменная модели, не нужная ни одной под-модели, в `Shared` **не
   входит** (правило 2) — проверяется фикстурой.
8. **A8.** `Shared` **приватна** (правило 3) — `grep "pub struct Shared"` пусто.
9. **A9.** Многоуровневая композиция (`extend_complex`) даёт `Shared` **на каждом**
   композирующем уровне (правило 4), проверка зелёный.
10. **A10.** `unsafe` в выводе отсутствует; `no_std` держится.

## Анализ

### Цель и контекст

Цель `-t rust` передаёт под-модели переменные родителя по одной `&mut`-параметром;
при превышении порога `clippy::too_many_arguments` (7, `self` входит) генератор
**эмитит заглушку** `#[allow(clippy::too_many_arguments)]`. Это **единственное
место во всём генераторе**, где в порождаемый код эмитится `#[allow]`, — то есть
единственное исключение из политики (а) [ADR](0050-rust-backend.md#архитектура-adr).

ADR принял **Option A**: `Shared` — структура объединённых нужд под-моделей, поле
композирующей модели, передаётся `&mut Shared`. Заглушка исчезает **по
построению**.

### Локализация (прочитано в коде и в порождённом выводе, 2026-07-17)

| Что | Где | Роль |
|---|---|---|
| Эмиссия заглушки | `rust_model.rs:918–921` | `if 1 + shared.len() + hal > 7 { … }` — **единственная** эмиссия `#[allow]` |
| Печать параметров | `rust_model.rs:855–862` | По одному `&mut` на элемент `shared`, без фильтрации |
| Неверный комментарий | `rust_model.rs:911` | «разделяет с корнем **девять** переменных» — замер даёт **восемь** |
| `Scope.shared` | `rust_model.rs:883` | Список имён, по которому печать решает `shared` vs `self.x` |
| Нужды | `rust_needs::FnNeeds` / `function_needs` | Считает, что нужно функции; для такта — аналог |
| Эталон композиции | `c_model.rs` (цель `c`) | Под-модель получает `Model *model` — то, чем `Shared` является в Rust |

### Замер (факты, а не оценка)

Переменных корня в `stacker.lam` — **девять**. `shared` считается **по каждой
под-модели отдельно** (минимум по нуждам):

| Под-модель | `shared` | Параметров | Заглушка |
|---|---|---|---|
| `CommandReceiver` | 6 | 8 | **да** |
| `MovementController` | **8** (все, кроме `eta`) | **10** | **да** |
| `LiftController` | 3 | 5 | нет |
| прочие примеры корпуса | 0–3 | 1–5 | нет |

**Кандидат и комментарий кода ошибались на единицу** («девять» у
`MovementController`): девять — размер **корня**, нужд у под-модели **восемь**.
Заявка «10 параметров» верна (`self` + `hal` + 8). Исправление комментария —
задача (A-3 ADR).

### Зависимости фичи (правило 17/19)

- **Зависит от:** **нет**.
  - **Код.** Правка внутри `generator/rust/` (`rust_model.rs`, `rust_needs.rs`,
    `rust_decl.rs`). Пересечение с [цель `rust`: хвостовой `if/else` с `return` даёт `needless_return`](0058-rust-tail-return-if-else.md)
    — **нет**: та правит `rust_func.rs`/`rust_stmt.rs` (печать тела функции), эта —
    `rust_model.rs` (сигнатура и поля модели). Обе могут идти в любом порядке.
  - **Инфраструктура.** Проверка (`rustc` + `clippy`) — уже зависимость проекта.
  - **Опора.** Детерминизм (**закрытая** [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md))
    — без него дифф корпуса был бы шумом перестановок и критерии A1/A3 не читались
    бы. Зависимость закрыта → блокировки нет.
  - **Смежность с [устранение всех предупреждений сборки (rustc + clippy)](0046-build-warnings-cleanup.md)** (чистка
    предупреждений) — **не зависимость**: 0046 чистит предупреждения **самого
    проекта**, 0059 — заглушку в **порождаемом** коде. Пересечения правок нет.
    Смежная находка: в `rust_model.rs` **пять** собственных
    `#[allow(clippy::too_many_arguments)]` (строки 389, 598, 695, 830, 1204) — это
    код генератора, а не вывод; в объём 0059 **не входит**, передано кандидатом.
- **Влияние на порядок разработки:** никого не разблокирует, никем не заблокирована.
  Место в очереди — по Tier.

### Приоритет (Tier) — обоснование

**Tier 3.**

- Порождаемый код **верен и проходит проверка** — сегодня, ценой заглушки.
- Пользователь дефекта **не видит**: страдает чистота вывода и принципиальность
  политики, а не работоспособность.
- Против Tier 2: ничто не сломано и обхода не требуется.
- Но и **не «косметика»**: это единственное исключение из политики, принятой
  ADR; исключения имеют свойство становиться правилом.

### Требования и проверяемые условия

- **R1. Заглушек нет.** Генератор не эмитит `#[allow]` в порождаемый код **ни
  разу**.
- **R2. `Shared` — по нуждам, а не «все переменные корня».** Переменная, не нужная
  ни одной под-модели, в `Shared` не входит (иначе имя типа лжёт).
- **R3. Нет `Shared` — нет типа.** Модель без нуждающихся под-моделей типа не
  получает (иначе `dead_code`).
- **R4. Приватность.** `Shared` не публична (публичность = глушение `dead_code`
  видимостью — запрет ADR).
- **R5. Заимствования.** `&mut self.hal` и `&mut self.shared` — раздельные поля;
  E0499 не возникает. `hal` в `Shared` **не входит** и остаётся **последним**
  параметром.
- **R6. Поведение неизменно.** Меняется способ доступа (`busy` → `shared.busy`), не
  семантика.
- **R7. Уровни.** Каждая композирующая модель получает свой `Shared`.
- **R8. Инварианты держатся:** `no_std`, отсутствие `unsafe`, приватность
  перечислений состояний, контракт 0033 (вход не расходует такт).
- **R9. Арность ограничена.** Такт под-модели — не более `self` + `hal` + `&mut
  Shared`.

### Особенности по обратной функциональности

**Наружный контракт не меняется** (правило 11): публичный API (`new`, `init`,
`tick`, `is_done`), трейт `Hal`, порты и поведение — прежние. Меняется
**внутренняя форма** порождённого модуля.

**Дифф корпуса будет широким и это ожидаемо:** правятся `stacker`, `elevator`,
`elevator_mini`, `extend_complex`; `comprehensive` не меняется (общих переменных
нет). В отличие от [цель `rust`: хвостовой `if/else` с `return` даёт `needless_return`](0058-rust-tail-return-if-else.md), критерий
«корпус побайтово прежний» здесь **неприменим** — и это осознанная разница, а не
послабление: 0058 меняла лишь то, что проверка отвергал, а 0059 меняет форму того, что
проверка принимает. Поэтому и требуется **поведенческая** сверка (A4), а не только
проверка.

Прочие цели (`c`/`c-hal`/`st`/`st-at`/`sv`/`plantuml`), симулятор, LSP, форматтер —
**не задеты**. Язык **не меняется** → версия не растёт (правило 22).

### Риски и зависимости

- **R-1. Тихая порча доступа** (главный риск). `Shared` меняет способ чтения/записи
  переменных — ровно тот класс, где ошибка **тихая**: урок (`always_comb`
  читал регистр вместо `_next` — **оба** проверки приняли молча) и урок (сверки
  не было вовсе при зелёном проверке — пробел нашла приёмка). Снижение: A4 —
  потактовая сверка обязательна и является **основным** критерием, а не
  дополнением к проверке.
- **R-2. E0499 при построении.** Если `Shared` окажется не полем, а вычисляемой
  ссылкой на `self`, вернётся ровно та ошибка, из-за которой 0050 отвергла
  указатель на корень. Снижение: правило 5 ADR — `Shared` **поле**, `hal` — другое
  поле; заимствуются раздельно. Контроль — сборка (E0499 громкая).
- **R-3. `dead_code` на полях `Shared`.** Поле, попавшее в `Shared` «на всякий
  случай», никем не читается → отказ проверки. Снижение: правило 2 (по нуждам).
  Контроль — A3; линт здесь **союзник**, а не помеха.
- **R-4. Потеря минимальности как потеря информации.** Сигнатура перестаёт
  показывать связность под-модели. Снижение: связность по-прежнему ограничивает
  **состав** `Shared` (объединение нужд), а не «все переменные корня». Принято
  осознанно (A-1 ADR).
- **R-5. Соблазн «заодно почистить» пять `#[allow]` в самом генераторе.** Это
  **другой** объём (код генератора, не вывод) — передан кандидатом; смешение
  сделало бы дифф нечитаемым.

### Побочная находка проработки (вне объёма)

**В самом генераторе — пять `#[allow(clippy::too_many_arguments)]`**
(`rust_model.rs:389, 598, 695, 830, 1204`). Это заглушки на **собственных**
функциях генератора, а не в выводе; политики (а) они не нарушают (та — про
порождаемый код), но воспроизводят ту же болезнь на уровень выше: функции печати
получают по 8–10 аргументов. Заведено кандидатом в `FEATURES.md` (правило 7);
в объём 0059 не берётся.

## Разработка

### Задача

#### Что было

`shared` считается **по каждой под-модели отдельно** (минимум по её нуждам) и
разворачивается в параметры по одному (`rust_model.rs:855–862`). Понятия «состав
общих переменных модели» — то есть **объединения** нужд — не существует.

Замер (`stacker.lam`, 9 переменных корня): `CommandReceiver` — 6,
`MovementController` — **8** (все, кроме `eta`), `LiftController` — 3.

#### Что сделано

1. Ввести вычисление **объединения нужд под-моделей** для композирующей модели —
   состав будущего `Shared` (правило 2 ADR: переменная, не нужная **ни одной**
   под-модели, в состав **не входит** и остаётся прямым полем; иначе имя типа
   лжёт, а поле ловит `dead_code`).
2. Считать нужды **тем же** механизмом, что уже считает нужды такта/функции
   (`rust_needs`), а не вторым предикатом рядом: разойдясь, они дали бы либо
   `dead_code` на поле, либо неразрешённое имя. Прецедент, ради которого это
   требование записано, — `function_needs` / `rust_expr::call` в этом же
   генераторе.
3. Правило 1 ADR: **нет нуждающихся под-моделей — нет типа** (в корпусе такой
   случай есть: `comprehensive`).
4. Правило 4 ADR: объединение считается **для каждой** композирующей модели
   независимо (в корпусе есть уровни: `extend_complex`).
5. Детерминизм: состав `Shared` — упорядоченный контейнер
   (`BTreeMap`/`BTreeSet`), порядок полей задаётся **типом контейнера**, а не
   строкой на эмиссии.

**Исправить неверный комментарий** `rust_model.rs:911` (A-3 ADR): «`MovementController`
разделяет с корнем **девять** переменных» → **восемь**; девять — это размер
**корня**. Ошибка кочует из кандидата в код и обратно, поэтому правится вместе с
кодом, а не «когда-нибудь».

Статус по обратной функциональности (правило 11): шаг **ничего не печатает** —
вывод всех целей неизменен; задача подготовительная.

#### Проверки

- `cargo build --bin lamc` — зелёная.
- Юнит-тесты состава: `comprehensive` → пусто (R3); модель с «ничьей» переменной →
  её в составе нет (R2/T6); `stacker` → у корня в составе 9 (объединение 6 ∪ 8 ∪ 3).
- `git diff --exit-code examples/generated/rust` — **пусто** (печать не тронута).
- **Негативный контроль (T13):** мутация «класть все переменные корня» обязана дать
  непрочитанное поле — то есть отказ проверки на следующем шаге. Контроль, не
  проверяющий взведённость ловушки, проверяет собственную удачу.

### Задача

#### Что было

Общие переменные — прямые поля композирующей модели; под-модель получает их
`&mut`-параметрами по одному; при `1 + shared.len() + hal > 7` эмитится
`#[allow(clippy::too_many_arguments)]` (`rust_model.rs:918–921`) — **единственное
место во всём генераторе, эмитящее `#[allow]` в порождаемый код**, то есть
единственное исключение из политики (а) ADR.

#### Что сделано

По составу из [общие переменные корня → структура `Shared` вместо параметров по одной](0059-rust-shared-struct.md#разработка):

1. **Тип.** Эмитить `struct Shared { … }` — **приватную** (правило 3 ADR:
   публичность заглушила бы `dead_code`-контроля видимостью, что ADR прямо
   запрещает).
2. **Поле.** Композирующая модель хранит `shared: Shared`; переменные из состава
   перестают быть прямыми полями. Переменные **вне** состава остаются прямыми
   полями (правило 2).
3. **Сигнатура.** Такт под-модели: `fn tick<H: Hal>(&mut self, shared: &mut Shared,
   hal: &mut H)` — **`hal` последним** (инвариант: иначе
   `f(&mut hal, hal.read_u8(…))` даёт E0499).
4. **Место вызова.** `self.sub.tick(&mut self.shared, &mut self.hal)` —
   заимствуются **раздельные поля**, а не `&mut self`. Именно этим `Shared`
   отличается от отвергнутого ADR «указателя на корень»: тот давал E0499,
   этот — нет.
5. **Доступ.** Внутри под-модели имя из состава печатается через `shared.` (сегодня
   — голым именем параметра); у композирующей модели — `self.shared.x`. Точка
   решения одна — `Scope.shared` (`rust_model.rs:883`), она уже отличает общее имя
   от локального.
6. **Инициализация.** `new()`/`init()` строят `Shared { … }` вместо перечисления
   полей (контракт 0033 не меняется: `enter` — поведение и живёт в `tick`).
7. **Снять заглушку.** Удалить `rust_model.rs:918–921` целиком: после правки
   параметров всегда ≤ 3, и условие мертво. Оставить `if` «на всякий случай»
   **нельзя** — это вернуло бы исключение из политики.

Статус по обратной функциональности (правило 11): **наружный контракт не
меняется** (`new`/`init`/`tick`/`is_done`, трейт `Hal`, порты, поведение);
меняется внутренняя форма модуля. Прочие цели, симулятор, LSP, форматтер не задеты
(правка внутри `generator/rust/`).

#### Проверки

- **A1/T1:** `grep -rn "allow(clippy::too_many_arguments)" examples/generated/rust/`
  — пусто.
- **A2/T2:** `grep -rn 'p.ident("#\[allow' grammar/src/generator/rust/` — пусто.
- **A5/T4:** такт ≤ 3 параметров (было 10 у `MovementController`).
- **A3/T3:** `./scripts/precheck.sh` — проверка `rust` зелёный.
- **A4/T5 — основная:** `cargo test --test conformance_rust_tests -- --test-threads=1`
  — вердикты не изменились. Проверка доказывает компилируемость, но **не** верность:
  правка меняет **способ доступа** к переменным, а это ровно тот класс, где ошибка
  тихая (урок: неверное чтение приняли **оба** инструмента SV; урок:
  сверки не было вовсе при зелёном проверке).
- **A6/T7:** `comprehensive` — `struct Shared` не эмитится.
- **A8/T8, T12:** `Shared` приватна; мутация в `pub` показывает, что контроль
  `dead_code` при этом слепнет.
- **A9/T9:** `extend_complex` — `Shared` на каждом композирующем уровне.
- **A10/T11:** `no_std` держится, `unsafe` отсутствует.
- **T10:** сборка без E0499.
- **T14:** вывод целей `c`/`st`/`sv`/`plantuml` не изменился.

#### Ожидаемый дифф

Меняются `stacker`, `elevator`, `elevator_mini`, `extend_complex`;
`comprehensive` — нет. Критерий «корпус побайтово прежний» здесь **неприменим**

быть не может, детерминизм гарантирован закрытой 0048.

## Тест-план

единственной заглушки линта в порождаемом коде. Язык не меняется → примеров и

### Отклонения от проработки (с обоснованием)

- **Тип `Shared` — `<Root>Shared`, а не голое `Shared`.** В плоском модуле цели
  `rust` модели соседствуют, и голое имя столкнулось бы (ADR приводил `Shared`
  условно). Уточнение реализации, критериям не противоречит.
- **Правило 4 ADR («Shared на каждом уровне») — вырожденно.** Общие переменные
  root-центричны (`shared_variables` считает нужды от корня), поэтому владелец —
  только корень, а промежуточные уровни `Shared` ретранслируют. Многоуровневый
  случай (`extend_complex`) компилируется и верен (A9).
- **Вынос в новый модуль `rust_shared.rs`** сверх задач/02 — потребовал
  храповик размера (`rust_model.rs` вышел бы за baseline). Baseline обновлён.

### Найденные дефекты

Нет. Побочная находка (5 `#[allow]` в самом генераторе) — вне объёма, кандидат.

### Примечание об эталоне

Правка меняет **способ доступа** к переменным (`busy` → `shared.busy`) — класс,
где ошибка тихая. Поэтому основной критерий — A4 (потактовая сверка), а не проверка:
проверка доказывает компилируемость, но не верность. A4 выполнен.

## Итог проработки (2026-07-17)

**Суть переформулирована замером.** `rust_model.rs:920` — **единственное место во
всём генераторе, эмитящее `#[allow]` в порождаемый код**, то есть единственное
исключение из политики (а) [ADR](0050-rust-backend.md#архитектура-adr) («не эмитить
то, на что линт ругается; контроль должен остаться живым»). Заглушка ставится по
условию `1 + shared.len() + hal > 7` (порог 7, `self` **входит**).

| Под-модель `stacker` | `shared` | Параметров | Заглушка |
|---|---|---|---|
| `CommandReceiver` | 6 | 8 | **да** |
| `MovementController` | **8** | **10** | **да** |
| `LiftController` | 3 | 5 | нет |

**Кандидат ошибался на единицу, и та же ошибка живёт в коде.** «У
`MovementController` их девять» — на деле **девять** переменных у **корня**, а
`MovementController` разделяет **восемь** (все, кроме `eta`). Заявка «10
параметров» верна (`self` + `hal` + 8). Комментарий `rust_model.rs:911` повторяет
ту же ошибку — правится задачей. Отсюда же наблюдение, важное для решения:
**`shared` считается по каждой под-модели отдельно**, минимумом по нуждам.

**Принято** ([ADR](0059-rust-shared-struct.md#архитектура-adr), Option A): `Shared` —
**объединение нужд под-моделей** (не «все переменные корня»), приватное поле
композирующей модели, передаётся `&mut Shared`; заглушка исчезает **по построению**
(параметров всегда ≤ 3). Ключ, которого не было у 0050: **E0499 даёт `&mut self`,
а не «структура»** — `&mut self.hal` и `&mut self.shared` суть раздельные поля,
поэтому довод, по которому 0050 отвергла указатель на корень, к `Shared` не
применим. Отклонены: структура ссылок на под-модель (множит типы, переносит
многословность в место вызова), статус-кво, `Shared` по порогу (форму вывода
начал бы определять порог линта → две формы, два пути кода).

**Цена принята осознанно:** теряется минимальность интерфейса (сигнатура перестаёт
показывать связность под-модели) и дифф корпуса будет широким — правятся
`stacker`, `elevator`, `elevator_mini`, `extend_complex`. Критерий «корпус
побайтово прежний» здесь **неприменим** (в отличие от 0058), поэтому **основным**
критерием назначена потактовая сверка: правка меняет **способ доступа** к
переменным — класс, где ошибка тихая (урок: неверное чтение приняли **оба**
инструмента SV). Язык не меняется → версия не растёт (правило 22).

**Побочная находка, вне объёма** (заведена кандидатом, правило 7): в самом
генераторе — **пять** `#[allow(clippy::too_many_arguments)]`
(`rust_model.rs:389, 598, 695, 830, 1204`). Политику (а) они не нарушают (та про
порождаемый код), но воспроизводят ту же болезнь уровнем выше.

## Итог (что сделано)

**Закрыта** (`ГОТОВО`, 2026-07-18). Общие переменные корня свёрнуты в структуру
`<Root>Shared`; единственное `#[allow]` в порождаемом коде исчезло — политика (а)
ADR стала безысключительной.

- **Крейт `grammar`** (`generator/rust/`): новый модуль
  [`rust_shared.rs`](../../takt-lang/src/generator/rust/rust_shared.rs) — вся
  логика общих переменных (`shared_variables` перенесён из `rust_model.rs`,
  `shared_union` = объединение нужд под-моделей, `shared_type_name`,
  `emit_shared_struct`, `emit_shared_new_block`). Вынос держит `rust_model.rs` под
  храповиком размера (0027). Корень владеет полем `shared: <Root>Shared`; под-модель
  получает `&mut Shared` **одним** параметром (`hal` — последним, правило 5);
  доступ — `Scope.shared_via_self` (`self.shared.x` у корня, `shared.x` у
  под-модели). Заглушка `#[allow(clippy::too_many_arguments)]` в `emit_tick`
  снята: параметров такта всегда ≤ 3.
- **Уточнение реализации к ADR:** тип `Shared` — **один на корень** (`<Root>Shared`,
  а не голое `Shared`): в плоском модуле цели `rust` модели соседствуют, и голое
  имя столкнулось бы. Многоуровневая композиция (`extend_complex`) обслуживается
  **одним** `ExtendComplexShared`, ретранслируемым `root → C → CC1` (общие
  переменные root-центричны). Правило 4 ADR («Shared на каждом композирующем
  уровне») выполнено вырожденно: только корень владеет общими переменными.
- **Проверка:** корпус (`stacker`/`elevator`/`elevator_mini`/`extend_complex`)
  проходит `rustc` + `clippy -D warnings` **без единой заглушки** (A1–A3);
  `conformance_rust_tests` вердикты **не изменились** (A4 — основной критерий:
  правка меняет способ доступа к переменным, класс тихой ошибки); прочие цели
  побайтово прежние (T14); `comprehensive` `Shared` не получает (A6). 3 новых
  юнит-теста (A5/A6/A7). 1988 тестов зелёные.

Дифф корпуса **широкий и осмысленный** (детерминизм 0048): наружный контракт
(`new`/`init`/`tick`/`is_done`, `Hal`, порты, поведение) неизменен. Baseline
храповика обновлён (`rust_model` 1361→1349, `rust_expr` 1126→1125). Язык не
менялся → версия не росла (правило 22). Детали, задачи/02,
отчёт [0059-rust-shared-struct.md#отчёт-о-тестировании](0059-rust-shared-struct.md#отчёт-о-тестировании).
