## Краткое описание

Панель структуры показывает список доступных проектов всегда: сверху — где
работать, снизу — с чем. Проект выбирают в списке, а кнопки над ним открывают,
переименовывают и удаляют **выбранный**. Окно выбора проекта упразднено.

> жизненный цикл по своду.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-10
- **Authors:** заказчик (требование), разработка

### Context

Список проектов жил в модальном окне: чтобы увидеть, что у тебя есть, надо было
позвать разговор, а после первого же открытия окно пряталось — и где автор
находится, панель не показывала. Удаление стояло мусоркой в строке списка,
переименования проекта не было вовсе.

### Decision

Список — часть панели, а не разговор: он стоит над составом открытого проекта и
виден всегда. Выбор в списке — величина страницы (`chosen`), и действия над
проектом обращены к нему: открыть, переименовать, удалить.

Право спрашивается у выбранного: переименование и удаление показываются только
владельцу — предлагать действие, которое сервер отвергнет, нельзя.

Границу между списком и составом двигает читатель: у каждой части свой предмет,
и общая ручка меняла бы не то, что тянут.

### Consequences

Окно выбора проекта снято вместе со своей кнопкой отмены. Двойной щелчок по
строке открывает проект — тот же приём, что у списка файлов на машине.

Без входа список говорит словами, что для него нужен вход: пустая область
читалась бы как поломка.

## Разработка

### Задача — список в панели

`list()` рисует строки-кнопки прямо в панели (`#projects`), отмечает выбранный
(`aria-pressed`) и забывает выбор, если проекта в списке больше нет: отметка на
пустом месте обманывала бы кнопки. Список рисуется при подключении, после входа,
выхода, заведения, переименования, удаления и загрузки архива.

### Задача — действия над выбранным

`openChosen`, `openProjectRename`, `openDropChosen` спрашивают выбор и говорят
словами, если его нет. Переименование зовёт `PATCH` с новым именем и обновляет
подпись открытого проекта, если переименовали его же.

### Задача — граница списка и состава

Своя ручка (`attachProjects`, ключ `takt.ui.projects`, умолчание — треть панели)
с теми же правилами, что у прочих: границы, память, клавиатура.

### Проверки

`check-web.sh` (105 тестов; два набора переписаны под новое устройство панели),
`check-design.py` (445 правил), прогон страницы на сервере с базой.

## Отчёт о тестировании

### Резюме

Требование выполнено, проверки зелёные.

### Фактические результаты по проверкам

1. Список виден без всякого разговора; выбранный проект отмечен.
2. «Открыть» открывает выбранный: дерево показывает его состав, список остаётся
   на месте.
3. «Переименовать» меняет имя: `demo` → `demo-2` в списке и в сообщении.
4. «Удалить» спрашивает по имени и уносит проект из списка; открытый при этом
   закрывается.
5. Кнопки переименования и удаления показываются только владельцу.

### Найденные дефекты

Свой, закрыт по ходу: обработчик старого списка пережил переезд и лез в снятое
окно — щелчок по строке валился `Cannot set properties of undefined`. Прогон
страницы это и показал; тестам класс невидим — они читают исходники, а не
исполняют их.

## Итог (что сделано)

Панель структуры отвечает на два вопроса подряд: где работать и с чем. Список
проектов перестал быть разговором, а действия над проектом — гаданием, к какому
из них они относятся.
