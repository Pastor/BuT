## Краткое описание

Признак «локальная не используется» (0376) считал **запись** использованием,
поэтому `var spare: u8 := 0; spare := n + 5;` без единого чтения заглушки не
получал. Замер-22 показал, что класс шире, чем предполагал кандидат:

| Потребитель | Ответ на вывод |
|---|---|
| `c`, `c-hal` | `cc -Wall -Wextra -Werror`: **`variable 'spare' set but not used`** |
| `rust` | `rustc -D warnings`: **`unused variable: spare`** |
| `sv`, `sv-mmio` | `verilator -Wall`: **`UNUSEDSIGNAL`** |
| `st`, `st-at` | принимают |
| эталон | исполняет |

То есть вывод **пяти** целей отвергают их же инструменты при **нулевом** коде
возврата `taktc`. Семантика при этом молчала: `SE-036` (0386) считала запись
использованием.

семантика прежние. Расширяется область срабатывания уже описанного
предупреждения и состав вывода целей.

### Context

Признак «локальная не используется» (0376) считал **упоминание** использованием,
в том числе запись. Поэтому `var spare: u8 := 0; spare := n + 5;` без единого
чтения заглушки не получал. Замер-22 (`scripts/probe.sh` + прогон
инструментов):

| Потребитель | Ответ на вывод |
|---|---|
| `c`, `c-hal` | `cc -Wall -Wextra -Werror`: `variable 'spare' set but not used` |
| `rust` | `rustc -D warnings`: `unused variable: spare` |
| `sv`, `sv-mmio` | `verilator -Wall`: `UNUSEDSIGNAL` |
| `st`, `st-at` | принимают |
| эталон | исполняет |

Пять целей из восьми порождают вывод, который отвергают **их же** инструменты,
при нулевом коде возврата `taktc`. Семантика молчала: `SE-036` считала запись
использованием.

Кандидат называл вопрос узко («отвечает ли `cc -Wunused-but-set-variable` —
не измерялось»). Прогон показал класс шире: `rust` и `sv` ломаются тоже, причём
у `sv` заглушки для обычной локальной не было **вовсе** (0376 покрыла `c` и
`rust`).

### Decision Drivers

1. **Невалидный вывод при нулевом коде возврата** — самый дорогой класс после
   молчаливого расхождения значений.
2. **Признак один на семантику и цели** (0386): расходиться им нельзя.
3. **Мёртвая переменная — это и сообщение автору**: компиляторы C и Rust
   предупреждают ровно так же.
4. **Идиома принадлежит целевому языку**, а признак — общий (0260/0337/0376).

### Considered Options

#### Option A. Оставить признак прежним, гасить у целей «по тексту»

**Cons:** знание раздвоится (что считать использованием — в двух местах), а
`SE-036` продолжит молчать о мёртвой переменной.

#### Option B. Считать использованием только чтение

Признак спрашивает чтения: цель присваивания — место записи, а не чтение;
внутри неё читаются индексы и базы (`arr[i] := 5;` читает `i`, не `arr`).

**Pros:**
- один признак служит и заглушке целей, и `SE-036`;
- совпадает с тем, что говорят `cc` и `rustc` про свой же код;
- у `sv` появляется недостававшая заглушка.

**Cons:**
- меняет поведение только что закрытой 0386 (её граница «запись = использование»
  снимается) — это осознанное решение, а не побочный эффект;
- риск шума: замер по корпусу обязателен.

### Decision

Принимается **Option B**.

Режим сбора задаётся полем `UsageSet::reads_only` — **флагом вместо второго
обхода**: копия правила «что считать упоминанием» разошлась бы с оригиналом
молча. Признак локальных (`unused_locals_of_block`)
включает его; фильтры печати целей (`compute_usage`) — нет: там вопрос другой
(«нужно ли имя в выводе»).

Цель `sv` получает **поглотитель** для такой локальной — ту же идиому, что у
неиспользуемого параметра (0337) и поднятых локальных со структурой (0375).

**Присваивание поглотителя печатается после тела:** чтение сигнала раньше
записи verilator встречает `ALWCOMBORDER` («behavior may imply latch»), а проверка
цели считает предупреждение ошибкой. Это выяснилось прогоном — первая редакция
печатала поглотитель рядом с объявлением.

### Consequences

#### Положительные

- Вывод пяти целей начинает собираться под флагами их проверок.
- `SE-036` сообщает автору о мёртвой переменной, а не молчит.
- Знание одно: и семантика, и цели спрашивают один признак.

#### Отрицательные / Action items

- Граница 0386 («запись считается использованием») снята — поведение
  предупреждения расширено осознанно.
- Возможен шум: замер по корпусу дал **ноль** новых предупреждений (единственное
  существующее — `var action` уровня модели в `elevator.takt`).

#### Acceptance criteria

1. Порождённый C собирается под флагами проверки (`-Wall -Wextra -Werror`).
2. Вывод всех восьми целей принимают их инструменты.
3. `SE-036` предупреждает о записанной-непрочитанной локальной.
4. Поведение не изменилось (трасса эталона прежняя).
5. Мутация «запись снова считается чтением» роняет контроля.
6. Корпус не даёт новых предупреждений; `precheck.sh` зелёный.

## Анализ

### Цель и контекст

Признак 0376 считал запись использованием, и локальная, которую тело только
пишет, оставалась без заглушки. Фича сужает признак до **чтений** и достраивает
заглушку у цели `sv`.

### Замер (правило 30, дата 2026-08-22)

Вход: `var spare: u8 := 0; spare := n + 5;` в теле `always`, без чтений.

| Потребитель | До фичи | После |
|---|---|---|
| `c`, `c-hal` | `cc`: `variable 'spare' set but not used` (**-Werror**) | принял |
| `rust` | `rustc`: `unused variable: spare` | принял, `clippy` принял |
| `sv`, `sv-mmio` | `verilator`: `UNUSEDSIGNAL` | принял, `yosys` синтезировал |
| `st`, `st-at` | принимали | принимают |
| эталон | исполнял | исполняет (трасса та же) |
| `SE-036` | молчала | предупреждает |

**Промежуточный замер** (после сужения признака, до правки `sv`) дал у цели
`sv` **другую** ошибку — `ALWCOMBORDER`: поглотитель читал сигнал раньше записи.
Класс двухслойный, замер снимался дважды.

**Шум:** прогон по всем `examples/*.takt` — ноль новых предупреждений.

## Разработка

### Задача

#### Что было

Признак «локальная не используется» (0376) считал запись использованием.
`var spare: u8 := 0; spare := n + 5;` без чтений заглушки не получал, и вывод
пяти целей отвергали их же инструменты при нулевом коде возврата `taktc`;
`SE-036` при этом молчала.

#### Что сделано

**1. Режим чтений вместо второго обхода.** У `UsageSet` появился флаг
`reads_only`: цель присваивания считается **местом записи**, а не чтением;
внутри неё читаются индексы и базы (`arr[i] := 5;` читает `i`, не `arr`).
Флаг — вместо копии обхода: второе правило «что считать упоминанием»
разошлось бы с первым молча.

**2. Признак локальных включает режим.** `unused_locals_of_block` спрашивает
чтения; тем самым чинятся сразу заглушка целей `c`/`rust` (0376) и `SE-036`
(0386) — знание одно.

**3. У цели `sv` появился поглотитель обычной локальной.** Прежде он был
только у поднятых со структурой (0375); идиома та же —
`logic _unused_x; … _unused_x = &{1'b0, x};`.

**Присваивание поглотителя печатается после тела.** Первая редакция ставила
его рядом с объявлением, и verilator ответил `ALWCOMBORDER` («always_comb reads
'spare' before assigning it later in the same block») — проверка цели считает
предупреждение ошибкой. Класс двухслойный: замер снимался дважды.

Статус по функциональности (правило 11): правка в семантике
(`semantic/unused.rs`) и у цели `sv`; цели `c`/`rust` починились сами —
заглушка у них была, не хватало признака. Редакторский слой — «н/п».

#### Проверки

```sh

```

- **Инструменты** (T1, T2): все восемь целей переводят, вывод принимают `cc`
  (с флагами проверки), `iec2c` + `cc`, `rustc` + `clippy`, `verilator` + `yosys`.
- **Поведение** (T4): трасса эталона `1, 2, 3` — прежняя.
- **`SE-036`** (T3): предупреждение выдаётся с координатой объявления.
- **Мутация** (T7): «запись снова считается чтением» роняет сборку
  порождённого C.
- **Шум** (T8): прогон по всем примерам корпуса — ноль новых предупреждений.

### Выводы и дальнейшие шаги

**1. Кандидат называл вопрос уже, чем он есть.** Запись гласила: «отвечает ли
`cc -Wunused-but-set-variable` — не измерялось». Прогон показал, что вывод

`UsageSet::reads_only`, а не вторым обходом: копия правила «что считать
упоминанием» разошлась бы с оригиналом молча. Тем же
изменением починились сразу заглушка целей и `SE-036`.

**4. Граница 0386 снята осознанно.** Та фича закрывалась с оговоркой «запись
считается использованием»; здесь оговорка снята, и предупреждение стало точнее
— ровно как у `cc` и `rustc` про их собственный код.

**5. Кандидаты.** Закрытие снимает кандидата «Локальная переменная, записанная
но не прочитанная».

**Вердикт: ГОТОВО.**

## Итог (что сделано)

- Признак «локальная не используется» спрашивает теперь **чтения**: цель
  присваивания — место записи, а не чтение (внутри неё читаются индексы и
  базы). Тем самым починились сразу заглушка целей `c`/`rust` (0376) и
  предупреждение `SE-036` (0386) — знание одно.
- **Режим задан флагом `UsageSet::reads_only`, а не вторым обходом:** копия
  правила «что считать упоминанием» разошлась бы с оригиналом молча. Фильтры печати целей режим **не** включают — там вопрос
  другой («нужно ли имя в выводе»).
- **У цели `sv` появился поглотитель обычной локальной** (прежде он был
  только у поднятых со структурой, 0375), и присваивание печатается **после
  тела**: чтение сигнала раньше записи verilator встречает `ALWCOMBORDER`, а
  проверка цели считает предупреждение ошибкой. Класс двухслойный — замер снимался
  дважды.
- **Кандидат называл вопрос уже, чем он есть:** «не измерялось, отвечает ли
  `cc`». Прогон показал отказ инструментов **пяти** целей при нулевом коде
  возврата `taktc`.
- Граница 0386 («запись считается использованием») снята осознанно.
- Поведение не изменилось; корпус даёт ноль новых предупреждений.

Детали — в [отчёте](0387-write-only-local.md#отчёт-о-тестировании).
