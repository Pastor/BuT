# Фича: Имя модели совпадает с именем файла — путь до состояния

- **Номер:** 0469
- **Статус:** ГОТОВО
- **Зависит от:** нет
- **Tier:** 2 (корректная программа не компилируется тремя целями; при
  «половинной» починке — молчаливо неверное поведение: тикал бы контейнер)
- **Класс:** семантика
- **Связанные issue (анализ):** кандидат, заведённый фичей
  [позиции у отказов целей — второй слой носителя](0468-target-refusal-position.md)

## Стадии жизненного цикла

Все стадии — **разделы этой карточки**. Отдельным артефактом
остаются только исправления — [`docs/fixes/`](../fixes/README.md).

## Краткое описание

Вход `import "clash.takt"; start Main = Clash;`, где файл `clash.takt`
объявляет модель `Clash`, отвергали три цели: «Состояние
'Work (App:Clash:Clash:Work)' не найдено». Причина — порядок разбора
уникального имени: последний сегмент сперва сверялся с **самим узлом** и лишь
потом искался среди детей, поэтому одинаковые сегменты подряд возвращали
контейнер файла вместо модели.

## Документирование

**Не требуется:** язык не меняется. Форма `import "файл"; start S = Файл;`
работала и раньше — она не работала лишь при совпадении имён.

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-09-01
- **Authors:** архитектор

### Context

Замер-01. Вход:

```takt
// clash.takt
model Clash { … }
start Root = Clash;

// app.takt
import "clash.takt";
start Main = Clash;
```

| Цель | Ответ до фичи |
|---|---|
| `c` | `CC-005` «Состояние 'Work (App:Clash:Clash:Work)' не найдено» |
| `rust` | `RS-013`, то же имя |
| `sv` | `SV-011`, то же имя |
| `st` | `ST-013` «Автомат ST: Work» |
| `plantuml` | переводит (карту состояний строит иначе) |

Управляемый эксперимент: переименование модели внутри файла (`model Worker`)
делает вход рабочим у всех целей. Значит дело не в импорте как таковом, а в
**совпадении** имени модели с именем файла: полный импорт вносит контейнер под
именем файла, и путь получает два одинаковых сегмента подряд.

Разбор `model_by_unique_name`: последний сегмент проверялся в порядке
«сам узел → `search_model`». На пути `App:Clash:Clash` это возвращало
**контейнер** (его имя тоже `Clash`), у которого искомого состояния нет.

Дефект **двухслойный**. После починки пути вывод трёх целей стал валиден, но
`rust` печатал `self.root.tick(&mut *hal)` в функции **без** параметра `hal`
(`E0425`): признак «нужен ли HAL» искал ребёнка по **локальному** имени среди
моделей карты, находил одноимённый контейнер, чей `unique` уже лежал в `seen`,
и отвечал «не нужен».

### Decision

1. **Приоритет прямому ребёнку.** В последнем сегменте пути сперва
   спрашивается `models.get(имя)`, затем «это сам узел», затем общий
   `search_model`. Подменить первую проверку общим `search_model` нельзя: он
   поднимается по `upper` и нашёл бы контейнер в словаре родителя — тот же
   неверный ответ.
2. **Ребёнок ищется по уникальному имени.** Признак HAL строит
   `<unique родителя>:<local ребёнка>` и лишь при неудаче падает на прежний
   поиск по локальному имени — он нужен детям **по вызову** (`= M`, `A | B`),
   которые живут в карте под своим уникальным именем.
3. **Случай входит в матрицу** новым видом обращения `ImportNameClash`: его
   проверяют все восемь целей и их инструменты, а корпус матрицы выгружается
   плагинам редакторов.
4. **Поведение сверяется потактово.** Компиляции мало: путь мог бы
   разрешиться в контейнер, вывод собрался бы, а тикала бы не та модель —
   отличает исходы только трасса порта.

### Considered Options

- **A. Приоритет ребёнку** — принят: чинит причину и не трогает форму имён.
- **B. Отказ семантики «имя модели = имя файла»** — отвергнут: правило сломало
  бы корпус (`examples/regulator.takt` объявляет `model Regulator`), а сама
  запись законна — мешало только разрешение пути.
- **C. Запретить одинаковые сегменты подряд в `unique`** — отвергнут: имя
  строится из дерева, и запрет означал бы переименование за автора.

### Consequences

Вывод корпуса не меняется: путей с одинаковыми сегментами подряд в нём нет.
Матрица растёт на один вид обращения (35 → 36 видов, 295 → 300 случаев).

**Побочное следствие для реестров 0467.** Вход, дававший «Состояние … не
найдено», стал корректным — и четыре кода (`CC-005`, `RS-013`, `SV-011`,
`ST-013`) корпус больше не порождает вовсе. Проверка качества диагностик это и
сказал: записи переехали из реестра позиций (долг 13 → 9) в реестр покрытия
(161 → 165). Это не потеря: код без входа проверяется юнит-тестом, и реестр
честно называет, что проверки целей его не видят.

#### Acceptance criteria

- A1. Вход со столкновением имён переводят **все восемь** целей.
- A2. Инструменты целей принимают вывод.
- A3. Трасса цели `c` совпадает с эталоном — тикает модель, а не контейнер.
- A4. Обе мутации (приоритет ребёнка, поиск по уникальному имени) роняют
  контрольных тестов.

## Анализ

### Цель и контекст

Предмет — **разрешение пути до состояния** при совпадении имён. Проверяемое
условие: путь ведёт к модели, чьё состояние ищут, а поведение цели совпадает с
эталоном.

### Замер

1. Таблица ответов целей — в разделе Context.
2. Управляемый эксперимент с переименованием: дефект исчезает.
3. После починки пути: `cc`, `verilator` принимают вывод, `clippy` отвечает
   `E0425` — второй слой.
4. После починки признака HAL: все инструменты принимают; трасса цели `c`
   (`1, 2, 3`) совпадает с эталоном (`1, 2, 3, 3` — четвёртый такт значение
   удерживает, записи нет).

### Зависимости фичи

Смежное: 0456 (усыновление имён при импорте), 0184 (импортированное объявление
— объявление импортёра), 0419/0449 (признак «нужен указатель»).

### Требования и проверяемые условия

- R1. A1…A4 выше.
- R2. Прежние формы импорта не затронуты: полный, выборочный, транзитивный,
  вложенная модель (законный `SE-106`).

### Критерии приёмки и способ проверки

Вид `ImportNameClash` в матрице (перебор 0450 по восьми целям, признак
указателя 0449), потактовая сверка
`takt-sim/tests/conformance/conformance_import_name_clash_tests.rs`, мутации,
полный `precheck.sh`.

### Редакторский слой

**Не затронут:** лексика и синтаксис не менялись. Корпус матрицы, который
получают плагины, пополнился новым видом автоматически.

### Особенности по обратной функциональности

Вход, прежде отвергавшийся тремя целями, теперь переводится всеми восемью.
Обратной несовместимости нет: отказ был дефектом, а не правилом.

### Риски и зависимости

Риск — изменить разрешение там, где прежний порядок был верен. Он сужен:
меняется **только** последний сегмент пути, и только добавлением более точной
проверки перед прежними. Контроль — вся матрица (300 случаев × 8 целей), она
покрывает и обычные импорты, и композиции.

## Итог

Столкновение имени файла с именем модели в нём перестало быть ловушкой:
путь до состояния ведёт к модели, а не к контейнеру. Дефект оказался
двухслойным — вторым слоем был признак «нужен ли HAL», искавший ребёнка по
локальному имени; его нашёл прогон инструмента, а не чтение кода.
