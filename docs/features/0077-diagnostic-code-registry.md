## Краткое описание

[заглушки генератора C: диагностика вместо тихого пропуска](0028-c-generator-stubs.md) держала **Accepted**-ADR на код `CC-014`

заняла `CC-014`/`CC-015` под непредставимые в C типы, затем `CC-016` (ширина порта)
и `CC-017` (инициализатор массива). Обе фичи выбирали код **грепом свободного** и
друг друга не увидели — то есть механизм выдачи кодов **не защищает от коллизий**.

Ближайшее лечение применено: 0028 при реализации взяла `CC-018` и далее.
**Системное** — реестр кодов диагностик в одном месте: сейчас коды живут только в
коде и в таблице `README.md`, пополняемой **вручную**.

Выявлено при реализации [генератор C: отображение типов Array/Bit/Rational](0029-c-type-mapping.md).

- **Related issues:** [Фича](0077-diagnostic-code-registry.md); прецедент [ADR](0027-module-size-split.md#архитектура-adr) (проверяемое машиной, — baseline-файл + проверка); повод — [генератор C: отображение типов Array/Bit/Rational](0029-c-type-mapping.md)/[заглушки генератора C: диагностика вместо тихого пропуска](0028-c-generator-stubs.md) (коллизия `CC-014`).

### Context

Коды диагностик (`SE-036`, `CC-014`, `SIM-010`, `AM-001`, …) выдаются **голыми
строковыми литералами** через `Diagnostic::with_code(&str)` (≈330 мест в
`grammar`, плюс два централизованных `code()`-диспетчера — `lexer::LexicalError`
и `eval::EvalError`). **Валидации формата и уникальности нет.** Новый код
выбирается **грепом «последнего занятого»** в префиксе — именно так фичи и
0029 независимо взяли `CC-014` и друг друга не увидели (коллизия; лечение — 0028
переехала на `CC-018`).

Документация кодов — **вручную** пополняемые таблицы, разбросанные по `README.md`
(раздел 7 для LE/SY/SE/CC/SIM; отдельные таблицы целей RS/SV; таблица DF в разделе
карты адресов). Реестр **отстаёт от кода**: `AM-001…006` и `PU-001` не описаны
вовсе, `ST` — лишь 2 кода из 13.

Инвентаризация (grep по `*/src`): **11 префиксов**, ~173 уникальных кода. Формат
единообразный `XX-NNN` (2–4 буквы, дефис, 3 цифры) — отклонений нет. В нумерации
есть **пропуски** (`CC-009`, `SE-024/031/032`, `ST-003`…) — норма (код выведен/
зарезервирован).

| Префикс | Слой | Префикс | Слой |
|---|---|---|---|
| LE | лексика | ST | цель Structured Text |
| SY | синтаксис | SV | цель SystemVerilog |
| SE | семантика | DF | флаг `--define` |
| CC | цель C | AM | парсинг карты адресов |
| RS | цель Rust | PU | цель PlantUML |
| SIM | симулятор (`EvalError`) | | |

**Корневая проблема — не в кодах, а в отсутствии единого проверяемого места:**
источник истины размазан по коду и ручным таблицам, ничто не гарантирует ни
уникальности, ни синхронности код↔документация.

### Decision Drivers

1. **Коллизия обязана ловиться машиной, а не дисциплиной.** Прецедент правила
   размера модуля: правило, живущее только в тексте, не работает
   (`validate.rs` дорос до 3654 строк). Реестр без проверки повторит судьбу README.
2. **Синхронность код↔документация — проверкой, а не ревью.** «AM/PU/ST не описаны» —
   прямое следствие ручного пополнения; проверка обязан валить сборку на
   незарегистрированном коде.
3. **Аддитивность (правило 11).** Решение не должно переписывать ≈330 мест
   `with_code` — риск регресса огромен, польза над проверкой маргинальна.
4. **Единый источник истины.** Одно место, где виден весь занятый диапазон и
   «следующий свободный» номер в префиксе, — чтобы греп-и-угадай стал не нужен.
5. **Соразмерность.** Не строить генератор/БД там, где хватает текстового реестра
   и shell-проверки (как `check-module-size.sh`).

### Considered Options

#### Option A. Единый реестр-файл + машинный проверка (валидация, не типизация)

Единый **источник истины** — `docs/diagnostics/README.md`: одна таблица, **каждый
код ровно раз** (код · значение · слой/источник · фича). Проверка
`scripts/check-diagnostic-codes.sh` в `precheck.sh`:

- извлекает коды, **эмитируемые исходником** (`with_code("…")` + оба
  `code()`-диспетчера — тоже строковые литералы);
- **двусторонняя** сверка: каждый эмитируемый код ∈ реестр (ловит
  незадокументированный AM/PU/ST); каждая строка реестра ∈ исходник **или** помечена
  `RESERVED`/`RETIRED` (ловит протухшую);
- **формат** `XX-NNN`; **дубль строки** реестра → ошибка;
- печатает **по префиксам максимальный занятый номер** (даёт «следующий свободный»).

**Pros:**
- Коллизия и рассинхрон ловятся `precheck.sh`/CI — драйверы 1, 2.
- Аддитивно: `with_code(&str)` не тронут, ≈330 мест целы — драйвер 3.
- Единое место + «следующий свободный» — драйвер 4; прецедент 0027 — драйвер 5.
- Реестр строится один раз извлечением из исходника → полнота гарантирована проверкой.

**Cons:**
- Уникальность проверяется **в precheck**, а не компилятором (окно между правкой
  и проверкой). Смягчено: проверка в CI обязателен, локально — в `precheck.sh`.
- Разовая миграция ~173 строк реестра (бутстрап скриптом из исходника).

#### Option B. Типизация: `with_code(DiagnosticCode)` (enum)

Заменить строковые литералы enum-ом (`DiagnosticCode::SE036`), уникальность —
вариантами enum (компайл-тайм).

**Pros:**
- Уникальность и полнота — гарантия компилятора; автодополнение в IDE.

**Cons:**
- ≈330 мест в **двух** крейтах + enum на ~173 варианта (риск лимита размера
  модуля 0027) — грубое нарушение драйвера 3 (аддитивность).
- Польза над проверкой маргинальна: проверка ловит те же коллизии в precheck; enum не
  решает рассинхрон с **документацией** (значение всё равно вне типа).
- `code()`-диспетчеры (lexer, eval) пришлось бы переплести с общим enum через
  границу крейтов (`simulation` → `grammar`).

#### Option C. Только линт-скрипт без файла-реестра

Проверка проверяет лишь «формат» и «нет двух `with_code` с разным текстом на один код».

**Pros:** минимум артефактов.

**Cons:**
- Семантическую коллизию (один код — два **разных** смысла) из строк **не
  вывести**; не чинит рассинхрон с документацией (драйвер 2) — реестра-то нет.
  Недостаточно.

### Decision

Принимается **Option A**. Единый реестр-файл + проверка — прямой аналог
проверяемого-машиной правила размера модуля, аддитивный (драйвер 3) и
соразмерный (драйвер 5). Enum (B) отвергнут ценой/риском при маргинальной пользе;
линт без реестра (C) не чинит документацию и семантическую коллизию.

- **Источник истины:** `docs/diagnostics/README.md` — таблица `Код · Значение ·
  Слой/источник · Фича`, по одной строке на код, отсортирована по префиксу и
  номеру. Значение мигрируется из README/комментариев; пробелы **AM/PU/ST**
  заполняются здесь (полнота — под проверкой).
- **Проверка** `scripts/check-diagnostic-codes.sh` (POSIX sh, как `check-module-size.sh`),
  включён в `precheck.sh` **и** в CI (через тот же `precheck.sh`):
  1. извлечь `EMITTED` = коды из `grammar/src` + `simulation/src`
     (`with_code("…")` и литералы в `code()`-диспетчерах);
  2. извлечь `REGISTERED` = коды из таблицы реестра;
  3. `EMITTED ∖ REGISTERED ≠ ∅` → **ошибка** «код эмитируется, но не в реестре»;
  4. `REGISTERED ∖ EMITTED` минус `RESERVED`/`RETIRED` → **ошибка** «код в реестре
     протух»;
  5. дубль кода в реестре, нарушение формата `XX-NNN` → **ошибка**;
  6. печать по префиксам максимального номера (справка «следующий свободный»).
- **`with_code(&str)` Не меняется** — аддитивность. Doc-комментарий метода
  дополняется ссылкой на реестр и правилом «новый код — сперва в реестр».
- **README раздел 7 и таблицы целей:** остаются как **человеческое** описание, но
  **перестают быть источником истины** — над каждой добавляется ссылка «полный
  реестр — `docs/diagnostics/`». Их полнота больше не требуется (реестр полон по
  проверке); переписывать их — **вне объёма** (риск/объём; драйвер 5).

**Обратная совместимость (правило 11):** ни один код не меняется, ни одно место
`with_code` не трогается → **вывод компилятора и симулятора байт-в-байт неизменен**
(тексты и коузы диагностик те же). Изменение — новый документ + новая проверка +
дозаполнение документации. Версия языка **0.3.0** без изменений; версии крейтов
без изменений (публичный API не тронут).

### Consequences

#### Положительные

- Коллизия кодов и рассинхрон код↔документация ловятся `precheck.sh`/CI.
- Один машинно-проверяемый список всех кодов; «следующий свободный» виден сразу.
- Пробелы документации (AM/PU/ST) закрыты и удерживаются проверкой.

#### Отрицательные / Action items

- Разовая миграция реестра (~173 строки) — бутстрап скриптом из исходника, значения
  курируются вручную.
- Уникальность — в precheck, не в компиляторе (окно правка→проверка). Принято.
- Правило «новый код — сперва в реестр» задокументировать в `docs/CODE.md`/`RULE.md`
  и doc-комментарии `with_code`.

#### Acceptance criteria

1. `docs/diagnostics/README.md` содержит **каждый** эмитируемый исходником код ровно
   один раз, с непустым значением; AM/PU/ST включены полностью.
2. `scripts/check-diagnostic-codes.sh` в `precheck.sh`: зелёный на текущем дереве;
   **краснеет** при (а) новом `with_code` вне реестра, (б) дубле кода в реестре,
   (в) нарушении формата, (г) протухшей записи без `RESERVED`/`RETIRED`.
3. Проверка печатает по префиксам максимальный занятый номер.
4. Ни один код и ни один текст диагностики не изменён — вывод целей и симулятора
   байт-в-байт прежний (двойной прогон `precheck.sh`, детерминизм 0048 цел).
5. README-таблицы несут ссылку на реестр как на источник истины; их переписывание —
   вне объёма (явно).
6. `./scripts/precheck.sh` зелёный.

## Анализ

### Цель и контекст

Сделать выдачу кодов диагностик защищённой от коллизий и рассинхрона с
документацией — **машинно**, а не дисциплиной. По [ADR](0077-diagnostic-code-registry.md#архитектура-adr)
(Option A): единый реестр-файл `docs/diagnostics/README.md` (источник истины) +
проверка `scripts/check-diagnostic-codes.sh` в `precheck.sh`. Прежде коды жили голыми
литералами `with_code(&str)` и грепом «последнего занятого» (так две фичи взяли
`CC-014`), а README-таблицы пополнялись вручную и отставали (AM/PU не описаны, ST —
частично). Прецедент — правило размера модуля: правило без проверки не
работает.

### Зависимости фичи (правило 17/19)

- **Зависит от:** `нет`. Опирается на существующие механизмы (`Diagnostic::with_code`,
  диспетчеры `LexicalError::code()`/`EvalError::code()`), но новой работы от них не
  требует. Прецеденты — ADR (проверка+baseline) и 0090 (CI = один `precheck.sh`).
- **Влияние на порядок разработки:** ничего не разблокирует и не блокирует; чисто
  инфраструктурная фича. Снимает риск будущих коллизий (полезно для любой фичи,
  заводящей новый код).

### Требования и проверяемые условия

- **R1. Полнота.** Реестр содержит **каждый** эмитируемый исходником код
  (`grammar/src` + `simulation/src`) ровно один раз, с непустым значением. Пробелы
  AM-001…006, PU-001, ST (все 13) закрыты.
- **R2. Формат.** Каждый код — `XX-NNN` (2–4 буквы, дефис, 3 цифры). Код-подобный
  литерал иной формы → проверка краснеет.
- **R3. Незадокументированный код.** Новый `with_code("XX-NNN")` без строки в
  реестре → проверка краснеет («код эмитируется, но не в реестре»).
- **R4. Протухшая запись.** Код в реестре, не эмитируемый исходником и без метки
  `RESERVED`/`RETIRED` → проверка краснеет.
- **R5. Дубль.** Один код перечислен в реестре дважды → проверка краснеет.
- **R6. Следующий свободный.** Проверка печатает по каждому префиксу максимальный
  занятый номер (кандидат «следующий» = +1) — грепа больше не нужно.
- **R7. Аддитивность (правило 11).** Ни один код и ни один текст диагностики не
  меняется → вывод целей и симулятора **байт-в-байт** прежний; детерминизм 0048 цел.
- **R8. Источник истины у документации.** README-таблицы несут ссылку на реестр;
  их переписывание — вне объёма.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | R1 полнота (171 код, 0 пустых) | `check-diagnostic-codes.sh` зелёный; grep пустых значений в реестре = 0 |
| A2 | R3–R5 проверка краснеет на нарушении | Негативные пробы: undoc / stale / dup / bad-format → exit 1 (в отчёте) |
| A3 | R4 `RESERVED`/`RETIRED` глушит | Проба: stale-строка с `RESERVED` → exit 0 |
| A6 | R6 печать next-free | Вывод проверки содержит максимум по префиксу |
| A7 | R7 вывод неизменен | `precheck.sh` (двойной прогон + `diff -r`, детерминизм) зелёный |
| A8 | R8 указатели на реестр | README §7 + `with_code` doc + `docs/CODE.md` ссылаются на реестр |
| A9 | Проверка в `precheck.sh` и CI | Строка вызова в `precheck.sh` (CI = тот же precheck) |

### Особенности по обратной функциональности

- **Все 7 целей и симулятор:** не задеты в поведении — `with_code(&str)` не тронут,
  ни одного кода не переименовали. Единственная правка кода — **doc-комментарий**
  `with_code` (комментарий → вывод байт-в-байт неизменен).
- **README/CODE.md:** дополнены указателями (документация, не поведение).
- **CI:** проверка приезжает автоматически — CI гоняет весь `precheck.sh`.

### Риски и зависимости

- **Извлечение EMITTED неполно/шумно.** Снижение: коды — строковые литералы
  `"XX-NNN"` (и `with_code`, и оба диспетчера `code()` — тоже литералы), берём
  их grep-ом по `*/src`; тесты (`*/tests`) исключены (там сверка того же кода).
  Проверено: проверка зелёный на 171 коде.
- **«Значение» не дословно.** Принято: столбец — краткая суть (README/комментарий/
  сообщение), не дословный `format!`. Полнота (не точность прозы) — под проверкой.
- **Окно правка→проверка** (уникальность в precheck, не в компиляторе). Принято ADR;
  CI обязателен.

## Разработка

### Задача

#### Что было

Коды диагностик выдавались голыми литералами `Diagnostic::with_code(&str)` (≈330
мест + два диспетчера `code()`), **без** валидации формата и уникальности. Новый
код выбирался грепом «последнего занятого» — так фичи и 0029 независимо взяли
`CC-014` (коллизия). Документация — вручную пополняемые таблицы `README.md`,
отстающие от кода (AM-001…006 и PU-001 не описаны, ST — 2 из 13). Машинной проверки
кодов не было вовсе.

#### Что сделано

Реализация по [ADR](0077-diagnostic-code-registry.md#архитектура-adr) (Option A) —
единый реестр + машинный проверка (аддитивно, `with_code` не тронут):

- **Реестр** `docs/diagnostics/README.md` — единый источник истины: таблица
  `Код · Значение · Источник` по префиксам (LE/SY/SE/CC/RS/SV/ST/AM/DF/PU/SIM),
  **171 код**, по одной строке. Значения мигрированы из README/комментариев;
  пробелы **AM/PU/ST** заполнены. Соглашения: формат `XX-NNN`, `RESERVED`/`RETIRED`
  для выведенных, «следующий свободный» из справки проверки.
- **Проверка** `scripts/check-diagnostic-codes.sh` (POSIX sh, образец
