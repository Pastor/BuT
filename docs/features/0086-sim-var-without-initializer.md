(«переменная не найдена») — то есть объявленная переменная для симулятора не

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-20
- **Authors:** Архитектор + Дизайнер симулятора
- **Related issues:** [Фича](0086-sim-var-without-initializer.md); прямое продолжение [структурные типы в симуляторе](0034-sim-struct-types.md) (гэп 0034-04)

### Context

Объявление переменной **без инициализатора** (`var q: u8;`) даёт в симуляторе
`SIM-009` («переменная не найдена») при её чтении — то есть объявленная
переменная для симулятора **не существует**.

Механизм (`simulation/src/unit/builder.rs`, `ModelNodeContext::get_value`):
значение переменной вычисляется лениво из её инициализатора
(`eval_expr(var_expr(var))`). У `var q: u8;` инициализатора нет →
`eval_expr` даёт `None`, и **единственный** запасной путь — `default_struct`,
который отдаёт нулевые поля **только структуре**  и `None` для
скаляра. `None` уводит поиск к родителю → имя не находится → `SIM-009` на
чтении.

Комментарий в коде прямо фиксировал это как **осознанный гэп 0034-04**
(«прочие типы без init по-прежнему не регистрируются»). Фича уже установила
политику: **структура без инициализатора → нулевые поля, как default-init в C**.
[`var q: u8;` без инициализатора → `SIM-009`](0086-sim-var-without-initializer.md) распространяет ту же политику на **все** типы.

Дефект — не структурный; выявлен **контрольной** пробой фичи (вне её
объёма).

### Decision Drivers

1. **Объявленная переменная обязана существовать.** Чтение `q` не может быть
   «не найдена», если `q` объявлена — это ловушка, а не диагностика.
2. **Прецедент 0034 уже задал ответ.** Уравнивание с C default-init (ноль) уже
   принято для структур; распространение на скаляры — единообразие, а не новая
   семантика.
3. **Согласованность с C.** Порождённый C zero-инициализирует поля структуры
   модели; значение по умолчанию симулятора (ноль) совпадает — потактовая сверка
   не расходится.

### Considered Options

#### Option A. Общий нулевой умолчание по типу через `default_field`

В ветке «нет инициализатора» вместо `default_struct` вызвать уже существующий
`default_field(ty, model)` — он строит нулевое значение для **любого** типа
(`bool`→false, `rational`→0.0, `fixed`→repr 0, `array`→нули, `struct`→нулевые
поля рекурсивно, целое/enum/bit→0). Тип берётся из `var_type(var)`; `None` только
для `Unresolved` (у которого типа нет — там `SIM-009` уместен).

**Pros:**
- Переиспользует готовый и уже проверенный (0034) слой; `default_struct`
  становится частным случаем и удаляется (дублирование уходит).
- Единая политика «нет init → ноль по типу» для скаляров, массивов, структур.
- Согласовано с C zero-init (драйвер 3).

**Cons:**
- Расширяет умолчание и на `Port`/`Const` без вычислимого инициализатора. Проверено
  прогоном всего корпуса — регресса нет (порт до первой записи драйвером = 0
  вместо падения — улучшение; `const` без init отсекает семантика раньше).

#### Option B. Умолчание только для скаляра (сохранить `default_struct`, добавить `default_scalar`)

**Pros:**
- Точечно, не трогает путь структуры.

**Cons:**
- Заводит **второй** аналог `default_field`, расходящийся с ним со временем
  (тот же запах, что 0034 уже вычистил); массив без init остался бы негодным без
  причины.

#### Option C. Регистрировать переменные заранее (энергично, при построении `Unit`)

Заполнить кэш нулями для всех объявленных переменных на этапе `build`.

**Pros:**
- Явная материализация.

**Cons:**
- Ломает **ленивую** модель `get_value` (кэш заполняется по требованию, 0032);
  энергичная инициализация задевает снимки/`dump` и порядок — несоразмерно.

### Decision

Принимается **Option A**: ветка «нет инициализатора» в `get_value` строит нулевое
значение через `default_field(var_type(var), model)`; `default_struct` удаляется
как частный случай. Политика «нет init → ноль по типу (как C default-init)»
становится общей для всех типов. Уместность нуля для `Unresolved` не возникает
(типа нет → `None` → `SIM-009`, что верно).

### Consequences

#### Положительные

- `var q: u8;` (и любой скаляр/массив/структура без init) существует со значением
  по умолчанию; чтение больше не даёт `SIM-009`.
- Дублирование `default_struct`/`default_field` устранено.

#### Отрицательные / Action items

- **0086-01:** заменить `None => default_struct(...)` на
  `None => var_type(var).map(|ty| default_field(ty, &borrowed))`; удалить
  `default_struct`; фикстура `tests/data/eval/var_no_init.lam` + значенческий
  тест `var_without_initializer_defaults_to_zero`; прогон всего корпуса симуляции
  (регресс портов/констант).
- **Версия языка не поднимается** — правка семантики **симулятора** (не языка);
  синтаксис/семантика Lam и вывод генераторов не меняются.

#### Acceptance criteria

1. `var q: u8;` без инициализатора читается как `0` (u8/bit), `0.0` (q), нулевые
   поля (struct) — вместо `SIM-009`. Значения захвачены прогоном (правило «зонд»).
2. Массивы **осознанно вне объёма исполнения** (нерабочая фича) —
   регистрация массива нулей при этом уже работает, но `.` над массивом остаётся
   негодным (это бит-доступ, не индекс); в фикстуру массив не включается.
3. Весь корпус симуляции (включая conformance C/SV/rust/st) зелёный — регресса
   портов/констант нет.
4. `./scripts/precheck.sh` зелёный; вывод генераторов на корпусе неизменен.

## Анализ

### Цель и контекст

Объявленная переменная без инициализатора должна **существовать** в симуляторе со
значением по умолчанию (нулевым, как C default-init), а не давать `SIM-009` при
чтении. Прямое продолжение [структурные типы в симуляторе](0034-sim-struct-types.md): та ввела
нулевые поля для структур без init, но оставила гэп 0034-04 (скаляры). Решение —
**Option A** ADR: общий умолчание по типу через уже существующий
`default_field`. Правка — только в симуляторе (`unit/builder.rs`).

### Зависимости фичи

- **Зависит от:** **нет.** Строится на закрытой 0034 (механизм `default_field`
  уже есть) — не блокирует. Массивы — вне объёма (нерабочая 0076), но 0086 их
  **не** требует: регистрация массива нулей уже работает, исполнение — за 0076.
- **Влияние на порядок:** ни одна фича очереди от 0086 не зависит; завершение
  никого не разблокирует.

### Требования и проверяемые условия

- **R1. Переменная без init существует.** Чтение скаляра/структуры без init даёт
  нулевое значение по типу, а не `SIM-009`.
- **R2. Ноль — по типу.** u8/bit/enum/целое → `0`; `q(m,n)` → repr 0; bool →
  false; массив → нули; struct → нулевые поля (как 0034).
- **R3. `Unresolved` остаётся `SIM-009`.** Переменная без типа умолчания не
  получает (типа нет) — «не найдена» уместна.
- **R4. Нет регресса портов/констант.** Расширение умолчания на `Port`/`Const`
  без вычислимого init не ломает корпус (порт до записи драйвером = 0 —
  улучшение; `const` без init отсекает семантика раньше).
- **R5. Согласованность с C.** Ноль совпадает с C default-init (прецедент 0034);
  вывод генераторов на корпусе неизменен.

### Критерии приёмки и способ проверки

| # | Критерий | Способ проверки |
|---|---|---|
| A1 | Скаляр без init → 0, не SIM-009 | Значенческий тест `var_without_initializer_defaults_to_zero` (u8/bit/q) на фикстуре `var_no_init.lam` |
| A2 | Чтение в теле проходит | Тот же тест: `seen := q` даёт 0 (значит `q` существует) |
| A3 | Нет регресса симуляции | `cargo test -p simulation -- --test-threads=1` — весь корпус, включая conformance, зелёный |
| A4 | `Unresolved` не задет | `predicate.rs` SIM-009-тест (MockContext, неизвестное имя) остаётся зелёным |
| A5 | Кодоген неизменен | `./scripts/precheck.sh` зелёный; `git diff examples/generated/` пуст |

### Особенности по обратной функциональности

Публичный API `simulation` не меняется (`default_struct` — приватная функция
`unit/builder.rs`, удаляется). Язык, семантика Lam, генераторы — **не задеты**.
Крейт `simulation` версию не поднимает (внутренняя семантика симулятора,
согласованная с уже принятой политикой 0034).

### Риски и зависимости

- **Порт без инициализатора получает 0.** Прежде — `SIM-009` (падение) до первой
  записи драйвером. Ноль-до-записи — улучшение, не регресс; снимается прогоном
  всего корпуса (все conformance-сценарии с портами зелёные).
- **Массив: `arr.N` — бит-доступ, не индекс.** В фикстуру массив не включён,
  чтобы не втянуть нерабочую 0076; регистрация массива нулей при этом уже
  работает (проверено зондом).

## Разработка

### Задача

#### Что было

`ModelNodeContext::get_value` (`simulation/src/unit/builder.rs`) вычисляет
значение переменной лениво из её инициализатора. У `var q: u8;` инициализатора
нет → `eval_expr(var_expr(var))` даёт `None`, а запасной путь
`default_struct(var, &borrowed)` возвращает нулевые поля **только структуре** и
`None` для скаляра:

```rust
match eval_expr(var_expr(var)) {
    Some(v) => Some(coerce_initial(v, var, &borrowed)),
    None => default_struct(var, &borrowed),   // только struct → Some
}
```

`None` уводит поиск к родителю → имя не находится → `SIM-009` на чтении. Гэп был
прямо помечен в комментарии как осознанный (0034-04).

#### Что сделано

Реализовано по **Option A** ADR:

1. **Ветка «нет инициализатора»** отдаёт нулевое значение **по типу** через уже
   существующий `default_field` (он покрывает bool/rational/fixed/array/struct/
   целое единообразно; `default_struct` был его частным случаем):

   ```rust
   None => var_type(var).map(|ty| default_field(ty, &borrowed)),
   ```

   `var_type` даёт `None` только для `Unresolved` → там сохраняется `SIM-009`
   (типа нет — умолчание неоткуда взять; верно).
2. **Удалён** `default_struct` — частный случай `default_field`, дублирование.
3. **Фикстура** `tests/data/eval/var_no_init.lam` (`u8`/`bit`/`q(8,8)` без init +
   наблюдатели) и значенческий тест `var_without_initializer_defaults_to_zero`.

**Статус по функциональности:**

| Функциональность | Работа | Обоснование |
|---|---|---|
| Симулятор (`unit/builder.rs`) | **да** | Общий умолчание по типу; `default_struct` удалён |
| Публичный API `simulation` | **н/п** | `default_struct` приватна; сигнатуры не менялись |
| Язык / семантика / кодоген | **н/п** | Не затрагиваются; версия языка **0.2.0** без изменений |
| Массивы | **н/п** | Регистрация нулей уже работает; исполнение — нерабочая 0076, вне объёма |

#### Проверки

- Значенческий тест `var_without_initializer_defaults_to_zero` (u8→0, bit→0,
  q→repr 0; `seen := q` проходит без SIM-009) — зелёный. Значения захвачены
  зондом, не угаданы.
- `cargo test -p simulation -- --test-threads=1` — весь корпус (вкл. conformance)
  зелёный; регресса портов/констант нет.
- `predicate.rs` SIM-009-тест (истинно неизвестное имя) — зелёный (не задет).
- `./scripts/precheck.sh` зелёный; `git diff examples/generated/` пуст.

### Замечания

- **Массивы вне объёма (осознанно).** Первый зонд включал `arr.1` и упал на
  `SIM-011` — в Lam `.N` это **бит-доступ**, а не индекс, а исполнение массивов —
  отдельная нерабочая [симулятор не исполняет массивы вовсе](0076-sim-arrays.md). Массив из
  фикстуры убран; при этом **регистрация** массива нулей (`Value::Array`) уже
  работает — то есть исправление покрывает и массивы на уровне регистрации.
- **Порты/константы без регресса.** Расширение умолчания на все типы прогнано всем
  корпусом симуляции (все conformance-сценарии с портами зелёные): порт до первой
  записи драйвером = 0 вместо падения — улучшение, `const` без init отсекается
  семантикой раньше.
- **Согласованность с C.** Ноль совпадает с C default-init (прецедент 0034);
  вывод генераторов на корпусе неизменен — потактовая сверка не расходится.

## Итог (что сделано)

Объявленная переменная без инициализатора теперь **существует** со значением по
умолчанию (нулевым по типу), а не даёт `SIM-009`. Принят **Option A** ADR —
прямое продолжение политики 0034 («нет init → ноль, как C default-init»),
распространённой со структур на **все** типы.

Правка — в `ModelNodeContext::get_value` (`simulation/src/unit/builder.rs`): ветка
«нет инициализатора» вместо `default_struct` (только структура) зовёт общий
`default_field(var_type(var), model)` — он строит нулевое значение для любого типа
(bool/rational/fixed/array/struct/целое). `default_struct` удалён как частный
случай (дублирование ушло). `Unresolved` (типа нет) остаётся `SIM-009` — верно.

Проверено **значенчески** (`var_without_initializer_defaults_to_zero` на фикстуре
`var_no_init.lam`: `u8`/`bit`→0, `q(8,8)`→repr 0, чтение в теле проходит); значения
захвачены зондом. Ловушка взведена: при откате исправления `unit.variable("q")` → `None`
→ тест падает. Регресса портов/констант нет (весь корпус симуляции, включая
conformance C/SV/rust/st, зелёный). Ноль согласуется с C default-init — вывод
генераторов **байт-в-байт неизменен**.

**Массивы — вне объёма:** их исполнение — отдельная нерабочая [симулятор не исполняет массивы вовсе](0076-sim-arrays.md) (`arr.N` — бит-доступ, не индекс); **регистрация**
массива нулей при этом уже работает. Версия языка не поднята (правка семантики
симулятора). `precheck.sh` зелёный; отчёт —
[`var q: u8;` без инициализатора → `SIM-009`](0086-sim-var-without-initializer.md#отчёт-о-тестировании).
