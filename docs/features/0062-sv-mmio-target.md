# Фича: Цель `sv-mmio`: адреса портов → регистровый файл на шине

- **Номер:** 0062
- **Статус:** ГОТОВО (2026-07-20; `./scripts/precheck.sh` зелёный)
- **Зависит от:** **[исправление](../fixes/0020-01-port-bit-out-of-range.md)** (Tier 1, заведён этой проработкой, **не закрыт**) — язык не выражает ширину адресуемого слова, поэтому `0x44533932:33` не интерпретируем, а правило 6 ADR запрещает **угадывать**. Формально `ЗАБЛОКИРОВАНА` определена правилом 17 через **фичу**-зависимость, а 0020-01 — исправление; буква правила фичу не блокирует, **существо — блокирует**. - **Приоритет / Tier:** **Tier 3** — ничего не сломано (`-t sv` честно игнорирует адрес: это **принятое** решение ADR, а не дефект), пользователя нет, ни одна фича от неё не зависит. **Ценность выше Tier:** фича замыкает 0020 — адрес начинает значить одно и то же по обе стороны шины.

## Краткое описание

Карта адресов ([адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md)) целью `sv` **не потребляется**:
MMIO-адрес для RTL бессмыслен — разыменование `*(volatile*)` в аппаратуре не
существует. Но осмысленна другая трактовка: породить **регистровый файл** на
APB/AXI-Lite/Wishbone, где адрес задаёт смещение регистра. Это **самостоятельная
цель**, а не флаг `sv`.

Вынесено закрытой [генератор генерации в SystemVerilog](0045-sv-backend.md) (ADR, вопрос 5, Option B).

> **Объединены два кандидата.** В `FEATURES.md` находка была записана **дважды** —
> «Цель `sv-mmio`: адреса портов → регистровый файл на шине» и «Цель `sv-mmio`» —
> с одним и тем же содержанием; при заведении сведены в одну фичу (решение
> заказчика 2026-07-17).

## Архитектура (ADR)

- **Status:** Accepted
- **Date:** 2026-07-17
- **Authors:** Архитектор + Дизайнер языка
- **Related issues:** [Фича](0062-sv-mmio-target.md); исполняет отложенное решение [ADR](0045-sv-backend.md#архитектура-adr) (вопрос 5, **Option B вынесен в кандидаты**); вскрыт [исправление](../fixes/0020-01-port-bit-out-of-range.md)

### Context

ADR (вопрос 5) принял **Option A**: цель `sv` адрес **не потребляет** —
«у RTL-модуля процессора нет; спрашивать, по какому адресу лежит `cmd_fork`,
так же бессмысленно, как спрашивать адрес ножки микросхемы». **Option B**
(`sv-mmio`: адрес → регистровый файл на шине) признан **ценным**, но вынесен в
кандидаты с двумя возражениями:

1. «**Требует выбрать шину** (APB? AXI-Lite? Wishbone?) — решение, для которого в
   требованиях нет **никакого** основания. Выбор произволен, а цена ошибки
   высока.»
2. «Резко расширяет объём: шинный автомат, декодер адреса, семантика
   чтения/записи, **тестбенч уровня шины (BFM)**.»

Оба возражения — про **шину**, а не про регистровый файл. Это и есть ключ к
решению (см. Decision).

#### Замер: что адреса корпуса говорят о себе (2026-07-17)

| Файл | Адреса | Похоже на |
|---|---|---|
| `stacker.lam` | `0x100`…`0x601`, сгруппированы по назначению (`0x1xx` задание, `0x2xx` позиция, `0x3xx` датчики, `0x4xx` цели, `0x5xx` вилы, `0x6xx` подтверждения) | **готовую карту регистров** — смещения, а не физические адреса |
| `elevator.lam` | `0x10000000`…`0x10000009` | **плоский физический MMIO** (база + смещение) |
| `extend_complex.lam` | `0x44533932`, биты `1`, `2`, **`33`** | одно слово, **три порта, разных направлений** |

То есть корпус пользуется адресами **двумя разными способами**, и цель обязана
работать с обоими.

#### Находка проработки: одно слово несёт порты разных направлений

`extend_complex.lam`: `out IDLE :1`, `out WORK :2`, `in WAIT :33` — **один**
адрес. Для регистрового файла это значит: регистр **не бывает** просто
read-only или write-only — направление принадлежит **биту**, а не слову.
Это ограничение дизайна, а не деталь.

#### Находка проработки: бит адреса не проверяется вовсе → [исправление](../fixes/0020-01-port-bit-out-of-range.md)

Греп по всему `grammar/src` не находит **ни одной** проверки диапазона бита;
`bit: Option<i64>` допускает и отрицательный. Цель `c-hal` на бите 8…31 читает
**всегда 0** (загружен один байт), на бите ≥ 32 — **UB** (`int >> 33`, C11
6.5.7p3); `cc -Wall` молчит, потому что бит — значение времени выполнения.
Дожило потому, что **`c-hal` не компилируется ни одним проверкой** (в `precheck.sh`
она только в проверке **детерминизма**).

**Следствие для 0062:** язык **не выражает ширину адресуемого слова** — есть
только адрес и бит. Пока это не решено, `sv-mmio` не может знать, какой ширины
регистр порождать для `0x44533932:33`.

### Decision Drivers

1. **Произвольный выбор нельзя маскировать под архитектуру.** Возражение ADR
   верно: основания выбрать APB/AXI-Lite/Wishbone в требованиях **нет**.
2. **Ценность — в карте регистров, а не в шине.** Адреса `stacker` уже **являются**
   картой регистров; шина — способ до них дотянуться.
3. **Проверяемость.** Тестбенч уровня шины (BFM) — половина объёма Option B и
   источник ошибок, не относящихся к Lam.
4. **Две половины одной шины.** Ценность, названная ADR: один адрес значит
   одно и то же для `c-hal` (сторона процессора) и `sv-mmio` (сторона периферии).
   Она достижима **без** выбора протокола.

### Considered Options

#### Option A. Выбрать APB (или AXI-Lite, или Wishbone) и породить готовый шинный блок

**Pros:**
- «Воткнул и работает» на конкретной платформе.

**Cons:**
- **Ровно то, что запретил ADR** (драйвер 1): выбор произволен. AXI-Lite —
  экосистема AMD/Xilinx; APB — ARM; Wishbone — открытые ядра. Требований нет →
  выбор был бы вкусовым, а зафиксировался бы в выводе компилятора.
- Тянет BFM в тест-план (драйвер 3).
- Выбрав неверно, платим дважды: второй протокол придётся добавлять рядом.

#### Option B. Шинно-агностичный регистровый файл; адаптеры — отдельные фичи

Модуль получает **простой синхронный регистровый интерфейс** (адрес, данные
записи, данные чтения, строб записи/чтения) — без протокола. Адаптер
APB/AXI-Lite/Wishbone пишется поверх (обычно десятки строк) и заводится
**отдельной фичей, когда появится требование**.

**Pros:**
- **Снимает оба возражения ADR**: выбирать шину не нужно (драйвер 1); BFM не
  нужен — регистровый интерфейс дёргается в тестбенче напрямую (драйвер 3).
- Даёт **всю** содержательную ценность: карта регистров из `.lam`, «две половины
  одной шины» (драйверы 2, 4).
- Адаптер — тонкий шим, и он **платформенный**, то есть ему и место снаружи.
- Объём соразмерен: декодер + регистры, без шинного автомата.

**Cons:**
- Не «готовый блок»: интеграция требует шим. Смягчение: шим тривиален и всё равно
  платформенно-зависим.
- Появляется свой интерфейс — его форму надо задать (правило 3 ниже).

#### Option C. Атрибуты/комментарии с адресами в выводе `sv`

**Pros:** дёшево.

**Cons:** ADR уже отверг это для 0045 («комментарий с претензией»; создаёт
**ложное впечатление**, что адрес учтён). Довод не изменился.

#### Option D. Не делать (статус-кво)

**Pros:** ноль работы; `-t sv` честно игнорирует адрес.

**Cons:** отложенное решение остаётся отложенным; адреса модели для
аппаратной цели — мёртвые метаданные.

### Decision

Принимается **Option B** — **шинно-агностичный регистровый файл**.

Возражения ADR против Option B оба относятся к **шине**, а не к
регистровому файлу; убрав протокол из объёма, мы снимаем оба и сохраняем всю
ценность. Выбор протокола — **требование**, и его должен принести заказчик, а не
угадать архитектор; до тех пор компилятор не обязан вставать на чью-то сторону.

**Нормативные правила:**

1. **Новая цель** `-t sv-mmio`, парная к `sv` — как `c-hal` парная к `c`
   (прецедент 0020-05, на который прямо ссылается ADR). Цель `sv`
   **не меняется**: адрес по-прежнему не потребляет.
2. **Порты с адресом** становятся битами регистров; порты **без** адреса остаются
   портами модуля. Смешение допустимо.
3. **Интерфейс** (форма): адрес, данные записи, данные чтения,
   стробы; синхронный, без протокола; ширина адреса выводится из **максимального**
   адреса модели.
4. **Направление принадлежит биту, а не слову** (находка выше): регистр может
   нести и читаемые, и записываемые биты. Бит `in` — записывается шиной, читается
   автоматом; бит `out` — пишется автоматом, читается шиной.
5. **Запись в бит `out` со стороны шины игнорируется**; чтение бита `in` шиной
   возвращает записанное. Иное — конфликт драйверов.
6. **Ширина регистра** берётся из решения по [исправлению 0020-01](../fixes/0020-01-port-bit-out-of-range.md).
   Пока исправление не закрыт, `sv-mmio` **обязана отказать** (диагностика) на бите вне
   поддержанного диапазона — **не угадывать**. Угадать ширину — значит повторить
   ошибку, за которую ADR отверг fixed-point (см. [fixed-point Q(m.n) как тип языка](0061-fixed-point-type.md#архитектура-adr)).
7. **`--address-map` работает** с `-t sv-mmio` — то есть проверку
   `bin/lamc.rs:532` (сегодня пропускает внешнюю карту только для `c-hal`)
   придётся расширить. Это **единственная** правка вне новой цели.
8. **Язык не меняется** → версия не растёт (правило 22).

### Consequences

#### Положительные

- Адреса модели становятся осмысленными для аппаратной цели; «две половины одной
  шины» (`c-hal` + `sv-mmio`) — замыкание фичи.
- Выбор протокола **отложен до появления требования**, а не принят вслепую.
- Тестируется без BFM.

#### Отрицательные / Action items

- **A-1. Зависимость от исправления** (правило 6). Пока ширина адресуемого слова
  языком не выражена, `sv-mmio` не знает, что такое `0x44533932:33`. Фича обязана
  **отказывать**, а не угадывать. Это делает 0020-01 **блокирующим** для полного
  объёма (частичный — только биты 0…7 — возможен, но бессмыслен: `extend_complex`
  корпуса им не покрывается).
- **A-2. Адаптеры шин — отдельные фичи** (APB / AXI-Lite / Wishbone), каждая по
  требованию. Кандидат.
- **A-3. Сверка обязательна и заводится вместе с целью**. У
  `sv` дефект «`always_comb` читает регистр вместо `_next`» приняли **оба**
  инструмента. Наблюдение для `sv-mmio` берётся **со стороны шины** (чтение
  регистра), а не иерархической ссылкой: именно так его видит потребитель.
- **A-4. `c-hal` не компилируется проверкой** — кандидат; без этого «две половины
  одной шины» проверяются только с одной стороны.

#### Acceptance criteria

1. **A1.** `-t sv-mmio` порождает модуль с регистровым интерфейсом; `stacker.lam`
   (17 адресов, `0x100`…`0x601`) даёт карту регистров, совпадающую с адресами
   модели.
2. **A2.** Модуль **синтезируется**: проверка **обоими** инструментами (verilator
   **и** yosys — ловят непересекающиеся классы, проверено 4 раза при 0045).
3. **A3.** Цель `sv` **не изменилась**: вывод `examples/generated/sv` побайтово
   прежний (опора — детерминизм закрытой [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md#архитектура-adr)).
4. **A4.** Потактовая сверка: трасса `sv-mmio` (наблюдение **через регистры**) =
   трасса симулятора на каждом такте.
5. **A5.** Слово со **смешанными** направлениями (`extend_complex`: `out :1`,
   `out :2`, `in :33`) обрабатывается по правилам 4–5 либо **отвергается**
   диагностикой (пока 0020-01 не закрыт) — но **не угадывается**.
6. **A6.** Запись шиной в бит `out` игнорируется; чтение бита `in` возвращает
   записанное.
7. **A7.** Порт **без** адреса остаётся портом модуля (правило 2).
8. **A8.** `--address-map` принимается целью `sv-mmio` (правило 7); приоритет
   источников адреса — прежний (inline < `address` < карта), фича не тронута.
9. **A9.** Язык не изменился; версия не поднята.

## Анализ

### Цель и контекст

ADR отверг потребление адреса целью `sv` («у RTL-модуля процессора нет») и
вынес `sv-mmio` в кандидаты с двумя возражениями — **оба про шину**: выбор
протокола не обоснован требованиями; BFM удваивает объём.

ADR принял **Option B — шинно-агностичный регистровый файл**: убрав протокол
из объёма, снимаем оба возражения и сохраняем ценность (карта регистров из `.lam`,
«две половины одной шины» `c-hal` + `sv-mmio`). Выбор протокола — **требование**,
и его приносит заказчик; адаптеры APB/AXI-Lite/Wishbone — отдельные фичи.

### Замер (2026-07-17)

| Что | Факт |
|---|---|
| `stacker.lam` | 17 адресов `0x100`…`0x601`, **сгруппированы по назначению** — фактически готовая карта регистров |
| `elevator.lam` | `0x10000000`…`0x10000009` — плоский физический MMIO |
| `extend_complex.lam` | `0x44533932`, биты `1`, `2`, **`33`** — **одно слово, три порта, разных направлений** (`out`, `out`, `in`) |
| Проверка бита | **отсутствует во всём `grammar/src`** (греп); `bit: Option<i64>` допускает отрицательный |
| `c-hal` на бите 8…31 | читает **всегда 0** (загружен один байт) — **молча неверно** |
| `c-hal` на бите ≥ 32 | **UB** (`int >> 33`, C11 6.5.7p3); `cc -Wall` **молчит** (бит — значение времени выполнения) |
| Проверка `c-hal` | **не компилируется вовсе** — в `precheck.sh` только в проверке **детерминизма** (строка 118) |
| Отсечение карты | `bin/lamc.rs:532` пропускает внешнюю карту **только** для `c-hal` |

Два вывода, определившие решение:

1. **Направление принадлежит биту, а не слову** — регистр не бывает просто
   read-only/write-only.
2. **Язык не выражает ширину адресуемого слова** (есть только адрес и бит) →
   `0x44533932:33` не интерпретируем без решения. Отсюда
   [исправление](../fixes/0020-01-port-bit-out-of-range.md).

### Зависимости фичи (правило 17/19)

- **Зависит от:** **[исправления](../fixes/0020-01-port-bit-out-of-range.md)**
  (заведён этой проработкой, Tier 1, **не закрыт**).
  **Обоснование:** правило 6 ADR запрещает угадывать ширину регистра. Пока язык не
  выражает ширину адресуемого слова, `sv-mmio` обязана **отказывать** на бите вне
  поддержанного диапазона. Частичный объём (только биты 0…7) технически возможен,
  но **бессмыслен**: `extend_complex.lam` корпуса им не покрывается, то есть цель
  не проходила бы собственный корпус.
  **Формально исправление — не фича**, а `ЗАБЛОКИРОВАНА` определена правилом 17 через
  **фичу**-зависимость. Поэтому статус фичи — `СОЗДАНА`, но в таблице она помечена
  зависимостью от 0020-01 явно: буква правила её не блокирует, существо — блокирует.
  Решение о том, заводить ли под 0020-01 отдельную фичу-владельца, — за
  заказчиком.
- **Не зависит от:** [генератор генерации в SystemVerilog](0045-sv-backend.md) (закрыта — даёт
  каркас `generator/sv/`), [адрес порта — размещение и потребление (карта адресов)](0020-port-address-decl.md) (закрыта —
  даёт `AddressMap`), [детерминированная генерация кода (единый порядок эмиссии)](0048-deterministic-codegen.md) (закрыта —
  даёт критерий A3).
- **Пересечения по коду:** [последовательная композиция (`+`) в цели SystemVerilog](0057-sv-sequential-composition.md)
  правит `sv_fsm.rs`; [fixed-point Q(m.n) как тип языка](0061-fixed-point-type.md) — `sv_type.rs`;
  0062 добавляет **новую** цель и трогает `bin/lamc.rs:532` + `generator/mod.rs`
  (вариант `Language`). Конфликты слияния тривиальны, но 0062 разумно вести
  **после** 0057: обе трогают эмиссию модуля.
- **Влияние на порядок:** никого не разблокирует. **Разблокируется** закрытием
  0020-01.

### Приоритет (Tier) — обоснование

**Tier 3.**

- Ничего не сломано: `-t sv` честно игнорирует адрес, и это **принятое** решение
  ADR, а не дефект.
- Пользователя нет: ни одного запроса на MMIO-периферию в требованиях; сценарий
  «софт на процессоре + ускоритель на FPGA» назван ADR как **вероятный**, а
  не как заявленный.
- Против Tier 2: ни одна фича от неё не зависит; ни один дефект ею не закрывается
  (0020-01 она **вскрыла**, но не чинит).

**Ценность фичи выше её Tier, и это стоит сказать:** она замыкает 0020 —
один и тот же адрес начинает значить одно и то же по обе стороны шины. Но
замыкание бессмысленно, пока **одна из сторон** (`c-hal`) читает биты неверно и
не компилируется проверкой. Поэтому рекомендация аналитика: **сначала 0020-01**.

### Требования и проверяемые условия

- **R1. Новая цель.** `-t sv-mmio`, парная к `sv` (прецедент `c`/`c-hal`, 0020-05).
  Цель `sv` **не меняется**.
- **R2. Порт с адресом → бит регистра; без адреса → порт модуля.** Смешение
  допустимо.
- **R3. Интерфейс без протокола:** адрес, данные записи/чтения, стробы;
  синхронный. Ширина адреса — из **максимального** адреса модели.
- **R4. Направление — свойство бита.** Регистр может нести биты обоих направлений.
- **R5. Запись шиной в бит `out` игнорируется; чтение бита `in` возвращает
  записанное.**
- **R6. Не угадывать.** Бит вне поддержанного диапазона → **диагностика**.
- **R7. `--address-map` принимается** целью `sv-mmio` (`bin/lamc.rs:532`).
- **R8. Приоритет источников адреса не меняется** (inline < `address` < карта).
- **R9. Инварианты держатся:** two-process, `always_comb` читает `_next`,
  уплощение композиции, вход в стартовое состояние не расходует такт (0033).
- **R10. Язык не меняется** → версия не растёт.

|---|---|---|
| A1 | Карта регистров `stacker` совпадает с адресами модели | Сверка порождённого с `stacker.lam` |
| A2 | Модуль синтезируется | Проверка **verilator И yosys** |
| A3 | Цель `sv` не изменилась | `git diff --exit-code examples/generated/sv` |
| A4 | **Потактовая сверка через регистры** | `conformance_sv_tests` (новый режим наблюдения) |
| A5 | Смешанное слово (`extend_complex`) — по правилам либо **отказ** | Фикстура + прогон |
| A6 | Запись в `out` игнорируется; чтение `in` возвращает записанное | Тестбенч |

### Особенности по обратной функциональности

**Правка аддитивна** (правило 11): добавляется **новая** цель; `sv`, `c`, `c-hal`,
`st`, `st-at`, `rust`, `plantuml`, симулятор и язык — не задеты (A3).

Единственная правка вне новой цели — `bin/lamc.rs:532` (R7): условие расширяется
с `!= "c-hal"` на «не `c-hal` и не `sv-mmio`». Аддитивно: где карта отсекалась,
она отсекается по-прежнему.

`Language` помечен `#[non_exhaustive]` — добавление варианта сборку потребителей
не ломает (та же особенность, что у 0045/0050).

### Риски и зависимости

- **R-1. Угадать ширину регистра** (главный риск). Язык её не выражает
  (`0x44533932:33`), и соблазн «ну пусть будет 64» повторил бы ошибку, за которую
  ADR отверг fixed-point: генератор молча выбирает семантику. Снижение:
  правило 6 — **отказ вместо догадки**; зависимость от 0020-01.
- **R-2. Тихо неверное чтение/запись.** Класс доказан дважды: у `sv` дефект
  «`always_comb` читает регистр вместо `_next`» приняли **оба** инструмента; у
  `c-hal` бит 8…31 читается как 0 **молча**. Снижение: A4 — сверка **через
  регистры** (оттуда, откуда смотрит потребитель), заводится **вместе** с целью.
- **R-3. Конфликт драйверов** на смешанном слове. Снижение: R5 + A6.
- **R-4. Соблазн «заодно выбрать шину».** Вернул бы возражение ADR.
  Снижение: адаптеры — отдельные фичи (A-2 ADR), каждая по требованию.
- **R-5. Проверять будет нечем с одной стороны.** «Две половины одной шины»
  проверяются только если обе половины проверяемы, а `c-hal` **не компилируется
  проверкой**. Снижение: кандидат заведён; A4 покрывает сторону `sv-mmio`.

### Побочные находки проработки (вне объёма, заведены)

1. **[Исправление](../fixes/0020-01-port-bit-out-of-range.md)** (Tier 1): бит
   адреса не проверяется нигде; `c-hal` на бите 8…31 читает **всегда 0**, на ≥ 32
   даёт **UB**; корпус содержит такой случай (`extend_complex.lam:13`).
2. **Цель `c-hal` не компилируется ни одним проверкой** — кандидат. В `precheck.sh`
   она только в проверке детерминизма: её вывод сверяют сам с собой, но никогда не
   подают компилятору. Это и позволило (1) дожить.
3. **Адаптеры шин** (APB / AXI-Lite / Wishbone) — кандидат, по одному на протокол,
   каждый по требованию.

## Разработка

### Задача

#### Что было

Цель `sv` адрес **не потребляет** (решение ADR, вопрос 5): порты Lam → порты
модуля; `--address-map` с `-t sv` отсекается `bin/lamc.rs:532`. Адрес для `sv` —
мёртвые метаданные.

#### Что сделано

Новая цель `-t sv-mmio`, парная к `sv` (прецедент `c`/`c-hal`, на
который прямо ссылается ADR):

1. **Вариант `Language`** + ветка в `generate()` (`Language` уже
   `#[non_exhaustive]`; общий слой заводить не нужно — `minimap::Map` и `Printer`
   общие, каркас доказан целями 0041/0045/0050).
2. **Порт с адресом** → бит регистра; **без адреса** → порт модуля (правило 2 ADR).
3. **Интерфейс без протокола** (правило 3): адрес, данные записи/чтения, стробы;
   синхронный. Ширина адреса — из **максимального** адреса модели.
   Форма интерфейса — единственное, что здесь изобретается; всё остальное
   диктуется моделью. Держать минимальной: адаптер APB/AXI-Lite пишется поверх и
   заводится **отдельной фичей по требованию** (A-2 ADR).
4. **Направление — свойство бита** (правило 4): в одном слове допустимы биты
   `in` и `out` одновременно — это **факт корпуса** (`extend_complex.lam`:
   `out :1`, `out :2`, `in :33`), а не гипотеза.
5. **Запись шиной в бит `out` игнорируется**; чтение бита `in` возвращает
   записанное (правило 5) — иначе конфликт драйверов.
6. **Не угадывать** (правило 6): бит вне поддержанного диапазона → **диагностика**.
   Угадать ширину слова значило бы повторить ошибку, за которую ADR отверг
   fixed-point: генератор молча выбирает семантику.

#### Проверки

- **T1/A1:** карта регистров `stacker` совпадает с адресами модели буквально.
- **T2/A2:** проверка — **verilator И yosys**.
- **T3/A3:** `git diff --exit-code examples/generated/sv` — пусто (цель `sv` не тронута).
- **T5/A5:** смешанное слово — по правилам либо **отказ**; **T12** (мутация):
  молчаливый выбор ширины обязан валить T5.
- **T8/A7:** порт без адреса — порт модуля.
- **T11:** ширина адреса выводится из максимума (`0x10000000` у `elevator`,
  `0x601` у `stacker`).
- **T13:** инварианты (two-process; `always_comb` читает **`_next`**; вход в
  стартовое состояние такта не расходует — контракт 0033).

### Задача

#### Что было

`bin/lamc.rs:532` — условие `if !external_entries.is_empty() && options.target != "c-hal"`
отсекает внешнюю карту (`--address-map`) для **всех** целей, кроме `c-hal`.
Потактовой сверки у `sv-mmio` нет (цели нет).

#### Что сделано

1. **Расширить отсечение** (правило 7 ADR): карта принимается и для `sv-mmio`.
   Правка **аддитивна** (правило 11): где карта отсекалась, она отсекается
   по-прежнему. Это **единственная** правка вне новой цели.
2. **Приоритет источников не трогать** (правило 8): inline < `address` < внешняя
   карта — контракт фичи.
3. **Потактовая сверка** `conformance_sv_tests` — новый режим наблюдения:
   значения читаются **со стороны шины** (чтение регистра), а не иерархической
   ссылкой `dut.<сигнал>`.
   **Наблюдение берётся оттуда, откуда его берёт потребитель** (правило
   проекта, `CLAUDE.md`): у `c` — поля структуры, у `sv` — иерархическая ссылка,
   у `rust` — выходные порты через HAL. У `sv-mmio` потребитель — шина.
   **Сверку заводить вместе с целью, а не после** (уроки и 0050): у 0045
   дефект «`always_comb` читает регистр вместо `_next`» приняли **оба**
   инструмента; у 0050 сверки не было вовсе при зелёном проверке — пробел нашла
   приёмка.

#### Проверки

- **T9/A8:** `--address-map` с `-t sv-mmio` принимается; с прочими целями (кроме
  `c-hal`) — по-прежнему отсекается.
- **T10:** приоритет inline < `address` < карта — прежний.
- **T4/A4 — основная:** трасса `sv-mmio` (через регистры) = трасса симулятора на
  каждом такте.
- **T6/T7/A6:** запись в бит `out` игнорируется; чтение бита `in` возвращает
  записанное.
- `./scripts/precheck.sh` — все проверки зелёные; вывод прочих целей не изменился.

### Ключевые наблюдения

- **Сверка через шину, а не иерархической ссылкой.** Наблюдение берётся оттуда,
  откуда его берёт потребитель регистрового файла: тестбенч драйвит `reg_addr` и
  читает срез `reg_rdata`. Дефект «`always_comb` читает регистр вместо `_next`»  исключён потому, что автомат `sv` переиспользован **без изменений** —
  сверка это подтверждает потактово.
- **Ширина данных = максимум `bit + width`, не фиксированные 64.** Иначе
  `verilator -Wall` даёт `UNUSEDSIGNAL` на старших битах `reg_wdata`. У `stacker`
  входы — плотные u8 (`[7:0]`), поэтому `-Wall` чист.
- **Гонка тестбенча ≠ дефект модуля.** Первый вариант T6/T7 снимал `reg_wen` в
  тот же слот, что и защёлкивание записи (блокирующее присваивание конкурирует с
  `always_ff`). Минимальная проба доказала корректность модуля; исправлен
  тестбенч (`#1` после фронта).

### Отклонения и ограничения

- **Смешанное слово с `out`-битами не в `-Wall`-проверке:** биты `reg_wdata` на
  `out`-позициях шиной не читаются (`UNUSEDSIGNAL`) — неотъемлемо для write-шины с
  read-only битами. Опорный пример проверки — `stacker` (уникальные адреса);
  смешанное слово покрыто кодогенным тестом + yosys. `extend_complex` не
  SV-транслируем сам по себе (`extern fn`).
- **Тайминг входов:** запись входа шиной синхронна (1 такт до автомата), поэтому
  потактовая сверка — на автономной фикстуре; семантика входов — отдельным
  тестом с явным таймингом.
- **Адаптеры шин** (APB/AXI-Lite/Wishbone) — вне объёма (A-2 ADR), кандидаты по
  требованию.
- **`bin/lamc.rs` ужат** дедупликацией веток (2009 → 1993); `compile_to_sv_mmio`
  вынесен в `compile_sv_mmio.rs` — оба файла под записями реестра долга (обновлены
  вниз).

## Итог проработки (2026-07-17)

**Возражения ADR сняты — оба они про шину, а не про регистровый файл.**
ADR вынес Option B в кандидаты, потому что тот «требует выбрать шину (APB?
AXI-Lite? Wishbone?) — решение, для которого в требованиях нет **никакого**
основания», и тянет **BFM** в тест-план. Убрав протокол из объёма, снимаем оба и
сохраняем всю ценность.

**Принято** ([ADR](0062-sv-mmio-target.md#архитектура-adr), Option B): **шинно-агностичный
регистровый файл** — модуль получает простой синхронный регистровый интерфейс
(адрес, данные, стробы) **без протокола**; адаптеры APB/AXI-Lite/Wishbone —
отдельные фичи **по требованию**. Выбор протокола есть **требование**, и приносит
его заказчик, а не угадывает архитектор. Побочно: регистровый интерфейс дёргается
в тестбенче напрямую — **BFM не нужен**.

**Замер, определивший дизайн:**

| Файл | Адреса | Что показал |
|---|---|---|
| `stacker.lam` | 17 шт., `0x100`…`0x601`, сгруппированы по назначению | это **уже** карта регистров |
| `elevator.lam` | `0x10000000`… | плоский физический MMIO |
| `extend_complex.lam` | `0x44533932`, биты **1, 2, 33** | **одно слово — три порта разных направлений** |

Отсюда правило: **направление принадлежит биту, а не слову** — регистр не бывает
просто read-only/write-only.

**Вскрыт [исправление](../fixes/0020-01-port-bit-out-of-range.md) (Tier 1),
и он блокирует полный объём.** Бит адреса **не проверяется нигде** (греп по всему
`grammar/src`; `bit: Option<i64>` допускает даже отрицательный). Цель `c-hal` на
бите 8…31 читает **всегда 0** (загружен один байт), на бите ≥ 32 даёт **UB**
(`int >> 33`, C11 6.5.7p3); `cc -Wall` **молчит** — бит есть значение времени
выполнения. Корпус такой случай **содержит** (`extend_complex.lam:13`). Дожило
потому, что **`c-hal` не компилируется ни одним проверкой**: в `precheck.sh` она
только в проверке **детерминизма** — вывод сверяют сам с собой, но компилятору не
подают.

Следствие для 0062: язык **не выражает ширину адресуемого слова**, поэтому цель
обязана **отказывать**, а не угадывать (правило 6 ADR). Угадать — значит повторить
ошибку, за которую ADR отверг fixed-point.

**Рекомендация аналитика:** сначала **0020-01**. Замыкание «две половины одной
шины» бессмысленно, пока одна из половин (`c-hal`) читает биты неверно и не
компилируется проверкой.

Язык не меняется → версия не растёт (правило 22).

## Итог (что сделано) — 2026-07-20

Принята **Option B** ADR (шинно-агностичный регистровый файл). Реализация по
задачам (интерфейс + карта регистров) и 0062-02 (приём карты + сверка);
блокер [бит адреса порта не проверяется — `c-hal` читает не тот бит либо даёт UB](../fixes/0020-01-port-bit-out-of-range.md) снят фичей-владельцем
[проверка диапазона бита адреса порта и безопасный принятый по умолчанию HAL](0098-port-bit-range-safe-hal.md) **до** взятия 0062 в работу.

**Сделано:**

- **Цель `-t sv-mmio`** (вариант `Language::SvMmio`, диспетчер `generate()`); ядро
  регистрового файла — новый модуль `generator/sv/sv_mmio.rs`. Автомат, композиция,
  сброс, функции — **переиспользуют** генератор `sv` без изменений; отличается лишь
  плумбинг портов.
- **Порт с адресом → бит регистра, без адреса → порт модуля** (правило 2):
  `collect_ports` исключает адресованные; адресованный `out` становится внутренним
  регистром автомата (`sv_fsm::Fsm::build`, `declare_reg: true`), адресованный
  `in` — регистром, пишущимся шиной (отдельный `always_ff` в `sv_mmio`).
- **Интерфейс без протокола** (правило 3): `reg_addr` (ширина — из максимума
  адреса), `reg_wdata`/`reg_rdata` (ширина — из максимума `bit + width`, не
  фиксированные 64: лишние старшие биты дали бы `UNUSEDSIGNAL`), `reg_wen`;
  синхронный. Адаптеры APB/AXI-Lite/Wishbone — по-прежнему отдельные фичи (A-2).
- **Направление по биту** (правило 4): чтение `reg_rdata` собирает слово из всех
  портов адреса; запись касается только `in`-битов (правило 5). Смешанное слово
  (out+in по одному адресу) собирается верно (тест `mixed_direction_word_*`,
  синтез yosys).
- **Не угадываем** (правило 6): `SE-060` (бит вне `[0, 63]`, из слоя 0098),
  `SV-013` (срез вне 64-битного регистра), `SV-014` (имя = сигнал интерфейса),
  `SV-006` (адресованный `inout`).
- **`--address-map` принят** (правило 7): единственная правка вне новой цели —
  `bin/lamc.rs` (`consumes_addresses += "sv-mmio"`) + `compile_to_sv_mmio` в
  `compile_sv_mmio.rs`. Приоритет источников (0020) не тронут. **`SE-052` снят
  для `sv-mmio`**: used-порт без адреса — не ошибка, а порт модуля.

**Критерии приёмки:** A1 (карта регистров `stacker` = адреса модели) —
`sv_mmio_tests`; A2 (verilator **и** yosys) — проверка `precheck.sh`; A3 (цель `sv`
байт-в-байт) ; **A4 (потактовая сверка через регистры)** —
`conformance_sv_mmio_tests::per_tick_trace_matches_generated_sv_mmio`; A5
(смешанное слово по правилам, не угадано) ; A6 (T6/T7 — запись в `out`
игнорируется, чтение `in` возвращает записанное) — самопроверяющийся тестбенч;
A7 (порт без адреса = порт модуля) ; A8 (`--address-map` принят, приоритет
прежний) ; A9 (язык/версия не менялись) .

**Отклонения и находки:**

- **Смешанное слово с `out`-битами не проходит `verilator -Wall`** и потому **не
  в проверке**: биты `reg_wdata`, соответствующие `out`-позициям, шиной не читаются →
  `UNUSEDSIGNAL`. Это неотъемлемо (write-шина регистрового файла с read-only
  битами). Опорный пример проверки — `stacker` (уникальные адреса, плотные u8-входы,
  `-Wall` чист); смешанное слово проверено кодогенным тестом + `yosys`.
  `extend_complex` (реальное смешанное слово корпуса) не SV-транслируем сам по
  себе (`extern fn`).
- **Дедупликация `bin/lamc.rs`:** ветки `c-hal`/`st-at`/`sv-mmio` и
  `plantuml`/`st`/`rust`/`sv` сведены к `report_hal_result`/`report_simple_result`
  — это окупило добавления, файл **ужат** 2009 → 1993 (реестр долга обновлён).
  `compile_to_sv_mmio` вынесен в `compile_sv_mmio.rs` (`lib.rs` под лимитом).
- **Тайминг сверки:** запись входа шиной синхронна (защёлкивается на фронте),
  поэтому потактовая сверка ведётся на **автономной** фикстуре (выходы без
  входов); семантика входов проверена отдельно с явным таймингом (гонка снятия
  `reg_wen` в тот же слот — артефакт тестбенча, не модуля).

Язык не менялся → версия не поднята (правило 22).
