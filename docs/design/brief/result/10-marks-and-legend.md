# Обозначения узлов и легенда — предложение по требованию заказчика

Требование (2026-09-08, дословно по смыслу): *имена состояний бывают длинными,
поэтому состояния обозначать символом `S` с номером нижним индексом
(предложить варианты) и заносить в легенду-таблицу; должна быть возможность
править латинские имена как кириллическое представление — простое связывание;
кружки состояний все одного размера.*

Требование **принято и лежит в основе оформления узла**. Ниже — что из него
следует, четыре варианта самого знака (образцы живьём — раздел
`data-control="--marks"` витрины) и последствия для формата файла раскладки,
которые обязан решить аналитик, а не дизайнер.

## Что изменилось против задание, пункт 2

| задание, пункт 2 (исходное) | Принято |
|---|---|
| карточка высотой `--h-control`, **ширина по имени** | **круг** диаметром `--node-d` — один размер у всех узлов |
| имя состояния крупно на карточке | **обозначение** `S`+номер на круге; имя — в легенде |
| вид строкой `--text-xs` на карточке | вид — меткой в легенде и навигаторе; на листе вид передан **формой** |
| — | **подпись под кругом**: авторская либо имя из модели, усечённая 12 знаками |

**Почему подпись под кругом всё же осталась.** Схема без имён читается только
с легендой в руках: автор, ищущий `DoorClosing`, иначе сверяет номера глазами.
Подпись под кругом на раскладку не влияет (её высота — вне круга, ширина
усечена), а ниже масштаба `0,5×` она скрывается вместе с подписями условий.
Если заказчик предпочтёт чистый рисунок — правило одно, снимается строкой.

## Варианты знака

| вариант | вид | за | против |
|---|---|---|---|
| **A — `S` + номер нижним индексом** (предлагается) | `S₂` рисованным индексом | читается как «состояние 2»; знак узкий, в круг 48 px входит с полями; индекс отличает номер от имени | индекс — два кегля в одном знаке |
| B — только номер | `2` | самый узкий знак, в кругу много воздуха | номер без буквы читается как порядок в списке, а не как имя предмета; на миникарте и в легенде теряется |
| C — `S2` в строку | `S2` | один кегль, проще в вёрстке и в экспорте | при двузначных номерах (`S12`) знак шире круга — придётся мельчить кегль, то есть заводить шестую ступень |
| D — буква имени + номер | `D₂` (от `DoorClosing`) | связь с именем видна без легенды | буква зависит от имени: переименование меняет знак, а два состояния на одну букву дают `D₂` и `D₃` — связь обманчива |

**Предложение — A.** Номер нарисован смещением базовой линии (`tspan dy`), а
не набран символом `₁`: подстрочных цифр в Fira Code нет, и промах дал бы
системный глиф на чужой базовой линии — то же правило, по которому в проекте
нарисованы указатель списка и разделитель крошек.

**Номер = место узла в ярусном порядке листа** (`rank`, затем `order` — R2),
а не порядок в тексте: так знак совпадает с порядком чтения схемы сверху
вниз. Номер устойчив, пока не меняется набор состояний; при добавлении
состояния номера пересчитываются, и это правильно — знак называет место на
листе, а имя называет состояние.

## Знак условия перехода

Требование (2026-09-08): условие перехода тоже бывает очень длинным — его
сокращаем до буквы `K` с номером нижним индексом и выносим в отдельную
легенду, как состояния.

**Принято.** На листе стоит знак `K`+номер; полное условие живёт во второй
таблице легенды и приходит подсказкой при наведении. Знак набран тем же
способом, что `S` (номер — рисованным нижним индексом), кегль `--text-sm`.

- **Номер `K` — порядок ребра на листе**, а не порядок условия в тексте: одно
  и то же условие (`AtTarget`) встречается на двух рёбрах, и знак называет
  переход. Поэтому в легенде рядом стоит примета `S3 → S5`.
- **У безусловного (`next`) знака нет вовсе**: условия у него не бывает.
- **Место знака относительно стрелки — авторское**: базовых мест три (начало,
  центр, конец), любое заменяется своим переносом. Правила — в патче книги,
  раздел `.edge-mark`.

## Легенда

**Две таблицы**: состояния (`S`) и условия переходов (`K`), каждая — «знак →
текст из модели → подпись автора → примета». Правила — в патче книги
(`03-BOOK.md.patch.md`, раздел `.legend`).

**Легенды двигаются относительно холста** (требование 2026-09-08): полка под
холстом (умолчание), колонка справа, плавающая панель поверх холста — её тянут
за заголовок с привязкой к сетке. На узком экране место одно — полка снизу.

- **Имя в модели — только чтение.** Схема не редактирует модель (решение A9
  карточки): переименование состояния делается текстом либо `rename` из
  редактора, и ключи раскладки едут за ним (R10).
- **Подпись автора — свободный текст**, в том числе кириллицей: это и есть
  «простое связывание» из требования. Пустая подпись — не «нет имени»: в поле
  стоит подсказка «имя из модели», и под кругом показывается само имя.
- **Выбор синхронен**: строка легенды, строка навигатора и узел на листе
  выделяются одной парой одновременно.

## Последствия для формата `.takt-ui` — решение аналитика

Подписи автора **обязаны переживать закрытие редактора**, а значит попасть в
файл раскладки: это авторская работа того же рода, что координаты. Предложение
к требованию R4 (формат файла) — добавить к листу карту подписей:

```json
{
  "format": 1,
  "corners": "square",
  "legend": { "place": "bottom", "x": 24, "y": 72 },
  "sheets": {
    "Engine": {
      "nodes": { "Idle": { "x": 240, "y": 72 } },
      "names": { "Idle": "Ожидание" },
      "edges": {
        "Idle>DoorClosing:0": {
          "points": [[240, 132]],
          "label": { "place": "center" },
          "name": "Есть вызов"
        },
        "DoorClosing>MovingUp:0": {
          "points": [[240, 276], [120, 276]],
          "label": { "place": "own", "x": 168, "y": 268 },
          "name": "Нужен подъём"
        }
      }
    }
  }
}
```

Что здесь появилось сверх координат: `names` — подписи состояний, `name` у
ребра — подпись условия, `label.place` — место знака (`start` | `center` |
`end` | `own` с координатами), `legend` — место легенды и её позиция при
плавающем размещении. Всё это авторская работа того же рода, что координаты, и
хранится с тем же каноном (ключи отсортированы, числа целые).

- ключ — то же имя состояния, что у координат; канон тот же (ключи
  отсортированы, отступ два пробела, `\n` в конце);
- подпись без состояния — та же «лишняя запись», что координата без
  состояния: попадает в уведомление о расхождении и снимается при записи (R5);
- `rename` переименовывает ключ подписи вместе с ключом координат (R10);
- поля `names` может не быть вовсе — старые файлы читаются как прежде.

**Чего дизайнер не решает:** входит ли `names` в формат первой редакции,
попадает ли в ссылку-снимок (`lay`) и как ведёт себя при импорте модели из
другого файла. Это вопросы задач 02 и 07 плана разработки; оформление к обоим
ответам готово — при отсутствии `names` под кругом стоит имя из модели, и
рисунок не меняется.
