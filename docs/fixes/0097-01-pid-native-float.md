# Исправление: пример ПИД на прозрачном `float` вместо явного `q(8, 8)`

> Фича: [../features/0097-pid-regulator-example.md](../features/0097-pid-regulator-example.md) ·
> опирается на механизм [q-арифметика через нативный float и флаг генерации (embedded ↔ float)](../features/0096-fixed-point-native-float.md)
> («прозрачный `float`») · запрошено заказчиком 2026-07-19

- **Статус:** **ИСПРАВЛЕН** (2026-07-19). `precheck.sh` зелёный (EXIT=0), весь
  тест-набор (2183 с `lsp`) зелёный.
- **Класс:** не дефект, а **приведение примера к предпочтительной форме
  авторства** (решение заказчика): числовые примеры пишутся на `float`, а
  представление `q` выбирается **флагами сборки** там, где нативного float нет.
  Ровно замысел фичи, применённый к корпусному примеру 0097.
- **Область:** `examples/pid_regulator.lam`, `scripts/precheck.sh`,
  `simulation/tests/examples_scenario_tests.rs`, регенерированный
  `examples/generated/{c,rust,st}/pid_regulator.*`. Крейты `grammar`/`simulation`
  (кроме теста) **не менялись** — механизм 0096 уже в ядре. Версия языка не
  менялась.

## Что изменилось

`examples/pid_regulator.lam` объявлял величины контура как `q(8, 8)`. Теперь они
объявлены как `float`; представление выбирают флаги генерации:

| Профиль | Флаги | Представление |
|---|---|---|
| `c` / `rust` / `st` (есть FPU) | — (умолчание) | нативный `double` / `f64` / `LREAL` |
| встраиваемые `c-hal` / `st-at` (МК без FPU) | `--float-embedded --float-as-q=8.8` | `q(8, 8)` |
| `sv` (FPGA/ASIC, нативного float нет) | `--float-as-q=8.8` | `q(8, 8)` (иначе `SV-003`) |

**Соседний `regulator.lam` Не трогали** — он остаётся демонстрацией `q(m, n)` как
**типа языка**. Так корпус сохраняет и явный `q`, и прозрачный
`float`.

### Ключевые факты, снятые пробой (2026-07-19)

- **`sv` через `--float-as-q=8.8` байт-в-байт равен прежнему явному q** (принцип
  0096-02): `diff examples/generated/sv/pid_regulator.sv` пуст, тестбенч
  `tb/pid_regulator_tb.sv` (хендрайтен, q-представление сигналов) остаётся
  валиден — проверка `verilator --binary` прошёл («ПИД сошёлся: ready, is_done,
  интеграл в пределах»). То есть коммит `.sv` **не изменился** от перевода
  источника.
- **`c-hal` / `st-at` через `--float-embedded --float-as-q=8.8` байт-в-байт
  равны** прежнему явному q для тех же целей (сверено `diff`).
- **Нативные `c`/`rust`/`st`** дают `double`/`f64`/`LREAL` без q-хелперов
  (`lam_q_floordiv` в выводе отсутствует); проходят свои проверки (`cc`,
  `rustc`+`clippy` под `-D warnings` в no_std, `iec2c`).
- **Тела написаны на переменных, не на литералах** — литерал `float` в теле дал
  бы `SV-003`; литералы только в инициализаторах объявлений.

## Правки

1. **`examples/pid_regulator.lam`:** типы `q(8, 8) → float`; шапка описывает выбор
   представления флагами (раздел «представление чисел»); anti-windup оставлен —
   он нужен q-представлению (wraparound), для нативного float безвреден.
2. **`scripts/precheck.sh`:**
   - список `FLOAT_AS_Q_EXAMPLES="pid_regulator"` + помощник `sv_float_flags`:
     цель `sv` для float-примеров получает `--float-as-q=8.8` (в проверке генерации и
     в проверке воспроизводимости 0048) — иначе `SV-003` уронил бы `SV_TRANSLATABLE`;
   - новый **«Проверка представления float»**: `pid_regulator` под
     `--float-embedded --float-as-q=8.8` обязан собираться в q для `c-hal`/`st-at`
     («q там, где аппаратного float нет») — жёсткий, ядро/флаги уже в репозитории.
3. **`simulation/tests/examples_scenario_tests.rs`:** тест
   `pid_integral_stays_bounded_and_converges` читал `i_acc`/`meas` как
   `Value::Fixed` (q-repr). В native-режиме симулятор считает `f64` → значения
   приходят `Value::Real`. Добавлен помощник `real_val`; проверки anti-windup и
   сходимости переписаны на значения (`|i_acc| ≤ 32.0`, PV → уставка `8.0`);
   удалён осиротевший `fixed_repr`. Контракт сценария и комментарий обновлены.
4. **`examples/generated/{c,rust,st}/pid_regulator.*`** регенерированы (нативный
   float). `sv`/`plantuml`/`_main.c` — без изменений.
