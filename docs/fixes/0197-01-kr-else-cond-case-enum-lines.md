# Исправление: канон стиля — K&R `else`, заглавные имена `cond`/`invariant`, перечисление по варианту на строке

> Фича: [../features/0197-language-code-style.md](../features/0197-language-code-style.md) · ADR: [../features/0197-language-code-style.md#архитектура-adr](../features/0197-language-code-style.md#архитектура-adr) · смежно: [канонический форматтер.lam (lamc fmt)](../features/0024-lam-formatter.md) (форматтер), [канон именования — предупреждение в fmt и LSP](../features/0226-naming-convention-warning.md) (канон именования)

- **Статус:** **ИСПРАВЛЕН** (2026-08-14), заведён в тот же день.
- **Обнаружено:** требованием заказчика 2026-08-14 — пересмотр трёх правил
  канона оформления.
- **Класс:** «канон описан в трёх местах, а решает одно» — правило живёт в
  форматтере, дублируется словами в документе и, для имён, в слое стиля.

## Проблема

Три правила канона расходились с тем, каким заказчик хочет видеть язык.

**1. `else` уходил на новую строку.** Документ объявлял это осознанным
расхождением с K&R («здесь Takt расходится с K&R, где принято `} else {`»), а
цепочка `else if` печаталась вовсе тремя строками:

```text
}
else
if level > limit {
```

**2. Имя `cond` каноном не проверялось вообще.** Ветка
`ast::ModelElement::Condition` падала в `_ => {}` слоя `style/naming.rs`, и
корпус успел разойтись: 46 имён `UpperCamelCase` против 20 `snake_case`
(`at_pickup`, `is_inbound`, `loaded`, `timeout`, `always_true`, …). То же — у
`invariant`, причём в двух местах сразу: `invariant` объявляется и элементом
модели, и элементом **состояния**.

**3. Перечисление всегда печаталось одной строкой** — и многострочную запись
автора форматтер схлопывал:

```takt
enum Op { Nop = 0, Lda = 1, Sta = 2, Add = 3, Sub = 4, Jnz = 5, Hlt = 6 }
```

## Причина

Отдельного «дефекта реализации» здесь нет — есть **решение заказчика**,
менявшее сам канон. Причина, по которой правки коснулись сразу пяти слоёв, в
другом: канон оформления имеет **три записи** — печать форматтера
(`takt-lang/src/format/`), проверка имён (`takt-lang/src/style/naming.rs`) и
свод правил словами (`book/src/21-code-style/index.typ`). Машинной сверки
«текст ↔ форматтер» нет и в общем виде она невозможна, поэтому
смена одного правила обязана пройти по всем трём записям вручную — иначе свод
становится обещанием, которого инструмент не исполняет.

Отдельно — **устройство накопителя печати**. `Out::line` завершает строку
`'\n'` **безусловно**, механизма продолжения не было вовсе; `else` оказывался
на своей строке не по решению, а по следствию. Для цепочки `} else if c {`
одного «дописать хвост» мало: заголовок `if c {` печатает **рекурсивный**
`stmt::print`, который не знает, что его позвали из ветки `else`.

## Решение

**Форматтер.** У `Out` появился `join(tail)` — снимает уже поставленный `'\n'`,
дописывает хвост и взводит `glued`, из-за которого следующая `line` печатается
без отступа. Флаг снимает первая же `line`; `blank` при взведённом флаге
подавлена (иначе восстановление пустой строки из исходника разорвало бы
`} else `), `finish` его проверяет. Ветка `S::If` свелась к одному приёму —
`join(" else ")`, дальше либо блок (`} else {`), либо рекурсивный `print`
(`} else if c {`); трёхстрочная ветка `else if` удалена.

Перечисление печатает `print_enum`: заголовок `enum Имя {`, по варианту на
строке, `}` отдельной строкой. **Висячей запятой нет** — грамматика
перечисления `CommaOne<EnumVariant>` её не принимает, и напечатанная запятая
сделала бы файл неразбираемым; это в точности класс исправления
[`taktc fmt` теряет реализацию модели](0199-01-fmt-drops-model-implement.md), где `fmt` уничтожал исходник
на месте. Заголовок печатается `line`, а закрывающая скобка —
`node_line(&loc, "}")`: `loc` перечисления покрывает запись **целиком**, и
хвостовой комментарий у него ровно один — тот, что стоит **за** `}`;
приклеенный к заголовку, он уехал бы вверх и на втором прогоне не нашёлся бы
там, где его ищут, — то есть печать перестала бы быть идемпотентной.

**Канон имён.** Ветки `Condition` («условие») и `Invariant` («инвариант») —
`UpperCamelCase`. Обход дополнен спуском в тело состояния
(`collect_state_element`, **исчерпывающий** `match` без `_`): `invariant`
объявляется и там, и без спуска правило действовало бы через раз — хуже, чем
не действовать.

**Корпус.** Переименованы 20 имён `cond` вместе со всеми ссылками; прогнан
`taktc fmt` по `examples/` и `book/src/**/examples/`; фикстуры тестов и
Takt-код внутри строковых литералов Rust приведены к новому канону точечно (по
трём затронутым конструкциям — сплошная нормализация фикстур сдвинула бы
позиции, на которые завязаны тесты LSP и диагностик).

**Документ.** Правило «`else` с новой строки» и «перечисление в одну строку
такой и остаётся» изъяты из `book/src/21-code-style/index.typ`; таблица канона
имён дополнена строкой `cond`/`invariant` (там же и в
`book/src/appendix-errors/index.typ`).

**(редакторский слой).** Правок **не требует**, и это проверено:
лексика, синтаксис и семантика не менялись, а LSP зовёт те же `format_source`
и `naming_warnings`, что и `taktc fmt`. Плагины
IntelliJ и Zed собственных правил стиля не ведут; их Kotlin-фикстуры с
`enum`/`cond` — входные данные лексера и сканера символов, к канону печати
отношения не имеющие.

## Проверки

- `takt-lang/tests/syntax/format_style_canon_tests.rs` — новые контроля, фикстурные
  (не зависящие от того, лежит ли подходящий файл в корпусе,):
  K&R для простого `else`, плоская цепочка `else if`, `if x {} else {}` одной
  строкой с круговым рейсом через `parse`, отступ на вложенности, комментарий
  между `}` и `else`; для перечисления — точный вид печати, **отсутствие
  висячей запятой с проверкой разбора**, отступ во вложенной модели, хвостовой
  комментарий при `}`, комментарии вариантов. Корпус эти классы почти не
  покрывает: цепочек `else if` в 308 файлах **ноль**, хвостовых комментариев у
  перечисления — **ноль**.
- `takt-lang/tests/syntax/style_naming_fmt_tests.rs` — список канона вырос с
  двенадцати видов до четырнадцати; добавлены контроля на `invariant` **в теле
  состояния** и контр-пример (`next`/`ref`/`always`/`every` не дают `CS-001` —
  ловит противоположную ошибку, «проверять то, на что лишь ссылаются»).
  `corpus_has_no_style_warnings` зелен: в `examples/` не осталось ни одного
  `CS-001`.
- `takt-lang/tests/syntax/format_tests.rs::a1_a3_corpus_report` — идемпотентность и
  семантическая нейтральность печати на всём корпусе.
- `./scripts/precheck.sh` — код возврата 0 (в нём `taktc fmt --check
  examples/`, проверка воспроизводимости 0048 и проверка примеров книги 0133).
