# Исправление: присваивание порта из порта даёт E0499 в цели `rust`

> Фича: [../features/0148-rust-printers-coverage.md](../features/0148-rust-printers-coverage.md) · анализ: [../features/0148-rust-printers-coverage.md#анализ](../features/0148-rust-printers-coverage.md#анализ) · отчёт: [../features/0148-rust-printers-coverage.md#отчёт-о-тестировании](../features/0148-rust-printers-coverage.md#отчёт-о-тестировании)

- **Статус:** **Заведён** (2026-07-29), обнаружен при разработке фичи.
- **Tier 2 — порождённый код не компилируется.** Отказ громкий; молча неверного
  поведения нет.
- **В объём 0148 не входит:** лечение вводит в печатник **новый** механизм
  (временные переменные), тогда как соседний исправление
  [сравнение `bit` с литералом даёт некомпилируемый Rust](0148-01-rust-bit-compare.md) обошёлся уже существующей коэрцией.
  Смешивать два предмета под одним номером — урок фичи.

## Проблема

Простейшая проводка «вход на выход» не транслируется:

```
in btn: bit;
out led: bit := 0;
model M { start S { always { led := btn; } ref T: btn; } state T; }
```

Порождается

```rust
hal.write_bit(OutBitPort::Led, hal.read_bit(InBitPort::Btn));
```

и `rustc` отвечает

```
error[E0499]: cannot borrow `*hal` as mutable more than once at a time
```

## Причина

И `write_bit`, и `read_bit` принимают `&mut self`. Внешний вызов захватывает
`hal` изменяемо **до** вычисления аргумента, а аргументу нужен тот же `&mut`.
Двухфазное заимствование здесь не спасает: оно допускает `v.push(v.len())`,
потому что `len` берёт `&self`, — а тут оба вызова изменяемые.

Два **чтения** в одном выражении проблемы не дают: `a & b` вычисляет операнды
последовательно, и заимствования не пересекаются. Именно поэтому
`stacker.rs` с двумя `hal.read_bit(...)` в одном условии компилируется.

## Почему дожило

Корпус ни разу не присваивает порт из порта: примеры вычисляют выход из
переменных состояния. Проверка цели `rust` гоняет только корпус — класс входа ему не
встречался.

## Что делать

Выносить чтение во временную переменную перед записью:

```rust
let value = hal.read_bit(InBitPort::Btn);
hal.write_bit(OutBitPort::Led, value);
```

Открытые вопросы (потому и нужен разбор, а не правка на месте):

- **чем определять необходимость выноса** — структурно (выражение содержит
  чтение порта либо вызов `extern fn`) или текстово (вывод содержит приёмник
  HAL). Текстовая проверка хрупка;
- **где заводить временную** и как **именовать**, чтобы не столкнуться с
  переменными модели и с временными соседних операторов;
- **порядок вычисления**: вынос меняет момент чтения порта относительно прочих
  операторов такта, то есть требует сверки с эталоном (цель `c` читает порт в
  том же выражении).

После починки — регресс **значением** (сверка с целью `c`), а не только фактом
сборки, плюс тест текста в `rust_printers_tests`.
