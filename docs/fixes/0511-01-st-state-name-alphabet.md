# Исправление: имя состояния судится алфавитом, а не занятостью

> Фича: [../features/0511-st-iec-keywords.md](../features/0511-st-iec-keywords.md)

## Проблема

Пополнение списка зарезервированных имён IEC  сделало **ложным**
отказ на именах состояний: `state On { … }` — обычная модель из примера
`book/src/01-overview/examples/blinker.takt` — стала получать `ST-014`, хотя её
вывод арбитр принимал и принимает.

Обнаружено прогоном **всех** примеров документа целью `st` при работе над
следующей фичей: отказ получили четыре примера (`blinker`, `ports`, `climate`,
`beacon`).

Машина об этом молчала: проверка примеров `book/` (0133) компилирует целью `c`, а
отказ цели `st` в предкоммите **не жёсткий** (генератор дописывается — так
устроено с 0041). То есть класс лежал ровно в слепом углу двух проверок.

## Причина

Проверка имени состояния (`check_st_name`, введена фичей ради **алфавита**)
заодно судила и занятость имени стандартной библиотекой IEC. До 0511 это почти
не проявлялось — список знал функции и типы, — но в выводе цели `st` имя
состояния **идентификатором не становится**: автомат печатается числами, а имя
попадает только в комментарий:

```
state := 2; (* On *)
```

То есть занятость имени к состоянию отношения не имеет вовсе, и отказ на него
был ложным и до 0511 (состояние `Exit`, `Step`, `Min` получило бы его же).

## Решение

Заведена `st_reserved::check_st_state_name` — проверяет только алфавит
(`ST-020`, не-ASCII попадает в комментарий и в разбор `CASE`). Имена
переменных, POU, функций и полей судятся по-прежнему.

Попутно примеры документа приведены к правилу: `on` → `enable`
(`07-functions`), `log` → `trail` (`03-types`). Оба имени `iec2c` отвергает как
идентификатор, и оба примера теперь проходят арбитра целиком — причём у
`functions.takt` тем самым снят и **segfault** `iec2c`, который прежде числился
отдельным кандидатом.

## Проверки

- `st_reserved_names_tests::state_name_is_not_judged_by_reservation` — модель с
  состоянием `On` переводится, а переменная `on` по-прежнему даёт `ST-014`
  (контроль обратного).
- Прогон **всех** примеров `book/` целью `st` с прогоном `iec2c`: остались
  только законные `ST-011` (границы цели) на двух примерах.
- `./scripts/precheck.sh` — зелёный.
