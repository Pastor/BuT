# Исправление: устаревшие стабы SV в каталоге вывода (доделка проверки)

> Фича: [../features/0045-sv-backend.md](../features/0045-sv-backend.md) · задача: [../features/0045-sv-backend.md#разработка](../features/0045-sv-backend.md#разработка) · обнаружено при эксплуатации (запуск `precheck.sh`, ревью каталога `examples/generated/sv/`)

- **Статус:** ИСПРАВЛЕН

## Проблема

`examples/generated/sv/` содержал **три вырожденных стаба** —
`comprehensive.sv`, `elevator.sv`, `extend_complex.sv` (по 33 строки, пустой
`always_comb begin state_next = state; end`, без портов и функций). Они не
соответствовали текущим `.lam`: например, у `extend_complex` состояния
`ST_START`/`ST_END`, тогда как у корня модели — `Start`/`Next`. Компилятор эти
примеры сегодня **не транслирует вовсе**:

```
comprehensive  SV-002  цикл `for` без известных на этапе синтеза границ
elevator       SV-005  внешние функции (extern fn)
extend_complex SV-002  досрочный возврат из функции `is_collected`
```

Файлы читались как «SV сгенерирован кусками/недоделан», хотя на деле вывода для
этих примеров нет. Проверка `verilator`/`yosys` их молча принимал (стабы валидны),
то есть каталог хранил вывод, которого компилятор уже не производит.

## Причина

[генератор генерации в SystemVerilog](../features/0045-sv-backend.md#разработка) (проверка SV) закрывалась на
**каркасе** [генератор генерации в SystemVerilog](../features/0045-sv-backend.md#разработка), когда транслировались
**все пять** примеров корпуса — их стабы попали в коммит `1bc357b`. Позже
[генератор генерации в SystemVerilog](../features/0045-sv-backend.md#разработка) добавила отказы
`SV-002`/`SV-005`, и три примера перестали транслироваться.

`precheck.sh` пишет вывод через `lamc ... -o "$SV_OUTPUT"`: файл создаётся только
при **успехе** генерации, а отказ старый файл **не трогает**. Поэтому стабы от
каркаса пережили появление отказов. Контроль задачи проверял лишь одну
сторону — что примеры из `SV_TRANSLATABLE` **присутствуют**; обратную сторону
(лишних `.sv` быть не должно) он не ловил.

## Решение

1. Удалены три устаревших стаба из `examples/generated/sv/`.
2. В `scripts/precheck.sh` (секция проверки sv) добавлен **зеркальный контроль**:
   каталог `examples/generated/sv/` обязан содержать **ровно** примеры из
   `SV_TRANSLATABLE`. Любой лишний `.sv` роняет предкоммит с подсказкой — либо
   это устаревший стаб (`git rm`), либо пример начал транслироваться (внести в
   `SV_TRANSLATABLE`). Так симметрично ловится дрейф в обе стороны.

Правка аддитивна (правило 11): существующий прямой контроль и прогон
`verilator`/`yosys` не тронуты; список `SV_TRANSLATABLE` остаётся единственным
источником истины о том, что цель `sv` обязана транслировать.

## Проверки

- **Чистый каталог — зелёный:** новый контроль даёт `sv_failed=0`; `verilator
  --lint-only -Wall` и `yosys synth -top` принимают `stacker.sv` и
  `elevator_mini.sv`.
- **Регресс ловится (проверка, который никогда не падал, — не проверка):** возврат стаба
  `comprehensive.sv` в каталог даёт `ЛИШНИЙ comprehensive.sv` и `sv_failed=1`.
- Проверки выполнены под `bash` (реальный shebang `precheck.sh`); связь с
  тест-планом фичи — критерии A3/A4 (проверка определяет, что считать правдой).
