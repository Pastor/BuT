# Исправление: симулятор не исполняет композицию с переходом `next`

> Фича: [../features/0057-sv-sequential-composition.md](../features/0057-sv-sequential-composition.md) · обнаружено при разработке сверки 0057-04

- **Статус:** **ИСПРАВЛЕН** (2026-07-29) фичей
  [симулятор исполняет реализацию состояния с переходом next](../features/0181-sim-state-implementation-tick.md). Заведён 2026-07-18.
  **Tier 2 — расхождение эталонов, не молчаливо неверный продукт.** Симулятор —
  эталон поведения; его дефект не портил порождённый код, но делал симулятор
  непригодным как эталон для `+`.
- **К цели `sv` отношения не имеет:** порождённый SV **верен** — сверен
  потактово с целью `c` (второй named-эталон ADR),
  `conformance_sv_tests.rs::sequential_composition_matches_generated_c`.
- **Класс:** «эталон А и эталон Б разошлись». ADR объявил эталоном `+`
  **обе** реализации — C (`generate_concat_tick`) и симулятор
  (`Unit::Sequential`), — предполагая их совпадение. Они **не совпадают**.

## Что не так

Состояние-реализация, несущее переход `next` (`start P = A + B { next Done; }`),
в симуляторе **не тикает шаги композиции** — оно немедленно уходит по `next`
(или терминирует), словно композиции нет.

Проба (2026-07-18, `build_unit` + потактовый прогон):

| Модель | Такт 1 | Поведение |
|---|---|---|
| `start P = A + B { next Done; }` | `states=["P"]`, `Terminated`, шаги не исполнены | **дефект** |
| `start P = A + B;` (без `next`) | `states=["S2"]`, шаги исполняются | работает (с оговоркой ниже) |
| `model P { start Q = A + B { next Done; } … } start R = P;` | `states=["Q"]`, `Terminated` | **дефект** (вложение не спасает) |

То есть триггер — **`next` на состоянии-реализации**, на любой глубине.

Дополнительно у работающей формы (`start P = A + B;`) наблюдается **сброс
наблюдаемой корневой переменной в 0 на такте переключения шага** (проба:
`stage` = 1 → 0 → 2 вместо 1 → 1 → 2) — вторичный дефект того же узла.

Порождённая цель `c` для тех же моделей даёт **верную** трассу
(`stage` = 1, 1, 2, 2, затем `Done`), совпадающую с SV.

## Почему дожило

`extend_complex.lam` (единственный пример корпуса с `+`) — корневая композиция
`A + B + (C|D) + E { next Next; }`, то есть ровно триггерная форма. Он **исключён**
из `examples_scenario_tests` («сценария не заявляет»), а `stacker`/`elevator_mini`
используют `|`, не `+`. Потактовой сверки цели `st`/`c` на `+`-с-`next` не было.
Итог: **потактовое исполнение `+` симулятором не проверялось нигде** — классическая
дыра в покрытии.

## Что делать

Исправить `simulation/src/unit/` так, чтобы состояние-реализация сперва тикало
композицию и брало `next` **только по её завершении** (эталон — C
`generate_extend_transition`: переход выполняется в ветви `is_done`). После
починки — снять исключение `extend_complex` из `examples_scenario_tests` (если
устранить и `extern fn`-препятствие) и **добавить сверку sim↔SV** рядом с
существующей sim↔C/SV↔C (`conformance_sv_tests.rs`), закрыв тройную сверку.

Смежно: дефект вторичного сброса `stage` — тот же узел `Unit::Sequential`.

## Как исправлено (фичей-29)

Разбор — [ADR](../features/0181-sim-state-implementation-tick.md#архитектура-adr), отчёт —
[reports/0181](../features/0181-sim-state-implementation-tick.md#отчёт-о-тестировании). Кратко:

1. **Композиция строится** дочерним юнитом узла (`UnitKind::Node::state_impls`)
   с контекстом узла как общим родителем. Прежде `build_node` поле `implements`
   состояния не читал вовсе.
2. **Такт узла тикает реализацию до проверки переходов**; переход берётся
   только по её завершении, на том же такте (`tick_node`, шаг 1a).
3. **Шаги `+` делят родительский контекст** — общий `shared_context` для
   `Concatenation` и `Parallel`; вторичный сброс `stage` устранён этим же.
4. **Наблюдение переживает завершение** — `Sequential::get_value` читает
   последний шаг при `index == units.len()`.
5. Дополнительно вскрылось: **`next` не был переходом вовсе** (жил отдельным
   полем `StateNode::Implement::next`, `build_transitions` его не собирал) —
   исправлено там же.

Тройная сверка sim ≡ C ≡ SV закрыта на обеих формах (`A + B` и `A + (B | C)`),
значенческие тесты — `takt-sim/tests/sim/sequential_composition_tests.rs`.

Исключение `extend_complex` из `examples_scenario_tests` **не снято**: его
причина — не этот дефект, а отсутствие заявленного сценария у стенда синтаксиса
(и `extern fn`). Корпусной пример на `+` с контрактом заводит фича
[корпусной SV-транслируемый пример на последовательную композицию `+`](../features/0166-sv-example-sequential-composition.md), которую 0181 и
разблокировала.
