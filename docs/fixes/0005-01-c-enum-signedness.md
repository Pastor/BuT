# Исправление: цель `c` теряет знак перечисления — переход мёртв молча

> Фича: [../features/0005-enums.md](../features/0005-enums.md) (+ [генератор C: отображение типов Array/Bit/Rational](../features/0029-c-type-mapping.md) — где живёт ветка `get_c_type`) · обнаружено при проработке [фичи](../features/0060-enum-width-shared-layer.md)

- **Статус:** **ИСПРАВЛЕН** (2026-07-18). Tier 1 — **молчаливо неверный вывод**.
- **Исправлен в объёме** [расчёт ширины перечисления — вынести в общий слой](../features/0060-enum-width-shared-layer.md):
  миграция цели `c` на общий расчёт (`semantic::enum_facts`) сделала знак верным
  **как следствие** — `enum Level { Low = -5 }` даёт `int8_t`, переход
  срабатывает. Доказано потактовой сверкой `conformance_c_tests`
  (`neg_enum_signedness_matches_generated_c`): `lv = -5`, `reached = 1`; плюс
  `-Werror=tautological-*` ловит возврат дефекта на сборке.
- **Класс:** тот же, что у [тихая мистрансляция `+` внутри `|` в целях C и Rust](./0003-01-concat-in-parallel-silent.md) —
  тихая мистрансляция: код компилируется, а автомат стоит.

## Что не так

`get_c_type` (`generator/c/mod.rs:218–239`) для `TypeNode::Enum` смотрит **только
на `max`** и **никогда** не проверяет знак:

```rust
let max = enum_node.variants.into_iter()
    .sorted_by(|a, b| a.1.cmp(&b.1))
    .collect::<Vec<(String, i64)>>()
    .last().map(|x| x.1).unwrap_or_default();
let bits: u8 = if max > u32::MAX as i64 { 64 } else if … { 8 };
Ok(format!("uint{}_t", bits))     // ← ВСЕГДА беззнаковый
```

Отрицательный вариант в C становится **беззнаковым полем**, а значение
печатается как есть.

## Проба (2026-07-17), четыре цели на одном входе

Вход: `enum Level { Low = -5, Mid = 0, High = 5 }`, `var lv: Level := Mid;`

| Цель | Тип | Верно? |
|---|---|---|
| **`c`** | **`uint8_t lv;`** | **НЕТ** — знак потерян |
| `rust` | `#[repr(i8)] pub enum Level { Low = -5, … }` | да |
| `st` | `lv : SINT;`, `Level_Low : SINT := -5;` | да |
| `sv` | `level_e` (знаковая ширина) | да |

То есть **три цели из четырёх правы, а эталонная — нет**.

## Чем это грозит: переход мёртв, автомат стоит

Порождённый C (модель `ref Done: lv = Low;` при `enter { lv := Low; }`):

```c
model->lv = -5;                 /* uint8_t ← -5 */
if (model->lv == -5) { … }      /* никогда не истинно */
```

**Проверено живым `cc`** (не рассуждением):

```
lv = 251
(lv == -5) = 0   ← переход не сработает НИКОГДА
```

`-5` заворачивается в `251`; при сравнении `uint8_t` продвигается до `int` (251),
а литерал остаётся `-5` → условие **тождественно ложно**, состояние `Run` не
покидается **никогда**. Модель, верная в симуляторе и в трёх других целях, в C
**молча стоит**.

`cc` **предупреждает**
(`-Wtautological-constant-out-of-range-compare: comparison … is always false`), но
это **предупреждение**, а не ошибка: проверка цели `c` (`cmake` + `ninja`, без
`-Werror`) такой код **принимает**. То есть контроль есть, но выключен — ровно урок: «проверка доказывает, что вывод компилируется, но не что он верен».

## Почему дожило

1. **Дыра в покрытии, а не в коде** (класс [генератор C: typedef корневой структуры для одиночной модели](../features/0026-c-root-typedef.md)):
   **ни одно** перечисление корпуса не имеет отрицательных вариантов — `Mode` 0…2,
   `Floor` 80…81, `Action` 670…671, `Command` 0…2, `Constant` 0…2, `Point` 0…1.
2. **`CLAUDE.md` прямо объявляет `Enum` доверенным** для сверки с C: «Не используй
   вывод C как эталон для этих типов (сверка — только `Integer`/`Enum`/`Bool`)».
   Проба это **опровергает** — доверять можно только **неотрицательным**
   перечислениям. Формулировку в `CLAUDE.md` необходимо поправить вместе с исправлением.
3. Потактовая сверка (`conformance_c_tests`) отрицательных перечислений **не
   гоняет**.

## Как чинить

Миграция цели `c` на **общий** расчёт диапазона/знака ([расчёт ширины перечисления — вынести в общий слой](../features/0060-enum-width-shared-layer.md)): знак — `min < 0`, тип —
`int{bits}_t` при знаковом диапазоне, `uint{bits}_t` иначе. Ветка `get_c_type`
перестаёт считать сама.

## Критерии закрытия

1. `enum Level { Low = -5, … }` → в C **`int8_t`**, а не `uint8_t`.
2. Переход `ref Done: lv = Low;` **срабатывает** (сегодня — никогда).
3. **Потактовая сверка** с симулятором на модели с отрицательным перечислением —
   зелёная (`conformance_c_tests`); сверка обязана быть **заведена вместе с
   исправлением**, иначе дефект вернётся молча.
4. `cc` не выдаёт `-Wtautological-constant-out-of-range-compare` на порождённом
   коде.
5. Формулировка `CLAUDE.md` про доверие к `Enum` при сверке — **исправлена**.
6. Корпус не меняется (в нём нет отрицательных перечислений) — то есть исправление
   доказывается **новой** фикстурой, а не диффом корпуса.
