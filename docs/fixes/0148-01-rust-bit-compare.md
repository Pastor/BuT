# Исправление: сравнение `bit` с литералом даёт некомпилируемый Rust

> Фича: [../features/0148-rust-printers-coverage.md](../features/0148-rust-printers-coverage.md) · анализ: [../features/0148-rust-printers-coverage.md#анализ](../features/0148-rust-printers-coverage.md#анализ) · отчёт: [../features/0148-rust-printers-coverage.md#отчёт-о-тестировании](../features/0148-rust-printers-coverage.md#отчёт-о-тестировании)

- **Статус:** **ИСПРАВЛЕН** (2026-07-29). Заведён в тот же день, при разработке
  тестов ветвей печатников.
- **Tier 2 — порождённый код не компилируется.** Отказ громкий, а не молчаливый,
  но пользователь не соберёт вывод вовсе.
- **Класс:** «два типа языка склеены в один тип цели» — `bit` в Takt целое
  однобитное, в Rust отображается на `bool`.

## Проблема

Три естественные записи проверки `bit` дают три разных исхода:

| Запись | `rustc` | `clippy -D warnings` |
|---|---|---|
| `ref T: btn = 1;` | **ОТКАЗ** `E0308: expected bool, found integer` | — |
| `ref T: btn = true;` | ОК | **ОТКАЗ** `clippy::bool_comparison` |
| `ref T: btn;` | ОК | ОК |

То есть **две из трёх** не проходят политику `-D warnings` проверки цели (ADR,
R9), а первая не компилируется вовсе. Проба 2026-07-29, форма
`in btn: bit; … ref T: btn = 1;` → `if hal.read_bit(InBitPort::Btn) == 1 {`.

Дефект касается и **переменных**: `var b: bit; … ref T: b = 1;` давало
`shared.b == 1` с той же ошибкой типов.

## Причина

`print_condition` печатал `Equal`/`NotEqual` через общий `cond_binary`, то есть
дословно: `<левый> == <правый>`. Для `bit`-операнда левая часть — `bool`
(`hal.read_bit(...) -> bool`), а правая — целочисленный литерал.

**Присваивание при этом работало верно**: `o := 1` даёт
`hal.write_bit(OutBitPort::O, true)` — коэрция литерала к `bool` там уже есть.
Разошлись два пути одной идеи.

## Почему дожило

Корпус ни разу не сравнивает `bit` с литералом: примеры пишут либо голый порт
(`ref X: btn;`), либо `if WAIT { … }`. Проверка цели `rust` гоняет **только**
корпус — значит, этот класс входа он не встречает. Ровно та дыра покрытия, ради
которой фича и заведена.

## Решение

`takt-lang/src/generator/rust/rust_cond.rs` — новая ветвь `boolean_comparison`,
проверяемая в `Equal`/`NotEqual` **после** спецформы `S(Модель) = Состояние` и
**до** общего `cond_binary`.

Если один операнд булев по статическому типу (`condition_type` → `Bit`/`Bool`),
а другой — литерал (`true`/`false` или число, 0 — ложь), печатается сам операнд:

- `x = 1`, `x = true` → `x`;
- `x = 0`, `x = false` → `(!x)`;
- для `!=` знак переворачивается.

Литерал ищется с **обеих** сторон (`1 = btn` так же законно). Проверка «второй
операнд не литерал» обязательна: иначе вырожденное `true = false` попало бы в
первую ветвь и потеряло вторую половину.

## Проверки

Регресс — `takt-lang/tests/targets/rust_printers_tests.rs`, пять тестов: сравнение с
числом, с нулём, `!=`, с булевым литералом, литерал слева. Плюс **контрпример**
`integer_compared_with_number_stays_a_comparison`: у целого операнда сравнение
обязано остаться сравнением — без него «починка», сводящая к операнду всё
подряд, прошла бы остальные тесты и сломала обычные сравнения.

| Проба (`rustc` + `clippy -D warnings`) | До | После |
|---|---|---|
| `btn = 1` | `E0308` | ОК |
| `b = 1` (переменная `bit`) | `E0308` | ОК |
| `btn = true` | `bool_comparison` | ОК |
| `btn` (голый) | ОК | ОК |

Взведённость доказана мутацией (`boolean_comparison` возвращает `None` всегда):
падают ровно пять тестов ветви, остальные 22 зелены.

`examples/generated/rust/**` не изменился — корпус этой формы не содержит.
`./scripts/precheck.sh` зелёный.
