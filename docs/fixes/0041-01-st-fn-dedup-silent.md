# Исправление: цель `st` молча склеивает одноимённые `fn` разных моделей

> Фича: [../features/0041-st-backend.md](../features/0041-st-backend.md) · обнаружено при проработке [фичи](../features/0065-st-namespace-isolation.md)

- **Статус:** **ИСПРАВЛЕН** (2026-07-18). **Tier 1 — молчаливо неверный вывод.**
- **Исправлен в объёме** фичи [изоляция пространства имён цели `st` (POU и переменные)](../features/0065-st-namespace-isolation.md)
  (префиксация POU именем модели-владельца делает функции разными **как
  следствие**; дедупликация по голому имени снята). Доказано структурно (две
  `FUNCTION` с разными телами), на уровне C (`iec2c` эмитит две `___*_HELPER`) и
  **поведенчески** — потактовая сверка `conformance_st_tests.rs`:
  модель `B` даёт `wb = 3` своей функцией, а не `2` (склейка с телом `A`).
- **Класс:** тот же, что у [тихая мистрансляция `+` внутри `|` в целях C и Rust](./0003-01-concat-in-parallel-silent.md) и
  [цель `c` теряет знак перечисления — переход мёртв молча](./0005-01-c-enum-signedness.md) — код компилируется, автомат стоит.

## Что не так

`st_func.rs:275` (`emit_functions`) дедуплицирует функции **по голому имени**:

```rust
// Пространство имён функций в IEC — плоское, поэтому дедупликация по имени.
// Одноимённые функции разных моделей столкнулись бы; столкновение поймает
// `iec2c` («duplicate»), то есть громко, а не молча.
let mut emitted: Vec<String> = Vec::new();
```

**Комментарий неверен, и проба это доказывает.** Дедупликация означает, что
`iec2c` **никогда не увидит дубля**: эмитится **одна** функция — тело первой
модели, — а тело второй **исчезает молча**. Ловить нечего.

## Проба (2026-07-17)

Вход: две модели, у каждой своя `fn helper` с **разными** телами.

```
model A { fn helper(x: u8) -> u8 { return x + 1; } … }
model B { fn helper(x: u8) -> u8 { return x + 2; } … }
start Top = A | B;
```

| Цель | Результат |
|---|---|
| **`c` (эталон)** | `DupA_helper` (`x + 1`) **и** `DupB_helper` (`x + 2`) — две разные функции; A зовёт первую, B вторую |
| **`st`** | **одна** `FUNCTION helper : USINT` с телом **`helper := x + 1;`** — на **обе** модели |

`grep -c "FUNCTION helper"` по порождённому `.st` → **1**.

**`iec2c` порождённый ST принял** (`rc = 0`, POUS.c/POUS.h порождены) — как и
должен: дублей в тексте нет.

## Чем это грозит: автомат стоит

Модель `B` вычисляет `w := helper(1)`.

- **Эталон (`c`):** `w = 1 + 2 = 3` → переход `ref Done2: w = 3` **срабатывает**.
- **Цель `st`:** `w = 1 + 1 = 2` → условие `w = 3` **никогда** не истинно →
  состояние `Run2` не покидается **никогда**.

Модель, верная в симуляторе и в цели `c`, на ПЛК **молча стоит**.

## Почему дожило

1. **Ложная уверенность, записанная в комментарии.** Автор 0041 предположил, что
   столкновение поймает `iec2c`, и дедупликацию поставил как «безопасное»
   упрощение. Проба опровергает: ловить нечего — второй функции в тексте **нет**.
2. **Кандидат унаследовал ошибку.** Формулировка кандидата (`FEATURES.md`) прямо
   повторяет комментарий: «Оба случая `iec2c` ловит **громко**
   («duplicate»/«invalid name»), **тихого расхождения нет** — поэтому кандидат, а
   не дефект». Из-за этого дефект Tier 1 три месяца числился «долгом Tier 3».
3. **Дыра в покрытии.** В корпусе нет двух моделей с одноимёнными `fn` — проверка
   `iec2c` зелен, и сказать ему нечего.
4. **Сверки для цели `st` нет вовсе.** `conformance_st_tests` не существует
   (есть `c`, `sv`, `rust`) — то есть поведенческая проверка ST не делается
   **никогда**, а проверка доказывает лишь компилируемость.

## Как чинить

Префиксовать POU **уникальным именем модели**, как это делает цель `c`
(`DupA_helper`/`DupB_helper`) — объём фичи
[изоляция пространства имён цели `st` (POU и переменные)](../features/0065-st-namespace-isolation.md). Дедупликация по голому имени
тогда исчезает вместе с причиной: имена перестают совпадать.

**Убрать дедупликацию, не префиксуя, — нельзя:** тогда `iec2c` действительно
даст «duplicate», то есть тихий дефект станет громким отказом. Это лучше
сегодняшнего, но всё равно отказ на корректной модели.

## Критерии закрытия

1. Две модели с одноимёнными `fn` дают в ST **две разные** функции (как в `c`).
2. Модель `B` из пробы вычисляет `w = 3`; переход `Done2` **срабатывает**.
3. **Потактовая сверка цели `st`** с симулятором на этой модели — зелёная.
   Сверки для `st` **не существует** — её придётся завести (правило проекта:
   «заводить сверку вместе с генератором»; для `st` это долг с фичи).
4. Комментарий `st_func.rs:275` — **исправлен**: он утверждает неправду и переживёт
   правку кода, если его не тронуть.
5. `iec2c` принимает вывод; корпус не меняется (одноимённых `fn` в нём нет).
