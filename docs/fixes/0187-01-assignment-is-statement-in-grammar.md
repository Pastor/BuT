# Исправление: присваивание отвергается семантикой, а должно — грамматикой

> Фича: [../features/0187-port-io-redesign.md](../features/0187-port-io-redesign.md) · ADR: [../features/0187-port-io-redesign.md#архитектура-adr](../features/0187-port-io-redesign.md#архитектура-adr) · задача: [../features/0187-port-io-redesign.md#разработка](../features/0187-port-io-redesign.md#разработка)

- **Статус:** **ИСПРАВЛЕН** (2026-08-01), заведён в тот же день **по требованию
  заказчика**: правило «присваивание — всегда отдельная операция» обязано
  держаться **синтаксисом** языка, а не проверкой после разбора.
- **Tier 3 — форма отвергается, но не тем слоем.** Молча неверного продукта нет:
  задача уже закрыла дыру диагностикой `SE-095`. Предмет исправления — **где**
  проходит граница языка.

## Проблема

Присваивание в языке Takt **синтаксически является выражением**: узел
`Expression::Assign` стоит в общей цепочке приоритетов (`Chain14<Precedence1Full>`
в `grammar.lalrpop`), поэтому разбирается везде, где допустимо выражение.

Проба 2026-08-01 (`takt_lang::parse`, то есть **только разбор**, без семантики) —
все три формы принимаются:

| Вход | Результат разбора |
|---|---|
| `var y: u8 := (x := 7);` | разобралось |
| `always { b := (a := 3) + 1; }` | разобралось |
| `always { if (a := 1) = 1 { … } }` | разобралось |

Отвергает их сегодня **семантика** — `SE-095`
(`validate/assignment_position.rs`). Это работает, но означает,
что в языке присваивание всё ещё выражение, а «оператор» — соглашение, которое
доказывается проверкой, а не формой.

## Чем это плохо

- **Граница языка описана в двух местах.** Грамматика говорит «выражение»,
  семантика — «оператор». Любой потребитель АСД (форматтер, LSP, плагины,
  будущие инструменты) видит форму, которой в языке нет: `format_source`
  напечатает `(x := 7)`, подсветка покажет его законным, автодополнение
  предложит.
- **Диагностика приходит позже, чем могла бы,** и указывает позицию
  **объявления** цели записи, а не место нарушения: `ExpressionNode` позиций не
  несёт (решение фичи). Парсер же знает точную позицию токена `:=`.
- **Тест парсера закрепляет обратное:** `feature_0021_operators.rs::
  colon_assign_expression_is_assign_node` требует, чтобы `(x := 7)` давал
  `Expression::Assign`. Пока он зелёный, грамматика обязана эту форму принимать.

## Что нужно сделать

1. Вывести присваивание из цепочки выражений в **правило оператора**: тело
   (`x := 1;`) и шаг цикла `for` — предполагались единственными позициями, где
   оно законно. Проба при разработке нашла **третью** — именованный аргумент
   инстанцирования (`Pid(kp := 0.25)`), см. «Как исправлено».
2. Новый код **`SY-006`** («присваивание не является выражением») с позицией
   токена `:=`.
3. Снять `SE-095` (пометить `RETIRED`) — либо оставить как недостижимую
   страховку **с явным обоснованием**; решение принимается при разработке.
4. Обновить тест (он фиксирует старую форму), форматтер и редакторский слой, приложение «Ошибки» документа.

## Цена и риски

- **Правка идёт в цепочку приоритетов, которую ADR велел писать один
  раз** (`Chain<Atom>`, два инстанцирования: `Expression` и `LoopCond`). Вынос
  `Assign` затрагивает обе — и это ровно то место, где легко получить
  конфликт LR(1) или молча сместить приоритеты. Требуется прогон всего корпуса и
  тестов парсера.
- **Форма может встречаться в фикстурах тестов** (там она законна сегодня):
  до правки нужен замер по `takt-lang/tests/`, `takt-sim/tests/`, `examples/`,
  `book/`.
- Ломающее изменение синтаксиса → (версия языка). Версия `0.8.0`
  не выпущена, изменения накапливаются в неё.


## Как исправлено

### Присваивание вынесено из цепочки приоритетов в три именованных правила

`Chain14` (уровень `:=` и `?:`) лишился ветви присваивания — теперь `Expression`
это **то, что вычисляется**, и `:=` в нём нет вовсе. Позиции записи перечислены
в грамматике явно:

| Правило грамматики | Позиция | Пример |
|---|---|---|
| `StatementExpr` | оператор тела | `led := 1;` |
| `StatementExpr` (шаг цикла) | третья часть `for` | `for var i: u8 := 0; …; i := i + 1` |
| `CallArg` | именованный аргумент вызова | `Pid(kp := 0.25)` |

Список позиций виден **в самой грамматике**, а не восстанавливается из проверок.

**Третья позиция обнаружилась пробой и едва не сломала корпус.** Аргумент
инстанцирования модели (`Pid(kp := 0.25)`) разбирался тем же
`Expression::Assign` внутри `FunctionCall`. Простой вынос `:=` из цепочки сделал
бы форму незаконной, а она стоит в `examples/pid_heater.takt` и в документе.
Поэтому заведено правило `CallArg` — узел АСД остался прежним, и **семантика
[параметризация моделей (ключевое слово `parameter`)](../features/0185-model-parameters.md) правок не потребовала**.

Правая часть присваивания — `Expression`, а не `StatementExpr`: цепочка
`a := b := c` есть присваивание внутри значения и потому тоже незаконна.

**Слева в `CallArg` допускается выражение, а не только имя** — и это тоже
нашёл предкоммит, а не рассуждение. Первая редакция требовала `Identifier`, и
тест `non_name_on_the_left_is_se076` покраснел: вход `Tuner(1 := 5)` прежде
давал внятное `SE-076` («слева от `:=` обязано стоять имя параметра»), а под
сужением получал синтаксический отказ **о присваивании** — сообщение не о том,
что автор сделал. Границу провели по назначению слоёв: форму держит грамматика,
структуру аргумента — семантика.

### Диагностика `SY-006` вместо перечня ожидаемых токенов

LALRPOP на `:=` в позиции значения сообщил бы «нераспознанный токен ':=',
ожидалось: …» со списком из двадцати пяти операторов — сообщение о механике
разбора вместо правила языка. `parse_entry::parser_error_to_diagnostic`
распознаёт `Token::ColonAssign` и печатает само правило, с позицией **токена**
`:=`.

### Судьба `SE-095`: сужен, а не снят

Проверка осталась и **достижима**: `twice(a := 3)` — именованный аргумент у
вызова **функции**. Грамматика его принимает (форма нужна инстанцированию
модели), а на уровне АСД вызов функции и инстанцирование — один узел `Function`,
различает их только семантика по месту. Поэтому `SE-095` стал страховкой на
остатке; формы, отсекаемые грамматикой, до него больше не доходят.

## Проверки

| Условие | Результат |
|---|---|
| `var y: u8 := (x := 7);` | `SY-006` на разборе |
| `b := (a := 3) + 1;` | `SY-006` |
| `if (a := 1) = 1 { … }` | `SY-006` |
| `a := b := c;` | `SY-006` |
| `a := 1;` и шаг `for` | законны |
| `Pid(kp := 0.25)` (корпус) | законно, вывод целей не изменился |
| `twice(a := 3)` — аргумент функции | `SE-095` (остаточный случай) |
| `Tuner(1 := 5)` — не имя слева | `SE-076` (диагностика 0185 сохранена) |
| позиция диагностики | токен `:=`, а не объявление цели записи |
| `cargo test --all-features` | зелёные |
| `./scripts/precheck.sh` | зелёный |

Контроль — `takt-lang/tests/syntax/feature_0021_operators.rs::assignment_inside_expression_is_syntax_error`
(четыре формы) плюс обновлённые ожидания в `port_access_contract_tests.rs` и
`lsp_port_io_tests.rs`.
