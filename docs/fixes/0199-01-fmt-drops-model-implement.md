# Исправление: `taktc fmt` теряет реализацию модели

> Фича: [../features/0199-model-implements-brace-form.md](../features/0199-model-implements-brace-form.md) · найдено фичей [контроль форматтера: корпус восстановлен, KNOWN_GAPS с ратчетом](../features/0230-format-corpus-sentinel.md) · анализ: [../features/0199-model-implements-brace-form.md#анализ](../features/0199-model-implements-brace-form.md#анализ)

- **Статус:** **ИСПРАВЛЕН** (2026-08-05), заведён в тот же день.
- **Обнаружено:** фичей [контроль форматтера: корпус восстановлен, KNOWN_GAPS с ратчетом](../features/0230-format-corpus-sentinel.md) —
  первым же прогоном форматтера по **восстановленному** корпусу.
- **Класс:** «инструмент молча меняет исходник» — тот самый, ради которого
  форматтер вообще **отказывается** печатать непокрытые узлы.

## Проблема

Два симптома одной ветки печати вложенной модели:

**1. Реализация терялась.** Форма фичи — `model M = A | B { … }` — печаталась
как `model M { … }`: композиция исчезала, модель становилась пустым автоматом.
Смысл программы менялся **молча**, без единой диагностики.

```takt
model Root2 = A | B {          // было
    var n: u8 := 0;
}
model Root2 {                  // стало после `taktc fmt`
    var n: u8 := 0;
}
```

**2. Пустое тело давало невалидный файл.** `model Root = A { }` печаталось как
`model Root = A;` — записи, которой **грамматика не принимает**. Файл после
форматирования переставал разбираться:

```text
Ошибка компиляции [SY-002]: нераспознанный токен ';', ожидалось "{", "(", "=", …
```

`taktc fmt` пишет файлы **на месте**, то есть уничтожал исходник.

## Причина

`format/mod.rs::print_nested_model` выбирал между двумя формами:

```rust
Some(implements) if model.elements.is_empty() => "model M = выражение;"   // симптом 2
_                                              => "model M { … }"          // симптом 1
```

Первая ветвь печатала синтаксис, которого в языке нет; вторая — игнорировала
поле `implements`, потому что писалась до фичи и о нём не знала.

**Почему дожило.** Единственная запись такой формы в репозитории —
`takt-sim/tests/data/eval/conformance_model_implement.takt`, а обход корпуса в
`format_tests.rs` до фикстур **не доходил**: он звал каталоги `grammar/tests/data`
и `simulation/tests/data`, переименованные фичей, а помощник обхода при
ошибке чтения молча возвращался. Тест рапортовал «весь корпус», видя 158 файлов
из 308. Причину молчания устраняет фича.

## Решение

Форма печати одна: `model Имя = выражение {` … `}`; без реализации —
`model Имя {`. Ветка «короткой формы» удалена — она печатала несуществующий
синтаксис.

## Проверки

- `takt-lang/tests/syntax/format_tests.rs::model_implement_with_body_keeps_implementation`
  — адресный тест: реализация уцелела; пустое тело печатается со скобками, и
  напечатанное **разбирается** (круговой рейс). Стоит отдельно от корпусной
  проверки: инвариант не должен зависеть от того, лежит ли в корпусе подходящий
  файл.
- `a1_a3_corpus_report` на восстановленном корпусе (279 файлов) — A3
  (семантическая нейтральность) зелена; мутация «вернуть потерю реализации»
  валит её на `conformance_model_implement.takt`.
- `./scripts/precheck.sh` — код возврата 0.
