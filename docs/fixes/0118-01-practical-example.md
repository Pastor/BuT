# Исправление: раздел «Практический пример» — полноценная модель группового управления лифтами

> Фича: [../features/0118-book-showcase.md](../features/0118-book-showcase.md) · использует [фичу](../features/0124-verify-graph-export.md) (экспорт графов верификации) · отчёт: [../reports/README.md](../features/README.md)

## Проблема

Раздел `book/src/17-showcase/` («Развёрнутый пример») держался на
**примитивном** примере — дозаторе из трёх состояний. по своду пример раздела
обязан быть **узнаваемым устройством промавтоматики**, богатым на функциональность
и наглядным. Дозатор этому не отвечал: он не показывал ни композицию, ни функции,
ни порты с адресами, ни осмысленную верификацию с построением автоматов, а
диаграммы верификации (Крипке/Бюхи/трасса) вовсе отсутствовали. Заказчик потребовал
переработать раздел в **практический** пример, раскрывающий почти всю
функциональность языка (запрос 2026-07-25).

## Причина

Раздел заводился (0118) как первый прикладной и намеренно взял простейшую модель,
чтобы обкатать структуру «одна модель → все цели/симуляция/верификация». Кроме
того, диаграммы Крипке/Бюхи инструментом **не порождались** — до [экспорт графов верификации (Крипке/Бюхи/произведение) в Graphviz DOT](../features/0124-verify-graph-export.md) экспорта графов верификации не
существовало, поэтому наглядно показать работу model-checking было нечем.

## Решение

Раздел переименован в **«Практический пример»** и переписан вокруг модели
**контроллера кабины лифта** (группового управления лифтами):

- **Модель** `examples/lift.takt` — шесть состояний (ожидание/движение
  вверх-вниз/торможение/посадка/закрытие дверей), **порты с адресами** (три
  способа задания, битовые порты в одном регистре), **инвариант безопасности**
  `SafeMove` (не двигаться с открытыми дверьми), именованные блоки
  `enter`/`always`, безусловный `next` и контрольные `ref`. Компилируется во **все**
  цели без предупреждений, симулируется (полный цикл обслуживания вызова).
- **Диспетчер секции** `examples/dispatch.takt` — функции `dist`/`pick`
  (композиция функций) выбирают ближайшую кабину; компилируется и симулируется.
- **Верификация** с диаграммами — реальным выводом `taktc verify --emit-graph`, отрендеренным в SVG (`dot -Tsvg`): структура Крипке, автомат Бюхи
  для `¬(F Boarding)`, произведение с контрпримером-лассо. Показаны свойство
  `F Boarding` (нарушено — оговорка про абстракцию управления) и
  `G (Stopping -> F Boarding)` (держится).
- **Симуляция** — сценарий входов `examples/lift-sim.json` (демонстрация написания
  файла симуляции) и трасса прогона.
- **Генерация во все цели** — показательные фрагменты в тексте (C `_tick` с
  `assert` инварианта, SV `always_ff`); **полный** порождённый код (c/c-hal/rust/
  st/sv) вынесен в новое приложение
  [«Порождённый код примера»](../../book/src/appendix-generated/index.typ)
  (`{{#include}}` файлов `generated/`), добавленное в `SUMMARY.md`.
- **Перенос длинных строк кода** в PDF — в `book.toml` добавлен `header-includes`
  с `fvextra` (`breaklines`/`breakanywhere`): принятый по умолчанию HAL цели `c-hal` эмитится
  одной строкой ~800 символов, без переноса она уходила бы за поле (Overfull).

## Проверки

- Все цели: `taktc compile -t {c,c-hal,rust,st,sv,plantuml} lift.takt` — 7/7 без
  предупреждений; `dispatch.takt` — компилируется.
- Симуляция: `takt-sim lift.takt -s lift-sim.json` — полный цикл (вызов 3-го →
  движение → торможение → посадка → закрытие → ожидание), инвариант держится;
  `dispatch.takt` — выбор ближайшей кабины (вызов 10 → кабина B).
- Верификация: `F Boarding` → нарушено (контрпример-лассо), `G (Stopping ->
  F Boarding)` → держится. Графы отрендерены `dot -Tsvg`.
- **Сборка PDF**: `make -C book build` — успешно (116 страниц); `Missing
  character`/`undefined refs` = 0; длинные строки порождённого кода **переносятся**
  (проверено рендером страницы приложения). `./scripts/precheck.sh` зелёный.
