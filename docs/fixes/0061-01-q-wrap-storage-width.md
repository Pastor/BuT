# Исправление: перенос `q(m, n)` идёт к ширине хранения, а не к `W`

> Фича: [../features/0061-fixed-point-type.md](../features/0061-fixed-point-type.md) · ADR: [../features/0061-fixed-point-type.md#архитектура-adr](../features/0061-fixed-point-type.md#архитектура-adr) · смежно: фича [насыщение (saturation) для fixed-point `q(m, n)`](../features/0170-fixed-point-saturation.md) (насыщение — при её проработке дефект и вскрыт)

- **Статус:** **ИСПРАВЛЕН** (2026-08-14), заведён в тот же день.
- **Обнаружено:** проба стадии архитектуры фичи (насыщение для `q`) —
  прежде чем добавлять вторую семантику переполнения, проверялась первая.
- **Класс:** молчаливое расхождение эталона и целей, дожившее из-за **дыры в
  покрытии**: все фикстуры сверки и весь корпус используют форматы, на которых
  дефект не проявляется.

## Проблема

Правило 3 ADR требует переноса (wraparound) к **`W = m + n`** — и эталон
(`takt-sim/src/eval/fixed.rs`, `wrap(v, m + n)`) делает именно это. Цели
`c`/`rust`/`st` переносили к ширине **хранения** `S = fixed_storage_bits(W)`,
округлённой вверх до 8/16/32/64.

Совпадают эти границы, только когда `W ∈ {8, 16, 32, 64}`. Замер по корпусу и
фикстурам: используются **исключительно** `q(8, 8)` (29 вхождений в фикстурах
сверки, 10 в корпусе) и `q(4, 4)` (1) — то есть ровно те форматы, где `W = S`.

Проба на `q(6, 6)` (`W = 12`, хранение 16 бит), `acc := acc + delta` при
`acc = 30.0`, `delta = 8.0`:

| Сторона | Такт 1 | Такт 2 | Такт 3 |
|---|---|---|---|
| эталон (симулятор) | **−26.0** | −18.0 | −10.0 |
| цель `sv` (`logic signed [11:0]`) | **−26.0** | −18.0 | −10.0 |
| цель `c` (`(int16_t)`) | **38.0** | 46.0 | 54.0 |
| цель `rust` (`as i16`) | **38.0** | 46.0 | 54.0 |
| цель `st` (`LINT_TO_INT`) | **38.0** | 46.0 | 54.0 |

Расхождение **молчаливое**: порождённый код компилируется, `iec2c` принимает,
verilator и yosys синтезируют. Ровно тот класс, о котором предупреждает
`CLAUDE.md`: проверка целевого языка доказывает валидность, но не верность.

Дефект достижим не только явным `q(6, 6)`: флаг `--float-as-q=m.n`  принимает любые `m`/`n`, то есть вещественная модель под, скажем,
`--float-as-q=6.6` считала бы в целях иначе, чем в симуляторе.

## Причина

Тип **хранения** и ширина **формата** — разные величины, и в трёх целях вторую
выражали первой. `fixed_storage_bits` заведён для объявления поля (в C нет
`int12_t`), и приведение к нему заодно давало перенос — но на своей границе.

В цели `rust` док-комментарий модуля прямо утверждал «сужение `as i{W}`… даёт
two's-complement перенос, как `wrap(_, W)`», тогда как код печатал
`as i{fixed_storage_bits(W)}`. Намерение было записано верно, реализация — нет,
и разошлись они молча.

Цель `sv` была права **с самого начала** (`logic signed [W-1:0]` — ровно `W`
бит), но контроля у этого свойства тоже не было.

## Решение

Перенос к `W` эмитится **явно** и **только когда `W ≠ S`** — иначе вывод для
всего корпуса изменился бы, а он обязан остаться байт-в-байт (снапшоты
`examples/generated`, детерминизм 0048).

- **Цель `c`** — хелпер `lam_q_wrap(v, w)`, вставляемый по факту вызова рядом с
  `lam_q_floordiv`/`lam_q_mul`/`lam_q_div`. Считает в **беззнаковом**:
  сужение знакового вне диапазона implementation-defined, а `uint64_t` определён
  стандартом при любом значении.
- **Цель `rust`** — пара сдвигов `(v as i64) << (64 − W) >> (64 − W)`: `<<` не
  паникует на потере старших бит, `>>` знакового арифметический. Явный
  `as i64` добавляется **только** для `i128`-промежутков (`*`, `/`, пересчёт
  `q → q`); уже-`i64` его давать нельзя — `clippy::unnecessary_cast` под
  `-D warnings`.
- **Цель `st`** — `FUNCTION LAM_Q_WRAP` на `MOD` с двумя поправками знака.
  Модуль `2^W` передаётся **аргументом**: сдвигов над числами в IEC нет вовсе
  (ловушка A-4 ADR). При `W ≥ 63` модуль `2^W` в `LINT` непредставим →
  новая диагностика **`ST-021`**, а не молчаливый счёт по неверному модулю.
- **Цель `sv`** — без изменений (была верна).

Правка покрывает все позиции, где рождается представление: бинарные операции,
унарный минус, приведения `q → q`, `int → q`, `float → q`.

## Проверки

Сверка **значений** (не факта компиляции) на новых фикстурах с `W = 12`:

| Проверка | Файл |
|---|---|
| эталон ≡ цель `c` | `takt-sim/tests/conformance/conformance_c_tests.rs::fixed_wrap_to_width_matches_generated_c` |
| эталон ≡ цель `rust` | `takt-sim/tests/conformance/conformance_rust_tests.rs::fixed_wrap_to_width_matches_generated_rust` |
| эталон ≡ цель `st` (через `iec2c` → C) | `takt-sim/tests/conformance/conformance_st_tests.rs::fixed_wrap_to_width_matches_generated_st` |
| эталон ≡ цель `sv` (через verilator) | `takt-sim/tests/conformance/conformance_sv_tests.rs::fixed_wrap_to_width_matches_generated_sv` |

Фикстуры: `takt-sim/tests/data/eval/conformance_fixed_wrap_w12.takt` (наблюдение
поля) и `conformance_fixed_probe_w12.takt` (наблюдение через выходной
float-порт — приём целей `rust`/`st` из 0061).

**Ловушка проверена мутацией:** предикат `width_is_storage` в цели `c` временно
заменён на `true` (то есть возвращено прежнее поведение) — контроль покраснел,
показав `[2432, 2944, …]` против `[−1664, −1152, …]`. Без этой проверки зелёный
тест не отличался бы от теста, который ничего не ловит.

Прежние сверки на `q(8, 8)` остались зелёными — то есть вывод для форматов
корпуса не изменился. Полный `./scripts/precheck.sh` — зелёный.
