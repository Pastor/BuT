# Исправление: `probe.sh` падал на пробе с объявленным типом

> Фича: [../features/0301-probe-checklist.md](../features/0301-probe-checklist.md) · анализ: [../features/0301-probe-checklist.md#анализ](../features/0301-probe-checklist.md#анализ) · отчёт: [../features/0301-probe-checklist.md#отчёт-о-тестировании](../features/0301-probe-checklist.md#отчёт-о-тестировании)

## Проблема

`scripts/probe.sh` завершался с кодом 1 **сразу после первой проверки** — на
любой пробе, содержащей объявление `struct`, `enum` или `type`, имя которого
**не** совпадает с именем файла. Замер не снимался вовсе: вывод обрывался на
строке «объявленные переменные используются».

Обнаружено 2026-08-19 при снятии замера [цель rust даёт невалидный код на сравнении перечисления с числом](../features/0281-rust-enum-compare-literal.md) (проба с
`enum Command { … }`). Воспроизводится и на структуре:

```sh
printf 'struct Point { x: u8, y: u8 }\n…' > probe.takt
scripts/probe.sh -n 1 probe.takt   # код 1, замера нет
```

Инструмент, поставленный правилом 30 обязательным для снятия замера,
не работал ровно на тех пробах, где объявлен тип, — то есть у всякой фичи о
типах, перечислениях и структурах.

## Причина

Скрипт идёт под `set -eu`. Проверка 1б («имя файла сталкивается с объявленным
типом») собирала результат подстановкой команд, тело цикла кончалось формой

```sh
[ "$lower_name" = "$lower_stem" ] && printf '%s\n' "$name"
```

При **несовпадении** условие ложно, `&&` даёт статус 1, он становится статусом
`while`, затем — статусом всего конвейера и подстановки, и `set -e` роняет
скрипт. То есть падение наступало именно тогда, когда ловушки **нет**.

**Контроль `scripts/test-probe.sh` этого не видел**: во всех его входах либо
объявленных типов не было вовсе, либо совпадение имён было (пункт 3), и тогда
`printf` возвращал ноль. Классический случай — проверка есть, а её отрицательная
ветвь не покрыта.

## Решение

Тело цикла кончается **успехом**: `&&`-форма заменена на `if … fi`. Граница
названа в комментарии рядом — «тело цикла обязано кончаться успехом», с
объяснением, почему под `set -e` это не стиль, а условие работоспособности.

В контроль добавлена проверка: проба с объявленным типом **без** коллизии имён
проходит без тревоги и **с нулевым кодом возврата** — то есть теперь покрыта
обе ветви проверки 1б.

## Проверки

```sh
scripts/test-probe.sh                       # сторож, шаг предкоммита
scripts/probe.sh -n 1 <проба со struct>     # код 0, замер снят
./scripts/precheck.sh                       # полный гейт
```

Мутация «вернуть `&&`-форму» валит новую проверку контроля (проверено).
