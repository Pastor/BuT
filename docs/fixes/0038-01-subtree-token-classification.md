# Исправление: `semantic_tokens` не классифицирует члены под-моделей

> Фича: [../features/0038-intellij-semantic-tokens.md](../features/0038-intellij-semantic-tokens.md) · обнаружено зондом [семантическая подсветка Lam в IntelliJ через lam-lsp](../features/0038-intellij-semantic-tokens.md#разработка)

- **Статус:** **ИСПРАВЛЕН** (2026-07-19).
- **Tier 2 — молчаливо неверная подсветка, но не порождаемый код.** Дефект в
  LSP-сервере (`grammar::lsp::semantic_tokens`): классификация имён неверна для
  всего, что объявлено внутри `model X { … }`. На компиляцию/поведение
  (`c`/`rust`/`st`/`sv`/симулятор) не влияет — только на цвет в редакторе. Но
  дефект **молчаливый** (зелёные тесты, неверные цвета) и виден пользователю.
- **Опровергает премису анализа 0038:** «серверная часть полностью готова, со
  стороны `grammar` — только тесты (R9)». Готова **не полностью**.

## Что не так

`semantic_tokens` строит **корневую** (файловую) модель и классифицирует каждое
имя через `ModelNode::search_func`/`search_state`/`search_enum_variant` +
`types`/`enums`/`models` этой модели. Но `search_*` ищут в текущей модели и идут
**вверх** по `upper` (разрешение области из вложенной точки) — они **не спускаются**
в под-модели. От корня «вверх» ничего нет, поэтому всё, объявленное внутри
`model X { … }`, поиском не находится и деградирует в `VARIABLE`.

**Зонд (0038-03) на фикстуре** `grammar/tests/data/lsp/semantic_tokens.lam`
(модель `Thermostat` с `fn scale`, `start Idle`, `state Done`):

| Имя | Где объявлено | Было | Ожидалось |
|---|---|---|---|
| `Celsius`, `Level` | корень файла | `type` ✅ | `type` |
| `Low`, `High` | корень (варианты `Level`) | `enumMember` ✅ | `enumMember` |
| `Thermostat`, `Main` | корень | `class` ✅ | `class` |
| `scale` | **под-модель** `Thermostat` | **`variable`** ❌ | `function` |
| `Idle`, `Done` | **под-модель** `Thermostat` | **`variable`** ❌ | `class` |

**Это общий случай, а не угол:** весь корпус оборачивает логику в под-модель
(`model Regulator { fn … state … } start Main = Regulator`), поэтому в **реальных**
`.lam` имена функций и состояний подсвечивались бы неверно — фича отгрузилась
бы сломанной. Класс дефекта — ровно тот, что дал восемь дефектов в фиче:
зелёные тесты («не паникует»), но результат не проверялся.

## Исправление

Локально в `grammar/src/lsp/semantic_tokens.rs` (функции `search_*` **не
тронуты** — их «вверх»-семантика верна для разрешения областей и используется в
других местах). `semantic_tokens` теперь собирает имена деклараций **всего дерева**
моделей (корень + все под-модели, спуск по `models`) в наборы по категориям
(`DeclNames`: `functions`/`types`/`variants`/`classes`) и классифицирует каждый
идентификатор по членству — в том же порядке приоритета, что и прежде
(встроенный тип → функция → тип → вариант enum → состояние/модель → переменная).
Обход разделяемых под-моделей однократен (visited по указателю).

**Продуктивный код `lsp.rs` изменён** (в отличие от плана R9 задачи,
который предполагал «только тесты»): премиса «сервер готов» оказалась неверна, и
без правки фича не работает на реальных файлах. Правка вынесена в **отдельный
исправление** (этот), а не сделана «заодно» в 0038-03 — как и требует дев-документ
0038-03 («расхождение → дефект сервера → отдельный исправление-YY»).

## Проверка

Тесты классификации `grammar/tests/semantic_tokens_tests.rs`
(`semantic_tokens_classification`) — включают члены под-модели `Thermostat`:
`scale` → `function`, `Idle`/`Done` → `class`. До исправления тест **красный**
(деградация в `variable`), после — зелёный. Робастность (`semantic_tokens_broken_source`):
на непарсящемся исходнике модель не строится, идентификаторы деградируют в
`variable` — поведение сохранено.
