# Исправление: ПИД-регулятор — тип данных с операциями, а не модель-автомат

> Фича: [../features/0182-pid-library-and-application.md](../features/0182-pid-library-and-application.md) · ADR: [../features/0182-pid-library-and-application.md#архитектура-adr](../features/0182-pid-library-and-application.md#архитектура-adr) · отчёт: [../features/0182-pid-library-and-application.md#отчёт-о-тестировании](../features/0182-pid-library-and-application.md#отчёт-о-тестировании)

- **Статус:** **ИСПРАВЛЕН** (2026-08-14), заведён в тот же день.
- **Обнаружено:** требованием заказчика 2026-08-14 с образцом на C: «пример без
  модели, только структура и три функции — инициализация, расчёт и сброс».
- **Класс:** «пример показывает не то, чем пользуются» — библиотека
  регулирования в промышленном коде есть **тип данных с операциями**, а фича выразила её автоматом.

## Проблема

`examples/pid_law.takt` описывал регулятор **моделью-автоматом**: состояния
`Control → Settled → Done`, накопитель и предыдущая ошибка — переменные модели,
настройка — параметры модели. Применение (`examples/pid_heater.takt`) брало эту
модель в композицию: `(Pid | Heater) + (Pid(kp := 0.25) | Heater(…))`.

Заказчик привёл образец на C — тот вид, в котором ПИД живёт в прошивках:

```c
typedef struct { float Kp, Ki, Kd; float Ts; float out_min, out_max;
                 float integral, prev_error; } PIDController;
void  PID_Init(PIDController *pid, …);
void  PID_Reset(PIDController *pid);
float PID_Compute(PIDController *pid, float setpoint, float measurement);
```

Разрыв не косметический. У автомата **регулятор один на программу**: его
состояние — переменные модели, и второй контур требует второго экземпляра
модели. У типа данных экземпляров столько, сколько объявлено переменных, а
закон записан **один раз** — ровно то, ради чего библиотеку и заводят.

## Причина

Дефекта реализации здесь нет — есть **решение заказчика** о том, чем должен
быть пример. Причина, по которой правка вышла за один файл: применение брало
`Pid` **моделью** (композиция `Pid | Heater`), и смена рода библиотеки
обязывала переписать и его.

## Границы языка, найденные пробами

Требование «файл только со структурой и функциями» сегодня **невыразимо**, и
это установлено не рассуждением, а тремя пробами:

| Проба | Ответ инструмента |
|---|---|
| файл `struct` + `fn` без стартового состояния | **`SE-011`** «Модель должна содержать начальное состояние» |
| `import { pid_reset } from "…"` | **`SE-017`** «Идентификатор не найден в импортируемом файле» — структура импортируется, **функция нет**. Снято исправлением [импорт переносит функции библиотеки](0182-04-import-functions.md) |
| функция объявлена, но не вызвана | в порождённый C **не попадает вовсе** |

Отсюда две вынужденные уступки, названные прямо в самом примере:

1. У файла есть **одно** состояние `Run`, и оно вызывает все три функции —
   иначе они не эмитятся ни в одну цель, и пример компилировался бы в пустоту;
2. ~~применение получает от библиотеки **тип и протокол**, а шаг закона пишет
   у себя: импортировать функцию нельзя~~ — **снято** исправлением
   [импорт переносит функции библиотеки](0182-04-import-functions.md): применение зовёт `pid_compute`
   библиотеки, и трасса от этого не изменилась.

Ещё две находки — **дефекты**, а не границы, и обе вскрылись на этом
примере:

- `import "lib.takt";` (файл целиком) отвечает `SE-074`, требуя импортировать
  `'p'` и `'r'` — **параметр и локальную переменную функции**, объявлениями
  библиотеки не являющиеся. Записана кандидатом в `FEATURES.md`;
- импорт переносил **имя** типа без его устройства — цель `c` печатала
  `Pid p;` без `typedef`, симулятор отвечал `SIM-012`. Вылечено исправлением
  [импорт переносит имя типа, но не его устройство](0182-03-imported-type-definition.md); без него схема «библиотека
  даёт тип» не работала вовсе.

## Решение

**`examples/pid_law.takt`** — библиотека: `struct PidState` (поля образца, плюс
`output` — в языке функция возвращает одно значение, и выход едет полем), три
функции `pid_init` / `pid_compute` / `pid_reset` и одно состояние `Run`,
которое их вызывает. Anti-windup сохранён: интеграл замораживается, когда
ошибка толкает выход дальше за предел, — как в образце.

**`examples/pid_heater.takt`** — применение: импортирует `{ PidState, target,
meas, ctrl }` (тип и протокол), держит **свой** экземпляр и пишет шаг закона в
`always` над его полями. Две ступени с разной настройкой сохранены: настройка
теперь не параметр модели, а **значения полей структуры**, что и делает
экземпляр вторым контуром.

**Имя структуры — `PidState`, а не `Pid`.** MatIEC содержит
`FUNCTION_BLOCK PID`, идентификаторы IEC регистронезависимы, и `TYPE Pid :
STRUCT` он отвергает: «invalid name defined for data type declaration». Та же
ловушка, что описана в живом контексте для имён **моделей** (`Concat`), впервые
сработала на имени **типа**. Доказано пробой: `PidX`, `PidState`, `Regulator`
проходят, `Pid` — нет.

**Цена формы: пример потерял цели `st` и `rust`.** Полноценная работа со
структурой — агрегатный инициализатор `var p: PidState := {…}` и доступ к полям
— в этих генераторах не реализована (`ST-011`, `RS-011`); `extend_complex.takt`
структуру объявляет, но полей не трогает, и потому проходит. Отказы штатные
(проверки `st`/`rust` мягкие, предкоммит зелёный), но покрытие примера сузилось до
`c` и `plantuml`. Применение (`pid_heater.takt`) целью `st` **транслируется** —
там структура живёт внутри модели.

## Проверки

- `./scripts/precheck.sh` — код возврата 0: компиляция всех целей, проверка
  воспроизводимости (два прогона × цель), `iec2c` на порождённом ST, `cc -Wall
  -Werror` на `c-hal`, `clippy -D warnings` на `rust`, verilator + yosys на
  `sv`, `taktc fmt --check examples/`.
- `takt-sim/tests/sim/examples_scenario_tests.rs` — контракт сценария примера:
  цепочка состояний, бюджет тактов, завершение.
- **Сходимость контура проверена прогоном, а не глазами**: `takt-sim` на
  применении показывает выход регулятора и температуру объекта по тактам.
