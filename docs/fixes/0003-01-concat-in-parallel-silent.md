# Исправление: тихая мистрансляция `+` внутри `|` в целях C и Rust

> Фича: [../features/0003-composite-states.md](../features/0003-composite-states.md) (композиция; манифестация C) · сопряжённая фича: [../features/0050-rust-backend.md](../features/0050-rust-backend.md) (манифестация Rust) · обнаружено при аудите композиции (запрос заказчика после проработки [фичи](../features/0057-sv-sequential-composition.md))

- **Статус:** Заведён (проработан, не исправлен)
- **Приоритет:** Tier 1 — молчаливо неверный вывод (компилируется и исполняется, но считает не то)

## Проблема

Последовательная композиция **внутри** параллельной — `(A + B) | C` — это
настоящая вложенность: она **не уплощается** (в отличие от `(A + B) + C`, который
проход `unroll_extend_expression` сводит к плоскому `A + B + C`). На этом входе
цели расходятся, причём две из них **молчаливо искажают семантику**:

| Цель | Поведение на `(A + B) \| C` | Вердикт |
|---|---|---|
| **C** | `_init`/`_tick` инициализируют и тикают **только `C`** — ветка `(A + B)` **выброшена целиком** → модель ведёт себя как один `C` | 🔴 молча неверно |
| **Rust** | тикает `a.tick(); b.tick(); c.tick()` каждый такт, готово когда готовы все три → `(A + B)` стало `A \| B` | 🔴 молча неверно |
| ST | отказ `ST-011` («…напечатать её шаги как параллельные значило бы молча изменить семантику модели») | 🟢 безопасно |
| SV | отказ `SV-002` («вложенная композиция внутри шага композиции») | 🟢 безопасно |
| PlantUML | аннотация текста `(A + B) \| C` — семантику не исполняет | 🟢 безвредно |
| Симулятор (эталон) | `Parallel[Sequential[A,B], C]` — исполняет верно | 🟢 эталон |

Порождённый C/Rust **компилируется и работает**, поэтому дефект не виден ни
компилятору цели, ни беглому чтению — ровно тот класс «молчаливой неверности»,
против которого заведены `ST-011` и `SV-002`. Проверено прогоном
2026-07-17 на модели `start Start = (A + B) | C`.

## Причина

- **C** (`grammar/src/generator/c/c_model.rs`): в `generate_parallel_items_init`
  и `generate_parallel_items_tick` рукава `_ => {}` (строки ~320 и ~425)
  **отбрасывают** ветку `StateExtend::Concatenation`, попавшую в параллель —
  инициализируется и тикается лишь `Model`/`Parallel`. Асимметрия: конкатенация
  **внутри конкатенации** на инициализации даёт `CC-007` (строка 371), но на
  такте молча пропускается (`_ => {}`, строка 697).
- **Rust** (`grammar/src/generator/rust/rust_model.rs`): сбор экземпляров
  параллели (`collect_instances`) **рекурсивно уплощает** ветку-конкатенацию в
  плоский список параллельных экземпляров → последовательность превращается в
  параллель. `RS-021` ловит конкатенацию **в шаге конкатенации**, но **не** ветку
  конкатенации в параллели.

Корень общий: ветку `Concatenation` в параллельном контексте оба генератора
обрабатывают как «плоский набор моделей», теряя её последовательную семантику —
вместо явного отказа, как у ST/SV.

## Решение

Минимальная безопасная правка (восстановить инвариант «никакой тишины», не
реализовывать полную поддержку — это отдельная фича):

- **C:** заменить `_ => {}` в `generate_parallel_items_{init,tick}` (и на такте
  конкатенации, строка 697) на **явную диагностику** по образцу `ST-011`/`SV-002`
  — расширить `CC-007` или завести выделенный `CC-0xx` на «конкатенацию как ветвь
  параллели».
- **Rust:** в `collect_instances`/сборе параллели детектировать ветку
  `Concatenation` и дать `RS-021` (или новый `RS-0xx`) вместо уплощения.

**Полная поддержка** `+` внутри `|` (вложенный счётчик шагов внутри параллельной
ветви — как уже делает симулятор) — **вне** этого исправления; при желании заводится
отдельной фичей симметрично 0057 (SV) по всем генераторам.

> **Область исправления.** Дефект — один класс в двух генераторах. Карточка ведётся единой
> (запрошена одна); C привязан к фиче (композиция), Rust — к 0050. Если
> команда предпочтёт раздельный учёт, Rust-часть выносится в `0050-YY` со ссылкой
> сюда.

## Проверки

- **Контр-примеры** `(A + B) | C` в целях `c` и `rust` → **ненулевой код** и
  текст диагностики; Не «работающий, но обрезанный/распараллеленный» модуль.
- **Регресс:** `A + (C | D) + E` (параллель в конкатенации, как `extend_complex`)
  по-прежнему транслируется корректно во всех целях; базовые `|`/`+` не задеты.
- **Сверка** с симулятором на `(A + B) | C` подтверждает расхождение до исправления
  (C ≈ `C`, Rust ≈ `A | B | C`) и отказ — после (связь с инвариантом
  «поведение сверяется потактово»).
