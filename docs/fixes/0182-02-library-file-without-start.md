# Исправление: файл без стартового состояния — библиотека, а не ошибка

> Фича: [../features/0182-pid-library-and-application.md](../features/0182-pid-library-and-application.md) · смежно: [общие переменные библиотечного файла в импортёре](../features/0184-imported-shared-variables.md) (усыновление импортированных объявлений), [многофайловость LSP — импорты и позиции диагностик](../features/0055-lsp-multifile.md) (поиск импорта) · связанный исправление: [пИД-регулятор — тип данных с операциями, а не модель-автомат](0182-01-pid-law-as-type-and-functions.md)

- **Статус:** **ИСПРАВЛЕН** (2026-08-14), заведён в тот же день.
- **Обнаружено:** при работе над [пИД-регулятор — тип данных с операциями, а не модель-автомат](0182-01-pid-law-as-type-and-functions.md)
  — пробой «файл только со структурой и функциями», которую заказчик просил как
  форму примера.
- **Класс:** «инструмент отвечает сообщением не о том» — законный файл получал
  диагностику о пропущенном `start`, которого автор не писал.

## Проблема

Единица компиляции без единого состояния — это **библиотека**: набор типов,
функций и переменных для подключения через `import`. Такой файл строится
семантикой полностью и импортируется без нареканий, но применить его как вход
нельзя — автомата в нём нет.

Отвечали на это два инструмента, и оба неудачно:

| Инструмент | Ответ до исправления |
|---|---|
| `taktc compile` | `Ошибка компиляции [SE-011]: Модель должна содержать начальное состояние` — **без позиции**, из недр генератора |
| `takt-sim` | `Шаг 1: [—]` и `Завершено: модель достигла терминального состояния за 1 шагов` — **успешный прогон автомата, которого нет** |

Вред у обоих один: сообщение не про то. Автор библиотеки читает «добавьте
начальное состояние» и добавляет его — то есть портит библиотеку, чтобы
замолчал инструмент. Симулятор же вовсе рапортует об успехе, и молчаливый
«прогон» библиотеки выглядит как проверка, которой не было.

## Причина

Отказ приходил из `semantic::minimap::Map::create` — то есть на этапе
**генерации**, куда файл доезжал уже построенным. Там известно только, что
стартового состояния нет; ни того, что состояний нет **вовсе**, ни того, что
файл подан как вход, а не пришёл из `import`, эта точка не различает. Отсюда и
формулировка про «должна содержать начальное состояние», и отсутствие позиции.

Симулятор до этой точки не доходил вообще: он строит юнит сам и на модель без
состояний отвечает пустым тактом.

## Решение

Заведён **`SE-102`** и единственная функция
`semantic::validate::entry::validate_entry_model`, которую зовут точки,
знающие позицию «вход»:

- `pipeline::parse_and_construct` — общий шаг **всех** целей компиляции;
- `takt-sim` — сразу после построения дерева.

Правило одно на оба инструмента: два ответа на один вход разошлись бы. Текст называет **что делать** — скомпилировать импортёра либо
добавить стартовое состояние.

**Признак библиотеки — отсутствие состояний вовсе**, а не отсутствие
стартового. Файл, где состояния есть, а `start` среди них нет, — это забытая
пометка, и ему по-прежнему отвечает `SE-011`. Спутав случаи, инструмент сказал
бы автору библиотеки о пропущенном `start`, а автору автомата — «файл
библиотечный», хотя тот писал автомат. Граница пришпилена отдельным тестом
(`missing_start_among_states_keeps_se011`).

**Языковой сервер проверку не зовёт — намеренно.** Позиция «вход» есть
свойство **вызова**, а не модели: библиотеку открывают в редакторе и правят, и
красная волна под каждым таким файлом была бы ложной тревогой. По той же
причине проверка не попала в `validate_model_all` — тому же дереву, пришедшему
из `import`, она не адресована.

## Проверки

- `takt-lang/tests/semantic/library_entry_tests.rs` — три утверждения, нарушаемые
  независимо: библиотека как вход отвергнута (`SE-102`, **с позицией и с
  названной причиной**), библиотека **через `import` работает** (иначе исправление
  запретил бы то, ради чего заведён), `SE-011` не подменён.
- `takt-sim/tests/sim/library_entry_tests.rs` — вторая точка входа: тот же `SE-102`,
  и **отсутствие** строки «Завершено» в выводе. Контр-пример рядом: обычная
  модель симулируется как прежде.
- Юнит-тесты `entry.rs` — на самой функции, без запуска инструментов.
- `./scripts/precheck.sh` — код возврата 0; проверка `check-diagnostic-codes.sh`
  подтверждает регистрацию `SE-102` в реестре.
